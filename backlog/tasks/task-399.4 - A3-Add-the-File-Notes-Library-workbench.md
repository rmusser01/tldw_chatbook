## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make linked files usable from Library without replacing or duplicating the existing Database Notes experience.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Wide Notes layouts show the collapsible navigator/editor split; narrow layouts switch Navigator and Editor without losing state.
- [ ] #2 Read-only files open in a selectable read-only body control, not an editable control that fails only when saving.
- [ ] #3 The host records source kind plus separate exact File host-return and Database-editor-Back targets; opening and returning restores mode, query generation, selection, expansion, focus, and scroll state without one target overwriting the other.
- [ ] #4 File selections open FileNotesWorkbench; Database selections switch the full surface to LibraryNotesCanvas after the leave guard. Direct combined-result Back returns to Files, notes opened from the delegated Database list retain Back to list, and persistent host chrome returns to Files.
- [ ] #5 A metadata-only Database navigator adapter delivers deterministic 100-row pages; combined search groups Files before Database notes, ranks only within each source, and labels authority. Each source has a focusable `Load more` row that alone fetches that source's next page; `PageDown` traverses all currently loaded rows across source groups and never auto-fetches at a group boundary.
- [ ] #6 Source-scoped loading and errors cannot blank or disable the other source.
- [ ] #7 Every specified focus transition lands on a mounted visible control; `F6`/`Shift+F6` include the outer Library rail and cycle only available visible regions; resize creates one scroll owner and preserves controller state without requiring widget identity to survive remount.
- [ ] #8 No File Notes UI-thread callback reaches 100 ms on the benchmark trace; deep and 5,000-sibling trees mount bounded row batches. The fixed 200,000-character interactive-body ceiling is distinct from the 2,000,000-character projection/FTS ceiling; larger supported files never mount the full body editor and instead show exact size, a labeled first-100,000-character excerpt, and streaming exact copy/export.
- [ ] #9 A pristine profile with zero roots, no file_notes.db/detached state, and no recovery evidence mounts the existing Database canvas directly and starts no File Notes path; detached projection evidence permits only bounded management bootstrap, while recovery evidence in an A-only build produces a source-scoped upgrade diagnostic without opening the recovery store.
- [ ] #10 Opaque frontmatter shows Frontmatter preserved (hidden), supports binding-local Treat entire file as plain body and Re-detect frontmatter, and is never parsed or regenerated by the body editor.
- [ ] #11 File workbench route, mode, query generation, selection, expansion, focus target, and scroll anchor are saved and restored when the user leaves Library and later returns, without changing the independently retained Database Notes state.
- [ ] #12 Every filename, root/relative path, search snippet, status detail, and error derived from a linked file is rendered as literal user content and cannot inject Rich/Textual markup or alter surrounding controls.
<!-- AC:END -->
