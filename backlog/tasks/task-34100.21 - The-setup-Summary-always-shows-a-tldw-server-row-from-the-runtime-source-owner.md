## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The setup Summary never says whether chatbook runs on this computer only or with a tldw server [coverage-06]. Someone who runs a server finishes setup without knowing whether they are connected, and a local-only user is never told where Library and notes live. PRODUCT.md asks users to understand what is local and what is server-backed.

The approved spec adds an always-present "tldw server" row to the Summary (which becomes Ready), on both tracks (decision D3, part 1). It is the review's "Runtime" row, named for what it measures, because "Runtime: this computer only" printed next to "OpenAI" told users that everything stays local. It lands on the Summary that TASK-34100.1 extracts, so FirstRunSetupWizard.py does not grow.

Spec: Docs/superpowers/specs/2026-10-03-first-run-setup-shape-design.md (revision 3, approved by the owner on 2026-10-03; ADR-217): D3 part 1, §3.0, §10 F2.

## Acceptance Criteria

- [ ] #1 Every setup Summary, on both tracks, shows a 'tldw server' row with one of four values: '✓ none — Library and notes stay on this computer'; '✓ <host> — connected'; '! <host> — not reachable now'; or '✓ none in use — <host> is set up but off'
- [ ] #2 The row's value comes only from RuntimePolicyContext (ADR-033). The [tldw_api] template address and the placeholder token never count as a server, and the placeholder is screened by the existing resolve_tldw_api_auth_token rather than a copy of it
- [ ] #3 When chat is routed through the server, the Provider row says so ('via tldw server <host>')
- [ ] #4 The row is computed when the Summary renders, from the runtime-source owner, never from values the wizard remembered
- [ ] #5 The Summary still fits 80x24 with the row added, and the row states its value as text
- [ ] #6 Verified live on a fresh isolated profile (TLDW_CONFIG_PATH and HOME set) through the real app, with real providers and the real llama.cpp server, never mock servers: local only with the real llama.cpp server; a real tldw_server bound and reachable; the same server stopped; and a server configured but not in use. Evidence is recorded in Implementation Notes

- [ ] #8 The matching Docs/User_Guide page content is updated where behaviour changed (no 'Verified against' stamps)
