## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A truncation helper has zero importers while 52 inline re-rolls of its body live in the package, plus about 20 private variants with drifting ellipsis glyphs and budget semantics, several of which append the marker unconditionally. Six of the re-rolls cap tool results that go on the wire, at a documented budget the appended marker then exceeds.

Source: core-runtime code review 2026-09-17 — `qa/core-code-review-2026-09-17/report.md`; per-slice evidence in `qa/core-code-review-2026-09-17/slices/`, reproductions in `qa/core-code-review-2026-09-17/phase4-verification.md`.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
PR #2745. The 52 truncation re-rolls split ~50/50 on the marker ("..." x32 vs
"…" x31) plus 25 named _truncate*/_ellipsize helpers — no majority to default to,
so the marker was an owner decision (2026-09-20): single-char "…" default with a
`marker=` override for ASCII/terminal contexts.

Added the canonical `Utils.Utils.truncate(text, limit, *, marker="…")`
(replacing the dead `truncate_content`): result-incl-marker never exceeds limit;
None/empty/within-limit pass through; hard-cuts when limit <= len(marker).
Gate-free test: Tests/Utils/test_truncate.py.

Adopted at the two gate-free-verifiable sites (owner scope "gate-free sites
only now"): Agents/run_hooks._truncate (byte-identical — kept its custom
"…[truncated]" marker + the truncate_hook_text alias + pins) and
Chat/provider_failures (detail[:237]+"..." → truncate(detail, 240), "…" default;
test asserts len<400, not the marker).

REMAINING: the inline `text[:N] + "..."` re-rolls carry a threshold-vs-keep
contract (fire at len>N, keep N, result N+len(marker)) that `truncate`
normalises differently (result length == limit) — each a small per-site shift,
not a byte-identical swap — and most are in ADR-126-gated UI/widget modules whose
exact-string pins run only in CI. The 25 named helpers each need signature/marker
review. These are the continued sweep.
