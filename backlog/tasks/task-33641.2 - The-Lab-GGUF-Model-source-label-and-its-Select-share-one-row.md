## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In F2 Lab ▸ Models, the GGUF source row shows the Select's value ("External GGUF") on one row and the "Model source:" label on the row below it. The row, the label and the Select are each 3 rows tall (`.gguf-source-mode-row`, `.gguf-source-label` and `.gguf-source-mode` in css/features/_llm-management.tcss). The label is centred vertically, but the borderless Select draws its value on its top row. The cubic review of PR #2937 found this in lab-211x44.txt and lab-235x52.txt. origin/dev 198a697e51 renders it the same way, captured live at 211x44, so it predates Phase 3.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The label and the value share one row, and the row keeps its height. Phase 9, plan Task 10; base 10fead87cb.

**Cause.** The mode Select is built with `compact=True`, so it paints its value on one row. `.gguf-source-mode-row`, `.gguf-source-label` and `.gguf-source-mode` are each three rows tall. The Select painted on the first of its three rows; the label, centred, painted on the second.

**Fix (AC#1, AC#2).** `.gguf-source-mode` in css/features/_llm-management.tcss gets `padding-top: $ds-space-1`. The value moves to the middle row, where the label is and where every other row of this form has its text. The three heights stay `$ds-size-3`. No raw literal was added, and both governance ratchets stay at zero.

**A first version was dropped.** It made the row, the label and the Select one row tall. That put the two on one row as well, but `test_supported_width_keyboard_reaches_each_provider_source_and_actions[llamacpp-llama-cpp]` then failed three runs out of three, alone too, and passes at the base. At 80x24 the three-row mode row does not fit under the view's last rows, so focusing it scrolls the form by 8 rows, and the managed controls are on screen when the mode changes to Managed. A one-row mode row fits without scrolling, and the managed controls then appear below the fold (managed selector at row 22 of a view that ends at row 21). Keeping the height keeps that behaviour.

**Test (AC#3).** `Tests/UI/test_llm_gguf_source_modes.py::test_model_source_label_and_value_paint_on_one_row`, at 211x44 and 235x52, reads the compositor's strips and asserts that "Model source:" and the Select's current value are each painted on one row and that it is the same row. Before the fix both sizes failed with the label on row 20 and the value on row 19. Both pass after it.

**The rest of the file.** Run alone at the head: 21 passed and 10 failed, all 10 with `RecoveryRequired` at setup, the same 10 as at the base (unmarked nodes; plan Task 14 owns that). Both keyboard-walk nodes pass. The two disabled-contrast nodes are among the 10, so they were measured once with a scratch plugin that gives them the `bootstrap_profile` marker: 2 passed.

**Live.** At 211x44 on a scratch profile, Lab ▸ Models ▸ Llama.cpp shows `Model source: External GGUF` on one row with a blank row above and below, and a click on the Select opens its two options directly under the value.

**Boot CSS.** The declaration adds 31 B to the boot bundle (607,963 B to 607,994 B; the limit is 608,090 B).

Docs/User_Guide has no text about this row; nothing there changed.

Files: css/features/_llm-management.tcss, the generated bundle, Tests/UI/test_llm_gguf_source_modes.py.
