## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
For the nine cloud providers, config.py::_normalize_legacy_provider_api_key never reads credential_source. With credential_source 'none' saved after a Clear in Settings, or 'environment' with the variable unset, and a key still present under the legacy [API] section, the loader copies that key into api_settings.<provider>.api_key and into the legacy <provider>_api dict. Readiness then resolves no key (so the Console says the provider is not ready) while readers of that dict, such as summarize_with_openai, send the cleared key. This is the opposite direction of TASK-33001.15 and older than it. Found by Phase 9's Task 9; read from the code, not run. ADR-012 says a credential the user removed is not used.
<!-- SECTION:DESCRIPTION:END -->
