## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in review of TASK-33620.15.5. The post-UI-ready pre-import pass now imports the Console's first-send modules (about 213 ms CPU, paced 1:1 and 3:1 on low-core hosts) before the speculative screen routes, and the warm-up parks while a navigation or accepted Console work owns the loop. So the screen routes start a few hundred ms later, and a send in the first second after UI-ready defers every speculative screen import until that run settles. The latency of the first navigation after boot was not measured on either arm, so a regression there would go unseen.
