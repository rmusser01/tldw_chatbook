## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** Verified live on a default install: replies grounded in real Library hits carry [Sn] markers, but no 'Cited sources (n)' row ever appears, and every `rag_citation_*` table stays at 0. This holds both for manually staged evidence and for Automatic retrieval, even after selecting the reply and waiting 20 s. The Sources modal is unreachable.

The S-labels are numbered per reply and never shown to the user: [S1] was zephyr-irrigation in one turn and quillmere-battery in the next. Staged chips and the Inspector source rows show no S-ordinals. The User Guide (context-and-rag.md:877-882) promises a 'Sources (N)' button whenever a reply is grounded. Unverifiable citations look more trustworthy than they are.

**Mechanism.**
- (a) The staged path cannot persist a trace. `[rag_citations] canonical_writes_enabled = false` ships as the default (config.py:5366-5367) and the getter fails closed, so no trace builder or finalizer is created. No UI exposes this switch.
- (b) The Automatic/prepared-bundle path never creates a CitationTraceBuilder (console_chat_controller.py:10793-10799, 10918-10922), yet still sends the '[Citation instructions] ... for example [S1]' block (answer_citations.py:182-190).
- The modal's bare 'Sources unavailable' (console_citation_sources_modal.py:356-363) is confirmed from code only.

**Severity / prior art.** P1. Verdicts are PARTIAL (live, code and skeptic), and the triage is KNOWN_PARTIAL. Related work:
- TASK-22302 is still To Do, but its fix landed in 3daa56bf4f, and it is not this mechanism. Its status should be reconciled.
- TASK-22617, TASK-22301, TASK-553.16, TASK-553.14 and TASK-19900.4 (all Done).
- ADR-024 (RAG citation provenance).

**Suggested direction.** First decide the contract. Either enable canonical citation writes by default, provisioning the fingerprint key on first use, or render an in-session 'Sources (n)' affordance from the in-memory evidence bundle when no trace will persist. Give the Automatic path a trace builder. When no source key will exist, stop asking for [Sn]. Show S-labels on staged chips and Inspector rows. Give the modal a cause and a next step. Align the User Guide.

Evidence: qa/console-ux-review-2026-09-29/findings.md → GAP5-05. Files: evidence/evidence__GAP5__17b-search-run.txt, evidence/evidence__GAP5__20-assistant-selected.txt, evidence/evidence__GAP5__32-select-latest.txt.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 With the shipped default configuration (canonical citation records on; the fingerprint key created in the secure system keyring on first use, not at boot), a reply that uses [Sn] labels from staged Library evidence shows a clickable 'Cited sources (N)' row. Its window lists each S-label with the document title, a snippet and Open in Library.
- [ ] #2 The Automatic (prepared-bundle) send path gets the same canonical capture as the staged path (fresh source authorization, trace builder, prompt evidence set), so a reply grounded by Automatic retrieval shows the same row and window.
- [ ] #3 The row and its window survive an app restart: reopening the chat shows 'Cited sources (N)' and the window loads the same rows.
- [ ] #4 Fail closed: when citation records are off, or the key or keyring is unavailable, no citation record is written and the model is not asked for [Sn] labels (Library evidence is sent without labels, to be referred to by title). A saved reply whose record cannot be verified because the key is unavailable shows 'Cited sources unavailable' instead of unexplained markers.
- [ ] #5 When sources cannot be shown, the window names the cause (for example citation records off, keyring unavailable, record missing, or load failed) and a next step, instead of a bare 'Sources unavailable'. The User Guide's description of the affordance matches the shipped name and behaviour.
- [ ] #6 A test runs both the staged and the Automatic send paths in the real ChatScreen against a real file-backed ChaChaNotes database with the shipped default config (only the provider and the keyring backend are doubles), asserts the rendered 'Cited sources (N)' row and the window's rows, and again after a restart over the same database. It fails on the pre-fix code.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Measure first. Write the AC#6 mounted test (real ChatScreen, controller, store and runtime; file-backed ChaChaNotes DB; shipped default config; provider and secure-keyring doubles). Run it on origin/dev and record why each path fails.
2. Config: ship `[rag_citations] canonical_writes_enabled = true`. A missing key means the shipped default (on); a malformed value still fails closed (off).
3. Key on first use: the app's boot composition stops touching the keyring. `CitationTraceRepository` keeps its key provider and gets one idempotent, thread-safe `ensure_local_fingerprint_key()`: load, or provision when no fingerprint-bearing rows exist (the factory's existing guarded rule, moved). It records why it is not ready. Callers run it off the UI loop: the Console capture paths before they build the trace builder, the citation-count reader and the Sources window (both already off-loop), and the deferred startup reconcile and legacy-migration units.
4. Automatic path parity: the prepared-bundle branch (and the dispatch-retry branch) run the bundle through the staged path's canonical capture (fresh authorization, builder, prompt evidence set, repair contract) via a runtime-owned collaborator, instead of `format_console_evidence_for_cited_answer`.
5. Fail closed (AC#4): when a capture yields no builder, the evidence goes out without [Sn] labels and with a 'refer by title' instruction, and with no repair contract. A saved reply whose record cannot be verified because the key is unavailable shows 'Cited sources unavailable'.
6. The Sources window maps each unavailable cause to copy plus a next step.
7. User Guide: rename to 'Cited sources (N)' and describe the persisted, fail-closed behaviour.
8. Gates: run the touched test files against a detached origin/dev worktree, compare reds by test id, and run the ratchets, census and preflight. Then a live check with a real Library note, a real model, and a restart.

## AC amendment (2026-10-29)

The ACs were amended on 2026-10-29 to record the owner decision of 2026-10-27
(TASK-33620.8 entry in the Console UX review's ux-decisions-2026-10-27): **persist
citations by default**. Canonical citation writes are on in the shipped config,
the fingerprint key is provisioned on first use, and the Automatic/prepared-bundle
send path gets the same citation capture as the staged path. Fail-closed
behaviour stays when the key or keyring is unavailable, with honest copy and a
next step. The owner chose this over the in-session, unpersisted Sources
affordance (option b) after asking what each option meant.

Changes from the original ACs:
- #1 and #2 now name the persisted contract (records on by default, key on first use).
- #3 (survives restart) is new; the decision is to persist.
- Original #3 became #4, scoped to the fail-closed cases this decision leaves.
- Original #4 (S-labels on staged chips and Inspector rows before send) moved
  to TASK-33620.8.1. A label shown before send can be wrong: the S-ordinal is
  assigned at the prompt boundary, after fresh source authorization can drop
  entries. The persisted Sources window is now the mapping from [Sn] to a document.
- Temporary (unsaved) chats still send [Sn]-labelled evidence with no record.
  That case is TASK-33620.8.2.
- Existing installs already have `canonical_writes_enabled = false` written into
  their config (it was the shipped default), so they stay off until changed.
  That needs an owner call and is TASK-33620.8.3.
