## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** Verified live on a default install: replies grounded in real Library hits carry [Sn] markers, but no 'Cited sources (n)' row ever appears, and every `rag_citation_*` table stays at 0. This holds both for manually staged evidence and for Automatic retrieval, even after selecting the reply and waiting 20 s. The Sources modal is unreachable.

The S-labels are numbered per reply and never shown to the user: [S1] was zephyr-irrigation in one turn and quillmere-battery in the next. Staged chips and the Inspector source rows show no S-ordinals. The User Guide (context-and-rag.md:877-882) promises a 'Sources (N)' button whenever a reply is grounded. Unverifiable citations look more trustworthy than they are.

**Mechanism.**
- (a) The staged path cannot persist a trace. `[rag_citations] canonical_writes_enabled = false` ships as the default (config.py:5366-5367) and the getter fails closed, so no trace builder or finalizer is created. No UI exposes this switch.
- (b) The Automatic/prepared-bundle path never creates a CitationTraceBuilder (console_chat_controller.py:10793-10799, 10918-10922), yet still sends the '[Citation instructions] ... for example [S1]' block (answer_citations.py:182-190).
- The modal's bare 'Sources unavailable' (console_citation_sources_modal.py:356-363) is confirmed from code only.

**Severity / prior art.** P1. Verdicts are PARTIAL (live, code and skeptic), and the triage is KNOWN_PARTIAL. Related work:
- TASK-22302 is still To Do, but its fix landed in 3daa56bf4f, and it is not this mechanism. Its status should be reconciled.
- TASK-22617, TASK-22301, TASK-553.16, TASK-553.14 and TASK-19900.4 (all Done).
- ADR-024 (RAG citation provenance).

**Suggested direction.** First decide the contract. Either enable canonical citation writes by default, provisioning the fingerprint key on first use, or render an in-session 'Sources (n)' affordance from the in-memory evidence bundle when no trace will persist. Give the Automatic path a trace builder. When no source key will exist, stop asking for [Sn]. Show S-labels on staged chips and Inspector rows. Give the modal a cause and a next step. Align the User Guide.

Evidence: qa/console-ux-review-2026-09-29/findings.md → GAP5-05. Files: evidence/evidence__GAP5__17b-search-run.txt, evidence/evidence__GAP5__20-assistant-selected.txt, evidence/evidence__GAP5__32-select-latest.txt.

Review finding ids: GAP5-05 — see qa/console-ux-review-2026-09-29/findings.md.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Citation records now persist by default (owner decision 2026-10-27), and replies that cite Library evidence show a working "Cited sources (N)" row. This holds whether the evidence was staged by hand or found by Automatic retrieval, and the row survives a restart and a Chatbook export.

**Measured first (origin/dev ed7481a30c).** A mounted probe forced records on and used a secure-keyring double. It showed three causes, not the one the triage named:
1. Records ship off.
2. With records on, the staged path writes its trace and the screen counts one source, but the transcript never gets the count. The TASK-34958 tick gate (c6d91555a4) keys on the store's display token, and a count found after the run has settled changes nothing it can see.
3. The Automatic path builds no trace at all.

The live check then found a fourth cause (AC#7, added): with records on, the next send after a cited reply is refused ("Conversation already has an active dispatch checkpoint"). TASK-22302's terminal path wrote the citation but never settled the turn's checkpoint. A probe on dev with records forced on reproduced it.

**Changes**
- Config: `[rag_citations] canonical_writes_enabled = true` ships. A missing key reads as the shipped default; a malformed value still fails closed. (config.py stays net-zero.)
- Key on first use: the boot composition (`defer_key=True` at both sites in app_service_wiring) no longer touches the keyring. `CitationTraceRepository` holds the key provider. Its idempotent, thread-safe `ensure_local_fingerprint_key()` loads the key, or provisions it under the factory's original guard: a write transaction proves that no fingerprint-bearing row exists. The protocol now lives in the new `Chat/citation_key_first_use.py`. A definitive outcome is kept; an unexpected failure is retried. Callers acquire the key off the UI loop:
  - the Console capture (`ensure_fingerprint_key_off_loop`, a worker for a file-backed DB);
  - the citation-count reader and the Sources window (both already off-loop);
  - the deferred startup reconcile, only when saved records exist;
  - legacy migration, only when a sidecar exists.

  Batch callers (Chatbook export and import) keep the eager factory default. A fresh profile's boot makes no keyring call; this was checked live, with no keystore file after boot.
- Automatic path parity: `capture_automatic_evidence` (in `console_library_search`) runs the prepared bundle through the staged path's canonical capture: fresh authorization, exact `[S#]` blocks, trace builder, prompt evidence set, repair contract. It authorizes against the turn's own session, so a tab switch during the search cannot change the scope. A session's "global" sentinel maps to the registry's Default workspace (task-15120 ruling), the only one with a registry row. The staged capture shares the code through `_capture_console_evidence_bundle`.
- Fail closed (AC#4): when no builder exists (records off, or the key/keyring unavailable), the evidence goes out without `[S#]` labels, under mixed-source guidance to cite by title, and with no repair contract. The dispatch-retry path never seals a trace, so it sends evidence the same way. A saved reply whose record cannot be verified because of the key state shows "Cited sources unavailable" (count sentinel -1, set off-loop in `citation_counts.py`).
- Transcript gate: count discovery resets the gate token before its sync. Without that, the row never painted after an idle run.
- Checkpoint settlement (AC#7): when a citation-sealed reply owns an in-flight durable checkpoint, it is settled first. That settlement writes the final body at the checkpoint's revision; the sealed citation then attaches to the settled row.
- Sources window (AC#5): each cause has copy and a next step. The causes are records off, keyring unavailable, key unreadable, records unavailable, record missing, reply changed, sources removed, and load failed. When nothing can be listed, the list and detail panes are hidden.
- User Guide (context-and-rag.md): the affordance is now "Cited sources (N)" in both places. It describes per-reply labels, persistence, the keyring key, the unlabelled fail-closed send and "Cited sources unavailable".
- Ratchet rows were raised with dated owner-decision comments (2026-10-04, expand limits): console_chat_controller +8, citation_trace_repository +53, console_chat_store +13, app_service_wiring +2. The console_transcript row is already red on dev (8821 against a budget of 8353); this branch adds 4 lines to it.
- Follow-ups: TASK-33620.8.1 (pre-send S-labels, the original AC#4), TASK-33620.8.2 (Temporary chats), TASK-33620.8.3 (existing installs keep the old shipped `false`; needs an owner call).
