## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in review of TASK-33620.15.5. The ADR-097 screen pre-import payload budget (Tests/Performance/test_screen_preimport_payload_budget.py) walks only the speculative screen routes. Since TASK-33620.15.5 the post-UI-ready pre-import pass first imports the Console's first-send modules (Chat/console_first_send_modules.py, about 70 modules and what they import, about 213 ms CPU in a fresh interpreter), and none of that is counted. A module added to that list, or a heavy import added to a listed module, grows the pass's idle work with no ratchet noticing.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The pre-import payload ratchet counts the first-send warm-up's modules and their imports, either in the existing screen census or as a separately pinned budget
- [x] #2 Adding a module to the warm-up list, or a heavy top-level import to a listed module, fails the ratchet with a message naming the module
- [x] #3 The new pin is set at the value measured on origin/dev at the time, with no slack
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. A second census in the payload budget file: fresh interpreter, app + chat as the route walk starts, then FIRST_SEND_MODULES in order, one marginal row per listed module.
2. Pin its module count as a new row (MAX_FIRST_SEND_WARMUP_ADDED_MODULES), exactly at the measurement, no LOC row; never raise an existing limit; dated owner-decision comment and an ADR-097 ledger row.
3. Breach message names new list entries and each new module with the entry that pulls it in (snapshot first_send_warmup.json via update_boot_budget_snapshots.py --only first-send); a newly imported HEAVY_MODULES dependency fails by name.
4. Mutation checks: a list addition, a top-level tldw import and a heavy third-party import in a listed module each turn it red.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The pass's first-send warm-up is now its own ADR-097 row. A second census in Tests/Performance/test_screen_preimport_payload_budget.py starts where the route walk starts (a fresh interpreter with app + the initial Chat route), imports FIRST_SEND_MODULES in the warm-up's order and records each listed module's marginal tldw modules and LOC. Measured 2026-10-20 on origin/dev 2d071d6d71's modules plus the list: 94 modules / 61,281 LOC. MAX_FIRST_SEND_WARMUP_ADDED_MODULES = 94, exactly, no slack (AC#3), with a dated owner-decision comment and an ADR-097 ledger row. It is a new row; no existing limit moved, and the route walk is unchanged, so its history stays comparable.

Decisions:
- Modules only, no LOC row. A LOC pin with no slack under 'never rises' would fail any edit that adds a line to one of these 94 Console modules. Per-entry LOC is printed in the table and the snapshot.
- Heavy third-party imports are invisible to a tldw-only count, so the same test fails if the warm-up newly imports any of test_app_import_weight.HEAVY_MODULES (torch, transformers, nltk, scipy, sklearn, pandas, docling, torchvision), naming the module and the listed entry.
- The breach message diffs against a new snapshot, boot_budget_snapshots/first_send_warmup.json, written only by scripts/update_boot_budget_snapshots.py --only first-send. It names new list entries and each new module with the listed entry that pulls it in. The snapshot sanity test covers it.

AC#2 evidence, each a temporary edit restored with Edit: appending UI.Screens.acp_screen to the list -> 97 > 94, 'NEW listed modules (1) ... + tldw_chatbook.UI.Screens.acp_screen' and its three modules 'by UI.Screens.acp_screen'; a top-level 'import tldw_chatbook.UI.Screens.acp_screen' in Chat/console_send_diagnostics.py -> 97 > 94, the three modules named 'by Chat.console_send_diagnostics'; a top-level 'import pandas' there -> 'imports heavy dependencies [pandas] (by entry: Chat.console_send_diagnostics)'. On the pre-change tree none of these failed any ratchet, because the route walk never runs the list.

Files: Tests/Performance/test_screen_preimport_payload_budget.py, Tests/Performance/boot_budget_ratchet.py (snapshot key), Tests/Performance/test_boot_budget_ratchet_messages.py (snapshot sanity), Tests/Performance/boot_budget_snapshots/first_send_warmup.json, scripts/update_boot_budget_snapshots.py (--only first-send), backlog/decisions/097-boot-budget-ratchets.md (ledger row). The file is already in perf-guard.yml, so the new test runs there.
