## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The review's biggest opportunity is the researcher loop: read → note → ask → keep. A researcher (Priya) and a power user (Alex) found it broken at these five joints.

- Quotes and kept answers lose their source.
- Console's staged context quietly drops, keeps or invents sources.

**Owner gate.** The staging part (S-06, S-18, S-20) changes the Console Inspector's Sources section. It replaces Console's single staged launch with a Console-owned, accumulating list (review roadmap R-09 in `improvements/ranked.md`). It needs owner approval before implementation, and must follow the Inspector's existing visual language. ADR-079 still holds: staging stays manual, with no auto-retrieve.

If S-03 or S-04 is built as a new capture modal (R-15), that modal also needs owner approval.

**S-03 (P2) · There is no way to quote a passage into a note with a link back to its source.** In "Spaced repetition, explained", Priya adds a highlight ("Practical guidance often lags behind the evidence." / "Note: key claim for ch2"). The highlight card's only action is "✕ Delete".
- Selecting text in Read and pressing Ctrl+C gives no feedback.
- Pasted into a note, the text arrives bare, with no attribution, and note Info has no Source field.
- Media Info shows "Canonical ID: local:media:26", but notes understand only `note://` links. The `media://` form exists only in the MCP layer (`tldw_chatbook/MCP/resources.py` and siblings).

Suggested direction:
- Add "Quote to note…" on highlight cards and a Reader selection key. It inserts "> quote — [title](media://id)" into a chosen or new note.
- Render `media://` links in note Preview so they open the reader.
- Show "Notes citing this item" in media Info.
- Do not rebind Ctrl+C.

TASK-34000.11 (N-08) makes note Preview handle link activation in-app instead of handing it to the OS. That should land first, and `media://` routing should extend it. TASK-34000.25 (S-02) adds a "Take note" action to the Media reader. Quote to note should reuse that note-creation path, not add a second writer. Lowered from P1: copy, paste and a hand-typed citation work.

**S-04 (P2) · Kept AI answers lose their provenance, and RAG answers cannot be kept.** Priya asks Console about a staged note, then uses More… ▸ "Capture as note". The captured note:
- uses the answer text as both title and body;
- has the Keywords "console, conversation:2f51b5a7-3b85-41de-a4d5-b7c3188e0009, message:5dc0e0c1-…";
- names neither the question, the source, nor the model.

Filtering Notes by "2f51b5a7" finds nothing. The Library RAG Answer panel has no save action.

Verified cause: `_capture_console_answer_as_note` (`UI/Console_Modules/message.py:2169`) writes only the message content plus id keywords.

Suggested direction:
- Add a provenance footer to the captured note: question, conversation title, date, model, and "Sources:" with links.
- Show "From conversation: <title> · Open" in Info.
- Add "Save answer as note" to the RAG Answer panel, with the same footer.
- Make the provenance searchable.

The Notes filter not searching keywords is N-09, and export dropping keywords is L-04. Both are filed separately, so this task must make provenance visible in the note itself. Lowered from P1: the conversation still exists.

**S-06 (P2) · A second "Use in Console" silently replaces the first staged note.**
- After note A, the strip reads "Staged for next send · 1 source · Thesis outline".
- After note B, it reads "Staged for next send · 1 source" / "Trip planning: Lisbon — note", and Inspect reads "Sources: 1 staged".
- Note A is gone without a word, and Notes select mode has no Use in Console.

Verified cause: `ConsoleRuntime.stage_console_staged_evidence` replaces the single staged launch (`Chat/console_runtime.py:2188-2194`). The overwrite happens in Console's runtime, not in the hand-off slot. The strip does show the true single source.

Suggested direction:
- Make staging additive: merge, de-duplicate by id, renumber, cap at 20.
- Build this on TASK-33620.7's per-session keying (To Do, which owns the stale strip after send).
- Status: "Added to Console · 2 sources staged".
- Add "c use selected in Console" to Notes select mode.

**S-18 (P2) · A deleted note stays staged in Console as "Ready", and the send drops it silently.** Alex stages "Trip planning: Lisbon", then deletes the note in Library. Console still shows:
- Inspect: "Sources — next send 1 · Trip planning: Lisbon (note · Ready";
- the strip: "Staged for next send · 1 source".

Send goes ahead with no notice. The live check showed the deleted text is not sent, because authorization drops it. But the user is told nothing, and believes the answer was grounded.

Suggested direction: when authorization drops a staged reference, block, or show at send, "Trip planning: Lisbon was deleted — not sent · Remove · Restore". Clear the reference, and revalidate the strip when entering Console. TASK-33621.20 (automatic-retrieval outcome disclosure) and TASK-33620.7 are adjacent but cover other paths.

**S-20 (P2) · Console's "Search Library" modal fails a first-timer.** On an empty profile with 2 notes, at 120x36:
- The modal opens without focus in its query field, so typing goes nowhere.
- While the first search is still loading the embeddings model, the strip already says "Staged for next send · 1 source" / "Library Search/RAG retrieval".
- An early Send is blocked with "Console send blocked: Library search has no available evidence. Review source authority before sending."
- Results that arrive after Un-stage stage themselves, and the strip shows "Staged for next send · 2 sources".

Verified cause, for focus: `ConsoleRagSettingsModal` (`Widgets/Console/console_rag_settings_modal.py:131`) sets no `AUTO_FOCUS`. The block copy is at `UI/Screens/chat_screen.py:18863`, with a sibling in `Chat/console_display_state.py:624`.

Suggested direction:
- Set `AUTO_FOCUS='#console-rag-settings-query'`.
- Show "Searching Library… · the first search loads the model" with Cancel, and let Send wait.
- Use plain block copy.
- Add a generation fence so that Un-stage or Cancel drops late results.

The late re-stage is the most serious part, and could be split out as its own P1 if this batch waits.

Review finding(s): S-03, S-04, S-06, S-18, S-20. Source: qa/notes-library-ux-review-2026-10-02/report.md
