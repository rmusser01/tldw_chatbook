## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact (P1).** Confirmed live on Anthropic claude-haiku-4-5 and OpenAI gpt-4.1-mini. Selecting a turn on 'Exchange history' or 'Usage & cost' shows 'Capture unavailable / Could not load captures. Select this turn again to retry.' Retrying fails every time, so 'Export selected call…' and the exchange-export dialog can never be reached. The 'what was actually sent' surface is the recovery tool for provider problems, and here it dead-ends behind a false retry promise.

**Verified cause.** This is a deterministic code bug, not missing data. `ConsoleTraceNativeReader._reconstruct_call` calls `json.dumps(dict(call.usage))`, but stored usage is frozen into nested MappingProxyType objects and `dict()` is shallow. Real usage from both providers is nested (Anthropic `cache_creation`; OpenAI `prompt_tokens_details`/`completion_tokens_details`), so the call raises 'TypeError: Object of type mappingproxy is not JSON serializable'. The Inspector's broad except swallows it without logging. This is the same class of bug as TASK-32342 (Done), in a different place.

The secondary details were also verified:
- When the section list gains focus it scrolls down one row, so the selected Turn 1 is off-screen.
- On 'Usage & cost' the basis label wraps, which leaves Turn 1's 'Estimated' orphaned above Turn 2.
- The llama.cpp caveat is hard-coded and shown for every provider.

**Prior art:** KNOWN_PARTIAL. TASK-32828 (In Progress) redesigned this modal; its AC#3 and AC#8 (per-call detail; Safe/Full reachable from call detail) are ticked but do not hold live. See also ADR-171 and Docs/superpowers/reports/2026-09-18-console-conversation-ux-verification.md.

**Suggested direction:**
- Deep-thaw the frozen usage before serialising, or store it as normalized ProviderUsage JSON.
- Log and classify reader failures, and drop the retry promise for deterministic ones.
- Keep the highlighted row in view and the basis label on its turn's line.
- Show the llama.cpp note only for llama.cpp.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Two layers, not one: the native reader raised TypeError on frozen nested usage (json.dumps(dict(usage))), and once thawed the raw provider keys still failed the capture contract, which carries normalized ProviderUsage (the projection rejected it as usage_json). The reader now deep-thaws and normalizes via ProviderUsage.from_provider_payload (legacy-imported rows are already ProviderUsage) and omits only usage it cannot normalize, never the call. Deviation from plan step 2: unrecognized usage is disclosed in the call's omitted fields, not as an uncertainty code, because any uncertainty code on a native call marks it unverified and the projection drops unverified native calls (the failure this task fixed); pinned with a Gemini-shaped payload. An empty usage payload now loads as no usage instead of an all-zero 'reported' record.

Inspector: capture-load failures are classified (busy store keeps the retry promise; decode errors say a retry will not help; anything else is 'an unexpected error', in plain words) and logged with reason + exception type only; the decode copy says usage figures are unaffected only on Usage & cost, the tab that shows them. The tab caveat no longer names llama.cpp; llama_cpp/local_llamacpp call details carry the literal-payload note.

'Scrolls down one row on focus' measured on the painted frame: nothing scrolled; the app-wide *:focus outline overpainted the list's first row. The section lists now use TASK-28226's content-safe cue (no outline, focus tint, focus-coloured highlight). Only the usage list never wraps; its rows lead with basis and cost so clipping drops token counts, not the basis. (Review follow-up: no-wrap on every list cut Context counts and Exchange call details at 235x52, measured on the painted frame; Context and Exchange labels wrap again, pinned by test_context_and_exchange_lists_wrap_rather_than_clip_their_labels.)

Tests (each red on origin/dev ed7481a30c for the stated reason): Tests/Chat/test_console_trace_native_reader.py::test_native_reader_loads_calls_whose_usage_is_nested (real repository + production projection; TypeError mappingproxy on dev), Tests/UI/test_console_conversation_inspector.py (real stored call -> reader -> projection -> Inspector loader -> Export selected call; failure classification; llama note; painted-frame rows at 80x24 and 235x52).
