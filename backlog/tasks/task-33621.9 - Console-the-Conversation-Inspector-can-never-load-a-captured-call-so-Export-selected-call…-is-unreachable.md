## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact (P1).** Confirmed live on Anthropic claude-haiku-4-5 and OpenAI gpt-4.1-mini. Selecting a turn on 'Exchange history' or 'Usage & cost' shows 'Capture unavailable / Could not load captures. Select this turn again to retry.' Retrying fails every time, so 'Export selected call…' and the exchange-export dialog can never be reached. The 'what was actually sent' surface is the recovery tool for provider problems, and here it dead-ends behind a false retry promise.

**Verified cause.** This is a deterministic code bug, not missing data. `ConsoleTraceNativeReader._reconstruct_call` calls `json.dumps(dict(call.usage))`, but stored usage is frozen into nested MappingProxyType objects and `dict()` is shallow. Real usage from both providers is nested (Anthropic `cache_creation`; OpenAI `prompt_tokens_details`/`completion_tokens_details`), so the call raises 'TypeError: Object of type mappingproxy is not JSON serializable'. The Inspector's broad except swallows it without logging. This is the same class of bug as TASK-32342 (Done), in a different place.

The secondary details were also verified:
- When the section list gains focus it scrolls down one row, so the selected Turn 1 is off-screen.
- On 'Usage & cost' the basis label wraps, which leaves Turn 1's 'Estimated' orphaned above Turn 2.
- The llama.cpp caveat is hard-coded and shown for every provider.

**Prior art:** KNOWN_PARTIAL. TASK-32828 (In Progress) redesigned this modal; its AC#3 and AC#8 (per-call detail; Safe/Full reachable from call detail) are ticked but do not hold live. See also ADR-171 and Docs/superpowers/reports/2026-09-18-console-conversation-ux-verification.md.

**Suggested direction:**
- Deep-thaw the frozen usage before serialising, or store it as normalized ProviderUsage JSON.
- Log and classify reader failures, and drop the retry promise for deterministic ones.
- Keep the highlighted row in view and the basis label on its turn's line.
- Show the llama.cpp note only for llama.cpp.
