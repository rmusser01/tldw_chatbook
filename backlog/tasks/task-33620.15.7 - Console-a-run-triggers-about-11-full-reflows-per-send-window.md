## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the same live profile as TASK-33620.15.3 (2026-10-10; 160x45, Anthropic haiku through the review proxy). The probe timed Textual's `Screen._refresh_layout`, `Compositor.reflow` and `render_update`, and recorded which widgets posted the `Layout` messages before each reflow.

Textual screen updates (`Screen._on_timer_update` > `_refresh_layout` > reflow and render) are the longest UI-loop blocks after a send is accepted: 242 ms per send in total, worst 487 ms, with about 590 visible widgets at about 50 turns. Between acceptance and the provider call a send runs a median of 11 reflows of 5 ms or more, 498 ms per send in the launch that recorded requesters (median reflow 37 ms, max 405).

The widgets whose `Layout` message preceded those reflows, most often first: `Static`, `Button`, `Horizontal`/`Vertical`, `ConsoleCharacterContext`, `ConsoleRunChip`, `ConsoleMarkdownMessage`/`ConsoleAssistantTurnWidget`, `ConsoleInspectorRail`, `ConsoleCostChip`, `ConsoleControlBar` and `ComposerControlButton`. Run-state and cost chips change text during a run and request a full layout each time.

Even with the GC and projection fixes (TASK-33620.15.3, TASK-33620.15.4) and run start moved off the loop, the counterfactual floor stays at a median of 43 ms and a p90 of 85-98 ms; this is that floor.

Fix direction: fixed-width chips and controls, so a content change needs no layout; `batch_update` around multi-widget syncs; a bounded transcript.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Partial (PR #3211): a run's 0.2 s poll ticks stop requesting whole-screen layouts for widgets whose copy or size did not change.

- Approach: skip writes that change nothing. Unchanged Static copy is not re-written (Model section values, Character title/identity, hidden setup-card steps, trace-recovery callout, attachment indicator, idle voice chip, agent/steering lines, send-authority facts, avatar caption). Inline width/height rules are cleared only when one exists (control-bar recovery height, Send disabled-reason strip), each as a literal None reset so ADR-161's Python style inventory reads it as a reset. Hidden zero-size compat statics take new copy with layout=False; the status line repaints in place when its cell width is unchanged; the prompt-queue shelf re-lays out only when drawn text, visibility or a button label changes; the no-character avatar blank is kept under the mount lock instead of re-mounted; a collapsed-rail inspector update no longer re-shows rows.
- Measured (live, paired, 160x45, Anthropic claude-haiku-4-5, 16 sends per arm): median full reflows per send window 24 on dev (pooled; 27.5 and 20.5 by round) vs 13 on the branch; screen-update time per window 480 -> 276 ms on the final head. Headless held send: 128 -> 8 layout requests over six unchanged poll ticks.
- Tests: Tests/UI/test_console_run_tick_layout_requests.py (widget pins with positive controls, a stale-inline-size control for the reason strip, and a held run over real poll ticks; the pins fail on dev), two avatar tests in test_console_character_avatar.py, two composer focus waits in test_console_composer_run_controls.py.
- Open: AC#2 holds for poll ticks but send start/end still request layouts for unchanged widgets, and AC#3 (half the reflows) was met in one round (-53%) but not the other (-37%); both remain in TASK-36012.
