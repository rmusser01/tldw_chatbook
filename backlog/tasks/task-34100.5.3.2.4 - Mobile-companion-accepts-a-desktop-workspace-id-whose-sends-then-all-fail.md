## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found during TASK-34100.5.3.2's live review (round v5r1, F2). It behaves the same on origin/dev 4b90eb860b and on the branch, so it is not that task's regression.

The served mobile companion keeps its own workspaces database under `<user_data>/mobile/`, separate from the desktop app's. But `POST /api/v1/mobile/conversations` accepts any `workspace_id` string, including a desktop workspace id such as `workspace-local-1`. The request returns 201 with `has_folder_tools: false`, and every send to that session is then refused. The serve log says only "mobile send refused"; the reviewer traced the refusal to the send's durable commit, where the workspace is unknown to the companion's own registry. The phone gets a session that looks valid but can never get a reply, and nothing says why.

Evidence: `setup-wizard-ux-qa/evidence/g532v5-rb-mobile/01-mobile-send-full-off-light-set.txt` (branch, session `5cc53d04`) and `02-negative-control-base-sends-full-surface.txt` (base, session `21ef0b58`, refused the same way), with the serve logs `g532v5-rb-mobile-serve.log` and `g532v5-rb-mobile-serve-base.log`.
