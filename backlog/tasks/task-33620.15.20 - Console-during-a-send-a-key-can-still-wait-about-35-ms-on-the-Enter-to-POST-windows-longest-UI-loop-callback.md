## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the independent review of TASK-33620.15.8 (2026-10-23). That task halved run start's own longest UI-loop callback (first sends 23.8 -> 10.6 ms, later sends 16.8 -> 8.6 ms, paired live against origin/dev 5b5920b8e2, Anthropic haiku, load 4-23). The longest callback anywhere between Enter and the provider POST did not move: first sends 38.2 -> 34.4 ms (paired -0.6 ms, 7 of 11 better), later sends 33.5 -> 35.0 ms (paired +0.9 ms, 11 of 28). So a key pressed during a send can still wait about 35 ms on some callback that is not run start's, and which callback that is has not been identified. Separately, that task's probe-free Enter-to-POST rounds (28 launches per arm) had paired ranges of -644..+493 ms on first sends and -1053..+373 ms on later ones: the medians showed no regression, but a small one could not be ruled out.
