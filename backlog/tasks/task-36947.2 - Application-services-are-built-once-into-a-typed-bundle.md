## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
- `tldw_chatbook/app_services.py` (stdlib-only module level, every service type under TYPE_CHECKING): `ScopedServices[L, S, C]`, one frozen/slotted/kw-only slice per ADR-250 section 2, `ProfileStorage`, `ApplicationServices`, `assemble_application_services(app)`. Required fields read `app.<attr>`; fields that can be unavailable today (databases, local conversation/quiz/study, citation trio, actor-pack import trio, library collections) are `T | None = None` and read through `_optional`.
- `ServiceWiringMixin._publish_application_services()` sets `self.services`; `TldwCli.__init__` calls it once between `_wire_character_persona_services()` and `_init_worker_handlers()`. No composition code moved; the app attributes are the aliases (147 rows, pinned in the test).
- Tests (`Tests/Architecture/test_application_services_bundle.py`): alias identity after construction; coverage of every service name read from an app-like receiver (bundle field or an `EXCLUDED` row naming its ADR-250 rule); module-level imports are stdlib only.
- Ratchets moved: module size rows (`app.py` 5686->5687, `app_service_wiring.py` 3693->3702), construct-time import allowlist (+`tldw_chatbook.app_services`). `app_services` is a new UI-ready module (1039 vs limit 1038); shed one by folding `Widgets/Chat_Widgets/chat_resume_panel.py` (28 lines, sole importer `chat_task_cards.py`) into `chat_task_cards.py`, so the census is back at 1038. `boot_budget_snapshots/ui_ready_modules.txt` was not regenerated (script-only; already stale at base).
- Red evidence (temporary source edits, then reverted): `sync_scope_service=app.server_sync_service` -> identity test fails ("app.sync_scope_service is not services.sync.sync_scope_service"); dropping `dreams_db` from `EXCLUDED` -> coverage test fails; `import httpx` at module level -> import test fails.
- Fix round 1: added `test_every_alias_is_still_the_bundle_field_after_mount` (run_test mount, same ALIASES list); regenerated `ui_ready_modules.txt` with `scripts/update_boot_budget_snapshots.py --only ui-ready` (1038 modules); docstring notes dynamic names are out of scope (ADR-250 s2). Red case for a new unbundled name: temporarily reading `app.zzz_new_service` in a scanned module fails the coverage test and names `['zzz_new_service']`.
- Decisions and deviations: `open_profile_storage`, its openers and `ProfileStorage.close()` are left out (ADR-250 section 6: added by the first PR that calls them, TASK-36947.6/.7); `ProfileStorage` is the typed holder only. `local_library_collections_db` is excluded (not bundled; ADR-250 rule 5's "replaced afterwards" category, which does not name it, and the ADR is not edited): `_wire_collections_capture_services` in `app_collections_wiring.py` (`self.local_library_collections_db = database`) re-assigns it when it is not a `LibraryCollectionsDB` (`app_collections_wiring.py`), so it is not fixed after composition. `console_settings_durability_owner` is excluded as session state (rule 4). Optional reads use a non-literal `getattr` so `test_app_string_lookup_census` stays at its pins.
- Pre-existing red at base 5ca7ec6a03, not caused here: `Tests/App/test_construct_runtime_imports.py` (18 unlisted modules before this change).
