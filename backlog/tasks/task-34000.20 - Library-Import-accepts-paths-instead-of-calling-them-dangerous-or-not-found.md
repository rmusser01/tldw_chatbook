## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: terminal users type '~/' by reflex. A first-time Library user (j2) typed `~/fixtures/import-docs/team-handbook.docx`, a file that exists, into Library › Import. The pre-check answered "Invalid path: Path contains dangerous pattern: ~/", treating an ordinary path as a security risk. Pressing Enter then gave "Can't find that path — check it, or use Browse… to pick a file or folder.". A mistyped, missing '~/' path produced three messages at once: the "dangerous pattern" line, the same "Can't find" line, and a "Could not find that file." toast. Yet pressing Enter before the pre-check finished imported the same path. Whether the same text is refused or accepted depends on timing.

Observed (verify/nl-v-l-05 at 160x45):
- 02-tilde-existing-enter shows both lines under the field, with the footer "enter check this path".
- 07-clean-race-tilde-article-after6s shows the fast-Enter race: the queue reads "✓ done · article-local-first.md · <1s / Imported article-local-first.md".
- The app log reads "WARNING … Rejected Library ingest path ~/fixtures/…".

Verified cause (origin/dev 2d34cbf80d):
- Library/ingest_preflight.py:421-424 calls `validate_path_simple(path_or_url, require_exists=False)` on the raw text, and Utils/path_validation.py:559-571 lists '~/' as a dangerous pattern.
- The submit path already expands it: UI/Screens/library_screen.py:28752-28754 calls `Path(raw_path).expanduser()`. Pre-check and submit therefore disagree.
- The "Can't find that path…" start line comes from Library/library_ingest_state.py:3226-3230 and appears for any path-problem error, including this one.

Suggested direction (the review's refined fix; a direction, not a mandate):
- Expand '~' at the pre-check boundary, matching the submit path.
- Make Enter wait for, or re-run, the pre-check for the current field text.
- Show one plain message per failure.
- Do not remove '~/' from `validate_path_simple` itself. The acceptance criteria of TASK-32927 rely on its other callers still refusing an unexpanded '~'.

Review finding(s): L-05. Source: qa/notes-library-ux-review-2026-10-02/report.md
