## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`get_cli_setting` costs about 11 ms per call even when warm, measured over 200 warm calls, because the cached read sits behind a per-call storage-admission handshake -- roughly 482 file opens per read. The value is cached; the admission is not. This single cost is behind most of the event-loop findings in this stream, and it retires the previous performance audit's 'config reads are cache-backed' as a cost claim.

Source: core-runtime code review 2026-09-17 — `qa/core-code-review-2026-09-17/report.md`; per-slice evidence in `qa/core-code-review-2026-09-17/slices/`, reproductions in `qa/core-code-review-2026-09-17/phase4-verification.md`.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A warm `get_cli_setting` call costs on the order of microseconds, not milliseconds
- [ ] #2 The admission handshake is amortised per derivation or per scope rather than paid per read
- [ ] #3 A benchmark pins the warm read cost so it cannot regress
