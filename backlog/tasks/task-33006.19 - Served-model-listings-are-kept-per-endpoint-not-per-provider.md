## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Chat settings keeps each listing with the connection it listed, and pick mode offers a listed model only while a pick of it lands on that connection.

- `Widgets/Console/console_settings_field_row.py`: `_served_models` maps a provider to `(connection identity, model ids)`. `_keep_served_models` records a listing with `_served_endpoint(provider)`, the identity the modal already computes (`_discovery_connection_identity`) of the connection the listing ran on: the Endpoint field for the draft's own provider (`_discovery_endpoint_value`), a registry entry's own URL for an entry. `_open_model_picker` passes pick mode only the models whose `_pick_endpoint` equals that identity, so `model_switcher.py` and the switcher keep their provider-keyed `served` mapping (its docstring says so now). `_pick_endpoint(source, provider, model)` asks the seam a pick uses: the draft's own pair stays on the Endpoint field (`_model_picked` does not rebase it), an entry keeps its URL, and any other pair runs through `_draft_rebaser` from `_snapshot_before_rebase()` with `FULL_MODEL_DEFAULT_FIELDS`, its URL shown as `_apply_rebased_state` shows it (`_initial_base_url_for_provider`). A failed rebase lands nowhere (None). An empty listing (a created entry that could not be listed) is still passed, so its server still counts as in use.
- Review round 1: the first version keyed another provider's check to `_base_url_for_provider`, whose `_provider_base_url_drafts` is written only at open and on suspend, so it went stale. A pick restores the pair's remembered endpoint draft, or resets an unedited session URL to the configured one, and the old check missed both. That reset is the rebaser's (`rebase_console_settings_draft` gives an unseen same-provider target its default chain's base URL, which for llama.cpp is None, meaning the configured URL; Switch model's popover rebases through it too), so a model listed at a chat's own session URL is not offered unless the Endpoint is retyped; TASK-35190 tracks keeping the session URL. One rebase per listed model costs about 0.07 ms (600 pairs measured in 42 ms), which a `ponytail:` comment notes.
- `console_settings_modal.py`: the listing-result handler records through `_keep_served_models` (one line fewer), and `__init__` starts the map empty, typed by the mixin's annotation. `_list_then_pick` (a created entry) records the same way. With TASK-33006.13's net-zero constant move, the modal measures 6,159, and its row in `Tests/Architecture/test_module_size_ratchet.py` is lowered to match.
- Going back to the endpoint that listed the models offers them again: they are still what that endpoint served.

Tests (each red before its fix, green after), in `Tests/UI/test_console_endpoint_discovery.py`:
- `test_a_listing_is_offered_in_pick_mode_only_for_the_endpoint_that_listed_it` (red at fc9f3ec375): Test connection lists `served-y` at 127.0.0.1:9099, then the Endpoint changes to :9100 and back. At the base, `("llama_cpp", "served-y")` was still offered after the change.
