## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**AC#1 done in burn-down PR 5 of the B2b follow-ups (stacked on PR #3441). AC#2 is not met as written, so the task stays To Do.**

- **On dev:** present. Only the read ran in a thread: the lore book's `json.loads` and `normalize_world_book_import`, and the dictionary's `json.loads` and `data` unwrap, ran on the event loop.
- **Fix:** `UI/Persona_Modules/roleplay_import_parse.py` (imported lazily; the pre-import module set is unchanged) holds `read_world_book_import` (read, parse, normalise) and `read_dictionary_import` (read; parse and unwrap `.json`), each awaited with `asyncio.to_thread`. Refusals keep dev's copy (`ImportNotJSON` carries the parser's reason). `json.loads` holds the GIL for its whole parse, so the parse passes a Python-level `object_hook` that returns each object unchanged and lets the interpreter hand the GIL to the loop between objects (standalone, a threaded 9 MB parse's longest loop gap fell from 32-63 ms to 14-27 ms).
- **Tests (`Tests/UI/test_roleplay_import_app.py`):** `test_a_lore_or_dictionary_import_parses_off_the_event_loop[lore|dictionary]` holds the parse (and the normalise) in its thread through the module's own `json` name and checks the screen answers meanwhile; red on the base ("parsed on the event loop"). Mutations M44-A, M44-B and M44-C (each step back on the loop) turn a case red. `test_a_file_the_import_thread_refuses_toasts_as_on_dev_and_adds_nothing` (six refusals) pins the copy; M44-D (no `ImportNotJSON` branch) turns the not-JSON cases red.
- **AC#2, the ADR-011 capture** (real `TldwCli` at 120x36, 348 characters, a 9.0 MB, 22,000-entry lore book imported from Characters; load average 14-63; the import split at the DB write and at the landing):
  - *Parse window* (click, sniff, read, parse, normalise): longest loop gap base 225 / 115 / 218 / 128 ms, head 56 / 57 / 48 / 63 / 44 ms. On the head every gap over 30 ms holds a generation-2 collection (25-35 ms) that the import's own allocations trigger, on whichever thread allocates; the heap was already frozen at UI-ready (ADR-198), and an extra freeze at arrival changed little (head 44 ms, base 128 ms).
  - *Write window* (`import_world_book`, in a thread on both arms): 100-205 s, gaps of 115-210 ms on both arms (GIL and GC pressure of the per-entry writes). Exists on dev; not this task.
  - *Landing* (switch to Lore, select, entries table): 1.1-3.0 s on both arms: the 22,000-row entries table is filled on the loop. Exists on dev; not this task.
  - So the import phase misses 50 ms on both arms for reasons outside the parse, and the parse window itself sits at the line. Open for the owner: re-word AC#2 to the parse window, or keep the task for the write and the entries table (to be filed).
