## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
From TASK-33621.4. A composer send over the Ask compaction trigger is held before commit; Continue, Regenerate, Retry, queued follow-ups and Buddy replies are refused before commit (console_compaction_gate). Automatic turns -- a goal iteration (ConsoleSubmissionOrigin.GOAL_ITERATION) or an agent wake (AGENT_WAKE) -- still reach the post-commit Ask block in console_context_compaction.py, which marks the assistant row Failed with the 'Conversation context reached its compaction threshold' System row. They were left alone in TASK-33621.4 because a refused automatic turn has its own stop semantics (a goal iteration terminates PREFLIGHT_REFUSED and the goal coordinator then sets the run state to 'Goal iteration settled.', hiding the reason; a wake owns a retry loop), which needs its own design and live check.

**Checked 2026-10-29 through the real controller** (store with ChaChaNotes persistence, goal coordinator, fleet-wake coordinator; only the provider adapter doubled). The chat held 12 persisted turns, 2,070 tokens against a custom 1,800-token budget (Ask trigger 1,440); the composer probe on the same request returned an Ask hold.
- **Agent wake: reproduced.** submit_draft(origin=AGENT_WAKE), with a live wake delivery registered and the coordinator's durable accept stubbed as Tests/Chat/test_console_chat_controller.py::test_wake_notice_fires_nothing does, was accepted with no provider call. It committed the wake notice (System), an empty Assistant row marked **failed**, and the System row "Conversation context reached its compaction threshold. Run /compact ...". Reading ConsoleFleetWakeCoordinator._finish_attempt (not run): the attempt was accepted before the block, so delivery completes the wake and consumes its results; it would not retry, but the turn reads Failed.
- **Goal iteration: not reached.** A goal iteration sends fresh context (no conversation history; Tests/Chat/test_console_goal_dispatch.py), so the Ask trigger, which counts history, never fires. dispatch_once ended DONE with one provider call and no Failed row.

Owner decision 2026-10-30: TASK-33621.4 shipped for the sends a user starts, and its AC#2 (a deliberate policy hold never marks a turn Failed) was narrowed to those sends. The agent-wake case is this task's.

2. Agent wake: before durable acceptance (no generation spent), probe the Ask trigger on the wake's request (history + notice) with the same side-effect-free probe the composer hold uses. Over the trigger: refuse before commit, pause the wake's chain with the bounded code compaction_ask (durable 'paused', not review-required; ADR-134: paused work gets no retry timer), keep the pending results and the unseen mark, and say why and how to go on in the run state and the fleet section ('Paused: context limit. 3. Resume on the user's decision (ADR-134 'explicit user action'): a compaction that lands for the chat (/compact, palette, Compact now, the hold card's Compact and send, /rewind Summarize) releases the pause and retries once; if the policy is no longer Ask (Automatic or Off) the coordinator releases it the next time it looks (any settle, e.g. the user's next turn). Send without compacting / sending a message is the user's own turn: the agent's results keep waiting (ADR-134 manual continuation). Cancel = do nothing; results stay saved. ## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
An agent wake over the Ask compaction trigger now pauses before acceptance instead of being committed and marked Failed; compacting the chat lets it go on. No new ADR: it is ADR-052's Ask (nothing compacts or sends over the trigger unattended) on ADR-134's pause model (paused work gets no retry timer until an explicit user action). No product choice was needed: an unattended wake never auto-compacts under Ask.

**Measured first (dev 8ae979d81b, real coordinator, ledger, runtime and controller; only the provider network doubled).** The wake was durably accepted, committed its notice and an empty assistant row, and the post-commit Ask block marked the row Failed with 'Conversation context reached its compaction threshold. Run /compact ...'; the wake then completed and consumed its results unseen. A goal iteration on the same over-trigger chat (Ask, custom 1,800-token budget) sent only its handoff: DONE, one provider call, no Failed row, no hold.

**Design.**
- Pause: before the durable accept, Chat/console_compaction_gate.pause_wake_at_ask_trigger runs the composer hold's side-effect-free probe on the wake's request (history plus the notice, as the submit path builds it). Over the trigger the wake is refused before commit: the prepared attempt is aborted (no turn spent), ConsoleFleetWakeCoordinator.pause_at_ask_trigger pauses the chain with the bounded code compaction_ask (durable 'paused', not review-required), the results stay pending, and the unseen mark is set. The run state and an unsaved System row say 'Background agent paused: this chat reached its compaction threshold (N of B tokens; trigger T). Its results are saved. Run /compact and the agent goes on, or send a message to continue yourself.' The fleet section reads 'Paused: context limit. Results saved. Run /compact to continue.'
- Resume: a compaction that lands for the chat (controller compact_context_now, which /compact, the palette, Compact now and the hold card's Compact and send use; and /rewind Summarize) calls release_compaction_pause, which lifts the pause and retries once. Leaving Ask (Automatic or Off) lifts it the next time the coordinator looks (any settle, e.g. the user's next turn). A user's own message, with or without compacting, is their turn: the results keep waiting (ADR-134 manual continuation). A chat still over its trigger pauses again on that one attempt; there is no retry loop (mutation: without the pause the coordinator re-attempted about once a second).
- Goal iteration: no change. The pin fails if a goal iteration ever carries history (mutation: replacing the goal's fresh context with the chat history turns it red), which is when its stop-before-commit must be built.
