## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Chose the neutral-copy branch of AC#1, as the plan advised: local_onnx and local_transformers are in neither `PROVIDER_PARAM_MAP` nor `API_CALL_HANDLERS` (62 keys each, the same set, measured at b2d1e8e20d), so there is no request map to derive their accepted fields from, and inventing entries would claim support no request proves.

- `console_provider_support.provider_request_keys(provider, app_config)`: the one lookup of a provider's `PROVIDER_PARAM_MAP` entry (registry ids decided as their family), or `None`. `supported_generation_fields` now uses it instead of its own copy of the lookup; its answer is unchanged (a provider with no entry keeps the capability answer, TASK-30012 AC#3).
- `console_settings_field_row.generation_field_support`: when `provider_request_keys` is `None`, every shown sampler (and Temperature, Max tokens, Streaming) joins the `unknown` set beside the reasoning and thinking controls, so `_field_help` leads its help line with `GENERATION_CONTROL_UNKNOWN_COPY`. No row is hidden, as before.
- Test (Tests/UI/test_console_settings_hidden_fields.py, whole file in the UI PR census): `test_a_provider_without_a_request_map_says_its_samplers_are_unverified[local_onnx|local_transformers]` mounts the modal at 211x44 under the production stylesheets, asserts no row is hidden, every field row's help starts with the neutral copy and still holds the field's whole help, and the core rows paint both. Red before the fix (`unknown` held only the five controls). `test_unknown_support_stays_visible_with_neutral_copy_in_its_help_line`'s last assertion ("known support keeps the field table's plain help" for Temperature) is rewritten on purpose: it holds for openai and is now the opposite for the unmapped case.
- Docs/User_Guide/console.md says so beside the existing neutral-copy sentence.
