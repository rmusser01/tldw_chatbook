Both nodes pass again. Both causes were in the tests; no production code changed.

(a) `test_create_endpoint_with_live_controller_rebase_settles[*]` (Tests/UI/test_console_endpoint_discovery.py). Cause: its last identity assert compared `provider_key` with the registry id. It was written in #2715 (cef6bd2a3e, 2026-09-18), when a draft's identity kept the owner key there. TASK-32566 (1b02010541, 2026-09-19) gave entry drafts the family execution key in `provider_key` and the dashed registry id in `entry_id`, and the assert was not updated. The test's own probe fake already expects `identity.provider_key == "llama_cpp"`. Rewritten on purpose: the node now asserts `(provider_key, entry_id) == ("llama_cpp", provider_id)`, the same guarantee (the draft addresses the new entry) against the current shape. Every later assert in the node passes unchanged.

(b) `test_settings_redirected_select_click_uses_real_mro_dispatch` (Tests/UI/test_console_modal_dismissal.py). Cause: a harness gap, not a layout defect. `_SettingsMROHarness` loaded only the screen sheets. TASK-33006.1 (caa36e0050) moved the Model view's row grammar into the app bundle (css/features/_console_panels.tcss), so in the harness a field's label took the whole row and the Streaming Select sat one cell wide at the row's right edge: Region(x=120, y=25, w=1, h=2), outside the 100-wide modal. Measured under the production stylesheets, the row is Label 18 | Select 13 | Source 20 | help with the Select inside the modal at 140x60 in the harness frame and at 211x44, 235x52, 140x60 and 100x30 in the production frame, so Phase 7's single control width does not squeeze it. Fix: the harness loads `APP_STYLESHEETS`, as `CoreFirstHarness` does. The click then opens the Select and the modal stays open. The four other nodes on that harness stay green.
