## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Console loss inventory (UI/Console_Modules/loss_inventory.py) counts every transcript message that has no persisted id. Console's own system rows (command output such as /help and /doctor, and error notices) are never persisted, so in a saved chat with nothing else at stake a single /help listing makes Ctrl+Q ask "Quit Chatbook? Temporary or unsaved messages: 1", and tab close shows the same row. This was reproduced through the real system-message seam (_append_native_console_system_message) during the TASK-33628.1 review. The close dialog already behaved this way; TASK-33628.1 AC#3 (quit totals equal the per-tab close sum) carries it into quit. The row's wording also misdescribes command output as a Temporary or unsaved message.

Owner call needed: leave command and notice rows out of both dialogs, or count them under wording of their own.

Owner decision, 2026-10-29: command output and notice rows (/help, /doctor, error notices) do NOT count as loss in the close and quit dialogs. They never trigger the prompt on their own, and when they sit beside real loss the dialogs neither count nor list them.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Console's own SYSTEM rows (command output such as /help and /doctor, and error notices) no longer count as loss in the tab-close or Ctrl+Q dialogs (owner decision 2026-10-29, recorded in the description and AC#1).

Measured first, on origin/dev 8ae979d81b. A probe drove /help, /doctor and a /prefill pin error notice through the real composer in a saved chat (real ChatPersistenceService). Each row is a SYSTEM tree node that the store never saves, and session_close_impact counted every node without a saved id. The live dev build (isolated profile, real claude-haiku-4-5) asked "Quit Chatbook? Temporary or unsaved messages: 1" on Ctrl+Q, and "Close tab "Tab 1"?" with the same row on the ✕, with only a /help row unsaved.

Fix: the one per-tab projection both dialogs share (loss_inventory.session_close_impact) now counts unsaved nodes whose role is not SYSTEM (_is_unsaved_message). Quit still sums the per-tab close impacts, so AC#3 holds by construction, and the mixed tests assert it. The rule is role-based on purpose. Every Console SYSTEM row is the app's own command output, notice or machine note, and Fork already leaves the same rows out (console_fork_skips, ADR-334 §2). SYSTEM rows that are saved never counted anyway.

Tests:

It pins the rows beside a real draft (only "Unsent drafts: 1" / "Unsent draft: yes") and beside a Temporary chat's real user and assistant messages ("Temporary or unsaved messages: 2", only the Temporary tab named, close dialog the same). All 8 cases failed on pre-fix code for the stated reason and pass with the fix.
- New unit case in test_console_session_close_impact.py (4 params, red then green).
