## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Library keeps a per-mode focus memory across the compact/wide crossing and restores it after a
compact-crossing resize, deferred until the layout settles. That deferred restore can move focus or
the caret away from where the user just put them. It happens on origin/dev with the Notes editor
alone, no link picker involved; reproduced 3/3 on both the P1-B tree and origin/dev during the
TASK-34000 P1-B final review (2026-10-23).

Repro:

1. Open a note at 160x45 and resize the terminal to 80x24.
2. Click the body, then press Tab. Focus is now on the compact Back button (`library-note-back`).
3. Resize to 160x45 and click the body.
4. Resize to 80x24. Within about 110 ms the deferred restore re-focuses Back.
5. Press Enter. This presses Back and closes the editor.

Companion: a key typed about 50 ms after a compact-crossing resize lands in the body, and the deferred
restore then moves the caret back to its pre-resize spot (8/8 at +50 ms), so the next keys land where
the user was, not where they are.

Both shapes were first seen in TASK-34000.11 fix round 5 (`fr5_probe_seq.txt`, `fr5_probe_tab.txt`);
its resize pins re-click the body and count calls rather than asserting where focus ends, which is a
test-side workaround, not a fix. Nothing in code references this task.
