## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Added thread=True to the run_worker call that enumerates audio devices (audio_troubleshooting_dialog.py:246).

_get_devices_safe is a plain def. Textual's Worker._run_async raises WorkerError('Request to run a non-async function as an async worker') for a non-coroutine target, Worker._run catches it generically, and exit_on_error defaults to True -- so opening the dialog exited the app. Reachable from the shipped stts route via the dictation window. The call also blocks on device enumeration, so a thread worker is the right shape independently of the crash.

Regression test: Tests/Widgets/test_audio_troubleshooting_dialog_worker.py asserts, per run_worker call site in the module, that a non-coroutine target declares thread=True. It fails on the pre-fix source at line 246 and correctly skips the sibling call at :226, which passes an already-created coroutine from an @work-decorated async method -- the same shape that produced a false positive in the review's own first enumeration.

Not changed: the :226 call site. Passing an already-called @work coroutine to run_worker is odd but not this defect; left for the wider guard in TASK-32800.4.
