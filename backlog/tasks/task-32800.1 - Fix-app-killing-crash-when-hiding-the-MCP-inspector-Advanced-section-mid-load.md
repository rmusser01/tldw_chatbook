## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Clicking 'Advanced...' and then 'Hide advanced' while the section load is still in flight takes the whole app down. `_load_advanced_section` dereferences `#mcp-adv-content` after awaiting `load_section()`, `_hide_advanced` has already removed that subtree, and nothing cancels the worker -- `exclusive=True` only cancels another worker in the same group. `exit_on_error` defaults to True, so the `NoMatches` becomes a process exit. The toggle is re-enabled before the load is scheduled, so the window is the whole round trip.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Guarded the post-await DOM dereference in _load_advanced_section (mcp_inspector.py:3417-3430).

After 'payload = await self._service.load_section(section)', the method updated #mcp-adv-content and then called _refresh_advanced_actions(), which itself does three more unguarded query_one calls. _hide_advanced() removes the whole Advanced collapsible, and the reveal toggle is re-enabled BEFORE the worker is scheduled, so the window is the entire round trip. exclusive=True does not help: Textual's exclusivity cancels another worker in the same group, never the running one. The await therefore resumed into a removed subtree, raised NoMatches, and exit_on_error (default True) exited the app.

Fix: after the await, query() for #mcp-adv-content and return if it is gone. Everything below that point belongs to the same subtree, so one guard covers both the content update and the action refresh.
