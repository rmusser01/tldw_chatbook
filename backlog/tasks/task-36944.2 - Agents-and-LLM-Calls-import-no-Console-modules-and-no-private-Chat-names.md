## Implementation Notes

- New test `Tests/Architecture/test_agents_chat_boundary.py`: 29 frozen `(importer, console module, reason)` rows; one test fails on a pair not in the list, one on a listed pair no longer imported, one on any underscore crossing (from-import, attribute read, getattr) in either direction.
- Underscore crossings found and fixed (13 names): Agents->Chat `_custom_endpoint_missing_key_readiness`, `_apply_custom_endpoint_engine_swap` (renamed public in place, no alias needed, no other private users); Chat->Agents `_count_model_messages`, `_spawn_override_targets`, `_coerce_autowake_enabled`, `_budget_weighted_tokens`, `_coerce_max_live_subagents`, `_coerce_retained_transcripts`, `_coerce_retained_transcript_max_chars`, `agent_service._setting`, `run_log._setting`, `mcp_tool_provider._controller_factory_current`, `._console_preparation_pipeline_current`.
- `agent_service.py` is size-pinned, so its public spellings live in `Agents/agent_service_public.py` (same function objects; `setting` delegates to `agent_service._setting` per call so the test pins on it still reach Console). `run_log.setting` and the two `mcp_tool_provider` names are renamed in place with `_x = x` aliases; mcp_tool_provider's in-module callers and its provenance tuple use the public names, and the one patch (`test_console_optional_app_services`) was retargeted. `test_console_personal_context_snapshot` now patches `agent_service_public.count_model_messages`, which the bridge reads live.
- RED: appending `from tldw_chatbook.Chat.console_runtime import x` to `Agents/run_log.py` failed the new-import test; commenting out the `groq` console import failed the stale-row test; importing `_setting` in `console_fleet_wake` failed the underscore test. All reverted.
