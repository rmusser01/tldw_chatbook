## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the PR #2939 checkpoint review; pre-existing (reproduces identically at merge-base 75c06af39a, at 69a9da95cc and at 4006b9da9a). Regenerating a reply whose request is over the compaction trigger is refused with 'Conversation changed before compaction could start.' This happens with a working summarizer and no compaction pause in effect. _compaction_admission succeeds, but _automatic_memory_admission returns None: the durable lineage ends at the user turn, while the active leaf is the forked sibling that has not been saved yet. So a user on a long chat cannot regenerate at all, and the copy blames a change they did not make. Once this is fixed, regenerate also reaches the Continue/regenerate retry-fence path that TASK-33621.3 (PR #2939) touches, so the fix must be verified together with it. Evidence: scratchpad logs TT-2939-review-probe-regen-{base,post}.log, TT-2939-review-probe-regen-why.log.
