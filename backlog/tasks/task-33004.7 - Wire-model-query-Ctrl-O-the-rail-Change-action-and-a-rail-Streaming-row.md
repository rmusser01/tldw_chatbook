## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
This subtask absorbs task-338.

/model is registered with an empty argument hint (Chat/console_command_grammar.py:110). _console_command_run_action calls the mapped action (UI/Screens/chat_screen.py:19211) with no argument (:19362-19383), so '/model son' ignores 'son'.

The rail Model section (UI/Console_Modules/left_rail.py:2263-2410) shows Temperature and Max tokens but not Streaming. Commit 0c26a8408 dropped it (task-338). The summary state carries structured temperature and max_tokens values but no structured streaming value (Chat/console_session_settings.py:763-783). The section's updater (_apply_console_settings_summary_state, chat_screen.py:9384) already writes only ids that are composed: TASK-32811.7's fix is on dev even though that task still reads In Progress.

The rail's 'Configure' action (left_rail.py:2397-2403, routed at chat_screen.py:24608 and :25055) opens the full modal. The synthesis renames it 'Change  Alt+M' so the rail teaches the switcher key. That removes the rail's direct entry to Chat settings, and the spec gives Chat settings its own Console key, Ctrl+O. No Ctrl+O binding exists anywhere in the app today, and the spec asks for a live check that the terminal delivers it.

The palette entry 'Console: Change model…' (UI/console_command_provider.py:42-46) still describes a provider and temperature form.

Constraints: ADR-083:20-22 caps the Model section's natural height at 15 rows, and chat_screen.py has 32 lines of headroom.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
`/model [query]`, Ctrl+O, the rail's Change action and a rail Streaming row are wired. The footer, F1, palette, slash popup and the Provider/Model chips teach Switch model (Alt+M) and Chat settings (Ctrl+O).

**What changed**
- `/model [query]` (AC#1, AC#7). `CONSOLE_ACTION_COMMANDS` gives `model` the hint `[query]`, so `/help` lists `/model [query]`. The shared action runner passes `parse.args` only to a command that declares a hint (`/new son` still opens a tab), and `chat_screen.py` has no `/model` branch. `open_model_switcher(screen, query)` in `UI/Console_Modules/model_switcher.py` hands the stripped query to the switcher's new `query` kwarg. The kwarg pre-fills Find, so the first rank highlights the best match. Only Enter applies.
- The runner now clears the composer before it runs an action command. This is the documented handled-command convention (`_clear_console_composer_draft`). Before, `/model son` stayed in the composer after Enter applied.
- Rail (AC#2 to AC#4). `ConsoleSettingsSummaryState.streaming` ("On"/"Off") joins the structured `temperature`/`max_tokens`. The left rail composes a Streaming row with the same classes, and `_apply_console_settings_summary_state` writes it. The section action reads "Change  Alt+M" under its kept id `console-model-section-configure`, and its route (both `on_button_pressed` copies) opens Switch model.
- Ctrl+O (AC#5). A `ChatScreen` binding to the existing guarded `open_console_session_settings` action, which ends in `_open_console_settings` (R9). It adds no method.
- Copy (AC#6, ADR-031 rule 4):
  - The footer adds "Alt+M switch model" and "Ctrl+O chat settings" right after F1 help, in mockup (a)'s order.
  - F1's Global group lists Alt+M, `/model [query]` and Ctrl+O.
  - The palette entries are "Console: Switch model…" (Alt+M) and "Console: Chat settings…" (Ctrl+O).
  - The slash descriptions name both surfaces.
  - The Provider/Model chips' tooltip adds "Enter: Switch model (Alt+M) · Chat settings (Ctrl+O)", and their Enter/Space binding text reads "Switch model".
