## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ADR-036 keeps `TldwCli` as the composition root and defers a typed immutable services bundle until there is more than one real composition root. MCP's standalone server, the mobile web service and config's lazy singletons now each compose their own databases. **Owner decision (2026-10-25): adopt the bundle.** It is a frozen, typed services bundle grouped per feature, built once in `app_service_wiring`. Consumers receive their slice through their constructors. Existing app attributes stay as aliases during migration. The standalone MCP server, the mobile web service and CLI tools such as `doctor` build their services through one shared factory instead of constructing databases ad hoc. There is still no DI container and no mutable registry. This task writes that decision up as an ADR (an ADR-036 amendment or a successor under the next free number) for the owner to accept. It does not implement the bundle.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F1; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Wrote `backlog/decisions/250-application-services-bundle.md` with status **Proposed**, and added its row to `backlog/decisions/README.md`. The ADR writes no code; TASK-36947.2 implements it once the owner accepts it.

- **Number and form:** a successor ADR that amends only ADR-036's deferral sentence. The rest of ADR-036 is unchanged, so it keeps its accepted record. ADR-036 is not edited until the owner accepts.
  - The ADR was first numbered 244. The coordinator renumbered it to 250 after review: 244 to 249 already appear on local or remote branches, 250 appears on none, and gaps are allowed.
  - On acceptance, set ADR-250 to Accepted, set ADR-036 to "Accepted; amended by ADR-250 (deferral clause)", and update both rows in the decisions README.
- **AC#2:**
  - Shape (section 1): a frozen, typed `ApplicationServices`. Each feature is a slice, and `ScopedServices` (with `local=None` by default) covers 15 local/server/scope trios and 20 server/scope pairs.
  - Grouping (section 2): a table of the main slices plus five rules for the rest. The exclusions are named: objects built around the app, configuration reloaded at runtime, UI state, and services built after composition (lazy properties, `on_mount`, first-use opens, rebuilt wiring, and the pinned skills stack).
  - Construction (section 3): composition is unchanged. The bundle is assembled once from today's attributes by `ServiceWiringMixin._publish_application_services()`, and the assembly code lives in `app_services.py`.
  - Teardown (section 5): the TUI keeps its unmount sequence. `ProfileStorage.close()` is for the other roots, and the mobile engine quiesces its chat database first.
  - Aliases (section 4): the app attributes are the aliases. The alias list only shrinks, an alias is deleted once a repo-wide scan finds no remaining reader, and there is no date.
- **AC#3:** section 6 gives the `open_profile_storage` signature and the openers, with one row per entry point.
- **AC#4:** section 8 rules out a DI container, a registry or locator, a lifecycle framework, and replacing services while the app runs.
- **Review round 1:** fixed every finding (I1 to I6, M1 to M6). These changed the design:
  - **Storage:** it is assembled after the late ChaChaNotes and Prompts assignments, so nothing is reordered.
  - **Lazy members:** the `Lazy` cell is gone. Today's lazy members behave differently from each other, so each one stays on the app until its consumer migrates.
  - **Skills:** the skills stack stays out of the bundle, because the Console's off-loop trust proof checks it.
  - **No app references:** this is now an end-state rule. Today's members that capture the app are listed and left alone in TASK-36947.2.
  - **Aliases and teardown:** both keep reading today's attributes, so tests that build a bare or fake app still work.
  - **Late services:** the services composed in `on_mount` or opened on first use are named.
  - **Open questions:** five, each a yes/no question with a recommendation.
- **AC#1 is not met:** it needs the owner to accept the ADR, so the task stays In Progress.
- **Verification:** `scripts/preflight.sh`, run through the scratch-profile wrapper, passed every derived-artifact check after each round. No tests were added, because the change is documentation only.
