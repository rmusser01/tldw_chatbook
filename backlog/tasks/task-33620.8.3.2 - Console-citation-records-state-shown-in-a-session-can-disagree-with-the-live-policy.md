## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in TASK-33620.8.3's review. Two in-session views read something other than the live citation-records policy:

1. After **Keep records** then **Don't keep** from the palette in the same session, the repository keeps its loaded fingerprint codec, so `fingerprint_key_state` still reports `ready` while writes are disabled. Capture fails closed (`local_citation_writes_ready` checks the policy) and terminal persistence falls back, so nothing is written, but the Cited sources window does not show the records-off copy until a restart. Before TASK-33620.8.3 no path could load a codec while records were off.
2. If saving an answer fails, the session keeps the answer, but the palette entry's text is built from the saved file, so after an unsaved **Keep** it says "Citation records are off for this profile" while they are on.

Reordering `fingerprint_key_state` to check the policy first is not a drop-in fix: `citation_counts` treats some key states as unverifiable and would start marking counted replies.
