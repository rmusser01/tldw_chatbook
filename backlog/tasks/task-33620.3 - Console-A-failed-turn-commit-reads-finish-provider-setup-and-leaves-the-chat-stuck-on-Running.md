## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** A send in a conversation with no `console_conversation_library_policy` sidecar row failed inside durable commit. The log shows 'Durable turn commit failed; turn refused (exception_type=RuntimeError)', phase=durable_commit status=failed, raised from `chat_persistence_service.py:1507-1525` when the policy row is None. The UI then stayed like this for more than 3 minutes:
- the user message with no assistant row;
- header 'Running';
- composer 'Send blocked — finish provider setup to continue ›' next to 'Preparing...';
- queue shelf 'Unsent turn needs attention';
- the quit dialog counting the chat as 'Live agent runs: 1'.

The provider was configured correctly throughout. So users are sent to fix a provider setup that isn't broken, and the chat looks stuck running forever. Any legacy or imported conversation without the sidecar row would take the same path.

**Severity / prior art.** P1; the reviewer rated it P2. NEW, with no prior art. It was found by a single reviewer and was **not** run through the live, code and skeptic verifiers; re-confirm the repro before implementing. It is another case of a failure travelling in the setup-blocked slot (Theme 0; the umbrella task owns typed blocker codes). The turn-lifetime owner is ADR-094.

**Suggested direction.** Map durable_commit failures to their own display state ('Turn not saved — nothing was sent', with Retry and Copy draft). End the Running and Preparing state for the owning session. Backfill or lazily repair a missing sidecar policy row on open, instead of refusing the turn.
