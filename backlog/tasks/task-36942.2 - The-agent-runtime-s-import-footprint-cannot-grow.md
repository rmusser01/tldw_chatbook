## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`Agents/agent_runtime.py:400-404` documents itself as a pure module with no Textual, app, DB or I/O imports. A fresh-interpreter probe shows importing it loads `textual`, `httpx`, `sqlite3`, `DB.ChaChaNotes_DB`, `Chat` and `config` (207 tldw_chatbook modules). Three import chains cause it:
- `agent_runtime.py:22` and `project_instruction_runtime.py:15` import `EPHEMERAL_ORIGIN_KEY` from `Chat.console_project_instructions`, which imports httpx (`:12`) and runs `Chat/__init__`, which loads the DB.
- `agent_runtime.py:23` and `agent_models.py:24/:28` import Chat provider modules, which also run `Chat/__init__`.
- `project_instruction_runtime.py:40` imports `tool_catalog`, whose built-in provider chain reaches `RAG_Search`, `config`, the DB and `UI.destination_recovery`.

Even with `Chat/__init__` treated as empty, the static closure is 188 modules. The fix needs the provider-type move, a neutral home for the constant and a tool-catalog decoupling, all tracked separately. This task only stops the footprint growing meanwhile. `agent_models`' existing purity test scans source text; it is not an import check.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F5; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
