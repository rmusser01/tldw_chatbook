## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Two ingest stylesheets remain in the CSS bundle after the standalone ingest window was deleted: they style that window's forms and tab strip, and sampling their selectors finds almost none still referenced from Python. They are harmless where they are -- unused selectors cost nothing at runtime -- but they are dead weight that misleads anyone reading the bundle for what the ingest UI looks like. Removing them is deliberately separate from the window deletion because they are part of the generated bundle, so a removal needs the bundle regenerated and the remaining ingest surface eyeballed for any selector that turns out to be shared.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The bundle no longer carries stylesheets whose only consumer was the deleted ingest window
- [x] #2 Any selector still used by a live surface keeps its styling
- [x] #3 The bundle is regenerated by its build script rather than hand-edited

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
One of the two sheets was dead; the other was not, and the task's premise about it was wrong.

_ingest_tldw_api_tabs.tcss (82 lines) is retired. Every distinctive selector it carried has zero mount sites: #tldw-api-tabs, #tldw-api-tabbed-window, #ingest-view-tldw-api, .ingest-form-scrollable, .ingest-status-area, .ingest-submit-button, .tldw-api-media-specific-options.

_ingest.tcss (613 lines) is NOT dead and stays. It still styles the prompt, character and note ingest handlers, which are live Library features and were never part of the retired media window -- #ingest-prompts-preview-placeholder, for one, is created by prompt_ingest_events.py today. The task assumed both sheets were dead weight; only one was.

The shared-selector check this task exists for caught a real trap. Two generic classes in the retired sheet are used elsewhere: .hidden is scoped there to the dead #tldw-api-tabs and is defined by other sheets anyway, so nothing is lost -- but .window-title is UNSCOPED and that sheet held the only bundled definition, while ChatbookExportManagementWindow, ChatbookTemplatesWindow and Voice_Cloning_Window all mount it. Deleting outright would have silently unstyled three live windows. The rule is relocated to components/_shared_components.tcss with a note explaining why it lives there.

Verified: bundle regenerated by build_css.py, never hand-edited. The only top-level selectors it lost are the three dead ingest ids; .window-title is present with its rule intact. Bundle 15072 -> 15001 lines. The app boots with zero stylesheet errors and reaches its startup summary.

Also noted for follow-up, not fixed here: app.py queries #ingest-window in two places, an id nothing creates since the window was deleted -- dead queries rather than a styling problem.
