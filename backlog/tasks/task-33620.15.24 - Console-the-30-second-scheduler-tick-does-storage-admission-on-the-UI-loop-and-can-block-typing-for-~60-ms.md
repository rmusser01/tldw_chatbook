## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the 2026-10-26 re-profile of Console typing latency (dev 0d7e418db1, live, Anthropic claude-haiku-4-5, 160x45, 24 sends). The scheduler loop's 30-second tick runs a storage-admission check on the UI loop (Scheduling/scheduler/loop.py around the tick's admission call, reaching Backup_Recovery/activation.py). When it lands while the user is typing or right after Enter it blocks keyboard input for about 58 ms; it hit 1 of 24 send windows. With the other post-acceptance blockers fixed (longest callback after acceptance now median 35 ms, max 60 ms), this tick is the largest single remaining pause in that window.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Summary: every storage admission the scheduler loop takes for itself, plus the tick's emergency-stop path lookup, now resolves off the UI loop. A tick's UI-loop cost while typing or right after Enter fell from a longest callback of 16.4 / 30.0 / 70.4 ms (median / p90 / max, 9 of 20 ticks at 20 ms or more) to 0.35 / 0.64 / 1.08 ms (0 of 20), paired live at the same load.

Approach
- One async seam, SchedulerLoop._admitted, replaces the three synchronous 'with _maintenance_operation(), execution_scope(...)' sites: run()'s startup scope, its per-tick scope, and _admitted_dispatch (tick, dispatch_reminder, run_reminder_now). The maintenance fence is still entered on the loop. It does no I/O, so a closed fence still refuses at once. _OffLoopExecutionScope enters and releases execution_scope on worker threads through _offload. The maintenance drain owns those hops even after their awaiter is cancelled.
- Semantics kept: the body awaits admission, so no job runs before it resolves. A refusal still yields False, and run() still returns on a refused tick scope. Ticks stay sequential. If a release overtakes an entry still in flight (cancellation), the entry closes the lease it acquired itself.
- Found live after the first change: _emergency_stopped resolved default_emergency_stop_path() on the loop. get_user_data_dir() is a guarded config read that enters storage admission for the config participant; one tick spent 98 ms (44 ms CPU) there. The import, the lookup and the read now run in one _offload hop, and the fail-safe (doubt reads as stopped) is unchanged.
- Trade-off: the admission now costs 8-129 ms of wall time on workers (GIL waits at load 25-40), and a tick's own span grew slightly. Nothing waits on a tick; the poll is every 30 s.

Tests (Tests/Scheduling/test_scheduler_tick_admission_off_loop.py, 6 tests, all RED on origin/dev 3be493413a)
- Each test holds the REAL execution_scope (or the stop-path lookup) on a threading.Event and releases it from the event loop. A loop-side admission can only time out, which is the RED. Each test also pins one semantic: no dispatch before admission, a refusal stops the scheduler and consumes nothing, no overlap or pile-up of slow ticks, cancellation with admission in flight (prompt exit, the drain owns the hop, the lease is released rather than garbage-collected), and a refused stop lookup holds dispatch.
- Negative controls, each Edit-applied and Edit-restored:
  - enter on a joined thread (the loop blocked): 4/4 red.
  - release on the loop: red (exit thread).
  - entry ignoring a prior release: red (finalized by GC, not released). This control first SURVIVED: generator finalization closed the leaked lease, so the test now asserts no scope is closed by GeneratorExit.
  - plain to_thread instead of _offload: red (the drain does not wait).
- test_failed_queue_load_never_acknowledges_covered_reload_token synchronized on 'running'. The initial load now starts after admission resolves off the loop, so a request made at 'running' is covered by the successful initial load. The test now waits for that load.
