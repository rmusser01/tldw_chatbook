## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Ctrl+Q on Roleplay now asks the same aggregate Save and continue / Discard and continue / Stay question that leaving the screen asks, and a failed save goes through the Retry / Stay recovery dialog instead of quitting.

Approach
- New `tldw_chatbook/UI/Persona_Modules/roleplay_draft_guard.py` holds the aggregate draft guard: `confirm_navigation`'s flow plus its save, await-owners and domain-naming helpers, moved verbatim from `personas_screen.py`. The flow takes an `ask` (how one prompt is awaited) and never pushes a screen itself.
- `PersonasScreen.confirm_navigation` passes `push_screen_wait`, so navigation is unchanged. The new `PersonasScreen.confirm_quit` calls `confirm_roleplay_quit`, which awaits both dialogs through `await_quit_prompt(no_answer=None)`. A prompt that vanishes unanswered is therefore Stay, with the "Quit cancelled." toast.
- Both hooks import the helper lazily, so it stays off the boot path (the ui-ready census and boot CSS budget pass unchanged).
- `personas_screen.py` drops from 16,533 lines to 16,397. dev was already 97 lines over its 16,436 ratchet row, so that row was red before this change. The row is lowered to the new measurement.
- `Tests/Architecture/test_quit_flow_prompt_choke_point.py` now also scans every function in the helper. The scan cannot follow `confirm_quit` there through `self.`. It also requires the scan to reach `PersonasScreen.confirm_quit` and the helper's two entry points, and it gains a negative control.

Tests
- `Tests/UI/test_roleplay_quit_guard.py` (bootstrap_profile) drives the real TldwCli, the real Ctrl+Q and the real Roleplay editor. Only the character store is stubbed and the shutdown is recorded. It has 7 tests: ask + Stay/Escape keeps the draft; Discard quits without saving; Save saves then quits; a failed save shows Recovery, Retry fails again, Stay keeps it, and after recovery Save quits; a vanished question or recovery prompt is Stay; a clean editor quits without asking.
- On pristine origin/dev, 6 of them fail with "Ctrl+Q quit straight past the unsaved Roleplay draft", plus the choke-point reach test. The clean-quit case passes on dev, as it should.
- Mutation check: a bare `push_screen_wait` in the quit path fails both vanish tests and the static scan.

Other changes
- The diagnostic inventory was regenerated after reading `--statements`. The one moved warning ("Could not present aggregate Roleplay navigation guard") is verbatim and static.
- User Guide: the Roleplay page's "Leaving with unsaved edits" section and the index Ctrl+Q row now cover this.

Not gated on PRs
- The new Pilot file uses bootstrap_profile, so it cannot join `scripts/ui_pr_gate_census.txt` (that slice is sandboxed). The architecture scan is not on the PR fast lane either. This is the same as the existing `test_app_quit_under_modal.py`.
