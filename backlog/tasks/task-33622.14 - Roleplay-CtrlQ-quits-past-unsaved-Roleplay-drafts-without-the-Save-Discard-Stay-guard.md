## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Ctrl+Q on Roleplay now asks the same Save and continue / Discard and continue / Stay question as leaving the screen. A failed save goes to the Retry / Stay recovery dialog instead of quitting. If a Roleplay save or reaction generation is still running, Ctrl+Q first says what it is waiting for.

Approach
- New `tldw_chatbook/UI/Persona_Modules/roleplay_draft_guard.py` holds the aggregate draft guard: `confirm_navigation`'s flow plus its save, await-owners and domain-naming helpers. They were moved verbatim from `personas_screen.py` and then ruff-formatted, with no behaviour change. The flow is handed an `ask` (how one prompt is awaited) and never pushes a screen itself.
- `PersonasScreen.confirm_navigation` passes `push_screen_wait`, so leaving the screen is unchanged.
- The new `PersonasScreen.confirm_quit` calls `confirm_roleplay_quit`, which awaits both dialogs through `await_quit_prompt(no_answer=None)`. A prompt that vanishes unanswered is therefore Stay, with the "Quit cancelled." toast.
- Review follow-up (AC #5): the guard waits for in-flight Roleplay work before asking. On the quit path that wait was silent, and a second Ctrl+Q did nothing because the quit was already in progress. `confirm_roleplay_quit` now shows "Waiting for Roleplay work to finish before quitting: <domains>." when it has to wait. Leaving the screen is unchanged.
- Both hooks import the helper lazily, so it stays off the boot path.
- `personas_screen.py` goes from 16,533 to 16,397 lines. dev was 97 over its 16,436 ratchet row, and the row is lowered to the new number.
- The quit-flow choke-point scan now covers the helper and must reach `confirm_quit` and the helper's entry points. It gains a negative control.

Tests
- `Tests/UI/test_roleplay_quit_guard.py` (bootstrap_profile) has 8 real-app Pilot tests. On origin/dev (bb865f5cfe), 7 of them fail with "Ctrl+Q quit straight past the unsaved Roleplay draft", as does the choke-point reach test; the clean-quit case passes there, as it should.
- The waiting-notice test also fails on the first fix commit, d34ff51d81, before the notice was added.
- Mutation check: a bare `push_screen_wait` in the quit path fails both vanish tests and the scan.
- Compared with an origin/dev base worktree, there are no new failures:
  - quit-flow, architecture and inventory suites, plain;
  - Roleplay and navigation suites, both plain and with a scratch bootstrap plugin, including `test_personas_workbench` in full.

Other changes
- Diagnostic inventory regenerated after reading `--statements`; one warning moved verbatim.
- User Guide: the Roleplay "Leaving with unsaved edits" section and the index Ctrl+Q row are updated.

Live (160x45, isolated profile)
- With a dirty draft, Ctrl+Q asks. Stay keeps the draft.
- Save and continue exits, and the name is saved on relaunch. Discard and continue exits, and the draft is gone on relaunch.
- A clean editor quits without asking.
- On dev, Ctrl+Q quit with no prompt and the draft was lost.
- I re-checked on the final commit. The waiting notice was not driven live because it needs a reference-image backend that is generating; the Pilot test covers it.
