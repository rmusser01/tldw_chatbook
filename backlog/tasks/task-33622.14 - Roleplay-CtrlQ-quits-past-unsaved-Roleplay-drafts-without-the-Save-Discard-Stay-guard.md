## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Ctrl+Q on Roleplay now asks the same aggregate Save and continue / Discard and continue / Stay question that leaving the screen asks. A failed save goes to the Retry / Stay recovery dialog instead of quitting. If a Roleplay save or reaction generation is still running, Ctrl+Q says what it is waiting for before it asks.

Approach
- New `tldw_chatbook/UI/Persona_Modules/roleplay_draft_guard.py` holds the aggregate draft guard: `confirm_navigation`'s flow plus its save, await-owners and domain-naming helpers, moved verbatim from `personas_screen.py` (later ruff-formatted, no behaviour change). The flow takes an `ask` (how one prompt is awaited) and never pushes a screen itself.
- `PersonasScreen.confirm_navigation` passes `push_screen_wait`, so leaving the screen is unchanged. The new `PersonasScreen.confirm_quit` calls `confirm_roleplay_quit`, which awaits both dialogs through `await_quit_prompt(no_answer=None)`. A prompt that vanishes unanswered is therefore Stay, with the "Quit cancelled." toast.
- Review follow-up (AC #5): before asking, the guard waits for in-flight Roleplay work (a form save, or a reaction generation holding the visual-identity operation). On the quit path that wait was silent, and a second Ctrl+Q did nothing because the quit was already in progress. Before this branch Ctrl+Q quit at once, so the silence was new. `confirm_roleplay_quit` now shows "Waiting for Roleplay work to finish before quitting: <domains>." when it has to wait. Navigation is unchanged.
- Both hooks import the helper lazily, so it stays off the boot path (the ui-ready census and boot CSS budget pass unchanged).
- `personas_screen.py` drops from 16,533 lines to 16,397. dev was already 97 lines over its 16,436 ratchet row, so that row was red before this change. The row is lowered to the new measurement.
- `Tests/Architecture/test_quit_flow_prompt_choke_point.py` now also scans every function in the helper. The scan cannot follow `confirm_quit` there through `self.`. It also requires the scan to reach `PersonasScreen.confirm_quit` and the helper's two entry points, and it gains a negative control.

Tests
- `Tests/UI/test_roleplay_quit_guard.py` (bootstrap_profile, passes under the plain command) drives the real TldwCli, the real Ctrl+Q and the real Roleplay editor. Only the character store is stubbed and the shutdown is recorded. It has 8 tests: ask + Stay/Escape keeps the draft; Discard quits without saving; Save saves then quits; a failed save shows Recovery, Retry fails again, Stay keeps it, and after recovery Save quits; a vanished question or recovery prompt is Stay; in-flight work over a dirty draft shows the waiting notice, asks nothing until the work finishes, then asks; a clean editor quits without asking.
- On origin/dev (bb865f5cfe), 7 of them fail with "Ctrl+Q quit straight past the unsaved Roleplay draft", plus the choke-point reach test. The clean-quit case passes on dev, as it should. The waiting-notice test also fails on the pre-follow-up commit (d34ff51d81) with "timed out waiting for Ctrl+Q to say what it is waiting for".
- Mutation check: a bare `push_screen_wait` in the quit path fails both vanish tests and the static scan.
- No new failures against an origin/dev base worktree: the quit-flow, architecture and inventory suites, and the Roleplay/navigation suites both plain and under a scratch bootstrap plugin (test_personas_workbench, test_personas_expression_slots, test_roleplay_character_conversation_browse, test_roleplay_recovery_layout, test_screen_navigation, test_screen_residency). The only difference is the personas ratchet row, which this branch turns green. One test_screen_navigation case swapped between runs; run alone it fails on both sides.
