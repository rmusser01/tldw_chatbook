## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** This breaks the promise that 'each tab runs its own agent'. With a run live in tab B, the reviewer clicked tab A and typed a prompt; pressing Enter 1.5-2.2 s later queued it into B each time (B's tab showed 'Q1'), and B answered it. A received nothing. In one trial the screen already showed A (highlighted tab, A's transcript) at the moment of Enter. The composer, however, still held B's leftover draft, and the merged 68-character text 'Reply with the single word ECHO.Count from 1 to 20 in Swedish words.' was sent to B as one turn. The click is acknowledged late: during a run B stayed highlighted for over 2.6 s and the view flipped about 4.4 s after the click (about 2-3 s when idle). Idle, text typed 0.4 s after a tab click was lost from both composers, and its 'y' opened Trace. The prompt runs with the wrong chat's context, tools and approval authority, spends tokens, and nothing on screen reveals it. Reproduced 3/3 on dev 64579cce2c at 235x52 with a slow proxy. Verdict severity P1; the reviewer rated it P0.

**Cause (verifier-corrected).** The finding blamed `await begin_manual_read_visit` in session.py, but moving that alone will NOT fix this. `_activate_native_console_session` relies on the coalescable console-sync pass to rebind the composer. When a pass is already running (routine during live runs), the call only sets a 'sync requested' flag. The in-flight pass already synced the draft to the old session, then paints the new session's tabs and transcript. Enter then pins the send to the stale visible-draft session id.

**Severity / prior art.** P1, triage NEW. Related: session.py read-visit seam added in d6e2a46384 (PR #2725) under TASK-32826 (In Progress). TASK-26834 (To Do) covers switch latency only, not misrouting. TASK-14808 (Done).

**Suggested direction.** Bind the composer to the new session synchronously as part of activation, saving the old draft to its owner and loading the new one, before any await and independent of the sync pass. Update the tab highlight in the same step. In the send path, refuse visibly and keep the draft when the composer's bound session differs from the active tab. Keep typed keys going to the composer during a switch, so tab-button focus cannot route letters to single-key bindings. Coordinate with TASK-26834 and TASK-32826.

Evidence: qa/console-ux-review-2026-09-29/findings.md → GAP1-01; evidence/evidence__GAP1__38-A-transcript-leak.txt, evidence/evidence__GAP1__57-A-two-runs.txt, evidence/evidence__GAP1__59-B-spanish-landed.txt, evidence/evidence__GAP1__40-B-clicked-window.ansi, evidence/evidence__GAP1__30-type-during-switch-toA.txt

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Summary: a session-tab activation now binds the composer to the clicked chat before its first await (old draft saved to its owner, new draft loaded, tab highlight + header title moved, composer focused), independent of the coalescable console-sync pass. Enter, the Send button and the spoken send refuse visibly ('Still switching chats, so nothing was sent. Your draft was kept.') when another chat's tab or transcript is already on screen while the composer is still bound elsewhere. Session-tab buttons no longer take focus on click (FOCUS_ON_CLICK = False), so keys typed after a click stay in the composer.

Approach / decisions:
- session.py: _claim_manual_read_visit (sync claim, computed before the switch so TASK-32826 same-conversation semantics hold) split from _read_claimed_visit (awaited after the switch); _bind_composer_to_active_session; refuse_send_from_unbound_composer. console_session_surface.py: show_active_session, highlighted_session_id, FOCUS_ON_CLICK = False. send_acknowledgement.request_visible_send and ChatScreen.handle_console_send_message call the guard. test_console_archive_recovery_boundaries' activation fake updated for the new call order (red on dev since PR #2725).
- Guard boundary (deviation from plan step 4, added as step 7): comparing the composer's chat with store.active_session_id alone refused TASK-4's fresh-profile first send (a display rebuild creates a blank active session while the composer still shows its own chat); test_console_fresh_profile_first_send_resolves_real_session_not_sentinel went red at eea28322af. The guard now refuses only when the active chat is already painted (highlighted tab or _last_native_transcript_session_id); until then the composer's chat is the one on screen and the send goes there (AC#2).
- The refusal's logger.warning (two session ids, no user content) was read with check_persistent_diagnostic_inventory.py --statements and recorded with --write.

Tests: Tests/UI/test_console_tab_switch_binds_composer.py (6 mounted tests on the real ChatScreen + store; all 6 red on origin/dev 0c3ebc6ed7 for the right reason -- dispatch to B with B's leftover merged, B still highlighted, Trace opened, focus on the tab button, refusal absent; all green on the branch).
