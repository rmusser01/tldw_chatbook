## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
When setup hands over to Console, the first minutes undercut a provider that actually works.
- Every successful 'Start chatting' raises a false 'Provider settings changed before Console opened. Review setup and try again.' (8 of 8 runs) and leaves the handoff pending.
- The first chat can ask for approval to use the app's own internal chat_with_llm tool, right after the Summary said 'Tools — all off'.
- Plain chat with a local model carries a ~20.8 KB agent preamble that lists 16 tools.
- A refusal before dispatch reads as jargon under a 'Response accepted; waiting for dispatch' panel, with no way to fix it.
- Provider failures drop the provider's own reason: 'API key expired.' becomes 'authentication failed'. Stalls read as 'unexpected provider error'.
- A cold local model shows 90 s of unchanging 'Generating…' before it fails.
- An intermittent trace failure blocks the first send with copy that contradicts itself.
- Arrival stacks toasts over the nav bar, including 'completed while hidden' while Console is on screen, and the status chips say 'Agent blocked' and 'Context unknown'.

This task implements part of SF1 in Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md. It covers the handoff and tool-catalog items of the finish routine (step 4), first-reply failures that name the cause and the fix (step 5), and the calm arrival (step 6). It takes enhancement E10's startup attention queue only where that removes stacked first-run toasts. It resolves entry-exit-handoff-03, -04, -05, -06, -22, -24, new-entry-exit-handoff-01, -02, gap-06 and gap-07. TASK-34100.2's catalog repair makes the capacity refusal rare; this task makes it actionable when it does happen. Two things are out of scope. A first-run arrival profile (collapsed rail, a receipt line instead of toasts) is design work. Whether the built-in tldw_chatbook MCP source belongs in plain chat at all is a product decision for the owner, not something to settle in a bug fix.

Coordination:
- Absorb or update task-33001.10 (the false toast; raise it to high or close it as superseded), task-33621.4 and task-33621.6 (recovery panel copy), task-33620.6 (the hidden-turn toast), task-33620 and task-33005.7 (readiness vocabulary), and task-33008 and task-33008.3 (where setup actions route).
- The Console files are high-contention with open PRs #2975, #2953, #2882 and #2918 from other sessions, so keep diffs tight.

## Implementation Plan

Order: highest value and lowest contention first. New logic goes into small helper modules; `console_chat_controller.py` and `chat_screen.py` (both already over their size ratchet on the base) get net-zero or shrinking diffs. `FirstRunSetupWizard.py` is not touched.

1. AC#1 (entry-exit-handoff-04, absorbs task-33001.10). In `UI/Console_Modules/session.py`, fence the first-chat handoff on values: compare the saved provider and model (and the full derived settings inside the consume) instead of the global config generation, and acknowledge under the generation that was actually re-verified (retry when only an unrelated write moved it). A genuinely changed default settles the stale handoff and names the model now in use. RED first: a test that stages the handoff, lets Console's real first mount write its rail scope, and asserts no warning and no pending handoff. Rewrite the generation-race tests that pinned the old fence so they publish a real provider/model change.
2. AC#8 (entry-exit-handoff-05, task-33620.6). In `Chat/console_runtime.py`, decide "hidden" when the notice would fire: skip the toast and keep the attention projection off when an answerable Console view is on screen and the receipt's conversation is its active tab. RED: a runtime test with a visible attached view and an active conversation; the hidden case still notifies once.
3. AC#2 (entry-exit-handoff-24). Name the direct runtime's unavailable tools once (`chat_with_llm`) and drop them from the agent's MCP catalog in `Agents/mcp_tool_provider.py` for every caller. RED: compose test asserting `mcp__tldw_chatbook__chat_with_llm` is absent. Record the owner question (built-in MCP source in plain chat; Summary Tools row wording) in the notes.
4. AC#10 (new-entry-exit-handoff-02). Move the Console toast rack below the header and status rows (ChatScreen BUNDLED_CSS plus regenerated bundle). RED: geometry test with the bundled stylesheet at 120x40.
5. AC#4 (gap-06). New helper that pulls one allowlisted field (`error.message`) from a provider error body (exception attribute or response on the cause chain), caps it at 200 characters, scrubs secrets and prefixes the provider name; `safe_provider_error_copy` appends it. `StreamStallError` gets its own category and copy. 6. AC#3 (entry-exit-handoff-03, task-33621.4 partly). 7. AC#9 (entry-exit-handoff-22). Plain readiness words: Library assistant-access chip, 'Context unknown' only when it blocks, Home 'Not set up' after Skip. RED: projection tests.
8. AC#5 (gap-07). Separate first-token window for local providers (default 300 s, configurable) from the 90 s inter-token stall window; waiting copy with elapsed time and a cold-load hint; timeout copy that names the setting; readiness not reset to Ready after a failed first reply. RED: watchdog tests.
9. AC#6 (new-entry-exit-handoff-01). Plain chat with no tool surface enabled gets a minimal prompt, or the preamble is budgeted against the window. RED: first-request plan test. Live: llama-server with -c 4096.
10. AC#11 (E10). Replace first-run arrival toasts with one 'Setup complete — <provider> · <model>' transcript line.
11. AC#7 (entry-exit-handoff-06, task-33621.6 partly). Diagnostics naming missing revision ids; backfill or await the revision row; never pair 'provider was not contacted' with the duplicate-request warning.
12. AC#13/#14: RED proof per AC, ratchet unchanged, User Guide content updated. AC#12: live runs on fresh isolated profiles (real OpenAI/Anthropic keys, real llama.cpp, expired OpenRouter key, retired Gemini model).

Any AC that turns out to need an owner decision or more than this task can carry stays unticked, with the reason in the notes.
