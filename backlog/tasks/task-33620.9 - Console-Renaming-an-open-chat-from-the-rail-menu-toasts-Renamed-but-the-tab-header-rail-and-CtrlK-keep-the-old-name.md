## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** Renaming a conversation that is open in any Console tab (active or not) through the rail row menu (💬 → Rename…) does three things:
- shows 'Renamed to X.';
- writes X to the database and bumps the version;
- changes nothing else.

The tab strip, the transcript header 'Conversation | <old>', the rail Chats row, the Conversations section and Ctrl+K's CURRENT/OTHER OPEN rows all keep the old title. Switching to the tab and sending does not help. Only a restart or reopening the chat shows X. Ctrl+K search for X finds only a History 'SAVED CHAT X' row. Pressing Enter on it switches to the existing tab, which still carries the old name. The same rename on a chat that is *not* open does update its rail row.

No data is lost (nothing reverts the DB title), but one conversation shows two names until restart. The cause: `_rename_console_conversation` (UI/Console_Modules/workspace.py:7693-7735) writes only the DB and refreshes the browser, and never updates the open ConsoleChatSession title.

**Severity / prior art.** P1, NEW, confirmed by all three verifiers. Related Done tasks:
- TASK-341: the inverse split, where a tab rename changed only the in-memory session. It now persists via ConsoleChatStore.rename_session.
- TASK-23200: added the rail menu Rename, with no open-session sync.
- TASK-25712: tree rows reuse the same menu.
- TASK-28125: the Ctrl+K F2 rename.

**Suggested direction.** Route every rename (tab, Ctrl+K F2, rail and tree menu, palette, Library) through one service. It writes the DB, sets the title on every open session bound to that conversation, invalidates the persisted-rows cache and publishes one refresh. Show the toast only after that.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G2-05 (source J3-02). Files: evidence/evidence__J3__131-renamed-open-nonactive.txt, evidence/evidence__J3__50-row-renamed.txt, evidence/evidence__J3__52-ctrlk-after-rowrename.txt, evidence/evidence__J3__99-relaunch.txt.
