## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Focus (AC#1).**
- Measured: a local probe recorded every `Widget.watch_has_focus` in the compact gates (17 nodes at `-n 4`). Only one focus change in an attach is heavy, `ConsoleComposerBar` gaining or losing focus. Textual's watcher restyled its whole subtree: 30 nodes, CPU median 8.3-9.9 ms (max 12.8), wall up to 97.7 ms at load 17-34. Navigation buttons restyle 1 node.
- In the mounted send harness, one focus move onto or off the bar restyled 27 nodes through the watcher, 24 of them composer descendants. That is beside the 2 nodes `_sync_interaction_classes` already scoped.
- Change: `ConsoleComposerBar.watch_has_focus` restyles only the bar and `INTERACTION_STYLED_DESCENDANTS` (`#console-command-visible-text`, the subject of the `#console-native-composer:focus-within` rule). The bar's own `:focus` rule sets only `outline`. `_sync_interaction_classes` reuses that restyle instead of its own copy.
- After: in the gates the bar's focus restyle styles 2 nodes, CPU median 0.6 ms (max 1.0), wall at most 1.1 ms (load ~10).

**Control-bar build (AC#2).**
- Measured, mounted, load 15: one `_sync_console_control_bar` built the workspace context twice from the same inputs, once in the Inspector leg and once in the rail-state leg. That was 5.8-6.9 ms of the sync's 27-31 ms of CPU, with the rail state at 3.4-4.0 ms.
- Change: the control-bar sync and `_sync_console_rail_and_controls` open the existing fingerprint-validated `tick_workspace_build_scope`, as `config_sync.settle_stopped_poll` already does. The helper `_workspace_build_scope` falls back to a no-op scope for bare test surfaces.
- After: 1 real build per sync (`build_console_workspace_state` calls 2 -> 1). Workspace-context CPU is 3.2-3.6 ms, rail state 0.7-0.8 ms, and the sync 22.6-24.7 ms.
- AC#2 wording amended by the coordinator's ruling (2026-11-05, review of c1ca7a7c61) from "no longer recomputes unchanged inputs on each sync" to "no longer builds the workspace context twice from the same inputs within one sync". Ticked on the 2 -> 1 build count above.
- Each sync still builds afresh. Caching across syncs needs a build fingerprint that covers every input. `_console_workspace_build_fingerprint` deliberately leaves out long-tail inputs (stars, unseen markers, collapse preferences), so a cross-sync cache could show stale rows. That cache is left as a follow-up for the coordinator to file.
- During a run, a coalesced sync now serves the tick's last display-read snapshot, as ticks and `settle_stopped_poll` do.
