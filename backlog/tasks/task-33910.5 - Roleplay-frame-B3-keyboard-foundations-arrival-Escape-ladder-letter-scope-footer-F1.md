## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Give Roleplay one keyboard projection on the current layout: focus arrives on the list, Escape never leaves the screen, single letters act only on navigation surfaces, and the footer and F1 follow focus. Spec §5.2 "B3 · Keyboard foundations (on the current layout)"; see also §4 "Interaction: keys, focus, Escape, footer, help, state and memory" and §5.9 G7a, G9a, G9c. Size M. Fixes RP-024, RP-026, RP-033, RP-034, RP-035, RP-036, RP-063 and RP-065 (mitigation).

Parent: TASK-33910 (Roleplay on the Library frame, sub-project B). Spec: `Docs/superpowers/specs/2026-10-02-roleplay-library-frame-design.md` (PR #2960).

**Scope**
- The keyboard projection in `roleplay_frame_state.py` (§4.2; no separate module); `personas_screen.py` adopts `TAB_REGION` and arrival goes to the list; `check_action` scoping.
- Escape rungs available before the frame: 0, 2, 3, 5, 7-11 (rung 10 goes to the old mode chips until B6).
- The footer projection replaces the hand-built hints; F1 → `action_show_workbench_help`.
- Keys `/` (pane-scoped), `ctrl+f`, `n`, `ctrl+n`, `i`, `del` (modal); the screen-level `ctrl+enter` is retired; the chip focus style differs from active.
- The mode strip's label `Modes:` becomes `Kind:` (RC-10).
- The guide's key table between `<!-- roleplay-keys:begin -->` and `<!-- roleplay-keys:end -->`, generated from the projection's F1 groups and checked by the new censused `Tests/UI/test_roleplay_guide_keys.py` (RC-9).

- Census first: run the Roleplay suites with the new arrival focus on a scratch branch to list tests whose early `pilot.press` relied on nav-bar focus; census and re-pin the `pilot.press("ctrl+s")` tests.

**Slice gates (card):** a focus change causes 0 recomposes and starts 0 workers; re-registration is skipped when nothing changed; pre-import +0; ADR-011 capture.
