## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: found while verifying TASK-34000.19. `LocalChatbookService._normalize_content_selections(None)` returns `{}`, but `ChatbookImporter.import_chatbook` reads only `None` as "everything" and treats `{}` as "nothing selected". So a service-route import with no selections writes nothing and still returns `success: True` ("No items to import"). No product caller reaches this today: the wizard calls the importer directly with `None`. But the seam promises a contract it does not keep, and the server-side `ChatbookImportRequest` treats a missing selection as "everything". The schema's `import_media=False` default also flows through `_as_dict` and deserves the same look.
<!-- SECTION:DESCRIPTION:END -->
