## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in review of TASK-33620.15.18. Since that task, the first-send warm-up starts no step until 0.15 s have passed with no input (INPUT_QUIET_SECONDS), so that a click's navigation never finds a new step started under it. The gate reads the stamp the idle heap refreezer uses, which every Textual InputEvent and Paste sets: keys and clicks, but also mouse moves and scrolls. So input that never pauses for 0.15 s keeps the warm-up waiting indefinitely: typing faster than about six keys a second, or moving the mouse steadily. At about five keys a second it lets one step through per gap, and the warm-up has 86 steps. A user who starts typing a first message as soon as the Console appears can therefore reach Enter with most of the warm-up still to do, and that send pays the remaining imports on the UI loop (about 64 modules, as without the warm-up; TASK-33620.15.18 measured Enter to provider call +14 ms slower without the warm-up). On origin/dev 7536ac3b87 the warm-up ran during typing, and keys landing in its steps were not slower (+0.2 to +2.0 ms paired). TASK-33620.15.18's AC #3 timings (the pass ends about 2.3 s after the Console's first frame on an idle established profile) assume no input during the window.
