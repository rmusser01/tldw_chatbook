## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Anyone with more notes than fit the pane cannot browse to them at ordinary big-terminal sizes. That includes a power user with a vault and also a first-timer after a single import. At 120 columns and wider the Notes tree does not scroll at all. Notes below the fold, the "Load more notes" pager and the "Recently deleted" link can be reached only through the filter. Keyboard-only and low-vision users are hurt most: Down and Tab move focus onto rows that are never painted, so Enter opens a note they never saw.

Observed on the golden profile (122 notes) at 160x45:
- Ten wheel events over the tree change zero cells (`verify/nl-v-n-04/02-after-wheel-tree-160x45.ansi`). The last painted rows are "📚 Reading queue 2026 ✨ · 1w" and "A very long note title that keeps going so we can test …".
- Pressing Down past the bottom of the pane and then Enter opened "Daily log 2026-09-17", a row that was never on screen (`12-enter-opened-hidden-160x45.txt`).

Six sources saw the same thing:
- At 120x36, 0 of the 122 notes are visible under 19 rows of chrome.
- At 200x50, Meetings, Projects, Research, Study, Unfiled and "Load more notes" are below the border.
- 235x52 behaves the same way.
- 80x24 and 100x30 do scroll.

Verified cause (origin/dev 2d34cbf80d):
- `#library-notes-list` is a plain `Vertical` (`Widgets/Library/library_notes_canvas.py:2345`), and Textual's default for a `Vertical` is `overflow: hidden`.
- Only the compact rule makes the list scrollable: `#library-shell-grid.library-notes-compact #library-notes-list` sets `height`, `min-height: 0` and `overflow-y: auto` (`css/features/_library.tcss:1004-1013`). That rule applies below `LIBRARY_NOTES_COMPACT_BREAKPOINT = 120` (`UI/Library_Modules/screen_constants.py:275`).
- The wide rule (`css/features/_library_panels.tcss:543-548`) sets widths only, even though its own comment calls the list "its scroll owner".
- Up/Down move row focus in place through `_move_library_list_row_focus` (`UI/Library_Modules/canvas_sync.py:61`), and nothing scrolls the focused row into view.

Suggested direction (a direction, not a mandate):
- Give the wide `#library-notes-list` the same `height: 1fr; min-height: 0; overflow-y: auto; overflow-x: hidden` that the compact rule has. Edit the source `.tcss` and regenerate the bundle with `css/build_css.py`; never hand-edit the bundle.
- When keyboard focus moves to a row (arrow keys or Tab), scroll that row into view.

Severity: j3 rated this P0. It is P1 because the filter is a workaround, if a poor one. No existing task owns this. TASK-18917 (Done) built the tree's placement-aware paging, and this fix makes that pager reachable.

Review finding(s): N-04. Source: qa/notes-library-ux-review-2026-10-02/report.md
