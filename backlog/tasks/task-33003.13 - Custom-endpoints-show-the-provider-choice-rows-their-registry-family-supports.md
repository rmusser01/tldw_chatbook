## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Generation-control support for an ADR-146 custom endpoint (custom-ep:<slug>) ignores the entry's registry family. Every family marks 3 of the 4 provider-choice controls (Reasoning effort, Reasoning summary, Verbosity, Thinking) unsupported, yet a custom-ep id shows all four. No PROVIDER_PARAM_MAP provider carries all four (openai 3, anthropic 1), so TASK-33003.8 AC#3's four-row case exists only through this gap. The owner should confirm whether a custom endpoint shows its family's supported set. Found in TASK-33003.8 review round 1 (F2) and the Phase 3 final review.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Owner ruling, 2026-10-09 (AC#1):** a custom endpoint (`custom-ep:<slug>`) shows exactly the provider-choice rows its registry family supports. That is the rule 5ba142ac79 already shipped: `console_provider_support.py::_registry_family_provider` decides the id as its entry's family (`family_execution_key`), the way the gateway sends it, for `supported_generation_fields`, `console_generation_control_support` and `reasoning_effort_values_sent` alike. Nothing in the rule changes. TASK-33003.8 AC#3's four-row case, which existed only through the gap, is gone with it.

AC#2: `Tests/UI/test_console_settings_hidden_fields.py::test_a_registry_endpoint_hides_what_its_family_hides` is parametrized over every family in `ENDPOINT_FAMILIES` (it pinned llama_cpp only); its rows live in the module-level `_FAMILY_ROWS`, and the test asserts their families equal `custom_endpoint_registry.ENDPOINT_FAMILIES`, so a new family fails it until it gets a row (review fix). Each case mounts the real modal under the production stylesheets at 211x44 on a registry entry of that family and asserts the hidden rows equal the family's (the shared support functions), the Sampling title names the entry, and the shown choice rows are literally: llama_cpp Reasoning effort; ollama none; openai_compatible Reasoning effort (support unknown, so it stays with the neutral note). Negative control: with `_registry_family_provider`'s registry lookup disabled (a source edit, reverted at once), all three cases fail: every row shows, as the rider found. The file runs whole in the UI PR census.
