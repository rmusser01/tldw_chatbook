## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
These four findings come from a power user (Morgan) working through Conversations and Prompts, and from the mechanical size matrix. In each one the screen either acts on something other than what it shows, or hides the content behind chrome or blank space.

**L-09 (P2) · A filter that hides the loaded conversation leaves the reader actions pointed at it.** At 160x45, `/ kubernetes` Enter lists "1 match for 'kubernetes'" (Kubernetes crashloop debugging). The Reader still says "Loaded Thesis: chapter 2 structure · 40 of 40 messages · complete." Then:
- `c` opens Console on "Thesis: chapter 2 structure".
- "Use as source" first writes the workspace link ("✓ linked · Default · this conversation can now be used in Console", with "Undo link"), then refuses with "Select a conversation before using it in Console."
- Archive does nothing.

Verified cause: the filter-submit handler only requests page 1. It never re-points or clears the reader (`UI/Library_Modules/library_conversations_controller.py:1434-1446`). Media does re-point after a settled filter, through `filter_select_first` (`UI/Screens/library_screen.py:16635-16642`).

Suggested direction: when a settled filter drops the loaded conversation, load the first match as Media does. Alternatively, label the Reader "Not in current results" and disable `c`, Resume, Use as source and Archive. Write the workspace link only after staging succeeds. Lowered from P1: each outcome is visible or can be undone, and clicking the row works around it.

**L-31 (P2) · About 19 rows of chrome sit above the first message.** At 80x24 and 60x24 the Conversations reader shows no message at all. The first transcript row sits at pane row ~26, which leaves 3 visible rows at 100x30, 5 at 120x36 and 8 at 160x45. At 80x24 the rows above it are:
- the "Conversation reader" heading;
- "Read  Info";
- "Resume conversation";
- "Use as source", plus a 2-row explanation ("This conversation is not in this workspace. Pressing this adds it to the active workspace first, and you can undo that.");
- "Archive conversation" and "Link to workspace";
- a 3-row status ("Conversations (12) · Thesis: chapter 2 structure · Release notes draft v1.0 · Loaded Thesis: chapter 2 structure · 40 of 40 messages · complete.");
- a 3-row "Find in complete transcript…" field;
- "Find previous / Find next".

Suggested direction:
- Open Find on demand with ctrl+f, as the Media reader does.
- Use a one-line status.
- Put the actions in one wrapping toolbar row.
- Cut the link-on-use reason to one line.
- Drop the "Conversation reader" heading.

Target: at 120x36 the first message starts at or above pane row 8.

**L-26 (P2) · Prompt "Use in Console" turns `{{notes}}` into `{notes}` with no warning, and leaves Instructions out under a different name.** Templates from elsewhere use `{{name}}`. Using "Summarize meeting notes", whose body contains `{{notes}}`, opens a dialog titled "Prompt variables" that has no fields. Apply then:
- puts "Summarize the following notes into Decisions and Action Items: {notes}" in the composer, collapsed into a pasted-text chip;
- leaves the status bar at "System Prompt: off".

The prompt's Instructions lane is skipped because the dialog's checkbox, "Replace the current session System prompt with this System lane", is off by default. That checkbox never uses the word "Instructions", which is the name the Prompts editor uses.

Verified cause:
- ADR-053 (`backlog/decisions/053-prompt-variable-grammar-and-guarded-insertion.md`) rules that `{{` is an escape for a literal `{` (`Prompt_Management/prompt_variables.py:376-383`).
- ADR-053 also mandates that exact checkbox copy, off by default (`Widgets/Console/prompt_variables_dialog.py:120-127`).

The grammar and the default are ADR rulings. What is missing is the feedback.

Suggested direction:
- Show an authoring hint in the prompt editor when `{{name}}` appears.
- Add a dialog status: "No variables — {{notes}} will be inserted as {notes}".
- Show an "Instructions not applied" line in the dialog and in the receipt.
- Title the dialog "Use prompt in Console" when the prompt has no variables.
- Do not collapse a prompt insert into the pasted-text chip.

Changing the grammar, the checkbox copy or its default would need an ADR-053 amendment, and is out of scope here.

**L-32 (P2) · The Prompts list gets half the pane, and the other half is blank.** At 160x45 the list shows 5 of 10 prompts in a scrolling list. Below it come "1-10 of 10" and about 14 blank rows. At 120x36 it shows 3 of 10 with about 9 blank rows.

Verified cause: `#library-prompts-pager` is a plain `Vertical` (`Widgets/Library/library_prompts_canvas.py:1082`) with the default `1fr` height. It therefore splits the pane with `VerticalScroll#library-prompts-list` (`:1021`). The Skills and Conversations pagers carry `classes="library-source-pager"`, which is `height: auto` (`css/features/_library.tcss:345-351`).

Suggested direction: give the Prompts pager the same class. If any CSS source changes, rebuild the bundle with `css/build_css.py`.

Review finding(s): L-09, L-31, L-26, L-32. Source: qa/notes-library-ux-review-2026-10-02/report.md
