## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in TASK-34100.16.1's review round v5r1. The Personal Context repository database is declared to backup but not captured (owner decision 2026-11-06, TASK-39110), so each of its files that exists is an explicit `unsupported` row. Personal Context opens and closes a WAL connection per operation, so the database's `-wal` and `-shm` files come and go. A present unsupported row's path is part of the reviewed backup scope, so a backup Review taken while a Personal Context operation is running fails at Create with `scope_changed` once that operation ends. The user can recover by reviewing again, and only profiles that have used Personal Context are affected.

TASK-34100.16.1 fixed the same failure for the excluded local stores (the Notes device-state store and the Personal Context interview drafts). It left this case alone because the fix needs a decision on how the repository's sidecars are reported, which either changes the owner-decided "every present file is unsupported" rows pinned by `Tests/Architecture/test_backup_owner_inventory.py::test_personal_context_stores_preview_under_their_installed_owners` or changes how the inventory digest treats unsupported transient files. The reproduction is `Tests/Backup_Recovery/test_capture_service.py::test_local_sqlite_wal_lifecycle_does_not_void_a_reviewed_scope[personal_context.repository]`, currently a strict xfail.
