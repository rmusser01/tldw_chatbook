## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: on 2026-10-03 the owner ruled that Ctrl+S saves in every editor, and ADR-031 was amended to match. Its 2026-10-03 refinement defines the behaviour:
- Ctrl+S performs the focused editor's visible commit action.
- In an autosaving editor it flushes the pending save immediately.
- A refused save is reported at the editor without moving focus.
- Outside an editor, Ctrl+S is unbound.

TASK-34000.40 brings the four Library editors (notes, prompts, skills, Folder files) into line, and TASK-34000.22 does the same for the Media analysis and metadata editors. The Roleplay editors are covered by the Roleplay Library-frame design (its R41).

Every other editor in the app still follows the old rule 2, which forbade Ctrl+S. A user who learns Ctrl+S in Library would press it elsewhere and get nothing, or find that the editor has no visible save at all. This task finds those editors and makes them consistent. Examples include Settings forms, Watchlists and briefings editors, Writing, Workflows, schedule editors, Study card editors and MCP configuration forms; the inventory decides the real list.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 An inventory of every editor and editing form in the app, with its current save model and Ctrl+S behaviour, is recorded in this task (derived from code, not from memory)
- [ ] #2 Every inventoried editor outside Library and Roleplay honours Ctrl+S per the amended ADR-031: it performs the visible commit action, flushes autosave, and reports a refused save at the editor without moving focus
- [ ] #3 Ctrl+S is bound nowhere outside editors. An architecture test fails if a screen-level (non-editor) binding claims ctrl+s, or if an inventoried editor lacks it
- [ ] #4 The footer and F1 advertise ctrl+s only while an editor that honours it holds focus
- [ ] #5 Regression tests pin Ctrl+S on a representative editor of each save model (explicit, autosave, modal form), and they fail on dev before the change
