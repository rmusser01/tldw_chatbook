## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
This is a rider from the TASK-33001.13 hotfix review (PR #2847), traced in code but not reproduced live.

**How it happens:**
- At load time, the runtime copies a legacy `[API] <provider>_api_key` value into `api_settings.<provider>`, and only when that provider's env var is unset (config.py:1735-1752).
- Settings sees that key as stored. Since #2847, a model-only save records `credential_source = "stored"` and keeps `api_key` untouched instead of rewriting it.
- The key only ever lived under `[API]`, so the `[api_settings.<provider>]` table on disk then says "stored" but holds no `api_key`.
- If the env var is exported later, readiness reports no key (the stored source has nothing to read), while actual requests use the env key.

Before #2847, dev saved "environment" and deleted the key, so this is strictly better. The two views can still disagree, though, which is what ADR-012's single credential lookup is meant to prevent.
