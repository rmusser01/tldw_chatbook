## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: the wave 1a reviews (TASK-34000.1, .2 and .3, plus the TASK-32633 slice) ruled a set of minor findings safe to defer. They lived only in a git-ignored working ledger. This task is their durable record, so none is dropped silently.

Deferred items:
- **Conflict callout and veto reason.** The conflict callout still takes focus on a conflicted autosave, and the reason for a refused autosave is visible only until the next keystroke. Both sit beside TASK-34000.10.
- **Sync-status listener.** `_arm` sets its pending flag before `set_timer`. The listener's refresh does DOM work while the Library screen is suspended.
- **Recovery receipt.** `recovery_finished_line`'s unhealthy branch has no test, and `_run_settled_pass`'s result is unused by its caller.
- **Export symlinks.** A symlink target that the export resolves is not passed back through `validate_path_simple`.
- **Coalesced save during a backup.** A save coalesced onto a running pass is dropped when a backup closes admission before the pass ends. It heals on the next change or start; the User Guide carries a caveat.
- **`settle()` bound.** `settle()` has no bound of its own. It terminates because shutdown and maintenance close admission first, and the UI wait is bounded.
- **Unbounded sync signal.** The sync signal a save awaits is inline and unbounded. A slow sync store holds a save, a delete or the quit flush, and past five seconds the quit prompt asks to discard changes to a note that is already saved.
- **Modal inventory.** The modal-dismissal inventory cannot see the export Replace prompt, because it is pushed from a module-level function outside the supported owner scopes. The inventory is red on dev for unrelated reasons.
- **Ruff formatting.** New files that are not ruff-format clean should be formatted in the same pass as dev's next format batch if any remain.
Added from the wave 1a final re-review:
- **Session guard after the save wait.** The session's save loop has no guard after its new bounded wait. If the session were replaced during the wait, the old chain would adopt the new one. No path reaches this today. Capture the note id and session generation before the wait.
- **Refused attention read.** A refused attention read is not retried when a backup's fence lifts. A hold published during a backup stays unpainted until the next publication, visit or save.
- **Quit wait reach and feedback.** The quit-time sync wait covers Ctrl+Q from the Library only. Nothing on screen says the quit is waiting, and a second Ctrl+Q is ignored.
- **`settle()` and the message pump.** `settle()` joins whole tasks, including a message handler that awaits a root command. A wait that starts while one is in flight runs to its bound.
- **Quit flush headroom.** When the save wait runs to three seconds, two seconds remain for the save and the other flushes before the quit prompt appears. Only the 3 < 5 relation is pinned.
- **Attention refresh ordering.** Two attention refreshers in different worker groups could finish out of order and store the older answer last. By reading only; not reproduced.
- **Test gaps.** No test pins that "Discard and quit" skips the sync wait. The screen-level path of `note_save_starts`'s False branch is pinned only indirectly.
- **Unexplained flake.** TASK-34000.1's carried flake (a save stuck in `saving`, then a shutdown hang on the maintenance gather; 1 run in 6, not reproduced since) is still unexplained.
- **Collections recovery export.** A file that appears mid-publish ends as "Legacy export failed" instead of the Replace prompt the other exports fall into. Safe, but inconsistent.
Added from the Qodo round on PR #3021:
- **Collections recovery on linkless volumes.** The Collections legacy-recovery service's own new-file publish still uses a hard link with no fallback (unchanged from dev). That export still fails on volumes without hard links (FAT32/exFAT, some SMB/NFS). The other exports gained an exclusive-create fallback in `atomic_write_text`.
- **Fallback coverage.** The fallback was proven on a FAT32 image only. Its errno allowlist for exFAT, SMB, NFS, Linux and Windows comes from documentation.
