## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make synchronization, agent visibility, and permission to disclose records to model providers independent and understandable controls.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A proposed ADR specifies local-model-only and explicitly allowed provider audiences, with a conservative migration rule for existing records and runtime-local grants.
- [x] #2 The design traces every relevant egress path: ordinary requests, profile tools, child runs, interviews, summaries, embeddings, background maintenance and exports.
- [x] #3 Provider identity changes, fallback routes, unknown destinations, mixed-source derivatives and cached snapshots fail or omit content according to a documented policy.
- [x] #4 Next Send and pre-request disclosure communicate the effective audience without revealing hidden records or treating device_only as a current model-egress guarantee.
- [x] #5 The design explicitly implements or amends ADR-102's broader device_only promise and resolves the existing unscoped unsupported-records existence signal, with targeted compatibility and disclosure cases.
- [x] #6 Shared-core and server compatibility implications, acceptance cases and an independently testable first release are documented.
- [x] #7 The task produces a reviewed design only; it does not silently change current permissions.
<!-- AC:END -->

## Implementation Notes

Produced the proposed provider-disclosure design and ADR-187: restrictive canonical policy plus encrypted peer-local destination/purpose grants, separate from Sync and agent authority. Conservative deny migration, exact route/account/custody identity, source/inline evidence authority, derivative intersections, final adapter-entry fences, current controls on replay and restricted Next Send/diagnostic behavior are explicit. The proposal amends ADR-102 device_only wording openly; no current permission or runtime guarantee changed.

Fresh read-only technical review found two Important release gaps, resolved before presentation: model-cache binary/live-slot state needs qualified lineage/current controls or exact reviewed clean owned isolation; model-generated web/MCP/skill/shell/file arguments and independent publication retain conservative input restrictions and stay disabled until native owners qualify. Targeted rereads found no outstanding Critical/Important/actionable Minor issue and readiness for written user review.

The first future release is deny plus qualified on-device enrollment for new registered V2 inputs/new conversations with all included context/tool/child/history seams qualified. Unqualified cache/tool/publication/model routes stay disabled; adaptive interviews/summaries/embeddings/jobs/remote audiences need separately qualified releases. Synthetic cases are future requirements, not passing provider/runtime evidence.
