## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The wizard's frame and lists use fixed sizes tuned for 120x40.

At 80x24, the stock terminal size, the frame takes 14 of 24 rows. The Summary then shows none of its ✓/✗ rows, and errors read as sentence fragments. Below 100x30 the size warning covers the key hints, and Welcome opens scrolled past its own heading. Large terminals leave 30 to 40 empty rows between the content and Next.

State and boundaries depend on colour or faint cues:
- Stock checkboxes draw 'X' both on and off, and tool switches show state only by knob position.
- Hidden content is signalled only by a 1.55:1 scrollbar thumb.
- Primary labels measure 3.78:1 and the unselected '○' 1.42:1. In the light theme the tracker's '!' measures 1.38:1.
- Secondary buttons render as bare text, and keyboard focus on primary buttons is invisible.
- Toasts show severity only by border colour.
- Back is bound to Ctrl+B, the default tmux prefix, and the hint line teaches it.

Riley, in an 80-column tmux split, scrolls every step and can't go Back. A low-vision first-time user can't read 'Next →' or see that unselected rows are options.

This task implements structural fix SF9 (a terminal-native frame): adaptive height tiers, state shown as text, theme-layer button and focus tokens, safe keys, and the size and contrast matrices as CI guardrails. Report: Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md (§5.1 SF9, §6 register). Resolves: a11y-01, a11y-02, a11y-03, a11y-07, a11y-08, a11y-09, a11y-10, a11y-11, cross-cutting-15, a11y-04, a11y-13, a11y-14, fulltrack-12, gap-08, gap-09. Every one was re-checked and is still present on dev 3c439d606e.
