## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Play any video the user would otherwise download: user-typed URLs and yt-dlp-supported site URLs stream through the player screen without touching disk. Every URL and redirect hop passes the SSRF egress policy; streams bypass the media byte cap by design and are time-boxed instead. ADR: backlog/decisions/044-ephemeral-generated-video-storage-playback-and-streaming.md
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 /stream-video <url> resolves direct media URLs and yt-dlp-supported site URLs with yt-dlp invoked as a subprocess only
- [x] #2 The fully resolved final URL is validated through the egress policy before reaching ffmpeg: typed URL seeds trust and redirect hops and yt-dlp -g output are re-validated because ffmpeg follows redirects internally
- [x] #3 ffmpeg reads streams with reconnect flags and the player handles stall and resume
- [x] #4 Non-seekable streams disable seek with a footer note and nothing is written to disk
- [x] #5 Stream sessions are time-boxed and user-terminated per the ADR residual-risk note
- [x] #6 v1 scopes to progressive single-URL streams; DASH/HLS separate audio/video muxing is documented as a follow-up

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented /stream-video URL streaming with egress gating (ADR-044 decision 5). Media_Playback/stream_resolve.py: http/https shape check; per-hop redirect walk where hop 1 carries the typed-URL trust seed (origin_set -- user intent) and every later hop AND the yt-dlp output URL are validated WITHOUT trust (a redirect/yt-dlp cannot bounce the player into a private network); direct-media content-type detection (video/audio/octet-stream); HTML pages fall to yt-dlp AS A SUBPROCESS ONLY with a progressive single-URL format selector (never imported as a library -- dependency weight + licensing); .m3u8/DASH refused with the documented follow-up note (AC6 v1 scope); Accept-Ranges probe decides seekability; nothing written to disk anywhere. player_pipeline: http(s) sources inject TermTube's reconnect flags (-reconnect 1 -reconnect_streamed 1 -reconnect_delay_max 5 -rw_timeout 15000000) before -i; ffprobe gets matching input options. VideoPlayerScreen stream mode: seekable=False disables seek (guarded action + hints line swap to the AC4 note), a …stalled indicator when no frames for 3s while playing (ffmpeg's reconnect does the actual resume, AC3), and a MAX_STREAM_SECONDS (2h) time box auto-stopping the session per the ADR residual-risk note (AC5). Grammar: stream-video registered (palette + unknown-hint derive; BOTH expectation files updated -- and this surfaced a miss from 3401.5: the exact-names tuple in test_console_command_grammar.py still expected the pre-video registry; fixed here, noting the tail-truncation that hid it in the earlier verification). _console_command_stream_video: resolves off-loop via asyncio.to_thread, pushes the player with seekable/max_seconds, no ephemeral gate (nothing writes locally). Tests: 18 new resolution cases (scheme refusal, direct media with trust-seed assertion, redirect chains with untrusted later hops, blocked-hop surfacing, HLS refusal direct AND via yt-dlp, yt-dlp missing/failure/output-validation, no-Location and hop-cap errors, grammar registration) plus pipeline stream-flag construction, screen hints swap and non-seekable refusal (never reaches the pipeline).
