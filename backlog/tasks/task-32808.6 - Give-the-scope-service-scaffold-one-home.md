## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
About 45 scope services each carry their own copy of the same four helpers -- roughly 2,000 lines -- and the copies are harmless in themselves. The call shape is not: awaiting a synchronous local call runs it on the event loop, and the fix for that exists in exactly one of the services. A shared base class would carry the four helpers plus one local-dispatch method that applies the threading rule once.

Source: core-runtime code review 2026-09-17 — `qa/core-code-review-2026-09-17/report.md`; per-slice evidence in `qa/core-code-review-2026-09-17/slices/`, reproductions in `qa/core-code-review-2026-09-17/phase4-verification.md`.


## Tier-2 scope correction (2026-09-21)

**Five of this task's stated scope numbers are wrong, and one of them changes the design.**

| stated | measured |
|---|---|
| "the four helpers" | **six** (`_maybe_await`, `_enforce_policy`, `_require_client`, `_normalize_mode`, `_identity`, `_dump`) |
| "~45 services" | **47** |
| "33 Interop + 12 core" | **31 + 16** |
| "~2,000 lines" | **1,776** |
| "the fix exists in exactly one of the services" | **nine** services thread it, in five mutually incompatible shapes with **two opposite fail-directions** |

The last row is the one that matters: a base class cannot be written until the dispatch predicate's
**fail-direction** is settled, because two documented rules currently disagree. Likewise the mode default --
**25 services default SERVER, 19 default LOCAL, with four `Interop`/`server_*` twin pairs inverted**, so a
base **cannot** hard-code it and `mode=None` must stay explicit per service.

This needs an ADR before a PR. Re-scoped as TASK-32898.

Measured by the tier-2 review against `origin/dev d0face3ebe`; evidence in `qa/tier2-code-review-2026-09-21/` (`report.md`, `validation/`). Tracked as TASK-32903.
