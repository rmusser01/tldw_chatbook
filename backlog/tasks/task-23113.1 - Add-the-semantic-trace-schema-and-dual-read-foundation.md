## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Introduce the append-only semantic trace data model and repository while preserving read compatibility with existing message-exchange captures.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [x] A versioned migration creates the append-only trace graph, semantic revision, content-addressed artifact, surface, call, owner, and graph-epoch storage required by ADR-097.
- [x] The repository exposes typed transactional operations and rejects invalid ownership, revision, call-state, and reachability-edge transitions at the database boundary.
- [x] Existing databases install the fast schema migration idempotently without content conversion while new databases start at the same schema version.
- [x] Trace reads prefer normalized records and fall back to existing message-exchange captures without changing current user-visible behavior.
- [x] Migration SQL is included in source and wheel distributions and historical-schema fixtures exercise the actual upgrade path.
- [x] ADR required: yes; ADR-097 is linked and no duplicate ADR is created.

## Implementation Plan

1. Define and test the immutable logical trace types and lifecycle invariants.
2. Add and package the fast trace-storage schema migration with genuine historical fixtures.
3. Add a transaction-aware repository for typed trace operations.
4. Add feature-gated normalized-first dual reads with legacy fallback.

## Implementation Notes

- Added immutable semantic trace models, exhaustive lifecycle validation, and a packaged v55-to-v56 append-only trace schema with historical migration, allowlist, and index-census coverage.
- Added a caller-transaction-owned repository with collision-safe artifact reuse, typed ownership/revision/call invariants, graph-epoch accounting, deterministic reads, and ambiguity-safe call idempotency.
- Added a feature-gated normalized-first projection injected through the Console store/runtime. Production normalized reads and writes remain off; the Inspector preserves legacy behavior and falls back per logical call when normalized data is missing, unverified, malformed, or ambiguous.
