## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while writing TASK-33621.153's real-controller test. Compaction summarizes complete user-led units (Chat/console_context_compaction.py complete_durable_units), and a unit may hold only user, assistant and tool rows: the scan stops at the first unit that holds anything else. A delivered agent wake commits a System notice row (origin agent_wake) into the turn it follows, so that unit, and every unit after it, can no longer be summarized. Measured through the real controller, store, compaction service and fleet-wake coordinator (only the provider network doubled; custom 1,800-token budget, Ask trigger 1,440): after one delivered wake, the probe on later sends returned decision NON_COMPACTABLE at 1,671 to 3,358 tokens, so no Ask hold appeared and nothing could be compacted. Consequences: a later wake over the trigger is not paused at Ask when no complete unit precedes the first wake, and when some do, /compact summarizes only those, so the paused wake can pause again. The composer's own sends lose the Ask hold the same way. Not checked live.
