## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Under trace capture (the Console default), the trace contract reserves a run's next model call only when the call before it bore a response (`console_trace_runtime.py`, the `trace_tool_chain_unavailable` refusal). Two features make a second call after a failed one: TASK-25901's in-place retry of a transient model error (a 429 or a 5xx) and ADR-110's provider fallback chain (`[console] agent_fallback_providers`). Under capture both were refused, and the Console showed 'Trace capture blocked — the provider was not contacted' for a send the provider had just answered, hiding its own error.

TASK-34100.2 worked around it: a captured run plans no model retries (`captured_run_budget`) and no fallback chain (`captured_fallback_providers`), so the provider's error ends the run. Retries and fallback therefore work only with capture off. This task makes the trace contract able to record that second call, so captured runs get them back.

**Correction (2026-11-24, round-24 stack).** The retry half no longer applies. Dev's 164abdc1c9 (2026-10-04) already reserves an unchanged retry against the failed call's saved surface, so the refusal above was a pass-1 log from before it. TASK-42472 removed `captured_run_budget` (its AC#9) and fixed the one refused retry path it found, a llama.cpp stream whose non-streaming fallback also failed, and the next send after such a run (its AC#8). The fallback half is still refused and is tracked by TASK-42525, which may supersede this task.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Under trace capture, a model request that fails with a retryable error (429, 5xx) is retried per the run budget, and each attempt is recorded in the trace as a call with its own failed or response-bearing outcome
- [x] #2 Under trace capture, a configured fallback provider is tried after the primary fails, and the trace records both calls and the switch
- [x] #3 No 'Trace capture blocked — the provider was not contacted' card appears for a run whose provider was contacted
- [x] #4 `captured_run_budget` and `captured_fallback_providers` are removed (or reduced to the capture-off identity), with tests that fail on the workaround
