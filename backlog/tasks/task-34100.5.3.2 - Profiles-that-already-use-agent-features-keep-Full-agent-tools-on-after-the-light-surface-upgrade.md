## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-34100.5.3 (merged in PR #3295) made plain Console chat offer only a light, safe tool set (date/time, calculator, ask-user) until the user turns on Full agent tools. That follows the owner's 2026-10-04 ruling "Light surface by default". The new `[tools] full_agent_tools_enabled` switch defaults to off for every profile that lacks the key. Profiles that existed before the change therefore lose things they use today in plain chat when they upgrade: sub-agents, workspace file and Git tools (including SSH remote workspaces), web and Watchlists tools, character tools and Canvas.

The owner ruled on the upgrade path ("Keep them on if used"). A one-time migration turns Full agent tools on for profiles that already use agent features. Fresh installs, and profiles that never used those features, get the light set. A CHANGELOG entry explains the change.

PR #3295 also merged before its pre-merge review fixes were pushed. This task carries them:
- The served mobile companion's Console bridge was built without the light-surface reader, so phone sends always got the full agent surface.
- The light surface's fail-closed branches were untested.
- A light plan could reach the compact find/load fallback.
- Some settings and User Guide copy still promised agent features in plain chat.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] #1 On the first launch after upgrading, a profile with no `[tools] full_agent_tools_enabled` key that already uses agent features gets `full_agent_tools_enabled = true` written once, and its plain Console chat keeps the tools it had. - [ ] #3 The migration runs at most once per profile, with a recorded marker. A user who later turns Full agent tools off is never switched back on
- [ ] #4 A profile whose config already sets `full_agent_tools_enabled` explicitly (true or false) is left exactly as it is
- [ ] #5 The migration never blocks or slows startup noticeably. Any detection failure leaves the profile on the light set and is logged without secrets or user content
- [ ] #6 Users can find out what changed: a CHANGELOG `[Unreleased]` entry, and the User Guide's Full agent tools section describes the upgrade behaviour (no 'Verified against' stamps)
- [ ] #7 The TASK-34100.5.3 pre-merge review fixes that missed PR #3295 are in and correct on today's dev:
