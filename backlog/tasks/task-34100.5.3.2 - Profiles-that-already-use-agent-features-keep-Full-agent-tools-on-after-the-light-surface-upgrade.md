## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-34100.5.3 (merged in PR #3295) made plain Console chat offer only a light, safe tool set (date/time, calculator, ask-user) until the user turns on Full agent tools. That follows the owner's 2026-10-04 ruling "Light surface by default". The new `[tools] full_agent_tools_enabled` switch defaults to off for every profile that lacks the key. Profiles that existed before the change therefore lose things they use today in plain chat when they upgrade: sub-agents, workspace file and Git tools (including SSH remote workspaces), web and Watchlists tools, character tools and Canvas.

The owner ruled on the upgrade path ("Keep them on if used"). A one-time migration turns Full agent tools on for profiles that already use agent features. Fresh installs, and profiles that never used those features, get the light set. A CHANGELOG entry explains the change.

PR #3295 also merged before its pre-merge review fixes were pushed. This task carries them:
- The served mobile companion's Console bridge was built without the light-surface reader, so phone sends always got the full agent surface.
- The light surface's fail-closed branches were untested.
- A light plan could reach the compact find/load fallback.
- Some settings and User Guide copy still promised agent features in plain chat.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Design: one small new module owns the upgrade (`Agents/full_agent_tools_upgrade.py`): a read-only detector over the profile's databases and a one-key config write under dev's config write lock. It runs once per launch as the first staggered boot worker (second, after recovery, since 2026-11-13) (after `_ui_ready`, on a thread), so it never blocks startup or the UI loop.

1. AC#1/#2 -- detector: open `agent_runs.db` (beside ChaChaNotes) and the workspaces DB read-only through `connect_private_sqlite` (a new registered read-only owner, inventory row C99, as `Chat/console_launch_wake` does); an absent file is "no signal", never created. Signals: a live (`deleted = 0`) row in `agent_definitions`; a `local-filesystem`/`ssh-filesystem` row in `workspace_runtime_bindings`; an agent run with a `tool_call`/`spawn` step whose tool is outside `LIGHT_SURFACE_TOOL_NAMES` (row steps and the legacy JSON blob), or any sub-agent run. Schema-tolerant (PRAGMA table_info / sqlite_master), cheapest query first.
2. AC#1-#4 -- the write: read the raw file (`read_cli_config_snapshot`); an explicit `[tools] full_agent_tools_enabled` (true or false) means nothing is touched; a recorded marker means the upgrade already ran. Otherwise one literal mutation (`apply_literal_settings_transaction_to_cli_config`) whose builder re-checks the raw file under the lock and sets `[tools] full_agent_tools_enabled = true` only when a signal was found, plus the marker. A fresh profile (config created this launch) skips detection. Never writes `false`.
3. AC#3 -- the marker lives in config.toml beside dev's other one-time flags (`[first_run]`, like `env_key_notice_shown`), so the upgrade runs at most once and a later "off" is never undone.
4. AC#5 -- time budget on the reads (SQLite progress handler); any detection or write failure writes nothing, leaves the light set, logs only an error type and the outcome (no paths' contents, no user text); a failed run retries next launch because no marker was written.
5. Wiring: `BOOT_WORKER_POLICY` row (first staggered; second, after recovery, since 2026-11-13), a starter in `TldwCli.boot_worker_starters()`, the boot-census allowlist row; mirror a written key into `app.app_config` on the UI thread, as the MCP hub's gate save does.
6. AC#6 -- CHANGELOG `[Unreleased]` entry; the User Guide's Full agent tools section explains the upgrade behaviour (no stamps).
7. AC#7 -- re-verify the six carried commits on today's dev: run their tests; fix what dev moved under them (the Settings ▸ Agents note's extra line pushes `test_new_clears_child_time_cap`'s New button off the harness screen); add `Tests/Architecture/test_console_agent_bridge_light_surface_wiring.py` to the PR fast lane (`FAST_LANE_TARGETS` + derived-artifacts.yml); raise the agent_service.py and settings_screen.py ratchet rows to their measured sizes (owner ruling 2026-10-04).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** A profile from before the light tool surface (#3295) that has no `[tools] full_agent_tools_enabled` and already uses agent features now gets `full_agent_tools_enabled = true` written once, at its first launch on this version, so plain chat keeps the tools it had. Fresh and unused profiles keep the light set, and their config.toml is not touched. The six #3295 review fixes that missed the merge are in and correct on today's dev. Verified live on isolated profiles: a profile built with pre-#3295 dev code (2561efd658), the real llama.cpp server with `--log-prompts-dir`, and the served mobile companion.

**Approach**
- `Agents/full_agent_tools_upgrade.py` holds the whole upgrade. `run_full_agent_tools_upgrade` runs these steps in order:
  1. A recorded marker means the upgrade already ran: stop.
  2. A raw config that sets the key (true or false; `read_cli_config_snapshot`, no defaults merged) is left alone, and the marker is recorded.
  3. Detect the signals.
  4. With a signal, write the one key and then record the marker. Without one, record only the marker.
- **Signals** (`detect_agent_feature_use`, cheapest first):
  - a `local-filesystem`/`ssh-filesystem` row in `workspace_runtime_bindings`. Only those two kinds are ever created (folder and SSH bindings), and archived workspaces count.
  - a live (`deleted = 0`) `agent_definitions` row;
  - any `agent_kind = 'subagent'` run;
  - a `tool_call`/`spawn` step of a primary or sub-agent run whose tool is outside `LIGHT_SURFACE_TOOL_NAMES`. The query covers the per-row step log (canonical JSON, so it parses JSON rather than matching text) and the pre-v13 `agent_runs.steps` blob. A malformed row is treated as `{}`.

  A local `!command` run (`local_command`/`raw_cli`) is the user's shell, not a model tool call, so it is not a signal.
- **Cheap, read-only, bounded.** Bindings are read through the app's own `WorkspaceDB` (new `has_runtime_binding`). `agent_runs.db`, which sits beside ChaChaNotes, is opened only if it exists, through `connect_private_sqlite` with `read_only=True, must_exist=True`. That is a new owner, `agents.full_agent_tools_upgrade`: inventory row C100 (C99 before the 2026-11-12 rebase; dev minted C99 for the plugin backup reader) plus backup-inventory rows, and it never creates, migrates or reconciles the database (the `chat.launch_wake` precedent). A progress handler enforces a 5 s budget. Measured on a loaded machine: 63 ms for an empty profile and about 1 s for 200,000 steps with no tool use (the worst case, because every other signal returns early).
- **The write.** One `apply_literal_settings_transaction_to_cli_config` mutation of `("tools",): {full_agent_tools_enabled: True}`. Its builder re-reads the raw file under the config write lock, so a value the user set in the meantime wins (mutation-checked, M1/M5). It never writes `false`.
- **When.** *(Superseded 2026-11-13: it is now the second member, right after `actor_pack_recovery`. See "CI lane and boot-order fixes" below.)* The upgrade is the first member of `BOOT_WORKER_POLICY`'s staggered tier (`_run_full_agent_tools_upgrade` / `full-agent-tools-upgrade`, `thread=True`), so it runs after `_ui_ready` on a worker thread and never blocks startup or the UI loop. The body in `app.py` hands over `local_workspace_db`, `chachanotes_db`, `app_config` and `call_from_thread` explicitly, because the app-lookup census pins Agents at zero `getattr(app, ...)`. A written key is mirrored into `app.app_config` on the UI thread, as the MCP hub's gate save does, so setup's Summary and Tools step agree. The worker closes only its own thread's `WorkspaceDB` connection.
- **Failure (AC#5).** Any exception, including a timeout, a non-landing write or a missing workspaces database, writes nothing, records no marker (so the next launch retries) and logs only `error_type`. The success line logs `outcome=` and `signal=` (a fixed kind), never a path or a tool name. Both diagnostics are reviewed into `production-diagnostic-inventory.json`.

**Decisions and deviations from the plan**
- **The marker lives in the workspaces database, not config.toml (plan step 3 changed).** Dev pins "a launch that changes no setting leaves config.toml as it found it" (`Tests/ProductionApp/test_config_profile_isolation.py`, TASK-35835/36385), and AC#2 says nothing is written for a no-signal profile. A config marker would have rewritten every upgraded profile's file. The marker is a `full_agent_tools_upgrade` row in `workspace_agent_backfill`, dev's existing once-per-profile backfill table (the workspace agent backfill's `assistant_defaults` row lives there). `WorkspaceDB.is/mark_agent_backfill_complete` take the key, and their default keeps old callers. *Reading of AC#2:* for a fresh or unused profile, config.toml is byte-identical and no key is written. The only write is that bookkeeping row, which AC#3's marker needs, in a database dev already writes at every first boot.
- **dev's `_CONFIG_MIGRATIONS`/`config_schema_version` runner was not used.** It is a pure config-to-config transform that runs in memory on every load, and its persist path rewrites the whole file with a backup, synchronously before the UI. This decision needs database reads and must write one key, off the UI thread. dev's actual one-time pattern is closer: a deferred boot worker plus a recorded flag, retried when it fails.
- **No comment-preserving TOML writer exists on dev** (`password_dialog.COMMENT_LOSS_WARNING` says so). *Superseded in the resume fix below:* the first version used the structured settings writer, which re-serialised the whole file and dropped the user's comments (review round 1, F1-10). The upgrade now adds one line through `config.insert_absent_cli_config_bool` and keeps every other byte.
- No fresh-profile special case (plan step 2): a fresh profile has no signals, so the general path keeps it light.
