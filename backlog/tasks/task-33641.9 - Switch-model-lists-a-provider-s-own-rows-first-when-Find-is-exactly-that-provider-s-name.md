## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In Switch model, typing a provider's name into Find ranks rows by text match alone, so an aggregator whose model ids start with that name (OpenRouter's openai/...) can outrank the named provider's own rows, and the named provider's row can be the last of the 30 listed. Found by Phase 8's Task 2 review (TASK-33008.2): after a return from Settings the reopened switcher highlighted an aggregator's model for a provider that lists none. Phase 8 fixed the reopen case only (never highlight another provider's row on a reopen). This rider is the typed-query ranking.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 When Find's text is exactly a provider's display name or id, that provider's rows are listed before other providers' rows that merely match the text [Implemented reading: first within their group, and its first row highlighted (or nothing highlighted when it has no selectable row); groups keep their order, so a READY PROVIDERS, PREVIOUS or RECENT row of another provider can still be listed above a NEEDS SETUP row of the named one. This holds for providers the list can show: the name or id of a legacy alias no chat uses (`mistral`), or of a non-current unsupported provider, ranks as any other text.]
- [x] #2 A query that is not exactly a provider's name ranks as today, pinned by the existing Find tests or by tests rewritten on purpose and named
- [x] #3 A test drives the two measured cases: a provider with an empty list beside a ready aggregator whose ids start with its name, saved and unsaved

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Find that is exactly a provider's display name or id (casefolded, surrounding spaces ignored) now ranks every row of that provider first. All in tldw_chatbook/Widgets/Console/console_model_popover.py:
- `_names(query, provider)` is the one test; `_pair_score` returns -1 for such a provider's rows, before the token check, so an id that is in neither the model ids nor the name ("llama_cpp" for "llama.cpp") now matches that provider's rows. Typed rows and their order inside the provider are unchanged.
- READY matches sort by score, so the named provider's models lead the 30 (they were last, or cut, behind 30 or more of OpenRouter's "openai/..." ids). NEEDS SETUP's rows were in provider order and are not sorted by score; a stable sort moves only the -1 rows to the front, and the eight-row group cap never cuts the named provider (as it already never cut a returned one). The highlight is the lowest score, so it is that provider's first row: a NEEDS SETUP row in apply mode too.
- A ready provider that lists no models has no row; Find naming it now opens READY PROVIDERS with its "no models reported · type its name and an id" line, the line a reopened list already showed. The named provider with no row to choose (it lists nothing, or a pick cannot take its NEEDS SETUP rows) highlights nothing: `_highlight_target` extends Phase 8's reopen rule (that provider's row or nothing, never another provider's match) to the typed name, so Enter says "Choose a model: type to search, then Enter." instead of applying the aggregator's openai/gpt-0 (round-1 review; it was highlighted, and Enter applied it). A reopen with "OpenAI " and the same query without the trailing space now agree. The loading-line filter now drops the line already shown (`row not in returned`) instead of testing the reopened key, the same rows for a reopen.
- `_typed_rows` treats an exact id like an exact name: a search, not a model id ("llama_cpp" offered itself as a TYPED MODEL ID for this chat's provider).
- Round 2: the name test reads only providers the list can show. `_visible_providers` (behind the `_highlight_target` guard) and `_typed_rows` now both take `_readiness_targets()`, which leaves out a legacy alias no chat uses, as readiness already did. Before, "mistral" matched the unused alias `mistral` (Mistral AI (legacy alias)) by id: no row was its, so the guard highlighted nothing and Enter applied nothing although Mistral AI's own mistral-* rows (or an Ollama server's mistral:* rows) were the matches, and no TYPED MODEL ID row was offered for the chat's provider (the `_typed_rows` half predates round 1, same root cause).
- Round 3: `_typed_rows` takes only its exact-id test from `_readiness_targets()`; its display-name checks (the exact name, and the name-and-space pairing) read every catalog provider again, as before this task. Only an alias's id collides with search words (`mistral`); its name ends in "(legacy alias)" or "(legacy generic)". With the unused alias out of both checks, "llama.cpp (legacy alias)" matched llama.cpp's name and a space, so "(legacy alias)" was offered, and highlighted, as llama.cpp's TYPED MODEL ID, and Enter applied it (Mistral AI's alias likewise). It now offers no typed row and highlights nothing, as before the task.
- Not changed: groups keep their order, so a PREVIOUS or RECENT row of another provider is still listed above (but not highlighted over) the named provider's rows. `_capped`'s keep of a reopened provider's first row now acts only under a query that is not that provider's name, which no caller opens; it stays for the popover's documented contract.

Tests (Tests/UI/test_console_model_switcher.py, gated whole in the UI PR census):
- New `test_find_with_exactly_a_providers_name_lists_its_rows_first[empty-unsaved|empty-unsaved-pick|empty-saved|empty-saved-ready|listed]`: the measured cases (OpenAI with an empty list beside a ready OpenRouter with 35 "openai/" ids, unsaved and saved) plus a listed case, with Azure OpenAI and Custom OpenAI-compatible NEEDS SETUP rows whose names hold the text. Typing "openai" with real keys; then Backspace ("opena") ranks as before (AC#2). Red at the base for all four: Azure's row first under NEEDS SETUP, OpenRouter's rows first under READY PROVIDERS. Round 1: `empty-unsaved-pick` added, and `empty-saved-ready` rewritten on purpose to expect no highlight (and an Enter that applies nothing); with the `_highlight_target` guard reverted those two and `no-models-saved` below fail (3 failed, 113 passed), with it 116 passed.
- New `test_find_with_exactly_a_providers_id_lists_its_rows_first`: "llama_cpp". Red at the base (only the TYPED MODEL ID row).
- Rewritten on purpose (AC#2), each pinned today's ranking for an exact name: `test_a_highlight_pair_past_the_match_cap_stays_listed[the-pair|returned-no-pair|returned-pair-no-longer-listed]` (the pair is now past the cut of OpenAI's own 31 models, since the aggregator no longer pushes them; the returned cases now assert OpenAI's rows lead), `test_a_highlight_pair_keeps_its_needs_setup_row[eight-rows-a-group|eight-rows-a-group-no-pair]` (the user's own "OpenAI" no longer lets the group cap cut OpenAI's row) and `test_a_list_reopened_from_settings_never_highlights_another_providers_row[no-models-saved|no-models-unsaved|model-no-longer-listed]` (the user's own "OpenAI" highlights OpenAI's row, else nothing, and the saved-empty case shows its line). With the popover change reverted, all 12 new or rewritten cases fail and the other 99 pass; with it, 111 passed.
- Round 2: new `test_find_with_an_unused_legacy_alias_id_ranks_as_any_text[mistral-ai|ollama-served]`: Find "mistral" highlights Mistral AI's mistral-large-latest (an Ollama chat: the server's mistral:7b), Enter applies it, and the chat's provider gets a TYPED MODEL ID row "mistral". Red at fbe21abadd (no highlight, 2 failed); with only the `_typed_rows` half reverted, 2 failed (no typed row); with both, 2 passed.
- Round 3: new `test_find_with_an_unused_legacy_alias_name_offers_no_typed_id[llama.cpp (legacy alias)|Mistral AI (legacy alias)]`: no TYPED MODEL ID row, nothing highlighted, and Enter applies nothing. Red at 02fb7f36e1 (2 failed: a typed row (llama_cpp or mistralai, "(legacy alias)")); with the fix, the six `-k legacy_alias` tests pass, the round-2 test among them.
- Every other Find test passes unchanged, among them the 2,000-model keystroke budget and `test_a_typed_id_another_provider_lists_under_the_name_is_one_down_away` ("OpenAI gpt-y" is not a name).
