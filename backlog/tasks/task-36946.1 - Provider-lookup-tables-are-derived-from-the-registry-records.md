## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Hand-maintained provider tables in `Chat/provider_readiness.py`, `Chat/provider_continuation.py` (a typing Literal and `_PAIRINGS`), `Chat/console_session_settings.py`, `Chat/provider_catalog.py` and `Agents/native_tools.py` repeat fields already on `ProviderRecord`. The registry already derives `NATIVE_TOOLS_KEYS` while `native_tools.py` keeps its own list.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F11; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).

## Implementation Plan

1. Probe each hand table against its registry derivation (same set/order) before replacing it.
2. Registry: add `base_url_required`, move `normalize_provider_config_key`, add derived key sets, `default_api_key_env_var`, continuation keys.
3. Replace tables in readiness, continuation (`_PAIRINGS`), console_session_settings, native_tools; Provider_Contract reads from the registry; drop the two outbound-import pin rows.
4. Parity tests assert against the derived values.
