## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Closed without a product change: the premise is false at fc9f3ec375 (Phase 9 Wave 3 head). Both ACs hold there; one new mounted test pins AC#1.

- No refresh is missing. When Chat settings closes, `ChatScreen.on_screen_resume` re-registers the Console footer twice (directly, and through `_sync_console_transcript_guidance` → `_sync_console_setup_modal` → `_apply_console_setup_block`), and the control-bar sync re-registers it again. Each registration reads the live focus (`_console_rail_focus_active`).
- The rail footer the entry-points test once read after Esc was truthful: focus had stayed on the rail's Model toggle after the rail's Change action, not after Chat settings. TASK-33007 found this in 3bc3d9c33b ("where focus ends after the rail's Change depends on whether the Model section was already open") and rewrote `_close_chat_settings` to press Esc, so AC#2 already held.
- Probe at the base (211x44): opened by Ctrl+O from the composer, then Esc, focus is the composer and the footer is the composer's, including `Alt+A approval | Alt+C context rail`; opened from the Provider chip, the same; opened from the rail's Model toggle, focus returns to the toggle and the footer leads `Esc composer · F6 panes`, which is that focus's footer (TASK-32322).

New test: `Tests/UI/test_console_switch_model_entry_points.py::test_chat_settings_closed_by_esc_leaves_the_focused_widgets_footer` opens Chat settings from the rail's Model toggle, then from the composer, closes each by Esc, and asserts focus went back to where it was opened and the footer is that widget's: it leads with the rail's exits for the toggle, and for the composer it does not, and it keeps Alt+A and Alt+C. Negative control: with both resume-time re-registrations removed (chat_screen.py `on_screen_resume`'s call and `_apply_console_setup_block`'s) it fails, timing out on the covered footer. With only the direct call removed it still passes, because the setup-block path re-registers. It joins the UI PR gate census as a node id (334), 3 of 3 serial.

For the owner: with focus inside a rail, the 211-column footer still leaves out Alt+A and Alt+C. The rail's exit hint is prepended (TASK-32322), and the footer drops hints from the end when it runs out of width. That holds whether or not a modal has been open, so it is outside this rider's refresh premise.

Lesson added mid-file in backlog/docs/lessons-testing-evidence.md ("A footer that names the wrong keys may be right about where focus is").
