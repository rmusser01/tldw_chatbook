## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: TASK-34000.19 fixed the Chatbooks screen's `i` (import), which ended the app. In Textual 8, `push_screen(..., wait_for_dismiss=True)` outside a worker pushes the screen and then raises `NoActiveWorker`. Its review found the same pattern on the same screen's other keys: `c` create (`action_create_chatbook`), `t` browse templates (`action_browse_templates`, twice), `m` manage exports (`action_manage_exports`), and the export-management window's button-driven delete (`_delete_selected` via `on_button_pressed`).

The live import also showed:
- `ImportProgressStep.on_show` starts the import twice, so the result screen reports the second run ("⊘ Nothing Imported — Skipped … already present").
- The result screen's Close calls `App.pop_screen(result)`, which raises `TypeError` in Textual 8 (`pop_screen` takes no argument). The wizard never dismisses, and the screen's success toast and refresh never run.
- The Chatbooks screen paints only the shell at 160x45 until clicked, and `i` works only after a click into the pane.
- "Browse for Chatbook" is clipped under the drop zone (only Tab reaches it).
- The wizard defaults `prefix_imported=True`, so imported titles read "[Imported] …".
