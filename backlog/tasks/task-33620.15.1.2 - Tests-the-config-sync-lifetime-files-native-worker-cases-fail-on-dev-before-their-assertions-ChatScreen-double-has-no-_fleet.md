## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Test-harness drift, not a production defect. The five native-worker cases passed at 8b2120305d and failed from PR #3023 (14e13bb82c, 2026-10-16), which made every full sync read the screen's attach visit (`_current_console_attach_visit`). A real screen has claimed its runtime at mount, so that read is a memoised lookup; the bare `Surface` double had no runtime, so the read claimed one and the attach read `console_view_hooks` -> `self._fleet`. Behind that were more answers the double lacked: the visit's class-default flags (bound by `Surface.__getattr__` as `MethodType(0, ...)`), `_is_active_console_screen` (`self.app`), and, from PR #3211 (TASK-33620.15.7, 2026-10-26), `mode_bar.content`, compared before `update(..., layout=False)`.

Repair (Tests/Backup_Recovery/test_console_config_sync_lifetime.py, `_WORKER_RETRY` only): the double now models the mounted, visible Console the cases interrupt. It has fleet and session-instruction owners for `console_view_hooks`, a completed attach visit, the runtime already claimed (as `restore_state` does before mount), and a mode bar that answers `content` like a Static. No assertion changed. The double's `_console_chat_controller=None` was unread in effect: removing it left 5/5 green, because the only read sits in `_projection_inputs`, whose failure `project_console_tick` swallows. The four cases that reach the native worker's refresh now also assert that the refresh recorded its projection inputs (`config_sync._cadence(screen).values is not None`).

Evidence, with production restored by Edit after each mutation. Every red is on the case's own assertion line in the subprocess script:
- M1, retry runs the control bar only: native-worker, real-pause, inprogress and external red at `len(workers)==1`.
- M2, retry ignores the maintenance pause: real-pause only.
- M3, retry ignores an in-flight sync: inprogress only.
- M4, no torn-down guard: teardown only.
- M5, the entry guard ignores a pending replay: external only.
- M6, `_projection_inputs` reads the controller unguarded: the four refresh cases red on the new cadence assertion, and 5/5 green with that assertion removed.
- AC3: removing the chat-controller answer turns the same four red on that assertion.
