## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Setting a key-encryption password in setup starts a lifecycle that nothing else in the app supports.
- Launching with python -m tldw_chatbook.app afterwards crashes in the unlock prompt (NoActiveWorker) and exits. The crash output prints frame locals that include part of the password verifier.
- The packaged tldw-cli prompt asks once, with no retry and no reset. A wrong password drops the user into Backup & Restore with no explanation.
- Protect ignores existing encryption, and Enter after success reopens the password dialog. A different second password rewrites the verifier over keys that are still encrypted under the first one. That locks out both launch paths, the step claims the keys are 'unchanged (plain text)', and every later save fails.
- No reachable screen can turn encryption off or change the password, although Protect points to Settings ▸ Privacy & Security.
- Encrypted values pass the API-key validity check, so any skipped decrypt would read as Ready and send ciphertext as a key.
- The password dialog opens without focus, so typed characters vanish.
- Protect misreads keyless, env-key and unsaved-key users, and its copy names a Skip button that doesn't exist.

This task implements SF6 (an encryption lifecycle with one owner) and roadmap items N8–N10 from Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md. It resolves protect-summary-01 to -07, new-protect-summary-02 and new-protect-summary-03. The risk is high, because a mistake here locks people out of their own app. Keep startup unlock pre-TUI and isolated, as the Backup_Recovery design intends. Never offer a way to start without decrypting until encrypted values read as absent.

Coordination:
- Open PR #2868 deletes UI/Tools_Settings_Window.py, the only code that calls disable_config_encryption and change_encryption_password. Once it merges, the wizard's Protect step is the only encryption UI, so this task adds the Settings ▸ Privacy & Security controls (enable, change password, turn off), porting them from git history.
- Update task-33621.25 to call out the module-path unlock as a user lock-out, and remove its census row along with the fix.
- Only the Protect-step parts depend on TASK-34100.1. The core can start immediately: module-path unlock through the shared startup preflight, ciphertext read as absent, refusing a second enable, validating before writing with rollback, and unlock retry and reset.
