## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Stores import `_core_*` helpers from participants at module top (e.g. `ChaChaNotes_DB.py:119-125`), and 66 production modules import participants, so private names have become de facto public API.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F10; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

1. AST-enumerate underscore names imported from `Backup_Recovery/participants.py` outside Backup_Recovery.
2. Rename the 11 helpers to public names (real definitions), keep `_x = x` aliases at the end of participants.py.
3. Rename every importer, string pin and patch target in tldw_chatbook/, Tests/, scripts/, Helper_Scripts/.
4. Add an AST guard in Tests/Architecture with a negative control.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Every participants helper imported outside Backup_Recovery has a public name
- [x] #2 Old private names keep working until no importer remains
- [x] #3 No module outside Backup_Recovery imports an underscore-prefixed participants name
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Renamed the 11 underscore helpers that stores/services import from `Backup_Recovery/participants.py` to public names (`core_access`, `core_cached_connection`, `core_closing`, `core_getter`, `core_operation`, `core_transaction`, `register_core_connection`, `close_settled_core_cache`, `repository_participant`, `retire_current_thread_caches`, `retired_core_connections`). The public name is the real definition; `_x = x` aliases sit at the end of participants.py (AC#2). All importers, string pins and patch targets in tldw_chatbook/, Tests/ and scripts/ moved to the public names by word-boundary rewrite (AST-verified no private import remains).

Guard: `Tests/Architecture/test_participants_public_names.py` (AST scan, plus a tmp_path negative control). RED evidence: with `from ...participants import _core_access` temporarily appended to `DB/Guardian_DB.py` the guard failed with `'DB/Guardian_DB.py:881 _core_access'`; reverted.

Round 2 (coordinator ruling: AC#1/#3 cover every Backup_Recovery participants module): `raw_participants` helpers `_file,_mkdirs,_remove_temporary,_replace,_scope,_selected,_service_file,_service_mutation,_runtime_operation` are now `file,mkdirs,remove_temporary,replace,scope,selected_target,service_file,service_mutation,runtime_operation` (`_selected` -> `selected_target`: plain `selected` collides with locals, and `selected_path` trips the diagnostic-inventory path-token rule), and `async_file_participants._FileJob` is `FileJob`; private aliases kept. Importers, attribute uses, setattr/getattr string targets and source-fingerprint pins moved by AST rewrite. The guard now covers every Backup_Recovery module whose name contains "participant" (incl. `rag_definition_participant`); negative control with an injected `raw_participants import _scope` failed with `DB/Guardian_DB.py:881 _scope`, then reverted.

Out of scope: test-only reads of internals such as `participants._repository_types` / `raw_participants._states`.

Tests: Tests/Backup_Recovery + Tests/DB + 39 changed test files show the same pre-existing xdist/timing failures as base; Tests/Architecture serial: 48 failures, all in the base list. preflight passes.
