## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`Tests/Wizards/test_first_run_setup_wizard.py::TestComposeCrashPolicy` asserts after fixed waits: `pilot.pause(0.2)`, `pause(0.4)` before reading the Summary rows, and `pause(0.8)` after a Retry. On the TASK-34100.8 branch, a full-file run fails one of these tests far more often than base does. Run alone, the class passes.

Evidence gathered in TASK-34100.8 review round 2 (2026-10-05). All runs were sequential and plain-command unless noted.
- HEAD failed in 4 of 5 full-file runs:
  - 3 runs failed `test_optional_step_failure_is_removed_and_reported_in_summary` with `assert 'RAG' in ''`. The Summary render had not finished within the 0.4 s pause.
  - 1 run, with the three branch-added tests deselected, failed `test_partial_retry_failure_rolls_back_and_next_retry_succeeds[refresh]` instead.
  - 1 run, with `test_summary_footer_shows_the_effective_config_path` deselected, passed.
- The round-1 head `bdc11fbe3a` failed the same way in its one run. Base `a1571e86db` passed the class in 3 of 3 runs.
- The class alone passed 3 of 3 at HEAD (32 passed each). The Summary render took 0.16–0.27 s in isolation at both HEAD and base.
- An instrumented run showed the stall is not I/O:
  - The `setup_started` config write finished in 50 ms.
  - The event loop then went quiet for about 0.43 s after the Summary was shown, so queued `on_show` messages ran late and the config load in the render worker started 0.47 s after the step activated.
- A full-file run at HEAD with the cyclic GC frozen and disabled (scratch `-p` plugin) passed the whole class.

The working explanation is that a gen-2 GC pause in a long single-process run pushes these fixed-budget waits over. The branch's Voice step mounts more widgets in every wizard: pickers, the key row and the service row. Product behaviour is unaffected, since one wizard runs per process. The core CI job runs this file whole (`--dist loadscope`) on pushes to `main`, so the flake would surface there.
<!-- SECTION:DESCRIPTION:END -->
