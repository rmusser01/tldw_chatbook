## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: sync, import and Folder files are the surfaces that touch the user's files on disk, and PRODUCT.md rules out interfaces that need log-reading to be trusted. Here, a power user with a synced or git-backed vault (Alex) is told a history is empty when it could not be read, and must decode raw nanosecond timestamps to choose between two versions. That user also has to stage a commit without ever seeing a diff. A first-timer (Jordan) is promised imported notes and shown a closed folder. On the unlinked Folder files screen, the side rail disappears entirely at 120x36. These are P2 findings with workarounds. Causes are at origin/dev 2d34cbf80d.

N-19, Sync Receipts says 'No writes yet.' when the history could not be read. The verifier confirmed this live by fault injection. The root showed 'Sync root activated.' and '✓ Up to date', while Receipts read 'No writes yet. Sync writes are listed here when you open this list.' It is not naturally reachable on small or medium roots, and reopening the list clears it, which is why it is P2. Verified cause: refresh_receipts (UI/Library_Modules/library_notes_sync_controller.py:875-913) catches each root's history-read failure, logs it and continues. It then publishes an empty list, which the canvas renders as the empty state (Widgets/Library/library_notes_sync_roots_canvas.py:122-127). It also reads only the roots on the visible page, and does not refresh when a root becomes active while the list is open. A realistic trigger is the history read refusing while sync admission is still closed, just after launch. The screen's own comment calls Receipts the only trace of the writes lasting sync performs on its own. Suggested direction: count failed reads and show "Couldn't read sync history for N folder(s) · Retry". Use the empty copy only when every read succeeded, iterate all roots, and refresh when a root activates.

N-27, 'View 10 imported notes' lands on a collapsed folder. After the receipt 'Import completed. 10 notes created', the button shows the list with '▸ md-folder' collapsed beside the other folders, and none of the 10 notes is visible. Suggested direction: on that arrival, use the tree locator to expand the destination, focus the first imported note and scroll it into view. This builds on TASK-34000.28's N-28 fix, which makes the locator load the notes of every folder it expands. Land that first.

N-35, sync comparison copy that must be decoded. Existing task TASK-32578 owns writing copy for the three lasting-sync refusal reason codes that have none. This task covers the rest. The comparison reads 'Note v2, updated 2026-10-03T07:31:38.164000+00:00 · 8 lines/74 chars' beside 'File modified 1791012703718513183 ns · 8 lines/75 chars' (Widgets/Library/library_notes_add_from_files_canvas.py:851-856), so the user cannot tell which side is newer. Unknown causes are named by Python exception class, for example 'Recovery failed — RuntimeError'. The fallbacks are at Library/library_notes_lasting_sync_state.py:1185 and :1201-1204. TASK-32545 (Done) chose to name the category there because no cause could be named, and this task replaces that with a plain sentence. The line 'Resolution history unavailable — it starts after this root is activated' also still shows after the root is active. Suggested direction: show both times as local 'YYYY-MM-DD HH:MM' and mark the newer one. Replace the class-name fallback with a plain sentence plus a next action, keeping the class name in the log only. Show the history-disabled line only while the root is inactive.

N-36, Folder files' Session Git shows status but never a diff. After an edit in a linked git vault, Session Git lists 'EDITED README.md · READY TO STAGE · Git: unstaged' and 'Status: CURRENT · READY — 1 can be staged · 0 can be unstaged.' It offers Stage and 'Show bulk · 1 stage', with no way to see what changed, including at Confirm commit. Widgets/Library/library_file_notes_git_panel.py has no diff path. Suggested direction: a read-only 'View diff' per row, using the staged diff for staged rows. Run git with external diff and textconv disabled, and keep paths out of the option position. Bound the output with the sync comparison's display limits, and add a staged-diff disclosure to Review commit.

N-37, unlinked Folder files is mostly blank, and the rail moves or vanishes. With no folder linked, 120x36 shows three full-width lines ('Folder files · No folder selected', 'Choose a notes folder.  Choose folder…   Review recovered pairing…', and an explanation), then about 25 blank rows. The Library rail is not rendered at all. Across sizes the screen is 61-90% blank, and where the rail does render, it starts 3-4 rows lower than on every other Library route. Triage rated this P3 because the rail-before-link layout follows an owner ruling. It was kept at P2 because the rail is missing entirely at 120x36. Suggested direction: keep the work pane mounted before a folder is linked, with a centred 'No folder linked · Choose folder…' empty state. Move the folder-authority and root rows into the work column so the rail stays put, and hide 'Review recovered pairing…' until a pairing exists. This changes an owner-ruled layout and adds a new empty state. Under the standing rule that each redesigned screen or mode needs explicit owner approval (improvements/ranked.md R-17), it needs that approval before it ships.

Review finding(s): N-19, N-27, N-35, N-36, N-37. Source: qa/notes-library-ux-review-2026-10-02/report.md
