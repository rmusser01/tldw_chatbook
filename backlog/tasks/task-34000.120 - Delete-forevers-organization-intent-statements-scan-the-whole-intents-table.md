## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: PR #3423 re-review 3 (m-2). Delete forever runs `CharactersRAGDB._NOTE_PURGE_ORGANIZATION_SQL` (`tldw_chatbook/DB/ChaChaNotes_DB.py`, about :20702) inside its `BEGIN IMMEDIATE` transaction: a `DELETE` of the note's unacknowledged link intents and an `UPDATE` that scrubs its acknowledged ones. Neither can use v59's `idx_notes_organization_intents_note_subject_latest`, because their `WHERE` does not imply that partial index's own `WHERE domain = 'notes.folder_link' OR (domain = 'notes.keyword_link' AND ... = 'note')`. Measured on 2026-11-07 with `EXPLAIN QUERY PLAN` on a real `CharactersRAGDB`: the `DELETE` scans the pending partial index plus a full scan for the `predecessor_intent_id` foreign-key check (no index on that column), and the `UPDATE` is a full scan with `json_extract` per row. 50,000 acknowledged intents took 43 ms, all of it while the purge holds the write lock. Acknowledged intents are kept for good as lineage, so the table only grows. Small next to the purge's FTS `optimize` today, but it scales with the user's whole organization history rather than with the one note.
