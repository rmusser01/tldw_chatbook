## Description

Why: PR #3423 re-review 2 (m-1), confirmed on both arms. When the Sync v2 organization group is not ready, the bulk Add/Remove keyword worker refuses every checked note up front (`tldw_chatbook/UI/Library_Modules/library_notes_controller.py`, about :7540-:7552), before the busy-open-note check and before `change_local_note_keyword` could report a note that already has, or never had, the keyword. So with the group not ready, Remove keyword... with a keyword none of three notes carries says "Removed 'zzznone' from 0 notes · 3 could not be changed — still checked, so you can try again. Sync v2 is not ready ..." and select mode stays, where before it said "... · 3 did not have it" and ended. A busy open note likewise gets the not-ready reason instead of "The open note has unsaved changes." Nothing is written either way and the User Guide describes the current wording, so this is precision of the receipt, not data.
