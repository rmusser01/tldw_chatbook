## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Slice D2 (spec §5.3, §5.4). Note bodies are the truth for which documents a note cites. A derived, device-local `note_source_links` table in the ChaChaNotes DB makes the relationship fast to query. It is rebuilt from the note body on every save through the note session, inside the save transaction and off the UI thread, and backfilled once at migration. It is never synced and never exported. It powers the Media Info line `Notes that cite this (N)`, the note Info line `Sources (N)`, and the Write in… picker's `Notes that cite this document` group. Migration duties (CLAUDE.md gotcha 1): bump the schema version, add a `VALID_TABLES['chachanotes']` entry and an `EXPECTED_CHACHANOTES_INDEXES` entry, and capture a query plan with `sqlite_stat1` absent plus its `scripts/index_plan_pin_census.tsv` row.
<!-- SECTION:DESCRIPTION:END -->

- [ ] #2 The migration backfills relationships for existing notes that already contain media links
- [ ] #3 Media Info shows `Notes that cite this (N)` and note Info shows `Sources (N)`, each entry opening its target
- [ ] #4 An index failure never blocks a note save; Info then shows `Sources: couldn't refresh — Rebuild`
- [ ] #5 Schema version, VALID_TABLES, EXPECTED_CHACHANOTES_INDEXES and the plan pin are updated in the same commit, and the pinned plan uses the new index with sqlite_stat1 absent
- [ ] #6 Save latency with the index is measured against the existing note-save budget and recorded in the task notes
- [ ] #7 In-memory SQLite tests (rebuild, backfill, removal) and a Pilot test of the Info lines fail on dev before the change
