## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-33620.8 turned `[rag_citations] canonical_writes_enabled` on in the shipped config (owner decision 2026-10-27, persist by default). The app writes the full default config into a new profile's config.toml on first run. So every install created since the section existed (2026-07-23) carries an explicit `canonical_writes_enabled = false`, and keeps citation records off after upgrading. A profile without the key gets the new default.

Changing those installs means the first real config migration (`_CONFIG_MIGRATIONS` in config.py, TASK-26040): it rewrites the user's config.toml, after a backup, and drops hand-written comments. It also can't tell the old shipped `false` from a deliberate recovery-switch `false`, since no UI exposes the switch. This needs an owner call: migrate, surface a one-time prompt, or leave existing installs as they are.

**Owner decision 2026-10-30: a one-time prompt.** On the first Library-cited reply after upgrading, ask once "Keep a record of which sources replies cite?", save the answer, and never rewrite config.toml. The answer therefore has to live outside config.toml and outrank the old shipped `false` written there at first run.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Installs whose config.toml still carries the old shipped `[rag_citations] canonical_writes_enabled = false` are now asked once, after their first reply sent with Library evidence, "Keep a record of which sources replies cite?". The answer is saved beside config.toml; config.toml is never written for it (owner decision 2026-10-30).

**Measured first (origin/dev 8ae979d81b).** With the bootstrap profile's config.toml carrying the explicit `false`, the composed policy is off, the staged Library send goes out unlabelled ("not saved as citations for this reply"), the reply completes, and nothing asks. **Design**
- Answer store: `Chat/citation_records_choice.py` keeps `citation_records_choice.json` (`schema_version`, `answer` keep/off, `answered_at` in the ADR-173 shape) beside the effective config.toml. Every read and write goes through the ADR-126 raw participant boundary as the settings-file owner `citations.records_choice` (route `citation_records_choice`, after the `notes.templates` precedent): `settings_file_participants` binding/route/owner map, `raw_participants` binding-check, reentrancy and temporary-publication route sets, a config-location `_Definition` in `config_adapter`, the Settings backup group, a recovery read limit, a recovery label, and owner inventory rows (producer census and the installed-file table). Writes publish a temporary file by replace. An unreadable or malformed file is neither an answer nor a reason to ask.
- Precedence (`CitationProvenanceRuntimePolicy.from_config()`, so boot composition and Chatbook export/import agree): `true` or a missing key is on, and the answer file is not even read; exactly `false` is on only with a saved Keep; `"false"`, `0` or a malformed value stays off and is never asked about.
- Who is asked: exactly `false`, no answer file, and no citation record of the profile's own (`rag_citation_traces` with origin `local` or `legacy_inferred`). Decided once per process, off the UI loop, and only in the `writes_disabled` key state (a keyring problem is not a question).
- When: both runtime capture seams (staged and Automatic) call `chat_rag_events.note_unrecorded_citation_evidence` with the turn's own session after a capture that sent evidence with no builder. Count discovery for that session's settled reply then asks (`citation_counts.ask_pending_records_question`, one line in ChatScreen's discovery worker), once per process and only while Console is the top screen.
- The question is a `ConfirmationDialog` subclass (`UI/Console_Modules/citation_records_question.py`): no button focused on open (the dialog body is), Keep records styled primary rather than destructive, Escape or a backdrop click closes it unanswered (it returns after a restart).
- Applying: `CitationTraceRepository.set_canonical_writes_enabled` swaps the live policy under `_key_lock`; the answer is applied first and then saved, so a failed save keeps the answer until Chatbook closes and says so, naming the palette entry for answering again after a restart (it never promises to ask again: a reply recorded under an unsaved Keep makes the profile ineligible). The key is still provisioned on first use.
- Command palette "Console: Citation records…" reopens the question with the current state where the answer governs, and otherwise names what config.toml decides. The Sources window's records-off copy points to it.
- Docs: User Guide (`console/context-and-rag.md`, Older installs), ADR-024 amendment 2026-11-06, a testing lesson.
