## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-33620.8 turned `[rag_citations] canonical_writes_enabled` on in the shipped config (owner decision 2026-10-27, persist by default). The app writes the full default config into a new profile's config.toml on first run. So every install created since the section existed (2026-07-23) carries an explicit `canonical_writes_enabled = false`, and keeps citation records off after upgrading. A profile without the key gets the new default.

Changing those installs means the first real config migration (`_CONFIG_MIGRATIONS` in config.py, TASK-26040): it rewrites the user's config.toml, after a backup, and drops hand-written comments. It also can't tell the old shipped `false` from a deliberate recovery-switch `false`, since no UI exposes the switch. This needs an owner call: migrate, surface a one-time prompt, or leave existing installs as they are.

**Owner decision 2026-10-30: a one-time prompt.** On the first Library-cited reply after upgrading, ask once "Keep a record of which sources replies cite?", save the answer, and never rewrite config.toml. The answer therefore has to live outside config.toml and outrank the old shipped `false` written there at first run.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] #2 No config migration and no config.toml write: the answer is kept in a per-profile file beside config.toml, which backup and restore carry with Settings. A saved Keep outranks only an explicit `canonical_writes_enabled = false`; `true` or a missing key always means on, and a malformed value stays off.
- [ ] #3 On a profile whose config.toml has that explicit `false` and no saved answer, the first reply sent with Library evidence (staged or Automatic) is followed by one question, "Keep a record of which sources replies cite?", with Keep records and Don't keep. No button holds focus when it opens, so typing that was meant for the composer cannot answer it; Escape closes it unanswered.
- [ ] #4 Either answer is saved and the question is not asked again, in that session or after a restart. Keep turns records on at once: the next Library-cited reply shows "Cited sources (N)", and that row and its window survive a restart.
- [ ] #5 Never asked: a profile whose config.toml has `true` or no key (new installs; records on), a profile that already holds citation records of its own and was then turned off in config.toml, and a profile with a malformed value.
- [ ] #6 The answer can be changed later without editing config.toml, from the command palette ("Console: Citation records…"). Where config.toml decides instead, that entry says so.
- [ ] #7 The Sources window's records-off copy, the User Guide and ADR-024 (a dated amendment) describe the question, where the answer is kept and its precedence over config.toml.

Each fails on origin/dev.
- [ ] #9 Live: with an isolated profile whose config.toml carries the old explicit `false` (real app, real model), the question appears once, the choice sticks across a restart, and Cited sources work after Keep.
