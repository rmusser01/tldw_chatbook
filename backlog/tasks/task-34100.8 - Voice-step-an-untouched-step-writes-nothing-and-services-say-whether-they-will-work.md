## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Voice step says 'skip with Next if you don't want voice', but Next always saves. On every profile that passed Voice untouched, setup wrote a hybrid text-to-speech table: the OpenAI backend pointed at the PocketTTS port with OpenAI voice names. Summary then showed a false '✓ Voice — PocketTTS (default voice)'. A cloud user who already has an OpenAI key loses working speech on the very first run. A power user who re-runs setup to change one thing silently loses a working OpenAI speech endpoint, and Exit does not undo it. PocketTTS is preselected even though it is a separate server that usually isn't running, and a failed test says only 'Not tested yet — the sample failed'. Choosing OpenAI voice without a key blocks Next, and the only offered fix, 'Add API key in Settings', ends setup without warning. Keyboard users lose their test result and sample text one Tab+Space after testing. Edits under Advanced keep claiming 'PocketTTS' and are discarded on a service switch, and a fixed error stays on screen.

This task implements the Voice slice of structural fix SF3, a session draft that replaces commit-on-Next (Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md, §5.1, stage 2 'untouched means unwritten' and the voice part of stage 3). It extends the delta-aware writes that Tools, Appearance and Speech already use; it does not replace them. Resolves: voice-speech-01, voice-speech-03, voice-speech-04, voice-speech-05, voice-speech-06, new-voice-speech-02, new-voice-speech-03.

Coordination:
- **Where the code is.** The Voice step now lives in UI/Wizards/first_run_voice_step.py, moved verbatim by TASK-33921; the review's current-dev pointers were re-checked there on 3c439d606e.
- **Done tasks this contradicts.** voice-speech-01 contradicts Done TASK-32959 AC#2 and the Done TASK-32958 design. The test that pins today's save-with-default-opted-out behaviour is replaced on purpose.
- **Save path.** A save with 'Use as default' unticked must not let the speech settings handler write the current settings back as defaults. Without that, the Summary keeps its false '(default voice)'.
- **Re-run prefill.** It must read the raw text-to-speech table from the TOML. The loaded settings view lacks some tables, and the Speech step fell into exactly that trap (new-voice-speech-01, filed elsewhere in this programme). Summary and tracker marks are cross-cutting-02's.
- **Keep (§5.5).** The step leads with the outcome, keeps the plumbing behind Advanced, and verifies a real sample with the existing OpenAI key.
- **Live verification.** On the dev machine, 127.0.0.1:8765 (PocketTTS's port) is held by another session's proxy, which answers 404. Use a free port for a real PocketTTS server and a genuinely closed port for the not-running case.

## Implementation Plan

0. Room first. `first_run_voice_step.py` is pinned at 1,070 and the wizard at 3,177. Move the OmniVoice block (state check, install, sample, commit) into `first_run_voice_omnivoice.py` as an intermediate `SetupStep` subclass, so its `@on` handlers and `@wizard_work` workers stay registered (MRO-checked by `test_first_run_step_modules`). Lower both ratchet rows to their new sizes.
1. PocketTTS decision (root of voice-speech-03). The backend layer does not take a new provider cleanly: `BackendRegistry` is sealed ("accepts no new providers"), and the 8-provider tuple is pinned across Settings contracts, the Speech pane, the playground and about 25 modules. So PocketTTS's native API (`POST /tts`, form fields `text` and `voice_url`, streamed WAV, default port 8000) becomes a dialect of the existing OpenAI-compatible slot, selected by an endpoint whose path is exactly `/tts`. A small `TTS/pocket_tts_native.py` holds the form, the voice list and a WAV-header repair (the real server streams a RIFF/data size it cannot know, which the app's playable-audio check rejects). Both `OpenAITTSBackend` (Console, Lab, Settings test) and the wizard sample use it. The PocketTTS preset becomes `http://127.0.0.1:8000/tts`, `alba`, `wav`. Settings > Speech & TTS configures the same slot: its Base URL takes the `/tts` URL. Fix `Docs/User_Guide/openai-compatible-tts.md`. Record the decision as an AC note.
2. AC#1 [voice-speech-01]: pure `voice_draft_from_config(raw [app_tts])` (raw table from COMPREHENSIVE_CONFIG_RAW, never the loaded view), plus `should_persist_voice_config(draft, baseline, acted)`. Prefill and preselect from them. commit() posts nothing for 'No voice for now' or an untouched draft. Add a `persist_default_preferences` flag on `STTSSettingsSaveEvent`; `_persist_settings` skips the snapshot preference mutation when it is False. A ticked save writes endpoint, auth and the draft's own model/voice/format/speed as defaults. An unticked save writes no default selection. Model/voice/format still travel with the endpoint whenever the OpenAI-compatible slot is the voice replies use, so a PocketTTS URL is never paired with tts-1-hd/shimmer/mp3. Summary row reads 'OpenAI · tts-1-hd · shimmer'. Replace the pinning test. Add byte-identical tests: populated config, a first run with an OpenAI key, and a custom-endpoint re-run.
3. AC#2 [voice-speech-03]: 'No voice for now' is the first Service radio and the default when nothing is saved. A status line under the radio, fed by a worker probe that is a single TCP connect with a 0.5 s timeout for PocketTTS, plus key presence for OpenAI. Typed sample failures are classified into 'Test failed — …' copy: not running, key rejected, no endpoint, timeout, not audio.
4. AC#3 [voice-speech-04]: an inline masked 'OpenAI API key' field. The key is staged in step memory, like the Provider step's staged credential, and also recognised from the Provider step's staged OpenAI draft. It is written only at commit, through the same `openai_api_key` STTS key Settings uses, and `note_key_entered()` is called so Protect offers encryption. Refusal copy names the escapes. 'Leave setup and add key in Settings…' confirms first.
5. AC#4 [voice-speech-05]: restore focus to Test and Hear after a test. The sample Input gets `select_on_focus=False`. Commit falls back to the default sample. Enter in Sample text runs the test, and the step's hint line says so (the container asks the step for its hints).
6. AC#5 [new-voice-speech-02]: an Advanced field that diverges from the preset flips Service to Custom (no preset re-apply) and keeps the edits as the Custom draft.
7. AC#6 [new-voice-speech-03]: `SetupStep.clear_step_error()`, called on every Voice input, auth or service change.
8. AC#7 [voice-speech-06]: copy changes, a checkbox label with help text, auto-tick after a successful test (counts as acting), Test and Hear as variant default, Voice and Format pickers with 'Other…', and an auth label that names the key.
