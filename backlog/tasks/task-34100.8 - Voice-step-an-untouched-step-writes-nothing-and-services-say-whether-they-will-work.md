## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Voice step says 'skip with Next if you don't want voice', but Next always saves. On every profile that passed Voice untouched, setup wrote a hybrid text-to-speech table: the OpenAI backend pointed at the PocketTTS port with OpenAI voice names. Summary then showed a false '✓ Voice — PocketTTS (default voice)'. A cloud user who already has an OpenAI key loses working speech on the very first run. A power user who re-runs setup to change one thing silently loses a working OpenAI speech endpoint, and Exit does not undo it. PocketTTS is preselected even though it is a separate server that usually isn't running, and a failed test says only 'Not tested yet — the sample failed'. Choosing OpenAI voice without a key blocks Next, and the only offered fix, 'Add API key in Settings', ends setup without warning. Keyboard users lose their test result and sample text one Tab+Space after testing. Edits under Advanced keep claiming 'PocketTTS' and are discarded on a service switch, and a fixed error stays on screen.

This task implements the Voice slice of structural fix SF3, a session draft that replaces commit-on-Next (Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md, §5.1, stage 2 'untouched means unwritten' and the voice part of stage 3). It extends the delta-aware writes that Tools, Appearance and Speech already use; it does not replace them. Resolves: voice-speech-01, voice-speech-03, voice-speech-04, voice-speech-05, voice-speech-06, new-voice-speech-02, new-voice-speech-03.

Coordination:
- **Where the code is.** The Voice step now lives in UI/Wizards/first_run_voice_step.py, moved verbatim by TASK-33921; the review's current-dev pointers were re-checked there on 3c439d606e.
- **Done tasks this contradicts.** voice-speech-01 contradicts Done TASK-32959 AC#2 and the Done TASK-32958 design. The test that pins today's save-with-default-opted-out behaviour is replaced on purpose.
- **Save path.** A save with 'Use as default' unticked must not let the speech settings handler write the current settings back as defaults. Without that, the Summary keeps its false '(default voice)'.
- **Re-run prefill.** It must read the raw text-to-speech table from the TOML. The loaded settings view lacks some tables, and the Speech step fell into exactly that trap (new-voice-speech-01, filed elsewhere in this programme). Summary and tracker marks are cross-cutting-02's.
- **Keep (§5.5).** The step leads with the outcome, keeps the plumbing behind Advanced, and verifies a real sample with the existing OpenAI key.
- **Live verification.** On the dev machine, 127.0.0.1:8765 (PocketTTS's port) is held by another session's proxy, which answers 404. Use a free port for a real PocketTTS server and a genuinely closed port for the not-running case.

**AC note: PocketTTS decision (root of voice-speech-03).** The official pocket-tts server (PyPI `pocket-tts` 3.3.0, Kyutai) serves `POST /tts` (form fields `text` and `voice_url`), streams WAV, listens on port 8000, and answers 404 on `/v1/audio/speech`, so the old preset (`127.0.0.1:8765/v1/audio/speech`) could never speak. A new TTS provider does not fit cleanly: the legacy `BackendRegistry` is sealed, and the eight provider ids are pinned across Settings, the playground and the preference contracts. So pocket-tts became a dialect of the existing OpenAI-compatible slot, selected by an endpoint whose path is exactly `/tts` (`TTS/pocket_tts_native.py`):
- It sends the form body and is WAV only.
- It repairs the RIFF/data sizes the server streams as placeholders, which the playable-audio check otherwise rejects.

Both `OpenAITTSBackend` (Console, Speech Lab, Settings test) and the wizard sample use it. The preset is now `http://127.0.0.1:8000/tts` · `pocket-tts` · `alba` · `wav`. Settings ▸ Speech & TTS configures the same slot: its OpenAI Base URL takes the `/tts` address, so setup and Settings agree. `openai-compatible-tts.md` was corrected; it no longer claims pocket-tts speaks the OpenAI route.
