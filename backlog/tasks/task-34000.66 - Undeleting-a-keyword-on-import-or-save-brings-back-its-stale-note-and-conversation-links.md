## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: found in TASK-34000.19's review. Soft-deleting a keyword leaves its `note_keywords` / `conversation_keywords` rows in place. `add_keyword` undeletes the row when the same text comes back, whether from a Chatbook import, the note editor's save path (`notes_scope_service._sync_local_note_keywords`), or an org-sync tombstone. Every old link then silently reappears. A reviewer probe showed a local note whose "archive" keyword had been deleted getting "archive" back after an unrelated bundle imported "archive". Bulk import widens the blast radius of this existing DB behaviour.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Reviving a soft-deleted keyword never re-attaches it to items it was linked to before the delete; only the link being written now exists
- [ ] #2 Deleting a keyword and re-creating it through the editor, an import and org-sync each leave earlier items unlinked, pinned against real SQLite
- [ ] #3 Existing databases with stale links from before the fix are handled (cleaned at delete or ignored at revive), with the choice recorded
