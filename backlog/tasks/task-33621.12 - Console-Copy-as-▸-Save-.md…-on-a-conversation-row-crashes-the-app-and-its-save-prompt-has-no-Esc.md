## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** In the rail Chats group, conversation row 💬 ▸ Copy as ▸ Save .md… ends the app every time (2 of 2 live runs on 64579cce2c). The handler at `chat_screen.py:7149` calls `self.push_screen(ConsoleSaveMarkdownModal(...))` on ChatScreen, which is a Screen. A Screen has no `push_screen` in Textual 8.2.8, so the worker raises `AttributeError: 'ChatScreen' object has no attribute 'push_screen'`. The log records `event=unhandled_exception` and then "App Unmounting". No file is written. What the user sees varies: in one run a full-screen traceback stayed up and ignored input for more than 2 minutes, and in the other the process exited within about 1 s. On relaunch the open tabs and the unsent draft are gone, but saved history survives.

The target `ConsoleSaveMarkdownModal` is also the only one of 51 Console ModalScreens with no Escape binding and no `SAFE_MODAL_CONTENT`. No user can hit that today, because the crash happens before the modal opens. The existing test monkeypatches the push, so it never ran the real call.

**Severity / prior art.** P0, KNOWN_PARTIAL. TASK-25886 (Done) shipped Save .md. TASK-32864 (To Do, low) names this modal's missing Escape binding as part of broader mixin adoption, but does not cover the crash. See also ADR-031, ADR-161 and commit d71410805c.

Out of scope: a clean Ctrl+Q also drops drafts and tabs with no warning. That is finding G4-11.

**Suggested direction.** Push the modal through the app, or through the screen's existing push delegate. Give the modal the SafeModalDismissMixin contract: an Escape binding, `SAFE_MODAL_CONTENT`, and Cancel/Save through the dismiss-once path. Replace the monkeypatched test with a live one, and add a parametrised sweep of every conversation and workspace row-menu action against a live ChatScreen.
