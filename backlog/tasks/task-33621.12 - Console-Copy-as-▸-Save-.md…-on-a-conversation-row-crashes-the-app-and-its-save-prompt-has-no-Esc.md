## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** In the rail Chats group, conversation row 💬 ▸ Copy as ▸ Save .md… ends the app every time (2 of 2 live runs on 64579cce2c). The handler at `chat_screen.py:7149` calls `self.push_screen(ConsoleSaveMarkdownModal(...))` on ChatScreen, which is a Screen. A Screen has no `push_screen` in Textual 8.2.8, so the worker raises `AttributeError: 'ChatScreen' object has no attribute 'push_screen'`. The log records `event=unhandled_exception` and then "App Unmounting". No file is written. What the user sees varies: in one run a full-screen traceback stayed up and ignored input for more than 2 minutes, and in the other the process exited within about 1 s. On relaunch the open tabs and the unsent draft are gone, but saved history survives.

The target `ConsoleSaveMarkdownModal` is also the only one of 51 Console ModalScreens with no Escape binding and no `SAFE_MODAL_CONTENT`. No user can hit that today, because the crash happens before the modal opens. The existing test monkeypatches the push, so it never ran the real call.

**Severity / prior art.** P0, KNOWN_PARTIAL. TASK-25886 (Done) shipped Save .md. TASK-32864 (To Do, low) names this modal's missing Escape binding as part of broader mixin adoption, but does not cover the crash. See also ADR-031, ADR-161 and commit d71410805c.

Out of scope: a clean Ctrl+Q also drops drafts and tabs with no warning. That is finding G4-11.

**Suggested direction.** Push the modal through the app, or through the screen's existing push delegate. Give the modal the SafeModalDismissMixin contract: an Escape binding, `SAFE_MODAL_CONTENT`, and Cancel/Save through the dismiss-once path. Replace the monkeypatched test with a live one, and add a parametrised sweep of every conversation and workspace row-menu action against a live ChatScreen.

## Implementation Notes

**Summary.** Copy as ▸ Save .md… on a conversation row no longer ends the app. It opens the save prompt, writes the Clean markdown to the chosen path, and keeps running. The prompt closes on Esc, Cancel or a backdrop click without writing, and focus returns to the row's 💬 control. A save that cannot complete shows a toast that names the file and the problem.

**Root cause.** `ChatScreen._save_console_conversation_markdown` called `self.push_screen`, but a `Screen` has no `push_screen` in Textual 8.2.8. The worker's `AttributeError` was fatal. The only test monkeypatched the handler, so the broken call had never run.

**Approach**
- The save flow moved to a new, lazily imported `UI/Console_Modules/markdown_export.py`.
  - It pushes the prompt through `screen.app.push_screen`.
  - Rendering and the blocking validate, mkdir and write steps run off the event loop (`asyncio.to_thread`).
  - Every failure becomes a `MarkdownSaveError` or exception toast with `markup=False`. The success toast names the folder.
  - `validate_path_simple(..., reject_shell_metacharacters=False)`, because this path only reaches `open()` and `stat()`.
  - Nothing is logged.
- `ConsoleSaveMarkdownModal` adopts the `SafeModalDismissMixin` contract: an Escape binding, `SAFE_MODAL_CONTENT`, and Cancel/Save through the dismiss-once path. A blank path shows a warning.
- `ConversationActionChosen` now carries `opener_id`, and the save handler restores focus to the row before the prompt opens.
- Closing the prompt re-syncs the Conversations tray, and its recompose used to strand focus on a neighbour, live sometimes the header's Settings control.
  - `RecomposeCaptureGuard` gains an opt-in `RECOMPOSE_KEEPS_FOCUS`, which the tray enables, plus a `recompose_in_flight` flag.
  - The restore only happens while focus is still exactly on the reset target predicted to match `Screen._reset_focus`, so a deliberate move made during the rebuild (for example, selecting a chat focuses the composer) wins. This fixes the review blocker introduced by `c5469ecd66`.
  - `ConsoleLeftRail._recover_pending_focus` waits for an in-flight rebuild of the section, polling every 20 ms at most 100 times, and stands down if focus moved.
- Tests added:
  - A Pilot row-menu Save .md suite: write, persisted chat, Esc/Cancel/backdrop, two unwritable paths, blank path.
  - A parametrised sweep of every conversation and workspace row-menu action id, derived from the menu models, against a live ChatScreen.
  - Guard tests and tray focus tests, including rail chat selection by click and by Enter.
  - Unit tests for the write step.
- The new re-arming timer is pinned in `EXPECTED_CLOCK_ROOTS`; `census()` shows no `.update(` reachable from it.
- The User Guide page `console/sessions-tabs-workspaces.md` now documents Copy as ▸ and Save .md….

**Trade-offs and residuals**
- A deliberate focus move to exactly the predicted reset target is overridden.
- If two tray rebuilds overlap, the second falls back to the old behaviour.
- Rename, Delete, Icon-and-colour and the workspace-menu prompts don't restore focus to the opener yet (outside AC#2).
