## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Establish truthful device-local storage primitives for per-conversation Library
policy and accepted-turn dispatch recovery, including upgrade preservation,
backward-compatible message sync, and temporary-session lifecycle, without
changing agent composition or Console UI.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A device-local policy table stores both axes with schema version, revision,
      update time, soft-delete retention, hard-purge cascade ownership, and no
      sync/Chatbook-export/metadata projection.
- [x] #2 The same v45 migration creates a dedicated device-local
      `console_dispatch_checkpoints` table/index with message/conversation foreign
      keys, strict bounded typed payloads, explicit accepted/dispatch-started
      state, checkpoint and frozen USER/assistant message revisions, cascade
      ownership, and no sync/import, Chatbook/trajectory-export, FTS, or generic
      trajectory projection.
- [x] #3 The v45 migration also adds nullable closed
      `messages.assistant_generation_state`; historical NULL assistants remain
      complete except when a valid active ADR-063 continuation is authoritative,
      and non-assistant rows remain NULL. The historical v4 bootstrap schema is
      unchanged; the one-time v45 migration traversed by both fresh and upgraded
      databases transactionally replaces all four final Sync-v1
      create/update/delete/undelete triggers so they serialize the field and
      watch updates. An already-migrated database needs no later trigger repair.
- [x] #4 In the same foundation slice, Sync-v2 message records, source readers,
      envelopes, and exact source-proof normalization accept the new explicit
      field before changed Sync-v1 intents can reach the outbox. Older payloads
      missing only `assistant_generation_state` normalize it to NULL; unknown,
      malformed, or mismatched fields still fail closed.
- [x] #5 The v44→v45 migration requires one sanitized legacy automatic-retrieval
      seed, inserts final rows for then-existing active and soft-deleted
      conversations, creates both tables/index, and advances the schema in one
      transaction whose runner acquires `BEGIN IMMEDIATE` before its initial
      version read; one
      config-layer helper supplies every production opener, while missing seed
      or failure leaves schema/version unchanged.
- [x] #6 Concurrent migrators cannot reseed a completed upgrade, and a later
      synced/imported conversation is never swept into legacy policy; fresh,
      current, v44, and older-schema opener tests prove the runner never relies
      on a nested upgrade from a deferred read transaction.
- [x] #7 The config schema/template supplies shipped Never/Blocked future-session
      defaults; new local sessions capture them once, while a newly
      synced/imported missing-row conversation resolves Never/Blocked without a
      write.
- [x] #8 Reads distinguish valid, absent, corrupt, and failed states; every
      non-valid state is explicit and fail-closed.
- [x] #9 Conditional insert and revisioned CAS prevent concurrent overwrite and
      never publish an uncommitted candidate.
- [x] #10 An app/store-owned coordinator performs durable reads off the event loop,
      publishes committed revisions to every live holder for the conversation,
      and exposes an explicit fresh-read operation for the runtime task without
      treating a cached holder as durable authority.
- [x] #11 First local conversation persistence includes captured policy atomically,
      and ephemeral promotion persists/restores policy and lineage atomically;
      a generic transactional sidecar-contribution seam supports later owners
      without naming or implementing future event kinds.
- [x] #12 Checkpoint repository primitives can insert USER + empty assistant +
      accepted checkpoint through a caller transaction, strict-read ownership,
      CAS state/attempt by expected checkpoint and both message revisions with
      both rows `deleted = 0`, atomically settle assistant terminal state plus
      checkpoint deletion, and atomically hand off to ADR-063 continuation
      ownership; no generic upsert bypasses CAS.
- [x] #13 Targeted historical migration, repository, concurrency, lifecycle,
      pristine-session navigation/close, policy-only promotion,
      checkpoint ownership/CAS/atomic settlement, soft-delete/restore/purge, and
      fresh/migrated Sync-v1 trigger payload/watch tests pass. Sync-v2 tests
      cover create/update/delete/undelete exact proof and outbox projection for
      explicit NULL/closed state plus older missing-field compatibility; rollback
      tests pass and mutation-check the missing/error fail-closed guards.
<!-- AC:END -->
