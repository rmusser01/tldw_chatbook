## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Across the product, streaming is edited through four control types (report: Consistency 1/4). In Settings the two controls disagree: the model default is an Inherit/On/Off Select (settings_screen.py:17397-17408), while the global fallback is a Checkbox (:18586-18592). Console Behavior also prints the raw config line 'chat_defaults.streaming is canonical; enable_streaming is read as fallback only.' (:18704-18708).

ADR-095 (095:78-79) settles Settings on a Select for streaming. ADR-006 and ADR-052 keep Console Behavior as the owner of the global fallbacks (from :18562) and of the memory and compaction defaults; this subtask does not touch the latter.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Console Behavior's global fallbacks now use Model defaults' rows: label, one-row control, Source word, one help line. Streaming is an On/Off Select from the model default's Inherit/On/Off family.

Commits: `fdbccb2e11` (feat), `92f7e617eb` (review round 1), `4325260ba2` (review round 2), `f409f743d3` (review round 3), `ca04108db7` (review round 4) and the review round 5 fix that follows it.

What changed:
- Rows (`settings_field_rows.py`, imported lazily; `compose_console_fallbacks`, `refresh_console_fallbacks`):
  - Temperature, Max tokens and Streaming come first. The reasoning note sits between Streaming and Reasoning effort, above the rows it describes. Then Reasoning effort, Reasoning summary, Verbosity, Thinking and Thinking budget.
  - Top P, Min P, Top K, Seed, Presence penalty and Frequency penalty sit in one closed one-row Sampling disclosure (`#settings-console-sampling`). Its title names every sampler `[chat_defaults]` holds or the draft edited (never a built-in Top P shown at rest) while the names fit the row ("Sampling · Top P 0.95 · Min P 0.05 · Top K 50"), counts them when they do not ("3 set"), and reads "none set" when none does.
- Values and Source words both come from what `[chat_defaults]` holds, read with the default chain's own coercion (`chat_defaults_value` and `chat_defaults_held_fields` in `console_session_settings.py`; the legacy `enable_streaming` key counts). That covers every fallback, the four reasoning and thinking choices included (review round 3: they were lowercased and filtered by Settings' own loader). A hand-edited value only one reading accepts can no longer split them: `streaming = 0` reads "On | built-in" (a new chat streams), `temperature = 3.0` reads "3.0 | Console Behavior" (a new chat gets 3.0), `seed = -1` reads "-1 | Console Behavior", a fractional Top K is blank. A choice Select shows only an exact option, so a saved `reasoning_effort = "High"` or `"bogus"` leaves it blank; that row still reads "Console Behavior" with "saved 'High' is not a choice" (`NOT_A_CHOICE_HELP`), because a new chat takes the saved text. Picking an option is an edit; a blank Select over such a value stages nothing (mount, Revert) until something is staged for the row, so a blank chosen after an option stages "default" and Save writes it (review round 5). The fallback rows' integer Inputs accept a leading minus so a shown `-1` can be backspaced away; Save still refuses it with the field's message. Showing a value Save would refuse stages nothing:
  - held: "Console Behavior" and the field's help;
  - not held (Streaming, Temperature and Top P show tldw's own value when the key is absent): "built-in" and "not set here · a provider's own setting comes first";
  - unsaved: "edited *";
  - a blank optional field: "provider" and "blank = provider default"; a blank enum shows "default", Chat settings' word for the same state (`BLANK_CHOICE_PROMPT`), which fits the 16-cell control;
  - a cleared Temperature or Top P: "Required: 0.0 to 2.0." (Top P "Required: 0.0 to 1.0."), Chat settings' copy (`REQUIRED_FIELDS`) with the field table's range, the one the Focused field guide prints; Save refuses a blank with that range.
- Streaming (`#settings-console-default-streaming`) stages, saves and reverts the same bool the Checkbox did. `chat_defaults.streaming` is written; `enable_streaming` is still read when `streaming` is absent.
- Inspector: the focused field's "Saved as" row and the streaming key fact sit in the closed "config key" disclosure (`#settings-console-behavior-config-key`, T4's helper). The Focused field guide prints no config key. While a fallback row reads "built-in", its guide's Validation row adds how to pin the shown value (`CONSOLE_PIN_BUILT_IN_HINT`); an edit drops it. Every Console Behavior guide now has the three shown rows the Inspector composes: Rail layout scope's Retention row is folded into Consequences, so its "Applies" row is painted (it was a fourth row with no widget).

Decisions:
- A built-in row treats any change as an edit (review round 1). With no `streaming` key the Select shows the built-in On, so choosing On used to stage nothing and On could not be pinned over a provider's Off. `_stage_console_default_value` now compares a field that `[chat_defaults]` does not hold against "nothing saved": Off and then On stays "edited *" and Save writes `streaming = true`. A control repeating the value it already shows (mount, a Revert sync) stages nothing. The same rule covers Temperature and Top P.
- Temperature and Top P stay required here. Accepting a blank and deleting the key would change what Save writes, so the row says the field is required instead.
- Ruling (review round 2, finding 5, owner call): Settings still cannot return a saved fallback to "not set". The cheapest closing that changes no saved-data semantics was taken: the guide says how to pin a built-in value, and settings.md says that removing the key from `[chat_defaults]` lets a provider's own setting come first again. A blank "not set" Select option would need Save to delete the key; that is left to the owner.
- Review round 4: Model defaults now reads choices the same way. `_select_option_value` and `_model_profile_enum_options` no longer lowercase, so a saved `"High"` or `"extreme"` leaves its Select blank, and the row reads "model default" with "saved 'High' is not a choice" (`_unshown_model_profile_choice`, used by `refresh_model_defaults`). A blank Select over such a value stages nothing (mount, Revert). Save reads Model defaults from its widgets, so without a guard the blank Select would have deleted the value on any other edit's save; `_updated_model_defaults_for_values` keeps it, as Console Behavior keeps its own. Before this round, such a save rewrote "High" as "high" and deleted "extreme". Both integer restricts are now one `_INTEGER_RESTRICT` (`^-?[0-9]*$`). An Input whose text repeats a saved value its normaliser refuses (`seed = -1`, `temperature = 3.0`) stages nothing; the mount's own `Changed` used to mark it "edited *" at rest. Temperature and Top P now stage through `_stage_model_profile_input` like the other fields.
- Review round 5: Model defaults reads its values through the default chain like its twin (`model_default_value` in `console_session_settings.py`, the `chat_defaults_value` twin, used by `_model_profile_values` for the three loaders and by `_unshown_model_profile_choice`). A hand-edited `streaming = "0"` shows Off and reads "model default" (it read Inherit and an unrelated save dropped it); `top_k = 2.5`, `min_p = "abc"` and a non-string choice such as `reasoning_summary = 1`, which a new chat ignores, show blank with what they inherit (they read "model default" or "saved '1' is not a choice"). Save now applies the staging rule: `_model_profile_input_for_save` keeps a saved value an untouched Input repeats although its normaliser refuses it (`seed = -1` blocked every save in the category with a toast naming a row inside the closed Sampling disclosure), and `_updated_model_defaults_for_values(..., dirty_keys=)` keeps every untouched row's saved value exactly, so the new reading changes no saved data. A blank chosen after an option is Inherit: it stages "", reads "edited *" with what it inherits, and Save deletes the override. Console Behavior's `_stage_console_default_value` follows the same rule for "default". This also closes part of the round-2 Ruling: a saved choice can now be returned to "default" from Settings.
- Model defaults keeps its two-name cap for the Sampling title, because that title also names hidden fields.
- On the shipped config Streaming reads "On · built-in" here while a new OpenAI chat streams Off; Model defaults says the same as "inherits Off · provider". The two rows name the same layers.
