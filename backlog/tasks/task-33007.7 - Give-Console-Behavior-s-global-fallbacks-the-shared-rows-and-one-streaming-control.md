## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Across the product, streaming is edited through four control types (report: Consistency 1/4). In Settings the two controls disagree: the model default is an Inherit/On/Off Select (settings_screen.py:17397-17408), while the global fallback is a Checkbox (:18586-18592). Console Behavior also prints the raw config line 'chat_defaults.streaming is canonical; enable_streaming is read as fallback only.' (:18704-18708).

ADR-095 (095:78-79) settles Settings on a Select for streaming. ADR-006 and ADR-052 keep Console Behavior as the owner of the global fallbacks (from :18562) and of the memory and compaction defaults; this subtask does not touch the latter.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Console Behavior's global fallbacks now use Model defaults' rows: label, one-row control, Source word, one help line. Streaming is an On/Off Select from the model default's Inherit/On/Off family.

Commits: `fdbccb2e11` (feat) and the review round 1 fix that follows it.

What changed:
- Rows (`settings_field_rows.py`, imported lazily; `compose_console_fallbacks`, `refresh_console_fallbacks`):
  - Temperature, Max tokens and Streaming come first. The reasoning note sits between Streaming and Reasoning effort, above the rows it describes. Then Reasoning effort, Reasoning summary, Verbosity, Thinking and Thinking budget.
  - Top P, Min P, Top K, Seed, Presence penalty and Frequency penalty sit in one closed one-row Sampling disclosure (`#settings-console-sampling`). Its title names every sampler that holds a value while the names fit the row ("Sampling · Top P 0.95 · Min P 0.05 · Top K 50"), counts them when they do not ("3 set"), and reads "none set" when none does.
- Source words come from what `[chat_defaults]` holds, read with the resolver's own coercion (`chat_defaults_held_fields` in `console_session_settings.py`; the legacy `enable_streaming` key counts):
  - held: "Console Behavior" and the field's help;
  - not held (Streaming, Temperature and Top P show tldw's own value when the key is absent): "built-in" and "not set here · a provider's own setting comes first";
  - unsaved: "edited *";
  - a blank optional field: "provider" and "blank = provider default"; a blank enum shows the prompt "Not set", which fits the 16-cell control;
  - a cleared Temperature or Top P: "needs a value · 0.0 - 2.0" (Top P "0.0 - 1.0"), because Save refuses a blank with that range.
- Streaming (`#settings-console-default-streaming`) stages, saves and reverts the same bool the Checkbox did. `chat_defaults.streaming` is written; `enable_streaming` is still read when `streaming` is absent.
- Inspector: the focused field's "Saved as" row and the streaming key fact sit in the closed "config key" disclosure (`#settings-console-behavior-config-key`, T4's helper). The Focused field guide prints no config key.

Decisions:
- A built-in row treats any change as an edit (review round 1). With no `streaming` key the Select shows the built-in On, so choosing On used to stage nothing and On could not be pinned over a provider's Off. `_stage_console_default_value` now compares a field that `[chat_defaults]` does not hold against "nothing saved": Off and then On stays "edited *" and Save writes `streaming = true`. A control repeating the value it already shows (mount, a Revert sync) stages nothing. The same rule covers Temperature and Top P.
- Temperature and Top P stay required here. Accepting a blank and deleting the key would change what Save writes, so the row says the field needs a value instead.
- Model defaults keeps its two-name cap for the Sampling title, because that title also names hidden fields.
- On the shipped config Streaming reads "On · built-in" here while a new OpenAI chat streams Off; Model defaults says the same as "inherits Off · provider". The two rows name the same layers.
