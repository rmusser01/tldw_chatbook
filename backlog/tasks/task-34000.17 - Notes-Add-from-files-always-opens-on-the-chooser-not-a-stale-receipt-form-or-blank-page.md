## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: "Add from files…" is the only way into both Import once and Keep a folder synced. A Notes power user (j3) activated a sync folder, and a stress tester (j6) hit a failed Recovery. After that, the button kept reopening on a leftover lasting-sync page for the rest of the session. Import once and every new sync setup were out of reach, so a user with a second folder could not add it. A keyboard-only user on the blank-page variant had no back control and no Esc hint. The verifier found the problem wider than reported: opening Keep synced and pressing ‹ Notes is enough to trigger it.

Observed:
- After activation (j3, captures 59-60): Add from files… reopens "Sync root activated. 64 applied · listed under Receipts" with only "○ Resolution history" and "‹ Notes". Esc and re-entry show the same receipt.
- After a check that ends in "Nothing to review." (verify 13-reopen-after-roots-phase, 160x45): the page shows only "Add files to Library notes." and "Nothing to review.". There is no Import once, no Keep synced and no ‹ Notes. The footer offers only "F1 help · Ctrl+P palette · Ctrl+Q quit".
- After a failed Recovery (j6, captures 92 and 94): the same blank page reads "Recovery failed — RuntimeError. Next: Check changes.".
- After Keep synced, then ‹ Notes (verify 03-reopen-after-configure-back): reopening shows the "Configure a local lasting sync root." form with "○ Check changes" and "‹ Notes", not the chooser.
- In every variant, only a restart clears the stale page.

Verified cause (origin/dev 2d34cbf80d):
- The Add from files handler (UI/Library_Modules/library_notes_controller.py:5065-5089) switches the view to 'lasting_add' but never resets the sync controller's phase. The canvas then renders whatever phase was left behind.
- UI/Library_Modules/library_notes_sync_controller.py leaves phase='roots' after a check with nothing to review (:1506-1509), after other non-review outcomes (:1510-1514) and after a failed Recovery (:1527-1529).
- `abandon_setup` (:1166-1178) never returns the phase to 'choose'.
- Widgets/Library/library_notes_add_from_files_canvas.py has no 'roots' branch in the body (:356-595) or the action bar (:1026-1156). Phase 'roots' therefore renders a heading, a status line and nothing else.

Suggested direction (the review's refined fix; a direction, not a mandate):
- Add a "begin Add from files" step that resets the lasting phase to 'choose', unless a check or activation is actually running.
- Make abandoning setup end in 'choose'.
- Have the canvas render the chooser for any phase it does not handle.
- Give the receipt page a 'Manage sync folders' action.

Review finding(s): N-17. Source: qa/notes-library-ux-review-2026-10-02/report.md
