## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Setup exists only as a full-screen Textual app, and Textual exposes no accessibility tree, so screen-reader users cannot set chatbook up at all. Over SSH, a full-screen app is often the wrong tool too. tldw-cli parses only recovery selectors [coverage-10].

The approved spec adds tldw-cli setup --plain (decision D10): a line-oriented setup on the same Textual-free setup core and commit builders as the TUI (TASK-34100.20), with one prompt per decision, plain OK:/FAILED: result lines, keys from a hidden prompt or an environment variable and never from argv, and meaningful exit codes. v1 covers Welcome, Connect, Model, where to keep the key, the verdict and a plain review of those areas; it has no test message and no server step, because both need the running app (owner ruling Q7). It follows the four-step Quick track (TASK-34100.24). Where TASK-34100.31 has landed, the key prompt offers the system keychain as an option after config.toml.

Spec: Docs/superpowers/specs/2026-10-03-first-run-setup-shape-design.md (revision 3, approved by the owner on 2026-10-03; ADR-217): D10, §2.5, §3.10, §3.11, §8.1 (plain mode, import purity), §8.4, §10 F13.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 tldw-cli parses its arguments with one parser: setup is recognised after the profile selectors and --config, so 'tldw-cli --config X setup --plain' works, and recovery behaves as before. Setup runs after the startup preflight, so an encrypted config unlocks through the one shared prompt. 'tldw-cli setup' without --plain opens the app straight into setup
- [ ] #2 Plain mode never imports textual, checked in a fresh subprocess
- [ ] #3 There is one prompt per decision: numbered choices with the default in brackets, letters filter long lists, '?' explains the prompt, and only the word 'quit' or end of input quits (exit 1). Every line is a complete sentence with no cursor movement, spinner or colour-only meaning. Results start with 'OK:' or 'FAILED:' (✓/✗ with --glyphs), progress reads 'Step 2 of 4: Connect', and every wait is bounded with 'Still waiting… 30 s' lines
- [ ] #4 Keys come only from a hidden prompt or an environment variable named by --key-env VAR or --key-env PROVIDER=VAR. A terminal that cannot hide input exits 2 with a message naming --key-env. Any argument that looks like a key flag (--key, --api-key, --token) exits 2 with the reason. After a hidden entry it prints 'Received a key ending abcd (N characters)'. A key is never echoed, logged or drafted
- [ ] #5 v1 covers Welcome (all three choices; choosing Full lists what v1 cannot run and where to change it), Connect (detection, a filterable list, the key and, where available, where to keep it, with the environment default first and config.toml before the keychain), Model (the curated list and 'type part of a model ID'), Ready (the verdict through an app-free entry, the Provider, tldw server and Keys lines, and the Data and Config paths) and, on a profile with a usable provider, a plain review where Provider, Model and Keys can be changed and the other areas print their value and 'Not changeable in plain mode yet'
- [ ] #6 Exit codes are 0 when setup is saved with a ✓ verdict or documents-first was chosen, 1 when quit before provider and model were saved or a save failed, 2 for usage errors (bad flags, a key on argv, no terminal, or a terminal that cannot hide input), and 3 when saved but the verdict is ✗
- [ ] #7 When chatbook may already be running with this profile, plain setup warns and asks before writing, and never refuses
- [ ] #8 tldw-cli --help lists setup and --plain; before the TUI's first-run offer takes the screen, one line says 'Using a screen reader? Quit and run: tldw-cli setup --plain'; the README and the User Guide carry the same line
- [ ] #9 Model-list consent is asked once, defaulting to No, and recorded; Welcome prints the recovery command for restoring a backup
- [ ] #10 Verified live on a fresh isolated profile (TLDW_CONFIG_PATH and HOME set) through the real app, with real providers and the real llama.cpp server, never mock servers: plain Quick with a real Anthropic key and with the real llama.cpp server; VoiceOver on macOS Terminal and NVDA on Windows Terminal or Orca on GNOME Terminal reading every prompt in order with the key prompt silent; one session with a person who uses a screen reader daily, completing plain Quick unaided, with their notes recorded; an SSH session; and each exit code. Evidence is recorded in Implementation Notes
- [ ] #11 New behaviour is covered by tests that fail on the pre-change code (RED verified), and no module-size or ADR-097 ratchet is raised
- [ ] #12 The matching Docs/User_Guide page content is updated where behaviour changed (no 'Verified against' stamps)
