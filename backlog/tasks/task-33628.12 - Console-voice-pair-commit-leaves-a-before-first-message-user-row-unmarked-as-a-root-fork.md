## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
From the PR #2965 (TASK-33628.6) final gate. The root_fork marker is written by the Console store's create_sibling and append paths and by the durable send commit. The completed voice-pair commit's USER row, appended at a before-first cursor (console_chat_store ~L16141), is not marked, because its reconcile in chat_persistence_service requires the user row's metadata_json to be NULL. On reload such a row chains after the legacy flat rows: dev's reading for unmarked roots.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Approach.** The voice exchange's prompt follows the typed prompt's rule. `ResolvedVoicePromotionDestination` gains `user_root_fork` (bool, default False; refused with a ValueError when the destination has a parent). `ConsoleChatStore._resolve_voice_promotion_destination` sets it through `console_legacy_flat_roots.voice_user_root_fork`, which applies `appended_metadata`'s rule to the claimed native leaf: a USER row appended with no parent while the session already holds a root, outside a fork projection. Because the flag is part of the destination, the lease's liveness check (`_resolve_voice_promotion_destination(context) == lease.destination`) covers it too. `ChatPersistenceService.commit_completed_voice_pair` writes `MessageMetadata(root_fork=True).to_json()` on the user row when the destination says so, and NULL otherwise. The retry reconcile compares the user row's `metadata_json` to exactly that expected value; every other check is unchanged. `_publish_voice_pair` marks the in-memory user row the same way, so later whole-record writes keep the marker (`keep_root_fork`) and a temporary chat's save writes it.

**Evidence.** Real store, real `VoicePromotionOwner` (with an inline sync runner so the in-memory DB stays on one thread), real `ChatPersistenceService`, in-memory `CharactersRAGDB`:
- `test_a_voice_exchange_sent_before_the_first_message_is_a_marked_root_fork`: a legacy flat conversation, the cursor placed before the first message, then claim, commit and publish. The prompt is saved parentless with `root_fork`, and the live row carries it. On reload there are two roots, and the voice pair is the sibling after `f0`. A Delete of `f1` counts and tombstones 3 (f1-f3), and the pair stays live through reopen.
- `test_a_temporary_voice_exchange_before_the_first_message_saves_marked`: the same rule in a temporary chat. The pair is marked in memory and kept when the chat is saved; the first prompt stays unmarked.
- `test_a_voice_exchange_at_an_ordinary_leaf_stays_unmarked`: the control. A pair under a saved leaf has no metadata.
- `Tests/Chat/test_console_voice_pair_persistence.py`: a marked commit's retry reconciles (`already_committed`). A marked row under an unmarked destination, and the reverse, fail closed with nothing changed. The destination refuses `user_root_fork` with a parent, or a non-bool value.
