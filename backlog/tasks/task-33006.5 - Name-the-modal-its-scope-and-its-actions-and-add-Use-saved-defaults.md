## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
C1(b) for chats with work: a chat that holds work has no way to adopt newly saved defaults, and nothing in the modal says where defaults live. Untouched chats already converge since phase 1. The ADR-095 amendment of 2026-09-26 gives chats with work 'Use saved defaults'. It rebases the draft onto the saved default chain for the chat's current provider and model: the model profile, then chat_defaults, then the provider. It carries over no deliberate edits, never changes the provider or model, and applies nothing until Apply.

The scope line reads 'Use: this conversation only. Defaults: future provider conversations.' (CONSOLE_SETTINGS_MODEL_SCOPE_COPY, console_settings_modal.py:857-863). It is pinned by Tests/UI/test_console_session_settings.py:12450 test_console_settings_modal_scope_line_names_session_and_default_scopes, which also pins a 'Save as provider defaults' label the code no longer shows. The header 'Conversation settings' (:1648) is pinned at :4407 and :13777. The name also appears in 47 strings across the code, many of them user-visible notices: chat_screen.py:3747-3835 and :15168, and settings_screen.py:12231-12239 and :16976. Log and exception messages use it too.

The footer (:2569-2610) offers Cancel, 'Save as model default', 'Make default for new chats' and 'Apply to this chat'. Ctrl+Enter is bound (:1141) but no button teaches it (report.md), although TASK-30014 AC#5 requires the accelerator to be discoverable. Phase 3 already made the Esc hint describe what Esc does.

The judge made 'adopt defaults' a button because Ctrl+R is banned (ADR-031 rule 2). Other ADR-095 rules that apply:
- Apply never mutates configuration (ADR-095:20).
- 'Save as model default' uses the full field mask (:74-77).

Ctrl+N is unbound in Console and is not a Textual Input binding.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Chat settings now names itself, its scope and its actions, and a chat that holds work can adopt newly saved defaults through **Use saved defaults**, then Apply; Apply writes no configuration.

**Approach**
- `Widgets/Console/console_settings_saved_defaults.py` (new, no ratchet row): the footer labels and `ConsoleSettingsSavedDefaultsMixin`. Use saved defaults computes `build_target_default_console_session_settings(app_config, provider, model)` for the draft's own pair (what a new chat on that pair resolves: model profile, `[console.provider_defaults.<provider>]`, `chat_defaults`, provider settings; a blank chat passes no extra sources), blanks the fields the provider does not accept, keeps every non-generation value (system prompt, Persona, name) and hands it to the controller's existing rebaser as the snapshot of a chat opened on that pair (`_initial_full_draft`, no edits). The rebaser's same-pair branch keeps that snapshot and carries nothing over, so the button is not the no-op R4 warned about, and the controller is unchanged (R1). `_apply_rebased_state` projects it; the unsaved guard then marks each field that differs from the conversation "edited *". It is disabled, and its label reads **Matches saved defaults**, while every shown field (a cleared Temperature/Top P counting as blank) and the endpoint already equal the defaults; focus moves to Apply after use. Ctrl+N presses Default for new chats (no-op while the close guard shows or the button is unavailable).
- `console_settings_modal.py` (wiring only, 6,189 -> 6,156; ratchet row lowered): title `Chat settings · <chat title>` (`chat_title` kwarg; `chat_screen.py` passes the session title, +1 line, PR-net -4), new model-view scope copy, footer order Esc hint · Use saved defaults · Save as model default · Default for new chats (Ctrl+N) · Apply to this chat (Ctrl+Enter), Cancel only in the Context view (R10), `ctrl+n` binding (show=False: the label teaches it), Use saved defaults in the Tab order, `_rebase_to(..., source=None)`. The compose-time button geometry (overwritten by `_sync_action_copy` at mount) and the per-call label rewrites ("Use for this conversation", "Make default for new chats") are gone; the save action always reads "Save as model default" (it writes the model profile), except the existing "Save endpoint & use model" state.
- `console_settings_unsaved.py`: `chat_settings_title()`; `_sync_unsaved_hint` also writes the title's unsaved count and re-syncs Use saved defaults (both guarded against a deferred call landing during unmount).
- Rename: every user-visible "Conversation settings" (chat_screen return/blocker notices and send tooltip, settings_screen return-continuation copy, buttons and empty-state copy, the Inspector summary card title, recovery copy, compaction next steps, the modal's tooltip and reasons) and the two "Console Settings" strings (`chat_screen` send tooltip, `UNSAVED_ENDPOINT_COPY`) now say "Chat settings"; docstrings too. Log calls and raised-exception messages keep the old name (AC#9). `Tests/Architecture/test_chat_settings_name.py` scans every string literal in the package (f-string pieces included, any case) and exempts only `logger.*`/`logging.*` calls and `raise` expressions (R18), with a self-check of the exemptions.
- Docs: `console.md` (title, scope line, footer and keys, Use saved defaults, Cancel in the Context view, Tab end), `settings.md` (how a chat with work adopts new defaults), `context-and-rag.md` (rename). Lesson added mid-file in `lessons-live-verification.md`: Ctrl+Enter can be sent through tmux as its CSI u sequence.

**Rulings**
- Ruling: no flag on the controller's rebaser; the saved-defaults snapshot is built outside the controller and handed to the unchanged rebaser for the same pair (its keep-the-snapshot branch then keeps the defaults) — R4's intent (logic outside the controller, nothing carried over, not a no-op) within R1's controller budget and the ADR's "uses the controller's existing rebase path" — cost if wrong: add a kwarg to `rebase_console_settings_draft` (+3 controller lines).
- Ruling: AC#4 names `build_default_console_session_settings`; staging uses `build_target_default_console_session_settings` (= `default_console_session_settings`, which wraps it), because that is what a new blank chat resolves (it leaves llama.cpp's `base_url` blank) — AC#4/#5 parity — cost if wrong: a llama.cpp chat would pin its configured URL.
- Ruling: the disabled state's visible reason is the button's own label, "Matches saved defaults", not an extra row — the Model view must fit 22 rows (T1 AC#9) — cost if wrong: a reason row that can push the view into scrolling.
- Ruling: Save as model default keeps its existing visibility (shown while a saved default differs); AC#2's order holds whenever it shows — a no-op save stays hidden — cost if wrong: one `display` line.
- Ruling: parity (AC#5) compares the fields the provider accepts; a new chat keeps values for hidden fields that the rebaser and Apply blank, and neither is ever sent.
- Ruling: AC#8's durable snapshot is read after `persist_session_if_needed` on the main thread: the harness's `:memory:` DB is per connection, so the worker-thread flush of an already-persisted chat cannot reach it (it records a persistence failure). The live store snapshot is asserted before that.
