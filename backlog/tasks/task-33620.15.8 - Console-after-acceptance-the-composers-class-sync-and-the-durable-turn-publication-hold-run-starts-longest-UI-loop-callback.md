## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Run start's longest UI-loop callback is about half as long, with no worker hop and no new await between the durable commit and its post-commit effects (the one new await is the catalog fingerprint's, in provider entry). The post-commit step's largest piece was not the durable publication but the composer's restyle on acceptance; it now restyles only what its state classes style, and Send's readiness restyles one composer callback later. With that step shorter, provider entry's two store reads were the longest callback, so the catalog fingerprint now also yields before its first read.

Changes:
- `ConsoleComposerBar._sync_interaction_classes` changes `console-composer-focused` / `console-composer-has-draft` with `update_classes(update=False)` and restyles only the bar and `INTERACTION_STYLED_DESCENDANTS` (`#console-command-visible-text`), the only nodes the rules keyed on those classes style. Textual restyled the bar's whole 26-node subtree (~0.3 ms a node against the app's ~4,300 rules) on every change, which also made the first keystroke after a Send pay it.
- `sync_action_state` sets Send's six readiness classes in one `update_classes` (one restyle, not one per changed class). Textual's own `disabled` and `variant` watchers still restyle it three times.
- `load_draft(text, defer_action_state=True)`: the draft, caret, hidden input and state classes change in the call; the action row (Send's readiness, its reason strip) syncs in the composer's next callback (`call_later`) from the then-current draft and cached run state. Only `_project_console_received_input` (durable acceptance, and an applied queued prompt) passes it, so a Send's acceptance clears the composer in the post-commit step as before and Send turns inactive one callback later.
- `UnifiedMCPControlPlaneService.run_catalog_fingerprint` yields before its first store read as well as between its two (TASK-33620.15.5). Provider entry reads the response rules' bindings (`ResponseRuleRuntime.begin_generation`) just before it, and the two admission-checked reads shared one callback.
- Not moved: the durable commit, `publish_durable_turn_identity` (under the probe's 0.3 ms timer floor on every send at this load), owners, staged input, workspace projection, queue acknowledgement and the trace request stay where they were; no await was added between the commit and the provider call except the fingerprint's.
