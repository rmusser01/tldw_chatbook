## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented MiniMaxVideoAdapter (tldw_chatbook/Video_Generation/adapters/minimax_video_adapter.py) against the docs-verified MiniMax-H3 contract (platform.minimax.io, verified 2026-08-07 -- the cancel endpoint DELETE /v2/video_generation/{task_id} was pinned from the official api-reference during implementation; queued tasks cancel free, running tasks refuse remotely so cancel is best-effort with the local stop always honored). Approach: submit POST /v2/video_generation with a single type=text content item (T2V only; reference assets refuse with a pointer to task-3401.8), poll /v2/query/video_generation/{task_id} at the configured interval with case-insensitive status parsing (v1/v2 docs disagree on casing), immediate download from the expiring task.content.url through the shared image http_client (per-hop egress validation; the CDN URL is untrusted -- no trusted_origins, no Authorization), v1-style file_id -> /v1/files/retrieve fallback, base_resp error envelope surfaced (code + status_msg) without the API key anywhere, task_id charset-validated before URL interpolation (fal request_id rule), 768P/2K resolution tier mapping from width/height, MiniMax 4-15s duration bounds enforced at the adapter. Cooperative cancellation: optional cancel_event kwarg (wired by 3401.5) -- poll loop wakes on cancel_event.wait, stops, best-effort DELETE, raises cancelled. resolved_model is set (adapter resolves the model before sending; per the task-558 contract rule). Trade-offs: reuses Image_Generation/http_client + fetch_image_bytes (egress-hardened) rather than a new video HTTP shim, wrapping ImageGenerationError into VideoGenerationError at the boundary. Tests: 16 mocked-HTTP cases (happy path incl. payload shape and trust boundaries, pending-status polling, resolution tiers, file_id fallback, failure/base_resp/key-safety, missing key, reference-asset refusal, duration bounds, invalid task_id, no-URL error, cancel preset/mid-poll/remote-cancel-failure, timeout). Verification: 76 passed in Tests/Video_Generation + console video message suite; ruff clean; registry smoke-checks the lazy minimax spec now instantiates MiniMaxVideoAdapter. Pushed to PR #1431 (feat/task-3401-video-generation-foundation). Live API verification remains with spike task-3401.1. ADR-044 linked; no new ADR required.
