## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the independent review of TASK-33620.15.26 (2026-10-29), confirmed by reading the code, not reproduced. _sync_native_console_transcript skips a pass when its gate is unchanged, and the gate records only whether _console_send_ack exists, not whether it holds a pending or standing-in row. ConsoleSendAcknowledgement.release asks for a repaint through request_console_repaint, whose pass (_sync_native_console_chat_ui) calls the transcript sync without force. So when a send's custody ends and the store has not changed, the released row can stay on screen until the gate's forced pass every 15th tick. TASK-33620.15.26 made the 'Sending...' row stand in for the store echo until the echo's turn writes its next row, so the row now lives longer than the pending row this pattern was written for. Most custody ends write rows (a reply, a failure status), which changes the gate on their own.
