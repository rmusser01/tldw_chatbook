## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Linking notes is the core action of a notes tool. Today the only link the app recognises contains the target note's UUID, and no screen shows that UUID.

How this hurts users:
- A first-timer coming from Obsidian or Logseq types [[Title]] and sees it render as plain text. The target's Info then says "Linked from (0) — no notes link here yet", and the user gives up (j1's linking task failed).
- A power user typed "See [[Trip planning: Lisbon]]". Lisbon's Info still shows only "Linked from (1) · Index — start here" and does not count the new note.
- The User Guide (`Docs/User_Guide/library/notes.md:463`) says hand-typed links count "as long as they use the same note:// form". That form requires the UUID.
- Worse, activating a stored note link in Preview hands it to the operating system.

Observed:
- A note whose body is "See [[Trip planning: Lisbon]] for the itinerary." shows that text exactly as typed in Preview at 160x45, styled as plain text (`verify/nl-v-n-08/08-typed-link-preview-160x45.ansi`).
- Activating a stored note link in Preview handed "note://5a13a9cb-ae08-424e-adac-fcefb424b550" to the OS URL handler. The verifier had stubbed the handler, and the stub recorded the URL (`browser_calls.log`).
- There is no link control, no "[[" completion and no F1 entry. The palette has no link command: searching "link" offers only Chunking Lab, Artifacts and Skills.

Verified cause (origin/dev 2d34cbf80d):
- Preview builds `Markdown(render_preview_source(...), id="library-note-preview-body", ...)` with Textual's default `open_links` (`Widgets/Library/library_notes_canvas.py:2909-2913`). The canvas has no `LinkClicked` handler anywhere, so a click goes through to `app.open_url`.
- Backlink edges are recorded only for a `(note://<id>)` tail (`_NOTE_LINK_TARGET_RE`, `DB/ChaChaNotes_DB.py:205`), which feeds the note_links relation built in TASK-32186. A bare [[Title]] never creates an edge.

OWNER RULING 2026-10-03 (encoded as the acceptance criteria below):
1. A [[ picker inserts a real note link.
2. A typed [[Title]] that matches exactly one note records a backlink.
3. Preview handles link activation inside the app and never hands it to the OS.

This is consistent with the TASK-32263 ruling (Done). That ruling stores a resolved link as `[[target|title]](note://<id>)` and renders it as its display text in Preview. It rejected resolving links at render time, because backlinks are answered from what was recorded when the note was saved or imported. So a typed [[Title]] is resolved when the note is saved, not when it is rendered.

Suggested direction (a direction, not a mandate):
- Ship the Preview fix first. Build Preview's Markdown with open_links=False and handle LinkClicked: a note:// link opens the target note in the editor, and Enter follows a focused link. What the handler does with an http(s) link is the implementer's decision, but it must be a deliberate decision, not Textual's default.
- Then add the [[ title picker, which inserts the stored link form.
- Then record a note_links edge for a bare [[Title]] or [[Title|alias]] that resolves to exactly one live note.
- The review also suggested a "Copy link to this note" action in Info. It is not part of the ruling and is optional.

No existing task owns this. TASK-32145 and TASK-32186 (both Done) built "Linked from" and the note_links relation.

Review finding(s): N-08. Source: qa/notes-library-ux-review-2026-10-02/report.md

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Typing [[ in the note body opens a title picker, operable by keyboard alone, that narrows as the user types. Choosing a note inserts a link that, once saved, appears in the target's Info → Linked from. Escape closes the picker and leaves the typed text as it was
- [ ] #2 Saving a note whose body contains a typed [[Title]] (or [[Title|alias]]) whose title matches exactly one live note records a backlink: the target's Linked from lists the linking note. A [[Title]] that matches no note, or more than one, records no backlink and is left exactly as typed
- [ ] #3 Activating a link in Preview (by click, or Enter on a focused link) is handled inside the app: a note link opens that note in the editor, and no note:// URL is ever passed to the operating system's URL handler
- [ ] #4 The User Guide's linking text (the notes.md "Linked from" row and any how-to) describes the picker and the typed-[[Title]] rule, and no longer requires a UUID the UI never shows
- [ ] #5 Regression tests (Pilot or unit) that fail on current dev pin #2 (a typed [[Title]] matching exactly one note creates a backlink, while zero or two matches create none) and #3 (activating a note link in Preview never reaches app.open_url)
- [ ] #6 Verified live at 160x45 and 80x24 in an isolated profile with a stubbed OS URL handler, with captures of the picker, the backlink count and the in-app open
