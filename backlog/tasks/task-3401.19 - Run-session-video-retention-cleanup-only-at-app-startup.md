## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Prevent Console screen construction or remount from reapplying session-retention cleanup to videos generated during the current app run. Live UAT observed a current-run Base video become expired after navigating away from and back to Console.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Session retention cleanup is applied once at app startup and not by each Console screen instance.
- [ ] #2 Navigating from Console to Settings and back keeps current-run generated cards ready.
- [ ] #3 Recreating or remounting ChatScreen does not remove current-run generated-video bytes.
- [ ] #4 The next real app startup still removes prior-run files when retention is `session`.
- [ ] #5 Focused lifecycle tests fail if retention cleanup moves back into per-screen store initialization.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Isolate every touched test-app constructor from the real generated-video directory by patching the shared app factory and the ProductionApp module before TldwCli construction.
2. Add focused RED tests proving app-construction cleanup, second-startup session/TTL and expired-card behavior, bounded exactly-once failure containment across fresh screens, explicit overrides, fail-loud missing ownership, and real Console -> Settings -> Console byte survival.
3. Create one app-owned VideoStore after effective config load, run the existing retention sweep synchronously once, and preserve the store after a bounded startup failure.
4. Make ChatScreen borrow that app-owned store (or an explicit test override) without constructing or cleaning a store; mutation-prove the navigation regression.
5. Run only the two touched focused test modules plus exact touched-file Ruff, temporary-output py_compile, and diff checks; self-review lifecycle/privacy, verify branch/PR identity, then close the task and update PR #1460.

Reason: ADR-044 already assigns session/TTL retention to app startup; this fix moves the existing operation to its correct lifetime owner without changing policy or storage.
