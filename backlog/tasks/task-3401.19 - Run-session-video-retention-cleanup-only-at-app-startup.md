## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Prevent Console screen construction or remount from reapplying session-retention cleanup to videos generated during the current app run. Live UAT observed a current-run Base video become expired after navigating away from and back to Console.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Session retention cleanup is applied once at app startup and not by each Console screen instance.
- [x] #2 Navigating from Console to Settings and back keeps current-run generated cards ready.
- [x] #3 Recreating or remounting ChatScreen does not remove current-run generated-video bytes.
- [x] #4 The next real app startup still removes prior-run files when retention is `session`.
- [x] #5 Focused lifecycle tests fail if retention cleanup moves back into per-screen store initialization.
<!-- AC:END -->

## Implementation Plan

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented startup-owned generated-video retention. After effective config load, the app creates one VideoStore and synchronously runs retention once per app; failure is bounded to an exception-type-only warning while the owned store remains available. ChatScreen borrows the app store, accepts an explicit test override, fails loudly when the owner is absent, and never constructs or cleans a store.

Focused lifecycle coverage uses real temporary files: Console -> Settings -> Console preserves current-run bytes and a ready card; a second app startup expires the prior session card; TTL keeps fresh bytes and removes stale bytes. Exact TDD evidence was RED with 4 failed, then GREEN. Mutation evidence changed the navigation card from ready to expired when per-screen cleanup was restored, and returned to ready after restoring the fix.

Final focused verification: 19 passed with 1 RequestsDependencyWarning in the two user-authorized test modules. Full Ruff passed only for Tests/UI/app_factory.py, Tests/ProductionApp/test_chat_composition_retirement.py, and Tests/Chat/test_console_video_message.py. Targeted Ruff E9,F63,F7,F82 passed only for tldw_chatbook/app.py and tldw_chatbook/UI/Screens/chat_screen.py. py_compile passed for exactly those five Python files into a validated TemporaryDirectory outside the repository, and the temporary output was removed. No broad or full suites were run, per the user-authorized narrow scope.

VideoStore retention policy is unchanged; the all-mode cap remains tracked separately in TASK-3401.20. Implementation commits: 4d54552f4, c19969fa5, 4ba1c2aed. ADR-044 applies, so no new ADR was required. No new generalizable incident surfaced, so no lesson was added.
