## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Slice D4 (spec §4.1, §4.2, §4.4, §4.4a, §4.5). This is the core desk. In the Media reader, `n` (or the toolbar **Note** button) opens the user's working note in the companion slot. The first time, the **Write in…** picker offers notes that cite this document, recent notes, or a new note. The note stays open while `]`/`[` or other navigation change the document. The header shows `Working note · <title> · cites N ▾` and `‹ Items`. `cites N ▾` reopens the picker to swap notes. Save never drops off the header. The Escape ladder runs note → reader → closed. The desk survives navigation for the session. It builds on TASK-34000.25 (state preservation) and on TASK-34000.39's one-row byline, and uses the note session (ADR-027) for saving.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 `n` in the Media reader opens the Write in… picker when no working note is set (groups: Notes that cite this document, Recent notes, + New note with the title pre-filled), and opens the working note directly when one is set
- [ ] #2 `]`/`[` and opening another item change the document while the working note, its caret and its scroll stay put
- [ ] #3 `cites N ▾` reopens the picker to swap the working note (the current note is saved first); `‹ Items` and Escape from the reader close the desk; closing does not forget the working note
- [ ] #4 Save stays visible at every width (the header drops `Working note ·` then truncates the title); Ctrl+S saves (amended ADR-031); a refused autosave never moves focus
- [ ] #5 Leaving Library and returning restores document, scroll, working note and caret for the session
- [ ] #6 Bare letters type in the note; desk keys act only while the reader has focus; footer and F1 advertise exactly the live keys
- [ ] #7 Pilot tests for each behaviour fail on dev before the change; verified live at 235x52, 160x45, 120x36 and 100x30
