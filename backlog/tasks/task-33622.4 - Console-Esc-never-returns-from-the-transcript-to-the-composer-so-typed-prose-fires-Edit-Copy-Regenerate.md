## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** Once the transcript has focus (F6 or a click on a message), Esc never gets back to the composer. The first Esc clears the message selection, and every later Esc does nothing visible. The composer stayed unfocused after 1, 2 and 3 Escs. F1 help says 'Escape: return to the composer', and the left rail footer shows 'Esc composer · F6 panes' (Esc works there), but the transcript shows neither the hint nor any mode indicator. Prose typed in this state never reaches the composer:
- unbound letters vanish ('hi');
- 'y' opens the full-screen Trace;
- 'n' toasts 'No review notes on this message.';
- a j or k inside the prose re-selects a message, and the following letters act on it. 'Make a joke about cats.' stacked two Edit Message modals, overwrote the clipboard and armed text-selection mode. 'look around' fired Regenerate, a paid request that created a new branch (Assistant 2/2).

Verified live on dev 64579cce2c at 160x45 (live, code and skeptic all CONFIRMED). Esc from Inspect does return correctly.

**Cause.** `ConsoleTranscript.on_key`'s escape branch always stops the event, so the screen's fallback to `focus_console_composer_home` is never reached.

**Severity / prior art.** P1, triage NEW. Related: TASK-18156 (Done, the Esc layering of text-selection mode, then message selection, then composer, which this breaks at the last step), TASK-32322 (Done, rail escape hints that the transcript never received), TASK-362 (Done, transcript keys in F1), TASK-31223.

**Suggested direction.** Stop the Esc only when something was actually cleared (selection, selection menu, text-selection mode, More menu). Otherwise let it bubble so the screen returns to the composer. Show a 'Transcript keys · Esc to type' indicator, or the rails' 'Esc composer' hint, while the transcript has focus. Route unbound printable keys to the composer, or reject them visibly. Consider requiring an explicitly confirmed selection before the paid Regenerate (r) and Fork (f) can fire.
