## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Seen live on 2026-11-21 while working on TASK-33621.6, on branch fix/task-33621.6-retry-capture-regression (origin/dev dc371f0842 plus a diff that does not touch streaming). The model was claude-haiku-4-5 behind the review proxy in `cut` mode, which drops the connection after 6 streamed chunks.

The prompt was "Write the numbers 1 to 80 as words, comma separated." The app tried three times (three POSTs, each cut) and ended with a Failed row. That row's text is all three partial attempts joined with no separator: "... nineteen, tweOne, Two, Three, ... Fourteen, FifteeOne, two, three, ...". The saved message (`assistant_generation_state='failed'`) holds the same joined text, so it survives a reopen.

Two things are wrong. A reader cannot tell where one attempt ends and the next begins, and the saved failed reply mixes outputs the provider produced for different requests.
