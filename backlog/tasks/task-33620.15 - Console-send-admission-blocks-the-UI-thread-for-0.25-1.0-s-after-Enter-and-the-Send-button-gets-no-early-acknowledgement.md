## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while fixing TASK-33620.5 (2026-10-04). That task paints the user row and 'Sending…' 31-78 ms after Enter, but then the synchronous admission work (_build_console_turn_execution_context on the UI thread) still blocks input for 0.25-1.0 s live; the app log named a 612 ms stall. The stall records point at storage-admission and config-file checks: _config_file_posture runs on every settings cache hit, 20-60 ms per tick in the harness, up to a 294 ms live stall. The mouse Send button and the Workbench send take a different path and get no early acknowledgement.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Measure on the parent build first (mounted harness probe + live tmux poll with a main-thread sampler, real Anthropic haiku via the review proxy): admission components cold/warm, every input block between Enter and the provider call.
2. Root cause A: the visible send (Enter) runs inside an app-pump callback, so every await in it (hook snapshot, any off-thread work) still blocks key delivery. Run the visible send as its own task after the acknowledgement paint, so no Textual pump awaits it.
3. Root cause B: the I/O-heavy admission captures (MCP definition maximum, skill context, project authority, RAG profile depth, scratch space, prompt-transform/character/persona/tool-policy reads) run on the UI thread. Capture them in a worker thread before the synchronous gate; the unchanged synchronous builder consumes them only when its inputs still match, so durable-acceptance ordering (gate re-check + accept_turn in one synchronous stretch), the snapshot contents and trace provenance stay as on dev.
4. Keep the repeated-Enter guard as on dev: a send request during an in-flight admission is deferred and replayed after it settles, never sent twice or refused with a toast.
5. Root cause C: _settings_cache_hit lstat-stamps every path component on every warm hit. Check the posture once per UI-loop stretch (invalidated by a rebuild/write and at the end of the stretch); callers off the loop keep the per-hit check.
6. Send button and Workbench send go through the same acknowledged, detached send as Enter.
7. Deterministic mounted test that fails on dev: a key typed while admission's capture is held is handled before it is released; negative controls (inline dispatch, on-loop capture). Posture memo test. Equivalence test for the snapshot.
8. Live before/after (first frame, longest input block, provider-call start), ADR-097 boot census, storage census, size ratchets, preflight, User Guide.
9. Review fix (tab switch during admission): a deferred send request records the chat it was made in and is dropped unless that chat is still the visible one when it replays; regression test that switches tabs between the second Enter and the replay.
10. Review fix (gate reads the visible tab): read the screen-level send gate (blocked/setup reasons) once, before the precapture await, while the send's own chat is the visible one; the gates after the await are already session-pinned. Regression test that switches to an unconfigured tab during the held precapture.
11. Cheap follow-ups: drop the now-uncalled session.py resolvers; one forced badge refresh when a run ends.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
A Console send's admission no longer holds key delivery, and the Send button and the Workbench's send now show the same "Sending…" acknowledgement as Enter. Two smaller costs on the UI loop are also gone: warm settings hits now stamp the config path once per loop batch, and during a run the sub-agent badge counts are re-queried at most once a second.

**Measured first (AC#1), parent build 2bbfd8ad8c.** On a cold first send, the turn-configuration builder held the UI loop for 531 ms in the harness: RAG profile depth 288, MCP definition maximum 114, scratch space 53, skill catalog 45, project authority 30. Live it was 613 ms. A send made 114-243 warm settings-cache hits, each one lstat-ing the config path: 53-251 ms per send in the harness, and a 294 ms stall live. The sub-agent count query was 18% of the main-thread samples between Enter and the provider call.

**Approach**
- The visible send now runs as its own task (`send_acknowledgement.request_visible_send` / `_start_send`). Before, it ran inside `app.call_later`, whose callback Textual's pump awaits, so every await in admission held key delivery. A send request made while a send is running is replayed once that send settles, so a double Enter never sends twice.
- `turn_admission.precapture` reads the service-owned turn authority in one worker hop before the gates. The gate re-check, the snapshot build and `accept_turn` still run in one synchronous stretch. The builder uses the precapture only while the session inputs it was read for still match. A failed precapture is dropped, so errors surface where they did before. Durable-acceptance ordering and trace provenance are unchanged; `Tests/Chat/test_console_turn_admission_precapture.py` checks the snapshot is the same.
- `config._settings_cache_hit`: on a thread that runs an event loop, the config file posture is checked once per loop batch. A rebuild or a write installs a new settings object. Callers off a loop keep the per-hit check.
- `Console_Modules/agent.py`: during a run, badge counts are refreshed on the first sync, then at most once a second.
- Enter, Send and the Workbench share the captured path. A trusted `! ` command commits its captured draft before it starts (on dev, a refused one came back as "! pwd! pwd"). Once the menu opens, `/rewind` commits its captured command and re-syncs the slash-command popup. Live, a Send click on the first build left the popup row drawn under the menu.

**Decision: TASK-33620.15.1 is not part of this PR.** It covers a later phase (acceptance to the provider call), while AC#2 here covers admission. Its fix is to cut the per-call storage-admission scope cost, which is a Backup_Recovery design decision. Two in-scope variants were measured and rejected: five worker hops for the MCP reads, and a 1 ms GIL switch interval.

**AC#2 is not fully met.** Final branch, 2026-10-08, 160x45, Anthropic haiku via the review proxy, six sends paired with the parent build. The longest hover wait from Enter to acceptance was 50-142 ms, against an idle wait of 20-35 ms; the parent build's was 224-387 ms. One send in six still waited 107 ms over idle. On 2026-10-06, 4 sends in 12 did, up to about 145 ms. Main-thread samples put that residual in two places: the acknowledgement's own layout pass, and a Console sync that ran during the precapture hop (provider readiness `load_settings`, `resolve_provider_endpoint`, storage admission), slowed by GIL contention with the worker. That is the same per-call cost TASK-33620.15.1 covers, so the residual was added there as AC#6.

**Review fixes (2026-10-08).** The checkpoint review found two ways the off-pump send let a tab switch reach the wrong chat. Checking them also turned up a third window. Each fix was written test-first, and each new test failed on the pre-fix head for the reason it pins:
- *Deferred replay ran in the wrong chat.* A second Enter during admission is replayed when the send settles. It replayed in whatever chat was visible then, so Enter, Enter, Alt+2 sent tab B's unsent draft. `request_visible_send` now records the chat the request was made in (the latest request wins) and drops the replay unless that chat is still visible; that chat keeps its draft. Pinned by `test_an_enter_deferred_behind_a_send_never_sends_another_tab_draft`. Negative control: with the chat check disabled, B's draft is sent again.
- *The send gate read the visible chat after the await.* The screen's send gate (provider readiness, archive, evidence, vision) describes the visible chat. It was read after the precapture await, so Alt+2 to an unconfigured tab refused tab A's send with B's reason ("Add API key ..."). `dispatch` now reads it once, before the await, in the same synchronous stretch as the hook gate's check that the send's chat is visible. The gates after the await are already session-pinned. This also removes the second readiness computation per send. Pinned by `test_leaving_a_tab_while_its_send_is_admitted_still_sends_it_there`.
- *Typing after Enter cancelled the send.* The hook gate refused a send whose composer changed after the capture ("Draft, chat or hooks changed; Send again."). Keys now flow during the hook snapshot read. A key typed straight after Enter (during the paint hand-off) hit the same refusal on origin/dev and on the parent build too (mounted probe; live on the parent: "...gammanext" left in the composer, nothing sent). Text typed after the capture belongs to the next draft (TASK-340), so the draft is now re-checked only after a review. The chat is always re-checked, because the gate read above depends on it. A tab switch during that one worker hop therefore still refuses the send and keeps its draft. Pinned by `test_a_key_typed_while_the_hook_read_is_held_joins_the_next_draft` and `test_a_ready_send_rechecks_its_chat_but_not_text_typed_after_capture`.
