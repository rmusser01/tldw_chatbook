## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-33620.1 has each scheduler tick record whether the emergency stop held dispatch in its heartbeat, and Schedules' liveness line reads that heartbeat. The note therefore lags a clear by up to one poll interval (documented), and on a STALLED or non-ticking scheduler it keeps showing the hold from the last heartbeat after the stop is cleared, which is misleading. Schedules already reads one small JSON file every 5 s for liveness; reading the stop file alongside it would make the note follow the stop itself (raised in TASK-33620.1's review).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->

- [ ] #3 The read stays off the UI loop
