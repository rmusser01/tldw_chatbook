## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A user usually files a note right after a quick capture, and that is exactly when the folders appear to be gone.

A power user capturing from Console through the palette ("New Note" → Blank note → Esc) comes back to a tree with two blank rows and then "▾ Unfiled":
- Agent_Lessons, Journal, Meetings, Projects, Recipes, Research and Study are missing.
- "g go to folder" lands on Unfiled.
- "Add note to folder" opens with nothing to choose.

The folders come back only after the user presses the rail's Notes row or creates another note.

Observed at 160x45 from a fresh golden launch, reproduced in two runs:
- After Create > Blank > Esc, the tree starts "▾ Unfiled / Capture from console · now / Ideas inbox · 2h …" with no folder rows above it (`verify/nl-v-n-13/r1-05-after-esc-160x45.txt`).
- Opening Add to folder shows the "Add note to folder" dialog with an empty folder Select (`r4-03-select-open-160x45.txt`).
- Both the palette's "New Note" and the rail's Create ▸ New note lead here.

Cause (traced by the review's verifier; file:lines confirmed at origin/dev 2d34cbf80d):
- The tree projection emits folder rows only after the root folder branch `NotesBranchKey(None, "folders")` has been loaded (`Library/library_notes_tree_state.py:1062-1071`).
- The rail-row entry requests that branch. The create path does not.
- `_create_library_note` (`UI/Screens/library_screen.py:30657`) reconciles the tree for "note_create" at :30804. That reconciliation then locates the new note through `_locate_library_notes_tree_target` (:18560).
- Nothing on that path requests the root branch when it is missing, so the tree is painted without folders and the folder pickers have nothing to list.

Suggested direction (a direction, not a mandate):
- In the create path, request the root (None, "folders") branch when it is missing, before locating the new note.
- Never paint rows with no label while the folders load; show "Loading folders…" instead.

No existing task owns this.
