## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** Measured at 160x45 with 100-150 ms polling:
- After Enter, nothing changes for 0.44-0.66 s.
- The composer then clears to its placeholder, showing 'Send disabled: type a message', while the Send button still reads 'Send'.
- For the next ~1.1-1.9 s every status surface stays idle: header 'Ready', no tab '●', no Run chip, rail row unchanged. The transcript still says 'No messages yet.' on a first send or a new Ctrl+T tab.
- The user row first appears 1.8-3.2 s after Enter.

The store has the echo much earlier: durable_commit succeeded at about 760 ms, so the gap is in rendering, not admission. The J5 profile log shows a 2.9 s synchronous admission on a cold send, so longer gaps are plausible.

Consequence, verified: retyping the prompt and pressing Enter 0.9 s into the gap created a queued duplicate that auto-dispatched. The result was two identical user rows, two replies and two paid provider calls.

**Severity / prior art.** P1, confirmed by all three verifiers. This is a **REGRESSION of TASK-351 (Done, AC#1**: 'echoes the user's message ... the instant the submit is accepted ... closing the composer cleared but transcript still says No messages yet gap') and of **TASK-457 (Done, AC#1**: cold-send optimistic echo). The acceptance-time echo was removed in b7dd8e53f2. TASK-485 (Done) already provides a transient-echo rollback. Raw admission latency stays with the PERF series; this task is about acknowledgement.

**Suggested direction.** Paint the pending user row, marked 'Sending…', and flip the header, tab marker, Run chip and Send control directly from the key handler or the runtime accept return. Do this before the synchronous admission work, not on the whole-screen sync tick. While a turn is pending, suppress the empty-draft reason, and key the empty state off 'no messages and no pending send'. Roll the row back with an inline error if admission or commit fails.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Enter now paints a "Sending…" acknowledgement (user row, Running header, tab dot, Run chip, Send "Sending...") before any admission work runs, and the unchanged send is handed to the app pump only after that frame is laid out. A per-tick control-bar restyle was also removed.

**Measured on dev 7d155170dc first (live, Anthropic claude-haiku-4-5 via the review proxy, tmux frame polling; mounted harness with the app's eager task factory and a main-thread stack sampler).**
- Enter → composer blanked: 946 ms (first send), 458 ms (warm), 800 ms (new tab) at 160x45; 592 ms at 80x24; 378 ms at 235x52. In those frames the header still read Ready, the transcript said "No messages yet."/"Ready — type a message to begin." and the composer said "Send disabled: type a message".
- Enter → user row and status surfaces: 2155 / 1831 / 1669 (row 3131) ms at 160x45; 1089 ms at 80x24; 1010 ms at 235x52. Bad frames (empty composer + Ready + no row): 2, 2, 2, 2, 3.
- Causes: (1) Enter's send ran its synchronous admission on the UI pump before anything was painted (`_build_console_turn_execution_context`, 0.25-1.0 s; live stall record names it at 612 ms); (2) nothing acknowledged the send before that work; (3) the row and status surfaces reached the screen only through the 0.2 s whole-screen sync tick (136-261 ms per tick in the harness, transcript painted last); (4) every tick `ConsoleControlBar._set_recovery_height` removed and re-added its height class, re-applying CSS to the whole bar subtree (20-108 ms per settled tick).

**After (same recipe, branch):** the full acknowledgement frame is on screen 47-97 ms after Enter at 80x24, 160x45 (first, warm, new tab; final build 67 and 47 ms) and 235x52, with zero bad frames; "Send disabled: type a message" never appears while the send is pending. Internally the paint takes 28-29 ms and the hand-off to the send runs 58-68 ms after the keypress. Settled-tick cost (harness): auto-speak sync 20-108 ms → 0.0-0.1 ms; control-bar sync 32-115 → 12-15 ms; whole tick 136-261 → 96-165 ms.

**Approach.**
- `UI/Console_Modules/send_acknowledgement.py` (new, imported on the first Enter only, so the ADR-097 UI-ready census is unchanged): a per-session, view-only acknowledgement. Only an idle session's plain text draft is acknowledged (slash, `! `, empty drafts, live runs and queues keep their existing surfaces). The synthetic USER row (status "pending") is projected into the transcript until the store's own echo appears; it is released when the dispatch admits no turn (refusal, hook review, command) or when the runtime's custody of the admitted turn ends without an echo (terminal callback on `accept_turn`), and a release requests one coalesced whole sync. Nothing writes the store, the runtime or the durable turn, so durable-acceptance ordering and the trace/provenance pipeline are untouched.
- Hand-off ordering: the paint runs on the screen pump with targeted pushes (transcript rows, `ConsoleComposerBar.show_send_acknowledged`, Run chip, header state, tab markers). The dispatch waits until a refresh has laid the row and chip out, via frame-length timer hops bounded at 6. A `call_after_refresh` hop alone failed: the screen ran six of them in 0.3 ms without yielding, before the row's and chip's own pumps had posted their Layout requests.
- Every later sync derives the same facts from the acknowledgement: `_console_active_run_copy` (Run chip, and through it `_console_run_active` and the hidden mode-bar copy, now derived from one place), the prompt-queue presentation (`sending` → "Sending...", refusing with "Queue opens once this turn is accepted"), the tab-marker overlay and the transcript projection.
- `ConsoleControlBar._set_recovery_height` touches classes only when they change.

**Trade-offs / not done.** The draft stays in the composer until acceptance (unchanged recovery semantics), so for the admission window the text shows in both places. The Send *button* (mouse) path is not acknowledged: it awaits the send on the screen pump and returns its outcome to the spoken-send path; the ACs name Enter. The synchronous admission itself (0.25-1.0 s live, dominated by storage-admission and config-posture checks) still blocks input after the acknowledgement; per the task description that is the PERF series' work. Observed but pre-existing (same rate on both arms, 1 in 4): after an injected `commit_durable_turn` failure a whole-screen sync is sometimes left mid-flight and the final state is not repainted.

**Tests.** `Tests/UI/test_console_send_acknowledgement.py` (bootstrap_profile; real ChatScreen, driver-delivered Enter, eager task factory, compositor-painted frames): acknowledgement painted before admission and validation with the hook-permission snapshot and provider validation both held (ordering asserted in one recorded sequence); no empty-composer/idle-header/no-row frame and no empty-draft copy while pending; runtime refusal rolls the row back and keeps the draft; custody refused before the echo releases the row and offers "Unsent turn needs attention"; a repeated Enter during admission never starts a second provider call; an unchanged control-bar sync does no style work; plus unit tests of the release rules and the Send presentation. All five mounted tests were red on origin/dev for the stated reasons.

**Gates.** `Tests/UI/test_console_send_acknowledgement.py` is added to `scripts/ui_pr_gate_census.txt` (floor 136 → 137) so the PR lane runs it. The prompt-queue painted-label walk gained a `sending` row (its completeness guard failed until it had one). The one new production diagnostic (a type-only WARNING if the paint itself fails) was reviewed with `--statements` and recorded with `--write`. Regression A/B against the merge base (exported tree): every head failure in `test_console_native_chat_flow.py` (diagnostic bootstrap plugin), `Tests/Architecture`, the runtime-ownership/workbench-contract, unmarked console and transcript suites reproduces on base or is flaky on both arms (private-scratch session switch, 1 in 3 each; workspace-link race, about half on each). `test_console_resend_click_re_runs_a_failed_turn_in_place` failed 2 of 3 times only in one five-file combination under heavy machine load and passed 3/3 alone on each arm.
