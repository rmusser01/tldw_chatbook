## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`update_keywords_for_media` and `create_document_version` execute DML on the held connection and document that they assume an existing transaction, but the shipped reading-list import path opens none: `import_reading_items` -> `execute_reading_import_job` -> `_execute_reading_import_job` (a per-row loop) -> `_materialize_reading_import_row` -> `update_keywords_for_media`. Because the connection keeps the legacy isolation level, the first bare call opens an implicit transaction that nothing commits, and `transaction()` then borrows it without committing, so every later Media write on that thread is rolled back at close. Reproduced: two media rows expected, one found, with a keyword and a read-it-later row lost.
