## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** With default settings, Console replies from Anthropic, OpenAI and the other existing cloud templates are not streamed. The row shows 'Assistant Generating…' for the whole provider call, with no elapsed time, and then the full text lands in one frame. Long answers look frozen, sometimes for tens of seconds. Users cannot start reading early, decide whether to stop, or tell a slow run from a stalled one.

The cause is a configuration default, not AgentService:
- The shipped template sets `streaming = false` under `[api_settings.anthropic]`, `[api_settings.openai]` and the other cloud sections.
- `[chat_defaults]` has no streaming key, so Console session settings resolve Streaming to Off.
- With Streaming switched On, `_StreamingModelAdapter` already streams through the agent_stream fence-gate: partial text and a 'Streaming…' header label appeared mid-run. The `streaming=False` literal at agent_service.py:3155 has no effect.

The User Guide (chat-basics.md:322-328, 462-467) promises streaming, a '[streaming]' suffix and a partial reply kept on Stop. None of these hold at default settings, and the in-flight marker is now a 'Streaming…' header label.

**Severity / prior art.** P1, triaged REGRESSION (verdicts PARTIAL). Streaming was the observed default when TASK-71 and TASK-347 (both Done) were reviewed in July. TASK-15456 (Done) is related. Open related tasks, which do not fully cover this:
- TASK-2122 (To Do): streaming usage capture is missing for 9 of 11 providers, which is why default-off currently keeps cost accurate. It must land or be confirmed before any default flips.
- TASK-338 and TASK-33004.7 (To Do): Streaming on/off visibility in the rail. That work stays there.

**Suggested direction.** Make and record a product decision on the default for cloud providers (for example `streaming = true` in the shipped `[chat_defaults]`), gated on TASK-2122. Also fix the Mistral template inconsistency noted there. Whatever the default, make the non-streamed path honest by adding an elapsed counter to 'Generating…'. Update the User Guide.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G1-10 (source J2-04). Files: evidence/evidence__J2__101-pollnum-drip.log, evidence/evidence__J2__22-drip-t5.png, evidence/evidence__J2__23-drip-t8.txt.

Dev-tip note (reviewed 64579cce2c; checked against 857b3dd7d0): Commit 0678f56b1f (TASK-33351, 13 gateway/host presets) adds new [api_settings.*] sections (vercel, zenmux, kilo, siliconflow, baseten, gmi, ollama_cloud, upstage, arcee, qianfan, nous, venice, meta) with streaming = true. It leaves anthropic, openai and the other existing cloud sections at streaming = false and adds no [chat_defaults] streaming key, so it does not fix this finding. It does make the per-provider default more inconsistent, which the default decision should cover.

Review finding ids: G1-10 — see qa/console-ux-review-2026-09-29/findings.md.
