## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by TASK-33620.15.18. A run's canvas settlement imports `Canvas.native_authority`, which imports `Canvas.gateway`; the gateway imports `aiohttp.web` at module scope, and `CanvasGateway.__init__` builds an aiohttp `web.Application`. So the first run's end, and the post-UI-ready first-send warm-up that pre-imports it (TASK-33620.15.5), load aiohttp: about 49 modules and 37-38 ms of CPU (two SSL contexts in `aiohttp.connector` among them), plus about 12 ms for `aiohttp.web`.

The warm-up parks before each step while a navigation holds the loop, and no longer starts a step right after an input, but it cannot yield inside an import it has started. After TASK-33620.15.18 split the rest of the run end's closure into small steps, aiohttp is the heaviest step left. Live on TASK-33620.15.18's head f1b164cc2f (160x45, established profiles, load 2-8): a Library click sent at the start of the warm-up's aiohttp step drew Library's first frame a paired median +13.8 ms later than origin/dev 7536ac3b87 without the warm-up at the same moment (6 of 8 pairs slower, -3 to +23 ms; origin/dev with the warm-up, at the start of its heaviest step, then native_authority: +52 ms, 8 of 8). A key sent at the same moment was not slower (+0.2 ms), and a click at a random moment of the window was not either (-9.5 ms, 10 pairs). Evidence: tools/evidence/bd5/M18/r6 (click@mod cells).

If the settlement does not need an HTTP server, it should not have to import one: the gateway's request and response types and the settlement lease could load without aiohttp, and the `web.Application` could be built when a gateway is started or mounted.
