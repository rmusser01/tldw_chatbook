## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`Utils/atomic_file_ops.atomic_write_text` (used by the emergency stop's durable write, among others) calls `os.replace` once. On Windows a reader holding the destination open (an antivirus scan, the agent loop reading the stop file each tool call since TASK-33620.1.12, or another app instance) makes `os.replace` fail with a sharing violation (PermissionError / WinError 5 or 32), so `/emergency-stop` or its Clear can fail intermittently. Found in the TASK-33620.1.12 review.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 On Windows, a transient sharing violation during the atomic replace is retried within a short bounded window before the write is reported as failed
- [ ] #2 A persistent failure is still reported, never swallowed
- [ ] #3 Covered by a test that simulates the sharing violation
