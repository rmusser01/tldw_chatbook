## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: Ctrl+Q silently loses unsaved Research workspace work. The screen defines `flush_pending_work` (`tldw_chatbook/UI/Screens/research_workspace_screen.py:728`), which leaving the screen through navigation awaits. It has no `confirm_quit`/`prepare_for_quit`, and the app's quit flow consults only those hooks. So a quit drops whatever the flush would have saved or asked about.

The gap was found while fixing the same defect in Library ▸ Notes (TASK-34000.1, review finding N-01). That fix added `Tests/Architecture/test_flush_screens_have_quit_hooks.py`, which lists this screen as a known gap. Removing the entry is this task's proof of done.

The fix should follow the Library and Roleplay precedents (TASK-34000.1, TASK-33622.14):
- Ctrl+Q awaits the same flush navigation uses.
- When the flush cannot complete, it asks "Keep editing / Discard and quit" with Keep focused.
- Every prompt is awaited through `await_quit_prompt` (ADR-031, task-33622.10 refinement).
