## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Fifty ADR numbers are shared by 117 decision files: 37 numbers by two files, 10 by three, 2 by four and 1 by five. So a reference such as 'ADR-228' (the SQLite store kernel and config-encryption key memoization) is ambiguous. Nothing stops a new decision from reusing a number.

**Owner decision (2026-10-25): renumber the younger file, as task ids do.** The oldest file of each shared number keeps it; each younger file takes the next free number and carries a provenance note naming its old number. This task records that rule and adds the guard. The renumbering itself is a separate, dependent subtask.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F17; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->
