## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
C7(b) does not affect only the switcher. The shared ModelSearchPicker (Widgets/model_search_picker.py) renders options as plain ids (:643-644, :697-705), and Down highlights the first enabled option instead of the committed one (:866-875). The Chat settings modal still chooses its model through it (Widgets/Console/console_settings_modal.py:1794), and it still makes the user choose a provider first (ConsoleProviderPicker at console_settings_modal.py:1725; _rebase_to(provider, None) at :5372).

The synthesis ships a pick-only mode of the switcher in this phase. The pair list, its tests and its result contract then live in one widget, and Chat settings can pick provider·model pairs instead of a provider alone. This phase does not wire the modal to the new mode, because the modal has zero line headroom. The picker's mark is a widget-level fix: every host that keeps ModelSearchPicker benefits from it.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Switch model gained a pick-only mode, and the shared ModelSearchPicker now marks the committed model in words and lands Down on it.

**What changed**
- `Widgets/model_search_picker.py`: `CURRENT_MARK = "● CURRENT"` lives here (the switcher imports it, so there is one spelling). Both result renderers (flat and provenance-grouped) add rows through `_add_result`, which builds a literal `Text` prompt (the flat list used to pass escaped markup) and appends `  ● CURRENT` to the committed model, recording its option index. Down highlights that index, else the first enabled row as before. `_hide_results` and each render reset the index.
- `Widgets/Console/console_model_popover.py`: `pick_only: bool = False`. In pick-only mode compose stops after the pair list and prints one key row, "Enter picks · Esc cancel" (no values label, value row, guard, Apply / Ctrl+N / Ctrl+O / Save buttons or scope line). Highlight moves never rebase the draft, so `draft_rebaser` is not called; Enter (or a row click) dismisses with `(provider_key(provider), model)`; `_submit` refuses (Ctrl+O), and `_activate` ignores the default actions (Ctrl+N), so `live_committer` and `setup_opener` are never called and no configuration is written. Esc dismisses `None` at once, even when the opener's draft carries edits. NEEDS SETUP rows are disabled options (one `_selectable` predicate drives both the OptionList and the initial highlight), so arrows, clicks and the initial highlight skip them; they are painted in the plain option colour, dimmed and not bold, because a disabled option otherwise inherits the bold primary header style. Copy that promised Enter is reworded in this mode: the Find placeholder says "Enter picks", PREVIOUS has no "Alt+M, Enter swaps back", NEEDS SETUP reads "set up in Settings first", and setup rows carry no "Enter: …" hint.
- `Docs/User_Guide/console.md`: the Chat settings model list marks the model the field holds with ● CURRENT and Down highlights it first. Pick-only mode has no entry point until phase 6 wires Chat settings' Change, so the guide does not describe it yet.
