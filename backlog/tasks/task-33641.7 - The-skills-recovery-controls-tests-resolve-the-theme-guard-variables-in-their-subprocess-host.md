## Notes

All thirteen nodes of the file pass (the twelve mounted ones and the posture test). Phase 9, plan Task 10; base 10fead87cb.

**Three causes, not one (AC#1, AC#2).** The stylesheet error was the first failure of every mounted node, and it hid two more.

1. The host was a plain `App`. `push_screen` loads the Library screen's sheet, whose `$ds-grid-line: $tldw-boundary;` has no source there, so the parse raised `UnresolvedVariableError`. The host now inherits `ThemeVariableDefaultsMixin`, as `TldwCli` and `Tests/UI/consolidated_css.py::ConsolidatedCSSApp` do.
2. The script read `self._library_skills_trust_posture` and wrote `_library_skills_view`. The screen lost those flat attributes on 2026-09-04 (ed4c29d45f); the state lives on `self._skills_state`. With the mixin alone the node failed with `AttributeError: 'Subject' object has no attribute '_library_skills_trust_posture'`. The script now uses `_skills_state.trust_posture` and `_skills_state.view`.
3. The script waited for `#skill-trust-bootstrap-input` and then pressed `#skill-trust-bootstrap-submit`. The Submit button sits in a container below the inputs and mounts one step later. With the file run alone that raised `NoMatches` in 2 of 13 nodes, then in 1 of 13 twice. The script now waits for the Submit button. The ordinary-unlock script had the same wait against the unlock modal (`#skill-trust-passphrase-input`, then `#skill-trust-passphrase-submit`). It lost that race once in nine runs of the file, and waits for Submit as well.

After the first three changes the file passed 13 of 13 in three runs alone, at load averages of 40 to 47. With the unlock wait it passed 13 of 13 in three more.

**What the mixin does and does not prove.** Importing `tldw_chatbook/css/Themes/themes.py` already guards Textual's built-in themes in place, so the new import by itself gives a plain `App` the names: with the mixin removed and the import kept, the three nodes tried (cancel-review, approve, navigation) passed. The mixin is kept because it is how the application resolves the names, and it also covers a theme registered without the guard.

**Census of other hosts (AC#3).** In-process hosts are covered already: `Tests/conftest.py` imports `themes.py` for every test process (TASK-33003.6). The open case is a host built in a child interpreter.
