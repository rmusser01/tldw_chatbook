## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The wizard says setup succeeded while the first message cannot be sent.
- OpenAI: the recommended model and the shipped default gpt-5.6-terra both resolve a stale 4,096-token context window, and the 4,096-token reply reservation fills all of it. Every send is refused, yet the Console header, Settings and the model switcher all say 'Ready · not tested'.
- OpenRouter and Hugging Face accept any key, because the "check" is a public model list.
- NVIDIA NIM and Novita can't list models at all, because the wizard gives discovery the chat URL instead of the base URL.
- Gemini gets no model list and no key check, and all 8 shipped Google catalog ids are retired (they return 404).
- Users with an exported key skip setup entirely and are told "you're ready to chat" with no check. With only a non-OpenAI key, new chats still point at an unkeyed OpenAI.
- Smaller defects: document analysis stays on OpenAI/gpt-4o whatever the user connected, template sample endpoints (TabbyAPI, vLLM) read Ready, local OpenAI-compatible sections ship with streaming off, and the env-key notice stacks on top of the model-list consent modal.

This task implements SF1 steps 1–3 of Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md ("first chat works" is the definition of done): repair the catalog, add a "Ready to chat?" verdict from Console's own preflight, and check keys where a model list proves nothing. It also covers the readiness parts of SF1's finish routine and the env-key "Keys found" part of enhancement E2. It resolves cross-cutting-01, new-cross-cutting-01, gap-01, gap-03, coverage-04, coverage-17, entry-exit-handoff-23, entry-exit-handoff-25 and new-coverage-power-02. Two related fixes belong to other subtasks: the chat-only filter on the '(recommended)' row (model-02) and the first-reply error copy (gap-06).

- [ ] #1 [cross-cutting-01] No model can be blocked before sending because zero input capacity is left. When a context window is only estimated, the reply reservation is capped (for example at min(max_tokens, window/4)). A test fails if any provider's shipped default or curated model resolves a window no larger than that provider's max_tokens
- [ ] #2 [new-cross-cutting-01] A model whose reply reservation leaves no input capacity reads 'Not ready', with a fix action, in the Console header, Settings, the model switcher and the wizard Summary, all from one capacity blocker in the shared readiness verdict. - [ ] #3 [gap-01] Setup rejects an invalid or expired OpenRouter or Hugging Face key through an authenticated check (OpenRouter /api/v1/key, HF whoami-v2) that shows the provider's reason. Those providers come from one public-listing set on the provider record, which now includes huggingface and novita
- [ ] #4 [gap-01] NVIDIA NIM, Novita and the other engine-driven presets list models in setup, because discovery gets the base URL rather than the chat URL. A valid key no longer reports 'Couldn't reach the server'
