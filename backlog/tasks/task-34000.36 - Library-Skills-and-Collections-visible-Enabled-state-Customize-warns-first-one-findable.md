## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A power user (Morgan) managing built-in skills cannot see whether a skill is on. Customize swaps a working built-in for a copy that may not run. A first-timer (Jordan) who saves something "for later" cannot find it again.

**L-11 (P2) · The built-in skill's "Enabled" switch shows OFF as an empty box, and the label never changes.** At 120x36, character-creator (Built-in) shows " Enabled " beside a Textual Switch.
- In both states the switch interior is empty. Only its background changes, a 1.22:1 contrast between on and off, so colour is the only cue.
- The only text cue is on the list row, which reads "› ✓ character-creator · Built-in · Disabled". It still carries the ✓, and the "· Disabled" suffix only fits at widths of 64 columns or more.

Verified cause: a Switch with a static label (`Widgets/Library/library_skill_work_pane.py:169-175`), which shipped with TASK-32954 (Done). The canvas family already records that Switch does not render reliably here (`Widgets/Library/library_skills_canvas.py:12-22`).

Suggested direction: replace the Switch with a Button labelled by `library_toggle_label` (`Library/library_shell_state.py:336`). That is the house text toggle, "Enabled: ✓ on ⇄ off". Drop the ✓ from list rows marked Disabled. Lowered from P1 because the list row says "· Disabled".

**L-28 (P2) · "Customize" hides the built-in and leaves a copy the agent cannot run, without warning first.** Pressing Customize on character-creator (Built-in):
- resets the work pane to "Select a skill to inspect it here.";
- removes the built-in row;
- lists "› ⚠ character-creator · needs review · overrides built-in" with the › marker left behind.

Only after the copy exists does the toast say "Copied to your skills — edit your copy. It needs review before the assistant can use it." The original cannot be compared or restored from the list.

Verified cause: `_customize_library_skill_builtin` seeds the copy, then resets the editor state and returns to the list without opening it (`UI/Library_Modules/library_skills_builtin_controller.py:148-197`). The "needs review" state is amplified by the harness's null keyring. The hidden built-in, the lost selection and the missing up-front warning are product behaviour.

Suggested direction:
- Put an inline consequence line under Customize, before copying. It should say what happens to the built-in and whether the copy needs trust review.
- After copying, open the copy in Trust or Edit.
- Show an overriding copy as "Replaces the built-in · Reset to built-in…".
- Clear the stale › marker.

**L-34 (P2) · "Keep for later" is split across three places, Home's count opens the wrong store, and Quick Capture's note box has no label.** A first-timer who presses Media's "Read later" cannot find the item again:
- Read later is not marked on list rows.
- It does not appear in Collections ▸ Reading.
- It is reachable only through Media ▸ Sets ▸ "Review read-later", an overlay that clips the reader.

Home's "Read-it-later: 2 items" opens Collections ▸ Reading (1), which shows a different item ("Zettelkasten in practice").

Collections ▸ Quick Capture accepts only web URLs ("Enter a valid http or https URL before saving."). Its 4-row text box, under "Title (optional)" and "Tags, comma separated (optional)", has no label or placeholder (`Widgets/Library/library_collections_capture_reader.py:438-441`).

Suggested direction:
- Give the box the placeholder "Note (optional)".
- Make the Read later confirmation name where the item went (Media ▸ Sets ▸ Review read-later), and show the count on that button.
- Add a cross-reference line to the Collections empty state, for example "Captures are web pages saved by URL. To keep a Library file for later, use Read later in Media."

TASK-32910 (To Do) owns Home's dropped read-it-later deep link. This task covers the rest, and checks that Home's count and the view it opens agree. Raised from P3 because of the Home mismatch the verifier found.

Review finding(s): L-11, L-28, L-34. Source: qa/notes-library-ux-review-2026-10-02/report.md
