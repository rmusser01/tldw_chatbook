## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The card's composition moved verbatim from `SettingsScreen` into `tldw_chatbook/UI/Settings_Modules/providers_models_card.py` (new package; DESIGN.md One Home Rule). Three module functions take the screen: `compose_providers_models_card` (was the body of `_render_provider_detail`), `compose_custom_endpoints_section` and `compose_custom_endpoints_children` (were `_render_custom_endpoints_section` / `_compose_custom_endpoints_children`). The only edits to the moved text are `self.` -> `screen.` and three call sites: the catalog toggles' settings now come from a new screen method `_model_catalog_card_settings()` (controller ruling R2: `load_settings` is still looked up in `settings_screen`, where `test_settings_model_catalog_toggles.py` patches it at six sites), the Custom endpoints call goes to the module function, and the `SettingsRegion` builder is `partial(compose_custom_endpoints_children, screen)` (the `SettingsRegion` docstring now says a builder may be a composer partially applied to the screen). Handlers, workers, `_custom_endpoints_view_config` and `_custom_endpoints_store` stay on the screen and still receive every bubbled event (task-1378 keeps that scope).

`_render_provider_detail` imports the module inside the method (R3), so neither boot nor the Settings route's pre-import payload loads it. The module imports the screen's own constants and widgets (`SettingsRegion`, `SettingsURLInput`, `_ProviderTestResult`, `_fold_long_tokens`, the copy constants) from `settings_screen`; that is safe only because the import happens after `settings_screen` has finished loading. `settings_screen.py` dropped its now-unused `custom_endpoint_rows` import (the tests import it from the view model) and gained `ModelCatalogSettings`.

**Geometry net written first** (Six Migration Rules rule 3): `Tests/UI/test_settings_providers_models_card_geometry.py`, committed alone before the move. With both disclosures open, it scrolls every painted control in the card to the top of the detail pane and asserts that `get_widget_at(center)` resolves to the control, at 160x45 and at 235x52, with the real stylesheet. The control set is discovered, with a floor of 30, so later Phase 7 reorders keep the net without pinning ids. It runs under `private_profile_test` for ADR-126 admission. It was green four times on the unmoved code, and a negative control (`#settings-test-provider` at height 0) fails it.
