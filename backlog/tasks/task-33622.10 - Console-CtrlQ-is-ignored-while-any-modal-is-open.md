## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ADR-031 and the footer advertise Ctrl+Q as app-global. TldwCli rebinds ctrl+q without priority (tldw_chatbook/app.py ~924). Textual merges subclass BINDINGS per key by replacement, so Textual's own priority=True ctrl+q is lost. App._check_bindings then walks the modal binding chain, which stops at the modal, so any open modal swallows Ctrl+Q. The TASK-33621.13 verifier reproduced it live: the Conversation Inspector was still up 25 s after Ctrl+Q, and no quit was logged. Pre-existing on dev.
<!-- SECTION:DESCRIPTION:END -->

## Summary
Ctrl+Q now reaches the app's quit flow while any modal or picker is open, and that path cannot skip a guard that already existed.

## Changes
- **`tldw_chatbook/app.py`**: `Binding("ctrl+q", "quit", "Quit App", show=True, priority=True)`.
  - Root cause: TldwCli's entry replaced Textual's own priority `ctrl+q`, and non-priority app bindings are inert under modals.
- **`tldw_chatbook/app_lifecycle.py`**: module-level `_quit_confirmation_screens(app)`.
  - It returns the active screen, then, only if that screen is modal, each screen beneath it down to and including the first non-modal screen.
  - `_confirm_and_quit` calls `confirm_quit` on each of them, top first; a False answer stops the quit and resets `_quit_in_progress`. It later calls `prepare_for_quit` on the same list.
  - With no modal open, the list is `[app.screen]`, so behaviour there is unchanged.
  - It is a module function so that harnesses borrowing `TldwCli._confirm_and_quit` need no new attribute.
- **`tldw_chatbook/Widgets/confirmation_dialog.py`**: `confirm_quit_discarding_edits(screen, message)` pushes a ConfirmationDialog ("Discard changes and quit?" / Keep editing / Discard and quit) and returns True only for Discard. It awaits the dialog, so it must run in a worker; the quit flow is one.
- **Dirty-guarded modals**: each answers `confirm_quit` only where its own close guard would fire.
  - `reminder_form.py`, `automation_definition_form.py` and `console_library_access_modal.py`: on `_dirty`.
  - `console_prompt_queue_modal.py`: on `has_unsaved_edit()`.
  - `console_prompts_modal.py`: on the new `_holds_dirty_edit()`, which the close and back paths now share.
- **`console_session_switcher_modal.py`**: the authority poll returns early while the switcher is not the top screen, instead of a bare `dismiss()` popping the quit prompt. The poll repeats, so it closes once it is on top again (ADR-031).
- **`splash_screen.py`**: docstring updated. Ctrl+Q mid-splash now quits instead of dismissing.
- **Docs**: User Guide `index.md` (Ctrl+Q row says what is asked about), `settings.md` (splash exception), `schedules.md` (form prompts). ADR-031 has a task-33622.10 refinement; `ctrl+p`, `f1` and `f6` stay non-priority.

## Implementation Notes (TASK-33622.10, whole branch: fb126339cd, 5a6c4e7fe2, 3e5483b782, 2d7674b66c, 7217eced4d)

**Summary.** Ctrl+Q now quits from under any modal, and the quit flow can neither hang nor crash the app when a prompt it shows is popped out from under it.

**1. Ctrl+Q reaches the quit flow under modals (fb126339cd)**
- The cause: `TldwCli` rebound `ctrl+q` without `priority=True`. That replaced Textual's own priority binding, and a non-priority app binding is never reached past a modal, so every modal swallowed the key. It is now `priority=True`, with an ADR-031 comment.
- Under a modal, `app.screen` is the modal. So the quit flow now asks every screen from the modal down to the topmost non-modal screen for `confirm_quit` and `prepare_for_quit`. With no modal open, that list is just `[app.screen]`, as before.
- A second Ctrl+Q while the prompt is up is still ignored.
- Ctrl+Q during the splash now quits in one press.

**2. Dirty modals ask before quitting (5a6c4e7fe2)**
- Five modals guard their own close with a discard prompt: ReminderForm, AutomationDefinitionForm, ConsolePromptsModal, ConsoleLibraryAccessModal and the ConsolePromptQueueModal edit view. Each now answers `confirm_quit` with a shared "Discard changes and quit?" prompt (`confirm_quit_discarding_edits`).
- ConsolePromptsModal's guard condition is now one `_holds_dirty_edit()`.
- The switcher's authority poll no longer dismisses while it is covered.

**3. One choke point for quit prompts (3e5483b782)**
- Every prompt the quit flow owns goes through `await_quit_prompt` in `Widgets/confirmation_dialog.py`: the Console-loss prompt and the workflow prompt (both via `TldwCli._await_quit_prompt`), the discard-and-quit prompt, and Settings' theme prompt.
- How it waits: it pushes with `wait_for_dismiss=True` and awaits the answer directly. Only "is the prompt still on the stack?" is polled, every 0.1 s, plus a 0.1 s grace for an answer still in flight.
- If the prompt leaves the stack unanswered, it returns the caller's Stay / Keep editing value, logs the prompt's class name, and shows "Quit cancelled." (quit path only).
- The quit walk moved into the same module, which is already loaded at boot, so the ADR-097 boot census doesn't grow. app_lifecycle.py is back to 2,140 lines against a 2,140 budget.

**4. A covered modal's close can't crash the app (2d7674b66c)**
- `SafeModalDismissMixin.dismiss` refuses while the modal is covered or already popped (ADR-031: only the top screen may be dismissed). Mixin modals, including the switcher and the video player, therefore can't pop the prompt.
- The video player's time box waits while covered and closes on its first tick back on top.
- For plain modals, `await_quit_prompt` finishes the close that went astray, so no screen is left on the stack with its result already spent (a second close would raise `InvalidStateError` and exit the app).
- Settings' theme prompt fails closed: only an explicit Discard drops the edits.
- `Tests/Architecture/test_quit_flow_prompt_choke_point.py` statically enforces the choke point, with negative controls.
- `test_quit_prompt_vanish.py` joins the UI PR gate; the floor goes from 118 to 119.
