## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in the PR #3458 review of TASK-33628.20 (2026-11-12). `/stream-video <url>` takes its text only after URL resolution: an egress-gated redirect walk, a yt-dlp fallback and a seekability probe, all awaited in a thread. Until resolution finishes, Ctrl+Q and tab close still ask about the command text. A re-send can also race it, the same way the review found for /doctor, which TASK-33628.20 then fixed by taking first. Unlike /doctor, /stream-video can fail ("Cannot stream that URL"), and that text must stay so the URL can be corrected. Taking it first therefore needs the take-then-restore pattern that /generate-video uses (`take_command_draft`, then `restore_command_draft` and `with_resend_hint` on failure), not a plain move.
