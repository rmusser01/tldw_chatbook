## Description

TASK-34100.4 made a saved key that is still `enc:` ciphertext read as absent, so its provider is never Ready. Readiness already knows why: its reason for that case is "Saved API key is still encrypted". No screen shows that reason. A local provider (llama.cpp on 127.0.0.1:8181) whose saved key is stranded reads only "Not ready · no key" in the Console header, "key missing · change it in Settings ▸ Providers & Models" and "Add or verify the llama.cpp API key to continue." in Chat settings, and "Key check: Not ready · no key" in Settings ▸ Providers & Models. On that same page the API key row says "No credential required · not required · this provider needs no key", which contradicts the key check beside it. Nothing tells the user that a key is saved but cannot be read, or that re-entering or clearing it fixes the provider.
