## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Rider from TASK-33001.6 (review fix round 1). TASK-33001.6 rewrote two tests in `Tests/ProductionApp/test_provider_selection_ownership.py`: the AC#2 palette test and the Settings-save test. Its review said CI's unwrapped run is the final word on them. It is not. No run outside a scratch copy executes their assertions.

- **Run on its own**, the file does not collect. The directory conftest rewrites `TLDW_CONFIG_PATH` at import, so the module-scope `import tldw_chatbook.app` raises ADR-126 `RecoveryRequired: raw_source_selection_changed`. The same collection error hits 14 of the ProductionApp modules.
- **In CI collection order** (`pytest Tests --ignore=Tests/UI`, where the app is imported before this conftest loads), the file collects. All 3 tests then fail in `_production_app` setup: `SettingsConfigAdapter.save_values` returns False, and the log says `Configuration mutation failed (phase=lock, ..., error_type=RecoveryRequired)`. The per-test profile redirect no longer matches the config selection bound at collection.
- **Both failures are pre-existing.** They are identical at fb8fc1854d (the old test names) and at c902f34b69.
- **A fix was tried in scratch.** Adding `pytestmark = pytest.mark.bootstrap_profile` (the TASK-32873 per-node opt-in in `Tests/conftest.py`) made all 3 pass in CI order.
- **Open question before adopting that fix:** the bootstrap profile is shared by every `bootstrap_profile` test in a worker. These tests persist `chat_defaults` and `api_settings.*` to it, so a later test in the same worker could see those values.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Phase 9, plan Task 14 (Wave 5); base 0af11c2871.

**Both failures reproduced at the base.** Alone: `ERROR ... RecoveryRequired: raw_source_selection_changed` at collection. In the Core Tests job's collection order (`pytest Tests --ignore=Tests/UI -k test_provider_selection_ownership --continue-on-collection-errors`, serial, the whole tree collected first): all three tests failed in `_production_app` setup, `save_values`/`save_sections` returned False with `Configuration mutation failed (phase=lock, ..., error_type=RecoveryRequired)`.

**Two causes, two fixes.**

- `Tests/ProductionApp/conftest.py` re-pointed HOME, USERPROFILE, the XDG roots and `TLDW_CONFIG_PATH` at its own temp tree when imported. `Tests/conftest.py` already points them at its sandbox before anything imports the app, so any app import after the re-point (every run that names a ProductionApp file, which loads the conftest first) failed with `raw_source_selection_changed`. The conftest now sets only `TMPDIR` (kept, unchanged) and its catalog-refresh fixture. Measured with the old and the new conftest and nothing else changed: the 17 ProductionApp files as files (xdist) went from 6 passed / 79 errors to 31 passed, and no test that passed before fails; most of the rest still fail locally in their bodies with `RecoveryRequired` (the known local noise, recorded in the lesson). A Tests/UI file named beside this file went from 2 collection errors to 13 tests collected.
- The three tests save `chat_defaults` and `api_settings.*` through the real config writer from inside the per-test sandbox, whose path no longer matches the selection bound at collection. Each is now `@private_profile_test`: it runs in its own pytest child with a fresh profile selected before the child imports anything.

**AC#1.** In the Core Tests collection order, at the head: `3 passed, 18 skipped, 94284 deselected, 8 errors` (the 8 are local collection errors of other files, identical at the base: missing `tldw_chatbook.Chat.console_thinking`, `Evals.source_reader`, `fido2`). Alone: `3 passed in 28.76s`. Negative control (one run, reverted): with the Switch model apply notice changed to "This chat changed" in chat_screen.py, `test_real_console_change_model_command_opens_real_picker` failed in its child on its own assertion (`assert 0 == 1`, `notifications.count('This chat updated')`) and the other two passed.

**AC#2: the isolation keeps each test's profile private.** `private_profile_test` gives each case `tmp_path/private-profile-process/profile` (created fresh, mode 0700) as `TLDW_TEST_CONFIG_ROOT`, HOME, the XDG roots and `TLDW_CONFIG_PATH` of its child, so what a test persists lives in that test's own directory and process; nothing is written to the shared bootstrap profile. `bootstrap_profile` (the fix tried in scratch) was not used for that reason.

**Lane.** The file now runs on every pull request: the PR Fast Lane's sandboxed step (`FAST_LANE_TARGETS` and derived-artifacts.yml), which the conftest fix makes safe to share an invocation. 3 of 3 serial in the lane's install set (a scratch blocker hid every package outside `-e . pytest pytest-asyncio pytest-timeout packaging`, plugins loaded as the lane loads them), in one invocation with `Tests/Backup_Recovery/test_skills_recovery_controls.py`, which joins in the same block: `16 passed` in 69.9 s, 67.1 s and 69.5 s; this file's three cases took 30.8 s, 29.4 s and 30.0 s. The whole sandboxed step in lane order (98 targets, serial, same install set) passed all three (39.6 s with the admission step running beside it).

**Lesson.** The TASK-33008 entry in backlog/docs/lessons-testing-evidence.md that warned about this conftest now says it no longer re-points the profile, with the measurement. Two later entries gained a sentence each: the TASK-33001.5 entry's advice to keep Tests/ProductionApp out of a combined run now says that is needed only for a scratch tree from before this change, and the TASK-33001.6 entry now says this rider chose `@private_profile_test` over the `bootstrap_profile` fix it tried in scratch.
