## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while fixing TASK-33621.6 (2026-10-29). An ordinary Console composer send freezes its staged-evidence decision (preserve_composer, TASK-34352) as frozen with nothing staged, and the dispatch checkpoint then records evidence_reconstructable=false (console_chat_controller reconstructability; console_native_commit likewise). Every unknown-delivery panel for such a send therefore shows Retry anyway disabled ('Retry response is unavailable because one-shot prefill or transient evidence cannot be reconstructed exactly.'), leaving Discard as the only action. Seen live on the fix branch: a SIGKILL mid-request, relaunch, checkpoint reconstructability_json had evidence_reconstructable false with no evidence staged; the mounted TASK-33621.6 harness shows the same. The TASK-33621.6 review recorded Retry anyway working on an earlier build.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
2026-11-21, branch fix/task-33621.6-retry-capture-regression (with TASK-33621.6), base origin/dev dc371f0842.

- Cause: since TASK-34352 every received composer send freezes its staged-evidence decision (`staged_evidence_capture` is always passed, console_received_dispatch.py), and the dispatch-path snapshot reports frozen too. Both reconstructability sites (`console_native_commit._controller_accept_durable_turn` and the temporary-chat registration in `console_chat_controller`) read `staged_evidence_frozen` as "evidence was used". So `evidence_reconstructable` was false for every send, and Retry anyway was disabled.
- Fix: only a carried evidence lease (`prepared_continuation.staged_evidence is not None`) makes a send unreconstructable. With nothing staged the request carried no staged evidence (`_capture_frozen_rag_context` returns nothing for a missing lease), and the restart retry (`_resolve_dispatch_retry_context`) never reads live staged evidence, so a retry cannot pick up evidence staged for the next message. console_received_dispatch.py is unchanged.
- Tests:
  - New `Tests/Chat/test_console_durable_turn_fix_round1.py::test_frozen_nothing_staged_keeps_checkpoint_reconstructable[False|True]` covers the durable and temporary-chat checkpoints. Both are red on dev (`False != True`) and green on the fix.
  - `test_explicit_frozen_evidence_makes_checkpoint_unreconstructable` (AC#2) stays green on both.
  - `Tests/UI/test_console_trace_recovery_after_provider_error.py::test_retry_anyway_redispatches_a_genuine_unknown_delivery` (AC#1, AC#3) is red on dev (button disabled) and green on the fix: 2 POSTs and the reply.
