## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Represent prepared provider requests as references to saved semantic revisions plus provider-only artifacts, normalized request headers, and persistent surface nodes instead of copying ordinary conversation content.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Prepared requests carry typed provenance for saved semantic revisions, provider-only artifacts, and explicit omission reasons through every supported request-building path.
- [x] #2 Ordinary saved message content is represented by revision references and is not serialized again into normalized trace payloads.
- [x] #3 Provider-only content is stored once by content address and bound per semantic revision and materialization policy.
- [x] #4 Mandatory credential filtering and content-free failure markers run before the first content-bearing artifact, header, surface, event, response, or diagnostic is persisted.
- [x] #5 Persistent surface nodes encode a head plus bounded predecessor and replacement ranges without storing repeated source lists.
- [x] #6 Normalized headers preserve provider, model, parameters, tool declarations, RAG or project context provenance, and transformation metadata needed to reconstruct what was dispatched.
- [x] #7 Equivalent materializations reuse artifacts while policy changes and omissions remain explicit and auditable.
- [x] #8 ADR required: yes; this task implements the provenance and storage boundaries in ADR-097.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
