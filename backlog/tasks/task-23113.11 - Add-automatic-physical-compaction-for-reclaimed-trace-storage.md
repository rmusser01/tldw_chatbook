## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Convert logical trace reclamation into bounded physical SQLite file shrinkage without blocking active conversations or invalidating reachable trace history.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

<!-- AC:BEGIN -->
- [x] #1 Automatic compaction runs only after successful logical garbage collection and according to explicit free-page, database-size, activity, and retry thresholds.
- [x] #2 Compaction never runs inside an active write transaction and coordinates with concurrent Console persistence without corrupting or dropping reachable data.
- [x] #3 Interruption or failure leaves the database readable and retryable and records bounded operational diagnostics.
- [x] #4 The canonical pinned compaction fixture completes in five seconds or less and demonstrates physical file-size reduction after reclaimed trace data crosses the configured threshold.
- [x] #5 Shared fork history and current trace owners remain intact after compaction and database reopen.
- [x] #6 ADR required: no; this is the deferred physical-maintenance phase already decided by ADR-097.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented automatic same-file SQLite compaction after successful trace-graph GC. Admission now enforces configured database, freelist, ratio, provider-idle, activity, retry, maintenance-lease, WAL, connection-quiescence, and disk-space gates. Console dispatch pauses through both provider seams while all managed ChaChaNotes transactions drain and registered handles close; VACUUM runs on a private autocommit connection, then the database is reopened and integrity-checked before the exact lease is released.

Added the v64→v65 content-free compaction-status singleton, bounded retry/interruption diagnostics, Settings privacy projection, default configuration, user documentation, and a checksum-pinned 5 MiB fixture whose focused gate proves file shrinkage in at most five seconds. Fork-prefix lineage, both attached owners, and current call history are verified after compaction and reopen. Runtime work is deduplicated by trace graph epoch so an unchanged database does not accumulate periodic GC result rows; retryable attempts reuse their exact completed GC prerequisite. Progress callbacks use a pre-VACUUM metric snapshot and never query the active SQLite statement.

The repository-wide generated inventory run also exposed stale pins from previously merged trace-GC and Notes synchronization work. This change deliberately refreshes the exact dynamic-SQL target evidence, production-diagnostic inventory, compaction-table allowlist, and missing trace-retention expression-index census; the fixed target sets are now closed by literal producers and their owning Notes, Sync, and Personal Context tests remain green.
