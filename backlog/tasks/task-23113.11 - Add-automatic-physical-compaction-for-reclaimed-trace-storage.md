## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Convert logical trace reclamation into bounded physical SQLite file shrinkage without blocking active conversations or invalidating reachable trace history.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] Automatic compaction runs only after successful logical garbage collection and according to explicit free-page, database-size, activity, and retry thresholds.
- [ ] Compaction never runs inside an active write transaction and coordinates with concurrent Console persistence without corrupting or dropping reachable data.
- [ ] Interruption or failure leaves the database readable and retryable and records bounded operational diagnostics.
- [ ] The canonical pinned compaction fixture completes in five seconds or less and demonstrates physical file-size reduction after reclaimed trace data crosses the configured threshold.
- [ ] Shared fork history and current trace owners remain intact after compaction and database reopen.
- [ ] ADR required: no; this is the deferred physical-maintenance phase already decided by ADR-097.
