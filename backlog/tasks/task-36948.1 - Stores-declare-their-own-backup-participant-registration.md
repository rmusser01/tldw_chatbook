## Implementation Plan

1. Add stdlib-only `DB/backup_participant_registry.py`: `@declare_store(owner_id, closer=, thread_cache=, policy=, read_only_policy=, finite_worker=, shared_connection=)`. The exact-type table is replaced on each declaration (under a lock), never rebuilt per call.
2. Decorate the 24 store classes with values that reproduce dev's tables exactly: dev's `run_finite_local_worker` closers table omits four stores that the pause table closes, so those four declare `finite_worker=False` (behaviour kept; the disagreement is now visible on the store). The service-cache lookups move into their stores as `thread_cache`; the two one-connection stores declare `shared_connection=True`.
3. `participants.py` reads the declarations and keeps no type list, closers tables, policy chain or owner-id sets. A scratch script checks the declarations against dev's tables.
4. Tests in `Tests/Architecture/test_participants_public_names.py` (arch PR lane): frozen declared set (static scan + runtime), no store table or store import in participants, one table across a real connection access. Show each red at base 5ca7ec6a03.
5. Re-point the one subprocess test that relied on `repository_types()` importing 13 store modules; raise the four ratcheted store rows by the +2 declaration lines.

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Each of the 24 participant stores now declares its own registration with `@declare_store(...)` from the new stdlib-only `DB/backup_participant_registry.py`, in the DB layer so stores in DB and in feature packages import it without an upward edge. `Backup_Recovery/participants.py` reads those declarations and no longer holds a type list, either closers table, the policy if-chain, the service-cache owner branch or the two shared-connection owner sets. It imports no store module.

- **Same behaviour as dev.** A scratch check compared the live declarations with dev 5ca7ec6a03's tables and found them equal: all 24 types, the finite-worker closers, the pause closers including service caches, `policy_id` for read-only and writable participants, and the shared-connection set. dev's two closers tables disagree: `run_finite_local_worker` never closes agent_runs, rag_indexing, library_ingest_jobs or notes.file_notes. The task did not ask to change that, so those four declare `finite_worker=False`. The difference is now visible on each store instead of hidden between two tables (see the follow-up in the report). A previous attempt had silently merged the two tables, which would have made finite workers close four more stores.
- **Declarations:** `closer` (a method name), `thread_cache` (a store-local lookup of the calling thread's cached connection; it replaces participants' reads of `_connections`, `_held` and `_thread_local`), `policy`, `read_only_policy` (Subscriptions' agent-read policy as data, not a callable), `finite_worker` and `shared_connection`.
- **AC#4:** `repository_types()` returns `registry.types`, a read-only table that is replaced (under a lock) on each declaration and never rebuilt per call. dev rebuilt it at least 3 times per `get_connection`. Iterating it is safe while other stores load.
- **One side effect:** a type is in the table only once its module has loaded, as dev's 11 optional types already were; dev imported the other 13 itself. `test_exact_type_imports_and_ordinary_constructors_do_not_load_engines` relied on those imports: probed in its own fresh-process setup, `repository_types()` held 0 types, so the test checked nothing. Its script, and `Tests/Performance/_stock_private_app_creators.py`, now import those 13 modules themselves. The script also asserts at least 13 types. Lesson added to `lessons-testing-evidence.md`.
- **Size ratchets:** ChaChaNotes_DB, Client_Media_DB_v2, Prompts_DB and Subscriptions_DB each grew by 2 lines (the import and the decorator). Their rows went up by 2, with a dated comment.
- **Tests** (`Tests/Architecture/test_participants_public_names.py`, arch PR lane): `test_declared_store_set_is_frozen` scans the source for decorators and checks the classes at runtime. `test_participants_keeps_no_store_table` checks for owner or policy literals and store imports. `test_registration_table_is_built_once_not_per_connection_access` uses a real LibraryCollectionsDB transaction. Red at base 5ca7ec6a03 (the test file copied into a base worktree): `assert {} == {...24 stores}`; the no-table check found the owner and policy literals in participants; `repository_types() is table` failed because a new dict comes back per call. All three are green here.
- Files: `DB/backup_participant_registry.py` (new), `Backup_Recovery/participants.py`, 24 store modules (import and decorator; plus a `_thread_cache` in the writing, research and event-state modules), the three test files above, `test_module_size_ratchet.py`, and `lessons-testing-evidence.md`.
