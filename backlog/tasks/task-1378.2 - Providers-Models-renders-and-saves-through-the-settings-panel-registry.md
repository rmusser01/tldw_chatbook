## Implementation Notes

Providers & Models is served by its registered panel: settings_screen.py has no comparison left that names it (enum member or string id), pinned by `test_categories_served_by_their_panels_have_no_comparison_left[PROVIDERS_MODELS]` (and `[NETWORK]`). Two commits: the six-member move with the save arm (22dd4c4f14), then the remaining arms through optional panel members (this commit's notes are under "Optional members").

**Pins first (AC#2).** Commit 51aa0b120a, alone, green at 8b0bca88cb (25/25 in the census file) and unmodified after the move (25/25). In `Tests/UI/test_settings_state_line_unsaved_count.py` (census), `@private_profile_test`, real screen: commit model and copy (badge, both scope lines, guided copy, `s`/`r`/`t` support and footer hints, dirty banner without "revert with r", snapshot preferences count as unsaved, save_state keeps the draft); a typed model marks the rail `*`, banner and Inspector status, the quit prompt names the category, a hop away and back keeps it with no prompt, and opening is clean; `s` pressed through the pilot reaches a writer patched on `settings_screen`; a failed save keeps the draft and `r` asks (Keep editing keeps it) then discards and repaints; nothing-unsaved `s` and `r` say so; with the real writer, a model typed back to the first-shown value after a save is staged (rail `*`, quit guard) and written.

**Move.** `ProvidersModelsPanel` in `UI/Settings_Modules/category_panels.py`, registered in `CATEGORY_PANELS` (round 1: the six required members). `render` delegates to `SettingsScreen._render_provider_detail` (unchanged, so every control's mount handling is unchanged); `has_unsaved_changes` is the draft or the snapshot preferences; `request_save` is the save arm moved verbatim (`self`->`screen`); `revert` is the screen's P&M `r` path (reload preferences when they are unavailable and nothing is unsaved, else confirm); `discard` (panel-only helper, not a Protocol member) is `_revert_category`'s P&M arm; `scope_text` gives today's banner scope and the guided-copy fall-through. The screen lost the save arm, the revert-action and `_revert_category` arms, and its unsaved, scope and render arms. `providers_models_card.py` was not used: its size row says new code goes in a sibling module.

**Patch reach (Review Focus 1).** The panel imports the screen-level names it uses from `settings_screen` at call time, the same principle as `_settings_config_adapter()`, so `monkeypatch.setattr(settings_screen, "persist_provider_settings_atomic", ...)` (four files) still reaches the save; settings_screen keeps that import as a marked re-export. Names no test patches there (and settings_screen no longer uses) come from their home modules.

**Tests changed.** Five tests called `screen._revert_category(PROVIDERS_MODELS)` directly; they now call `PROVIDERS_MODELS_PANEL.discard(screen)` (the same post-confirmation discard): field_guide_in_view, custom_endpoint_default, llamacpp_consumers, console_provider_apply_defaults_flow, provider_select_out_of_options.

**Red evidence** (temporary edits, all reverted; `-k "providers_models or registered_panels"`, 8 tests): badge -> "Pending — save with s": 4 failed; panel unsaved -> False: 5 failed; panel save does nothing: 4 failed; discard keeps the draft: 1 failed (`assert True is False`); writer imported from its home module instead of settings_screen: 2 failed (the patched writer never called); the model Input's mount echo staged as an edit: the clean-open assertion fails (`assert True is False`).

**Optional members (TASK-1378.2 round 2; the remaining-categories follow-up designs against these).** On `SettingsCategoryPanel` in `UI/Settings_Modules/category_panels.py`; every registered panel (Network, Providers & Models, the Speech adapter) now subclasses it, so the defaults are inherited. Each default is the answer the screen gives an unregistered category, so Network and Speech behave as before.
