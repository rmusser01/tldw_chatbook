## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Setup can start two large downloads, the 1.1 GB OmniVoice voice service and the 633 MiB Parakeet dictation model, and nothing owns them. A Speech download has no Cancel, speed or time left, and the status above the bar still reads 'Not installed.' Pressing Next lets it run on silently, the tracker marks Speech ✓, and when it finishes the model never becomes the dictation default. Killing the app mid-download leaves a 120 MB partial that earns no credit, so the retry starts from zero. Starting both installs fails the second as 'busy', and the message names the wrong model. The install review opens with an internal ticket id and hashes, while the facts a newcomer needs (size, location, licence) are scattered. A first-time user can't stop a 600 MB download they didn't mean to start. A power user's finished download quietly does nothing.

This implements enabler E-c (shared download coordinator) from the review report, Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md (§5.2): one job owner shared with Lab ▸ Models, with resumable staging, progress, cancel and ETA, a guard when the user leaves mid-download, and completion applied through the step's own commit. Resolves: [voice-speech-09] [voice-speech-10] [voice-speech-08] [voice-speech-11] [voice-speech-18].

Coordination: task-33079 (verify concurrent Parakeet and OmniVoice installs, To Do) is related, and its premise needs updating: concurrent installs do not race. They serialize through the single global acquisition session lease, so the second fails fast as busy. This task's concurrency test should close or rewrite its ACs. The progress widget, install-plan panel and acquisition layer are shared with Lab ▸ Models, so every fix here lands there too.

**Approach**
- **Cancel (AC#1).** Cancellation is cooperative, never a thread kill. A host builds a `DownloadControl` (`Model_Artifacts/download_control.py`: label, `wait_if_busy`, a `threading.Event` cancel switch) and passes it to `provision(control=...)`. On the worker thread's own event loop (`Worker.cancel()` cannot reach an `asyncio.run()` inside a thread worker), a watcher polls the switch every 0.1 s and cancels the session task at its current await; `stream_fetch`'s `finally` closes the HTTP stream. While the session lease is still held, every stage the run touched is removed (`ModelArtifactService._discard_download_stage_for`, added to the provision-continuation allowlist), and `AcquisitionCancelledError` reports what was kept. A cancel that arrives during install or activate is deferred, so the run never reports a promotion that half-happened.
- **Queue (AC#3).** `provision()` still serialises through the one global session lease. A control with `wait_if_busy` retries the lease every 0.5 s and emits a `queued` progress event naming the in-process holder, which is recorded in `active_acquisition()`. Without it, `AcquisitionBusyError.holder_label` names the holder. The busy copy now names the model actually downloading, or says "Another model download is already running" when the holder isn't known; it no longer names the caller's own model. Both wizard steps queue.
- **Mid-file resume (AC#4).** `stream_fetch` fsyncs every `FETCH_CHECKPOINT_BYTES` (8 MiB), but only when the response carries strong validators, and reports the durable length. `_fetch_one_file` writes it to the fetch-state sidecar with `complete: false`. The existing preflight credit and Range-resume path (`_reconcile_durable_bytes` truncates to the checkpoint) then just work. When a stage holds bytes, the review says "A previous download stopped at X of Y MiB" and its confirm button reads **Resume download**. HF verified: the pinned Parakeet v2 encoder URL redirects to `us.aws.cdn.hf.co`, which answers `206` with `content-range` and a strong ETag (`g14v3-recheck/01`). With weak or no validators, no checkpoint is claimed and the retry restarts honestly.
- **Speed/ETA and the shared widget (AC#1).** Pure helpers in `model_browser_state.py` do the work: `TransferRateEstimator` (an 8 s sliding window, no estimate under 1 s, reset on a new phase or a backwards count), `transfer_summary`, `format_time_left`, `waiting_for_copy`. `ModelInstallProgress` shows "X of Y MiB · speed · time left" for every host (Lab ▸ Models, Library, wizard). A host that passes `cancellable=True` gets **Cancel download**, shown during queued, fetch and pre-verify. The Speech status line comes from `first_run_speech_step_state.speech_install_status` / `speech_not_installed_status`. The GGUF button is now also gated on `_lifecycle_pending` (Language and Precision already were).
- **Install review (AC#5).** `ModelPlanPanel` is now a container. A summary leads with Download, "Installs to: ~/… (N GiB free)", and licences per component ("CC-BY-4.0 (speech model) · MIT (voice-activity detector)"), followed by terms and the resume line. A collapsed **Details** section holds source, revision, licence, **Licence text:**, precision, "1 file"/"N files", provenance, destination and staging. SPDX ids render canonically (`display_license`). Decision: the plain-words component copy (and hiding the "…recorded by TASK-593" notice) lives in the display layer (`component_copy`), not the descriptors. `usage_notice` is persisted in installed manifests and hashed into the stage name, so rewording it would orphan in-flight partials and make existing installs look foreign. Two tests pin the copy keys and frozen notices to the descriptors.
