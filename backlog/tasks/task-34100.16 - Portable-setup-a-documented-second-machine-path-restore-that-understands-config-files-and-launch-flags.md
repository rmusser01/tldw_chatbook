## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A power user setting up a second machine has no supported path. The only import on Welcome, 'Restore a backup', opens on 'Create backup' and never names the archive format. Given a config.toml, it fails with an opaque 'backup_operation_failed', and 'Create backup' stays disabled with no reason shown. What does work is undocumented anywhere a user looks: copy a finished config.toml (with its [first_run] keys) plus env keys, or point TLDW_CONFIG_PATH at one, and the app boots straight to Console. The CLI has no --config or --no-splash flag. In the review, the power user could not produce an archive in the time allowed and found the working route only by experiment.

This implements the right-sized second-machine contract (§2(c)) and step 1 of enhancement E6 from the review report, Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md (§5.4): docs first, then --config PATH and --no-splash, then a restore entry that names the format and recognises a settings file. Resolves: [entry-exit-handoff-16] [coverage-10].

Out of scope, per the verifiers: the full headless 'tldw-cli setup --non-interactive' flow is deferred to TASK-34100.17. An 'Import settings from config.toml' flow with a diff preview carries secret-handling risk and needs its own task. Coordination: task-32562 (In Progress) owns backup and restore across platforms. The restore-screen changes here (Inspect entry mode, format hint, TOML and folder pre-check, the reason Create is disabled) should land with it or on top of it.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** One launch can now run against a copied config (`--config PATH`) and skip the splash (`--no-splash`) through both `tldw-cli` and `python -m tldw_chatbook.app`. `--help` ends with a note that names `TLDW_CONFIG_PATH`, the "Setting up another machine" guide section, and that a copied config carries its saved keys. Setup's **Restore a backup** now opens on Inspect, titled "Restore from a backup". The Inspect pane names the archive format, and the pane recognises a config.toml or a folder before inspecting. A disabled **Create backup** says why on the line above it. The User Guide has the second-machine section. AC#4 is not ticked: Create backup cannot produce an archive on fresh profiles, on base too (reason below).

**Approach and decisions**
- `tldw_chatbook/Utils/launch_options.py` (stdlib plus `profile_paths` only) now owns the one tldw-cli parser. It moved from `app_entry._build_arg_parser`, which now delegates to it.
  - `--config` sets `TLDW_CONFIG_PATH` for this process and its children. That keeps one source of truth, which Settings already reads (it names the file an "override config"). The flag wins over an inherited value. The path is lexical and absolute, and a folder is a usage error (exit 2).
  - `--config` is adopted **before** the ADR-126 storage fence and the TASK-34100.4 startup unlock, so both admit and unlock the selected file.
    - In `cli.py` it runs after the recovery selectors; combined with `--recovery-profile` it is a usage error.
    - In `app.py` it runs under `if __name__ == "__main__"` ahead of `admit_startup()`. That costs +2 lines, putting app.py exactly at its unchanged 5712 row. Importing the helper only under `__main__` keeps the UI-ready census at 1033/1033.
  - `--help` is still answered after the fence: `Tests/Architecture/test_recovery_entrypoints.py` pins fence-before-help.
  - `--no-splash` reaches the instance through `apply_launch_options`, in both runners, and `TldwCli.compose` reads it (net-zero lines). Neither flag writes config or touches `[first_run]`.
- Restore from setup:
  - `BackupRestoreScreen(initial_mode="inspect")` opens on Inspect, titled "Restore from a backup", with focus in the archive field. `action_backup_restore(mode="home")` gained the argument with zero net lines in `app_lifecycle.py`, which is already over its row on base. The Welcome step and the Continue-setup dialog pass `"inspect"`. Settings' entry keeps the ordinary home.
  - Pure rules live in `backup_restore_state.py`:
    - `archive_source_problem` runs before any inspection. A `*.toml` gets "That's a settings file, not a backup archive." with the guide pointer and `tldw-cli --config <file>`. A folder gets "Choose the archive file, not a folder."
    - `create_unavailable_reason` now decides the Create button's state as well as the reason shown.
  - The reason goes on the existing message line directly above the buttons. Two rejected options:
    - A separate reason line cost two rows at 54x22 and pushed a focused checkbox out of the scroll body (caught by `test_backup_data_groups` narrow width).
    - A longer pre-review sentence wrapped at that width.
  - The pre-review copy is "Create backup unlocks after a successful Review." It returns after any form change.
- Scope kept as filed: no "Import settings from config.toml" flow, no headless setup (ADR-217 D11), and `tldw-cli --config X recovery` is not supported (the `recovery` subcommand is matched first, as before).
