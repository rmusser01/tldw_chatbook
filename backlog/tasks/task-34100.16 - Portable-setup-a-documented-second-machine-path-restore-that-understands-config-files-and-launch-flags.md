## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A power user setting up a second machine has no supported path. The only import on Welcome, 'Restore a backup', opens on 'Create backup' and never names the archive format. Given a config.toml, it fails with an opaque 'backup_operation_failed', and 'Create backup' stays disabled with no reason shown. What does work is undocumented anywhere a user looks: copy a finished config.toml (with its [first_run] keys) plus env keys, or point TLDW_CONFIG_PATH at one, and the app boots straight to Console. The CLI has no --config or --no-splash flag. In the review, the power user could not produce an archive in the time allowed and found the working route only by experiment.

This implements the right-sized second-machine contract (§2(c)) and step 1 of enhancement E6 from the review report, Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md (§5.4): docs first, then --config PATH and --no-splash, then a restore entry that names the format and recognises a settings file. Resolves: [entry-exit-handoff-16] [coverage-10].

Out of scope, per the verifiers: the full headless 'tldw-cli setup --non-interactive' flow is deferred to TASK-34100.17. An 'Import settings from config.toml' flow with a diff preview carries secret-handling risk and needs its own task. Coordination: task-32562 (In Progress) owns backup and restore across platforms. The restore-screen changes here (Inspect entry mode, format hint, TOML and folder pre-check, the reason Create is disabled) should land with it or on top of it.
