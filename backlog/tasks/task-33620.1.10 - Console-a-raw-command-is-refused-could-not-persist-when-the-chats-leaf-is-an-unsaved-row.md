## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Live 2026-11-23 on TASK-33620.1's branch at 9130078ee3 (evidence bd5/U04/r5-2026-11-23/40-55, real app, isolated profile, raw CLI unlocked and armed). During an emergency stop a '! echo hi' draft read Held and Enter was refused with a System row naming /emergency-stop clear, as the owner decision wants. After Clear the button read Run, but Enter was refused with 'Raw CLI could not persist this command locally. The exact draft was restored.' The same happened in a chat that had already run a raw command, and with a freshly typed command. A chat with no refusal row ran its command. In that chat a second raw command in a row was refused the same way, and on origin/dev 9418f179e3 (same profile setup, no stop involved) a second raw command in one chat was refused the same way too. Reading the code: `ConsoleRawCliController._execute` resolves the command's transcript anchor with `persisted_message_id_for_session_node(session, active_leaf)` and refuses when the leaf has no persisted id. A refusal's System row is never persisted, and in this scratch profile the raw marker was not either: the profile also logged 'run log: base directory escapes root; logging disabled' and 'Raw CLI persistence was incomplete'. So the stop's refusal row always blocks the next raw command in that chat, and the 'two in a row' case may or may not reproduce outside this profile layout. A likely fix is to anchor to the nearest persisted ancestor (`ConsoleChatStore._nearest_persisted_ancestor_id`), as ordinary persistence already does, but the raw path's anchor custody needs its own review.
