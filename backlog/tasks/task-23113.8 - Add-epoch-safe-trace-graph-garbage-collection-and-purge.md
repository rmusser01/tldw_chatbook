## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Reclaim unreachable trace graph data safely across conversation deletion, branch pruning, retention, migration, and concurrent reachability changes while preserving shared fork history.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] A schema-derived root/edge inventory covers calls and lifecycle links, segments and inherited boundaries, conversation visibility/ownership, retention, events, surfaces, bindings, locators, headers, artifacts, response links, and migration state.
- [ ] Every inventoried mutation that can change trace reachability advances the single global trace-graph epoch in the same transaction.
- [ ] Garbage collection marks from persisted conversation, fork, open-call, migration, soft-delete, and explicit retention roots and sweeps only when the exact marked epoch remains unchanged.
- [ ] Deleting one fork or owner never removes revisions, artifacts, surfaces, events, or calls still reachable from another owner.
- [ ] Conversation purge and retention expose explicit logical-reclamation results and are idempotent after interruption.
- [ ] A compaction-heavy adversarial fixture proves no reachable trace data is deleted under concurrent ownership changes.
- [ ] Privacy tests verify deletion or retention across every durable trace owner and projection.
- [ ] ADR required: yes; this task implements the reachability and deletion boundary in ADR-097.
