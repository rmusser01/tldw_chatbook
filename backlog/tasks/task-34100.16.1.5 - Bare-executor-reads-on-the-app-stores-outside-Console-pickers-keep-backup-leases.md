## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in TASK-34100.16.1's review round v5r2 (finding R2-1). An `asyncio.to_thread` (or `run_in_executor`) call that reads or writes the app's live ChaChaNotes or Media store leaves that pool thread's cached connection open. A backup's local pause cannot revoke such a foreign-thread lease (`participants.retire_current_thread_caches`), so after the user reaches one of these surfaces, an idle Create backup ends in `admission_timeout` until the app quits. `participants.run_finite_local_worker` is the fix: it retires only the caches the call itself opened.

TASK-34100.16.1 fixed the Library Notes paths, Console's retrieval-scope picker, the RAG FTS legs it scopes (`RAG_Search/pipeline_functions_simple.py`), and Console's dictionary and world-book pickers, each with a RED real-SQLite lease test and a structural guard. A heuristic census of the rest of `tldw_chatbook/` found 99 more executor offloads inside functions that touch `chachanotes_db`, `media_db`, `CharactersRAGDB` or `MediaDatabase`. Some already retire their own handle (for example `chat_conversation_scope_service`'s `list_and_close`, `console_conversation_hydration`'s `read`, the `app_lifecycle` quit paths), so each needs triage. That fixes every site at once, but it re-opens a connection per offloaded read, so it needs a latency measurement against the UI performance ratchets.
