## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Slice D1 of the approved reading desk (spec §5.1, §5.2, §5.5). Quotes and source lines in a note carry `[title](media://<media-uuid>)` and `[title, ¶n](media://<media-uuid>#p<n>)` links. Today nothing in the app can open them, and Preview hands unknown schemes to the operating system (finding N-08). This slice routes `media://` links inside the app, through the same router TASK-34000.11 adds for `note://`. A link opens the document at its paragraph. If the document changed, it heals by finding the quoted text. It also gives honest states for a source in Trash or not in this Library. MCP's existing `media://<integer-id>` resources keep their meaning.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Activating a `media://<uuid>` link in a note opens that Media item in the Library reader; with `#p<n>` it opens scrolled to paragraph n (paragraphs = blank-line blocks of the stored text, spec §5.2)
- [ ] #2 If paragraph n no longer contains the quote's opening words, the reader runs Find on them and says `Paragraph moved — found by text`; if nothing matches it says `Passage not found in the current version`
- [ ] #3 A link to a trashed item shows `In Trash · Restore` (ADR-055 seam); a link to an item not in this Library shows `Not in this Library — <title>` and offers nothing destructive
- [ ] #4 Integer `media://<id>` URIs used by MCP resources are unaffected (resolver unit tests cover UUID vs integer)
- [ ] #5 Regression tests (resolver unit tests + a real-app Pilot test that a link opens the right document at the right paragraph) fail on dev before the change
- [ ] #6 Verified live at 160x45 in an isolated profile
<!-- AC:END -->
