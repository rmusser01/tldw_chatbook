## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**User impact.** Quitting the app throws away unsent work without warning. On origin/dev @ 64579cce2c the reviewer had three things open: a Temporary chat with a reply (chip 'Temporary - not saved'), a saved chat with the unsent composer draft 'draft alpha unsent do not lose', and an 'Unsent turn needs attention' shelf. Pressing Ctrl+Q showed **no dialog**, and the UI was gone within 0.5 s. After relaunch, the Temporary chat was gone from the rail and the DB, the reopened saved chat had an empty composer, and the parked turn was gone.

**The warning that does exist undercounts.** When a run *is* live, the quit dialog 'Quitting Chatbook will cancel or discard:' lists only 'Live agent runs: 1 / Delegated agents: 0 / Sessions with queued prompts: 0 / Unsent queued prompts: 0'. It reports nothing for the draft and parked turn it is about to discard, so the zeros read as all-clear.

**Close and quit disagree.** Closing a single tab already warns 'Unsent draft: yes', 'Temporary or unsaved messages: N' and 'Pending attachments: N', and offers Stay. Quitting closes every tab and asks about none of these.

**Why it happens.** The quit guard in `app_lifecycle.py` reads `controller.lifecycle_impact()`, which counts only live runs, delegated children and queued prompts. `ChatScreen.confirm_quit` always defers to that guard. Drafts, pending attachments, unsaved Temporary messages and parked turn recoveries (`ConsoleRuntime._turn_recoveries`, memory only) never raise `has_loss_risk`, so quit proceeds. The tab-close impact (`ConsoleSessionCloseImpact`) does count drafts and attachments, but it also misses parked turn recoveries.

**Severity and prior art.** P1 (both findings).
- G4-11 is triaged NEW.
- GAP2-15 is triaged KNOWN_PARTIAL against TASK-14806 (Done), which guards queues across close, navigation and quit (AC#1, #7, #9) but never extended the guard to drafts, Temporary chats or parked turns.
- Not restoring open tabs is by design (ADR-033:184). Saved conversations stay reachable in the Chats rail. The real losses are drafts, Temporary chats, attachments and parked turns.

This subtask covers only the quit and close loss inventory. Persisting drafts or parked turns across launches would contradict ADR-033/098 and needs its own ADR, so it is out of scope.

**Suggested direction.**
- Build one loss projection per open session covering: unsaved transcript messages (includes Temporary chats), non-empty drafts (including the visible composer's live text), pending attachments, parked turn recoveries, and the existing live, queued and delegated counts.
- Use it filtered to one session for tab close, and summed for quit and fleet leave, so the two dialogs cannot drift apart again.
- Set `has_loss_risk` when any count is non-zero.
- Render only the non-zero rows, and name the affected tabs.
- Use the UI's own wording for parked turns ('Unsent turns needing attention').
- Add a note that open tabs are not reopened but saved chats stay in the Chats rail.
- Keep the aggregate content-free, per TASK-14806 AC#7.
- Keep the revision-pinned re-check loop in `_confirm_console_runtime_quit`.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G4-11, GAP2-15; qa/console-ux-review-2026-09-29/evidence/evidence__GAP2__57-quit-26tabs.txt, evidence__GAP2__59-relaunch-after-26tabs.txt, evidence__GAP2__45-paste10k-restore.txt; code: tldw_chatbook/app_lifecycle.py:2035-2061, tldw_chatbook/UI/Console_Modules/session.py:2904-2924, tldw_chatbook/UI/Screens/chat_screen.py:17116-17119.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Tab close and app quit now read one content-free loss inventory, so Ctrl+Q asks before it discards a draft, a Temporary chat, a staged attachment or a parked unsent turn, and the two dialogs cannot drift apart.

**Close (fix 1).** The per-tab projection and its dialog copy moved out of `session.py` into `UI/Console_Modules/loss_inventory.py`, which the close and quit paths import lazily (it stays off the boot path). `ConsoleSessionCloseImpact` gains `unsent_turn_count`, read from `ConsoleRuntime.recoveries_for_session`, and `has_loss_risk` counts it. One renderer writes only the non-zero rows. The close dialog's "Live agent turns" row is now "Live agent runs", the quit dialog's word for the same count. `session.py` shrinks from 7,000 to 6,921 lines, and its module-size ratchet row is lowered to match.

**Quit (fix 2).** `_confirm_console_runtime_quit` builds `console_quit_impact(runtime)`: the same `session_close_impact` for every open tab, summed by `ConsoleLossTotals.of`, so the quit totals equal the per-tab close impacts by construction. The visible composer's live text is read through `runtime.view`; any other tab's draft comes from the store. The fleet lifecycle revision is still pinned for the shutdown fence, and the re-check loop is kept; it now compares the whole inventory. The dialog lists only non-zero rows: drafts, Temporary or unsaved messages, attachments, "Unsent turns needing attention", live runs, delegated agents, queued prompts and pending decisions. It names up to five affected tabs, then "and N more", and adds the ADR-033 note ("Open tabs are not reopened next time. Saved chats stay in the Chats rail."). The old "Sessions with queued prompts" row is dropped, since "Unsent queued prompts" covers it. With nothing to lose, Ctrl+Q still quits without asking.

**Tests.** `Tests/UI/test_console_quit_loss_guard.py` has seven tests on the real TldwCli, ChatScreen, controller, store and ConsoleRuntime, pressing the real keys:
- a lone draft;
- a draft left in Console while Home is on screen;
- a Temporary chat with a parked turn;
- a lone attachment;
- nothing to lose;
- tab close naming the parked turn;
- quit totals equal to the sum of the per-tab close impacts.

On origin/dev (3efe8476ce, and again on b5150753eb after the final rebase), six of them fail with "Ctrl+Q quit straight past ..." or a missing row; the nothing-to-lose case passes on both. On the final head, all seven pass. The module-size ratchet and the UI-ready census fail on that head with exactly dev's own reds (eight rows; 1032 > 1031 with an identical module diff). `loss_inventory` is not resident at UI-ready. Unit cases were added in `test_console_session_close_impact.py`. The quit harness doubles were updated in `test_app_quit_guard.py` and `Tests/ProductionApp/test_workflows_session_lifecycle.py`.
