## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**User impact.** Quitting the app throws away unsent work without warning. On origin/dev @ 64579cce2c the reviewer had three things open: a Temporary chat with a reply (chip 'Temporary - not saved'), a saved chat with the unsent composer draft 'draft alpha unsent do not lose', and an 'Unsent turn needs attention' shelf. Pressing Ctrl+Q showed **no dialog**, and the UI was gone within 0.5 s. After relaunch, the Temporary chat was gone from the rail and the DB, the reopened saved chat had an empty composer, and the parked turn was gone.

**The warning that does exist undercounts.** When a run *is* live, the quit dialog 'Quitting Chatbook will cancel or discard:' lists only 'Live agent runs: 1 / Delegated agents: 0 / Sessions with queued prompts: 0 / Unsent queued prompts: 0'. It reports nothing for the draft and parked turn it is about to discard, so the zeros read as all-clear.

**Close and quit disagree.** Closing a single tab already warns 'Unsent draft: yes', 'Temporary or unsaved messages: N' and 'Pending attachments: N', and offers Stay. Quitting closes every tab and asks about none of these.

**Why it happens.** The quit guard in `app_lifecycle.py` reads `controller.lifecycle_impact()`, which counts only live runs, delegated children and queued prompts. `ChatScreen.confirm_quit` always defers to that guard. Drafts, pending attachments, unsaved Temporary messages and parked turn recoveries (`ConsoleRuntime._turn_recoveries`, memory only) never raise `has_loss_risk`, so quit proceeds. The tab-close impact (`ConsoleSessionCloseImpact`) does count drafts and attachments, but it also misses parked turn recoveries.

**Severity and prior art.** P1 (both findings).
- G4-11 is triaged NEW.
- GAP2-15 is triaged KNOWN_PARTIAL against TASK-14806 (Done), which guards queues across close, navigation and quit (AC#1, #7, #9) but never extended the guard to drafts, Temporary chats or parked turns.
- Not restoring open tabs is by design (ADR-033:184). Saved conversations stay reachable in the Chats rail. The real losses are drafts, Temporary chats, attachments and parked turns.

This subtask covers only the quit and close loss inventory. Persisting drafts or parked turns across launches would contradict ADR-033/098 and needs its own ADR, so it is out of scope.

**Suggested direction.**
- Build one loss projection per open session covering: unsaved transcript messages (includes Temporary chats), non-empty drafts (including the visible composer's live text), pending attachments, parked turn recoveries, and the existing live, queued and delegated counts.
- Use it filtered to one session for tab close, and summed for quit and fleet leave, so the two dialogs cannot drift apart again.
- Set `has_loss_risk` when any count is non-zero.
- Render only the non-zero rows, and name the affected tabs.
- Use the UI's own wording for parked turns ('Unsent turns needing attention').
- Add a note that open tabs are not reopened but saved chats stay in the Chats rail.
- Keep the aggregate content-free, per TASK-14806 AC#7.
- Keep the revision-pinned re-check loop in `_confirm_console_runtime_quit`.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 With no live run and nothing queued, Ctrl+Q shows a quit confirmation offering Stay whenever at least one of these exists: an unsent composer draft, an unsaved Temporary-chat message, a pending attachment, or a parked 'Unsent turn needs attention' recovery. With none of them present, quit proceeds without a dialog as it does today.
- [ ] #2 The quit dialog lists every non-zero loss category (drafts, unsaved or Temporary messages, pending attachments, unsent turns needing attention, live runs, delegated agents, queued prompts) and names the affected tabs. It shows no zero-count rows, and draft or message content never appears in it.
- [ ] #3 The tab-close confirmation also reports parked unsent turns. For any set of open sessions, the quit dialog's totals equal the sum of the per-tab close impacts for those sessions.
- [ ] #4 The quit dialog states that open tabs are not reopened on the next launch and that saved chats remain available in the Chats rail.
- [ ] #5 Choosing Stay leaves every draft, Temporary chat, pending attachment and parked turn intact and the app running.
- [ ] #6 A regression test drives the real quit path (the app quit action through the Console quit guard) on a real ChatScreen with a real ConsoleRuntime. With only a composer draft present it asserts that the confirmation appears; this test fails on pre-fix code, which exits with no dialog. A second case asserts that a Temporary chat with a parked unsent turn is counted.
