## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
A pick now counts as one edit, **Model**; what its rebase changes is re-based out of the unsaved guard's baseline instead of being counted.

- `console_settings_unsaved.rebased_unsaved_baseline(baseline, before, after)`: after a pick, every Apply-committed settings field (Endpoint, the generation fields, Streaming's Inherit/On/Off draft) that the user had not edited takes its rebased value as unedited; so does an edit the rebase did not carry (blanked because the new provider rejects it, AC#2, or replaced by the new pair's value). Only an edit the rebase carried keeps its old baseline, so it still counts. The pair's own baseline never moves, so the pick counts as Model against the opened pair.
- `ConsoleSettingsUnsavedGuardMixin._rebase_to_pick(provider, model)`: wraps the controller rebase for pick mode's result (`console_settings_field_row._model_picked` calls it instead of `_rebase_to`). It keeps each pair's baseline as a pick leaves it and gives it back when a pick returns there, because the rebaser restores that pair's remembered snapshot: back on the opened pair only its own edits count and Model does not. Use saved defaults still goes through `_rebase_to` and still counts what it changes. A credential round trip carries the current pair's baseline (unchanged path); the per-pair copies do not travel, so a pick back after one falls to the general rule.
- TASK-33003.10's guarantee holds: a Streaming pick after the switch is still named.
- Pin rewritten on purpose (name it in the PR): `Tests/UI/test_console_settings_unsaved_guard.py::test_credential_round_trip_keeps_the_restored_edit_unsaved[model]` asserted `{'Model', 'Streaming'} <= labels` under Qodo #2937's ruling that a pick's re-base of Streaming counts as an edit; this rider rules it does not, so it now asserts `labels == ('Model',)` (the [temperature] case still asserts `('Temperature',)`). The test is now a `@private_profile_test`, because it builds the production app's config and without a private profile it fails at `_build_production_app` with `RecoveryRequired: raw_source_selection_changed` under any runner (it did at base locally). It joins the UI PR census as a node entry (MINIMUM_FILES 351 -> 352). The node (both cases) passed 10 of 10 serial runs (`-p no:xdist --timeout=180`, scratch profile, 36-43 s each), the bar TASK-33003.21's closure set for it.
- New tests in `Tests/UI/test_console_settings_model_change.py` (whole file in the UI PR census), real pick gesture (Change, Find, Enter) and the controller's rebaser: `test_a_pick_alone_is_one_edit_named_model` (llama.cpp with Min P 0.05 picked to Anthropic: labels, title and Esc prompt name Model only; Min P was blanked) and `test_a_pick_keeps_the_edits_it_carries_and_drops_the_rest` (Temperature and Min P edited, pick Anthropic: Model and Temperature; then a Streaming pick is named; back on model-a: Temperature and Min P).
- Negative controls (source edits, reverted at once): with `_model_picked` calling `_rebase_to` again, all three fail (the [model] pin and both new tests: the prompt named Model, Endpoint, Temperature, Min P and Streaming); with the per-pair restore removed, the second new test fails on the return (`('Temperature',)`).
- Docs/User_Guide/console.md: the unsaved paragraph says a picked model is one edit and what the switch changes is not counted (it used to say Streaming's re-base counts).
