## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The root cause in TASK-33621.21 is app-wide. Inside the running app, sys.stderr is Textual's capture with fileno() == -1; the first tqdm bar (built even when progress bars are disabled) creates a multiprocessing lock, which on macOS starts CPython's resource tracker, raises 'ValueError: bad value(s) in fds_to_keep', and leaves tqdm's class lock held. The guard, allow_tqdm_without_stderr_descriptor(), runs only at the start of a dictation attempt. A download from another feature first (embeddings, TTS models, media transcription, Models screen installs) can still fail that way and wedge every later download in the process, Dictate's included until its guard repairs the lock.
<!-- SECTION:DESCRIPTION:END -->
