## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by reading during the TASK-33620.3 / TASK-33621.53 review (2026-10-29); not probed. TASK-33621.53 made an ordinary send whose durable commit fails before the store's reservation pause as PERSISTENCE, so its card and shelf can end it. That pause runs only for an ordinary native commit owner. In the agent background chat-start path the chat start takes ledger custody (accept) before the commit, so a commit that then fails in the store's preflight returns a refused result with no pause, and the chat start's final cleanup abandons the target preparation only when the start was not accepted. The target chat may therefore be left with a COMMITTING preparation that nothing ends, the same jam TASK-33621.53 fixed for ordinary sends. Confirm it on the real controller and store, and if it reproduces, release it without sending the turn twice.
