## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: TASK-34000.5 found that `load_settings()` builds its returned settings from a fixed dict literal. Any top-level TOML table not listed there is dropped, so every reader of that table silently gets its defaults. That is how the Media Analysis tab could never see `[analysis_defaults]`, for every user.

The guard added in that task (`Tests/test_config_load_settings_table_guard.py`) derives the tables the app reads from the code. It found 21 more tables that are read from the loaded settings yet dropped by the loader (19 on the first pass; TASK-34000.5's fix round 1 taught the derivation the `(app_config or {})` receiver and one level of import-resolved call-site propagation, which surfaced `model_capabilities`, `webhooks` and `web_server`, and moved `canvas` out of the register -- see the note below). They are pinned in its `PRE_EXISTING_DROPS` register, which can only shrink:
- `API`
- `AppRAGSearchConfig`
- `HiggsSettings`
- `OmniVoiceSettings`
- `app_tts`
- `chat`
- `custom_endpoints`
- `custom_openai_2_api`
- `encryption`
- `global_tts_settings`
- `home`
- `llm_management`
- `media_creation`
- `model_capabilities` (`UI/Screens/settings_context_memory.py:305`, the Settings screen's context-window state)
- `network`
- `provider_setup`
- `rag`
- `tldw_api`
- `transcription`
- `web_server` (`config.py:374` reached from `UI/Screens/settings_screen.py:6393`: the Settings screen builds its Canvas policy from `app_config`, so its view of `[web_server]` misses the user's table; the runtime policy reads the raw TOML)
- `webhooks` (`Agents/run_webhooks.py:317` reached from `Agents/agent_service.py:3882` via `webhook_config_from_settings(load_settings())`: **a configured run webhook never fires** -- the user's `[webhooks]` url, enabled flag and secret are all dropped before the reader sees them)

Also to check, outside the guard's register since fix round 1: `canvas` -- its only accesses on the loaded settings are `app_config.setdefault("canvas", {})` and a store (`UI/Screens/settings_screen.py:31700-31703`), which the guard does not count as reads; whether the user's `[canvas]` table is honoured there still needs the same finding as the rest.

Several change behaviour that matters:
- `webhooks`: a configured run webhook never fires today;
- `network`: TLS trust and `ssl_verify`;
- `encryption`;
- the TTS backends;
- the RAG service constants;
- custom endpoints.

A reader may also consult the raw TOML elsewhere, in which case the drop is harmless at that site. Each table needs that checked before it is carried through. For each table, decide whether the reader's user-set value was ever honoured, and fix the loader (or the reader) so it is. Carrying a table through can turn on behaviour users configured long ago but never got, so verify each one, and treat security-relevant tables (`network`, `encryption`) with care: a value that silently tightens or loosens TLS or encryption must be called out.
<!-- SECTION:DESCRIPTION:END -->
