## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`ConsoleChatController` exposes a settable `self.app` (assigned by the chat screen and the launch-wake path). It reads at least 18 app attributes and forwards the whole app into five helpers.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F1; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The controller holds no reference to the app object
- [x] #2 Every service it used through the app arrives through its construction
- [x] #3 No helper it calls receives the app object
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add `ConsoleControllerHost` (frozen dataclass): the members the controller uses, taken from `app.services`, plus narrow callables for UI capabilities and app state outside the bundle. Add one builder over an app, used by `ConsoleRuntime`.
2. `ConsoleChatController` takes `host=`, drops `self.app`, and reads members and callables from the host. Runtime-owned calls go through `_hooks_v2_runtime`. The five forwarded helpers get the host's members.
3. Configuration capture: `ConsoleRuntime` passes a capture callable over its own app. The stock-service identity proofs keep their semantics inside it, and the "controller.app was re-pointed" checks are deleted.
4. Remove `controller.app` reads from the helper modules (preparation, dispatch, recovery, wiring, prompt queue, spend projection, goal status). Remove the four assignment sites. Shrink `HeadlessAppContext` to the resume attributes and give mobile a host.
5. Tests: one shared factory derives a host from a fake app as production does. Convert the `controller.app` tests to it. Add guards: an AST check plus a runtime check that the controller has no app attribute, and an AST check that no module reads `controller.app`.
6. Verify: the Console suites, P0 gate, and mobile tests against base; boot ratchets; app-lookup census; Tests/Architecture (serial); preflight.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
**Shape.** `ConsoleChatController(..., host=)` takes one frozen `ConsoleControllerHost` (`Chat/console_controller_host.py`); `self.app` is gone, and an absent host is the module sentinel `_NO_HOST` (the old "no app"). The host holds:
- members taken from `app.services` (D1): `unified_mcp_service`, `workspace_registry_service`, `change_review_consent_service`, `chachanotes_db`, `local_character_persona_service`, `prompt_scope_service`, `subscriptions_db`, `local_watchlists_service`, `watchlist_bundle_service`, `library_rag_search_service`, plus `raw_cli_runtime` (rule 4, passed by the runtime);
- UI capabilities: `notify`, `call_from_thread`, `post_message`, `on_ui_thread`, `is_headless`, `console_attention`;
- readers of app state outside the bundle, read when used (rule 4/5): `read_app_config`, the lazy skills pair, settings-durability owner, new-chat default generation, the two on-mount watchlists services, `personal_context_service`;
- app-anchored operations: `send_refusal`, `capture_turn_configuration`, `project_index_service`, the two inspector-count publishers.
Members keep their alias names, so the duck-typed turn-context readers take the host where they took the app. `controller_host_for_app(app)` builds it (members from `app.services`; an app double without a bundle gets none).

**Construction sites.** `ConsoleRuntime.ensure_chat_controller` passes `host=controller_host_for_app(self._app, raw_cli_runtime=...)`; `set_chat_controller`, the launch wake and `attach_review_presenter` no longer assign `controller.app`. The review presenter is installed as `partial(present_code_review_original, app=app)`. Mobile builds an explicit host (store-less MCP service, registry, chat DB, direct `call_from_thread`); `HeadlessAppContext` shrank to the two attributes the resume helpers read. Removing it is a follow-up (the resume helpers still take an app-shaped object). Runtime-owned calls (`accept_turn`, staged-evidence snapshot, `_resolve_new_console_assistant`, worktree fencing, prompt-queue archive recovery) go through `_hooks_v2_runtime`.

**Helpers (AC#3).** The five forwarded helpers receive the host. Every `controller.app` / moved-method `self.app` read now reads the host: preparation, received dispatch, run-start tools, hook preparation, worktree recovery, project dispatch, plugin tests, library search, automatic submission, agent reply, personal context, project index preparation (`project_index_key_for_service` added), tool-result observation, prompt-mixin service, wiring, prompt queue, spend projection, goal status. Configuration capture: `_controller_capture_turn_configuration_snapshot(app, controller, ...)` and the three `capture_*_configuration_owned` take the app from the runtime-built capture callable; the stock-source proofs (`vars(app)`, `factory.__self__ is app`, `loader.args[0] is app`, `screen.app_instance is app`) are unchanged. The hook stock proof `controller.app is app` became host-member identity with the app's registry and consent service.

**Deleted re-pointing checks** (the state no longer exists):
- `getattr(creator, "app", app) is not app`, `controller.app is not app` and `self.app is not app` (configuration preparation);
- `controller.app is not app` and `ReceivedPreparationSource.controller_app` (received dispatch);
- `_HookPreparationSource.controller_app` and `controller.app is not app` (hook preparation);
- `controller.app is not app` and the `unified_mcp_service` identity recheck (run-start tools);
- `self.app is not app` (automatic submission) and `controller.app is not app` (composer run controls);
- the app in the plugin-test owner tuples;
- the preparation owner's `app` identity (prompt-mixin service).
Deleted test cases: `test_original_v2_capture_refuses_changed_controller_input_before_context[app]` and `test_changed_owner_refuses_shared_publication_after_native_read[service]`.

**Boot and ratchets.** The new module is resident at UI-ready, so `console_interrupt_rounds` no longer eagerly re-exports `build_local_review_hook` (its only reader is the controller's lazy forwarder), which takes `console_local_review_hook` off the boot path. The census is 1038, three boots in a row (base wobbles 1037/1038); `ui_ready_modules.txt` was regenerated. App-lookup census: Chat 173 to 145. Size pins: controller 29173 to 29132, interrupt rounds 6303 to 6298, composer run controls 1567 to 1566. `console_runtime.py` stays at 7069.

**Tests.** `Tests/Chat/console_controller_factory.py`:
- `bind_app` replaces `controller.app = fake`. It installs a host rebuilt from the fake on every read, through the production builder, so later patches still reach the controller as the lazy reads did.
- `bound_app`, `update_app` and `host_for_app` support it. `bind_runtime_app` stands in for the old `set_chat_controller` injection.
- An AST rewrite converted 255 assignments and 127 reads. Late patches became `update_app`. 106 `bind_runtime_app` calls were inserted before test hand-offs.
- Rigs over fake apps bind after `ensure_chat_controller`.
- The Console harnesses (`republish_services` in `Tests/UI/app_factory.py`) and `attach_chachanotes_db` republish `app.services` after tests patch aliases.
- Tests that relied on `app.console_runtime` now set the runtime reference instead.

**Guards** (in `Tests/Architecture/test_console_controllers_define_their_self_attributes.py`, which a lane runs): an AST check that the class binds and reads no app-like attribute; an AST scan that no module reads a controller's `app` (including Chat/ helpers that take the controller as `self`, and the `creator`/`preparation_owner` aliases), with negative controls; and a runtime check of both construction sites (direct with a host, and `ConsoleRuntime.ensure_chat_controller`) that no attribute or host field is the app. Red evidence (temporary edits, reverted): `self.app = None` in `__init__` fails the AST check; a `getattr(controller.app, ...)` in `console_library_search` and a `getattr(self, "app")` in `console_tool_result_observation` fail the scan; `value._owner_app = self._app` in `set_chat_controller` fails the runtime check (`assert not ['_owner_app']`).
