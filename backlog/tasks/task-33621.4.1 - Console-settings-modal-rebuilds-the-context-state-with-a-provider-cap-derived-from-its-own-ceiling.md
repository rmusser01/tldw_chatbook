## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Raised by the delta review of TASK-33621.4 (2026-11-22). When the Context and memory view changes a policy field, it rebuilds the control state (console_settings_modal.py, around lines 1393-1420 and 2545-2560). It derives `provider_input_cap_tokens` from the old state's safe input ceiling plus the reserved tokens, and passes the old `request_overhead_tokens` back in. A ceiling already reduced by a real provider cap or by mandatory input can then be counted twice or become a cap the provider never set, so the rebuilt Effective budget and trigger can drift from the forecast's own state. Not investigated; recorded so it is not lost.
