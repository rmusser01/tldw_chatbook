## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Ready's verdict is computed offline, so it cannot prove that a key is accepted, that the account can pay, or that replies survive persistence (the Moonshot defect TASK-34100.3 fixes appears only in saved chats). The approved spec offers "Say hello" on Ready and on the dashboard: one short, real message sent through Console's probe turn (TASK-34100.28), with the reply shown in place (decision D5). It never spends money without a press: cloud and generic endpoints run only on an explicit press with a money-first cost line, and only allowlisted local engines on loopback, with no key and nothing to load, run by themselves on first run (owner ruling Q2). Start chatting opens a new chat, and the test stays in History. It builds on Ready (TASK-34100.23) and the dashboard (TASK-34100.26).

Spec: Docs/superpowers/specs/2026-10-03-first-run-setup-shape-design.md (revision 3, approved by the owner on 2026-10-03; ADR-217): D5, D4 (verdict states), §3.6, §3.7, §8.1, §8.4, §10 F9b.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Ready and the dashboard show 'Test it [ Say hi in five words. ] [ Say hello ]' when the verdict is ✓ Ready, ✓ Set up or ! test didn't finish, never on ✗ or not set up. Enter in the field or the button sends one probe turn
- [ ] #2 Cloud providers and every provider outside the local allowlist send only on an explicit press, under a consent line computed from the prepared probe request that leads with money where the price is known (the spec's D5 table). The line is recomputed when the prompt changes and is never hidden while the button is visible. There is no extra dialog and nothing is remembered
- [ ] #3 The test runs by itself only on first run, and only when the provider is in the local-engine allowlist (never custom, custom-ep or another generic endpoint), the host is loopback, no key is configured, and nothing has to be loaded. Otherwise a local test waits for a press, with a line that names any model it would load and its size. It runs at most once per run unless the provider or model changes
- [ ] #4 The verdict region adds the test outcomes: a reply that proves the key makes the verdict ✓ Ready to chat; a failure that proves the setup cannot work makes it ✗ with one fix action; a failure that does not makes it '! Set up, but the test didn't finish'. The test result has its own line without a glyph, so the region never shows two marks
- [ ] #5 When the key is not checked, focus starts on Say hello, which ignores activation for 0.5 s after Ready renders. After a reply focus returns to Start chatting, and after a failure it moves to the fix action
- [ ] #6 While a test runs, Ready shows elapsed seconds and [ Skip test ] (Esc), and every exit, Start chatting included, stops the test without a notice
- [ ] #7 Replies and provider error text render as plain text: Rich markup is escaped and terminal control sequences are stripped
- [ ] #8 Start chatting opens a new conversation. The test exchange is not carried into its context, and the 'Setup test' conversation stays in History
- [ ] #9 The palette's 'Setup: Say hello' opens the dashboard with Say hello focused and its cost line on screen, and never sends directly
- [ ] #10 Verified live on a fresh isolated profile (TLDW_CONFIG_PATH and HOME set) through the real app, with real providers and the real llama.cpp server, never mock servers: a real OpenAI key end to end in two minutes or less hands-on; an OpenAI account with no credit; an expired OpenRouter key; a reasoning model and Anthropic with extended thinking; the real llama.cpp server on a non-8080 port auto-testing with no outbound model request (network monitor); Ollama with the model not loaded and a LiteLLM proxy on loopback, neither auto-running. Evidence is recorded in Implementation Notes
- [ ] #11 New behaviour is covered by tests that fail on the pre-change code (RED verified), and no module-size or ADR-097 ratchet is raised
- [ ] #12 The matching Docs/User_Guide page content is updated where behaviour changed (no 'Verified against' stamps)
