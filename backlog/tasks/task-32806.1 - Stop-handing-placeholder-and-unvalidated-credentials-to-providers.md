## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`config.get_api_key()` screens only one literal placeholder and returns the value raw, so a configured `YOUR_KEY` or a whitespace-padded key is handed to five live spend and readiness call sites, while the shared validity rule the rest of the codebase uses rejects both. The realtime pre-connect credential gate compounds it by testing raw truthiness, so a placeholder passes the gate and is handed verbatim to the provider session -- exactly the outcome the gate's own comment exists to prevent.
