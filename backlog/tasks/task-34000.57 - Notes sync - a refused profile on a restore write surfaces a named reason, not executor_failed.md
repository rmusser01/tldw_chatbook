## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: TASK-34000.48 added a `replacement_profile_unproven` refusal to the filesystem's `replace`. It is raised before anything is written, when a caller asks to write under a line-ending profile the reviewed file cannot prove. The executor's `_TYPED_REASON_CODES` does not list it. It would therefore surface as a generic `executor_failed`, and no copy row would tell the user what happened or what to do.

PR #3047's pre-merge review found it reachable only in a narrow case: `_advance_restore` of a resolution admitted on an older build, whose desired file was written LF over a one-line CRLF reviewed file. Nothing is written when it fires. But a user who meets it gets an unexplained failure.
