## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
From TASK-33621.2 (PR #3005). _build_speculative_voice_capture_request still admits every owned row as its saved revision. It does not use console_trace_row_sources' saved_message_id media check, so a voice send after a /generate-image result can hit the same surface_prefix_mismatch refusal TASK-33621.2 fixed for typed sends.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A voice send after an image result is not refused at the dispatch-commit check
- [x] #2 The voice builder uses the same unsaved-row source and saved-media rules as the typed send path
- [x] #3 A real-controller test pins it
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Reproduce through the production voice stages with a real controller: typed exchange, /generate-image, then a Capture-On voice turn (controller preparation, gateway VOICE_PROVISIONAL dispatch, sealed manifest, winning promotion and trace import).
2. In prepare_speculative_voice_attempt, apply console_trace_row_sources.saved_message_id to each owned row after the existing persisted-id fence; a row that omits saved media becomes a provider artifact.
3. Label unsaved rows with unsaved_row_sources, as the typed builder does.
4. Pin both rules at the builder and the whole turn at the controller; read the recorded trace back.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The voice trace builder now uses the typed path's two rules (TASK-33621.2): a saved row that leaves its media out is a provider artifact, not that message's saved revision, and unsaved rows take `unsaved_row_sources`.

What dev actually did (origin/dev dc371f0842, measured): the voice turn after an image result was NOT refused at its own dispatch commit -- the provisional voice boundary (`console_voice_trace_gateway`) does no revision-projection check, and the import accepted it. The defect was the record: the voice turn's trace named the image-result row's saved revision, so reading the trace back gave `[text, image_url(data:image/png;base64,...)]` for a row the provider received as "[image] a red square". AC#1 holds on both trees for the voice turn itself. Two further refusals showed up on the send AFTER the voice turn and are filed, since neither is this builder: TASK-33621.159 (any typed Capture-On send after a promoted voice turn fails: the completed-turn witness validates the voice call ids, UUIDv5, as UUIDv4 revision refs; a no-image control fails the same way) and TASK-33621.160 (with .159 relaxed in a throwaway probe, an image in the history still refuses that successor as `unsupported_surface_change`, identically with and without this fix).

Change (`Chat/console_chat_controller.py`)
- `prepare_speculative_voice_attempt`: after the existing persisted-id fence, `saved_message_id(message, row)` decides; an owned row that omits saved media goes into `media_omitted` and skips the revision lookup. The persisted-id fence stays: a voice turn over an unpersisted owned row still needs pre-dispatch authority (stricter than the typed path, unchanged).
- `_build_speculative_voice_capture_request(..., media_omitted=frozenset())`: owned rows in it, and every unsaved row, get `ProviderArtifactTraceProvenance` with the source `unsaved_row_sources` assigns (a system row inside the history is history, not rendered system context; the role-only mapping made the aggregate refuse the request).
- Module-size row: 28,764 -> 28,772, the exact measurement (+14 on dev's 28,758).
