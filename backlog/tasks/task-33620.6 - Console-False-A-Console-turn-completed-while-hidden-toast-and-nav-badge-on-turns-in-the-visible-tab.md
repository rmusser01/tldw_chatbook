## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** In the visible, active Console tab, every completed turn after the first in a session raises the toast 'A Console turn completed while hidden. Return to Console to review.' (about 5 s). At the same moment the nav tab flashes '⌃2 Console !' for about 0.75-1.3 s. This was reproduced on turns 2, 3 and 4 in a fresh 120x40 profile without ever leaving Console. It needs only back-to-back sends: no scrolling, theme switch or palette push.

The toast fires while the transcript still shows 'Assistant Streaming…' and the status reads 'Run: Agent running.', so it is raised before the result is even rendered. The first send escapes only because of timing: an extra config write in `_record_successful_first_send` delays the done-callback. A notice that is wrong on every turn teaches users to ignore the same channel that carries the real 'failed while hidden' warning.

**Severity / prior art.** P1, confirmed by all three verifiers. KNOWN_PARTIAL:
- TASK-22514 (In Progress). Its AC#7 specifies the hidden-completion notice, not its suppression when the tab is visible.
- ADR-094 (Console turn lifetime and navigation boundary).
- TASK-31385 (Done) already gates *blocking-round* notices on visibility (AC#3), but not terminal completions.

The mechanism is in `console_runtime.py:1436-1466, 1495-1540` (`recompute_console_attention` / `_notify_terminal_receipt`).

**Suggested direction.** Gate the notice and the '!' projection on real hiddenness. Skip both when a view is attached, the Console screen is current, and the receipt's conversation is the attached view's active session, reusing TASK-31385's pattern. Alternatively, hand completion to the attached view first (refresh and acknowledge), then recompute.
