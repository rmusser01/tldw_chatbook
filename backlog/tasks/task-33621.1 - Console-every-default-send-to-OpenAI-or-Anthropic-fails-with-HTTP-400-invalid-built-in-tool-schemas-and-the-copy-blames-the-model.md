## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact (P0, triage NEW).** On a default profile (setup complete, local tools on by default) every Console send to Anthropic `claude-haiku-4-5` and OpenAI `gpt-4.1-mini` fails with HTTP 400, including direct sends with no proxy and repeat sends. The user sees 'Assistant Failed / Response failed.' and a System row: 'Agent run failed: provider returned HTTP 400 (Provider error from <provider>: bad request. Status: 400. Selected model: <model>. The provider rejected this request. Confirm the model is still available, or choose another model from the model picker.)'. For the two most common cloud providers, the core loop is broken out of the box.

**Verified cause.** Three built-in tools in `tldw_chatbook/Agents/local_tool_provider.py` declare top-level schema combinators: `watchlists_update_collection_sources` (anyOf), `watchlists_check_sources` (oneOf) and `todo_update` (anyOf+allOf). Both providers reject each one on its own. The recovery advice is wrong: claude-sonnet-4-5, claude-opus-4-1, gpt-4o-mini and gpt-4.1 reject the same schema, so changing the model cannot help. The OpenAI path logs the provider body (`tools[34]`, `invalid_function_parameters`). The Anthropic path logs only 'Handler for anthropic directly raised; error_type=ChatBadRequestError; status=400', with no provider message.

**Prior art:** the tools were introduced by TASK-22862 and TASK-22863 (watchlists) and TASK-13216 (todo). The misclassified-400 family includes TASK-32342 (Done) and TASK-32369 (To Do). TASK-399 covers anyOf support in schema forms, which is unrelated to provider tool schemas.

**Suggested direction:** flatten the three schemas to type=object with properties, required and additionalProperties. Enforce 'at least one of add/remove', 'exactly one of source_ids/collection_id' and 'deleted excludes content/activeForm' in the handlers, and state each rule in the tool's description. Add a provider-schema conformance test over every disclosed tool schema, or sanitise at projection time. Classify provider 400s that name a tool or parameter as 'tool definition rejected: <tool>' and drop the 'choose another model' advice for that class. Log a redacted provider message on the Anthropic error path. The general copy mechanism is handled with G4-06.

## Implementation Notes

**Summary.** Default Console sends to OpenAI and Anthropic no longer fail with HTTP 400. The three built-in tools with top-level JSON-Schema combinators have flat schemas now. Their either/or rules are stated in each tool's description and enforced by each handler with an error that names the rule. The native tool projection also strips any remaining top-level combinator, whatever the tool's source.

**Approach**
- **Schemas** (`Agents/local_tool_provider.py`): the schemas of `watchlists_update_collection_sources`, `watchlists_check_sources` and `todo_update` are now `type: object` with `properties`, `required` and `additionalProperties`.
  - `todo_update`'s rules are two constants, `TODO_UPDATE_CHANGE_RULE` and `TODO_UPDATE_DELETE_RULE`. The same wording appears in the description and in the handler's `rule: …` error.
  - `Tools/watchlists_command_service.py` returns "Rule: …" errors for the add/remove rule and for the exactly-one-scope rule.
- **Projection** (`Agents/native_tools.py`): `schemas_to_openai_tools` is the single native projection for local, builtin, Library and MCP tools.
  - `provider_conformant_parameters` removes the top-level `anyOf`, `oneOf`, `allOf`, `enum`, `const` and `not` keywords, forces `type: object`, and never mutates its input.
  - When the stripped rule is only required-argument alternatives, `argument_rule_sentence` restates it in the description. This covers `library_search_notes` and MCP tools.
- **Copy** (`Chat/console_provider_gateway.py`): `_provider_error_copy_with_model_recovery` now receives `request.tools` and the provider message.
  - `rejected_tool_name` names a tool only if the request actually sent it, matched by quoted name or by position. Position is used only when every sent entry is a named function tool.
  - The advice depends on the tool: an `mcp__` tool gets "turn off that MCP server"; Chatbook's own tools get "please report it", plus the switch if its group has one.
  - When the provider blames a tool definition without naming a tool, the copy says choosing another model "is unlikely to help".
  - Every other 400 keeps the model-recovery copy.
- **Logging** (`LLM_Calls/LLM_API_Calls.py`): the Anthropic HTTPError path logs the provider detail through `_credential_redacted_detail`. That helper masks the request's key and subscription token, then runs `redact_log_line`. The diagnostic inventory row was updated to 134 calls.
- **Docs:** `Docs/User_Guide/console/agent-runs-and-tools.md` explains how MCP schemas are projected and adds a troubleshooting entry for the new copy.

**Tests**
- New: `Tests/Agents/test_provider_tool_schema_conformance.py` (34) and `Tests/Chat/test_console_tool_definition_rejection.py` (6). The joined tests send through the real Console path to loopback Anthropic and OpenAI validators.
- Updated: `Tests/Agents/test_local_tool_provider.py`. The stale allOf test was rewritten as `test_todo_update_delete_rule_is_enforced_by_the_handler_not_the_schema`, and the new raw-boundary error strings are pinned. Tests that were silently red because of the sandbox's config admission are marked `@pytest.mark.bootstrap_profile`.
- Updated: `Tests/Chat/test_cohere_native_tools.py`.

**Decisions and trade-offs**
- The rules are now enforced by handlers, not by the schema, because providers refuse top-level combinators.
- Stripping at projection is a backstop against third-party MCP schemas. MCP servers remain responsible for validating their own calls.
- A rule that cannot be restated safely is dropped, not paraphrased.
- Only a name the request actually sent is ever echoed in copy, never provider text.
