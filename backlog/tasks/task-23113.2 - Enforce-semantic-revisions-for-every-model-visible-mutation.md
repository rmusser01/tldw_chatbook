## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Route edits, regeneration replacements, deletes, and other model-visible message changes through one transactional semantic revision coordinator so persisted conversation state cannot diverge from trace lineage.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Initial message persistence and every provider-visible envelope edit, regeneration replacement, role or semantic-sidecar change, and hard delete create, advance, or preserve an opaque semantic revision in the same SQLite transaction.
- [x] #2 The coordinator records the exact provider-visible envelope and stable predecessor relationship without deriving revision identity from canonical-text hashes.
- [x] #3 Unchanged messages created before the coordinator was installed acquire reusable digest-free revision metadata lazily before capture or legacy matching.
- [x] #4 Every revision-policy materialization passes the mandatory credential sanitizer, and sanitizer failure persists only a content-free omission.
- [x] #5 Direct mutation paths that would bypass semantic revision creation fail closed at the persistence boundary.
- [x] #6 Failed persistence leaves both conversation content and revision lineage unchanged, including in-memory projections after rollback.
- [x] #7 Existing non-model-visible UI metadata changes do not create semantic revisions.
- [x] #8 Soft deletion changes visibility/ownership and graph reachability without creating a new revision while the retained semantic envelope remains unchanged.
- [x] #9 Tests enumerate all current message mutation routes and prove the database guard rejects every inventoried model-visible bypass category.
- [x] #10 ADR required: yes; this task implements the mutation-integrity boundary already decided by ADR-097.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Inventory and classify every canonical message and provider-visible sidecar mutation route, then pin the census in a structural regression test.
2. Add the packaged v56-to-v57 fail-closed mutation guard, connection-local authorization, minimal credential sanitizer, and transaction-scoped semantic revision coordinator using genuine historical fixtures.
3. Route every inventoried model-visible writer through the coordinator, preserving rollback-safe in-memory state and leaving presentation-only updates revision-free.
4. Run the targeted coordinator, migration, sanitizer, writer, packaging, and census suites; complete independent specification and code-quality reviews before closing the child task.
