## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- **Port of PR #3431** (another contributor's branch, about 2000 commits behind): d60471a7d8 cherry-picked with `-x` onto dev 8a55555798. The bug was still on dev, which cut over to the compact split at 90. In `run_test` paints of the mock tier at 91, 94 and 97 columns, the library pane was 174, 180 and 186 columns wide inside an 87-, 90- and 93-column workbench. Import…, + New, the work area and the Inspector were all off-screen. With the port, 91-97 show the compact split dev shows at 90, with Import…, search, Name, Tag and + New whole. 90 and 98 paint the same on both trees.
- **Cut-off re-derived against dev's CSS.** Dev's `css/components/_agentic_terminal.tcss` now writes the 2:4:2 min-widths as tokens: `#personas-library-pane` `$ds-size-24`, `#personas-work-area` `$ds-size-40`, `#personas-inspector-pane` `$ds-size-30` with `margin: $ds-space-0`. `css/core/_variables.tcss` resolves them to 24, 40 and 30. These app-tier rules outrank the widget-tier `PersonasScreen #personas-*` rules. `#personas-workbench` adds `border: solid` and `padding: $ds-space-1`, 4 cells across. 24 + 40 + 30 + 4 = 98, so the cut-off stays `24 + 40 + 30 + 4 - 1` (97). The PR's pin test measures `needed = 98` from the mounted panes on dev's CSS.
- **Why a literal, not a computed value.** No Python source holds the `$ds-size-*` values. Computing them at import would mean reading and parsing two `.tcss` files in a pre-imported module. Reading the live panes' min-widths at resize does not work either, because the compact class swaps them for 16/34/22. The constant follows `roleplay_frame_state.py`'s precedent instead: it mirrors the CSS, and a test on the mounted widgets pins it. A fix-up commit changed its comment to name the tokens; the line count is unchanged.
- **Red/green.** With the constant back at 90 (dev's source), 8 of the 24 new cases go red. They are the six 91/94/97 cases across both tiers (library overflow), the sweep at 91, and the pin (`90 == 98 - 1`). The 16 cases at dev's own widths (80-90, 98-220) pass there, which is AC#2's "unchanged". With the port all 24 pass.
- **Not fixed here (pre-existing; proposed follow-up).** From 61 to 73 columns the compact split's own minimums (16 + 34 + 22 + 2 border = 74) do not fit either. Measured on the branch with `run_test`: at 61-73 the library is 59-71 wide and the Inspector is off-screen. Those widths are compact on dev too, so the code path there is the same. At 60 and below one pane shows. The compact split also middle-elides list names, as dev already does at 80-90.
- **Docs.** The PR's User Guide paragraph said "Below 98 columns ... all three panes still fit". A fix-up commit limits it to 74-97.
- **Lanes.** `test_personas_workbench.py` is censused only by node, so the three new nodes were appended to the UI census tail. Local serial times with the lane's flags at load 18-24: `test_workbench_panes_and_library_controls_fit_at_width` 52.1 s (22 cases), `test_workbench_panes_fit_at_every_width_from_80_to_220` 36.7 s, `test_compact_cut_off_is_the_widest_width_the_minimums_cannot_fill` 4.0 s.
- **Files:** `tldw_chatbook/UI/Screens/personas_screen.py` (still 16,892 lines, its ratchet pin), `Tests/UI/test_personas_workbench.py`, `scripts/ui_pr_gate_census.txt`, `scripts/check_ui_pr_gate_census.py`, `Docs/User_Guide/roleplay-chat-dictionaries.md`.
