## Description

## Implementation Plan

1. New Sync_Interop adapter module (`Sync_Interop/chat_sync_source.py`, off the boot path): `CharactersRAGDBChatSyncSource(db)` implements `ChatSyncIntentSource` plus the restore enumerator and the incoming-apply local-store surface. Move verbatim from `CharactersRAGDB`: `read_committed_chat_sync_intent`, `_previous_committed_chat_payload_hash`, `read_committed_chat_delete_intent`, `list_current_committed_chat_sync_intents`, `_split_chat_sync_stable_key`, `get_chat_message_hash`, `append_chat_message`, `delete_chat_message`, the two legacy intent-payload normalisers and their key set, and `_chat_sync_payload_hash_from_row` (as `chat_record_payload_hash`). The adapter runs every statement on the DB's own connection and `transaction()`; it never opens its own.
2. Delete-proof hashing stays inside the write transaction through a narrow DB-layer port in `DB/transaction_observer.py` (stdlib only, no Sync_Interop types), the same shape as TASK-36949.3's semantic port: a process-wide hasher slot, `install_chat_record_hasher`, and `chat_record_hash(row)`, which fails closed with a named error when nothing is installed. The four tombstone writers call it from the same places as today. The adapter module installs it on import; every composition root that installs semantic coordination installs it too, and the test conftest installs it for the suite.
3. ChaChaNotes_DB drops every Sync_Interop import (TYPE_CHECKING and lazy) and the moved methods.
4. Callers: `ConsoleChatStore` builds the adapter from `persistence.db` (no `getattr` method lookups) and checks the producer's source is the adapter over that same DB. Tests construct `ChatSyncV2OutboxProducer(source=CharactersRAGDBChatSyncSource(db))` and call the moved methods on the adapter; the semantic-mutation inventory pins and its doc follow the moved writer routes.
5. Tests: in-transaction and rollback cases for the hashing port, the unset-port fail-closed case, the no-Sync_Interop source check, root-install assertions in the existing per-root test; fresh-interpreter children that delete messages install the port.
6. Ratchets: lower the ChaChaNotes_DB size row, delete the two ChaChaNotes_DB -> Sync_Interop allowlist rows; run covering tests at base and head, serial Tests/Architecture, both boot-import ratchets (ui-ready twice) and preflight.

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Chat-sync persistence moved out of `CharactersRAGDB` into `Sync_Interop/chat_sync_source.py`. `CharactersRAGDBChatSyncSource(db)` is a frozen dataclass over one DB. It implements `ChatSyncIntentSource` (`read_committed_chat_sync_intent`, `read_committed_chat_delete_intent`), the restore enumerator (`list_current_committed_chat_sync_intents`) and the incoming-apply local-store surface (`get_chat_message_hash`, `append_chat_message`, `delete_chat_message`). The code moved verbatim, together with its helpers (`_previous_committed_chat_payload_hash`, `_split_chat_sync_stable_key`, the two legacy intent-payload normalisers and their key set). `self.<db member>` became `self.db.<db member>`, and the lazy imports became top-level imports. Every statement runs on the DB's own connection and `transaction()`. `append_chat_message` still coordinates through `db._coordinate_semantic_mutation`, the same reach `console_dispatch_repository` uses.

**Atomicity design (Review Focus 2).** The four tombstone writers need the deleted row's Sync record hash inside their own write transaction, before the content is cleared: `soft_delete_message`, `soft_delete_message_subtree`, `update_message` when it deletes, and `update_provider_continuation` when it discards. The smallest design that keeps atomicity is a narrow DB-layer port with the same shape as TASK-36949.3's. `DB/transaction_observer.py` (stdlib only) holds a process-wide `_chat_record_hasher` slot, `install_chat_record_hasher` and `chat_record_hash(row)`. The DB calls `chat_record_hash(row)` from the two places that used to call `_chat_sync_payload_hash_from_row`, so the hashing stays inside the same transaction. The implementation is `chat_sync_source.chat_record_payload_hash`. The adapter module installs it when imported, and every composition root that installs semantic coordination also calls `install_chat_sync_hashing()`:
- app_entry ×3;
- serve;
- mobile_service;
- the MCP server;
- the RAG backfill.

A caller-driven transaction was rejected because every soft-delete caller would have had to route through the adapter.

**Behaviour change.** A process that never ran a composition root and never imported the adapter now raises `ChatRecordHashingNotInstalledError` on its first message tombstone. The transaction rolls back and nothing is deleted. Before this change, the tombstone was hashed through the DB's own lazy Sync_Interop import.
- Helper_Scripts/ and scripts/ have no message deleters (grep).
- The dev-only `Tests/Benchmarks/character_qualification_fixture.py` build CLI soft-deletes, so it now fails closed if run by hand. Its in-process tests are covered by conftest.
- The test conftest installs the port for the session.
- The two fresh-interpreter child programs that delete messages install it explicitly: `test_recovered_media_messages.py` and `test_recovered_media_direct_messages.py`. Before that fix, 23 of their cases failed closed.

**Callers.** `ConsoleChatStore` builds the adapter from `persistence.db` through `chat_sync_source_for(db)`, which returns `None` unless the DB is a `CharactersRAGDB`. That replaces the three `getattr(db, "<chat-sync method>")` lookups. It then compares the producer's source with that adapter (dataclass equality is identity of the wrapped DB) instead of with the raw DB. The import is lazy because the store is resident at ui-ready.

`_ContinuationValidatingChatStore` (envelope_applier) adapts a `CharactersRAGDB` local store the same way. A DB handed to `SyncEnvelopeApplier` as `local_store` therefore still applies Chat records. Without this, `call_if_present` would have silently no-op'd the apply: 4 `test_console_thinking_sync` cases failed until it was added. The app string-lookup census is unchanged, because these lookups were on a DB or a producer, not on the app.

Tests construct `ChatSyncV2OutboxProducer(source=CharactersRAGDBChatSyncSource(db))` and call the moved methods on the adapter. The changes touch 15 test files. The semantic-mutation inventory pins and their doc rows follow the three moved writer routes. No test patched a moved name (grep).
