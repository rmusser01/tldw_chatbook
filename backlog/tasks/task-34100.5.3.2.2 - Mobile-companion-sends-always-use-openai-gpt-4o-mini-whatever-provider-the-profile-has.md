## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by TASK-34100.5.3.2 (review round 1, F8-9) and re-checked on origin/dev e8eeae7db9.

The served mobile companion (`tldw-serve`) builds its Console engine in `tldw_chatbook/Web_Server/mobile_service.py`. That code hard-codes `provider="openai"` and `model="gpt-4o-mini"` for the chat controller. Every phone send therefore goes to OpenAI's gpt-4o-mini, whatever provider and model the profile has chosen in setup or Settings, including a local llama.cpp or Ollama server or Anthropic.

The consequences:
- A user with no OpenAI key gets a failed send.
- A user who chose a local model may send their text to a cloud provider they never selected.
- A user with an OpenAI key is billed for a model they did not pick.

Live verification for TASK-34100.5.3.2 could only drive a phone send by pointing `[api_settings.openai] api_base_url` at the local server (see `backlog/docs/lessons-live-verification.md`).
