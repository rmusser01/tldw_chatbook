Found while verifying TASK-33620.15.41 (2026-11-05). TASK-33621.20's mounted regression test Tests/UI/test_console_library_pause_recovery.py::test_the_shelf_never_offers_a_send_the_card_is_sending pins that a turn the paused-send card is retrying is offered nowhere else: not on the unsent-turn shelf, and not in the composer. On origin/dev 29592ecc9b its [search] case fails every run (5 of 5 local runs) at line 205: after Retry, while the retried Library search runs, the composer holds the message being sent ('first automatic send'), so the user could send it a second time. Its [stream] case fails the same assertion intermittently: 4 of 29 dev runs at host load 12-37. In 16 interleaved pairs it failed 3 times on dev and 5 times on the TASK-33620.15.41 branch. That branch's Library changes are never reached here (the test uses a stub search service, and a probe in the real service never fired), and disabling its run-chip change did not stop the failures. Batches of eight runs swung from 1 to 8 failures within half an hour, the 8 with only the unreached Library changes applied to dev, so the rate is set by timing on the host, not by either tree. The file runs in no PR lane (TASK-33621.55), which is how this went unnoticed. The cause has not been traced; the card's retry path (ConsoleChatController.retry_library_preparation) and whatever restores a paused turn's draft to the composer are the places to start.
