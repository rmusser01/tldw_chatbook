## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found during TASK-34100.16.1.3's live run and noted in its report (evidence `.worktrees/setup-wizard-ux-qa/evidence/g161v5-rt/`). No task tracked it until the 2026-11-28 re-triage. On the Backup & Restore screen, "Continue in recovery mode" did nothing under `python -m tldw_chatbook.app`, while it worked under the `tldw-cli` entry point (`main_cli_runner`). There are two such buttons: one for a Replace restore (UI/Screens/backup_restore_screen.py:285-289) and one for a later rollback (:421-425). A user who launched Chatbook the documented developer way gets a button that cannot do what it says.

Cause (read on dev 2df861ec7d, not yet confirmed live):
- The screen shows the button whenever the app has a `request_recovery_restart` method (`_requires_recovery_restart`, backup_restore_screen.py:2932-2933).
- The app's handler (app_lifecycle.py:112-121) goes ahead only when `_recovery_restart_available` is set.
- Only `main_cli_runner` sets that flag (app_entry.py:768), and only it starts recovery after `app.run()` returns.
- `python -m tldw_chatbook.app` goes through `_run_module_main` (app_entry.py:362, app instance at :535), which never sets the flag.

So the press ends at the warning toast "Open Chatbook from its CLI to continue in recovery mode." (app_lifecycle.py:120), which the reviewer did not see.
