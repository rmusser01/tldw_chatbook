## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In the real app, Backup & Restore ▸ Create backup did not produce an archive on any of the isolated macOS profiles tried during TASK-34100.16 and its review rounds. Review succeeds, Create backup is enabled and pressed, and the run then ends at "Failed: capturing" with no file written. The base build (74557e202a, before TASK-34100.16) fails the same way, so this is a backup-engine defect, not something the setup entry introduced.

This matters beyond backup. The User Guide's second-machine route ("Setting up another machine" ▸ "Restore a backup") offers Create backup as the way to carry data; until it works, the guide sends users to copy config.toml and the data folder instead (verified live in TASK-34100.16 review round 3, `g16-r3/`). It also blocks the "Restore with a real archive made by Create backup" leg of TASK-34100.16 AC#4, which was re-scoped to this task. TASK-32562 (In Progress) reports macOS create, restore and open passing in its own installed-product harness, so the gap is between that harness and an ordinary isolated profile. This task owns finding and closing that gap.

Filed in TASK-34100.16 review round 2 as TASK-34560 and renumbered to this subtask in review round 3, before it ever reached `dev`.

Observed failures (evidence under `.worktrees/setup-wizard-ux-qa/evidence/`):
- **Fresh profile, setup's Restore entry ▸ Create form.** Review shows Partial; Acknowledge, then Review again, then Create gives "Failed: capturing … (backup_operation_failed)" (`g16-r/11`, `g16-r2-r/13-14`). Recording the hidden exception shows `RecoveryRequired("capture_source_outside_scope")` raised while `storage_admission._discover_capture_inventory` builds the capture inventory: the selected config path is not inside the admitted session's roots (`g16-r/18`). The base build fails identically (`g16-r/15-BASE-…`).
- **Fresh profile with HOME outside the repository (scratchpad).** Attempt 1 gives "Failed: capturing / review_required / Review: scope_changed". Attempt 2, after a fresh Review, gives `backup_operation_failed` (`g16-r2-r/15`, `15b`).
- **A profile that has already chatted (llama.cpp), via Settings ▸ Overview ▸ Backup & Restore.** "Failed: capturing — The application could not pause background work in time … (admission_timeout)" (`g16-r2-r/24`, `g16-r/14`).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Create backup failed for four distinct reasons, none of them the timeout length. Each fix has a real-SQLite / real-HOME regression test that is RED on the base and GREEN after. Evidence lives under `.worktrees/setup-wizard-ux-qa/evidence/`, and archives under `.../setup-wizard-ux-qa/archives/`.

- **admission_timeout** (AC#2, #4). Local Notes reads ran on a bare `asyncio.to_thread`. Each left the executor thread's cached ChaChaNotes connection holding a storage lease that a backup's local pause never revokes, so every later idle Create timed out. The affected reads are Info backlinks (`list_note_backlinks`), the `[[` picker (`list_note_link_candidates`), the Library `note://` link follow (`get_note_by_id`) and `count_notes`' general path. All now run through `run_finite_local_worker`. A structural test pins every offload in `notes_scope_service.py`. The sync-log retention leak was fixed on dev independently (TASK-38955); its failure path is now covered too.
- **scope_changed** (AC#4).
  - The 65 s change-review retention pass created an absent `agent_runs.db`. It now prunes only an existing DB.
  - Excluded local SQLite stores (Notes device state, Personal Context interview drafts) carried file metadata on sidecars that come and go with each WAL connection. Excluded rows now carry no metadata.
  - The non-excluded `personal_context.repository` has the same failure, but its rows are owner-decided (TASK-39110), so it is a strict xfail held for **TASK-34100.16.1.1**.
- **capture_source_outside_scope** (AC#4). No longer reproduces (October base 4de437a5c5 and again on this rebase). It is pinned by a non-reproduction test with a negative control, not a RED test. It now also maps to its own actionable message ("…outside the storage Chatbook registered when it started… Quit and reopen Chatbook…") instead of `backup_operation_failed`.
- **Round trip** (AC#3). Opening Console created an empty `~/.config/tldw_cli/tokenizers` (0755), so every later archive carried `tokenizers.custom`. Isolated restore on a new machine then refused every folder with `isolated_destination_parent_overlaps_control`: the engine needs that shared folder to pre-exist as an empty owner-only container, which dev's own round-trip harness makes by hand. `CustomTokenizerManager` now creates the folder only on its first write, owner-only. Archives that hold real custom tokenizers, or come from a profile an older build already gave the folder, still need it: **TASK-34100.16.1.2**, with the User Guide workaround. A reviewer's run of **Replace selected stored data** over a keyring-off profile stopped at `recovery_required` (`credential_unreadable`) after a clean Review: **TASK-34100.16.1.3**, documented in the guide. AC#3 is met through **Restore as isolated profile**.
