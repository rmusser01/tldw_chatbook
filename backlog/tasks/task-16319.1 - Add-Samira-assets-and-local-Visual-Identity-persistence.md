## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented the local Samira Visual Identity foundation under ADR-067.

- Schema and repository: ChaChaNotes schema v38 adds the documented four-table server-aligned semantic subset for packs, immutable versions, version-bound assets without the server draft foreign key, and actor bindings. VisualIdentityRepository enforces atomic publication, activation, graph integrity, and create-only ownership boundaries; local keys and the owner sentinel are explicitly not server identities, and legacy character expression BLOB storage is unchanged.
- Contract and assets: strict server-aligned expression normalization, manifest validation, bounded decoding, and package/user resource loading cover the sanitized V2 JSON card, canonical metadata-embedded PNG, manifest, license notice, and exactly 31 valid 1024x1024 WebPs licensed AGPL-3.0-or-later. Reactions total 3,366,092 bytes, the largest is 130,864 bytes, and the complete 35-file Samira resource directory is 5,389,539 bytes.
- Seeding and concurrency: eager, lazy, and injected profile startup use stable provenance and serialized, idempotent repair. Seeding never overwrites, duplicates, resurrects, or steals renamed, customized, collided, archived, deleted, or valid user-bound state. Built-in resources remain immutable through importlib.resources; edits and mutable state stay profile-owned.
- Packaging tradeoffs: source-wheel and extracted-sdist wheel proofs use separate sources/targets, a sanitized offline build environment, and a curated build-tool layer containing only build, setuptools, wheel, packaging, and pyproject_hooks. Installed trees remove only write bits, preserve direct entrypoint execution, snapshot hashes plus stat metadata, and restore exact modes.
- Modified areas: v38 migration and ChaChaNotes wiring, Visual Identity repository and strict asset contract, app/config startup seeding, Samira resources and package metadata/checker, installed-distribution coverage, lifecycle/contract/assets tests, and corrected synthetic schema-rewind fixtures.
- Evidence: 33 installed-distribution tests passed; the TASK-16319 schema/repository/contract/assets/lifecycle/card suite passed 471 tests; the broad migration/DB rewind slice passed 398 tests. Both source-built and sdist-derived installed wheels passed v35-to-v38 migration, strict resource validation, one-card/one-pack/one-version/31-asset seeding, first edit plus FTS, and package immutability. Missing-reaction, missing-migration, identical-rewrite, timestamp-touch, corrupt-graph, and metadata mutations were rejected or detected. Final specification and quality reviews approved the implementation with no findings.
- Full-suite caveat: a broad repository run was attempted but was not green because of unrelated existing or environment failures: the exact chat_screen size-ratchet baseline, Console/controller/provider continuation drift, a Pillow-version visual-evidence fixture mismatch, and sandbox prohibition on local socket binds. No failure entered Samira, Visual Identity, migration, lifecycle, or packaging code; all Task-owned suites passed and reviews found no regressions.
