## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Follow-ups from TASK-33620.15's review (2026-10-09). With keys flowing while a send is admitted: (a) a held non-repeat press still sends its capture when the composer changed during the wait, so a spoken 'Console, send' during the wait can send the same text twice, and a tab round-trip can do the same; (b) ready sends no longer re-check the draft after a non-append edit during admission -- the commit fails closed, so the sent text stays in the composer with no cue and invites an accidental resend; (c) while a press is held in tab A, an Enter in tab B is refused with 'your previous message is still being sent' without naming the other tab; (d) image-only presses are never deduplicated as bare repeats, so a refused or review-held image send can show a second notice on replay.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 No press, held or spoken, ever sends the same captured text twice; pinned by a mounted test that fails on the current behaviour
- [x] #2 When a sent draft cannot be committed out of the composer, the user sees that it was sent (or the composer clears it), so it is not resent by accident
- [x] #3 A refusal caused by a send in another tab names that tab
- [x] #4 An image-only repeat press is deduplicated like a text repeat
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
A Console send's capture is now sent at most once. A sent draft also leaves the chat it was sent from, or Console says that it was sent. A press refused because of a send in another tab names that tab. A bare repeat press, image-only or text, counts only when the first send asked for another Enter. Lead ruling in force (TASK-33620.15): what is sent is what the composer held at the press that sent it.

**Approach.** The new module `UI/Console_Modules/sent_draft.py` is imported on the first send, so the ADR-097 census is unchanged.
- *A capture is superseded* once the composer's draft generation has moved on (a commit, clear, retire or another draft), unless the draft was only reloaded with nothing typed since (`capture_superseded`). A superseded capture is never sent:
  - `observed_send` drops it when its send starts;
  - `_replay` drops a held press holding one before scheduling it, so no phantom "Sending…" row appears;
  - `_defer` discards such a held press instead of refusing a newer press because of it.
- *A dispatched capture is taken out* through one helper (`take_out_sent_draft`). The prompt queue's sent and queued commits both use it.
  - Visible chat: it commits the capture. After a reload with nothing typed, it commits from the reloaded draft. If it still cannot commit (a non-append edit), the user's text stays. Console then says "Your message was sent, but the composer still shows it …", and `ConsoleComposerBar.retire_captured_drafts()` moves both the generation and the edit serial, so no earlier capture can pass as a reload and be sent again.
  - Hidden chat: it takes the sent text off that chat's saved draft and keeps anything typed after it. On dev, the runtime cleared a saved draft only when it was exactly the sent text, so text typed after it brought the sent text back.
- *Bare repeats.* A bare repeat is replayed only when the send it repeats left the draft and asked for another Enter on exactly that draft (`_console_unknown_send_armed`, the unknown command's "Press Enter again to send as text"). After a send, a refusal or a hook review, it does nothing. An image-only press that repeats the running image-only send (same staged image) is dropped at the press. On dev a text repeat also wrote a refusal twice, so text and image now follow the same rule.
- *Naming the other tab.* `_defer`'s refusal now names the other tab: "Not sent: your message in “<tab>” is still being sent. …". `ConsoleHooksController` records which chat holds the Send gate, takes a `session_label` accessor, and its "already in progress" refusal ends "in “<tab>”" when that chat is another one. Titles are sanitised to one bounded line and markup-escaped.

**Decisions and deviations**
- Plan steps 3-4 said a sent draft the commit cannot take out would be recorded as spent, and held presses checked against those records. Retiring the composer's draft revision does the same job with no extra state: every earlier capture becomes superseded, while a deliberate press made after the notice is a new capture and is sent.
- The spoken path (`handle_console_send_message`) is not routed through the flight. The send-start check covers it from the other side (a spoken send that commits first supersedes the Enter's capture), and the replay check covers a held press.
- A superseded held press is dropped silently. A notice there would contradict the "was sent" notice in the case it most often follows.
- `send_acknowledgement.py` grew by 31 lines (751 to 782; the plan said net-zero). No ratchet row covers it. Moving its existing capture helpers out would offset the growth, but R is changing the same file for TASK-33620.15.1, so they stay. The new logic is in `sent_draft.py`.
- The queued path for a hidden chat now keeps text typed after the queued draft. Before, it cleared that chat's draft.

**Tests.** `Tests/UI/test_console_send_resend_guard.py`: 10 tests, about 75 s. It is not added to the UI PR gate, because it is slower than 30 s. Every test failed on origin/dev 46c3959526, run in a detached worktree, for the reason it pins:
- held press then spoken send: `['acknowledge this send', 'y', 'y']`;
- spoken send committing while an Enter paints: `['y', 'y']`;
- tab round-trip `[round_trip]` and `[typed_in_b]`: the draft was sent twice;
- non-append edit: no "was sent" notice;
- tab left after type-ahead: `'acknowledge this sendx' == 'x'`;
- held press in A, Enter in B: the generic notice;
- spoken send in A, Enter in B: the generic "already in progress";
- bare repeat during a refused send `[image_only]` and `[text]`: the refusal was written twice.

**Negative controls.** Each mutation was restored by text edit and checked with diff against a saved copy.
- No send-start check: the spoken-then-Enter case sends twice.
- No replay check: the held press is scheduled again (two schedules).
- No reload commit: `[round_trip]` keeps the sent text.
- No retire: `[typed_in_b]` sends twice.
- No hidden-chat strip: the tab-left case fails.
- Replaying any still-shown repeat: `[text]` fails. No image-repeat check: `[image_only]` fails.
- Generic copy: both naming tests fail.
