## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Follow-ups from TASK-33620.15's review (2026-10-09). With keys flowing while a send is admitted: (a) a held non-repeat press still sends its capture when the composer changed during the wait, so a spoken 'Console, send' during the wait can send the same text twice, and a tab round-trip can do the same; (b) ready sends no longer re-check the draft after a non-append edit during admission -- the commit fails closed, so the sent text stays in the composer with no cue and invites an accidental resend; (c) while a press is held in tab A, an Enter in tab B is refused with 'your previous message is still being sent' without naming the other tab; (d) image-only presses are never deduplicated as bare repeats, so a refused or review-held image send can show a second notice on replay.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 No press, held or spoken, ever sends the same captured text twice; pinned by a mounted test that fails on the current behaviour
- [x] #2 When a sent draft cannot be committed out of the composer, the user sees that it was sent (or the composer clears it), so it is not resent by accident
- [x] #3 A refusal caused by a send in another tab names that tab
- [x] #4 An image-only repeat press is deduplicated like a text repeat

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
A Console send's capture is now sent at most once. A sent draft also leaves the chat it was sent from, or Console says that it was sent. A press refused because of a send in another tab names that tab. A bare repeat press, image-only or text, counts only when the first send asked for another Enter. Lead ruling in force (TASK-33620.15): what is sent is what the composer held at the press that sent it.

**Approach.** The new module `UI/Console_Modules/sent_draft.py` is imported on the first send, so the ADR-097 census is unchanged.
- *Spent captures.* The composer records a capture's draft generation as spent when a send takes it: a commit that takes it out, a sent capture whose commit could not (`spend_captured_draft`), and a retire (`retire_captured_drafts`). A press holding a spent capture is never sent (`ConsoleComposerBar.captured_draft_spent`, read by `sent_draft.superseded`):
  - `observed_send` drops it when its send starts;
  - `_replay` drops a held press holding one before scheduling it, so no phantom "Sending..." row appears;
  - `_defer` discards such a held press instead of refusing a newer press because of it.
  A clear, a replaced draft or a reload spends nothing, so a press made before it still sends what it captured.
- *A dispatched capture is taken out* through one helper (`take_out_sent_draft`); the prompt queue's sent and queued commits both use it.
  - Visible chat: it commits the capture. After a reload with nothing typed, it commits from the reloaded draft. If it cannot (a non-append edit) and the draft still holds the sent text, the user's text stays, Console says "Your message was sent, but the composer still shows it ...", and the draft is retired so no earlier capture of it is sent again. If the user cleared or replaced the text, nothing is said; a draft edited in place is retired silently so the next press on it is a new capture.
  - Hidden chat: it takes the sent text off that chat's saved draft and keeps anything typed after it; the notice is shown only when the saved draft still holds the sent text.
  - An escaped `\! ` chat draft is dispatched without its backslash. The dispatched stash now says so (`ConsoleDraftStash.escape_removed`), and the commit takes out the text as typed (`as_typed`). On dev such a send never left the composer.
- *Bare repeats.* A bare repeat is replayed only when the send it repeats left the draft and asked for another Enter on exactly that draft (`_console_unknown_send_armed`, the unknown command's "Press Enter again to send as text"). An image-only press that repeats the running image-only send (same staged image) is dropped at the press.
- *Naming the other tab.* `_defer`'s refusal names the other tab ("Not sent: your message in "<tab>" is still being sent. ..."). `ConsoleHooksController` records which chat holds the Send gate and its "already in progress" refusal ends "in "<tab>"" when that chat is another one. Titles are sanitised to one bounded line and markup-escaped; the refusal text is only ever shown through notify (markup), the dispatch result's `detail` is not rendered elsewhere.

**Checkpoint-review fixes.** The first cut treated any move of the draft generation as "another send took this capture". A clear moves it too, so (1) a held Enter, or an Enter about to start, was dropped silently when the user cleared the composer after pressing it (dev sent it), and (2) a draft cleared or replaced during admission, visible or hidden, drew a false "was sent" notice; an escaped send drew it too. Replaced with spent records as above; the notice and retire need the sent text still in the draft.

- `send_acknowledgement.py` grew by 31 lines (751 to 782; the plan said net-zero). No ratchet row covers it.
