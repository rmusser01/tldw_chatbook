## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** Setup: a named workspace with a bound git folder. The Inspect pin 'Choose folder · Project' opens the Conversation Inspector. Pressing its 'Choose folder' button hard-locks the app, reproduced 3 of 3 times.

Mechanism:
- `_recover_project_instructions` is a plain @on message handler, not a worker, and it awaits `app.push_screen_wait(ProjectInstructionSetupModal(...))` at `session.py:5420`.
- Textual pushes the modal and then raises `NoActiveWorker`.
- The TASK-32533 keep-alive swallows the error and shows 'Something went wrong in _select_project_instruction_binding'. The Inspector's message loop is dead, but the Inspector stays on the screen stack.
- The first Esc, Cancel or folder click closes the picker, but the result goes to a future nobody awaits. The folder is never applied: the pin still reads 'Choose folder · Project' after a restart.
- From then on every key, click and resize goes to the dead, detached Inspector. Ctrl+Q cannot reach the App either, because the binding chain is built from a detached widget.
- The process idles until it is killed with SIGTERM.

This is the only in-Console control for giving file tools a bound folder.

**Severity / prior art.** P0, KNOWN_PARTIAL:
- TASK-32533 (Done) introduced the keep-alive.
- TASK-32569 (To Do) makes a kept-alive dead pump visible, but does not cover a dead screen left on the stack.
- TASK-1230 (Done) fixed an earlier soft-lock from a navigation guard.
- TASK-32800.4 (Done) added `scripts/check_textual_worker_contract.py`, which does not catch `push_screen_wait` outside a worker.
- TASK-32828 (In Progress) is redesigning the Inspector.

**Suggested direction.**
1. Run the binding selection in a worker, or use the push-with-callback pattern already used nearby in `session.py`.
2. Make the keep-alive in `app_lifecycle.py` never leave a dead screen on the stack. Either fall through to a loud exit, or remove the dead screen and any screens above it and refocus a live screen. Popping only the modal, or making Ctrl+Q a priority binding, is not enough.
3. Add a worker-contract rule for `push_screen_wait` reachable from a non-worker coroutine.

Evidence: qa/console-ux-review-2026-09-29/findings.md → GAP4-01; qa/console-ux-review-2026-09-29/evidence/evidence__GAP4__14-choose-folder-click.txt, evidence__GAP4__25-after-ctrlq, and evidence/GAP4/app-log-run1.log (line 268, NoActiveWorker at site_line=5420).

Review finding ids: GAP4-01 — see qa/console-ux-review-2026-09-29/findings.md.

## Implementation Notes

Fixed GAP4-01 (P0). Pressing "Choose folder" or "Enable" in the Conversation Inspector froze the app, and Ctrl+Q was ignored.

**Approach**

- **Inspector** (`tldw_chatbook/Widgets/Console/console_conversation_inspector.py`):
  - `_recover_project_instructions` is now a sync handler. It runs `_apply_project_instruction_recovery` in its own worker group (`exit_on_error=False`), with a guard so only one recovery runs at a time.
  - A failure shows a toast, logs only the exception type, and leaves the Inspector live.
  - The Safe→Full trace-view confirmation (`action_viewer_profile`) is fixed the same way, and the View: Safe/Full button is wired to it.
- **Keep-alive** (new `tldw_chatbook/app_keep_alive.py`, called from `app_lifecycle._handle_exception`):
  - `pump_loop_ended(frames)` reads the traceback to tell whether the error ended the pump's loop. Only a failed dispatch or mount does.
  - `retire_dead_pump` then acts on a pump whose loop ended:
    - a dead **screen**: it resolves pending results with None, pops the screen and everything above it, and evicts it from the reusable-screen cache;
    - a dead **widget**: it moves focus and mouse capture off the widget's subtree;
    - **nothing live would be left**: it returns None so the app takes Textual's loud exit.
  - `keep_alive_notice` writes the toast text for each case.
- **CI** (`scripts/check_textual_worker_contract.py`, W003):
  - It flags a wait-for-dismiss push reachable from a non-worker entry point.
  - It resolves callables across modules, and treats `push_screen` callbacks as entry points.
  - It does not flag a push built inside `run_worker(...)`'s arguments.
  - The new census `scripts/textual_wait_push_census.tsv` grandfathers 26 unreviewed roots.
- **Store** (`tldw_chatbook/Chat/console_chat_store.py`): `publish_durable_turn_identity` writes the project-instruction state on first persist, with net-zero added lines.
- **Docs**: the User Guide `Docs/User_Guide/console/context-and-rag.md` and `Docs/User_Guide/index.md`, plus the diagnostic inventory. The `app_lifecycle` size budget was lowered from 2140 to 2134.

**Tests**

- New: `Tests/UI/test_console_project_instruction_choose_folder.py` (real picker, choose/enable, Esc/Cancel) and `Tests/UI/test_app_keep_alive_dead_screen.py` (production TldwCli with the keep-alive on).
- Extended: `Tests/Scripts/test_check_textual_worker_contract.py`, the recovery and viewer tests in `Tests/UI/test_console_context_modal.py` and `Tests/UI/test_console_inspector_workflow.py`, and `Tests/Chat/test_console_first_send_atomicity.py`.
- On the merge-base, the AC#4 and AC#5 tests fail for the right reason and W003 flags the Inspector. All of them pass on HEAD.

Second round:
**Summary.** The Inspector's project-folder recovery and its Safe→Full trace confirmation now run in workers. The handler-error keep-alive can no longer leave a dead screen or dead focus in charge. A new W003 contract rule pins wait-for-dismiss pushes reachable outside a worker. A new chat's project folder is committed inside its first durable transaction.

**Approach**
- **Inspector** (`Widgets/Console/console_conversation_inspector.py`):
  - `_recover_project_instructions` and `action_viewer_profile` start `run_worker(..., exit_on_error=False)` in their own groups, with an in-flight flag so repeat presses are ignored.
  - The worker queries the panel with `query().results()`, so an Inspector closed mid-picker is harmless.
  - `_name_unchecked_project_folder` resolves a restored chat's folder name before the next-send preview.
  - `PROJECT_LOCATOR_NOT_CHECKED` in `Chat/console_display_state.py` replaces a duplicated literal.
- **Keep-alive** (new `app_keep_alive.py`, called from `app_lifecycle._handle_exception`):
  - `pump_loop_ended` classifies the traceback against Textual 8.2.8's two loop-ending catches.
  - `retire_dead_pump` pops a dead screen and everything above it, resolving pending result futures with `None`.
  - It refocuses and releases mouse capture off a dead widget's subtree.
  - It forgets a dead reusable screen so navigation rebuilds it.
  - If only the placeholder would remain, it returns `None` so the app takes Textual's loud exit.
  - The toast copy says what happened.
- **W003** (`scripts/check_textual_worker_contract.py` + `scripts/textual_wait_push_census.tsv`, 26 baseline roots):
  - Roots are `@on`/`on_*`/`action_*`/`watch_*`/`key_*` handlers and pump-scheduled callables.
  - A root counts when it transitively (name-resolved, across modules via kwargs, dict keys and aliases) awaits a wait-for-dismiss push.
  - `@work`, and pushes built inline as `run_worker`'s argument, stop the propagation.
- **Persistence:**
  - `ChatPersistenceService.commit_durable_turn(project_context_json=...)` writes a new chat's controls in the same off-loop `BEGIN IMMEDIATE`.
  - `ConsoleChatStore.commit_durable_turn` snapshots the state under `_preparation_lock`, then re-writes after the commit only on a mid-commit re-choice or when the adapter lacks the keyword.
  - `_persist_project_instruction_state` resolves a committed-but-unpublished first identity from the reservation.
  - Removed: the redundant post-promotion write and the dead `_deferred_project_instruction_state_session_ids` set.
- **Tests and docs:**
  - New: `Tests/UI/test_app_keep_alive_dead_screen.py` and `Tests/UI/test_console_project_instruction_choose_folder.py`.
  - Extended: first-send atomicity, W003, context-modal and Inspector-workflow tests.

W003 checker hardening, over three checkpoint-reviewed rounds plus bot-thread rounds on PR #2944:
- Rows are keyed by entry point plus push site.
- self.x() resolves through the MRO, subclasses and mixin hosts, never to an unrelated class by bare name.
- The last definition wins.
- Lambdas and local rename chains of any length are followed.
- A bare call no longer resolves to a class method, while a class-body bare name reads its own class first (901a2ab1a4).
- A hand-rolled wait (push with callback= plus an awaited future in one function) is flagged.
The census is byte-identical to --write output. Known limitations are pinned by strict xfails using a dedicated exception (FreezeObserved / MissedHandRolledWait).
