## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Five small truth-and-space problems in Media, Search/RAG and Import. Each one is a status that describes something other than what is on screen, or space spent on noise instead of the document. Each has a workaround, so they are polish. Together they wear down a power user's (Morgan's) and a researcher's (Priya's) trust in what the screen says.

**L-15 (P3) · Media reader Find needs Enter, and keeps showing the previous query's count and marks.** At 160 columns, with "retrieval" typed into Find but not submitted, the status still reads "Match 1 of 2" from the previous query 4 s later. Only Enter updates it. The placeholder "Search content…" does not mention Enter, while the list filter a few columns away updates as you type.

Verified cause: the Find status is updated only on submit (`Widgets/Library/library_media_content.py:451-488`).

Suggested direction: add an `Input.Changed` handler. While the input differs from the submitted query, the status reads "Enter to find" and Prev/Next are dimmed. Counting lines instead of matches is L-14, owned by TASK-32384 and TASK-28021, and is out of scope here.

**L-24 (P3) · Search/RAG silently keeps the previous query's source toggles.** After a RAG Answer run with only Media on, a search for "spaced repetition" from the rail box at 120x36 returns "1 result for 'spaced repetition'.". The panel still shows ☑ Media (24), ☐ Conversations (12) and ☐ Prompts (10). In the journey, the "Scope: …" line was above the viewport, so the researcher concluded her notes did not match. Re-enabling sources gave more results.

Suggested direction: make the results count scope-aware, for example "2 results · Media only — Search all sources" with a one-press reset. A search started from the rail box should restore all sources. Lowered: the scope line is visible at 160 columns, and the zero-result copy points at the sources.

**L-25 (P3) · An absolute file:// path takes the reader's first rows, and the reader is no wider than the list.** At 100x30, an imported PDF opens with its byline set to the full local path ("file://…/paper-retrieval-practice.pdf"), wrapped over 4 rows. That leaves a reader of about 44 columns beside a list just as wide. At 160x45 the reader is about 54 columns, and text wraps near 50. Reading is the reader's main job, yet it gets the least space, and the path exposes the local filesystem.

Suggested direction:
- Show the byline as "<basename> · local file", and put the full path in Info.
- Give the Reader a prose floor of about 72 cells before the list grows.
- Collapse Nav automatically, once, when a document loads, as Notes already does.

Keep within the ADR-086 adaptive-reader rules. Lowered: the 4-5 rows came from a long harness path, and typical paths take 2.

**L-35 (P3) · A fully successful import still offers "Retry this batch" and the footer "r retry".** After "This queue: 5 done", with every file "✓ done", the queue ends with "Retry this batch" and the footer says "after esc: r retry". A literal first-timer assumes something failed.

Code: the button is at `Widgets/Library/library_ingest_canvas.py:2079-2092`. The binding `r` → `library_ingest_retry_last` "Retry this batch" is at `UI/Screens/library_screen.py:1150`.

Suggested direction: label by outcome. Show "Retry this batch" only when rows failed or were skipped; otherwise show "Import again with these settings…" and "r import again". Change the button, the binding description and the footer chip together.

**L-38 (P3) · Clearing the Media filter also resets the sort and the type chosen while filtered.** With a filter, a type and "sort: Title A-Z" applied, the scope-line Clear returns "Media · 23 of 23 · all types · sort: Newest". The toolbar "Clear filter" button resets the sort too.

Verified cause: on clear, `_request_library_media_filter` restores `_library_media_unfiltered_scope`, the snapshot taken when the filter was first applied (`UI/Library_Modules/library_media_controller.py:2273-2284`). Any sort or type chosen while filtered is lost.

Suggested direction: on clear, rebuild the scope from the applied scope with `query=''`, keeping sort and type. Use the snapshot only to restore the selection. TASK-32350 (Done) deliberately lets the scope-line Clear also drop the type facet, so that a type-only scope's Clear is never a dead button. Keep that, but never reset the sort.

L-29 (P3, residue of done task-31635). In Media Trash, selecting a trashed row leaves a different, live item in the Reader. Per the task-31635 ruling it is labelled 'not in Trash', and Delete forever names the trashed row, so this is not data loss. It still reads as the wrong item at a glance. Evidence: qa/notes-library-ux-review-2026-10-02/verify/nl-vb-7/05-trash-enter-160x45.ansi. Suggested direction: the selected Trash row shows a short content excerpt, and the Reader's identity line says 'Still showing <title> from Media · r restore to read'.

Review finding(s): L-15, L-24, L-25, L-35, L-38, L-29. Source: qa/notes-library-ux-review-2026-10-02/report.md
