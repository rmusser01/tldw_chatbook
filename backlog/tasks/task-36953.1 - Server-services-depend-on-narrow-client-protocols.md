## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Each of the 47 `server_*_service.py` modules depends on the whole `TLDWAPIClient` (1,220 methods; median use 13), which makes fakes large and hides what each service needs.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F14; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Each server service declares a typing Protocol listing only the client methods it uses
- [x] #2 A test fails if a service calls a client method its Protocol does not list, or if a Protocol lists a method the client lacks
- [x] #3 Runtime behaviour is unchanged
<!-- AC:END -->

## Implementation Plan

1. Inventory every `server_*_service.py` (47 at base 5ca7ec6a03) and classify each: drives `TLDWAPIClient` (gets a Protocol) or not (exempt, with the reason).
2. In each client-driving service, declare one `typing.Protocol` listing exactly the client methods it reaches (direct calls, `getattr`/`hasattr` probes, names passed to helpers or spec rows), and annotate its client parameter, attribute and `_require_client` return with it. Typing only: stdlib `typing`, no runtime path changes.
3. Add an AST test under `Tests/Architecture` that fails if a service touches a client method its Protocol omits, or a Protocol lists a method `TLDWAPIClient` lacks; show both failure modes red with temporary edits.
4. Verify runtime unchanged: each touched service's tests plus the boot-import ratchets, against a base worktree; `Tests/Architecture` serially vs the base failure list; preflight.

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Typing-only change: each server service names the client methods it uses.

**Inventory: 47 `server_*_service.py` at base 5ca7ec6a03.** The draft's 45 changed paths were 44 services plus the new test. 44 drive `TLDWAPIClient` and each now declares one module-level `typing.Protocol` (`Server<Name>Client`, 1,050 methods in all, median 14) that annotates its `client` parameter and `_require_client()` return. 3 are exempt, listed with reasons in the test's `EXEMPT`: `Notifications/server_notifications_scope_service.py` and `Server_Runtime_Interop/server_runtime_scope_service.py` wrap another service and hold no client; `MCP/server_unified_service.py` drives `MCPUnifiedClient` (built per target by `app_service_wiring.py`), not `TLDWAPIClient`.

**Protocol shape.** Members are `async def name(self, *args: Any, **kwargs: Any) -> Any: ...`; the client's async-generator methods (`stream_*_events`, `process_/ingest_mediawiki_dump`) are plain `def`, because calling them returns an async iterator, not a coroutine. This keeps AC#1's method list and drops signatures: argument and return types now come from `TLDWAPIClient` (via mypy) only at call sites where the client is not narrowed to the Protocol; full signatures are a possible follow-up. Only `Protocol` was added to each `typing` import; no `runtime_checkable`. The `TLDWAPIClient` names removed were all inside `if TYPE_CHECKING:` blocks (an emptied block was dropped). `Chatbooks/server_chatbook_service.py` keeps `TLDWAPIClient` for `build_tldw_api_client_from_config`, which returns the real client.

**Taking over the previous draft.** Its 44 Protocols were checked against an independent, deliberately over-inclusive scan (every attribute and string literal naming a `TLDWAPIClient` member). One gap: `Media/server_media_reading_service.py` reaches `process_video/audio/pdf/ebook/document/plaintext` through `getattr(self._require_client(), client_method_name)`, and its Protocol listed none of them; the draft test passed it. Added the six. The draft test's Kanban-only rule was replaced by a general one (below). `Research_Interop/server_research_service.py`'s import block was re-joined (ruff I001 from the draft).

**Test (`Tests/Architecture/test_server_service_client_protocols.py`, AST).** Per service: exactly one Protocol; the methods the module touches equal the Protocol's methods (catches both a missing and an over-listed method); every Protocol method exists on `TLDWAPIClient`. "Touches" = attribute reads on the client and `getattr(<client>, name)`; the client and its aliases, helper parameters and dynamic `getattr` names are as revised in fix round 1 below. `ABSENT_PROBES` excuses `run_research_websearch`, a dead `getattr(..., None)` probe that no client has, in the research-search service only.

**Red evidence (temporary edits, each reverted).** Media without the six `process_*` entries: red, `calls client methods its Protocol does not list: ['process_audio', ...]` (the draft test was 92 passed on that state). Tools service calling `get_tts_health`: red (a). Tools Protocol plus call naming `no_such_client_method`: red, `Protocol lists methods TLDWAPIClient lacks` (b). Tools Protocol over-listing `get_tts_health`: red. Kanban `getattr(..., spec.method_name)`: red, `<unresolved getattr spec.method_name>`.

**Fix round 1 (review rv-cp; test only, no runtime change).**
- *Important #1, fail closed:* a `getattr` name resolves only through string literals, module-level string constants (bound once), and the arguments at every same-module call site of the enclosing function (keyword or position, recursively, defaults included), or for `x.<field>` every same-module dataclass constructor slot, `<field>=` keyword and attribute assignment. Every other value fails as `getattr name <expr> at <file>:<line>`. Today's Media and Kanban sites resolve fully, so no allowlist was needed.
- *Minor #2:* client aliases now follow annotated, walrus and tuple assignments, `self.<attr>` targets and functions that return the client; a client argument is followed into a same-module function or method by position or keyword whatever the parameter is called. A hand-off the scan cannot follow (another module's function, a container slot) fails as unresolved.
- *Minor #3:* new `test_exempt_service_reaches_no_tldw_api_client`: no exempt service names `TLDWAPIClient` or `_require_client`, and the two scope wrappers touch no client at all. The inventory test is renamed `test_exemption_tables_name_real_services` and also checks `ABSENT_PROBES` paths.
- *Minor #4:* `ABSENT_PROBES` is keyed by `Research_Interop/server_research_search_service.py` and excuses only the `getattr(client, name, default)` shape.
- *Red evidence (temporary edits, each reverted; serial runs):* Tools `_rv_call(method_name=_RV_CONST)` + `self._rv_call("get_audio_streaming_limits")` → red `['get_audio_streaming_limits', 'get_custom_voice']` (the round-0 test missed both); `_RV_METHODS[kind]` and an f-string at call sites → red unresolved with `server_tools_service.py:138/139`; a Kanban row via a constant → red `['get_tts_health']`, via `str.lower("X")` → red unresolved at `:986`; annotated, walrus, tuple and `self._api` aliases, helper parameters `api`/`gateway` and a client-returning helper → red, 7 names; a container store and a hand-off to `build_runtime_api_client_provider_from_config` → red unresolved; the runtime scope wrapper calling `self.client.get_jobs_config()` → red, the MCP service importing `TLDWAPIClient` → red; a direct `run_research_websearch` call in Tools and in research-search → red in both.
- *Green:* the test file 92 passed (`-n 4` and serial); preflight (Python 3.12) passed.

**Files.** 44 `server_*_service.py` modules; new `Tests/Architecture/test_server_service_client_protocols.py` (needs a lane entry); `backlog/docs/lessons-testing-evidence.md` (dynamic-`getattr` census lesson; its fail-closed rule corrected in fix round 1).
- Fix round 2 (84b1d657cf, test only): a module constant resolves only when the whole module stores to it once (re-binds in module-level if/try, `global`, `del` or same-named locals make it unresolved, which fails closed); every client expression must sit in a followed form (attribute read, call argument, assignment value, paired tuple element, return, store target, comparison, truth test) or the test fails with file:line.
