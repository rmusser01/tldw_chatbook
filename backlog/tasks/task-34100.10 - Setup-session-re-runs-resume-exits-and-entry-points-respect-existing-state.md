## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Setup has no model of a setup session. Its state is a handful of loose first_run flags, and five hand-wired entry points each handle cancel, guard and resume their own way. This breaks people who return to setup:
- A re-run ignores the current provider, model, voice, RAG choice and track, and greets the user with first-run copy. Its untouched steps overwrite working settings. Cancelling a re-run opened from Settings lands on Console.
- Resume hides the key field and restores the wrong choices.
- 'Later' saves nothing, so setup nags at every launch.
- Every 'Continue setup' or 'Set up provider' control opens an expert Settings form preset to OpenAI.
- Ctrl+Q skips the exit guard that Esc honours.
- Esc on the Summary leaves setup unfinished.
- Skip, Exit and the next launch land on three different screens.

Jo (local-first) faces a three-pane editor asking for an OpenAI key and gives up. Riley re-runs setup to change one setting, walks every step, and finds his TTS endpoint broken.

This task implements structural fix SF7 (a setup-session model and one entry contract) and enhancement E10 (one startup attention queue). Report: Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md (§5.1 SF7, §5.4 E10, §6 register). Resolves: cross-cutting-05, entry-exit-handoff-12, provider-04, cross-cutting-08, entry-exit-handoff-07, entry-exit-handoff-08, entry-exit-handoff-13, entry-exit-handoff-27, gap-05, new-full-track-steps-01, new-voice-speech-01, protect-summary-08, protect-summary-11, protect-summary-14, cross-cutting-19, entry-exit-handoff-11, entry-exit-handoff-15.
