## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Full track has no tldw server step, its order puts a download-heavy Voice step early, and a power user who only wants to set the provider and model must walk every later step. "Protect keys" often has nothing to protect.

The approved spec fixes Full at eleven steps in dependency order: Welcome, Connect, Model, tldw server, Search, Tools, Spoken replies, Dictation, Appearance, Keys, Ready (decision D2). Every optional step defaults to "not now" and writes nothing when untouched. "Save and finish with defaults" is offered on Model and "Finish with defaults" on every later step. The optional tldw server step commits through the shared runtime-source coordinator (TASK-34100.19) and discloses sync preparation before the choice (decision D3, part 3). It builds on the cleaned-up Full steps (TASK-34100.13, which removes Notes), the setup registry's names (TASK-34100.15) and the setup core (TASK-34100.20).

Spec: Docs/superpowers/specs/2026-10-03-first-run-setup-shape-design.md (revision 3, approved by the owner on 2026-10-03; ADR-217): D2, D3 part 3, §3.3, §3.4, §10 F6.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Full is Welcome, Connect, Model, tldw server, Search, Tools, Spoken replies, Dictation, Appearance, Keys, Ready, with the tracker titles from the spec's area table ('Keys', not 'Protect keys'). The Full-order tests are rewritten to this order and RED-verified
- [ ] #2 On Full, Model's nav offers 'Save and finish with defaults', and steps 4 to 10 offer 'Finish with defaults'. Both go straight to Ready, every unvisited step writes nothing, and Ready shows '– Left at their defaults: …' naming them in order. The palette has 'Setup: Finish with defaults', and no new key chord is taught
- [ ] #3 Leaving every optional step untouched, through Next or either finish button, leaves config.toml byte-identical apart from first-run bookkeeping
- [ ] #4 The tldw server step offers 'Not now — this computer only' (the default, which writes nothing) or 'Connect to a tldw server' with address, token and Test connection. What sync preparation sends is said before the choice. The address is never prefilled from the template, and the token never with the placeholder
- [ ] #5 Save & continue commits through the shared coordinator. A token rejection, a non-tldw server or a policy block refuses the save with the cause under the field; an unreachable or untested server, or a tldw server reached without a token, offers 'Save anyway' or 'Keep editing' inline; a commit failure leaves the step with the prior values restored
- [ ] #6 On a re-run with a server bound, 'Connect to a tldw server' is preselected with the address and 'token saved', and choosing 'Not now' switches back to local through the same coordinator
- [ ] #7 Every Full step, including the tldw server step, fits 80x24
- [ ] #8 Verified live on a fresh isolated profile (TLDW_CONFIG_PATH and HOME set) through the real app, with real providers and the real llama.cpp server, never mock servers: Full with a real Anthropic key and a real tldw_server (connect, wrong token, server stopped, Save anyway); Full finished from Model with Save and finish with defaults; a re-run that switches back to local. Evidence is recorded in Implementation Notes
- [ ] #9 New behaviour is covered by tests that fail on the pre-change code (RED verified), and no module-size or ADR-097 ratchet is raised
- [ ] #10 The matching Docs/User_Guide page content is updated where behaviour changed (no 'Verified against' stamps)
