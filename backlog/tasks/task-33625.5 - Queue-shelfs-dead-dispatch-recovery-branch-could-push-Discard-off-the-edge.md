## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
From the TASK-33625.4 (PR #2964) review. ConsolePromptQueueRegion.sync_presentation has a 'dispatch-recovery' branch (Retry anyway / Retry response / Unavailable) that production never reaches: presentation_for never passes dispatch_recovery= to derive_prompt_queue_presentation, and dispatch recovery has its own #console-dispatch-recovery region. If it were ever reached, its ~70-cell copy would push Discard past the right edge of a shelf 92-101 cells wide that is not in narrow mode.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
I deleted the shelf's dispatch-recovery branch. No production caller could reach it, so nothing changes for users.

**Unreachable, by grep (origin/dev f0ffcf9e81):**
- derive_prompt_queue_presentation has one production caller, ConsolePromptQueueUIController.presentation_for, which never passed dispatch_recovery=.
- ConsolePromptQueuePresentation is built only inside that function. The one test that builds it directly (test_console_selection_end_to_end) uses primary_action "send".
- sync_presentation has one caller, chat_screen._sync_console_composer_action_state, which passes presentation_for's result.
- So primary_action "dispatch-recovery" and recovery_actions were never set outside test_console_dispatch_recovery.py.
- The recovery card (#console-dispatch-recovery) does use handle_primary_intent's retry_response / retry_anyway / discard path, through chat_screen._dispatch_console_recovery_action. That path stays.

**The clip was real.** A temporary probe (deleted) fed the real 'Response delivery status is unknown on the source device.' copy and the production actions through the old branch, under every app sheet. Discard ended at cell 102 on shelves 92, 96, 100 and 101 wide; at 92 the row painted '...Retry anyway      D'. The shorter 'Response accepted; waiting for dispatch.' fit. At 91 (narrow) and 102 it fit.

**Removed from tldw_chatbook/UI/Console_Modules/prompt_queue.py:**
- the dispatch_recovery parameter and its branch;
- the ConsolePromptQueuePresentation.recovery_actions field;
- the dispatch-recovery branch in sync_presentation, and both in on_button_pressed;
- the ConsoleDispatchRecoveryAction / ConsoleDispatchRecoveryState imports.

handle_primary_intent's docstring now says recovery actions come only from the card. Walking down the deleted code orphans nothing: the removed imports are still used by the card and the models. No CSS changed.
