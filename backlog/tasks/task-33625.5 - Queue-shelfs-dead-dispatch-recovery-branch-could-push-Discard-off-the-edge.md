## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
I deleted the queue shelf's dispatch-recovery branch from tldw_chatbook/UI/Console_Modules/prompt_queue.py. Production could not reach it: presentation_for, the only production caller of derive_prompt_queue_presentation, never passed dispatch_recovery=. Users see no change.

**Removed:**
- the dispatch_recovery parameter and its branch;
- the ConsolePromptQueuePresentation.recovery_actions field;
- the dispatch-recovery branches in sync_presentation and in both on_button_pressed paths;
- the two imports they used.

handle_primary_intent's retry_response / retry_anyway / discard path stays, because the #console-dispatch-recovery card uses it. Its docstring says so. The file shrank from 1202 to 1147 lines.

**The clip was real.** With the real 'Response delivery status is unknown on the source device.' copy, the old branch put Discard at cell 102 on shelves 92-101 cells wide.

**Tests** (Tests/UI/test_console_prompt_queue.py, Tests/UI/test_console_dispatch_recovery.py):
- New: test_painted_label_walk_covers_every_shelf_projection_input. It fails if the projection accepts a queue mode, or any parameter after snapshot/activity of any kind, that the TASK-33625.4 painted-label walk never exercises. composer_collapsed is exempt.
- New: test_queue_shelf_has_no_dispatch_recovery_mode pins the deletion.
- The walk now paints the failed-turn row behind a full queue ('Queue 10/10').
- Re-pointed: the shelf-recovery unit test now uses the production dispatch_recovery_blocked=True.

Three review follow-ups were applied: the wider guard, the full-queue row, and the User Guide wording.

**Evidence:**
- Both new tests are red on origin/dev and green on the branch.
- Mutations:
  - restoring the parameter turns both new tests red;
  - dropping the recovery-blocked row turns the guard red;
  - adding a positional input turns the widened guard red, and the old keyword-only guard missed it.
- 17 touched-module test files: identical failures on the branch and on dev (91 each, all pre-existing).
- Boot ratchets pass. The module-size ratchet fails only on rows that already fail on dev.
- Collect-only finds 0 errors. preflight passes.
- Live run on an isolated profile showed the shelf's Draining, Pausing and Paused states with whole labels. After a SIGKILL between acceptance and dispatch, the recovery card appeared, and its Discard settled the turn.

**Docs:** Docs/User_Guide/console/chat-basics.md now places the pending-response actions on the recovery card. backlog/docs/lessons-live-verification.md gains an entry: a pending dispatch needs a SIGKILL of the app's own pid.

Status is left In Progress for the lead to mark Done at merge.
