## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Library's pane frames paint $ds-column-line ($surface-lighten-2), which TASK-33003.6 did not cover (its ACs name the grid-line and control-edge boundaries). They measure 1.28:1 at origin/dev and on the Phase 3 branch, below the WCAG 1.4.11 3:1 floor for component boundaries. Found in TASK-33003.6 review round 1 (F7).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Library's pane frames now read at 3:1 on every measurable theme.

**Fix.** `$ds-column-line` resolves to `$tldw-boundary` (css/core/_variables.tcss), the colour the theme guard already pins to 3:1 on surface and panel for `$ds-grid-line` and `$ds-control-edge`. It was `$surface-lighten-2`. No Library rule changed: `#library-shell-grid`, `#library-rail`, `#library-file-notes-rail` and `#library-canvas` still say `border: solid $ds-column-line` on `$ds-surface-panel`.

**The token is shared, so every other user moves with it.** Each one paints on a `$surface` or `$panel` fill, which is what the gate measures:
- Home: `#home-triage-grid`, `#home-rail`, `#home-canvas` (panel).
- Console: the rail section rules `.console-rail-section-header` (surface) and `.console-workspace-conversations-header` (the rail's panel); the context tray, session, workspace and run-inspector frames (panel); the transcript separator `.console-transcript-rule` (colour and hatch), which by the same token becomes a 3:1 line between messages. That one was resolved from the token, not captured live for this rider.
- Settings: `.settings-instant-apply-group` and `.settings-secondary-card` (panel).
- Lab: the `#lab-rail` right edge (panel). Workflows: the library and navigator right edges.

**Gate (AC#1)**, Tests/UI/test_theme_contrast.py, 89 measurable themes (70 shipped, 19 built-in):
- `test_library_pane_frames_clear_non_text_contrast` (new): reads each Library frame rule's border token from features/_library.tcss and resolves it through `_variables.tcss`, then asserts 3:1 on surface and on panel.
- `test_boundary_tokens_clear_non_text_contrast_on_every_theme`, `test_user_saved_themes_get_visible_boundaries` and `test_user_theme_with_any_kept_variable_form_still_loads` now also measure `ds-column-line` (through `_assert_boundaries_visible`), so saved user themes are covered.
- Red before the fix: 182 failed (89 + 89 + 4 user-theme nodes), for example "zero_day_stealth: ds-column-line #393940 is 1.51:1 against surface #1A1A20". Green after: 781 passed.

**Live (AC#2).** tmux, 211x44, scratch profile (HOME, XDG and TLDW_CONFIG_PATH in scratch, null keyring), default theme textual-dark, Library opened from the top tab, `capture-pane -p -e` parsed as one stream. All 839 frame cells on rows 5-42 (shell grid, rail and canvas) paint (119,119,119) on (36,47,56): 3.05:1. The same cells measured 1.28:1 before, (62,62,62) on (36,47,56). No capture is committed; the phase's Capture pass takes the kept set.

**Files.** css/core/_variables.tcss; the regenerated tldw_cli_modular.tcss and screen_*.tcss sheets (one line each); a stale ratio in a features/_console_panels.tcss comment; Tests/UI/test_theme_contrast.py; DESIGN.md, backlog/docs/design-language.md and the themes.py mechanism note, which now name the third token.

- Ruling: change the token, not the three Library rules. Why: every user of `$ds-column-line` is a pane frame or section rule under the same WCAG 1.4.11 floor, and TASK-33641.1 names the Console rail rules among them. Cost if wrong: a surface that wanted a quieter line (the transcript separator is the likeliest) needs its own token.
