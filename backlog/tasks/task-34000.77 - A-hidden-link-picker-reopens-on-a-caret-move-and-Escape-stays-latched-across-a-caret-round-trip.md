## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The P1-B final re-review of TASK-34000.11 (2026-10-23) found two small behaviours in the Notes `[[` link picker.
Neither can rewrite an existing link: a caret inside a closed link is never a completion. Both only affect the
user's own unclosed `[[`.

1. **A picker hidden by the canvas comes back on the next caret move.** When the editor surface goes, for example
   when Preview is pressed or a validation veto routes to Info, the canvas hides an open insert picker
   (`library_notes_canvas.py` ~4100-4112). The controller's open request survives that hide, so returning to the
   editor and moving the caret within the same `[[` reopens the picker, even though the "only a typed edit opens
   the picker" rule says it should not.

   Repro: with `[[Lisb` open, press Preview through a programmatic `Button.press()`, then Edit, then Left. The
   picker opens. A real mouse click on Preview does not reproduce this, because the body's blur closes the picker
   first.
2. **Escape stays latched across a caret-only round trip.** Press Escape on `ab [[Tri`, then press Home and End,
   then type `p`. The picker stays closed. Only a typed edit outside the context clears the latch; before the
   final fix round, any caret departure cleared it.
<!-- SECTION:DESCRIPTION:END -->
