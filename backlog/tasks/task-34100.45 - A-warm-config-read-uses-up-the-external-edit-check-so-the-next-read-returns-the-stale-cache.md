## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found during TASK-34100.13's review (finding V2, 2026-10-27; dev-owned, not fixed there). `config.toml` edited outside the app while it ran was not picked up by the next reads: the first-run wizard opened 13 s after the edit and still showed the old value, and only the wizard's own first save reloaded the file (`.worktrees/setup-wizard-ux-qa/evidence/g13v5-vr-a120/config-08-external-gate-edit.toml`, `41-rerun-tools.txt`, the app log at 18:22–18:23). TASK-34100.13 made the setup steps stop writing a stale value back; the stale read itself remains.

Cause (read, not fixed): `config._warm_config_cache_hit()` (TASK-32804.1) repeats the guarded fast path's check, including the throttled `_external_edit_detected()`. When that returns True the warm hit falls through to `_load_cli_config_bootstrap()`, whose own `_external_edit_detected()` call is inside the same 1 s throttle window and returns False, so the bootstrap's lock-free fast path returns the cached config unchanged. The one detection is consumed by the warm check and never forces the re-read (`force_reload=... or edit_detected`) it exists for.
<!-- SECTION:DESCRIPTION:END -->
