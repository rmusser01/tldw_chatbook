## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: TASK-34000.18 made the Media list highlight an ORDER-based fact: every door that opens or selects an item for the Reader sets `highlight_held_by_reader`, so while the Reader shows an item that is not on the current page, no row wears the `▸` cue and the selection keeps naming the Reader's item (owner Q2 (b)). One door was left out: `_open_library_external_media_detail`, the route a remote ingest receipt's "Open" takes to show a SERVER item. It enters the external detail without setting the hold, so the list's builder falls back to row 0 and paints the cue on a local item that has nothing to do with the server detail the Reader is showing. This predates the P1-A batch; the Reader's own controls are unaffected (the final-review C-1 fix makes them act on the loaded item whatever the view), so only the cue is wrong.
