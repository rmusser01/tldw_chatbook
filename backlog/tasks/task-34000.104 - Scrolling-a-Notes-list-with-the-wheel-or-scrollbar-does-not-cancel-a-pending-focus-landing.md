## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: Found in the Task 8 re-reviews (R3 for the scrollbar, R4 for the wheel; TASK-34000.29 N-29) and ruled a follow-up by the final polish-1b review. `_withdraw_library_notes_pending_focus_handoffs` (`UI/Screens/library_screen.py:26062`) is called from the screen's `on_key`, `on_mouse_down` (:8726) and wheel handlers (`on_mouse_scroll_down` :8738, `on_mouse_scroll_up` :8748). Textual stops a wheel event at the widget that scrolls, and `ScrollBar._on_mouse_down` stops a scrollbar press, so neither reaches those handlers: "every real input withdraws" is false for scroll input. Measured in R4: after an open (owed role `trash-restore:0`), two wheel notches scrolled the Recently deleted list from 0 to 4 and the owed role stayed; the user then wheeled up from 5 to 1 and one ordinary Notes sync jumped the list back to 5. The effect is bounded: scrolling moves no focus and writes nothing, and only a later landing's keep-in-view scrolls over the user's position, in the Trash list as found.
