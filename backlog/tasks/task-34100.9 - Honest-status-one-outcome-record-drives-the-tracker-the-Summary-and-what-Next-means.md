## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The wizard's marks and its Next button don't tell the truth. The tracker ticks ✓ for steps that were skipped, refused or discarded, and going Back wipes what it knew. The Summary and the tracker disagree about the same step. Next silently means save, skip, write defaults or refuse, depending on the step. Exit keeps every write but lists none of them. Summary rows print config ids, point to the wrong homes and raise false alarms: a working model-from-disk Parakeet reads 'configured but not installed'. A first-time user (Sam) believes a dropped key was saved and only hits the failure in Console. A power user (Riley) sees '!' on a healthy re-run and has to diff config.toml to learn what setup did.

This task implements structural fix SF4 (one outcome record per step drives every mark) and the rest of SF3's semantics: what Next means and says, an Exit dialog that lists what was saved, and a GGUF picker that waits for Next. It also adds the wizard part of SF1, a Summary 'Ready to chat?' row computed with Console's own send preflight, as a second line of defence for cross-cutting-01. Report: Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md (§5.1 SF1, SF3 and SF4; §6 register). Resolves: cross-cutting-03, cross-cutting-02, cross-cutting-09, voice-speech-13, cross-cutting-10, protect-summary-12, protect-summary-16, protect-summary-17, voice-speech-14. Every one was re-checked and is still present on dev 3c439d606e.

Coordination:
- This task builds on the per-step fixes in TASK-34100.6 (the Provider skip), TASK-34100.7 (a Model skip that keeps the key) and TASK-34100.8 (the Voice delta-commit).
- The catalog repair for cross-cutting-01 is TASK-34100.2. The Ready row only checks the result and must call Console's shared code, never a copy of it.
- Keep TASK-25818's restraint: skipped optional steps show a neutral '–'. Also keep the '!' glyph and the Summary's force-reload read-back (§5.5 Preserve).
- Don't answer a false ✓ with more confirm dialogs.
- Add the wizard as a consumer in task-33005.9 (shared connection evidence) and task-33005.7 (readiness vocabulary).

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 [cross-cutting-03] Next means one thing on every step: it saves what the user chose and continues, or writes nothing on an untouched step. It is labelled 'Save & continue' when the step will write and 'Continue' when it won't. Welcome and Protect copy describe the real skip ('Next without a password keeps keys as plain text'). 'Retry with Next' appears only when a retry can succeed. Pressing only Next through both tracks over populated configs leaves config.toml byte-identical apart from first-run bookkeeping
- [ ] #2 [cross-cutting-02] Each step records one outcome when the user leaves it: saved, kept current, skipped, staged, or needs attention with a reason. The tracker and the Summary both render from that record and never disagree. Outcomes survive Back. A refused or failed check never shows ✓. Skipped Voice and Protect show a neutral '–', and an untouched step on a re-run shows ✓ (kept current), not '!'
- [ ] #3 [cross-cutting-09] The Exit dialog lists the areas saved this session, read from the outcome record (e.g. 'Saved so far: provider and model (OpenAI · gpt-4.1-mini) · theme (nord)'). Free text such as the voice sample text is never copied into the draft checkpoint. Every config write setup makes either goes through the audited commit path or appears in the outcome record
- [ ] #4 [voice-speech-13] Choosing a transcribe.cpp GGUF writes nothing until Next, and Exit setup leaves config.toml unchanged. The chosen file shows its name and a Clear action. The control says it applies to Library audio import, not dictation (or it moves to Library ingest settings or Lab ▸ Models). The Summary reports the configured GGUF
- [ ] #5 [cross-cutting-10] The tracker always names the current step. When titles don't fit (Full track, 80 columns), a caption reads e.g. 'Step 7 of 11 · Tools — next: Notes'.
