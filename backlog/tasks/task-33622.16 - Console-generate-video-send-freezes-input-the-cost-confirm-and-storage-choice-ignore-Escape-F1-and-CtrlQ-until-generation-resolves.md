## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found live during TASK-33622.15 (2026-10-03) and reproduced on dev. After sending /generate-video with Enter against a paid backend, the 'Generate video?' cost confirmation ignores Escape, F1 and Ctrl+Q, and so does the capacity/storage choice that follows, until the generation resolves. Sending with a mouse click on Send does not freeze. The suspected cause (the send awaiting the whole slash command inline on the UI path) is inferred from symptoms, not confirmed with a stack. The user cannot cancel a paid generation or quit while it runs.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** Every Console slash command now runs in a ChatScreen worker, and the send returns at once. The one exception is an argument-free `/rewind`, which opens its picker with a `push_screen` callback and never waits on it. Enter, the Send button, the Workbench "send" action and a spoken "Console, send." all take that path. The cost confirm, the paid generation and the storage choice no longer park any message pump. A failed or stopped `/generate-video` or `/generate-image` never overwrites what the user did in the composer while it ran.

**Root cause (confirmed, not inferred).** An await-chain dump of each pump's task, taken in a mounted test on dev `01a2020981` (evidence `uxrev/evidence/bd3/V/await-chain-dev-01a2020981.txt`), shows the mechanism.
- Enter: the APP pump was parked in `MessagePump.on_callback` → `_send_console_message_from_visible_action` → `_dispatch_console_command` → `_console_command_generate_video` → `Worker.wait()` (the confirm's `push_screen_wait`). Enter schedules the send with `app.call_later`, and Textual awaits a coroutine callback on the pump it was posted to. That pump dispatches every key, so Escape, F1 and Ctrl+Q were all dead.
- Send button: the same chain ran on the Console's own pump (`on_button_pressed`). Keys still worked, but the Stop button that cancels a paid run was dead for the whole generation.
- TASK-33621.28 had fixed this freeze for the hook review only. The send also awaited every slash command inline.

**Changes.**
- New `tldw_chatbook/UI/Console_Modules/command_handoff.py` (lazy-loaded on the first slash command, never on the boot path). `run_console_command` starts the dispatch in a non-exclusive `console-command` worker group, so `/stop` can run beside a generation.
  - It drops a repeat of the SAME captured draft revision for the same chat while that draft's first run is in flight. The hand-off lets a second press arrive early; on dev it queued behind the parked pump.
  - It ends a command quietly when the modal it waits on is cancelled (`WorkerCancelled`). Live finding: Ctrl+Q under the confirm made shutdown cancel the confirm's waiting worker, and that surfaced as an `unhandled_exception`.
  - It hands the command the draft its send captured (a contextvar set inside the command's own worker).
- New `tldw_chatbook/UI/Console_Modules/command_draft.py` (checkpoint-review fix, also lazy). `/generate-video` and `/generate-image` used to save the live draft, clear the composer, and on failure clear it again and paste the saved text back. Once the Console stays live during a generation, that wiped text typed meanwhile (the review repro: Enter the command → Generate → type → Stop), and after a chat switch it wiped the OTHER chat's draft, because every Console chat shares one composer. Now:
  - A command takes only the revision its send captured (`commit_captured_draft`), so keys typed right after Enter stay. `/generate-image` awaits its prompt preparation before taking the draft, so this window was real there.
  - It puts the command back only into the same draft scope (unchanged draft generation) while that scope is still empty. Otherwise the user's text stays, and the failure row ends "The composer has changed since, so the command was not put back; to try again, send: <command>".
  - It restores with `restore_stashed_draft` (the original literal segments), not as a paste. A paste-bearing draft is never parsed as a command, so Enter used to send the restored command to the model as chat; now Enter re-runs it.
- `chat_screen.py`: the KIND_COMMAND branch calls the hand-off. Net-zero lines (25402 on both origin/dev `5e0341d1ec` and the branch merged onto it).
- `Docs/User_Guide/console/video.md` and `attachments-images-voice.md`: Escape at the cost confirm starts nothing and keeps the draft; the Console stays responsive during a generation; what comes back into the composer after a failure or Stop.
- Diagnostic inventory: two constant-string `logger.debug` calls in `command_handoff.py`, read before regenerating (no user content, paths or secrets). `command_draft.py` logs nothing.

**Deviations from the plan.**
- Step 3: every command but argument-free `/rewind` is handed off, with no `in_worker_task` check. A command is never "sent", so the spoken path has no outcome to wait for. An unconditional hand-off also avoids the contextvar and eager-task traps recorded under TASK-33621.28.
- Step 4: no early reservation of the video in-flight guard. The repeat-key drop closes the double-press window. A different `/generate-video` sent while one runs still gets the existing post-confirm "already running" refusal, so there is no double spend.
