## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Let users inspect how an existing profile record or pending proposal was created and approved, including honest limitations when legacy evidence cannot be resolved.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 My Profile record details and proposal review expose read-only recorded provenance: source, actor, reason, timestamps, version identifiers, promotion identifiers and source-reference availability.
- [x] #2 Bare source IDs and hashes remain unverified metadata; quotation, authority, confidence and semantic support are not inferred from their existence or an approval reason.
- [x] #3 Manual, migration, approval, promotion and tombstone metadata reflect stored fields; edit history and inference classification are explicitly unknown when not retained, including accept-edited and later Settings edits.
- [x] #4 Inspection uses the user-owned Settings authority and cannot broaden agent access; profile lock, removal, replacement and selection/version changes clear stale details and reject late worker results.
- [x] #5 Existing canonical fields and owning services are used without schema changes, derivative storage, historical-body recovery, source resolution or provider calls.
- [x] #6 Imported or user-controlled metadata renders as bounded literal text without interpreted markup, terminal controls or active links.
- [x] #7 Targeted service and mounted UI tests cover truthful unknown states, deleted metadata, stale availability, unchanged acceptance behavior and narrow layouts under ADR-150.
<!-- AC:END -->
