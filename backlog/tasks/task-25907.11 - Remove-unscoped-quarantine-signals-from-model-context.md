## Description

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Model-facing Personal Context serialization never includes the unscoped unsupported_records_present field or a replacement quarantine existence/count signal.
- [x] #2 When no eligible record fits, unsupported quarantine state cannot create a Personal Context block or injected Console profile message.
- [x] #3 With permitted records and request fixed, toggling the native unsupported-record hint leaves serialized content, selected versions, token estimate, packing and permitted selection rows unchanged; supported positive controls still reach production entry points.
- [x] #4 Existing scope/private/expiry/conflict filtering, whole-record 12 KiB and ten-percent input budgets, native authority revalidation and root snapshot behavior remain covered by targeted regression tests.
- [x] #5 Regression evidence uses real offline service/tool/context and Console request preparation, preserves the frozen 24-case fixture and historical reports, and reports the remaining device-only disclosure gap honestly.
- [x] #6 No shared V1 schema/canonical bytes, repository migration, grant, provider call, real profile, Sync semantics, background worker or broader V2 feature is changed; the completed fix is documented and reviewed through its own targeted checks.
