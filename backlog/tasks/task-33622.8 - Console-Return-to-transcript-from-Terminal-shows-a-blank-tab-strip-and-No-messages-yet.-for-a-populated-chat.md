## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** Right after using a host terminal, the user sees their conversation apparently wiped and their tabs gone. That invites panic, duplicate work or a 'Clear'. Open the Terminal from the Context rail (even unarmed), then click 'Return to transcript'. The Console header still names the active conversation, but the tab strip shows only 'New tab' (other tabs and 'Temporary' are gone), and the transcript says 'No messages yet.' although the chat has messages. It held 3/3 at 160x45 with no resize, unchanged for at least 15 s. Focus lands on the transcript surface, not the composer, so typed letters do not reach the draft, and 'y' opened Trace. No data is lost: Ctrl+K lists 'Active (2)', and any later sync (sending, or opening and dismissing any modal) redraws everything, but the user cannot know that. The existing test only checks that the transcript widget exists and has focus, never tab labels or message count. Verified on dev 64579cce2c (live and code CONFIRMED, skeptic PARTIAL).

**Cause.** `_return_from_console_terminal` / `_build_console_center` mount a fresh center without re-running the native session UI sync (tab strip plus transcript) that screen resume runs.

**Severity / prior art.** P1, triage NEW. Related: TASK-22512 (Done), TASK-26034, TASK-31520 (screen instance reuse).

**Suggested direction.** After the swap back, run the same session UI sync that resume runs and restore the captured reading state. Alternatively, keep the transcript center mounted and toggle display between it and the Terminal workspace so nothing is recomposed. Focus the composer on return.

Evidence: qa/console-ux-review-2026-09-29/findings.md → GAP4-04

Review finding ids: GAP4-04 — see qa/console-ux-review-2026-09-29/findings.md.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Return to transcript now restores what the user left: the same tabs, the conversation at the place they were reading, and the keyboard in the composer.

- The swap captures the transcript reading state before the Terminal replaces it (`capture_center_reading`).
- On return, `finish_center_swap` invalidates the transcript sync gate (it still held the pre-swap token, so every later tick skipped the fresh widget and a populated chat read "No messages yet."), runs the native session sync (tab strip and transcript), restores the reading position, and focuses the composer instead of the transcript surface (where a typed "y" opened Trace).
- Chosen over the "keep the transcript mounted and toggle display" alternative to keep the change small and local to the swap; the swap's focus branches moved from chat_screen.py into Console_Modules/terminal.py, lowering the screen's size-ratchet row.
- Known residual: the one-time "Each tab runs its own agent" coach-mark, if it was showing and not yet dismissed, is not re-shown after the round trip (it reappears on the next transition to two tabs, by its own design). Filed as TASK-33622.24.
- Review fix (2026-10-29): the captured reading position is keyed by the conversation it came from, and Return restores it only while that conversation is still active (AC #2 says "the active conversation's ... reading position"). Before, a conversation activated while the Terminal was open opened at the old one's offset. `test_return_never_applies_one_conversations_reading_to_another` was red on the pre-fix head (scroll_y 2.0 on the other conversation) and passes now. `test_unsent_draft_survives_a_terminal_round_trip` pins the draft: shell typing never touches it, and typing after Return resumes it. Restoring after a deferred (held or in-progress) sync is filed as TASK-33622.23.

Tests (`Tests/UI/test_console_terminal_integration.py`): `test_terminal_round_trip_restores_tabs_transcript_and_composer_focus` seeds two chats (24 messages in the first), Temporary and New tab, scrolls up, opens the Terminal, returns, and asserts the same tab labels, the same rendered message ids, scroll_y restored, composer focus, and that "y" lands in the draft without opening Trace; the two older round-trip tests now expect composer focus. Red on origin/dev 3efe8476ce (tabs ['New tab'], 0 messages, transcript focused); green on the branch.

Live (isolated profile, real Anthropic claude-haiku-4-5 through the review proxy, 2026-10-29): at 235x52 two tabs with real replies -- after Terminal and Return the tab strip, all four messages and composer focus were back, and "y" landed in the draft; at 80x24 with the Inspector open and the transcript scrolled up, the same round trip restored the tabs, the reading position and composer focus.
