## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** Right after using a host terminal, the user sees their conversation apparently wiped and their tabs gone. That invites panic, duplicate work or a 'Clear'. Open the Terminal from the Context rail (even unarmed), then click 'Return to transcript'. The Console header still names the active conversation, but the tab strip shows only 'New tab' (other tabs and 'Temporary' are gone), and the transcript says 'No messages yet.' although the chat has messages. It held 3/3 at 160x45 with no resize, unchanged for at least 15 s. Focus lands on the transcript surface, not the composer, so typed letters do not reach the draft, and 'y' opened Trace. No data is lost: Ctrl+K lists 'Active (2)', and any later sync (sending, or opening and dismissing any modal) redraws everything, but the user cannot know that. The existing test only checks that the transcript widget exists and has focus, never tab labels or message count. Verified on dev 64579cce2c (live and code CONFIRMED, skeptic PARTIAL).

**Cause.** `_return_from_console_terminal` / `_build_console_center` mount a fresh center without re-running the native session UI sync (tab strip plus transcript) that screen resume runs.

**Severity / prior art.** P1, triage NEW. Related: TASK-22512 (Done), TASK-26034, TASK-31520 (screen instance reuse).

**Suggested direction.** After the swap back, run the same session UI sync that resume runs and restore the captured reading state. Alternatively, keep the transcript center mounted and toggle display between it and the Terminal workspace so nothing is recomposed. Focus the composer on return.
