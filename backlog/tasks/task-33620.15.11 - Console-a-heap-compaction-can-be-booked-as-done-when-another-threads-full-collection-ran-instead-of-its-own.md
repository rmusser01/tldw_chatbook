## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The idle heap re-freeze and its compaction (TASK-33620.15.3) freeze the heap only after a full collection really ran, judged by CPython's generation-2 pass count moving across the gc.collect(2) call. If a worker thread's generation-2 pass finishes between the before and after reads while the UI thread's own call was skipped, the count still moves, and a compaction whose collection never ran is recorded as done: frozen garbage is frozen again and stays until the next compaction. The damage is bounded (the next compaction reclaims it) and was never observed live, but the check proves only that some pass completed, not that this call's pass ran.
<!-- SECTION:DESCRIPTION:END -->
