## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Three places where Notes breaks the input conventions the rest of Library follows. A keyboard-only user (Sam) and a Notes power user (Alex) lose either a cue, a draft, or staged review work. Nothing is lost on disk.

**N-31 (P3) · Notes text fields do not show the "typing in field" footer, and Esc in the filter throws away the draft.** Elsewhere in Library (Conversations, Prompts, the landing, Import), focusing a text field switches the footer to "typing in field | esc … | after esc: …". That tells a keyboard user that single letters will type. In the Notes filter, Title and Keywords the footer stays "esc focus rail | F1 help · F6 next pane …". This happens, for example, after `/` focuses the filter, or after returning from the palette at 80x24, where a typed `g` went into the filter.

One S-08 capture at 160x45 does show "typing in field" on the Notes list after a filter submit. So the cue is at best inconsistent, depending on how focus arrived.

Pressing Esc in the Notes filter with an unsubmitted query clears it. At 160x45 the box reads "Filter notes… (Enter)" again.

Cause (hypothesis): the shared footer transform keys on any focused Input or TextArea (`UI/Screens/library_screen.py:4736-4831`). The Notes tiers therefore most likely miss a footer refresh on focus change, or build their footer outside it. Not traced.

Suggested direction: apply the shared "typing in field / after esc:" grammar to every Notes tier, and make Esc in the filter blur without clearing the draft. Lowered: the claimed collision between chips does not render; the harm is a missing cue plus a lost draft.

**N-33 (P3) · Ctrl+S saves only in Skills.** Library has four editors on one screen, with four save models:
- Skills: Ctrl+S saves the skill ("ctrl+s save skill", bound at `UI/Screens/library_screen.py:1047`).
- Notes: Ctrl+S does nothing. The status stays "Unsaved changes · Next: Keep editing; changes save automatically." until the 2 s autosave fires.
- Prompts: only a "Save changes" button.
- Folder files: autosave, with no Save.

`action_library_notes_save` (`:8688`) and its `check_action` gate have no binding and no caller.

ADR-031 (`backlog/decisions/031-tui-keybinding-and-footer-hint-conventions.md`) rule 2 forbids binding terminal-convention keys, including ctrl+s, for app actions. Notes having no Ctrl+S is deliberate there, and pinned by tests, so Skills is the outlier.

This task does not decide the rule. It is one of:
- **(a)** Make Skills conform to ADR-031: remove its ctrl+s binding and footer chip, and wire or remove the dead Notes save action.
- **(b)** Record that an ADR-031 amendment is needed for an editor-scoped Ctrl+S bound in all four editors at once, and get the owner's ruling. This is owner question Q2 in report.md, also raised by R-08 and R-27 in `improvements/ranked.md`.

**Owner ruling 2026-10-03: (b).** Ctrl+S saves in every editor. ADR-031 is amended (refinement dated 2026-10-03): `ctrl+s` performs the focused editor's visible commit action, flushes an autosaving editor immediately, reports a refused save at the editor without moving focus, and is unbound outside editors.

Implementation waits for that choice.

**N-34 (P3) · In Add from files, Escape cancels a running import while "‹ Notes" leaves it running, and every exit drops a sync review's staged choices.** Escape means "back" everywhere else in Library. Here:
- Escape while an import is checking or importing calls `cancel()`, and the receipt reads "Cancelled. Finished items were not rolled back." The visible "‹ Notes" button returns and lets the import continue.
- In a keep-synced review, leaving by any route discards the staged choices. After a "Keep both" had been staged for "conflict.md · Both file and note changed", re-entering shows "No choice selected.", with no warning.

Verified cause:
- The Escape branch is at `UI/Library_Modules/library_notes_controller.py:3095-3102`.
- `abandon_setup` sets `_review_plan = None` (`UI/Library_Modules/library_notes_sync_controller.py:1166-1178`).

Suggested direction:
- Esc during an import behaves like "‹ Notes": the import continues, and cancelling stays on an explicit "Cancel import".
- Keep staged review choices until the folder observation changes.
- Give the back cue its origin ("‹ Sync folders").
- Clear the stale "Choice staged" line.

Lowered: the footer says "esc cancel", and nothing is lost on disk.

Review finding(s): N-31, N-33, N-34. Source: qa/notes-library-ux-review-2026-10-02/report.md
