## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in the independent review of TASK-33621.21 (2026-11-22). On a first run the controller emits "Preparing speech model…" (WARMUP_MESSAGE_FIRST_RUN), but the warm-up wait's first progress check, about 50 ms later, finds no attributed download (every current adapter, ADR-284) and repaints the chip with "Loading speech model…" (WARMUP_MESSAGE): `Chat/console_voice_input.py`, the quiet-loading branch of `_run_warmup_off_the_executor` (around lines 2112-2116). So the first-run copy is effectively never seen; live captures show "Loading speech model…" at 6 s. Two tests assert the first-run copy and pass only when they read the chip inside that 50 ms: `Tests/UI/test_console_dictation_firstrun.py::test_a_slow_first_run_shows_the_preparing_message_not_a_frozen_button` and `::test_an_unrelated_ui_refresh_cannot_wipe_the_preparing_message` fail about 1 run in 3 on dev (the first failed on dev ddd3c02052 and passed on the TASK-33621.21 branch in the same comparison run).
