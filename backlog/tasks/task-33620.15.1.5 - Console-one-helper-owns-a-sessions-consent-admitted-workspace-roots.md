## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Three places read a session's Change Review roots the same way, through consent admission for the session's own workspace:
- the turn-configuration builder (resolve_runtime_turn_configuration_snapshot through capture_console_turn_configuration);
- ConsoleChatController._hook_authority_values;
- resolve_session_workspace_roots, which the Environment panel and the Change Review opener use (TASK-33620.15.1.3).

Each one repeats the same steps: check for a turn-context provider, read the session's workspace id, then call capture_change_review_admission. Only the snapshot and the narrow read coerce the roots to str. If one copy drifts (another workspace id, a missing coercion, a different provider branch), the Environment panel, Change Review and hook authority can each describe a different tree. Today only an equivalence test ties the narrow read to the snapshot.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 One function reads a session's consent-admitted roots, and the snapshot builder, hook authority and the Environment and Change Review accessor all use it
- [x] #2 For the same session all three return the same str-coerced tuple, pinned by a test
- [x] #3 No caller builds a turn snapshot to get the roots

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Tests first: the three readers agree on str roots for one session (mounted, real controller); replacing the one read reaches all three; no snapshot is built for the roots even with a provider
2. read_session_change_review_admission in console_turn_context owns the read (session's own workspace + consent admission); capture_change_review_admission coerces roots to str at the source
3. Builder, hook authority and resolve_session_workspace_roots call it; the accessor drops its provider branch

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Summary: one helper, `read_session_change_review_admission(app, store, session_id)` in `Chat/console_turn_context.py`, now owns the read of a session's consent-admitted Change Review roots: the session's own workspace id, then the consent admission. The turn-configuration builder (`capture_console_turn_configuration`, reached through `resolve_runtime_turn_configuration_snapshot`), `ConsoleChatController._hook_authority_values` and `resolve_session_workspace_roots` (the Environment panel and Change Review opener) all call it.

- `capture_change_review_admission` returns `str` roots at the source, so every reader compares like with like. Before, hook authority returned the admission's roots uncoerced while the snapshot it is compared against (`runtime_current`) stored `str(root)`. In production `ChangeReviewAdmission.ready_roots` is already `tuple[str, ...]`, so the mismatch showed only with admissions that return `Path` roots (the tests' stubs); the coercion makes the contract hold for any admission.
- `resolve_session_workspace_roots` no longer asks an installed turn-context provider for a whole snapshot to keep its roots (AC#3). The runtime-owned controller always has no provider (`ConsoleRuntime.ensure_chat_controller` forces `turn_context_provider=None`), so production behaviour is unchanged. Hook authority's provider branch still reads the provider's snapshot, because it reads all four authority values from it and then checks them against that same snapshot; it does not build a snapshot only for the roots.
- The turn-admission precapture (`turn_admission.capture_authority`) keeps calling `capture_change_review_admission` with the workspace id it took from the store on the UI loop, because it runs on a worker and must not read the store. It now gets `str` roots too.
- The helper's docstring says what a worker caller sees of the store (review follow-up, 2026-10-27): the store belongs to the UI loop, so a worker reads the session's workspace as of its read. That suits the Environment panel, whose stale-scope guard drops an answer the scope has moved past (TASK-33620.15.1.6); the precapture freezes the UI loop's workspace id instead and calls the workspace-level read the helper composes. Keeping the precapture on the same seam as the other three readers is filed as TASK-33620.15.1.7.

Tests (each red on origin/dev 3be493413a for the stated reason, green here):
- `Tests/UI/test_console_session_admitted_roots.py` (mounted, real runtime-owned controller): the three readers return the same `str` tuple for `Path` admission roots (dev: hook authority returned `PurePosixPath`); replacing the one read in `console_turn_context` reaches all three, each asking about the session's own workspace (dev: the builder and hook authority called their own imported references, so only the accessor saw the replacement).
- `Tests/Chat/test_console_session_workspace_roots.py`: an installed provider is not asked for the roots (replaces the test that pinned the opposite); `capture_change_review_admission` returns `str` roots.
- `Tests/Chat/test_console_configuration_capture.py`: the precaptured-domain guard now patches the new seam name.

Modified: `tldw_chatbook/Chat/console_turn_context.py`, `tldw_chatbook/Chat/console_configuration_capture.py`, `tldw_chatbook/Chat/console_chat_controller.py` (net zero lines, at its ratchet), the three test files above. The new mounted file runs in PR Fast Lane (admission-sensitive 2).
