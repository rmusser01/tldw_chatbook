## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The splash screen builds one nine-key dictionary with nine separate config reads, costing about 59 ms of every app launch before first paint; the same loader is copy-pasted in a settings viewer. Opening Settings then Speech and TTS spends 65 ms re-reading already-cached config on the UI thread, when the settings screen holds a snapshot one line away and both readers already accept a mapping.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
PR #2739 (`fix/core-review-loop`), all three ACs done.

AC#1 (splash one-section read): `splash_screen` + `settings_splash_screen_viewer`
read the `[splash_screen]` section ONCE (was 9 `get_cli_setting` calls); test
pins the single read.

AC#2 (panel from the settings screen's snapshot): the ~65 ms first-open cost was
~13 admission-scoped reads -- 9 realtime/handsfree readers + 2 direct realtime/
dictation reads + 2 pipeline reads, each re-entering the storage-admission scope
(~7 ms). Threaded an optional preloaded config mapping through the read path:
`console_voice_input._realtime_read(section, key, default, *, config=None)` reads
a dict key from the mapping when supplied and delegates to `get_cli_setting`
(byte-identical) when not; the 9 readers accept `config=`. `SpeechTTSSettingsPanel`
gained a `config_snapshot=` param and builds both drafts from one mapping. The
settings screen already loads `get_runtime_config_snapshot().values` one line
before constructing the panel (for the speech-TTS state), so it now passes that
same snapshot in -- the panel's first-open build reads ZERO additional config.
Constructed without a snapshot (test harnesses) the panel loads once. Snapshot
sections are plain dicts with env folded at load, so reads equal `get_cli_setting`.

AC#3 (probes): the launch cost is pinned by AC#1's splash single-read test; the
panel-open path is pinned gate-free in
`Tests/Chat/test_console_voice_input.py` (the reader config-path never touches
`get_cli_setting`, resolves flat + dotted sections, defaults on a missing key,
and matches the live read) and CI-covered by the Speech & TTS panel UI suite
(`Tests/UI/test_settings_speech_tts_panel.py`, ADR-126-gated locally).
