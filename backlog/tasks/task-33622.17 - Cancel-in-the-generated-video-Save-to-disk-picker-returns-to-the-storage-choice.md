## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Owner decision 2026-10-03. TASK-33622.15 documented that Escape or Cancel in the generated video's Save-to-disk picker discards the video without asking. The owner ruled that Cancel should return to the storage choice instead, so a generated (often paid) video is never lost to a dismissed file picker.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Cancel or Escape in the Save-to-disk picker returns to the storage choice with the generated video still available
- [x] #2 The video is discarded only by an explicit discard choice
- [x] #3 Ctrl+Q while the picker or its Replace / Destination-changed confirmations are open still asks before discarding the video
- [x] #4 The User Guide's video page describes the new Cancel behaviour
- [x] #5 Tests pin the return-to-choice path and fail on the previous behaviour

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Cancel or Escape in the generated video's Save-to-disk picker now returns to the storage choice with the same staged video; only an explicit discard (the choice's Discard, or Discard and quit when Ctrl+Q asks) throws it away.

- Fix (`UI/Console_Modules/video.py`, `_save_pending_console_video_external`): a cancelled picker returns False (the resolver's existing "back to the choice" answer, already used for failed saves) instead of None. None stays the lost-ownership answer, so a drain while the picker is open still closes the video. No new module, modal or CSS.
- Re-entry: the resolver's existing loop re-opens a fresh `ConsoleVideoCapacityModal` with the same reason/size/capacity, so the options are identical and a second cancel loops again. The same `PendingVideoArtifact` (one temp stream) stays registered; no operation, publication gate or deferred close is created by a cancelled picker, and the eventual save writes one file with no staging sibling. (There is no capacity reservation in this path; the publication gate is the nearest thing and is asserted absent.)
- #2998's quit guarantees are unchanged: the picker and Replace / Destination-changed screens are still `GeneratedVideoFileSave` / `GeneratedVideoConfirmation` with their `confirm_quit`; the re-opened choice keeps its own.
- Tests: new `Tests/UI/test_console_video_picker_cancel.py` (bootstrap_profile, real TldwCli + resolver + picker + choice): Escape -> choice (same three options, same live video), Ctrl+Q on the re-opened choice asks / Stay, a second round through the Cancel button, then a real Save writes the exact bytes as the only file; and a cancelled picker followed by Discard is the only thing that closes the stream. `Tests/Chat/test_console_video_capacity.py`: the old `..._picker_cancel_discards_without_card` pin is replaced by `..._picker_cancel_returns_to_the_storage_choice` (two cancels, then Discard; stream live at every screen) and `..._cancel_then_save_writes_the_same_staged_video`; five tests whose scripted picker ended in a cancel now end with an explicit "discard" (and one asserts every scripted screen was shown).
- Docs: `Docs/User_Guide/console/video.md` (cancel returns to the choice; only an explicit discard loses the video). This supersedes the TASK-33622.15 wording "cancelling the picker discards the video without asking".
