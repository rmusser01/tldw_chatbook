## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented the overflow-menu arm of NV-01; both AC prongs are met (no truncation at 140 cols; overflow destinations reachable via a consistent menu).

**What changed**

- New `UI/Navigation/nav_overflow_menu.py`: `NavOverflowMenu` modal lists all 13 destinations via `nav_button_label` (digit prefixes kept, so the menu doubles as shortcut documentation), suffixes the active destination with " (current)", posts `NavigateToScreen(primary_route)` on press, Escape dismisses.
- `UI/Navigation/main_navigation.py`: the static "More: Ctrl+P" hint is now a compact borderless `Button("More ▾", tooltip="All destinations")` docked outside the scroll strip. `_refresh_overflow_hint_visibility()` (on_mount timers at 0.05/0.25s + on_resize) shows it only when `strip.virtual_size.width > strip.region.width + reclaimable`, where `reclaimable` is the button's own width when displayed — so at 140 cols (134 needed) the button hides and Settings renders in full, while at <134 the button reappears and clipped destinations are one menu-press away. A zero-guard skips the toggle while layout is unsettled (a 0-width virtual size would otherwise misread as "fits" and pin the button hidden).
- Tests: `Tests/UI/test_screen_navigation.py` gains `test_nav_bar_no_destination_truncates_at_140_cols` (140×40: hint hidden, virtual ≤ region, every button edge inside the strip) and `test_nav_bar_overflow_menu_reaches_undigitized_destinations` (110×32: hint shown, menu opens, Lab/Logs/Settings rows plain, home carries "1 Home", console "(current)", pressing Logs posts `NavigateToScreen("logs")`, modal dismissed).

**Decisions / trade-offs**

- F7/F8/F9 shortcut arm rejected (plan item 3): a second hidden key vocabulary; the palette (Ctrl+P) already covers keyboard reach.
- NV-02 (Home card "Start a conversation"/"Set up Console model" verb swap) is deferred: AC #1 encodes NV-01 only, and the Home card slot is Home-screen onboarding (TASK-1508 lineage), not tab-bar chrome. Proposed follow-up: one constant label ("Open Console") with state carried by the card's status line instead of swapping verbs.
- The hint Button is deliberately NOT classed `nav-button`, so existing `.nav-button` selectors keep counting only destinations.

**Test fallout swept (pins updated for the Static→Button change)**

- 12 files: Static-typed lookups → Button label pins (`"More ▾"`); `"More: Ctrl+P" in screen_text` pins at ≥140-col sizes → `display is False` pins (hint hides when everything fits); nav-identity comparisons switched from `query(Button)` to `query(".nav-button")` so the new button doesn't add a phantom 14th destination; one overlap test at 140 cols now pins hint-hidden + Settings-fully-visible; the bare-app visibility test asserts inside the running app (widget `display` does not survive shutdown).
- Verified green: test_screen_navigation 80; visibility/master_shell/empty_setup 26; 3 unified-shell replays; first_run/navigation_smoke/keyboard_focus 16; focus_visual_sweep 5; visual_audit 4; destination_shells 104; phase6 release replay 1; gate1/phase3/latest-dev smoke 14.
