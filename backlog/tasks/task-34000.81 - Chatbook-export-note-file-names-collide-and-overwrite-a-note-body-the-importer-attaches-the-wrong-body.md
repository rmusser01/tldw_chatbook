## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: a bundle is a backup. `ChatbookCreator` names each note file `sanitize_filename(title) + ".md"` under `content/notes/`, so two notes whose titles sanitize to the same name write the same file: the second body overwrites the first, the export still reports success, and the manifest's second item points at a path the zip does not hold. On a case-insensitive filesystem (macOS, Windows) titles differing only in case collide ("Meeting notes 2026-09-30" and "Meeting Notes 2026-09-30" in the seeded Library); `"a/b"` and `"a:b"` both sanitize to `ab.md` on every filesystem. On import the first item receives the second note's body and the second item fails as "Note file not found" -- one body lost, one body attached to the wrong note.

Observed on TASK-34000.31's live walk (2026-10-24, isolated profile, 122-note bundle): `04-bundle-inspection.txt` shows `MISMATCH content/notes/Meeting notes 2026-09-30.md 'Meeting Notes 2026-09-30' 'Meeting notes 2026-09-30'` and `MISSING FILE content/notes/Meeting Notes 2026-09-30.md`. The front matter now written by TASK-34000.31 carries the note `id`, which gives the importer a way to detect the mismatch.

Pre-existing; found while verifying TASK-34000.31 (N-20). Review finding(s): fix round 1, M5.
