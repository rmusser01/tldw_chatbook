## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Phase 2 capture triage reproduced this in Settings ▸ Providers & Models ▸ Provider. Type 'llama', Tab into the list and press Enter on a provider. The Provider control still holds the typed filter 'llama', and the filtered list stays open and framed. The same happens after r ▸ Discard changes. The list's focus frame covers the first cell of every row ('lama.cpp', 'ocal Llamafile'), and its right edge is clipped. At 211x44, origin/dev 89dd84943a behaves the same way, so the defect predates Phase 2.

task-33007.2 AC#3 fixes the lost first character. This rider covers what is left: the leftover filter text and the clipped frame.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
TASK-33007.2's rebuilt Provider control already behaved as AC#1-#3 ask for every name narrower than the control. One case did not, and this task fixes it: a display name as wide as the control's text area or wider lost its head. The task also adds the tests that were missing and records how AC#3 is read.

The fix (review round 1, finding I1): the control's text area is 33 cells at 211x44 and 235x52, and "Text Generation WebUI (Oobabooga)" is exactly 33. Textual's Input keeps one cell for the caret after the last character and scrolls to it, and every select-all left the caret there. So once the control was focused, or that provider chosen, it read "ext Generation WebUI (Oobabooga)", and it stayed that way after focus left. A wider custom-endpoint name showed only its tail. The control now selects its name with the caret at the head (on focus, on the click that focuses it and after a choice), and a control without focus is put back on the head each time its name is re-synced, so a caret the user left at the end does not keep the row scrolled. Typing still replaces the whole name.

What was checked, in a mounted Settings with the real stylesheet:
- AC#1: after Enter on a filtered row the control shows the provider's display name and the list is closed. That holds for a legacy alias ("llama.cpp (legacy alias)", the second reference capture), for the provider the form already holds (nothing is staged there, so only closing the list restores the name) and for "Enter provider ID".
- AC#2: r, then Discard changes, puts the saved provider's name back, closes the list, and rebuilds it unfiltered with the saved provider highlighted. The same holds when the Inspector's Revert (r) button is clicked while the list is still open on a filter.
- AC#3: at 211x44 and 235x52 the open list's whole box, its scrollbar included, lies inside the card's content area and no ancestor clips it, for the full list and for a short filtered one.

Ruling: AC#3 is read on the list's box, and no frame is added. The AC was written against the old framed list, whose right border was clipped. TASK-33007.2 removed that frame on purpose (the spec's "one frame level"), so there is no border left to clip. Cost if wrong: one CSS rule gives the list a border; the new test is frame-agnostic and would still apply, and TASK-33007.2's held-click test, which finds its row by exact text, would need re-pinning.
