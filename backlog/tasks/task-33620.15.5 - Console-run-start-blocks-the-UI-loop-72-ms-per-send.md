## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the same live profile as TASK-33620.15.3 (2026-10-10; 160x45, Anthropic haiku through the review proxy; main-thread samples every 4 ms inside UI-loop callbacks between acceptance and the provider call).

Run start (`ConsoleRuntime._run_custodied_turn` > `submit_draft`) holds the UI loop for 72 ms per send over 30 sends, and 169 ms on the first send after a launch (5 sends). By samples:
- `PromptHistory.append`'s two guarded config operations (`default_prompt_history_path`, storage admission): about 12 ms per send;
- the MCP catalog fingerprint (`run_catalog_fingerprint`, `catalog_fingerprint` across the unified, local and permission stores): about 19 ms;
- first sends only: lazy imports (`console_visual_transcript`, the hooks `lifecycle` module, the MCP `server` module AST) about 25 ms, the full MCP composition (`effective_tool_states`, `local_external_catalog`, `get_external_servers`, `get_kill_switch`), and `_serialize_provenance`.

TASK-33620.15.1 covers the MCP composition's storage-admission cost per call; this task covers the rest of run start's loop time.

Fix direction: pre-import the lazily imported modules at idle; memoise `PromptHistory.append`'s guarded config operations; yield to the loop between the composition's reads.
