## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Capture provider call boundaries, dispatch uncertainty, responses, tool-loop chronology, retries, and failures through durable pre-dispatch reservation and idempotent settlement.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Capture On durably reserves a call and persists `dispatch_started` before any provider adapter may transmit bytes.
- [x] #2 Calls transition only through the reserved states `reserved`, `not_dispatched`, `dispatch_started`, `dispatch_unknown`, `response_started`, and terminal outcomes, with invalid transitions rejected.
- [x] #3 Streaming and non-streaming providers, llama.cpp, retries, cancellations, exceptions, and multi-call tool loops all use the same reservation and settlement boundary.
- [x] #4 Every provider-adapter entry seam is inventoried; sensitive auxiliary completion is explicitly admitted as Capture Off or governed by a separately approved trace policy.
- [x] #5 Response payloads and tool events are appended in coherent call order and link to a verified exact assistant revision when available, otherwise to a labeled sanitized response artifact.
- [x] #6 Settlement is idempotent after crashes or duplicate completion signals and unresolved dispatches remain visibly uncertain rather than silently disappearing.
- [x] #7 No provider call can bypass the trace gateway while Capture On is active.
- [x] #8 Targeted benchmarks meet reservation p95 at or below 10 ms with max 50 ms and settlement p95 at or below 25 ms on the ADR fixture.
- [x] #9 ADR required: yes; this task implements the provider/runtime boundary in ADR-097.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Inventory the existing call lifecycle repository APIs, every provider-adapter entry seam, capture admission and pause behavior, assistant persistence seam, cold-start recovery path, and latency fixture; pin the inventory with focused tests before production edits.
2. Under strict TDD, add one durable Capture On reservation boundary that reconciles immutable idempotency identity, binds the verified surface/header or explicit incomplete marker, commits dispatch_started before adapter entry, and fails closed into Retry or a separately admitted one-shot Capture Off path.
3. Route streaming, non-streaming, llama.cpp, fallback retries, cancellations, exceptions, and multi-call tool loops through the same token-gated adapter seam; keep sensitive complete_auxiliary calls explicitly Capture Off and keep the normalized writer user-facing gate hard-off.
4. Under strict TDD, add idempotent response_started and terminal settlement, exact assistant-revision comparison with sanitized response-artifact fallback, bounded retry after post-dispatch persistence failure, and monotonic cold-start recovery for reserved, dispatch_started, and response_started calls.
5. Add the pinned five-database latency benchmark for reservation/dispatch_started and off-UI-thread settlement, then run targeted lifecycle, gateway, persistence, privacy, inventory, packaging, static, and independent spec/quality review gates.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented the ADR-097 provider/runtime trace boundary end to end.

- Added durable pre-dispatch reservation, verified request binding, dispatch uncertainty, response-started and terminal state enforcement across streaming, non-streaming, llama.cpp fallback, retries, cancellation, exceptions, and tool loops.
- Added exact assistant-revision verification with labeled sanitized response-artifact fallback, idempotent settlement, bounded retry, monotonic cold recovery, and a cap-64 off-UI settlement scheduler with race-safe teardown and progress-preserving overflow handling.
- Inventoried provider entry seams and retained explicit Capture Off admission for sensitive auxiliary completion.
- Added the five-database reference benchmark and fixture v4. Critical reserve, bind, and response-started writes defer auto-checkpoint only for their connection-local transaction and restore the exact caller setting; terminal settlement remains the bounded off-UI checkpoint owner. ADR-097 documents this policy.
