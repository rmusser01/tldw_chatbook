## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make the shared Prompt block editor accept the single canonical Additional-context block produced locally by a valid Recipe fill while continuing to reject user-authored or malformed use of the reserved Additional-context ID namespace.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A valid `PromptImprovementService` Recipe-fill result with non-empty `additional_context` mounts in the shared Prompt editor for mandatory review instead of raising a reserved-ID error.
- [x] #2 A Prompt definition may contain at most one exact `additional-context` block and only in the User lane; its editable title, syntax, content, and position survive editor rebuilds.
- [x] #3 Recipe definitions, System-lane blocks, duplicate exact IDs, suffixed/prefixed reserved IDs, and user add/rename attempts remain rejected by the reserved Additional-context namespace guard.
- [x] #4 Focused service/editor/modal/native tests and adjacent structured-artifact, provider/privacy, menu/workbench, lint, compile, and diff gates pass without changing provider calls, Prompt storage, navigation, or Task 13 governance.
<!-- AC:END -->
