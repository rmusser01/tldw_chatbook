## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Library Notes `[[` link picker (TASK-34000.11) is placed with `position: relative` + `overlay: screen` +
`styles.offset`, so every anchor pass has to re-derive the widget's flow slot from `region − last offset` before it
can compute the next offset, and the very first open — before the box has a laid-out region — has to GUESS an
absolute offset for one frame. That bookkeeping cost fix round 2 an off-screen box (offset (-72, -57) measured when
two passes ran in one frame) and fix round 4 a frame painted at y=72 on a 45-row screen (a `visibility: hidden`
widget is not in the compositor map, so its flow slot could not be read).

Textual's tooltip mechanism places a screen overlay by `absolute_offset` instead: the widget's top-left is the given
screen cell, with no flow slot to subtract. The Console already does this — `Widgets/Console/console_selection_menu.py`
(lines 1–15 explain the rule), `console_message_more_menu.py:138`, `console_workspace_action_menu.py:228`, and
`Widgets/persona_buddy_widget.py:913-921`. Moving the picker to the same mechanism removes the `region − last offset`
bookkeeping, the one-anchor-pass-per-refresh guard it needs, and the first-open guess.

Fix round 5 of TASK-34000.11 ruled that a terminal resize CLOSES the picker (no re-anchor survives one), so this
task is about the steady-state open, narrow, scroll-follow and the first frame — not about resizes.
