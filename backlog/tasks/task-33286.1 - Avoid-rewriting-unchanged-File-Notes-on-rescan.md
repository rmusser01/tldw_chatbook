## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Reopening an indexed File Notes folder repeats replica and search index writes for every unchanged file. Show the complete confirmed folder sooner while keeping disk authority and replica repair.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A healthy rescan of unchanged files does not rewrite their replica rows or search entries.
- [x] #2 Changed bytes, tombstones and missing, stale or duplicate search entries still repair through the existing path.
- [x] #3 Paired Terminal runs record activation to visible File Notes, loop gaps and ordinary quit on the same seeded folder.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Pin needless writes and existing repair with a real replica fixture.
2. Index each scanned root’s search rows once and use them only to verify unchanged live bytes and search text under the existing SQLite guard. Keep disk reads, cancellation, recovery and the current repair path.
3. Verify Notes and recovery tests plus three paired Terminal activations of the same populated folder.

ADR required: no
ADR path: N/A
Reason: Existing ADR-296 and ADR-351 already govern disk authority and replica retention. This change keeps the schema, access, storage owner and recovery behavior.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
FileNotesService and FileNotesReplica skip writes after checking exact disk bytes, live replica metadata and the matching indexed text. Existing repair covers changed bytes, damaged replicas and reappearing tombstones. A second-connection write after the lookup also took the repair path.

Three paired 995-file Terminal runs dropped median first paint from 2868.2 to 2262.2 ms. All six sessions quit normally with no fixture database descriptors. Evidence and the original 50/100 ms limits are in Docs/QA/console-library-responsiveness/README.md. Broader qualification and hosted checks remain open.
