## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
An A/B toggle takes 16-20 keys today because nothing remembers what the user ran before (report.md issue 6). Synthesis rule 6 and spec §4 rule 6 forbid a new store, and spec §10 rules out schema migrations and new indexes, so recents must come from data that already exists:
- list_all_active_conversations (DB/ChaChaNotes_DB.py:11160) returns conversations newest first with a LIMIT, but only for global scope (scope_type = 'global', :11208).
- get_conversations_metadata_by_ids (:11306) reads metadata in batches of up to 500 ids.
- parse_console_generation_settings (Chat/console_generation_settings_metadata.py:240) parses the ADR-095 snapshot and fails closed on malformed or future-version objects.

Open chats, including temporary ones that were never persisted, contribute only through the live session store. Workspace-scoped chats that are not open therefore do not appear in RECENT.

The read must stay off the UI loop and be bounded; the Fedora lag program found blocking calls on the UI loop before. Favourites and pins wait until user testing shows that PREVIOUS plus RECENT is not enough.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] #2 PREVIOUS is the most recent pair for this chat other than the current one, falling back to the most recent pair overall. After switching from A to B, PREVIOUS is A; after switching back, it is B.

- [x] #6 No schema change, index, config key or new persisted store is added.
- [x] #7 The User Guide says that recents come from open chats and recent global-scope chats, and that workspace chats appear only while open.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**What it is.** A new module, `tldw_chatbook/UI/Console_Modules/model_switcher.py`, which later Phase 4 tasks grow into Switch model. It holds only the recents data and does no rendering. Nothing imports it yet, so the `_ui_ready` census is unchanged (R17: openers import it lazily).

- `read_recent_model_pairs(db, sessions)` (async) returns RECENT as distinct `ModelPairUse(provider, model, last_used)` rows, newest first. It runs `persisted_model_pair_uses` in a worker thread through `run_owned_db_call`. That function makes one `list_all_active_conversations(limit=50)` call (global scope only) and one `get_conversations_metadata_by_ids` batch, parses each row with `parse_console_generation_settings`, and skips the rows of chats that are open. Rows whose snapshot is absent, invalid, from a future version or carries no model are dropped (fail closed). The open sessions, temporary chats included, are read on the caller's thread before the first await. A failed read logs the exception type at debug level and keeps the open sessions' pairs.
- Last use of an open saved chat (review fix round 2). An open chat counts only through its live session's `updated_at`, which sending moves; `add_message` never touches the row's `last_modified`, so the row cannot stand in for an open chat. A chat reopened from Sessions (or woken at launch, or opened in Buddy) used to start with `updated_at` = the time it was opened, so an old chat jumped to "used just now". `hydrate_console_session` (Chat/console_conversation_hydration.py, the one caller all three reopen paths share) now stamps the new session's `updated_at` from the row's `last_modified`, as a chat restored at startup already keeps its saved `updated_at` (UI/Console_Modules/session.py). Both resume paths now agree, and this also covers workspace chats, chats older than the 50th and chats with no snapshot. The stamp lives in the caller, not in `restore_persisted_session`, because console_chat_store.py is over its module-size row on dev. Round 1's matched-pair rule (the stored row wins while the pair is unchanged) is gone: it made an open chat's messages invisible to RECENT.
- Side effect, intended: the conversation switcher and Sessions list sort open chats by `updated_at` and derive their age from it, so a chat just reopened now shows its row's age instead of "just now" until it is used. The agent-created-chat path (chat_screen.py) calls `restore_persisted_session` directly for a row it just created, where the open time is the row's time, so it is unchanged.
- `ModelPairUse.used_label(now)` returns the last-use text, for example "used 2h ago" or "used 2h ago in this chat". It reuses `console_environment_state.relative_age` and prints "used just now" under a minute.
- `PreviousPairMemory` / `PREVIOUS_PAIRS` keep PREVIOUS in process memory, keyed by session id (R5). `record_switch(session_id, before, after)` stores the replaced pair; a no-op switch or a model-less pair is ignored. `previous(session_id, current, recent)` returns that pair, or RECENT's newest pair other than the current one.

**Wiring contract for TASK-33004.4 and .5.** Open the switcher at once and fill RECENT from `await read_recent_model_pairs(app.chachanotes_db, store.sessions())` in an async worker, once per open and never per Find keystroke; each call pays about 45 ms of connection setup off the loop. PREVIOUS is `PREVIOUS_PAIRS.previous(session.id, (provider, model), recent)`. A switcher commit that changes the pair calls `PREVIOUS_PAIRS.record_switch(session.id, before, after)`. Known limit (R5): a pair change made in Chat settings is not recorded until P6, so PREVIOUS then falls back to RECENT.

**ACs #1-#3 are open until the switcher is wired.** Each AC has a data half, which this task proves, and a UI half, which needs later tasks. All three are held to the same standard (review fix round 1 unticked #1 and #2):
- #1: data proven by the merge, open-chat, reopened-chat and label tests. The RECENT rows and their last-use text are rendered in TASK-33004.4.
- #2: `PreviousPairMemory` is proven by the toggle and fallback tests. A switcher commit calls `record_switch` in TASK-33004.5 (or wherever the commit lands).
- #3: `test_read_runs_off_the_ui_thread_without_blocking_the_loop` blocks the DB call on a worker thread while the event loop keeps ticking. `test_persisted_read_is_bounded_to_fifty_with_one_metadata_batch` pins one listing (`limit=50`) and one 50-id metadata batch. The switcher being usable before the read ends, with the group filling in afterwards, arrives in TASK-33004.4.

The review of those tasks ticks these three ACs, and this task then moves to Done.

**Timing (AC#5).** Measured on a file DB of 10,000 conversations seeded through `add_conversation`: 9,000 global chats with snapshots over 40 pairs, 500 workspace chats and 500 with no snapshot. The DB file was 27.4 MB, with no `sqlite_stat1`. Python 3.12.11, Apple Silicon.
- The read itself (`persisted_model_pair_uses`): 1.22 ms cold; warm median 0.65 ms, p95 0.77 ms.
- End to end (`read_recent_model_pairs`, including the worker hop): median 43.5 ms, maximum 47.0 ms. Almost all of that is the worker thread opening a fresh connection under `operation_owned_connection`: `SELECT 1` through the same path costs 42.7 ms, and the hop alone costs 0.03 ms. This is the per-call connection cost the 2026-09-27 performance audit names. None of it runs on the UI thread.
- Listing plan: `SEARCH conversations USING INDEX idx_conversations_archive (archived=? AND deleted=?)`, an existing index.

Re-measured after review fix round 1 on the same seeding (fresh 27.4 MB DB):
- The read itself: 1.70 ms cold; warm median 0.79 ms, p95 1.01 ms.
- End to end: median 50.1 ms, maximum 54.6 ms. Of that, 48.3 ms is the fresh-connection `SELECT 1` and 0.03 ms is the hop.
- Plan unchanged.

The fix adds no query. The spread against the first run is the per-call connection cost. Fix round 2 returns the read to its first shape (open chats' rows skipped by id, a list of uses) and adds no query; the reopen stamp parses a `last_modified` value the reopen already holds, so it was not re-timed. The timing scripts are local only: `.superpowers/` is gitignored, so they are not in the repository.

**AC#6.** The diff touches no schema, migration, index, config key or store. PREVIOUS is a dict in process memory. `Docs/security/production-diagnostic-inventory.json` gains one row for the new module's single debug call; it was reviewed with `--statements` and logs only the exception class name.

**AC#7.** Docs/User_Guide/console.md now explains where RECENT and PREVIOUS come from: open chats (temporary ones included) and the 50 newest global-scope chats. It says that workspace chats appear only while open, that damaged or newer-version settings are skipped, that RECENT fills in after the list opens, and that PREVIOUS is remembered while the chat stays open (fix round 1: the memory is keyed by session id, and a chat reopened from Sessions is a new session).

**Tests.** The ten tests in `Tests/Chat/test_model_switcher_recents.py` all pass. That directory, unlike Tests/UI, does not import the app per test, so the tests run cleanly locally. The fail-closed test uses a real in-memory DB. The merge, open-chat, reopened-chat and off-thread tests use a real file DB, because an in-memory ChaChaNotes DB is per thread and a worker would see an empty schema. `test_an_open_chat_with_an_unchanged_pair_counts_at_its_live_use` is the round-2 reviewer's scenario (chat A open on its stored pair, row 1 day old, used 1 minute ago; chat B 3 hours old): A sorts first as "used 1m ago" and is chat C's PREVIOUS fallback. `test_a_chat_reopened_from_sessions_keeps_its_stored_last_use` reopens a real row through `hydrate_console_session` and asserts the stamped `updated_at` and the RECENT order.

Mutants (each fails at least one test):
- no stamp in `hydrate_console_session` (fix round 2): the reopened-chat test fails;
- round 1's matched-pair rule: the open-chat and merge tests fail;
- reading on the loop thread;
- a limit of 60;
- PREVIOUS ignoring its memory;
- open chats' stored rows not skipped: the merge test fails.

A blank-model mutant survives because it is equivalent: the parser's `_nonblank_string` validator already rejects a blank model.
