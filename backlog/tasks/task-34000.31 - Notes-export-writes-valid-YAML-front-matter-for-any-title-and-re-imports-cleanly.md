## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: a researcher (Priya) exports notes to use them in Obsidian, Pandoc or a static-site tool, and research titles routinely contain colons. Every exported note with an ordinary title such as 'Paper notes: Retrieval practice' or 'Trip planning: Lisbon' carries front matter that a YAML parser rejects. Those tools then fail on the file or read it wrongly. The app cannot read its own export back either.

What was observed: the bundle file and the single-note 'Export Markdown' file for 'Trip planning: Lisbon' both fail yaml.safe_load with 'mapping values are not allowed here'. A title starting with '*' fails with an alias error ('while scanning an alias'), and a leading quote also breaks parsing. A '#' in a title silently turns the rest of the value into a comment, so the parsed title is wrong or null. Re-importing both files through Add from files > Import once went wrong too. The bundle file was previewed as 'Create 1 new note: Lisbon, 3 days', both imported bodies kept the raw '---' block as text, and the single export's keyword 'travel' was not restored. The note text itself survives, which is why this is P2.

Verified cause: both export paths write each front-matter value unquoted with string formatting. The bundle path writes the title at Chatbooks/chatbook_creator.py:1465 and the tags as one comma-joined string at :1469. Single-note export does the same in build_note_export_content (Library/library_notes_state.py:880, title at :915, keywords as a comma-joined string).

Suggested direction: one shared front-matter renderer that serializes with a real YAML dumper (imported lazily), used by both paths. Tags and keywords become YAML lists. Round-trip tests go through a standard YAML parser and through the app's own Markdown importer (_split_frontmatter, Notes/note_import_parsers.py:557). Keyword loss inside export bundles is finding L-04, owned by TASK-34000.19, and out of scope here. This task only makes what is written valid and readable.

Review finding(s): N-20. Source: qa/notes-library-ux-review-2026-10-02/report.md
