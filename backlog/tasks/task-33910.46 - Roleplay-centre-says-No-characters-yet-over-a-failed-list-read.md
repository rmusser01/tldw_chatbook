## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Fixed in burn-down PR 3 of the B2b follow-ups, with TASK-38228 and TASK-33910.37.

- **On dev (29592ecc9b):** `_characters_empty_guidance_text` never consulted `_character_list_failed`. A failed read commits total 0, so with nothing open the centre said "No characters yet — use New or Import to add one." over the list's "Characters could not be loaded." row. This PR fixes it.
- **Fix:** with the read failed, the centre reads "Characters could not be loaded — use **Retry** to read the list again."
  - It opens with the list row's own sentence and points at the row's Retry, the way the empty copy points at New and Import.
  - The centre gets no Retry button of its own. Spec R25 gives the work pane's `PersonasKindEmptyState` the actions when B5b-2 builds it, and that card should carry a failure state.
  - A successful empty read still says "No characters yet …".
- **Tests (`Tests/UI/test_roleplay_item_list_app.py`):**
  - `test_a_failed_server_read_says_so_in_the_centre_and_an_empty_one_does_not` is RED on dev at the centre assertion. A server read failure already reached the failure row on dev, so it isolates this bug from TASK-38228. A Retry that then succeeds with no rows brings "No characters yet" back.
  - `test_a_database_fault_shows_the_recovery_row_and_the_centre_says_so_until_retry` covers the local DB fault.
  - `test_a_successful_empty_read_still_says_no_characters_yet` uses a fresh DB with its built-in card deleted. It passes on dev, as a guard.
  - The over-reach mutation (failure copy whenever the total is 0) turns the two empty-read assertions red.
- **User Guide:** `Docs/User_Guide/roleplay-chat-dictionaries.md` gives the centre copy.
- **Ratchet:** `personas_screen.py` grows; its ratchet row is raised in the same commit, with a dated owner-decision comment.
