## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Credential resolvers disagree on whether an environment variable or the stored `api_settings` key wins. The hosted provider engine (33 presets) resolves explicit, then environment, then stored, citing an env-first repo rule; moonshot, zai and qwencloud resolve explicit, then stored, then environment; the custom-endpoint registry resolves environment then stored. CLAUDE.md states the stored key outranks the environment variable. A user with both set gets a different key depending on the provider family. Which order is correct is an owner decision; this task records it and makes every resolver follow it.

**Owner decision (2026-10-25): environment keys take priority when set.** The order is: a call-time explicit key, then the provider's environment variable when it is set to a usable value, then the stored `api_settings.<provider>.api_key`, then the legacy `[API]` value. This reverses the rule CLAUDE.md currently documents for the bridged chat providers ("an explicit `api_settings.<provider>.api_key` now outranks the matching environment variable", made uniform by PR-T2/task 7). Those handlers, moonshot, zai and qwencloud change behaviour; the hosted provider engine already follows the decided order. Readiness must use the same order as the spend path, so the Console readiness check and the key actually sent never disagree. A caller that pre-resolves the stored key and passes it as the explicit argument must not bypass a set environment variable. Placeholder and whitespace-padded values stay rejected at every step (`resolve_provider_api_key`). Today the engine fails closed on an unusable stored key even when a usable environment variable is set (`hosted_provider_engine.py` `_resolve_api_key`). Under this decision the environment key is used, and the unusable stored value is surfaced as a readiness warning, not an error.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F11; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
