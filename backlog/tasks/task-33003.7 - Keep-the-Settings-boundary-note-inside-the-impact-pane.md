## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The Scope Inspector's boundary note now sits fully inside the inspector's visible window at rest, at 140x42, 211x44 and 235x52, under the production stylesheet. The strict TASK-25890 xfail is removed, and task-25890 is closed.

**Root cause (measured under the production stylesheet).** Two separate causes. (1) At 211x44 the Overview inspector's field rows each carried a blank row below them (`#settings-impact-pane .settings-detail-row { margin-bottom: 1 }`), 7 rows in all, so the note's last row ("destinations") fell below the fold: note 37..40, visible window 17..39. (2) At 140x42 the pane's `2fr` share is 25 columns (an 18-cell text column), so each row wrapped 4-5 times and the note sat at y=55, below a pane that ends at 40. At 235x52 it already fitted.

**Fix.**
- `css/features/_settings.tcss` (regenerated into `screen_agentic_settings.tcss` by `build_css.py`): the blank-row override is deleted, so inspector rows use the one-row rhythm (spec §6). The pane gets `min-width: $ds-size-36` (the spec's Inspector width) through a new `.settings-inspector-floor` class.
- `UI/Screens/settings_screen.py`: `SETTINGS_INSPECTOR_FLOOR_MIN_WIDTH = 42 + 56 + 36` (134). The floor class is set at compose time and in the existing `_sync_responsive_workbench`, beside the compact-workbench classes and following the same pattern. From 134 columns the detail pane keeps 56 columns (a 24-cell label plus a 20-cell field), and below that it keeps its width first. The floor binds only between 134 and about 186 columns; at 211 and 235 it has no effect (the inspector is 43 columns).
- Ruling: a width-gated class instead of pure CSS. Why: Textual CSS has no width condition, and a static floor starved the detail pane at 120 columns (Model/Endpoint 6 editable cells, Network CA path 7; `test_settings_compact_fields` goes red, reproduced). Cost if wrong: about 12 Python lines in settings_screen.py (which has no size ratchet row), plus a 12-column step in the detail pane between 133 and 134 columns.
- No inspector row is reordered or removed (ruling 17).

**Tests** (Tests/UI/test_destination_visual_parity_correction.py):
- The settings param of `test_runtime_and_settings_default_states_preserve_workbench_geometry` is no longer xfail.
- `test_settings_boundary_note_is_fully_visible_at_rest[140x42|211x44|235x52]` is a stronger check than the contract. The contract accepts a note whose top row sits under the fold hint (a `$ds-size-34` floor passes it with the note hidden, reproduced). This test requires the whole note inside the body's `scrollable_content_region`.
- `test_settings_inspector_floor_yields_to_the_detail_pane_when_narrow` resizes 140→120→140 and checks that the class follows in both directions.
- `test_settings_inspector_rows_stay_reachable_in_every_category[211x44|235x52]` covers AC#3: in every category, the pinned header fits and no row is wider than the pane, and after scrolling to the end the last body row is inside the window.

- Negative controls: floor only → rest at 140 and 211 plus the contract fail. Margin removal only → rest at 140, the contract and the floor test fail. A static floor → all 4 test_settings_compact_fields cases fail, as does the floor test (5 of 7).
