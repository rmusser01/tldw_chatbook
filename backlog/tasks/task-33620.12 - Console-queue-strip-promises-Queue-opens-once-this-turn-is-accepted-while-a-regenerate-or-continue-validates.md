## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
From the PR #2948 (TASK-33620.4) checkpoint review. The prompt-queue coordinator decides preparing_before_acceptance from run status alone (VALIDATING/RETRYING and not yet accepted, console_prompt_queue_coordinator.py around preparing_before_acceptance). It does not check for a prompt chain. regenerate_message sets VALIDATING ('Validating provider.'), so during a regenerate or continue's validation window the composer strip still reads 'Queue opens once this turn is accepted'. A regenerate or continue never opens the queue, so this is the same false promise TASK-33620.4 removed for the streaming phase. The User Guide's 'once one is streaming' wording is accurate, but the QUEUE_REASON_* comments in console_display_state.py over-claim.
