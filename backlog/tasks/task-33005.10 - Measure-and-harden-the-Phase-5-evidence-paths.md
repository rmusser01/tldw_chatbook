## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Deferred items from the Phase 5 final review triage, none a user-visible defect today:
- Cost: a readiness build with evidence present is unmeasured on the warm switch path, and the modal identity resolves readiness on every call (Task 1 M-4, Task 2 M-2).
- Threading: `_BEGIN_ORDER` (provider_test_evidence.py) is an itertools.count with no lock; fine under the GIL, unproven on a free-threaded build the owner plans for.
- Design debt: Save rebuilds the saved identity instead of persisting `semantic_identity`; Settings duplicates the snapshot model-facet logic (settings_screen.py, Task 3).
- Test gaps: no keyed Settings -> Chat settings case (Task 1 M-5); `test_closing_mid_probe_raises_nothing_and_a_late_result_loses` cannot fail on a raise (the worker swallows it); `test_model_summary_sync_invalidates_mounted_context_allocation` passes without its allocator assert biting (Task 3).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The evidence paths are measured and hardened: begin order is allocated under a lock, the warm readiness build's rise with evidence present is memoized away, Settings and the snapshot share one model facet, and the three named test gaps each have a test that fails when the behaviour breaks.

AC#1 (measured, then memoized). A warm `build_console_settings_readiness` (median of 7 x 4,000 builds, same settings and config) took 10.0 us for llama.cpp and 24.8 us for OpenAI with no evidence owner or an empty one, and 33.7 / 53.4 us with a record for the connection (30.8 / 48.1 us with a record for another one): keying the connection (`_console_connection_identity`) parsed the endpoint three times (`effective_provider_endpoint`, `canonical_connection_identity`, and the `ProviderDraftIdentity` canonical check), most of the rise. TASK-18909 counted about 400 builds per warm switch, so roughly 10 ms a switch. `resolve_provider_endpoint` is now memoized for plain string inputs (`lru_cache(256)` over the unchanged body): its result is a frozen pure function of two strings, and a value that could carry a secret (user info, a query, a fragment; refused anyway) is never a cache key. After: 15.0 / 30.8 us with a record (12.3 / 28.1 us for another connection's), the no-evidence build unchanged; the remaining ~5 us is the key digest, the owner lookup and its `replace`. Test: `test_a_warm_readiness_build_with_evidence_parses_no_endpoint` counts calls of the unmemoized body during a warm evidence-present build (0; 3 with the memo bypassed), and `test_endpoint_parsing_memo_skips_values_that_can_carry_a_secret`. The modal identity resolving readiness on every call (the description's Task 2 M-2) is in console_settings_modal.py, which is not this task's file in Wave 5 and is not an AC: not changed.

AC#2. `_next_begin_order()` takes `_BEGIN_ORDER_LOCK` around `next(_BEGIN_ORDER)`; both token classes use it. `test_begin_order_allocation_waits_for_its_lock` holds the lock and sees a begin on another thread wait (fails without the lock, on any build). `test_concurrent_begins_across_stores_never_share_an_order` begins 3,200 probes from eight stores on eight threads and requires distinct, gap-free orders; under the GIL it passes without the lock too (`next()` is atomic there), so its negative control is a read-yield-write allocator, which it fails (`[2, 2, 3, 3, ...]`).

AC#3. Premise partly stale, as the plan said. Save already passes `setup_mutation.semantic_identity` to `rebase_after_save` (since 95857a454f). The one rebuild left, `replace(tested_identity, credential_source=...)`, is TASK-33005.4's no-endpoint fallback (257b4c1781): `build_provider_setup_mutation` issues no semantic identity when no endpoint is saved, and `_validate_provider_setup_mutation` rejects one without endpoint keys, while the rebuilt identity takes every field from the same draft the mutation was built from. That half is closed with this evidence, not changed (changing it is a persistence-contract change in provider_setup_persistence.py, outside this task). The model-facet half is done: `model_facet(model, endpoint, model_ids)` in provider_test_evidence.py is the one derivation; `ProviderReadiness.snapshot` and Settings' `_provider_test_rows` both call it (settings_screen.py -5, row 35,777 -> 35,772). A whitespace-only model now reads "missing" in the Settings word as it did in the snapshot. Test: `test_settings_and_the_snapshot_derive_the_model_facet_one_way`.

AC#4, each with its negative control:
- Keyed Settings -> Chat settings: already at HEAD, as the review M-5 case `test_settings_test_result_reaches_chat_settings_for_the_same_connection[stored-key]` (Tests/UI/test_settings_provider_test_draft.py), so no new file was needed; but no lane ran it. With Chat settings keying revision 0 again (the M-5 bug), it fails (`assert None is not None`); keyless and stored-source-without-key still pass. It joins the UI PR census as a node.
- `test_closing_mid_probe_raises_nothing_and_a_late_result_loses`: the probe swallows a raise (`one()` logs it) and the switcher's worker does not exit on error, so "the newer result stands" also held when the late probe crashed before settling. It now records the owner's publishes for the llama.cpp connection (Ollama is probed too) and requires the late refused result to be offered and lose (`("unreachable", False)`, never `True`), and no probe worker to end in error. With the late probe raising, the old body passes and the new test fails ("never happened"); with the owner ignoring begin order, both fail.

Rewritten on purpose: the mutation shows the hidden readiness line, the section's demand and height must grow by the same rows, and the credential poll is stopped first. With the summary sync's `_request_console_context_allocation_reconcile()` removed it fails (`assert 5 > 5`: the section keeps its height and clips the word).
Both rewritten tests run under `private_profile_test`, so they reach their assertions here. Negative controls on private-profile tests were source edits reverted after the run (a parent-side plugin never reaches the child; lesson added to lessons-testing-evidence.md).
