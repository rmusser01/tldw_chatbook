## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
`model_switcher._switcher_sources` returns a `SwitcherSources` TypedDict (the eight `ConsoleModelPopover` keyword arguments it supplies, typed with the popover's own seam aliases, imported under TYPE_CHECKING only), so both `**_switcher_sources(...)` calls lost their `# type: ignore[arg-type]`, and the inner `connection_prober` lost its `no-untyped-def` ignore.

The precise type surfaced two real mismatches, both fixed without a cast:
- `PairUse` (console_model_popover.py) declared `provider` and `model` as settable attributes, which the frozen `ModelPairUse` dataclass cannot satisfy; they are now read-only properties.
- `PreviousPairMemory.previous` took `Sequence[ModelPairUse]`, but the popover hands its `previous_pair` the `Sequence[PairUse]` it holds. It now takes and returns `PairUse` and compares `(use.provider, use.model)`, which is what `.pair` returned. Same objects at runtime, same behaviour.

Evidence (mypy is not in CI, so this is the check): `mypy model_switcher.py console_model_popover.py` (repo config, scratch cache). At the base with only the two call-site ignores deleted it reports 22 `arg-type` errors on the two `**_switcher_sources(` lines; at head it reports none there. The 6 errors left in the two files are the base's own (`detected` typed `str | None` in `_open_switcher`, three in the popover), unchanged.

Behaviour: Tests/Chat/test_model_switcher_recents.py, Tests/UI/test_console_settings_model_change.py (the pick-mode tests) and Tests/UI/test_console_model_switcher.py, xdist `-n 6 --dist loadfile`: 149 passed. That run lists Tests/UI/test_app_instance_warning.py first, which imports the app at collection time as the CI UI shards' other files do; without it every test_console_model_switcher.py node errors at setup with the local `RecoveryRequired: raw_source_selection_changed` noise, at the base too.

Modified: tldw_chatbook/UI/Console_Modules/model_switcher.py, tldw_chatbook/Widgets/Console/console_model_popover.py.
