## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: TASK-34000.24 made every Library "Use in Console" hand-off link the item to the active workspace and name that workspace in the receipt. The label comes from `_library_source_workspace_label` (`Workspaces/display_state.py`), which falls back to the raw workspace id when the registry holds no display name for it — a workspace created without a name, or one deleted after the membership was written. That label feeds Console copy too (`Console_Modules/workspace.py`: "workspace {row.workspace_label}"), so a user can read an opaque id such as `ws-thesis-9f2c` where the app elsewhere promises a workspace is named by its display name (the TASK-32107 rule the .24 refusal copy follows).

The receipt and Console lines should degrade to honest copy — "an unnamed workspace", "a workspace that no longer exists" — never to an identifier the user never chose and cannot act on.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] A membership whose workspace has since been deleted is described as such in the same two places, with the same no-id rule.
- [ ] Named workspaces keep rendering their display name exactly as today (regression pin), and the Default workspace's semantics (task-15120) are unchanged.
