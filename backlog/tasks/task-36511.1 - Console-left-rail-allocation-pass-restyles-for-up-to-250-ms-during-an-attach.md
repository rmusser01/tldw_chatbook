## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Cause.** The attach's allocation batch (one Screen after-refresh batch, measured per callback with a local probe on `Screen._invoke_and_clear_callbacks`) restyled 158 nodes. 111 came from `_prepare_allocation_reconcile`: its `section.add_class("h-auto")` on five newly mounted bounded sections restyled each section's whole subtree. 44 came from `ConsoleInspectorMore._apply_open`, which removed its `h-*` class and added the same one back, two subtree restyles for no change. The `h-*` utility rules are bare `.h-<n> { height: ... }`, so no descendant style depends on them.

**Change.** A new `set_height_class(node, name)` in `Widgets/Console/console_bounded_section.py` makes `name` the node's only `h-*` class in one batch (`update_classes(..., update=False)`) and restyles the node alone (`stylesheet.update_nodes([node])`), only when its classes changed. The prepare pass and `_apply_open` call it. A non-native section never carries another `h-*` class, so the replacing swap matches the old add there.

**Measurement** (compact gates, 17 nodes at `-n 4`, dev bb80905eb3 vs branch):
- Batch probe, heavy allocation batches: nodes styled, median 158 -> 8 (max 160 -> 27). Prepare CPU median 23.2 -> 1.4 ms. Batch CPU median 40.4 -> 8.4 ms. Batch wall median 53.5 -> 15.8 ms. Load: dev 28-34, branch 21-24.
- Stack sampler (TASK-36511's `sitecustomize`, steps of 30 ms or more), interleaved 3 rounds per arm. Left-rail allocation steps: dev 23 at load 13-32 (wall median/max 77.8/212.1 ms, CPU 43.1/59.2 ms, 10 over 100 ms). Branch 3 at load 20-28 (walls 56.9, 66.5, 143.3 ms; CPU 10.0-12.8 ms). The round at load ~20 had none, and the round at load 22-27 maxed at 66.5 ms. The single 143 ms step was in the round at load 25-28 and used 10.8 ms of CPU, so the wall time was scheduler delay.
