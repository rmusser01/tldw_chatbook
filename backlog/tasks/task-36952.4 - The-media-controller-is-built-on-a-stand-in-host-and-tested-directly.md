## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-36952's first criterion is that the media subsystem's controller is constructed without the screen and tested directly. After TASK-41757, `LibraryMediaController` reaches its host only through the typed `LibraryMediaHost` protocol: four shell-service protocols plus the Textual services it reads off the host. Production still passes `LibraryScreen`, which the owner accepted on 2026-11-22. But no test builds the controller on anything else, so nothing shows that the protocol is the whole contract. Every media test goes through a mounted `LibraryScreen`.

Owner ruling, 2026-11-23, on how TASK-36952 closes: "Add a direct test, then close". A test builds the media controller on a stand-in host (not `LibraryScreen`) and exercises it directly. Production still passes the screen. TASK-36952 closes when this task lands.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
A new test file builds `LibraryMediaController` on a stand-in host, a bare Textual `Screen` defined in the test, and drives one entry point per shell-service protocol. No production code changed.

**AC #5.** Owner ruling, 2026-11-23, on how TASK-36952 closes: "Add a direct test, then close". A test builds the media controller on a stand-in host (not `LibraryScreen`) and exercises it directly. **Production still constructs the controller with `LibraryScreen`:** `LibraryScreen.__init__` still calls `LibraryMediaController(self, ...)`, unchanged by this task.

**The stand-in** (`Tests/UI/test_library_media_controller_stand_in_host.py`).
- `_StandInHost(Screen)` defines all 43 service members by hand, each through `_recorded`, which records the call in `calls` and returns `answers[name](*args, **kwargs)` (None when unset). Async members stay async. It carries `app_instance` (a `Mock`) and a `shell_state` dict.
- It is pushed onto a bare `App` in `run_test()`, so `app`, focus, `run_worker`, `query_one` and the `ancestors` identity are Textual's own.
- `_controller_on` supplies the controller's 30 accessor and setter keywords from its own signature: `<field>_accessor` reads `shell_state[<field>]`, `set_<field>` writes it. A keyword added later is supplied without an edit.
- **AC #1.** The module names neither `LibraryScreen` nor `library_screen` (grep: 0). Loading it in a fresh process leaves `tldw_chatbook.UI.Screens.library_screen` out of `sys.modules`; the stand-in's MRO is `_StandInHost, Screen, Generic, Widget, DOMNode, MessagePump, object`.

**AC #2.** `test_the_stand_in_provides_every_member_of_the_host_protocol` reads the member set from `LibraryMediaHost.__protocol_attrs__` (62: 19 framework, 43 service), the set `typing` builds over the protocol's whole MRO. Service members are the union of the four bases' own `__protocol_attrs__`; each must be defined on `_StandInHost` itself, and each framework member must resolve on the mounted stand-in.
- **Why not the AST helpers** in `Tests/Architecture/test_library_media_wiring.py` (`_media_host_members`, `_media_service_members`): they collect only `def` nodes from the source, so a member declared as an annotation would pass unseen. The runtime set has no such gap and needs no import of a test module.
- **Why the stand-in's own class for services:** a protocol member that happens to share a name with a `Screen` attribute would otherwise pass by inheritance (the `register_footer_shortcuts` shape from TASK-41757's lesson).

**AC #3**, one controller entry point per protocol. Each test asserts what the stand-in recorded and the controller's own result:
- **Shell:** `_patch_local_media_record` asks `source_record_id` for each cached Media record (recorded: both records, in order) and rewrites only the matching one (the `local_source_records` tuple it leaves).
- **Review set:** `_decorate_library_media_reviewed` asks `review_set_service` once and returns the rows with `reviewed` True, False and None, and caches `(revision, done map)` in `LibraryMediaState.review_done_map_cache`.
- **Reader-layout sync:** `_resize_library_media_reader_shell`, parametrized over Conversations, Notes, Prompts and Skills: the stand-in records exactly that route's sync, with no arguments, and the event is stopped.
- **Workspace depth:** `_open_selected_media_handoff` reads `library_workspace_depth_state` once; with a depth row blocked as `no_active_workspace`, the controller says that row's copy through `app_instance.notify` and does not call `open_chat_with_handoff`.

**AC #4.** 14 negative controls, each a temporary edit run through pytest and then restored (`scratchpad/p4md/mutate.py`, log `negctl.txt` in the coordinator's `_arch-sdd` folder). Each went red on the assertion named:
- AC #2's check: the stand-in without `walk_active_review_set`; the stand-in without `app_instance`; the protocol gaining `library_workspace_depth_label`; the protocol gaining `focus_next` (a `Screen` name). Each red named the member.
- Shell: the controller calling `source_record_id(record=record)` (recorded calls); dropping `keywords` from the rewrite (records).
- Review set: an extra `review_set_service()` call (recorded calls); `bool(...)` on the done mark (rows: None became False); caching `revision + 1` (cache).
- Reader layout: Conversations/Notes and Prompts/Skills syncs swapped (recorded calls, all 4 params); `event.stop()` removed (stopped event, all 4).
- Workspace depth: `library_workspace_depth_state(refresh=True)` (recorded calls); the refusal copy changed (notify); the refusal's `return` removed (hand-off not called).
