## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implements the owner's ruling of 2026-10-04 on TASK-34100.5's owner question 1, "Light surface by default". Plain Console chat should keep a small, safe tool set (for example date/time, calculator and ask-user). It should offer no sub-agents, skills, web or other autonomous or costly tools until the user turns them on. Setup and the Summary should say exactly what is on, and small local models should get the minimal prompt.

Today a fresh profile with every tool gate off still hands plain chat the whole default agent surface. Live on TASK-34100.5's branch, gpt-4.1-nano listed sub-agent, skill, run-log, chat, web, Watchlists, todo and character tools. It answered "Reply with just: hi" by calling `spawn_subagent`; the sub-agent errored (TASK-34100.5.1) and the reply came after the tool noise (evidence g5-v-oai 03, g5-r2b-oaihome 04). The Summary's Tools row can only hedge ("gates off; the assistant may still use chatbook's own tools … when the model's context window has room"). The context meter does not count the tool surface that is sent, because the controller's `preview_tool_schemas` hook was never implemented (TASK-34100.5, AC#6 notes).

TASK-34100.5 already removed `chat_with_llm` from the catalog and plans a guessed small window without tools. This task changes what plain chat is offered by default, which that task left to the owner.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** Plain Console chat now gets a light tool surface by default: date and time, calculator and ask-you-a-question, plus any tool the user turned on. Sub-agents, skills, chat forks, run-log tools, find/load discovery, Canvas, profile tools, the workspace/web/Watchlists/todo/character tools and chatbook's own MCP source come back with one new switch, **Full agent tools** (`[tools] full_agent_tools_enabled`, off), or one tool at a time through the existing gates. Setup and its Summary say exactly what is on, and the context meter counts what is sent. Verified live with a real OpenAI key, my own llama-server and the shared server on 8181.

**Approach**
- **One definition.** `Agents/plain_chat_tool_surface.py` holds `LIGHT_SURFACE_TOOL_NAMES` (`get_current_datetime`, `calculator`, `ask_user`), the new gate, the config readers, the narrowing, and the Summary/Tools-step wording.
- **One choke point.** `build_console_first_request_plan(light_surface=True)` is shared by live dispatch and both previews. In light mode it:
  - keeps the safe set, every built-in the user switched on (`BuiltinToolProvider` only lists gated built-ins whose gate is on), an opted-in `web_deep_search`, Library tools (composed only when the session allows assistant Library access), tools from MCP servers the user added (`MCPToolProvider.server_key_for`, a new method used here; the built-in source is excluded), and an armed raw shell;
  - drops every other name, zeroes `max_subagents`, turns off every runtime schema, run-log disclosure and discovery (`build_first_request_schema_plan(allow_discovery=False)`; a light set that does not fit falls back to no tools);
  - uses the minimal prompt: the session prompt or "You are a helpful assistant.", plus one line when tools are sent (below).
- **Not dispatchable either.** `run_reply` also drops the fork/new-chat, install-skill, script, worktree and managed-promotion closures, and passes no fleet or progress inbox, so a hallucinated `spawn_subagent` is never run (unit-tested).
- **Per send.** `ConsoleRuntime` hands the bridge `light_surface_configured`, read on every send, so a switch flipped in setup or the MCP hub applies on the next send. Bridges built without a reader (every pre-existing test harness) keep the full surface.
- **Meter (AC#5).** `ConsoleAgentBridge.preview_tool_schemas(resolution)` now exists; the send preflight, the capacity check and the voice preflight pass the send's resolution (same line counts). The light rows are computed from config and sized with the planner's own direct-disclosure test, so a window too small for them counts none, as the send does. A full-surface send caches the rows it disclosed for the next preview. The breakdown rows are built but rendered nowhere, so the Context view's "Request overhead" row, which read "unknown", now shows the last prepared request's non-conversation tokens and names the tool share ("496 tokens (tool schemas 496)").
- **Setup and Summary (AC#4).** The Tools row, the Quick-track note (TASK-34100.5 owner question 2) and the Tools step's opening line all come from `summarize_tool_surface(config)`. Setup's Tools step and the MCP hub's Tool gates pane both gain the Full agent tools switch; the hub leads with it under a line naming the light set.

**Decisions (owner-level choices made narrowly, per the ruling)**
- **The safe set** is exactly the ruling's three examples. `ask_user` still follows its own gate and needs the `[console] local_tools_enabled` master, as before.
- **One opt-in switch, not flipped defaults.** The local master and the character gate default on, and a fresh profile's template writes `local_tools_enabled = true`, so "turned on by the user" cannot be read from them. Flipping their defaults would leave existing profiles with web tools but no sub-agents, and would drop `ask_user`, which is composed by the same provider. Instead those switches scope their groups *within* Full agent tools, and their descriptions say so. Gates that default off (the eight built-ins, `web_deep_search`) mean "the user turned this on", so they work without the full surface.
- **A `$skill` turn keeps the agent surface.** Skills run as sub-agents, so a light turn would refuse the skill the user just named.
- **The hint line.** On this branch, gpt-4.1-nano answered a second "Reply with just: hi" by calling `ask_user` (malformed, failed). A probe against the real API with the exact light tools gave tool calls 15/15 with the bare one-liner, 4/15 without `ask_user`, and 0/15 with "Answer directly; call a tool only when the request needs one." That line is the registered internal prompt `agents.console_light_surface_hint`, sent only when tools are.
- **Small windows get the minimal prompt.** The light set is 495 native / 780 fenced tokens (mostly `ask_user`'s description), and the planner discloses a catalog only within 10% of the window. A self-hosted guess (planned as 4,096) or any window under about 8k fenced gets the one-liner and no tools, as the ruling asks.
