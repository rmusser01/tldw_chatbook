## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The agent note tools (`Tools/note_management_tools.py:69`) read `config.chachanotes_db` at call time instead of calling the self-initializing `get_chachanotes_db_lazy()`. They work in the TUI only because app start-up created the database first. In a fresh process they fail with 'No unified database template for NotesInteropService' (reproduced). Their tests replace the service with a fake, so the real path is never exercised. Other users of config's database go through the lazy getters, which create the database when needed.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F9; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Plan: note tools take a `db_provider` callable; the registrar (`BuiltinToolProvider`) supplies it via `build_gateable_tool`.

- `_NoteTool` base holds `db_provider` (default `config.get_chachanotes_db_lazy`, resolved at call time). `_notes_service(db_provider)` builds the real service from that DB; cache keyed on (db path, id(db)). No config global is read; `_notes_db_base_dir` and its config import are removed.
- `BuiltinToolProvider(chachanotes_db_provider=None)` defaults to `get_chachanotes_db_lazy` and passes it to the note tools; `build_gateable_tool(entry, db_provider=None)`.
- Tests (Tests/Tools/test_note_tool_user_id.py): real service on a tmp DB via the tool path; fresh-subprocess test (DB asserted under scratch HOME). Existing fake-service tests now stub the default provider; obsolete path/reload-binding tests replaced.
- RED at base: fresh-process test returned `Failed to create note: No unified database template for NotesInteropService.`; real-service test `TypeError: CreateNoteTool() takes no arguments`. GREEN after.
