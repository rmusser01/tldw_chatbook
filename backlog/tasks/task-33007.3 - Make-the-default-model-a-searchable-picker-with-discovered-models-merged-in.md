## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The default Model field is a free-text Input with a SuggestFromList typeahead of discovered ids (settings_screen.py:16800-16807; _model_field_suggester :14748-14763). That ghost suggestion measured 2.8:1 and is accepted only with an undiscoverable → key (report persona Sam).

Verified finding C4: selecting or saving a discovered model never replaces a default that is already set. Ticking a discovered row only records the selection (handler :28984-28997), Save selected only appends to the list (:17103-17106), and _model_to_activate_after_save keeps a non-empty field (:14775-14791, TASK-369).

Console already uses ModelSearchPicker (Widgets/model_search_picker.py:60). It has provenance groups (show_provenance, :131), a discovery overlay (set_discovered_models, :363-396) and, since phase 4, a '● CURRENT' mark and highlight for the committed model. The same widget gives Settings recognition over recall.

Constraints:
- ADR-002 (002:10-12) requires explicit persistence of discovered ids into [providers]. Choosing one as the default must not bypass that.
- task-14812 AC#6 and the TASK-364 comment at console_model_popover.py:1097-1099 say a model from the previous provider must never linger. A provider change already stages the new provider's default by writing #settings-model-value directly (settings_screen.py:28214-28227).
- 14 test files query #settings-model-value. A hidden adapter keeps that id, following the modal's legacy-adapter precedent (console_settings_modal.py:1809-1840).

Tests on today's typeahead:
- Tests/UI/test_settings_provider_test_draft.py:1193 (test_model_field_suggester_completes_discovered_ids) pins the SuggestFromList typeahead.
- :1180 pins the empty-field auto-fill, which stays.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The Default model row is now `DefaultModelPicker` (a `ModelSearchPicker` subclass in
`UI/Settings_Modules/providers_models_card.py`) over a hidden, unfocusable
`Input#settings-model-value` adapter. The adapter keeps its id and value, so staging,
the dirty markers, save and revert still read and write one value (AC#7).

- **Row (AC#1, AC#2).** At rest the row reads label | field (the Connect control column,
  so its Source word lines up) | Source word | help "type to search · Custom ID for
  others". While the picker holds focus the row opens: Custom ID drops below the field,
  the picker's status line shows, the grouped list spans the row, and the Source word
  and help step aside (CSS only; the field keeps its full width, so the TASK-32593
  20-cell floor holds at 120 columns). The list opens only for the focused field (the
  field posts `Changed` for its resting value on mount) and highlights the saved default
  as it opens; the `● CURRENT` mark is the picker's. The `SuggestFromList` typeahead and
  its two helpers are deleted.
- **Scope (AC#1, AC#6).** The picker reads the provider the form holds (a manual key
  included) and the screen's own app catalog and scope service (new optional
  `catalog_scope_service` argument). A provider change re-scopes it to that provider's
  own default; an earlier provider's discovery overlay is cleared, never left for a
  return trip.
- **Discovery merged (AC#1, AC#4).** A successful Discover overlays its listing with the
  new `set_discovered_models(..., served_now=True)`: ids no list holds group as **Served
  now** (Settings drops the listing whenever the provider, endpoint or credential
  changes, so it is that endpoint's current listing, as the modal treats its exact
  listing). Choosing one only stages `chat_defaults.model`; Save selected stays the only
  path into `[providers]` (ADR-002) and still fills an empty Model (TASK-369), then
  reloads the picker so the saved ids group as saved.
- **One setter (R8).** `_set_model_field_value` writes the adapter (quietly where the
  caller staged the draft itself) and syncs the picker; all five writers go through it
  (verified-default intent, Save selected's fill, navigation context, provider change,
  revert), the vLLM presentation restore re-syncs the picker, and the adapter's own
  `Input.Changed` handler syncs it for any direct write. The picker's `ModelSelected` /
  `ModelValueChanged` write the adapter, whose handler stages it (AC#3, C4).
- **Custom ID (AC#5).** An id no list holds is typed after Custom ID; an id that is not
  bounded single-line text holds no model (the adapter is blank and the picker says
  "Invalid model ID").
- **Esc (task-1560, ADR-031).** One Esc drops an unfinished search (closing the list),
  keeps a typed Custom ID, and releases the field, so the footer's "Esc, s" saves what
  was typed.
- **R9.** '/' "Model" and the navigation-conflict review land on the picker's field;
  the picker joins `_REGISTRY_LOCKED_FIELD_SELECTORS`.
- **R10 / AC#8.** No Python style writes: Settings-scoped token rules in
  `features/_settings.tcss` name the picker's parts by type, so every rule stays in the
  lazy Settings sheet (an id or class token from the picker would pin it to the boot
  bundle). The shared picker sets its Custom ID button's `display` inline only when
  hidden, so a host stylesheet can decide when a shown one displays. The screen handles
  the picker's messages by name (`on_model_search_picker_*`) and imports the picker
  module lazily, so the Settings pre-import payload stays at 556 modules.

### Rulings

- Ruling: Esc in Custom ID mode keeps the typed id and leaves the field, instead of the
  picker's own Esc (which rolls back to the previous model) -- task-1560's "Esc, s save"
  would otherwise save the old model -- cost if wrong: one branch in
  `DefaultModelPicker._cancel_edit`.
- Ruling: discovered ids group as "Served now" (the shared vocabulary), not a new
  "Discovered" heading -- the modal already labels an exact current listing that way and
  no two surfaces may contradict -- cost if wrong: a label constant.
- Ruling: Tab from the open field reaches Custom ID, then the list, then Context window
  (the modal's order); Model itself stays the same Tab stop from Provider (parent AC#2
  unchanged) -- cost if wrong: two `can_focus` flags.
- Ruling: the new test file is not added to `scripts/ui_pr_gate_census.txt` (T2's
  ruling: Phase 6 edits the same census) -- cost if wrong: one line and a `MINIMUM_FILES`
  bump in the phase PR.
