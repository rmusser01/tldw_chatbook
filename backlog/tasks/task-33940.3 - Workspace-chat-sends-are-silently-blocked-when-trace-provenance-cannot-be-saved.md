## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
With the shipped default `[console] exchange_capture = true`, every send in a new workspace chat (three tries, three chats) ended with terminal status BLOCKED and the copy "Trace provenance could not be saved. Retry, Send without capture, or Cancel." That copy was never shown: no System row, no toast, an empty assistant row, and the workspace tree only says "Blocked". Nothing explains the underlying failure in the log. With capture off, the same chat sends normally. A workspace user on default settings cannot chat at all and cannot see why.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

1. RED in a private profile: a capture-on durable send whose chat has a system prompt must reach the provider; a genuinely failing provenance build must leave a log line and be projected into the recovery card.
2. Label unsaved rows by role through one helper shared with the voice-capture builder; pass the swallowed exception to the failure handler and log its type; admit the TRACE_PROVENANCE pause in the transcript projection.

## Implementation Notes

Root cause: `_build_durable_trace_request` gave every provider row without a saved revision the fallback `ACTIVE_REQUEST`. The leading system row (any system prompt or seeded greeting -- every workspace persona chat) lands in the request's `system` category, which accepts only `RENDERED_SYSTEM`, so `ConsoleRequestProvenance` raised `TraceProvenanceAlignmentError` and a bare `except` turned it into a silent BLOCKED pause. The voice-capture builder already mapped rows by role; that mapping is now `_unsaved_trace_artifact_source`, used by both builders (it also closes the same latent mismatch for unsaved tool rows).

Visibility: the handler now logs `exception_type` only (the inventory review confirms no content), and `trace_call_recovery_state` admits `TRACE_PROVENANCE`, whose actions (retry / send_without_capture / cancel) are exactly the existing card's non-temporary actions. It was excluded since the projection and the pause kind landed together in c78f641adf; no test asserted the exclusion.

Evidence: `Tests/Chat/test_console_trace_system_prompt_send.py` (2 private-profile tests; RED on dev, GREEN). The 43 trace/recovery test files have an identical set of 157 failures on this branch and on clean origin/dev (local sandboxed-config `RecoveryRequired`; those suites do not run in dev CI either). Live: the shipped-default workspace send with capture on completed with no provenance failure in the log (it was blocked before).
