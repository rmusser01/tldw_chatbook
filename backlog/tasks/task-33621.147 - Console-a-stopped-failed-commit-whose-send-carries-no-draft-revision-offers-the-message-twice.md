## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in the TASK-33621.59 review (2026-11-06), by reading. When a received claim's draft revision is None, the preparation's input draft revision is None too. Stop over a failed durable commit then cancels with the draft restored, but the store records no cancelled draft revision, so the runtime also puts the turn on the unsent-turn shelf: the text would be in the composer and on the shelf. The card's own Cancel send avoids this by not restoring the draft when the revision is unknown. Whether a manual send can reach this state in practice is not established.
