## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
About 141 media-named methods (5.5k lines) still live on LibraryScreen, and the media controller calls back into 44 of them through lambdas. If the move exceeds one reviewable PR, split this task into subtasks before starting.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F2; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Split into 8 serial, stacked subtasks, measured at `08b3c9d337` (TASK-36952.2's head). Each move slice moves its bodies byte-for-byte onto `LibraryMediaController`, removes the callbacks it makes dead, retargets every test that reaches a moved body in the same commit, and lowers the lambda, unbound-call and size pins to their measurements.

The coordinator's rulings bind every slice:
- **R1, asserts.** Only the receiver may change inside an `assert`: `LibraryScreen.<m>(fake)` becomes `LibraryMediaController.<m>(fake)`, a `getsource` subject moves to the controller, and `screen.<m>` becomes `screen._media_controller.<m>`. The proof is mechanical: undoing each receiver substitution leaves the def AST-equal to base. The notes list every in-assert site.
- **R2, body tokens.** Moved bodies are byte-for-byte except for 9 enumerated tokens:
  - 4 `self in/not in <widget>.ancestors` checks, resolved against the screen handle;
  - 4 `LibraryScreen.<static>` calls, which become `LibraryMediaController.<static>`;
  - 1 `self._media_controller` hop, collapsed to `self`.

  Each of the four membership checks gets a test that goes red when it is reverted to the controller's `self`.
- **R3, the AC #1 exceptions.** `_sanitize_media_field` moves into the media controller module, behind a `staticmethod` alias at the old screen name, so the other controllers' bindings are unchanged. `_toggle_library_media_reader_pane` stays on the screen: it is the multi-subsystem reader-pane dispatcher, and it is the one AC #1 exception.
- **R4, AC #2's reading.** AC #2 is met when the controller takes a typed host Protocol of framework and shell services (implemented by `LibraryScreen`) instead of `LibraryScreen`, and no callback reaches a media-named screen method. The shell, review-set, notes and workspace callbacks are not media behaviour. Removing them is a later shell-services task.
- **The AC #5 receiver.** `LibraryMediaController.<m>(fake)` counts as retargeted.
- **AC #4.** The recipe's own probes, as written, run as a paired base/head comparison in one session at load ≤ 5 (n=6 per arm), between `08b3c9d337` and the last slice's head.
- **The per-slice teardown AC.** The probe's mounts, unmounts and nodes vary with load on this host. So targeted swaps, whole-screen recomposes and refreshes must match on every run; mounts, unmounts and nodes are compared by each row's most common tuple, over n=6 interleaved, order-swapped runs per arm; and any tuple seen on one arm only is flagged in the notes.
- **Size pins.** Each slice lowers `LibraryScreen`'s row and raises the media controller's row in the same commit, to the measured values.
