## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact (P1).** This was reproduced twice after a first call got HTTP 429 or 500 and the retry's trace reservation then failed before dispatch (reservation_status 'unknown'). It happens on the 'Trace capture blocked' card:
- **Cancel send never cancels.** The card's status changes to 'Trace reservation status is unavailable.' and the card stays, even after repeated clicks. It is the one escape hatch, and it fails.
- **Send without capture and Retry capture make no provider call.** There is no POST and no send-stage log line. Each shows 'Working…' for about 1 s and is then replaced by 'Response delivery status is unknown on the source device. / Retry anyway may send a duplicate request because delivery status is unknown. [Retry anyway] [Discard]'. That is false: the only POST was the rejected 429/500, the retry never left the app, and the session is local. The 'source device' sentence is remote-handoff copy (console_chat_models.py:695).
- **Retry anyway works but gives no acknowledgement.** Its row stays byte-identical for 4.2 s until the reply arrives.
- **Header disagrees.** The composer, rail and Inspect handle say blocked while the header chip says 'Ready'.

Across three panels, the app makes three different claims about the same send, and users are pushed toward Discard.

**Prior art:** KNOWN_PARTIAL: TASK-25823 (Done; remote-handoff copy during local sends, same family), TASK-31976 (Done), TASK-25814 (Done), PR #2882 (TASK-32951, TASK-32953). The verifier noted that a 'provider_entry never entered' rule would not catch this case. Delivery state has to come from the failed call's definitive HTTP outcome together with the fact that the retry never crossed dispatch.

**Suggested direction:**
- Record 'provider rejected' and 'not dispatched' outcomes instead of 'unknown'.
- Make Cancel unconditional from the user's side: mark an unknown reservation abandoned locally, settle it later, and restore the draft.
- Make Retry capture re-run capture.
- Split the dispatch-recovery copy into local and remote variants.
- Add an immediate 'Retrying…' busy state.
- Derive the header chip from run state.

The row's evidence files, uxrev/evidence/L3/59-cancel-send-500.txt, 08-send-without-capture-result.txt, 10-retry-anyway-working.txt and J2/103-retry-capture.png, were not copied into qa/evidence.
