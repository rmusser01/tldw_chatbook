## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** This is a new user's first task. On Quick setup ▸ Provider, the fourth Down arrow (or a click) lands on the first Cloud row, 'ByteDance Seed (BytePlus)'. The step body goes blank and a red toast reads "Something went wrong in _ownership_for — the screen was kept open…". The cause is a ValueError at `provider_setup_persistence.py:193`: the provider key is not in `_CANONICAL_PROVIDER_KEYS`. That affects 13 of the 24 Cloud rows (BytePlus, Cerebras, DeepInfra, Fireworks, MiniMax, Nebius, Novita, NVIDIA NIM, SambaNova, StepFun, Tencent TokenHub, Together, Xiaomi MiMo), plus 'Custom Hosted', which is listed under Local. Google Gemini, a canonical key, works as a control.

After the error:
- Up, Ctrl+B, Esc, Tab and Ctrl+N do nothing; only the mouse works.
- Next → from the blanked step exits the app (NoMatches in `commit`).
- ← Back then Next → also exits the app (NoMatches in `_credential_draft`).
- In a session resumed from "Continue setup?", ← Back is disabled.
- The only clean escape is clicking Exit setup. The profile is not bricked.

**Severity / prior art.** P0, KNOWN_PARTIAL. TASK-33002.13 (To Do, low) makes the wizard offer the same set as Settings, but covers only the Custom Hosted key, not the crash, the keyboard loss or the exit. See also TASK-1267 (Done, the wizard's nav focus strategy), TASK-33008 and TASK-2040.

**Suggested direction.**
1. Use one source of truth: list only providers that setup persistence can own, or give the missing keys endpoint and credential ownership.
2. For an unsupported key, show an inline 'not available in setup yet — configure in Settings' row instead of raising.
3. Make the credential draft and commit tolerate a torn-down step.
4. After any caught step error, restore focus to the nav bar.
5. Re-check why ← Back is disabled on a resumed Provider step.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G3-01 (source J1-01); qa/console-ux-review-2026-09-29/evidence/evidence__J1__08-provider-down-3.png, evidence__J1__08-provider-down-3.txt.

Dev-tip note (reviewed 64579cce2c; checked against 857b3dd7d0): 0678f56b1f (TASK-33351, 13 gateway/host presets: Arcee, Baseten, GMI, Kilo, Meta, Nous, SiliconFlow and others) adds entries to provider_catalog.py / provider_registry.py but leaves _CANONICAL_PROVIDER_KEYS in provider_setup_persistence.py unchanged. If the wizard's catalog includes these presets, which is likely because it groups the live catalog, the set of rows that crash on highlight gets larger. It does not fix the defect. Not verified live.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Summary: The first-run Provider step now lists exactly the providers the Settings picker offers, and provider setup can save all of them. An error raised inside a wizard step or the wizard container no longer blanks the step and later quits the app. The step stays on screen with an error line, the keyboard stays live, and Back, Esc and Next keep working, including on a session resumed from "Continue setup?". (G3-01)

Note: these notes describe the tree after rebasing onto origin/dev (which includes 31a356c916, TASK-33510/33511). Before that rebase the branch carried its own registry-derived ownership filter (`_setup_keeps_api_root`/`_HOSTED_PRESET_RECORDS`, 22 of the 26 missing presets). The rebase drops that filter in favour of dev's `_ENGINE_PRESETS`, which owns every engine preset.

Approach:
- One provider set. The new `settings_provider_catalog()` (Chat/console_session_settings.py) is the Settings handler catalog filtered by the new `provider_setup_persistence.setup_owns_provider()`. `SettingsScreen._provider_catalog_entries` and the wizard's ProviderStep (through `first_run_step_guard.first_run_provider_catalog()`) both read it. The execution-only `custom_hosted` is no longer offered (TASK-33002.13).
- Error containment. The new UI/Wizards/first_run_step_guard.py provides the `WizardErrorGuard` mixin, applied to SetupStep and SetupWizardContainer. It wraps `_on_message`, so a raising handler no longer stops the widget's message loop and detaches it. It acts only when the app keeps its UI alive (`_keep_screen_alive_on_handler_error`, default on outside headless runs), so the test suite keeps its exception signal. It pins copy naming only the controls that work (no Back on Welcome), re-anchors orphaned focus, and logs the exception type and the raise and innermost-Chatbook frames, attributed to the step that raised. It also calls `persist_event('first_run', 'contained_exception', ...)`. A repeat of the same failure logs at DEBUG, so a failing 250 ms interval cannot flood the log. Messages and tracebacks are never logged, because they can hold a typed key. `SetupWizardContainer._advance` contains its own exceptions through `contain_advance_error`, so Next can no longer exit the app.
- Credential safety. `ProviderStep.select_provider` is transactional: presence, initial endpoint, auth requiredness, endpoint visibility and every widget query run before `selected_provider_key` or the key and endpoint inputs change. A failed switch keeps the previous provider with its own key, and Next never stages one provider's key for another.
- Back on resume. `update_progress` sets `can_go_back` before `current_step`, and `WizardNavigation.watch_can_go_back` (BaseWizard.py) keeps Back in sync whatever order a wizard uses.

Decisions and trade-offs:
- A failed switch leaves the highlight on the failing row and the selection on the previous provider. Snapping the highlight back was rejected because it traps arrow-key users on that row.
- AC#1's alternative, an inline "configure in Settings" row, was not needed: every listed provider is saveable.
- FirstRunSetupWizard.py shrinks by 1 line (10,860 to 10,859). New code went into first_run_step_guard.py because the file is over its size ratchet.

Second round (after review):
The first-run wizard and Settings ▸ Providers & Models now offer one provider set, `settings_provider_catalog()` in Chat/console_session_settings.py. Setup persistence owns every key in it: engine presets through the registry derivation from TASK-33510, which this branch keeps byte-identical to dev. The execution-only `custom_hosted` key is no longer listed.

Any other error on a wizard step is contained by the new UI/Wizards/first_run_step_guard.py. It is a separate module because FirstRunSetupWizard.py is ratchet-red; the wizard's net line change is 0.
- `WizardErrorGuard`, a mixin on SetupStep and SetupWizardContainer, contains a raising handler in `_on_message`. It also wraps every `action_*` / `_action_*` method at class creation, because Textual runs key bindings in the App loop, which the app never keeps alive.
- `contain_advance_error` contains the Next worker.
- Recovery pins an error line that names only working controls, re-syncs the nav bar (validate_step, _sync_exit_controls, _sync_action_controls), and releases or re-anchors stranded focus.
- Logs carry the error type and frame identifiers only, deduplicated per site, plus a persist_event diagnostic with an inventory row.
- `provider_switch` names the provider that stays selected after a failed pick and clears its own line on success.

`ProviderStep.select_provider` does all fallible reads before mutating state, so a failed switch keeps the previous provider and its typed key. `update_progress` sets `can_go_back` before `current_step`, which fixes the disabled ← Back on a resumed session without touching BaseWizard.

The User Guide pages First_Run_Setup.md and settings.md are updated, with no Verified-against stamp. `Docs/security/production-diagnostic-inventory.json` gains the guard's row.

Tests: the new Tests/Wizards/test_first_run_provider_catalog.py (82 tests), plus additions to Tests/Chat/test_provider_setup_persistence.py and Tests/UI/test_settings_provider_switch_atomic.py.

Decisions:
- The highlight does not snap back after a failed switch, since that would trap the arrow keys above a failing row; the copy names the retained provider instead.
- Containment follows app_lifecycle's keep-alive policy, so headless tests keep their exception signal.
