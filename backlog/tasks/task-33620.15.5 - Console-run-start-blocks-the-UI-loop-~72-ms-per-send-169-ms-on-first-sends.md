## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the live send-window profile of 2026-10-10 (the same round that filed TASK-33620.15.3, .4, .6 and .7). Method: isolated profiles, Anthropic haiku through the review proxy, 160x45, 56 sends over 10 launches; a probe on the app's PYTHONPATH timed every UI-loop callback and sampled the main thread every 4 ms while a callback ran, between a send's acceptance and its provider call.

After a send is accepted, run start (`ConsoleRuntime._run_custodied_turn` > `submit_draft`) holds the UI loop for 72 ms per send over 30 sampled sends, and for 169 ms on the first send after launch (5 sends). 81% of it is on-CPU. On first sends it was the longest single callback of the window in 3 of 5 sends (callbacks of 40 ms or more: median 76 ms, max 123 ms). On later sends its two longest callbacks were 16-28 ms each. By samples:
- `PromptHistory.append` builds a file job whose source selection calls `default_prompt_history_path()` twice. Each call is a guarded config operation (storage admission, companion guard, pause probe): about 12 ms per send.
- The MCP catalog fingerprint that decides catalog reuse (TASK-33620.15.1) reads the permission store and the local store, each through an admission scope, in one callback: about 19 ms per send.
- First sends only: lazy imports on the loop (the hooks v2 lifecycle package, `console_visual_transcript` with PIL, `web_tool_impls`) about 25 ms, and the full MCP composition in one callback of about 75 ms (fingerprint, kill switch, external catalog, built-in inventory, which parses `MCP/server.py` three times, tool states, local tool provider).

TASK-33620.15.1 made later run starts reuse the composed catalog. This task shortens what is left of run start's loop time without moving it to a worker thread: TASK-33620.15.1's worker hop made first sends reach the provider 97-249 ms later.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Measure first (AC#1). Live, isolated profiles, Anthropic haiku via the review proxy, 160x45: the send-window probe (callback timings, 4 ms main-thread samples) plus a record of every module imported on the UI thread; origin/dev (detached worktree) vs this branch, sends interleaved, at least 12 pairs including at least 5 first sends after launch. Attribute each send's run-start callbacks by component.
2. First-send lazy imports. A small Console module names the modules a first send's run start imports lazily (hooks v2 lifecycle, `console_visual_transcript`, `web_tool_impls`, plus any the import record adds). The app's existing post-UI-ready pre-import pass (daemon thread, same on/off switch, off in the ADR-097 census) imports them before the speculative screen routes; its heap freeze covers them. Nothing moves before UI-ready. Tests: the pass warms them (red on origin/dev); every function-local import at the run-start sites is warmed or already in the UI-ready snapshot.
3. Prompt history. Memoise `default_prompt_history_path()` on `config.current_config_identity()` (identity read before and after, kept only if unchanged). The file job's worker scope still re-derives the selection from the live config, so a stale memo can only refuse, never redirect a write. Tests: a second append resolves the data directory zero times (red on origin/dev); an identity change re-resolves; entries and refusals unchanged.
4. MCP run start, kept on the loop. Cache `_load_server_module_ast` by the file's identity (device, inode, size, mtime); yield to the loop between the composition's admission-checked store reads (fingerprint: permission store, then local store; composition: kill switch, external catalog, inventory, tool states), so no two store scopes share one callback. Tests: one parse per unchanged file (red on origin/dev), a re-parse when the file changes, the same manifest; no two run-start store reads in one loop callback (red on origin/dev); the catalog-reuse and reuse-key tests unchanged.
5. Measure each piece's effect, then live after (AC#2, AC#3: Enter to provider call without the probe). Gates: the touched modules' test files against an origin/dev worktree by test id, the ADR-097 census, boot CSS and pre-import payload budgets, size ratchets, ruff, `./scripts/preflight.sh`.

Round 2 (2026-10-19, after the interruption; rebased onto origin/dev 4de437a5c5, ~1,500 commits later):

8. Re-derive the warm-up list from the new live record and the harness record; add the run-end imports and one idle parse of the manifest source; pace the warm-up with the pass's own duty-cycle pacing and custody park (it ran as one unpaced burst before).
