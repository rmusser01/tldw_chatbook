## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Prevent unsupported V2 profile data from bypassing native V1 consumers while the remaining privacy and rollout owners are unqualified. Wire a version-aware decoder and closed compatibility barrier into existing native owners without permitting V2 storage, migration, disclosure, source inspection or Sync.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A bounded native decoder validates explicit manifest, scope, record and proposal V1/V2 kinds with positive controls and exact canonical-byte preservation; duplicate JSON keys, invalid selectors, wrong kind/version, unsafe coercion and invalid V2 semantics fail with content-free errors.
- [x] #2 A compiled native route registry and immutable compatibility result are consumed by repository/service/bootstrap; unregistered routes and every V2 profile remain blocked, and no config, imported receipt, serialized assertion or caller flag can create a V2 permit path.
- [x] #3 Repository guards check the authenticated current manifest before ordinary content decryption and inside mutations, including individual getters, local metadata, snapshots, Undo/outboxes, first-link paths and proposal/interview commits; V1 records inside a blocked profile cannot leak or mutate.
- [x] #4 Every canonical insertion rejects V2/unsupported incoming bodies even under an otherwise healthy V1 or absent profile, rolls back atomically and preserves existing V1 creation, CAS, encrypted local state and wire bytes; no storage/AAD migration is introduced.
- [x] #5 Native status preserves profile presence with a generic compatibility reason, and existing app, Settings owner access, context/tool advertising, interview/proposal, export/recovery and Sync routes fail closed without provider/source calls, plaintext output, false absence or automatic Start Fresh.
- [x] #6 Synthetic native tests use real temporary encrypted SQLite and in-memory key protection, cover successful V1 controls, blocked V2, duplicate/coercion/corruption, stale prepared reads and rollback; any observed failure receives a reproducible regression before a fix.
- [x] #7 Targeted affected tests, static/format checks and affected boot/import guards pass on Python >=3.12 without a full sweep; published shared-core schemas/fixtures/contracts and independent TASK-25907.10 task/roadmap suffix remain unchanged.
- [x] #8 ADR-193 and its separate activation/retirement/disclosure/source/server prerequisites are linked in the plan and final notes; one fresh final reviewer checks the complete unit, material findings are resolved and documents distinguish a shipped deny barrier from V2 qualification or activation.
<!-- AC:END -->
