## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** While a run is active, the expanded composer never paints Stop at any width. Live checks at 80x24, 120x40, 160x45 and 235x52 with a slow proxy all showed the row ending `Queue  Dictate  Redir`, with `Stop` appearing 0 times on screen. Stopping a runaway, wrong or expensive agent run (which may be executing tools) is the core recovery action on a live work surface, and DESIGN says to "make cancellation available". The User Guide (`Docs/User_Guide/console/chat-basics.md:325`) says Stop appears "between Send and Mic", which is false.

**Verified mechanism.** The action row has a fixed budget of 33 cells (`BASE_ACTIONS_WIDTH` 25 plus Send width 14 minus 6) in `tldw_chatbook/Widgets/Console/console_composer_bar.py`. Send (14), the gap (2) and Dictate (11) use 27 of them. That leaves 6 cells for Redirect (10 cells), which is cut to `Redir`, and 0 for Stop (6 cells). Stop is composed last, so clipping always removes it first.

Keyboard access is also broken:
- Tab reaches the clipped Stop, but it shows no visible focus.
- Enter on it does not stop the run, because `ChatScreen.on_key` sends Enter from any composer descendant to the send path (log: `phase=ui_action status=not_dispatched`).
- There is no stop key binding. Esc, Esc and Ctrl+C do not stop a run.
- Ctrl+P "stop" lists nothing relevant, and there is no `/stop` command (`/emergency-stop` only holds new runs).
- The `stop` WorkbenchAction is filtered out of the header by `TOP_ACTION_IDS`.

The only working route is undocumented: collapse the composer, and the strip then shows `Composer hidden - Generating ... Stop`. The idle-style `Send disabled: …` text also sits next to a button labelled `Queue`.

**Severity / prior art.** P0. This is a **REGRESSION of TASK-28227 (Done)**. Its AC#5 says "Plain Stop ... behaves exactly as today", and it added Redirect "next to Stop (visibility synced with Stop)" (commit 42d9b7b737) without budgeting for it. It also breaks the contract of TASK-1680 (Done): the row is width-bounded, carries Send/Stop/Mic, and new actions must not grow it. Verdicts: live PARTIAL, code CONFIRMED, skeptic CONFIRMED.

**Suggested direction.**
- Make the row budget run-aware and derive it from the controls actually shown.
- Place Stop first after the draft, or swap it into Send's slot while running, with warning styling, so clipping can never remove it.
- Budget Redirect explicitly, or drop Dictate while running.
- Stop the composer Enter capture from swallowing Enter on a focused composer Button.
- Add a stop route for the viewed tab's run: a key shown in the footer only while running, a palette command, and `/stop`.
- Say "Type to queue" instead of the Send-disabled reason while running.
- Fix chat-basics.md.

The cross-region width-priority model belongs to the Theme 5 umbrella task. This task only guarantees Stop and Redirect inside the composer row.
