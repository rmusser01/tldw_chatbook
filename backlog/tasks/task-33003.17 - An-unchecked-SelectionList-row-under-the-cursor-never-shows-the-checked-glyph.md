## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
In the discovered-models list an unchecked row under the cursor now paints an empty box, and a checked one paints its X. No other SelectionList paints an unchecked row under the cursor as a checked one any more.

**Root cause.** Textual picks the box's style from four component classes. `selection-list--button-highlighted` is the UNCHECKED box under the cursor. components/_lists.tcss listed it in the shared "selected row" rule beside the two checked classes, so all three painted `$text` on `$surface`, bold underline: the X showed whether or not the row was checked. TASK-368 scoped the discovered-models list's unchecked box (`color` and `background` both `$ds-grid-line`, so no X shows) and its checked box, and left this state to the shared rule.

**Fix** (css/components/_lists.tcss).
- The shared rule no longer lists `SelectionList > .selection-list--button-highlighted`. Textual's own default for that class, an unchecked box, paints it.
- `#settings-discovered-models-list .selection-list--button-highlighted` joins the list's unchecked-box rule.

- Ruling: fix the shared rule, not only the one list. Why: the same rule painted the cursor row as checked in the other three SelectionLists (artifact share dialog, the chat question card, Library skills), where checked and unchecked were identical under the cursor. Cost if wrong: those three lists show Textual's stock unchecked box under the cursor, the same box they show at rest; one selector line puts the old paint back.

**Test (AC#2)**, Tests/UI/test_settings_discovered_model_toggle.py, `test_unchecked_row_under_the_cursor_shows_no_checked_glyph`, 6 nodes: the production stylesheet (bundle and split sheets) on agentic_terminal, textual-dark and textual-light. It moves the cursor to a checked row and then to an unchecked one and reads the three button cells from the frame.
- Discovered-models list, mounted inside `#settings-providers-models-card` so the card's highlight bar applies: the unchecked row's X has ink equal to its box (no glyph), and the checked row's X reads at 3:1 or more on its box.
- Any other SelectionList: the unchecked row under the cursor paints exactly as an unchecked row at rest, and its X ink differs from the checked row's by 3:1 or more.
- Red before the fix: 6 failed. textual-dark painted the unchecked cursor row's X as #E1E1E1 on #1E1E1E in both lists.
- The node carries the repo's `bootstrap_profile` marker, so a plain run of the file reaches its assertions on a machine where Tests/UI setup otherwise fails with `raw_source_selection_changed`. The file is on the UI PR census whole, so this node runs there as a `bootstrap_profile` entry, by the census's allowance for them (Tests/CI's `_BOOTSTRAP_OK` lists the UI Fast Lane census, and the census holds 68 other such entries). That is a known exception to ledger R11, which puts a bootstrap_profile test in the PR Fast Lane's admission-sensitive step and never the census (TASK-32873); the file's other test is unmarked, so the file stays whole in the census (whole-PR review, round 1, 2026-10-18).
