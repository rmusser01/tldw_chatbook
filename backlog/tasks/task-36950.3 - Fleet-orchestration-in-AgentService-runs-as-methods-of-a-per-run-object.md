## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
The fleet operations now live in `tldw_chatbook/Agents/agent_run_tools.py` as methods of `AgentRunTools`. `_run_one` builds one instance per run, at the point where the closures used to be defined. This is a pure move.

**What moved.** The fleet block went in full:
- `_reserve_child_execution`, `_launch_fleet_child` and `initialize_child_hooks`;
- `_spawn` and `spawn`;
- `wait_agents` and `check_agents`;
- `recover_current_worktree`, `merge_agent_worktree_tool` and `discard_agent_worktree_tool`;
- `_resume_retained_child` and `send_to_agent`.

The steering drain (`drain_causal_steering`) and the fleet message tools also moved: `progress_authorized`, `report_to_supervisor`, `list_peer_agents`, `send_to_peer` and `read_agent_messages`.

**How the bodies were moved.** A symtable-guided rewrite resolved every name in each closure:
- the closure's `self` (the service) becomes `self.service`;
- each `_run_one` local it shared becomes `self.<name>`;
- `nonlocal` lines are dropped.

An AST check compares each method with its base closure after undoing exactly those renames, and all 18 compare equal. The only other difference is docstring indentation.

**The traps:**
- **`self` rebinding.** `_run_one` rebinds `self` for a code-review child, and the object is built from that rebound service.
- **Late-bound locals.** `_run_one` sets `run_tools.hook_run` right after `ToolHookRun(...)` and `run_tools.progress_reader` right after the reader opens, both before the loop runs. `progress_authorized` is a method now.
- **Shared counters.** `sub_agent_spawns` and `child_started` are attributes. The review capacity probe and `invoke_tool`'s skill branch read `run_tools.sub_agent_spawns`.
- **The `core_operation` decorator.** `_launch_fleet_child` is wrapped in `core_operation(service.db)` per instance in `__init__`, where the closure was decorated at definition time.
- **Monkeypatch targets.** Tests monkeypatch five of the names the moved code reads on `agent_service`: `_setting`, `AgentConfig`, `get_internal_prompt`, `load_agents_routing_config` and `build_first_request_schema_plan`. The moved code reads all five through the module, so the patches still reach it. `get_internal_prompt` was added in fix round 1. It is patched through a helper (`fail_once(agent_service, "get_internal_prompt")` in `test_agent_service_review_containment.py`), which the first census missed. A sweep of every `(alias, "name")` and `agent_service.<name>` patch under `Tests/` finds no other name the moved code reads.
- **Ordering.** The object is constructed right after `review_owner` is resolved and before the review capacity install (fix round 1, review M-1), so the capacity lambda never sees an unbound `run_tools`. The constructor has no side effect whose order relative to that install matters. `fleet.durable_handle_map()` is a locked read that returns a copy. `core_operation(service.db)` only builds the context-manager object; its body runs per call. The install only swaps `review_adapter.capacity`. Event and persistence order is unchanged, and no lock is shared between the two steps.

**Other changes.**
- `agent_service.py` drops the imports it no longer uses.
- It keeps `contain_child_budget`, `STEP_TOOL_CALL` and `compute_definition_fingerprint` as re-exports, because `agent_native_execution` reads them as `native_host.<name>`.
- The `agent_service.py` size row drops from 9,720 to 8,099, then to 7,677 with TASK-36950.4.
- `agent_run_tools.py` is 1,788 lines (2,217 with the run-log tools), below the 4,000-line row threshold. It is imported lazily from `_run_one`, so boot imports are unchanged.

No new tests: this is a pure move under the existing fleet and agent-service suites.
