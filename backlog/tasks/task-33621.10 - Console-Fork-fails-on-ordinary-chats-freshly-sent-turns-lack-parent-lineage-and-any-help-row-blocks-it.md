## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact (P1).** Fork does not work on ordinary saved Console chats. Two independent defects cause this, and both reproduce live:

**(a) Fresh saved pair.** In a saved chat whose turns were sent in the current app session, no message can be forked. On the assistant row the guide shows 'f Fork' with no warning and the button looks normal, but pressing f only shows the toast 'Saved Console fork parent is unavailable.' The user row shows 'Fork unavailable - Saved active leaf lineage is unavailable.'
- Cause: `_hydrate_durable_turn_owner_messages` (console_chat_store.py:6856-6899) sets `persisted_message_id` but never the in-memory `parent_message_id`, so `_fork_lineage_entry` and `_fork_database_active_leaf` fail. The DB rows are correct, and fork works after a restart, which is an undiscoverable workaround.
- The same missing lineage also breaks automatic compaction (finding GAP2-01); coordinate so that one lineage fix serves both.

**(b) Command output.** /help, /doctor, unknown-command hints and similar output (63 call sites of `_append_native_console_system_message`) add non-persisted SYSTEM nodes to the in-memory tree. Every later message then shows 'Fork unavailable - Only user and assistant messages can be forked.', even on an Assistant row. The block lasts until the chat is reloaded from the DB. ADR-092:44-50 and the fork spec (:149-150, :391) say these rows should be excluded, not treated as blockers.

The command a learner is most likely to run silently disables a headline feature, and the error text contradicts what the user sees.

**Prior art:** REGRESSION of TASK-23088 (Done) AC#1/#2. See also ADR-092:44-50,245-248; Docs/superpowers/specs/2026-08-26-console-chat-fork-design.md:149-171,391; TASK-22060 (In Progress, related persisted-parent bug); TASK-23146 (To Do).

**Suggested direction:**
- Set the in-memory user and assistant parent ids during hydration, mirroring `publish_first_persisted_conversation` and the recovery path.
- Make the fork prefix walk skip non-conversational SYSTEM, TOOL and display-only nodes, or render command output as ephemeral notices outside the canonical tree.
- Word refusals to name the blocking row and the nearest valid boundary.
- Gate the guide's 'f Fork' on real eligibility.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G1-09 (sources J8-03, L4-01); qa/console-ux-review-2026-09-29/evidence/evidence__J8__77-fork-f.png, evidence__J8__79-newtab-fork.png, evidence__L4__13-selected-assistant.txt, evidence__L4__15-control-selected.txt.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Fork now works on ordinary saved Console chats (G1-09, a regression of TASK-23088). Each change was written test-first.

**Approach**
1. **Lineage at the source.** After the durable commit, `_hydrate_durable_turn_owner_messages` mirrors the committed parents:
   - The USER row copies the new required field `ConsoleDurableTurnCommit.user_parent_message_id`, which holds the value the acceptance wrote.
   - The ASSISTANT row points at the USER row.
   - `persist_provider_continuation_event`'s first save also sets the live parent.
   - This also gives compaction snapshots a single ordered parent chain (the GAP2-01 cause).
2. **Command notes are excluded, not refused (ADR-092 §2).** `console_fork_skips` / `console_fork_source_ids` drop SYSTEM rows, saved or not, from the copied lineage. This is applied in eligibility, fence issue, re-validation and the dialog prefix (session.py uses `store.fork_source_message_ids`). `ChatPersistenceService._fork_source_parent` walks past saved `system` rows at commit time.
3. **Eligibility checks what the fence checks.**
   - `console_fork_prefix_refusal` checks every copied row, including its saved parent link.
   - The refusal names the blocker (the selected row or an earlier one) and the nearest boundary that `can_fork` accepts, or says no earlier message can be forked.
   - `check_console_fork_saved_tail` replaces the "Saved active leaf lineage" jargon with the named row.
   - `describe_console_fork_row` never quotes placeholder text.
4. **Guide.** `action_row_guide` omits `f Fork` when Fork is disabled. The store's refusal takes precedence in `_fork_disabled_reason`, after the wait states.
