## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Follow-ups from the PR #2943 (TASK-33621.19) round-5 checkpoint review. None blocks #2943.
(a) handle_primary_intent (prompt_queue.py ~631-643) shows result.queue_notice only when result.accepted is true. But retry_dispatch_recovery settles the owner regardless of acceptance, and the resume_durable_postcommit branch can return a non-accepted result after the recovery is cleared. So the queue lands on Context changed with no notice.
(b) Pre-existing at merge-base 75c06af39a: when settle_dispatch_recovery_and_drain's resume() refuses after the owner is cleared ('All agent slots are currently in use.' or the backup-maintenance refusal), the waiting prompts stay paused with no notice. The shelf then shows Paused/Resume.
(c) Pre-existing: if a pending-response Retry ends FAILED (accepted, terminal_status FAILED), the queued prompts behind it still drain. In a normal chain a FAILED turn pauses the queue.
(d) The User Guide list of what triggers the review ('An edit, a delete, a compaction, or a failed Retry stopped') is incomplete. A Retry or Retry failed that the user STOPS also moves the epoch (console_chat_store._settle_failed_retry_context).
(e) Live reachability of the pending queued response plus context change shape (covered by two real-controller tests in #2943) is not established.
