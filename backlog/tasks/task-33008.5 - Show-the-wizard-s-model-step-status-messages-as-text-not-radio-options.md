## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The wizard's model step mounts its status messages as disabled SetupRadioButton options inside the model RadioSet (FirstRunSetupWizard.py:3836-3906). The messages are: listing unavailable; connection failed, including 'Authentication failed — this API key was rejected. Go Back to fix it…'; loading; pick a provider first; and no models found. A failure is therefore drawn like a choice (report, persona Jordan). In the wizard, the judge's surface map changes only these placeholders.

The TASK-21143 trust chain (tracker mark, Model-step confirm gate, Summary override) reads the classified outcome right after these mounts (:3911-3915). It must behave as before.

These tests in Tests/Wizards/test_first_run_setup_wizard.py assert the RadioButton type:
- :8817, in test_mounted_provider_handoff_preserves_typed_discovery_outcome (:8743)
- :9035, in test_model_connection_failure_shows_bounded_category_and_retry (:8982)
- :9243 and :9264, in test_mounted_model_owner_timeout_fences_late_result_and_keeps_manual_retry (:9173)

The file is already over its size row: 10,462 lines against 10,404 (Tests/Architecture/test_module_size_ratchet.py:81).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** The Model step's five statuses (loading, pick a provider first, no models found, listing unavailable, connection or authentication failed; the capture fixes later added a key-required copy under the connection-failed id) are now one plain text line each, with the same ids and the same copy. They are no longer disabled radio rows, so a failure no longer draws like a choice. Retry, manual model entry and the TASK-21143 trust chain are untouched.

**Approach.**
- `first_run_model_step.py` mounts every status through one helper, `_status_line(text, line_id)`. It returns a `Static` with `disabled=True` and `markup=False`. The line stays inside `#setup-model-choice`, so every id-only consumer keeps working, and no CSS was added (capture fix 06a later added `#setup-model-choice.-status`'s `min-height`, and 06b `.setup-step-error`'s padding, to `_wizards.tcss`).
- `disabled=True` is load-bearing. An enabled non-radio child becomes the RadioSet's highlighted node, and Space then fails an assertion inside Textual 8.2.8 (`RadioSet.action_toggle_button`) and exits the app. A status line is never mounted beside model rows.
- `markup=False` is new behaviour. The connection-failed copy embeds typed text (the endpoint), and with markup on a bracketed word in it would be consumed as a tag: measured on Textual 8.2.8, `http://[localhost]:8080` renders as `http://:8080`. A bracketed IPv6 address such as `http://[::1]:11434` is left intact either way, so it is not the reason.
- A status line now wraps on a narrow screen. The old radio row cut it off with an ellipsis.
- The step shrank from 1,012 to 1,000 lines, and its size row was lowered to 1,000. `FirstRunSetupWizard.py` was not touched (3,177 lines, row unchanged). The task text names that file because it predates the TASK-34100.1 split; AC#4 was read against the step module.

**Tests rewritten on purpose (AC#3).** Eleven tests read a status as a radio row, three more than the plan's preflight listed. The nine in the wizard file assert through one helper (`_model_status_line`) that the picker's only child is exactly a `Static` with the expected id and copy, disabled and not focusable. The helper compares the text `render()` produces. `Static.renderable` is a shim in this repo that returns the source string, so it reads the same whether or not markup consumed part of the copy.
- `Tests/Wizards/test_first_run_setup_wizard.py`: `test_mounted_provider_handoff_preserves_typed_discovery_outcome`, `test_model_connection_failure_shows_bounded_category_and_retry`, `test_mounted_model_owner_timeout_fences_late_result_and_keeps_manual_retry`, `test_mounted_models_404_then_manual_model_never_reports_verified`, `test_model_step_no_provider_shows_pick_a_provider_copy`, `test_model_listing_unavailable_is_disabled_and_manual_entry_remains_enabled`, `test_auth_failed_probe_drives_row_gate_tracker_and_provider_notice` (now pins the full authentication copy), and the two the preflight missed: `test_mounted_real_transport_preserves_404_server_and_payload_categories` and `test_model_step_discovery_timeout_keeps_manual_entry_and_retry`.
- `Tests/UI/test_first_run_wizard_live_contract.py`: `test_model_step_renders_auth_copy_on_both_handoff_branches`. It is now a private-profile test, because it could not run its body in a shared profile here. Its first wait now waits for the wizard's container, because the child process starts cold and the old wait could return before the screen had composed.
- Same file, found in review: `test_production_sized_catalog_reaches_the_model_picker`. Its wait read radio labels only, so on any status it would have sat out its full 30 s, and its failure check (`"Couldn't reach" in label`) could no longer fire. It now waits on the picker's children, asserts that no `#setup-model-connection-failed` line rendered, prints the picker's content when it fails, and is a private-profile test.
- New: `test_model_status_is_plain_text_that_space_and_enter_cannot_pick` renders each of the six states, focuses the picker and presses Space, Enter and Down. It asserts the app is still running and nothing is selected. A seventh case passes `[bold]x` as the failure reason and expects it back unchanged, which pins `markup=False`.
- Proof the list is complete: with only the production change applied over the base tests, exactly those nine functions in the wizard file fail.

**One unrelated test changed.** `TestComposeCrashPolicy::test_optional_step_failure_is_removed_and_reported_in_summary` now waits for the summary rows instead of a fixed 0.4 s. Adding the new test upstream in the same file moved a full garbage-collection pause (about 340 ms in that process) into its 0.4 s window, so it failed in 5 of 5 file-level runs at head and in none of 3 without the new test. The lesson is in `backlog/docs/lessons-testing-evidence.md`.
