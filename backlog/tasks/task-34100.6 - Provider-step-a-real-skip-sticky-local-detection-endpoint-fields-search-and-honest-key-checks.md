## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Most first runs stall on the Provider step. A newcomer with no key yet finds that Next refuses every time and only a hidden Enter-in-the-key-field gesture skips. After that skip, the skipped provider's form stays on screen: a key pasted after Back is silently discarded, or Model loops on 'Saving the provider and model setup failed'. For a local-first user, a detected server is forgotten as soon as any provider is picked. LM Studio and Jan are never looked for, and 'no local server found' gives no reason and no next step. Azure OpenAI, Databricks and Cloudflare dead-end with no field for the URL they need. KoboldCpp and Z.ai save endpoints their handlers can't use, 32 presets show a Test button that never enables, and the 60 providers sit in an unsearchable five-row box. A power user's exported keys aren't marked in the list, and a rejected env key can't be replaced. Errors appear before the user does anything, lead with env/TOML jargon, sit far from the field at 2.74:1 contrast, and the step advances with ✓ over its own failed checks.

This task implements structural fix SF5 from the review (Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md, §5.1): the provider form is driven by the provider catalog, and detection is the first row. The shared catalog record that Settings already uses gains the facts the form needs: locality, key URL, env var, required base URL with its label and example, local ports, route suffix, check kind, and a legacy flag. The step then renders from that record. The task also carries the Provider-step slices of SF3 (a skip that works by keyboard and mouse and keeps the user's choice) and SF4 (one status owner, honest marks, readable errors), plus enhancements E2, E3 and E11. Ship it in slices that each stand alone: the skip and stale-draft fixes first, then Azure/Databricks/Cloudflare, then sticky detection, then the filter. Don't block on the full registry. Resolves: new-a11y-terminal-visual-02, new-provider-01, provider-01, provider-02, provider-05, coverage-08, coverage-19, cross-cutting-07, entry-exit-handoff-21, gap-04, new-coverage-power-03, new-provider-02, provider-03, provider-06, provider-11, provider-12, provider-13, provider-14, provider-15, provider-16, provider-19, provider-20, provider-21, provider-22, provider-23, provider-25, provider-26.

Coordination:

It makes the wizard a consumer of task-33005.9 (shared connection evidence) and task-33005.7 (readiness vocabulary), and it reuses the Settings-only non-billable key check from task-33005.4. entry-exit-handoff-21 complements task-33008.3.
- **Related issues elsewhere in this programme.** cross-cutting-03 (what Next means on every step), cross-cutting-06 (browsing selects; single dispatch) and provider-04 (resume hides the key field). new-model-01 and new-cross-cutting-02 share provider-21's hard-coded 'unconfirmed' model verdict, so whichever task lands first fixes that literal.
- **Order.** Land the stale-draft release (new-a11y-terminal-visual-02) with or before Next-on-empty-key skipping. Otherwise every user who goes Back and then skips lands in the loop.
- **Open PR #2862** moves the wizard's radio, step and provider-option widgets verbatim into a new module. Re-anchor if it merges first.
- **Keep (§5.5).** Sub-second detection that ignores non-LLM servers, forgiving endpoint entry, specific connection errors, secrets never written unless saved, and one catalog shared with Settings.
- **Live verification.** Discovery today probes only 127.0.0.1:8080, :9099 and :11434 plus configured endpoints. On the dev machine another session's Next.js server holds :8080, and neither Ollama nor LM Studio is installed. So llama.cpp is verified with a real llama-server on another port plus a configured endpoint.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** The Provider step is rebuilt around the shared catalog record
(structural fix SF5): `Chat/provider_setup_facts.py` owns what setup needs per
provider (locality, env var, sourced key URL or an explicit unconfirmed list,
per-account base URL with label and example, local ports, route suffix, check
kind, legacy flag), exposed as `ConsoleProviderCatalogEntry.setup_facts`, and
read by both the wizard and Settings. Detection is the list's first group, the
step has one status line, and Console's Get started card finally scans. The work
landed in the slices the description asked for (A: skip; B: key entry; C:
endpoint fields; D: list; E/F: detection, checks and status; G: Console card;
then the docs, the inventory pin, the boot-CSS shed and the live-found fixes).

**Approach and decisions.**
- *Helper modules, never a raised row.* The step module was split into a base
  chain (`first_run_provider_detection` -> `_key_entry` -> `_list` -> `_check`
  -> `ProviderStep`) so `@on` handlers stay registered. Rows lowered: Provider
  2,458 -> 1,713, Model 1,012 -> 991, wizard 3,177 -> 3,170. `chat_screen.py`
  stays exactly at base (25,391 lines, 764 methods).
- *Skip (A).* Next with an empty key, Enter in it and 'Skip — connect later' set
  a one-shot flag; the choice and typed drafts stay, the staged draft and Model
  handoff are released (`first_run_provider_skip.release_staged_provider_setup`).
- *Key entry (B).* `clean_api_key` strips invisible characters, wrapping (smart)
  quotes and `Bearer `/`NAME=` prefixes and says what it removed;
  `ProviderKeyInput` cleans the whole paste and echoes only length and last four.
- *Endpoint fields (C).* Per-account URL fields for Azure, Databricks and
  Cloudflare; KoboldCpp saves its native route; Z.ai owns its route suffix;
  TASK-34332's burst loss fixed by `BurstSafeInput` (marked Done in its file).
- *List (D).* Filter field and count on one row, Settings' matching rule
  (`settings_provider_view_model.provider_matches_query`); letters typed on the
  list go to the filter while the list keeps focus (burst-safe); Enter in the
  filter picks the highlighted match (it no longer advances the wizard); legacy
  rows behind 'Show legacy entries (N)'; 'Ready on this machine' (found servers,
  exported or saved keys) computed after first paint.
- *Detection (E).* Discovery adds :1234 (LM Studio), :1337 (Jan) and :5001
  (KoboldCpp), mapped to the Custom row and named by engine, plus the Custom
  rows' configured endpoints, in the same parallel short timeout; loopback
  spellings merge into one result per port. Found servers are sticky list rows;
  picking an engine by hand fills the found port; a quiet 15 s loopback re-check
  runs while the step shows; no-server state with the addresses checked, Check
  again, a collapsed how-to and 'Use llama3.2 with Ollama — I'll start it later'
  (Model starts with `llama3.2` typed).
- *Named failures.* `local_server_discovery.transport_failure_category` names
  certificate failures (`tls_untrusted`) and https-against-plain-HTTP
  (`tls_plain_http`, both live shapes) for the Settings probe and model
  discovery; the probe uses the app TLS policy (Settings ▸ Network's CA) and
  falls back to default verification if the policy can't be read. No inline
  'turn verification off'.
- *Checks and status (F).* 'Check key' runs the step's own selected-provider
  listing (the call Settings' key check makes) and reads it through Settings'
  `key_check_probe_result`; Next can reuse that listing. One status owner
  (`_set_status`) styles ✓/✗/! lines; a 401 refuses Next with the error under
  the key; any other failure flips Provider to '!' when Provider's check
  settles (`first_run_model_discovery.handed_off_probe_failure`). The pinned
  strip is `$text` on `$error 25%`, padded and prefixed '✗ '.
- *Console (G).* Root cause measured live: the card's scan ran on the UI loop,
  where `recovery_review.unqualified` raised `ProviderReconnectRequired`, which
  the card swallowed at debug level. It now scans off the loop
  (`discover_local_servers_off_loop`), offers 'Look again for a local server',
  says 'No model connected' when a local server answered, and 'Set up provider'
  opens Settings on a provider whose key is exported
  (`console_onboarding_state.env_keyed_provider_for_recovery`).
