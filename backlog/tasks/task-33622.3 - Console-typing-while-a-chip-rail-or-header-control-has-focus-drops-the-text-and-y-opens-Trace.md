## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** 'Just start typing' is the Console's core affordance, and terminal users type without looking. Printable keys typed while focus sits on a non-text Console control (status-strip chip, rail button, header action) are dropped with no feedback. The bare screen-level 'y' binding opens the full-screen Trace from any such control, and the rest of the user's words then run as Trace single-key commands. All three paths reproduce at human typing speed (150 ms per key) on dev 64579cce2c:
1. Click the Library access chip, press Esc, type 'yes'. Trace opens, and 'e'/'s' fire Trace actions ('All records are already loaded.', 'No matching Trace event.'). After Trace closes, the draft is empty and focus is on the chip.
2. Press Alt+I, then type 'Say hi.' + Enter. Trace opens and the draft is empty.
3. Click header Help, press Esc, type a 30-character sentence. None of it reaches the composer, which still shows 'Send disabled: type a message'.

The verifiers corrected several points. Returning focus to the invoking control is the recorded design (TASK-16211), and F1 then Esc does return to the composer; only mouse-opened dialogs strand focus. A second Esc returns to the composer. The focused chip does get a tint plus bold and underline, but the composer's unfocused state barely changes. Duplicate Library access dialogs stack only under burst input. Verdicts: live, code and skeptic all PARTIAL.

**Severity / prior art.** P1, triage NEW. Related: TASK-16314 (added the bare 'y' Trace binding), TASK-16211 (modal dismissal and focus return), TASK-32322 (rail escape hint), TASK-24604, TASK-23198, TASK-1800, TASK-24705.

**Suggested direction.** Add a type-to-compose fallback: an unbound printable key from a non-text Console control focuses the composer and inserts the character. Take Trace off the bare 'y', either with a modifier chord or by scoping it so it cannot fire from status-strip or header controls. Consider returning focus to the composer when a mouse-opened status-strip or header dialog is dismissed. At minimum, make the unfocused composer visibly different (e.g. an 'Esc to type' hint). Guard Library access activation so a dialog already on the stack is not pushed again.
