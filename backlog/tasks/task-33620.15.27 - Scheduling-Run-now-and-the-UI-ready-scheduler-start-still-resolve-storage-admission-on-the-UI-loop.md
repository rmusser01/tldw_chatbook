## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found reviewing TASK-33620.15.24, which moved the scheduler loop's own storage admissions off the UI loop. Callers outside the loop still enter storage admission (stats, realpaths, control-record reads) synchronously on the app's event loop: SchedulingService.run_reminder_now (the Schedules 'Run now' path, Scheduling/services/scheduling_service.py) enters execution_scope and reads the reminder row on the loop around the loop's own off-loop dispatch, and app startup calls execution_allowed for the scheduler DB (and for the FTS backfills) in on_mount and after _ui_ready (app.py). Live, the scheduler's own on-loop admission measured about 9 ms median and up to 70 ms at high load before TASK-33620.15.24; these sites have not been measured.
