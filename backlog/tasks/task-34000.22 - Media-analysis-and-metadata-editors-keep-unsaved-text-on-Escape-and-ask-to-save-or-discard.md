## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: a power user (Morgan, j4) writing an analysis by hand in the Media reader pressed Escape out of habit and lost the whole paragraph. Escape elsewhere in Library means "leave the field" and keeps the text, and the Prompts editor refuses a dirty Escape with "esc save or discard first". Here one reflex keypress destroys authored text with no prompt. Keyboard-only users are hit hardest, because Escape is how they get out of a field.

Observed (live, 160x45, golden profile): Analysis ▸ Add analysis ▸ type a paragraph ▸ Esc. The reader shows "No analysis yet." and the text is gone (verify capture 06-after-esc). While typing, the footer read "esc close". The verifier also found the same unguarded discard in the Edit metadata form.

Verified cause (origin/dev 2d34cbf80d): `action_library_media_viewer_back` (UI/Screens/library_screen.py:30950) clears the sub-state flags unconditionally: metadata `editing` at :30977-30980 and `editing_analysis` at :30985-30988. Its docstring records that these forms have no dirty field, so Escape copies their Cancel buttons, which also discard unconditionally. ADR-055 Pattern D requires an explicit act before unsaved drafts are dropped: a dirty-veto plus a deliberate Discard. Prompts and Skills already conform; these two Media forms do not.

Hypothesis, not reproduced: the rail-switch reset clears both forms the same way (library_screen.py:22394 `editing = False`, :22397 `editing_analysis = False`), so pressing another rail row may also drop the typed text silently. Confirm this before fixing.

Suggested direction (the review's refined fix): record a baseline when each form opens. A dirty Escape keeps the form, and the footer chip reads "esc save or discard first" (the existing `LIBRARY_PROMPT_DIRTY_ESCAPE_CHIP` copy). While the form is dirty, Cancel becomes "Discard changes". A clean form still closes in one step. Apply the same to the metadata form.

Owning-task note: no existing task covers this. Finding L-07 (Add analysis leaves focus on the Items row) is a separate review finding about the same editor's focus, not about discarding.

Review finding(s): L-08. Source: qa/notes-library-ux-review-2026-10-02/report.md

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** The Media reader's two authoring forms now hold a draft in state (`LibraryMediaState.edit_draft` /
`analysis_draft`, beside `editing` / `editing_analysis`; field count 84 -> 86), compose from it, and refuse every exit
while it differs from the saved value (ADR-055 Pattern D): Escape, "‹ Back", a row press, the keyboard row walk (`on_key`
Up/Down over a media row, plus a silent `on_descendant_focus` backstop for a click's queued focus bubble and Tab), a rail
row, the nav bar (`flush_pending_work`, through #3184's `say()`/`spoken` so one click gets one toast) and Ctrl+Q
(`library_pending_work._unsaved_names` names "unsaved analysis" / "unsaved media details"). The one predicate is
`LibraryMediaController._library_media_editor_dirty()` ("edit" / "analysis" / "") over two pure functions in
`Library/library_media_viewer_state.py` (`media_edit_form_dirty`, `media_analysis_dirty`: raw compare, no stripping,
None is clean, typed-back-to-baseline is clean). The veto copy is `LIBRARY_MEDIA_EDIT_DIRTY_VETO_COPY` /
`LIBRARY_MEDIA_ANALYSIS_DIRTY_VETO_COPY` (`markup=False`); the footer chip reuses `LIBRARY_PROMPT_DIRTY_ESCAPE_CHIP`
through `_library_media_escape_label` (so `check_action` and the chip read one seam); the viewer relabels Cancel
"Discard changes" in place (`LibraryMediaViewer.sync_editor_drafts`, called on both sync paths, never a
compose-compare input, so a keystroke never recomposes the field) -- that press and Save are the only two ways out of a
dirty form. Drafts are seeded at open (a mount-time `Changed` is a no-op), written on every `Changed`, resynced only on
the clean<->dirty flip, cleared beside every flag clear, and dropped per item at `_select_library_media_reader_row`
(the TASK-34000.24 `link_receipt` rule) so a clean draft is never composed over the next item's form.
