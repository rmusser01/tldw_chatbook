## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** On 6 of 6 healthy sends at 235x52, while the header said 'Running' and the transcript said 'Thinking... 5s', the Inspect rail showed:
- pinned summary 'Run: Blocked';
- Run section 'Provider: blocked - Provider setup needed: current run is active', in red;
- Conversation settings 'Not ready - current run is active';
- collapsed edge badge 'setup'.

All of these reverted once the run finished.

On 3 of 5 slow-mode sends, 1.5-3 s after Enter, the composer also showed 'Send blocked - finish provider setup to continue >'. That strip links to `app.run_setup_wizard`, and clicking it mid-run opened the first-run wizard over the Console. The cause: the prompt queue's pre-acceptance 'Preparing...' tooltip (and, by the same code path, 'Queue full') is passed in the `setup_blocked_reason` slot.

The panel that answers 'What happens if I send now?' is therefore wrong on every turn. Users learn to ignore 'Blocked' and 'setup' before a real key problem ever occurs.

**Severity / prior art.** P1, confirmed by all three verifiers. This is a **REGRESSION of TASK-347 (Done)**: status surfaces should reflect active generation. It also regresses **TASK-32345 (Done)**, whose guard was applied to one consumer only, and **TASK-24602 (Done)**. TASK-21145 is related. The mechanisms:
- `active_run` is computed as a provider-readiness blocker and routed through the 'Provider setup needed: {blocker}' template (`console_settings_summary.py:167`, Inspector at chat_screen.py:14424-14433).
- The authority rollup evaluates 'Blocked' before run_active (`console_send_authority_summary.py:143-150`).
- The edge badge matches 'provider' plus 'blocked' in row text.

The umbrella task owns the shared ConsoleRunPresentation. This task makes these specific surfaces honest.

**Suggested direction.** Treat active_run as a run-state fact, not a provider blocker, for display consumers. Keep it only for gating settings mutations, where the settings modal already renders it correctly. Let run_active and a pending approval win over a provider 'blocked' caused by active_run. Derive the edge badge from the structured run status. Give the queue its own reason slot, so that Preparing and Queue full have their own copy and never get the setup link.
