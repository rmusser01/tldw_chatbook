## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: "Export…" in the Media list toolbar is the obvious "save my stuff" button for a first-timer. Pressing it hangs the whole app. Nothing responds, Ctrl+Q included, so the user has to kill the terminal and loses any unsaved work elsewhere in the session (compounded by N-01). Keyboard-only users are stuck as well: no key gets them out.

What was observed:
- Library ▸ Media (23) ▸ click "┃ Export… ┃" in the Items toolbar. After that, F1, Ctrl+P, rail clicks and Ctrl+Q do nothing.
- Resizing the tmux window from 160 to 120 columns does not repaint. Verify capture 07 still shows the 160-column frame, cut off.
- The process sits at 0% CPU. The app's SIGUSR2 faulthandler dump shows the main thread idle in `selectors.select` inside the asyncio loop, with no traceback.
- Reproduced 3/3 by the first-timer journey (j2), including a fresh profile with one imported .md, and again by the verifier.
- Other Export paths do not freeze. Select mode ('s' ▸ Export) and the rail Export reach the same canvas without a hang, so the trigger is the list-toolbar button.

Verified cause (origin/dev 2d34cbf80d): the verifier proved a self-removal deadlock with a minimal Textual repro.
- `LibraryMediaCanvas.handle_library_media_export` is the one async forwarder among the canvas's sixteen rows (Widgets/Library/library_media_canvas.py:537-546).
- It awaits the controller's handler, which runs `_open_library_export_canvas` (UI/Library_Modules/library_export_controller.py:741-786). That calls `_apply_library_open_item_surface`, which awaits `self.recompose()` (UI/Screens/library_screen.py:12404-12405).
- The recompose removes the media canvas whose message pump is still awaiting the handler, so neither side can finish.
- The forwarder's docstring ("awaits a modal") is stale.
- Introduced by 480eadbba8 (2026-09-09, "the media canvas owns its sixteen canvas-origin rows"). Sibling export buttons such as `#library-prompts-export` are routed on the screen (library_screen.py:29708) and do not hang.

Suggested direction (a direction, not a mandate):
- Make the canvas's export forwarder synchronous and hand off through `self.screen.call_later`, or route `#library-media-export` on the screen like its siblings.
- Guard `_apply_library_open_item_surface` against being awaited from a handler on a widget its recompose removes.
- Fix the stale docstring.

Ownership: no existing task owns this. The Export canvas's own content problems are owned elsewhere: L-18 (TASK-32381, TASK-32382) and L-04.

Review finding(s): L-01. Source: qa/notes-library-ux-review-2026-10-02/report.md

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Premise, established first (plan step 0).** The review found the P0 on dev 2d34cbf80d. Between that commit
and this wave's base 8c4dfe59a2, 3cee32b3d0 (task-31249) replaced the inline
`await self._apply_library_open_item_surface(...)` in `_open_library_export_canvas` with
`self.call_after_refresh(self._project_library_export_canvas)`, which runs on the SCREEN's task and completes.
So on the base the press already opens Export (control captures 93-94; the new regression test passes 4/4
there). What was still missing, and what this task ships: the hand-off at the widget, a guard for the whole
class, and a regression test that fails instead of hanging.

**Root cause (file:line at 2d34cbf80d).** `LibraryMediaCanvas.handle_library_media_export`
(`Widgets/Library/library_media_canvas.py:538-546`) was the one `async` forwarder of the canvas's sixteen; it
awaited `LibraryMediaController.handle_library_media_export` → `_open_library_export_canvas`
(`UI/Library_Modules/library_export_controller.py:777-784`) → `_apply_library_open_item_surface`'s structural
branch `await self.recompose()` (`UI/Screens/library_screen.py`, now :12556). `Widget.recompose`
(textual 8.2.8 `widget.py:1713`) removes the screen's children, the Media canvas among them, and each removed
widget's `_message_loop_exit` (`widget.py:4523`) gathers its children's pump tasks with no timeout. The press was
running ON the canvas's pump task, so the teardown waited for the handler and the handler for the teardown.
`App._prune` also hands the removal to `app.call_next`, so the APP pump parked too (that is why Ctrl+Q died), and
`Screen.recompose` holds `App.batch_update`, so nothing repainted. The verify dump's main thread idle in
`selectors.select` is what a fully parked loop looks like; the await chain in capture 81 names the exact path.

**Changes.**
- Hand-off: the canvas forwarder is synchronous like its siblings (stale "awaits a modal" docstring corrected);
  the controller's handler is synchronous and hands the open to the screen's pump with `self.call_next(...)`.
- Guard (`UI/Navigation/surface_swap_guard.py`): `pump_awaiting_its_own_removal` compares the current asyncio
  TASK with the pump task of every strict descendant of the removed roots (measured: `active_message_pump`
  reads the canvas on two shapes that complete, and a removed ROOT may await its own removal). Wired at
  `BaseAppScreen.recompose` and `BaseAppScreen.children_safe_to_await_removing`, and the Library calls the
  latter at every awaited canvas-host child removal: `_project_library_canvas_child`,
  `_repair_library_entry_canvas_owner`, `_reconcile_library_entry_state` (re-raised past its retry handler),
  plus `library_browse_route_swap.py`'s stale-child and source-strip removals.
- Fallback: `_apply_library_open_item_surface` turns a refusal from either branch into its documented
  whole-screen refresh on the screen's own pump, logged at ERROR naming the widget
  (`log_refused_surface_swap`). Rationale: with the WIP's raise, the live defect-reintroduced run showed the
  keep-alive toast and a blanked Items pane (Textual closes the pump whose handler raised); with the fallback
  Export opens and the log still names the bug. The raw seams still raise, so tests stay loud.
- Tests: `Tests/Architecture/test_surface_swap_guard.py` (predicate against a minimal app for 2 refused + 6
  completing shapes, the child-swap twin, a static AST pin over `Widgets/Library` with its negative control);
  `Tests/UI/test_library_media_export_no_freeze.py` (AC#4, 4 parametrizations, imports no fix-side module so
  it runs unmodified on any commit; PR UI lane); `Tests/UI/test_library_surface_swap_refused_on_real_screen.py`
  (the five Library seams on the real screen; not in the lane); `Tests/UI/pump_probe.py` (helper, never
  collected: wall-clock polls, `cr_await` chains naming the parked pump, cycle-cutting `unpark` for tear-down).
  PR UI lane: the gated file alone measured 4 passed in 30.12 s (37.9 s wall) against the 60 s budget (capture 83).
- CI: the Architecture file is in the fast lane (`derived-artifacts.yml` + `test_ci_queue_pressure_contract.py`);
  the gated Pilot file is in `scripts/ui_pr_gate_census.txt`.
