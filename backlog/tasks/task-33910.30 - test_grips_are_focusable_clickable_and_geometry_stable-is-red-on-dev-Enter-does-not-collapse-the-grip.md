## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`Tests/UI/test_library_media_reader_shell.py::test_grips_are_focusable_clickable_and_geometry_stable` is red on dev. After it focuses the Library grip and presses Enter, the grip still reads "collapse" (`AssertionError: assert '<---' == '--->'`), so the test cannot show that Enter collapses the pane.

ADR-212's grip exception (G1a) relies on grips answering Enter and Space like buttons. While this test is red, nothing in the Library suite protects that guarantee.

**Evidence (Roleplay frame B0, TASK-33910.1):**
- The failure is identical on dev and on the B0 head. B0's paired base arm saw it in the shell and library groups on both arms (base `74bd039d60`).
- On 2026-10-03 the whole file was run serially at dev `0409592a2d` and at the B0 head. The test failed 4 of 4 runs, 2 per arm.
- The same file has 7 other failures that occur on both arms. They cover persisted layout reads, settings repair and peer-shell resync.
- Run alone, the test passes on both arms. The failure therefore depends on test order: an earlier test in the file leaves state behind.

The fix is to repair the test or retire it in favour of a test that pins the same contract.
