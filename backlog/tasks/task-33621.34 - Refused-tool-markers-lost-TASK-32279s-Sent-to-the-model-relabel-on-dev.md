## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**What dropped it.** `git log -S 'Sent to the model'` from dev returns nothing (history simplification hides it), so I read the file's blob at each commit on PR #2594's branch. The label is present from 47a613e375 through 1170311a6c and absent from 35b8300999 on. That commit is "Merge origin/dev (a7f78053df, incl. #2586 lane A) into fix/approval-wave-b-card". Its message says "console_message_actions.py: this lane never touched it (ours == merge base), dev's version taken". The premise was false, because 47a613e375 on that same lane had touched the file. Taking dev's copy reverted the three TASK-32279 hunks (the import, the `_TOOL_REFUSAL_OUTPUT_ACTIONS` table and `_is_refusal_marker`, and the branch that picks between them). Dev's side carried TASK-32312's thinking-edit filter, which survived. The PR merged as 98fa72d040 without the relabel. Nothing else from TASK-32279 was lost: `console_activity_status_word` and the `denied` / `blocked (Off)` / `blocked (kill switch)` words are still on dev.

**Fix.** Restored the three hunks on dev's current file. TASK-32312's filter and every later change are untouched. The raw-CLI early-return branch keeps "Full output", as TASK-32279 left it. `raw_cli_activity_presentation` maps a cancelled or timed-out command to `blocked`, which is a refusal status, but that body is the command's own output.

**Tests.** The pin `test_refused_tool_marker_says_the_body_went_to_the_model` was red at 2f7790873a (4 failed) and is green after the fix (4 passed). The new `test_stopped_raw_cli_marker_keeps_full_output_label[cancelled|timed_out]` pins the raw-CLI boundary. The whole file gives 126 passed, 6 failed. The 6 failures are the same canvas/mermaid tests that fail at the base ("Canvas is disabled" from the config-reading canvas gate), which is unrelated to this task. Mutations (Edit-applied, Edit-restored):
- M1: relabel inside the raw-CLI branch. The guard fails 2 of 2.
- M2: `_is_refusal_marker` true only for `denied`. The pin fails 3 of 4 (blocked_off, blocked_kill_switch, blocked).
- M3: relabel every marker. `test_full_output_tool_marker_keeps_full_output_label` and `..._with_full_output_and_diff_...` fail.
- M4: drop the pin from the workflow step. `test_fast_lane_target_set_is_exact_and_non_overlapping` fails.

**Lane.** `check_ui_pr_gate_census.py` rejects entries outside `Tests/UI/` ("not a Tests/UI path"), so the census cannot take this pin. The whole file cannot ride a lane while its 6 canvas tests fail. So four node ids joined the PR Fast Lane's sandboxed step ("Run fast PR contract"): the pin, the raw-CLI guard, and the two TASK-1860 "Full output" pins that catch M3. `FAST_LANE_TARGETS` in `Tests/CI/test_ci_queue_pressure_contract.py` mirrors the step. The entries sit beside the approval riders rather than at the tail, to stay out of other PRs' tail appends. The 8 tests take 0.8 s. Lane contracts: `Tests/CI/test_ci_queue_pressure_contract.py` 156 passed, `test_derived_artifacts_workflow.py` 78, `test_console_approval_critical_gate.py` 6, `test_console_p0_regression_gate.py` 175, `test_self_hosted_runner_routing.py` 403, `test_personal_context_regression_gate.py` 8, `test_project_chat_uat_gate.py` 1. Pinned ruff 0.16.6 reports the same findings in `console_message_actions.py` before and after (5 B008, all pre-existing).

**Live (2026-11-22, real app, real config, real claude-haiku-4-5 through the review proxy).** Both profiles were isolated and set `[tools] create_note_enabled = true`. The fix build (this branch) and a detached dev worktree at 2f7790873a got the same prompt. On each, a real approval card for `create_note` appeared, and I pressed Deny. Both markers read `create_note · Denied by you`, and the app log has `tool_result tool="create_note" outcome=blocked`. With the marker selected, the action button reads **Sent to the model** on the fix build and **Full output** on dev. Evidence (screenshots, pane text, log excerpts, test logs) is in the session's `tools/evidence/bd5/U34/`.

**Docs.** `Docs/User_Guide/console/agent-runs-and-tools.md` already describes "Sent to the model", so this fix makes the guide true again without an edit.

**Follow-ups noticed, not done (outside the ACs).**
- The expanded detail of a call-id tool marker (`format_tool_activity_detail` in `Chat/console_tool_activity.py`) still heads the refusal text with **Result**. That repeats, one level down, the misreading TASK-32279 fixed.
- The `tool-output` tooltip ("Show or hide this tool call's full result (o)") and the `o` binding's footer label ("Full output") are not status-aware either.

**Lesson (left here, per instructions, rather than in lessons-*.md).** A merge resolution that takes one side whole on the premise "this lane never touched the file" must check that premise with `git log <merge-base>..<lane-head> -- <file>`. Here the check would have listed 47a613e375. The pin stayed red for ten weeks because no PR lane ran its file, so a revert of a pinned fix is only caught if the pin is laned.
