## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
This covers the local half of C2. Keyless local servers read Ready once a model is set, whether or not they are running (llama.cpp defaults to 127.0.0.1:9099, console_provider_gateway.py:195), and nothing probes them in the background.

The switcher from phase P4 is where a user chooses between them, so that is where a bounded, cached reachability probe belongs (judge-synthesis §4 P5; spec §5 'local endpoints'). A bounded, non-generating probe already exists: _test_console_connection (chat_screen.py:3207-3247) calls probe_settings_endpoint with a 2.5 s timeout (SETTINGS_ENDPOINT_PROBE_TIMEOUT_SECONDS, settings_endpoint_probe.py:49).

The provider set needs care:
- URL_BASED_PROVIDER_KEYS includes qwencloud (provider_endpoint_contract.py:24-40), which is a cloud provider. D2 forbids auto-probing it, so that set cannot be the probe set.
- KEYLESS_PROVIDER_KEYS (provider_readiness.py:89-111) excludes qwencloud but includes custom, custom_2 and custom_openai_api, which can point at a remote hosted service. 'Keyless' alone is therefore not 'local'.
- A custom endpoint that resolves a credential would send it, so it is excluded too.

The mockup's NEEDS SETUP row for a refused server reads 'start it; rechecked on open': the fix is outside the app, so Enter must not send the user to Settings for it.

The Fedora UI-lag program found network and keyring calls on the UI loop causing stalls. Probes must never delay opening the switcher, and ADR-011 keeps provider calls out of shared widgets.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Opening the switcher probes each configured keyless endpoint it lists whose host is loopback or a private-network address, off the UI thread. The switcher paints and accepts keys without waiting for any probe
- [x] #2 Each probe uses the existing short bounded timeout, and one open never has more than a small, fixed number of probes in flight
- [x] #3 A result younger than a named cache window is reused: opening the switcher twice inside the window sends at most one probe per endpoint
- [x] #4 No credential is ever sent by an automatic probe. qwencloud, every key-requiring provider, any keyless endpoint on a public host, and any custom endpoint that resolves a credential are never contacted automatically
- [x] #5 Probes run through a seam the screen or a Console module owns; the switcher widget makes no network call itself (ADR-011)
- [x] #6 Results enter the shared evidence owner. A refused llama.cpp shows 'Not ready · refused :9099' in the switcher and, when it is the active chat's connection, in the Console status row. A running server shows 'Ready · reachable HH:MM'
- [x] #7 A row whose failure lies outside the app (a refused or timed-out local server) shows in-place guidance such as 'start it; rechecked on open', and Enter on it does not navigate
- [x] #8 Closing the switcher mid-probe raises nothing, and a late result cannot overwrite newer evidence
- [x] #9 A test proves the probe runs off the main thread and that the switcher's first paint does not wait for it
- [x] #10 A live capture at 211x44, with llama.cpp stopped and Ollama running, shows both words in the switcher

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. console_send_connection (console_session_settings.py): the connection a send uses, resolved as the readiness builder keys its evidence lookup, so a settled probe is the one readiness reads.
2. connection_probe.py: switcher_probe_target (keyless AND URL-based, no credential, loopback/private literal host, models route), switcher_probe_plan (thread), switcher_connection_prober (named cache window, per-open in-flight cap, each probe in a worker thread through settle_connection_probe, settled callback).
3. Popover: optional connection_prober seam offered once per provider per open for rows a probe can change; refresh_readiness (no network); retry_connection rows read "start it; rechecked on open", lead NEEDS SETUP, and Enter explains in place.
4. model_switcher.open_model_switcher passes the seam; chat_screen idle poll reads the evidence version before building readiness (probes settle off-thread).
5. Tests (Chat targets/parity, UI pilot + Console integration, mutation checks), console.md, live 211x44 capture with llama.cpp stopped and Ollama running.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Opening Switch model (Alt+M) now checks the local servers it lists, in the background, through the Console's one probe path; results enter the shared evidence owner, so the switcher rows and this chat's status read "Not ready · refused :9099" or "Ready · reachable HH:MM".

**Which connections (AC#1/#4).** `connection_probe.switcher_probe_target`: keyless AND URL-based (`KEYLESS_PROVIDER_KEYS & URL_BASED_PROVIDER_KEYS`, so not qwencloud and not the in-process mlx/onnx/transformers/local_llm), a models route, `credential_revision == 0` (no credential would be sent: excludes keyed vLLM, a custom slot or registry entry with a key), and a literal `localhost` / loopback / private-network IP (link-local and public IPs, IPv4-mapped included, and every other host name are never contacted; names are not resolved). The connection comes from the new `console_session_settings.console_send_connection`, resolved exactly as the readiness builder keys its evidence lookup (pinned by `test_the_probed_connection_is_the_one_readiness_reads`).

**How (AC#2/#3/#5/#8/#9).** `switcher_connection_prober(app, app_config)` is the seam `model_switcher.open_model_switcher` passes to the popover (`connection_prober`); the widget only offers its rows and re-reads readiness (`refresh_readiness`, no network, ADR-011). Per open: planning runs in a worker thread, at most `SWITCHER_PROBES_IN_FLIGHT = 3` probes run at once, each in its own worker thread through `settle_connection_probe` (the 2.5 s probe, Task 1's begin-order settle, so a late result never replaces a newer one). A connection probed (queued) or tested on any surface less than `SWITCHER_PROBE_CACHE_SECONDS = 10` ago is not probed again. Rows offered: Ready rows and failed-test rows, the only words a probe can change. Closing the switcher cancels the wait; a running probe still settles.

**Rows (AC#6/#7).** A `retry_connection` row reads "start it; rechecked on open" and Enter on it says "<provider> did not answer: start it; rechecked on open." instead of opening Settings. Failed-test rows now lead NEEDS SETUP: in a default profile ~45 cloud providers without keys filled the 8-row cap and hid a refused llama.cpp.

**Also fixed (root cause found live).** `local_server_discovery.connect_error_is_refused` now looks inside exception groups: a refused `localhost` (::1 + 127.0.0.1) read "unreachable" instead of "refused :PORT", on every probe surface (shipped llama.cpp default is `localhost:8080`). The idle Console poll now reads the evidence version before building readiness, so a probe settling off-thread mid-build still refreshes on the next tick (Task 2 review M-3; pinned with a negative control).

**Tests.** `Tests/Chat/test_switcher_probe_targets.py` (28: targets, exclusions, identity parity), `Tests/UI/test_console_switcher_local_probe.py` (11: off-thread + first paint, in-flight cap, cache incl. in-flight reopen, no key/cloud/public, Enter in place, close mid-probe + late result, no network in the widget, real Console Alt+M -> header refused, mid-poll settle race), `Tests/Chat/test_local_server_discovery.py::test_a_host_name_refused_on_every_address_reads_as_refused`. `Tests/UI/conftest.py` gains `_no_switcher_local_probes` (the egress guard failed 15 existing Alt+M tests on real loopback probes; same pattern as `_disable_model_catalog_refresh`). Mutation checks (guard removed -> its test fails) for the Enter guard, failed-test ordering, host/key filter, in-flight cap and the queued mark.

No CSS. connection_probe stays lazily imported (boot census unchanged). Diagnostic inventory regenerated for one reviewed `logger.debug` (provider key + exception class).
