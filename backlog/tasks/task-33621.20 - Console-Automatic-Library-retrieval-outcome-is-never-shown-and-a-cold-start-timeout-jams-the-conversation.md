## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** With Library set to Automatic, a send whose search finds 0 matches looks the same as any other turn:
- the chip still reads 'Library · Auto on';
- 'Sources: 0' does not change;
- nothing appears on the turn.

The controller does persist a bounded `library_preparation` sidecar (`{"outcome":"zero_matches"}`) on the USER message, but no UI code ever projects it, live or after a restart. A successful retrieval is not disclosed either, so a user relying on grounded answers cannot tell a grounded turn from an ungrounded one.

A real retrieval failure is worse. The first Automatic send after every launch hits the 5 s `library_preparation_timeout` while the RAG service cold-initialises (about 4-5 s). The turn then pauses with only 'Queue 0/10 · Unsent turn needs attention · Restore / Discard', while Inspect says 'Run: Ready' and no reason is shown. Nothing in the UI calls retry, bypass or cancel for a RETRIEVAL pause. Every later send in that conversation is refused at `controller_submit` with the undisplayed 'Another send is still preparing for this conversation.' This holds even after Discard and after switching the policy to Never.

**Severity / prior art.** P1, REGRESSION of TASK-19900.3 (Done 2026-08-23):
- AC#5: a timeout or failure pauses with Retry, Send once without Library, and Cancel.
- AC#6/#7: zero-match sent-turn disclosures persist.

TASK-3504 (Won't Do) was closed as superseded by this same PR #1933 design.

Out of scope: the false 'Retrieval failed' Trace entry from `capture_provider_failure` is finding G2-37. An empty-Library hint on the chip is optional and has no task.

**Suggested direction.**
- Render the persisted sidecar as a compact per-turn line ('Library: N sources sent' / '0 matches · sent without Library evidence').
- Show the reason for RETRIEVAL pauses and wire Retry, Send once without Library and Cancel.
- Make Restore or Discard cancel the paused preparation.
- Pre-warm the RAG service, or exclude cold initialisation from the 5 s budget.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G2-09 (source J4-05); qa/console-ux-review-2026-09-29/evidence/evidence__J4__61-auto-send-2.png, evidence__J4__log-excerpts.txt.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Status (2026-10-10): AC#2, AC#3 and AC#4 are met. AC#1 is not started, and AC#5 is half done.** AC#5's first test (the zero-match line rendered from the persisted sidecar after a reload) needs AC#1. Both are left for a follow-up; see the end of these notes.

**AC#4 (cold start).**
- `LibraryLocalRagSearchService.warm_up()` builds the shared RAG runtime.
- `Chat/console_library_search.py` runs that build under its own 60 s bound before the 5 s search budget, in the first-send and dispatch-retry paths.
- The automatic search runs as its own task, registered per session (`controller._library_search_tasks`):
  - while it runs, the run chip reads **Run: Searching Library…**;
  - `is_stop_allowed` shows **Stop**, and `stop_active_run` cancels only that task;
  - a Stop becomes a RETRIEVAL pause (`library_retrieval_stopped`);
  - cancelling the send itself (shutdown, close) still propagates;
  - the chip is handed back afterwards, because a Retry's continuation is refused from VALIDATING ("A run is already preparing.").
- Off the UI thread: the build already runs in `asyncio.to_thread`.
- With Library set to Never, no preparation runs, so there is no warm-up either.

**AC#3 (jam).**
- The refused submit now carries `preparation_id`, and `ConsoleTurnRecoveryEntry` records it.
- `discard_turn_recovery`, used by both Restore and Discard, releases exactly that RETRIEVAL-paused preparation. It does so through `Chat/console_unsent_turn.py`, which keeps the draft the shelf action left.
- Teardown passes `release=False`, because the controller's own close and shutdown abandon live preparations.

**AC#2 (reason + actions).**
- `trace_call_recovery_preparation` and `trace_call_recovery_state` now project RETRIEVAL pauses into the pre-dispatch card. The card shows the reason ("Library search timed out; your message was not sent" and "Problem: …") and three actions:
  - **Retry Library search** (`retry_library_preparation`);
  - **Send once without Library**, a new button (`bypass_library_preparation`);
  - **Cancel send** (`cancel_library_preparation`), which refills an empty composer.
- The run chip and the Inspect Run line read **Blocked — Library timeout / error / stopped**.
- A card action that sends or returns the turn drops its unsent-turn shelf copy (`ConsoleRuntime.forget_turn_recoveries_for_preparation`).
