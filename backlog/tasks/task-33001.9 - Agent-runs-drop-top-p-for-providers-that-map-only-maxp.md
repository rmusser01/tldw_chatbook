## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Rider from TASK-33001.2 (preflight ruling R4). TASK-33001.2 made one table, `GENERATION_FIELD_REQUEST_KEYS` in Chat/console_provider_support.py, the only definition of which `chat_api_call` key(s) carry each generation field. It maps `top_p` to both `topp` and `maxp`, because the Console request builders (`ConsoleProviderGateway._chat_api_kwargs` and `_chat_api_kwargs_from_prepared`) send top_p under both names, and OpenAI, Groq, Moonshot, Z.ai and custom-openai-api carry only `maxp` in `PROVIDER_PARAM_MAP`.

The agent runtime has its own copy of that mapping: `_CHAT_CALL_PARAM_MAP` in Agents/agent_service.py maps `top_p` to `topp` only. `project_chat_handler_kwargs` forwards only mapped keys, so an agent run whose sampling params include top_p sends no top_p at all to those providers, with no warning. The Console chat path is unaffected. The Settings and Console surfaces now report Top P as supported for OpenAI, because the Console request does forward it, so an agent run silently disagrees with what those surfaces show.
