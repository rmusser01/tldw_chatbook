## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Keep ephemeral generated-video storage bounded throughout a long-running app session without reapplying startup cleanup. When one generated video is larger than the configured cap, preserve user control by offering an explicit managed-store exception, external save, or discard instead of silently losing media.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 After each successful ordinary video save, the active store is at or below the configured total size cap; the only permitted over-cap state is one explicitly approved oversized video as the store's sole file.
- [x] #2 Ordinary saves evict oldest live videos first, their existing cards resolve as expired, and the newly saved video remains ready.
- [x] #3 A video larger than the entire cap is not silently stored or discarded: initial generation and Regenerate both offer Keep here and evict all, Save to disk and open externally, or Discard.
- [x] #4 Keep here removes all other managed videos before appending the new card; Save to disk uses an `.mp4`-default file picker with no-clobber commit and confirmed replacement, then opens externally and appends no card; Discard and picker cancellation append no card.
- [x] #5 Post-save capacity enforcement never reapplies session or TTL startup cleanup, while the approved sole oversized file remains subject to normal session/TTL removal and is evicted by a later ordinary save.
- [x] #6 Concurrent saves from threads or app processes sharing one store root and filesystem failures cannot report false cap compliance, expose a partial managed file, destroy existing videos on publication failure, or lose the generated payload before the user chooses another outcome; lock contention times out without hanging startup or generation.
- [x] #7 Capacity inventory and eviction never follow symlinked directories, symlinked files, junctions, or reparse points outside the managed root, including during ordinary saves, startup capacity, and evict-all.
- [x] #8 Focused mutation tests protect the save-time capacity hook, oldest-first order, in-process and root-scoped interprocess locks, non-following deletion, startup-policy separation, no-clobber/overwrite handling, and staged-artifact lifetime across screen teardown.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Harden `VideoStore` inventory against linked/reparse-point escapes and add one bounded root-scoped transaction spanning threads and app processes.
2. Make ordinary saves publish complete candidates, evict oldest files, verify actual capacity, and return typed overflow or recoverable managed-save failures without reusing startup retention.
3. Preserve unstored generation bytes in an idempotently owned pending artifact and add retry/oversized adoption plus atomic external-copy operations. Create a per-message public, lock-linearized publication gate before generation storage begins so teardown cannot race either initial publication or later adoption, reach into private store transactions, or require an unlocked rollback.
4. Add the three-choice Console modal and one shared initial/Regenerate outcome resolver, including overwrite reconfirmation, OS opening, terminal screen ownership, active-operation lifetime, and screen-unmount cleanup.
5. Prove the real storage, generation, modal, startup-containment, concurrency, security, failure, and mutation paths with only touched-file-related tests; run scoped static checks and record completion evidence.
