## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-33620.1 made the stop hold every manual Console send and queue admission, and show the hold. Several other entry points still start runs while the stop is active, because controller.submit_draft has no stop gate of its own (only send_refusal_copy, which the Console composer's dispatch path consults, reads the stop):
- Prompts already queued before /emergency-stop drain after the running turn ends. ConsolePromptQueueCoordinator._drain_waiting (Chat/console_prompt_queue_coordinator.py) claims and submits waiting entries without consulting the stop.
- Goal iterations (ConsoleSubmissionOrigin.GOAL_ITERATION) reach submit_draft the same way.
- The Buddy conversation send (UI/Navigation/buddy_conversation.py) calls controller.submit_draft directly.
- The mobile web server's send (Web_Server/mobile_service.py) calls engine.controller.submit_draft directly.
Found by reading the code on 2026-10-29 (the last two by TASK-33620.1's review); none reproduced live yet. TASK-26004 says the stop holds every new run, so one gate where every path converges (submit_draft or runtime admission) is preferable to one per caller.
<!-- SECTION:DESCRIPTION:END -->
