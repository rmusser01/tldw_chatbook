## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in the TASK-33628.16 review and confirmed on 2026-11-06 (origin/dev 8ae979d81b plus that fix; the archive check is unchanged by it). The archive check for an open Console tab refuses while any transcript row has no saved id, and Console's own SYSTEM rows (/help and /doctor output, error notices such as the /prefill pin usage hint) are never saved. So once one of them is in a saved chat, archiving that chat, or the workspace it belongs to, is refused with "Wait for the transcript to finish saving before archiving." The wait never ends, because nothing is still saving. (From code reading, not tried: the check only looks at open tabs, so closing the tab should let the archive through.) A throwaway test on the real path (real TldwCli, ChatScreen, controller, store, ChatPersistenceService on an in-memory ChaChaNotes DB, real keys, only the provider gateway replaced) saved one real turn: both the chat and the workspace archive checks returned no refusal. After /help, /doctor or /prefill pin ran and the composer was cleared, both returned that refusal, for all three row kinds. The owner decision of 2026-10-29 (TASK-33628.16) ruled that these rows are not loss in the close and quit dialogs, and Fork already leaves them out (ADR-334 §2); the archive check is the remaining place that treats them as unsaved work.
<!-- SECTION:DESCRIPTION:END -->
