## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found during the TASK-33620.3 / TASK-33621.53 review (2026-10-29). Stop sets the ordinary commit owner's explicit_stop while its durable commit runs. If that commit then fails, the send is paused as PERSISTENCE and its card reads 'Send could not be saved' with Retry send, although the user asked to stop. By reading (not probed), this holds both for a failure inside the commit's transaction (the store's existing pause) and, since TASK-33621.53, for one before its reservation (which used to jam the chat instead, so the new behaviour is still an improvement). Decide whether an explicitly stopped send whose commit fails should settle as stopped, with its text given back, rather than offer a retry.
<!-- SECTION:DESCRIPTION:END -->

<!-- SECTION:PLAN:BEGIN -->

1. Measure on dev with a probe on the real ChatScreen/runtime/controller/store and a file-backed DB: hold the commit, press Stop, let it fail before and inside the reservation; record pause, card, shelf, draft, attachments.
2. Write the failing tests first (both windows, plus the next send answered), on the durable mounted harness.

4. Runtime: a stopped refusal returns the unsent turn to the draft with its attachments (the card Cancel path) instead of shelving it.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Owner decision 2026-10-29 (treat as stopped) recorded in the ACs: a send stopped while its durable commit runs, whose commit then fails, is abandoned; its text and attachments go back to the draft and neither the card nor the shelf offers it again.

Measured first (dev 8ae979d81b, real ChatScreen/runtime/controller/store over a file-backed DB, commit held on its worker thread, Stop pressed, then the commit fails): in both windows (store preflight before the reservation; persistence write inside it) the send paused as PERSISTENCE, the card offered Retry send, the shelf held the turn and its image, and the echo stayed. Also measured: while the commit runs the run state is VALIDATING, so the composer's Stop and Ctrl+G are not offered (check_action False); the command palette's "Console: Stop this tab's run" is the Stop a user can press then, and the tests press that action.

Change: console_native_commit._controller_stop_failed_commit runs in _controller_accept_durable_turn's generic failure branch after the pause (the store's own pause, or pause_unreserved_failed_commit). When the native owner was explicitly stopped and the send is still that attempt's PERSISTENCE pause, it releases the native owner, cancels the pause the way the card's Cancel send does (echo removed, text restored), drops the preparation, sets the run STOPPED ("Send stopped; nothing was sent.", console_turn_preparation.SEND_STOPPED_COPY) and returns a STOPPED refusal carrying cancelled_draft_revision. console_runtime passes that revision on _ConsoleTurnRefusedError (returned_draft_revision), and _finish_custodied_turn returns the unsent turn to the draft with its attachments (return_turn_recovery_to_draft, the card-Cancel path) instead of shelving it. A failure with no Stop is unchanged.
