## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in TASK-33620.15.57's review (2026-11-06). Since TASK-33620.15.57, the Console's idle maintenance holds while either pre-import thread is alive, including its custody parks and the warm-up's final input wait. A request whose timer fires inside that window is dropped, as for any busy owner, not deferred. On a host with fewer than 4 usable CPUs the pass is paced at a yield ratio of 3.0 with gaps of up to 6 s, so it can run for tens of seconds, and a send that settles inside it loses its run_settled re-freeze until the warm-up's closing re-freeze. If the warm-up stops early on an exception, no closing re-freeze runs and nothing asks again until the Console's next paint or settled run. Neither path has been measured on a low-core host, nor with a send typed during the pass.
