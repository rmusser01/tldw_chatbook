## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
After the user answers Quit, _confirm_console_runtime_quit re-reads the whole loss inventory and, if anything differs, warns "Console activity changed; review the updated impact" and asks again. Since TASK-33628.1 the inventory includes per-tab unsaved counts, tab titles, drafts and unsent turns, not only the fleet lifecycle counts. So a loss that shrinks while the dialog is open (a message finishing persistence, an auto-title landing) also forces a second prompt, although the user already agreed to lose more than that. A steady mid-stream probe showed one prompt only, so this is a risk during long agent runs rather than an observed regression. Re-asking only when something grew, or a tab not yet named became affected, keeps the safety without the extra question.
<!-- SECTION:DESCRIPTION:END -->
