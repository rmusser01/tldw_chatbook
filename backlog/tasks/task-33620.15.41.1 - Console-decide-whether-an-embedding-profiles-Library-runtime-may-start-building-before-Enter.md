## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while fixing TASK-33620.15.41 (2026-11-05). A keyword-only profile (BM25 Only) no longer builds the Library's search runtime, but Semantic and Hybrid profiles genuinely need it: the first Automatic send after launch waits for it to build. Live with Hybrid Basic (model cached, Anthropic haiku), in four unloaded rounds per arm at host load 6-13, that build was 4.4-7.7 s of a 6.2-10.7 s Enter-to-provider wait on dev 29592ecc9b and 4.6-5.8 s of 6.6-8.4 s on the TASK-33620.15.41 branch, whose Hybrid path is unchanged. In two loaded rounds per arm (load 108-111) it was 27-36 s of 35-45 s on dev and 30-31 s of 40 s on the branch. Almost all of it is importing sentence-transformers, torch, transformers and chromadb plus the embedding model load and its dimension probe, so nothing inside the build is worth shaving. The wait is now named on the run chip ('Searching Library…'). By TASK-33621.20's design the build starts only when an Automatic send is preparing, never at boot. Starting it earlier, for example when a draft is typed in a chat whose Library Auto is Automatic, would hide most of it, at the cost of loading the embedding stack for drafts that are never sent. That trade-off is an owner decision.
