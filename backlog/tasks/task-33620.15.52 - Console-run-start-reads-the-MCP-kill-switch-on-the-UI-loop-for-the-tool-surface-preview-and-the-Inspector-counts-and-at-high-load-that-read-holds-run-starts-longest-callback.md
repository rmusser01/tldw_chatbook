## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by TASK-33620.15.38's live rounds (2026-11-05, origin/dev 29592ecc9b, Anthropic claude-haiku-4-5 via the review proxy, 160x45, a fresh isolated profile per launch, lean probe with exact timers on recovery_activation.selected_path and its callers). Two callers: ConsoleAgentBridge.preview_tool_surface (preflight_tool_surface, from ConsoleCompactionPreflight's conversation-memory and capacity checks) and offered_builtin_tool_count (ConsoleChatController._publish_mcp_inspector_counts). Run start already reads the kill switch once for MCP and local tools (LocalKillSwitchRead, TASK-33620.15.1); these preview and Inspector reads are separate. Evidence: tools/evidence/bd5/R38/ (v2base, v2pair; kit2/r38check.py prints the callers).

**Approach.** Owner rule 2026-11-06: "stamp-proven kill-switch read for the tool-surface preview, not a worker hop". The code is in `Chat/console_run_start_tools.py` (`preview_switch_anchor`, `keep_preview_switch`, `proven_preview_switch`) and is used only from `owned_preflight_tool_surface`.
- Recording a read: just before a preview's real read on the worker, take the permission file's stamp, the admission epoch and the store's installed identity (`_source_identity` minus the store object: type, path, binding, config identity, selected generation). Keep the answer only if:
  - the read returned;
  - the file was settled `SETTLE_NS` before that stamp (the anchor's rule);
  - the epoch and the identity did not move during the read.
- Using a recorded read: the next stock light-surface preview, if it captured the same store object, answers on the loop when the identity and epoch are unchanged and one `stat` returns the recorded stamp. Otherwise it reads through the hop as dev does, and that read records a new answer.
- Fail-closed: a read that raises still answers engaged, and nothing is kept from it. Taking an anchor drops the previously kept answer.
- Estimate only: run start's composition and every tool call read the switch through their own gates. ADR-230's "no permission cache" gets a dated amendment for this one bounded exception (owner decision).
- What the proof does not see: an admission change written only by another process (storage admission's per-call stamps catch it at the next real read). A config publication changes the config identity, so the next preview reads for real. Live, the first-run modal dismissal and the first send each publish config, so each session's first two sends pay one hop (their first preview) and later sends none (markers below).
- Inspector counts: dev's reuse of run start's own read is kept, not a worker read. It is the read this same run start composed under, and it is current by construction (on reuse runs it is the kept composition's decision, proven by this run start's fingerprint). It counts exactly the tools the run was offered, which a later worker read could contradict if the switch changed in between. It costs no I/O, and it keeps the synchronous publish free of new hop, cancellation and retirement custody. The fallback paths stay as on dev: a run whose read raised, or a run that composes nothing (MCP excluded and local tools off), still reads the switch for the chip. Neither is reached by a stock send with default settings.
