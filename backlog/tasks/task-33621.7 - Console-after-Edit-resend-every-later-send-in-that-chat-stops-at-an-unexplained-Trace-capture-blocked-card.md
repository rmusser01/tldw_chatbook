## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact (P1, triage NEW).** Edit & resend on the last user message breaks trace capture for the rest of the chat. Every later send fails trace reservation (`error_category=unsupported_surface_change`, ValueError) before the provider is contacted, and stops at the generic 'Trace capture blocked' card. The card gives no cause and has no per-chat 'don't ask again' option. Only 'Send without capture' works, and it has to be chosen on every send. 'Retry capture' opens a 'Response delivery status is unknown … Retry anyway may send a duplicate request' panel, although the provider was never contacted. 'Cancel send' shows 'Trace reservation status is unavailable.' and does not dismiss the card. The card's 'Impact: The provider was not contacted.' is accurate on this path.

The trigger is specific: an in-place edit with Save followed by a send captures normally, and a control chat with 5 plain sends never showed the card. So an ordinary editing action silently makes every later send cost an extra click, with no explanation. The recovery-button defects on this card come from the same mechanism as finding G4-05. This task owns the Edit & resend trigger and the cause copy, and it verifies the buttons on this path.

**Prior art:** the user guide (Docs/User_Guide/console/semantic-trace-capture.md:149-162) claims Edit & resend is a supported trace call boundary. ADR-097:42-46,251 describes copy-on-write edit revisions and a prior unsupported_surface_change incident. TASK-32048 (Done) and TASK-32075 (Done) fixed the same error for different triggers.

**Suggested direction:** route Edit & resend through the same trace-call reservation as a normal send, so the edit appends a replacement record and advances the surface. That needs an ADR-097 amendment, as in the TASK-32048/32075 precedents. As a stopgap, map unsupported_surface_change to cause-specific copy ('Trace capture can't follow this edited branch yet') and offer 'Send without capture for this chat', remembered per conversation.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G4-10 (source J2-05). The row's evidence files, uxrev/evidence/J2/142-j22-send-after-resend.png and 141-j22-after-resend.txt, plus the j22 app log (trace_reservation failed, about line 379), were not copied into qa/evidence.

Dev-tip note (reviewed 64579cce2c; checked against 857b3dd7d0): No commit in 64579cce2c..857b3dd7d0 touches this mechanism. Open PR #2882 (not on dev) wraps unsupported_surface_change as TraceSurfaceChangeRefused and records reservation_status 'not_established' when rollback proves no reservation exists. That probably fixes the Cancel send and Retry capture dead-ends on this path. It does not fix the Edit & resend trigger or add cause copy. Re-verify after it merges.

Review finding ids: G4-10 — see qa/console-ux-review-2026-09-29/findings.md.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
After Edit & resend, later sends in the chat capture normally: no decision card, and the trace reservation succeeds.

**Root cause (shared with TASK-33621.29).** Edit & resend dispatches its own call with capture off (no turn preparation, so `capture_mode` defaults to CAPTURE_OFF), and the edited sibling branch never reaches the trace surface. The next captured FRESH or AGENT_FIRST send therefore carried a rewrite of the recorded surface's tail plus the new turn. The planner admits only an append or a one-item replacement, so it refused with `unsupported_surface_change` (`count_or_span`). Compact now produces the same shape for a different reason (TASK-33621.29). Measured live on dev f9baac8706: prefix 2, 1 recorded entry changed, 3 incoming (evidence bd5/U04/01-06 "before" shots and logs).

**Approach (ADR-097 amendment 2026-10-27).** A new typed replacement-plus-append, the rewritten tail, for FRESH/AGENT_FIRST only, when no completed tool-turn transition applies: the recorded tail after the matched prefix (no retained suffix), messages only, within the 256-node bound. Every replacement row is an exact saved revision whose live message is the direct parent of the next row's message, the last row is the call's own user turn, and the oldest row is parented by the last retained saved row (or nothing, from the conversation root). `RewrittenTailWitness` (console_trace_final_values.py) carries the proof; `console_trace_rewritten_tail.py` (lazy-loaded, read-only SQL) builds it in the planner and rechecks it in the dispatch-binding transaction, failing closed. The service threads the witness like the completed tool-turn witness. Edit & resend itself stays uncaptured; the edited branch enters the trace at the next captured send.

**AC#2** was amended first, citing the owner's 2026-10-27 ruling: no remembered per-chat capture bypass. **AC#3:** on this path the card no longer appears, so neither button is reachable from it. Before the fix (dev f9baac8706, bd5/U04/03-04) Retry capture re-showed "Trace capture could not start" with no unknown-delivery or duplicate panel, and Cancel send dismissed the card; the composer was empty afterwards. Restoring the draft on Cancel for every trigger is TASK-33621.6 AC#1.
