## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Four editors give the same fields different labels:
- 'Think budget' (UI/Screens/settings_screen.py:17378, :18695, :15861), 'Budget' (Widgets/Console/console_settings_modal.py:2125) and 'Thinking budget' (settings_screen.py:12177).
- 'Budget strategy' (:18403) and 'Budget mode' (modal :2250).
- 'When limit nears' (:18427) and 'Behavior' (modal :2295).
- 'Endpoint' (:16810), and 'Base URL' in the modal (:1755) and the custom-endpoint editor (:17567).
- 'Presence' and 'Frequency' (:17274, :17284, :18658, :18668; modal :2005, :2012) against 'Presence penalty' and 'Frequency penalty' (:12171-12172, :15825-15831).
- 'Response max tokens' (:17254, :18636, :15813) and 'Max tokens' (:12169).

Settings also keeps two private copies of field copy that already disagree with each other: the dirty-field label map (:12156-12177) and the inspector guidance table (:15800-15860). The Console surfaces show raw sampler names with no help (report, heuristic 10).

STORAGE_FIELD_LABELS (UI/Screens/settings_storage_defaults.py:55) is the in-repo precedent for one label table. This table extends phase 1's field-to-request-key definition, so labels, help, ranges and request keys cannot drift apart. Rendering help lines inside the Console modal is layout work outside this phase.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
One field table in `Chat/console_provider_support.py` now labels every model-configuration field, and all four editors read it.

**Approach**
- `ModelConfigField` / `MODEL_CONFIG_FIELDS` / `MODEL_FIELD_LABELS` sit beside `GENERATION_FIELD_REQUEST_KEYS`, not in a new module, because the ui_ready census has 0 headroom. The table covers the 14 generation fields plus `endpoint`, `conversation_budget_mode` and `compaction_mode`. `request_keys` is a property that reads `GENERATION_FIELD_REQUEST_KEYS`, so there is no second copy.
- Labels: Max tokens, Presence penalty, Frequency penalty, Reasoning effort, Reasoning summary, Thinking (thinking_effort), Thinking budget, Endpoint, Budget strategy, When limit nears. Every label is at most 23 cells, so no geometry changed.
- Settings: `MODEL_PROFILE_ROW_LABELS`, the dirty-field label map and the inline inspector guidance dict are gone. The dirty names, the hidden-rows summary, the form rows, the Console Behavior fallback rows, the context pair, the Control guide rows and the `_normalise_*` error labels all read the table. A focused model-default field's inspector shows the table's help (Purpose) and range (Validation). The "Saved as" provenance row stays (ruling 5). Endpoint help and range come from the table too.
- Modal: every label comes from the table, including Endpoint (was Base URL), Thinking budget (was Budget), Budget strategy, When limit nears and the Model-capacity "Max tokens" readout. `_PROVIDER_CHOICE_CONTROLS` is built from the table. Net -10 lines (7816 to 7806), so its module-size row is green again.
- Popover: the Temperature label and the Streaming button read the table through `_streaming_label()`.
- The Endpoint label is also used in the Settings custom-endpoint editor, the new-endpoint template modal, and the "... must be a valid http(s) URL." copy (`console_session_settings`, `custom_endpoint_registry`). `console_session_settings`' max-tokens error reads the table.
- Rider: `reasoning_effort_values_sent()` keeps only the reasoning levels the real request builder forwards (`build_local_thinking_payload_fields`), and resolves `custom-ep` ids to their family. Settings' Reasoning select for llama.cpp, MLX-LM or a llama-family named endpoint therefore no longer offers "minimal". vLLM and custom OpenAI-compatible still send "minimal" as `reasoning_effort` and keep it. `_registry_family_provider()` is the shared custom-ep resolution that `supported_generation_fields` now uses too.
- `settings_search_index.py` keeps its literal rows. It gains Max tokens, Thinking budget, Thinking and Budget strategy rows, and the old names stay as aliases.

**Found live, fixed:** at 211x44 the Settings screen crashed with an AttributeError in `_provider_field_guidance_rows_base` when no field was focused (`None.removeprefix`). It is guarded, and the mounted test now pins the no-focus case.
