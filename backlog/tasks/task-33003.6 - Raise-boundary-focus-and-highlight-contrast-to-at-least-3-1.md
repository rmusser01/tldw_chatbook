## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Boundaries and focus are close to invisible. Field borders measure about 1.05:1 and the modal frame about 1.01:1 (report.md issue 2). $ds-grid-line is $surface-lighten-1 and $ds-control-edge is $surface-lighten-2 (css/core/_variables.tcss:11, :43). The agentic_terminal theme also sets ds-grid-line explicitly, to #26364D on a #0D1626 panel (css/Themes/themes.py:1561-1564).

On the Settings category rail, focus only swaps $ds-surface-panel for $ds-surface-raised and adds bold (css/features/_settings.tcss:198-203). That measures 1.107:1 in agentic_terminal and 1.22:1 in textual-dark, where the focused fill is darker than the unfocused one. A focused active row looks exactly like an unfocused active row (:193-197 versus :205-209), and two tests pin that (C8(4)).

The same report issue measured the Select highlight at 1.12:1 and found that a focused primary button gets darker, so focus reads as disabled.

WCAG 1.4.11 asks for 3:1 on focus indicators and component boundaries. ensure_readable_text_hues (css/Themes/themes.py:83) is the precedent: it pins generated text hues per theme on both the shipped-theme and user-theme load paths, and Tests/UI/test_theme_contrast.py gates it.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Grid lines, control edges, the Settings rail focus cue, focused variant buttons and the list highlights on Chat settings and Settings ▸ Providers & Models now reach at least 3:1 in every theme that resolves to colours.

**Boundaries (AC#1, AC#2).** `$ds-grid-line` and `$ds-control-edge` now point at `$tldw-boundary` (`BOUNDARY_VARIABLE` in `css/Themes/themes.py`). No tcss defines that name, so each theme's own entry paints; the per-theme `ds-*` dict entries stay inert (themes.py header note, ruling 15). `ensure_readable_text_hues` sets it on all three paths that already call it: shipped themes, Textual's built-ins and every user theme through `create_theme_from_dict`. It starts from the theme's own entry, or `surface-lighten-2`, and blends toward the text pole in 5% steps until the colour clears 3:1 against both `surface` and `panel`. A hand-set entry below 3:1 is replaced. ANSI palettes cannot be measured; they get the old `surface-lighten-2` value (`transparent`), so the name is never undefined. The key is recorded as pinned, so the theme editor does not copy it into a saved file.
- `Tests/UI/test_theme_contrast.py`: 89 measurable themes (70 shipped + 19 built-ins) resolved through `_variables.tcss` on top of the theme table, which is how a tcss source sees them. A dict-only fix fails this test. User themes load through `load_user_themes`: a pastel palette, and a file that sets `tldw-boundary` below the floor by hand. A real `Stylesheet` parse runs under all 91 registered themes, the two ANSI ones included.

**Rail focus (AC#3, AC#6, ruling 16).** A focused category row now draws a thick left edge (`█`) in `$ds-active-fg`. The base rule reserves that column as `border-left: blank` (the row's own fill), so focus moves no label and adds no row. `$primary` misses 3:1 against surface or panel on 29 of the 89 themes. `$ds-active-fg` is `$text-primary`, which the guard pins to 4.5:1 on both surfaces, and it measures 3:1 or more on the focus fill in all 89 themes; `test_settings_rail_focus_edge_clears_non_text_contrast` gates that.
- Rewritten on purpose (AC#6): `test_settings_active_category_focus_style_keeps_label_readable` and `test_settings_category_active_states_use_selected_contract`. They still require a readable label (no reverse, bold underline) and no dominant geometry on the rest states. The focus states must now also carry the edge, with its column reserved at rest.
- Rendered: `test_settings_rail_focus_draws_a_readable_edge_on_every_row`, for the active and an inactive row in agentic_terminal and textual-light.

**Focused buttons (AC#4).** `Button:focus` painted the focus tint over every variant, so a focused primary read as disabled: Chat settings' "Use for this conversation" dropped from 9.42:1 to 1.94:1. Four one-line rules in `components/_buttons.tcss` keep a variant's own fill on focus.
- Settings had its own alias: `#settings-shell Button:focus` and `.settings-action-row / #settings-impact-pane Button:focus` set `background: $ds-surface-raised`, the resting surface that design-language §2.7 forbids as a focus fill. Live on textual-light, a focused Test Provider fell from 1.08:1 to 1.02:1 against the card: Textual's 5% focus tint pulled the fill toward the card. Both rules drop the background, so the house focus tint (or the variant's fill) paints. Test Provider is now 1.65:1 focused. This is a visual change for every focused default button in Settings; the Theme card's chips keep their own id-scoped rules.
- Rendered: `test_console_settings_focused_button_keeps_its_contrast` (Apply and Cancel) and `test_providers_models_focused_button_keeps_its_contrast`. The latter fails on the old Settings rule (textual-light 216 -> 206 on a 208 card).

**Highlights (AC#5).** In Chat settings (every OptionList, so Select overlays and the model and provider lists) and in `#settings-providers-models-card`, the highlighted option is an inverted bar: `$ds-active-fg` fill with a `$ds-surface-panel` label. This follows the TASK-33065 Theme-list precedent. The rule lives in `components/_lists.tcss`. The modal's three `ConsoleSettingsModal Select > SelectOverlay Option*` rules were dead, because Textual 8 options are lines, not widgets, and are deleted. The ▶ glyph moves to Phase 4 (ruling 16).
- Rewritten on purpose: `test_console_settings_modal_select_overlay_is_readable` pinned those dead rules. `assert_all_native_choice_selectors_follow_contracts` gains `NATIVE_CHOICE_BAR_OVERRIDES` (the Theme list plus the three new selectors) with its own bar contract. That test is red at the base and at head: at head only the three pre-existing violators remain (`#console-workspace-tree:focus > .tree--cursor`, `#settings-workspace-persona-picker` and `#settings-workspace-profile-picker`).
- Rendered: `test_console_settings_select_highlight_is_a_readable_bar` and `test_providers_models_highlighted_option_is_a_readable_bar`. The P&M test measures 1.00:1 on the old CSS.

**Boot CSS.** Component-class selectors (`.-primary`, `.option-list--option-highlighted`) keep a rule in the boot bundle. The first draft exceeded the byte ratchet by 593 B. The final bundle is 125 B smaller than the base (607,855 / 608,090) because the dead Option rules are deleted, `Button:focus` and `Button:hover:focus` (identical bodies) are merged, and the Settings variant rules became unnecessary.
