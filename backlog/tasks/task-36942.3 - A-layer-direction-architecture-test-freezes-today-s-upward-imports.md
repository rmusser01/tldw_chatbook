## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
There is no global layer rule. Executable upward imports today (top-level plus function-level):
- domain to presentation: 80, of which 42 top-level;
- DB to feature packages: 335, of which 169 top-level;
- kernel modules to higher layers: 89.

TYPE_CHECKING-only imports add 3, 23 and 10 to those. 55 package pairs import each other at top level, and 123 counting function-level imports too (129 with TYPE_CHECKING-only imports). `Docs/QA/architecture-review-2026-10-25/scripts/` contains the stdlib graph builder and the layer ranks used to measure this.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F6; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
**Summary.** `Docs/Architecture/layer-map.md` documents the four layers, which package sits in each, the direction rule, and the DB exception for domain model modules (linked from `Docs/Architecture/README.md`). `Tests/Architecture/test_layer_direction.py` is a stdlib AST scan of `tldw_chatbook/` with two tests: `test_no_new_upward_import` (AC#2) and `test_allowlist_has_no_stale_rows` (AC#3). `Tests/Architecture/layer_direction_allowlist.tsv` freezes 191 `src_module<TAB>dst_module<TAB>kind` rows at dev `2b296e60b3`. The test runs in the PR Fast Lane, after `test_study_handler_service_keywords.py`, and the matching `FAST_LANE_TARGETS` pin is in `Tests/CI/test_ci_queue_pressure_contract.py`.

**Decisions.**
- Import resolution and the top/lazy/TYPE_CHECKING classification copy the review's `graph.py`. Layer ranks copy `layers.py`. At `2b296e60b3`, the test's row set equals the `(src, dst, kind)` set derived from `graph.py`'s graph, with the model exemption applied (191 = 191).
- The test enforces the documented exception: DB to a domain module named `models` or `*_models` is allowed and gets no row. That covers 65 of the 336 DB to domain imported names, in 17 distinct imports. The other 271 names (79 rows) are frozen. The alternative was to freeze the model imports too, and then the test would contradict the documented rule. If that call is wrong, it costs 17 rows and one `continue`.
- The record counts imported names; a row is one distinct (src, dst, kind). Census at base: domain to presentation 80 names / 53 rows, DB to domain 336 / 79, kernel to higher 89 / 59. The 80 and 89 match the record. DB to domain was 335 at `7a5e2513c5` and is 336 at the base.
- Kind changes count. Moving an allowlisted import into a function fails as a new `lazy` import and as a stale `top` row.

**Evidence.**
- Red: with an empty allowlist, `test_no_new_upward_import` failed with `191 new upward import(s)`.
- Red under temporary source edits, all reverted. A new top-level import (Notes to Widgets), a new function-level import (Notes to UI), DB to `agent_service` and kernel to DB each failed, each named at file:line. A TYPE_CHECKING-only import and DB to `agent_models` passed. Deleting the allowlisted lazy import in `Backup_Recovery/launcher.py` failed as stale. Moving `Utils/launch_options.py`'s top-level import into a function failed both tests. A two-field row failed with the row's line number.
- Green: 2 passed in 5.2 s unloaded. The first test's call phase, the cached scan, takes 4.9 s; under parallel load it took 7 to 9 s. Nearly all of that is `ast.parse` of the 2,000 non-presentation files.

**Review round 1.**
- **M2.** A call to `importlib.import_module` (any `import importlib as x` alias) or to a bare `import_module` imported from `importlib`, with a string-literal first argument, now counts as a `lazy` import of that module. A non-literal name and `__import__` stay out of scope; the doc says so and names `Chat/console_first_send_modules.py`'s eight unseen presentation imports. The allowlist is unchanged at the base: 12 literal calls exist outside presentation, and none points upward.
  - Red: the pre-fix test passed a module-level `importlib.import_module("tldw_chatbook.UI.Screens.library_screen")` in `Notes/recovery.py`.
  - Green: the fixed test flags that call, a bare `import_module` of `Widgets.emoji_picker` and an aliased `_il.import_module` of `Web_Server.served_relay_publisher`, each as `lazy`. It passes a non-literal name, a TYPE_CHECKING call, and a local function that happens to be named `import_module`.
- **M1.** The doc now says rows are per (source, target, kind), so another import of a listed triple passes. It names the three package-`__init__` targets (`Widgets.Console` twice, `tldw_api`) and qualifies the kind-change bullet.
- **Coordinator ruling.** The doc and the new-import failure message both state the re-export shim rule.
