## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Setup is a fixed sequence of steps, and it does not adapt to what the user came to do. Someone who only wants to chat walks six Quick steps, and two of them do nothing useful for most people: Voice defaults to a local server most newcomers don't run, and Protect is empty when no key is stored. Someone who wants to work with their documents has to get through Provider and Model first. Someone with a tldw server finishes setup without being offered the connection, because the only control is in a collapsed Settings section, and the Summary never says whether chatbook is running local-only. A re-run replays first-run setup instead of showing what is already configured. These are decisions about the shape of setup, not point bugs, so the owner ruled: write the spec first, and build only after explicit approval.

This task produces that spec. It covers structural fix SF10 ("Steps earn their place"), the recommended information architecture in report §4.3 and the re-run dashboard in §4.4 item 6, enhancements E1 (Say hello), E5 (re-run dashboard), E8 (keychain-first keys), E9 ("what's next" checklist) and E12 (plain-text setup), and the parts of E6 (portable setup) beyond TASK-34100.16. Source: Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md. It resolves review issues coverage-06, coverage-16 and entry-exit-handoff-28. All three were re-checked on latest dev and are still present: _QUICK_TRACK still lists Voice and Protect, nothing under UI/Wizards references tldw_api, and Welcome offers only Quick and Full.

Coordination:
- The spec reverses TASK-21148's ruling that Protect always appears on Quick, and must say so. It keeps that ruling's guarantee that the step count never changes mid-run.
- task-28019 overlaps. Narrow it to its modal-sequencing AC (#3), and move its documents-first AC into a follow-up filed from this spec.
- Placeholder-token screening already exists (task-31417, Done on dev) and should be reused.
- The spec builds on, and must stay consistent with, these sibling subtasks:
  - TASK-34100.2 and .5: first-chat readiness and handoff (the Ready row).
  - TASK-34100.4: encryption lifecycle (Protect and E8).
  - TASK-34100.10: setup-session model and entry contract (re-run dashboard).
  - TASK-34100.13: Full-track step clean-up.
  - TASK-34100.16: second-machine docs and flags (step 1 of E6).
- No ADR owns the wizard's shape today. ADR-012, ADR-029, ADR-033, ADR-076 and ADR-126 each constrain part of it.

- [ ] #2 [coverage-16] The spec decides and specifies a 4-step Quick track (Welcome, Connect, Model, Ready). Voice moves to Full and becomes a Ready next step, "Hear replies aloud…". Protect leaves Quick and is replaced by a Ready option, "Encrypt saved keys with a password…", shown only when a key was stored in this run. The spec records that it supersedes TASK-21148 AC#5 while the step count still never changes mid-run, restates the Welcome label and time copy, and lists the tests and the User Guide track table that pin 6 steps
- [ ] #3 [entry-exit-handoff-28] The spec decides and specifies a documents-first Welcome choice ("Start with my documents or notes — set up AI later"). It finishes setup through the single finish path without raising the model-list consent modal, lands on Library Import with "Write a note" as the secondary action, leaves Console's Get started card intact, and keeps skipping to one gesture. task-28019 is narrowed to its modal-sequencing AC
- [ ] #4 A design spec exists at Docs/superpowers/specs/2026-10-03-first-run-setup-shape-design.md with one section per decision in this task, and every claim it makes about current behaviour is re-checked on latest origin/dev and cited by file:line
- [ ] #5 The spec fixes the Full track's step list and order (report §4.3 proposes 11: Welcome, Connect, Model, Server, Search, Tools, Spoken replies, Dictation, Appearance, Protect keys, Ready) with a reason for each position. Every optional step defaults to "not now" and writes nothing when left untouched, and a "Finish with defaults" exit is available once Model is saved
- [ ] #6 The spec specifies the Ready screen: a "✓ Ready to chat — <provider> · <model> (<context>)" or "✗ Can't chat yet" row computed by Console's own send preflight (not a wizard copy of it), rows only for steps the user saw, Data: and Config: lines, and the §4.3 link-outs. The layout fits at 80x24 and keeps the Library exits (task-32072/32140) visible
- [ ] #7 [E1] The spec specifies "Say hello": a prefilled one-line test, sent on Enter through Console's real admission and dispatch path; the reply streamed inline with model and latency and carried into Console as the first turn; on failure, the plain cause plus one fix action. It runs by default for local providers, runs for cloud providers only after consent copy ("Uses a few tokens"), and offers "Skip test" for offline users
- [ ] #8 [E5] The spec specifies the re-run as a "Review your setup" dashboard: current values read from the real config, a Change action per row that opens that single step and returns, untouched areas never written, "Done" returning to the origin, "Run the full walkthrough" as the secondary action, palette commands per area, and Console readiness deep links landing on the matching row, consistent with TASK-34100.10's entry contract
- [ ] #9 [E8] The spec specifies keychain-first key storage. At key entry the user chooses: system keychain (recommended), config.toml plain text, encrypted with a master password, or environment variable. Ready names where each key lives. The spec also covers the fallback when no keyring backend exists (headless Linux, SSH), migration of existing plaintext and encrypted keys, and whether "Remember on this device" ships, consistent with TASK-34100.4's encryption lifecycle
- [ ] #10 [E9] The spec specifies a "what's next" checklist on Ready (Hear replies aloud, Add a document and ask about it, Sync a notes folder, Add a project folder, Connect a tldw server). It replaces the arrival toasts with one dim Console line naming provider, model, streaming and context, and Speak or Dictate with nothing configured opens a compact setup sheet at that moment
- [ ] #11 [E12] The spec specifies `tldw-cli setup --plain` for screen-reader and SSH users: the same state machine and commit path as the TUI, one prompt per decision with plain ✓/✗ result lines, keys read from a hidden prompt or an environment variable and never from argv, and a non-zero exit on failure
- [ ] #12 [E6, beyond TASK-34100.16] The spec decides whether to build non-interactive setup. If yes, it specifies "Export these settings (no keys)" on Ready and `tldw-cli setup --from FILE --non-interactive [--key-env VAR]`, both using the same commit path and readiness check, taking keys only from env or stdin, and exiting non-zero on failure. If no, it records the deferral and the condition that would reopen it
- [ ] #13 For each change, the spec names the report §5.5 "Preserve" behaviours it must not break, including at least: secrets never written unless saved, model-list consent asked once, the Summary read back from disk, Restore a backup reachable from Welcome, and the Get started card catching Skip and Exit
