## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
With an unsaved endpoint, Context and memory now says "Save the <provider> endpoint in Model and generation to continue." on the line above its footer.

Cause. The reason line was filled only when the draft had no unsaved endpoint, because in the Model view the Save endpoint & use model button stands in for Apply and needs no reason. The Context view hides Apply and that button, so it showed Cancel and nothing else.

Fix. In `_sync_default_readiness` the unsaved-endpoint case gets its reason unless Save endpoint is offered (the Model view) or a default-save recovery holds the modal (it hides both views and their tabs, so there is nowhere to send the user). The `endpoint_not_saved` copy changed from "Save the <provider> endpoint in Chat settings before using it here.", which was never shown and named the modal the user is already in.

Tests, Tests/UI/test_console_session_settings.py, production stylesheet, 211x44:
- `test_console_settings_context_view_says_where_to_save_an_unsaved_endpoint`: the Model view shows Save endpoint and no reason; after a click on Context and memory, Apply and Save endpoint are hidden, and the line is the Static's text and is in the painted rows; after a click back, no reason. Against the modal at 10fead87cb it fails with `'' == 'Save the Ollama endpoint in Model and generation to continue.'`.
- `test_console_settings_default_recovery_adds_no_unsaved_endpoint_reason[model]` and `[context]`: a recovery shows no such line. `[context]` fails when the recovery clause is removed.

Live, scratch profile, vLLM, tmux, 211x44: one character appended to Endpoint under Connection. Model and generation: the Model row read "Not ready · endpoint unsaved · context unknown", the footer "Use saved defaults  Save endpoint & use model  Default for new chats (Ctrl+N)", and no reason line. Context and memory: "Save the vLLM endpoint in Model and generation to continue." above "Esc close (asks: 1 unsaved)   Cancel".

User guide: Docs/User_Guide/console.md has a paragraph on the unsaved endpoint in both views. Review fix (2026-10-11): it said Context and memory "has no save actions", which reads as if that view never had Apply. The view normally shows Apply to this chat, and `_sync_default_readiness` hides it in both views while the endpoint is unsaved. The paragraph now says Apply is hidden there as well and nothing stands in for it.
