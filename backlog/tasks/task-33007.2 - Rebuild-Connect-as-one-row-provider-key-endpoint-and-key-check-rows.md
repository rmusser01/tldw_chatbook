## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Connect today has four problems:
- The provider list is a searchable OptionList fixed at 6 rows, and its focus border clips the first character of every option, so Anthropic reads 'nthropic' (css/features/_settings.tcss:458-463; composed at settings_screen.py:16743-16765).
- Credentials are a separate section (:16865-16904).
- Test Provider is a button with a guidance line and a multi-line result (:16925-16943).
- A Provider readiness block repeats readiness, provider and model source, endpoint and key status (:17006-17031).

Providers are grouped Cloud / Local / Custom & legacy aliases (settings_provider_view_model.py:142-146, built at :190). The few configured providers are therefore mixed in among 27 or more entries.

ADR-012 (012:29) requires the card to distinguish a key saved in config, a key from an env var and a missing key. Entry must stay masked, the saved key must stay clearable, and the env var must be described as the safer path. D4 keeps all key entry here. Phase 5 supplies the shared readiness vocabulary and the non-generating key check behind 't' (D2); this subtask gives it one row. The labelled result detail (phase 2) needs a home that does not push Default model down.

Conditional rows must survive under their current conditions:
- Manual provider (:16783-16798)
- QwenCloud API mode and its guidance (:16818-16864)
- Hosted-provider guidance (:16902-16914)
- The OpenAI restored-connection review (:16916-16921)
- The navigation-conflict and return-continuation blocks (:16955-17005)
- The vLLM recovery gate that disables the card (:16696)

Tests/UI/test_settings_provider_view_model.py:121 pins today's group order.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. View model: a "Configured" group leads the provider list (credential in config or shell, or an endpoint unlike the shipped template's); custom slots may lead, legacy aliases stay last; one summary line. Rewrite the grouping pin on purpose.
2. Card module: Connect becomes Provider / API key / Env var / Endpoint rows (label, one-row control, Source word, one-line help) ending in a Key check row (readiness word + "Test (t)"); the readiness block, Credentials header, Test guidance and result leave the card; Model moves under a "Default model for new chats" header with its Source word.
3. Provider control: a one-row Input that shows the chosen provider and filters a never-focused list under it (Up/Down, Enter, Esc); the hidden Select#settings-provider-value stays the provider key (R5).
4. Inspector: a Key block with what t checks and the labelled result rows (R7).
5. Screen: route dynamic updates through one refresh helper; point '/' Provider and conflict review at the visible control (R9); delete helpers left unused.
6. Tests first where new; rewrite pinned tests on purpose (R15 snapshot included); docs; CSS through tokens and the bundle script; live keyboard captures at 211x44.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Connect is now one row per fact, built in `UI/Settings_Modules/providers_models_card.py`.
Provider, API key, Env var and Endpoint each read label | one-row control | Source word |
one-line help, and Connect ends in one Key check row: the readiness word and **Test (t)**.
The Model row moved under a "Default model for new chats" header with its own Source word.

- **Provider (AC#1, #3).** `ProviderFilterInput` (a `PickerSearchInput`) shows the chosen
  provider's display name and is the only Tab stop. Typing filters the list under it
  (`#settings-provider-picker`) by name or id. The list has `can_focus = False`, opens only
  while the control is focused, and follows the control's Up/Down/Enter/Esc. Blur or Esc closes
  it and puts the name back; a closed list is always unfiltered. It draws no focus frame, so
  no option's first character is covered. The hidden `Select#settings-provider-value` still
  holds the provider key (R5).
- **Configured first (AC#2).** `build_provider_picker_groups(..., configured=)` leads with a
  "Configured" group. It holds providers with a credential (in config or the shell) or an
  endpoint that differs from the shipped template's (`configured_provider_keys`). Configured
  custom slots lead too; legacy aliases stay labelled, in "Custom & legacy aliases", last.
  The set is read only when the unfiltered list is built (compose, open, close), never per
  keystroke. `provider_picker_summary` gives the row's help ("configured: Anthropic · 59 more").
- **Key and env var (AC#4, #5).** `api_key_row_copy` gives the Source word: **saved in config**,
  **from env var**, **missing**, **not required**, **edited \***, **cleared \***, **subscription**,
  **this endpoint** or **invalid**, plus a help line. **Clear** sits in the row.
  `env_var_source_word` and `endpoint_row_copy` give the other two rows' words and help.
- **Key check (AC#6-#8).** `key_check_verdict` shows the last check's Readiness row, or else the
  word the shared evidence gives the draft. A draft env var name that readiness rejects falls
  back to the saved settings. The labelled result rows and what **t** checks moved to the
  Inspector's new **Key** block (R7). Removed from the card: the Credentials header and status
  line, the Test guidance line and result, and the Provider readiness block. Their facts now sit
  in the rows' Source words (provider and model source, key source, endpoint), the Key check
  row (readiness) and the Inspector.
- **Screen.** `_update_provider_dynamic_widgets` and the subscription poll go through
  `refresh_connect_rows` / `refresh_key_rows`. The '/' "Provider" entry and the conflict review
  now land on the visible control (R9). Deleted because nothing used them any more:
  `_provider_key_status`, `_provider_credential_status`, `_provider_registry_credential_status`,
  `_provider_endpoint_display_value`, `_settings_source_label` and `SETTINGS_SOURCE_LABELS`.
- **CSS.** New Settings-scoped token rules in `features/_settings.tcss`. At 211x44 the control
  column is 36 wide on every row, so the Source words line up. A narrower card shrinks the
  Source word and help first and keeps each control's text at least 20 cells wide (TASK-32593).
  The old six-row picker rules are gone. Rebuilt with `build_css.py`; the boot bundle is unchanged.
- **AC#9.** These conditional rows keep their conditions, and their tests are in the covering
  run: Manual provider, the QwenCloud API mode row and its guidance, hosted guidance, the OpenAI
  restored-connection review, the navigation-conflict and return-continuation blocks, and the
  vLLM gate.

Rulings:
