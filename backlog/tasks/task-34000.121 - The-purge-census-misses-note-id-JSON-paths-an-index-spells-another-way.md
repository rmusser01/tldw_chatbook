## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: PR #3423 re-review 3 (m-4). The Delete forever completeness census discovers the JSON paths a note id hides in from the schema's own index SQL (`note_id_json_paths`, `Tests/ChaChaNotesDB/note_trace_census.py` about :43-:110). Its regexes accept only `json_extract(<column>, '$.a.b')` and a non-nested `CASE ... END`. A future index that keys a note id with `->>`, a double-quoted or bracketed path, or a nested `CASE` is not discovered, and nothing goes red: the fixture is then never asked to fill that path, so a purge that forgets it passes. On today's schema it finds exactly the four v59 paths (intents and heads, `$.note_id` and `$.subject_id`), so nothing is missed yet.
