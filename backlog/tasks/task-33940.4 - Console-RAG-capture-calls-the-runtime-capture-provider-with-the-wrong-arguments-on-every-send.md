## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Every Console send logs "Console RAG capture unavailable; reason=capture_provider_failure". With exception logging added, the cause is `TypeError: ConsoleRuntime._capture_frozen_console_staged_rag() missing 1 required positional argument: 'launch'`. The production controller (built by ConsoleRuntime) is wired with a three-argument provider, but `_capture_rag_context` calls it with two, and ConsoleRuntime lacks the staged-evidence snapshot hooks that would select the frozen path. The exception is swallowed without a traceback, so Library retrieval for a send silently never happens and the trace records a false "Retrieval failed". This is review finding G2-37 (listed under TASK-33621), which has no task of its own.

## Implementation Notes

Root cause: since 5e2127eaaa (merged via #2504) ConsoleRuntime wires `rag_capture_provider=self._capture_frozen_console_staged_rag` (draft, turn_context, launch), and `_capture_rag_context` calls the live seam with two arguments. Production sends are custodied; a custodied turn without a staged launch had `staged_evidence_frozen=False` and fell through to the live seam, raising TypeError on every send (swallowed; false "Retrieval failed" trace pair; review finding G2-37). A custodied turn WITH a launch but no preparation ("/" or "$" draft, capture off) hit the same path and silently dropped its staged evidence.

Fix: at the capture decision, custodied turns always take the frozen route (`_capture_frozen_rag_context` now takes the lease directly); with no launch nothing is captured and no retrieval trace is recorded. The no-preparation case builds a `_PreparedEvidenceLease` from the admitted launch and releases it at acceptance via the shared `_release_evidence_lease`. `staged_evidence_frozen` is untouched (it drives dispatch-recovery reconstructability). Both capture except-sites now log `exception_type` (structural only; inventory reviewed). Not done: replacing the duck-typed `rag_capture_provider.__self__` lookups with explicit constructor parameters.

Evidence: `Tests/Chat/test_console_runtime_rag_capture_wiring.py` (3, real runtime wiring, private profile): the no-staged send logged the failure on dev and is clean now; the "/" staged-evidence case captured nothing on dev and now attaches + releases; the ordinary staged case passed before and after (guard). Regression: 24 related files compared per file (120 s per-test timeout) against a clean origin/dev worktree -- zero tests failing only on this branch; five files that hang on BOTH sides were re-run per test under xdist with thread timeouts -- identical 81 failed / 24 passed / 36 errors / 15 crashed on both sides. Live: a real send logged no `RAG capture unavailable` line (it logged one on every send before).
