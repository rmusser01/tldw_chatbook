## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The Library reader now re-checks its loaded transcript every time the Conversations list reads again, and reloads it when the transcript changed. It uses the path the list already uses: a return visit to the reused Library screen runs ScreenResume, then a page request, then apply, then _ensure_library_conversation_reader_selection.

Root cause: _ensure returned early whenever the list record's conversation version matched the loaded one. A message delete, Undo, edit or send never changes conversations.version, so the list re-counted the messages while the reader kept its load.

Fix:
- New module UI/Library_Modules/library_conversation_reader_freshness.py (not a *_controller glob member). ensure_reader_current holds the existing version decision, moved over unchanged. Once per list read it starts a re-check of an eligible loaded transcript: one bounded read (one message, one character) of the saved message_epoch and message_total. message_epoch hashes the conversation's message row count and version sum, so every reader-visible write moves it.
- If either value moved, the reader reloads through the existing fenced pipeline (_start_library_conversation_reader_selection). Read/Info mode and the Find query are kept, and Find re-runs against the reloaded transcript.
- The "already checked" mark is the new LibraryConversationsState.reader_checked_read field: (list request generation, reader generation). A transcript loaded at or past the marked reader generation is current for that list read. So a load _ensure started, a reload the re-check started, and a load a row press started straight through the reader pipeline are all exempt from a second read in the same list read.
- The re-check is fenced:
  - mounted authority;
  - Conversations row still selected;
  - not in select mode;
  - same loaded id and loaded generation.
- A failed or None read keeps the transcript as it is. The list's own absence check settles a deleted conversation.
- library_conversation_reader_controller.py: _ensure delegates through a local import, so nothing is added at boot. The file went from 976 to 964 lines, and its ratchet row was lowered to 964 (967 after the review round below). library_screen.py is untouched. No schema change. One new diagnostic, added in the review round below.

Residuals:
- A list re-read from paging or filtering also costs one bounded re-check read while a transcript is open.
- The re-check worker is not gated on Library being suspended. Leaving Library mid-re-check can start a reload while it is covered, which costs one extra load. The mounted-authority and row fences still hold. The reader controller has no suspended accessor, so adding one means new constructor wiring in the controller and library_screen.py.
- The reader mounts newly inserted rows at the end (pre-existing _sync_messages behaviour). That is correct for sends and for anything appended. A restore that inserts rows in the middle while the reader already shows the gap is not reachable from Console today, because Undo is only offered before you can leave.
