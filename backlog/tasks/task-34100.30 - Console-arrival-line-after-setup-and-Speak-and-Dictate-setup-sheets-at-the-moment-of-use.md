## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Voice and dictation matter the first time someone presses Speak or Dictate, not as a detour inside a two-minute setup. And the hand-off into Console is a stack of toasts that cover the nav bar [new-entry-exit-handoff-02].

The approved spec replaces the arrival toasts with one dim transcript line naming provider, model, streaming and context, quoting the setup test when there was one (decision D6, part 2; TASK-34100.5 AC#11 provides the single line). It also opens a compact single-step setup sheet over Console when Speak or Dictate is pressed with nothing configured (D6, part 3), using the single-step host from TASK-34100.26 and the Voice and Dictation step states (TASK-34100.8, TASK-34100.13). Over Console a sheet never accepts or shows an API key (task-33008 AC#4); a service that needs one sends the user to Settings through task-33008's round trip. The arrival line quotes the test from TASK-34100.29.

Spec: Docs/superpowers/specs/2026-10-03-first-run-setup-shape-design.md (revision 3, approved by the owner on 2026-10-03; ADR-217): D6 parts 2 and 3, §3.8, §3.9, §10 F10.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Before code changes, Implementation Notes record what Speak and Dictate do today on a profile with nothing configured
- [ ] #2 After setup, the new conversation starts with one dim system row, never a toast and never sent to the model: 'Setup complete — <provider> · <model> · streaming on · <context>. Switch models with Alt+M, or Ctrl+P then "model".' A local provider reads '<engine> on this computer · …'. After a test it adds 'Your test reply is in History: "Setup test · <provider> · <model>".' Every value comes from the resolved request settings. There is no line when the verdict was ✗, and the line is not repeated on later launches
- [ ] #3 Pressing Speak with no voice configured, or Dictate with no dictation engine, opens that area's single-step sheet over Console. Save writes through the step's own commit and then does what was asked: reads the reply aloud or starts dictating. Cancel writes nothing, and focus returns to the control that opened the sheet
- [ ] #4 Over Console the sheet never accepts or displays an API key. A service that needs one shows 'Needs an OpenAI key — add it in Settings ▸ Providers & Models…', which uses task-33008's round trip and returns to the chat, and the sheet promises no setup resume
- [ ] #5 The sheet fits 80x24 (at most 76x20), its styles load with the sheet rather than the boot stylesheets, and a step renders the same in the corridor and in the sheet
- [ ] #6 Verified live on a fresh isolated profile (TLDW_CONFIG_PATH and HOME set) through the real app, with real providers and the real llama.cpp server, never mock servers: arrival lines after Quick with a real OpenAI key (with and without a test) and with the real llama.cpp server; Speak with nothing configured, choosing OpenAI and hearing the reply; Dictate with nothing configured through to dictated text; and a voice service that needs a key taking the Settings round trip. Evidence is recorded in Implementation Notes
- [ ] #7 New behaviour is covered by tests that fail on the pre-change code (RED verified), and no module-size or ADR-097 ratchet is raised
- [ ] #8 The matching Docs/User_Guide page content is updated where behaviour changed (no 'Verified against' stamps)
