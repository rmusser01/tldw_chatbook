## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the review of TASK-33620.15.8. Send's readiness is synced from two places. The screen's sync (ChatScreen._sync_console_composer_action_state) counts a draft or a staged image (_console_pending_image_attachment). The composer's own sync (ConsoleComposerBar._sync_current_action_state) counts a draft or any pending attachment label. Whichever runs last decides Send's state. Since TASK-33620.15.8 the composer's own sync runs one callback after a Send's acceptance, so after any screen sync in the same step, and its reading wins there. The divergence predates that task and matters only if a non-image attachment label can stay staged; whether it can has not been checked.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->

- [x] #2 A test fails when the two sites give Send different readiness for a staged attachment

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Measure: mounted probe staging each kind the store accepts (image, attachment-mode document, image without bytes, inline text) with an empty draft; read the send gate.
2. Decide the rule from the send gate: an empty draft sends only with a staged image carrying bytes (_console_pending_image_attachment); anything else is refused unsent.
3. Make the composer own the rule (has_sendable_payload: draft text, or the screen-provided sendable-attachment predicate read live), used by both sync sites; the attachment label stays presentation only.
4. Tests first (red on dev): both sync orders agree per kind and match what pressing does; the composer resync reads the store, not a stale label.
5. Update the bare-composer price test to the new contract, census entry, ratchet row, User Guide if behaviour visible.
6. Live-verify in the real app; rebase; gates; preflight.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Measured first (dev 3be493413a, mounted probe, empty draft): a staged attachment-mode document with bytes, an image without bytes, and an inline-text item each painted Send disabled from the screen's sync and ready from the composer's own resync, and pressing Send refused each one (False, no message, item still staged). Only an attachment-mode image with bytes was ready from both sites. The send gate (_send_console_message_from_visible_action_observed, also behind Enter) admits an empty draft only when _console_pending_image_attachment() finds such an image, so that is the rule. No staging path produces another kind today: the picker, path drop/paste and Alt+V stage images only, and every text/code/data/PDF/document/e-book file is inserted into the draft as text. The flip was therefore latent, plus one reachable seam: the label is repainted only by the screen's sync, so a composer resync after a send's custody took the image read the stale label as ready (pinned by test; not seen live at 250 ms sampling on dev).

Fix: ConsoleComposerBar.has_sendable_payload() is the one rule (draft text, or the screen-supplied sendable_attachment_provider, which is the send gate's own predicate read live). _sync_current_action_state and ChatScreen._sync_console_composer_action_state both pass it as has_draft; the attachment label is presentation only.

Tests: new Tests/UI/test_console_send_ready_attachment.py (2 mounted cases, both red on dev for the right reason: document-with-bytes (True, True) != (False, False); stale label (False, False) != (True, True)); unwired-provider mutation turns both red. The bare-composer case in test_console_send_price.py now installs a provider (a label alone no longer makes Send ready). Census +1 tail entry (floor: dev 964 + 1 = 965 after the rebase onto 416feb50ee). chat_screen ratchet row 24319 -> 24320 with a dated owner-rule comment.

Live (real app, claude-haiku-4-5 via review proxy, isolated profile; evidence tools/evidence/bd5/S22): dropping notes.txt inserts it as draft text, Send ready, clicking Send sent it and the model replied; an image (with haiku marked vision-capable in the profile) stages with Send ready, stays ready after a keystroke resync with an empty draft, sends on Enter and the model described it, then Send returns to 'type a message'; X clears it to disabled. Same on dev for these reachable flows. Found: the shipped default model claude-haiku-4-5 is not vision-capable by default, so images block Send there (filed TASK-37031). Enter with the caret after an inserted-file token asks 'Expand?' first (paste-token design, same on dev).
