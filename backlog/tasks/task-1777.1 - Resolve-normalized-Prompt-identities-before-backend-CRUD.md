## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Ensure Console distinguishes a normalized Prompt row's composite UI identity from its backend `source_id`, so real Local and Server Library rows round-trip through detail, update, usage, and validation without false changed-or-deleted failures.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A real normalized Local Prompt list/search row can be selected and fetched through PromptScopeService without a false changed-or-deleted error.
- [x] #2 Console uses the record's backend `source_id` for detail, update, saved-Prompt usage, and Recipe/Prompt stale validation while retaining the composite `id` only as the UI row identity; legacy/raw test doubles remain supported.
- [x] #3 Console integration coverage uses the real PromptScopeService and PromptsDatabase and proves guarded/open/update/usage paths receive the correct source identity.
- [x] #4 Focused Prompt scope, Console modal/native, Library, provider/privacy, and full-app regression suites pass with no changes to composer-menu placement or provider/privacy behavior.
- [x] #5 Saved Recipe source and raw identity are captured together, so colliding Local/Server source IDs and late cross-source detail completions cannot redirect Recipe stale validation to the wrong backend.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add a real-service RED regression that lists/selects a normalized Local Prompt row and proves Console currently forwards the composite UI identity into PromptsDatabase detail.
2. Add focused RED cases proving normalized `source_id` is used for detail, selected working-copy identity, update, usage, and stale validation while legacy/raw-shaped records still work.
3. Implement the smallest Console-side identity selection correction without changing PromptScopeService's normalized response shape or backend CRUD contract.
4. Run focused PromptScope, Console modal/native, Library, privacy/provider, Ruff, compile, and diff gates; reproduce the real isolated capture scenario.
5. Record the existing ADR-040 as applicable (no new ADR), complete ACs/notes only after verification and independent review, and commit the scoped fix.

Independent review fix round 1: add a colliding Local/Server Recipe ID plus late cross-source completion RED regression; capture Recipe source explicitly alongside its raw `source_id` in both manual-apply guards and model-facing request snapshots; validate latest Recipe detail only against that captured pair; remove the mutable unqualified source lookup. Amend verification notes to distinguish the implementer's passing exact reruns from the independent review run where the unchanged stale-search timing node also failed in isolation.

Root-cause hypothesis: Console's Browse, detail, and save identity helpers prefer normalized `id` (`local:prompt:<source-id>`) over `source_id`; the working Library integration does the opposite before backend calls. Preferring `source_id` at those Console consumption points will restore real round trips without expanding the PromptScopeService API.
