## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Entering Library › Notes from the rail does not reliably put keyboard focus where the user expects. Depending on load, focus ends on the Notes filter, the rail's "Import…" button (`#library-ingest-top-button`), the first tree note, or the Library (Nav) grip. A keyboard user who clicks Notes and starts typing can therefore type into nothing, or press Enter on Import. Found during the Roleplay frame B0 live check (TASK-33910.1); it is pre-existing on dev and not caused by B0.

**Evidence (B0 focus investigation, 2026-10-02).** Interleaved ABBA trials at 160x45: the filter ended focused in 14/19 base runs and 14/19 B0-head runs (Fisher p = 1.0); at 120x36, 3/4 vs 2/4. All four wrong end states occur on base. Wrong endings rise with CPU load (9/22 at load 9.5-18.4 vs 1/16 at load 3.6-8.6, both arms pooled).

**Root cause.** Several unordered async participants write focus on Notes entry, and the result depends on how they interleave:
- The Notes canvas's data loads land as canvas recomposes, each followed by a queued focus restore (`library_notes_controller.py:2113`, inside `_restore_library_notes_focus_identity`).
- The list-entry arm runs `_focus_library_list_entry` (`library_screen.py:10930` is its empty-list fallback to the filter; the first-row branch is taken once rows are mounted).
- The browse shell is composed with the stored layout. On first entry that layout has both panes closed, so the shell's mount-time sync disables the Items pane until the first settled sync reopens it.

Two bad interleavings turn this into a wrong final focus:
- **Restore cannot land.** The restore runs while the mount sync has the Items pane disabled, so `set_focus` is a silent no-op and the restore never re-arms.
- **Prune, then automatic reopen.** The restore lands first, then a later canvas recompose prunes the filter and Textual parks focus on the previous focus-chain entry, the Nav grip. The first settled sync then sees focus on the grip as the Nav pane reopens, and its automatic reopen moves focus into the Nav pane's first focusable widget, the Import button.

**Also:** the investigation's A/B oracle (the filter) is itself the empty-list fallback; the list-entry method's documented intent is the first row. The fix should settle which target is intended.

**Scope note:** the racing code is in `library_screen.py`, `library_notes_controller.py` and the canvas sync, which PR #2862 also rewrites; coordinate with it. The automatic-reopen rule lives in the shared shell (ADR-212), so a change there applies to Roleplay too.
