## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Moved `Utils/Splash_Screens/` to `UI/Splash_Screens/` with `git mv` (history follows). Path name kept: the `Utils` shim path and every old import/grep target stay recognisable, and UI already mixes `*_Modules` and bare names.

- Only non-byte-identical edit: `card_definitions.py` used `from ..Splash_Strings` / `from ..Splash`; relative imports to `Utils` cannot survive the move, so they became absolute `tldw_chatbook.Utils.*` imports. (`DEVELOPER_GUIDE.md` path text updated too.)
- Old paths: `Utils/Splash_Screens/__init__.py` is a ~30-line alias: a `sys.meta_path` finder maps `...Utils.Splash_Screens[.x]` to the real UI module object (no second copy, one effect registry) and the package replaces itself in `sys.modules` with the real one. Lazy: `import tldw_chatbook.app` loads none of it. Coordinator ruling: the shim's UI import is a plain literal (not hidden in a variable); it has ONE explicit `top` row in `layer_direction_allowlist.tsv` plus a dated exception line in `Docs/Architecture/layer-map.md` (no row was deleted by the move; custom splash cards may use old paths). The row goes when the shim is retired.
- Production imports retargeted: `Widgets/splash_screen.py`, `Widgets/settings_splash_screen_viewer.py`, `UI/Wizards/first_run_appearance_step.py`.
- Patch-path review: no `patch(`/`monkeypatch` string path names the old location (only `monkeypatch.setattr(SplashScreen, ...)`). The only module-path strings are `import_module` names in tests, which the alias serves unchanged; the registry builds names from `__package__` (now the UI path). One retarget was needed: the lazy-import guard in `Tests/Performance/test_app_startup_performance.py` checks `sys.modules` by name, and old names would never appear, making it vacuous; it now names the UI paths.
- Ratchets: boot-import and ui-ready snapshots swapped the three Splash rows (hand-edited, sorted; the updater script also rewrote unrelated stale rows on dev, not committed). `Docs/security/production-diagnostic-inventory.json` regenerated: digests identical, only the two files' paths changed (pure move). No layer-allowlist or module-size rows named these paths.
- Docs: CLAUDE.md, AGENTS.md, Docs/Architecture/app-shell.md.
- Tests: splash suites (Utils/Widgets/UI splash tests) have the identical 17 failures at base 198eca8b93 and on this branch (pre-existing, assertions untouched). Alias probe: old and new import give the same class and registry; 87 effects load.

- Review fixes: layer-map exception now also names the dynamic submodule finder (comment at the finder says the same); the alias loader restores the real module `__spec__` so `importlib.reload` works (test `test_old_import_path_keeps_ui_module_spec_so_reload_works`, red with the restore removed, green with it); stale path text fixed in the playback test docstring and SPLASH_SCREEN_GUIDE.md.
