## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-36946's criterion is that adding an engine preset touches only its registry record and its config template section. After TASK-36946.1 and .2, checked on dev `d85e90bc9e` on 2026-11-20, the newest preset (`commandcode`) still appears by hand in two more product files, and tests fail unless a new preset is added there too:

- `ContinuationProvider`, a `Literal` in `Provider_Contract/provider_continuation.py`. `Tests/test_provider_registry.py` pins it equal to the registry-derived `CONTINUATION_PROVIDER_KEYS`.
- `KEY_URLS` / `KEY_URL_UNCONFIRMED` in `Provider_Contract/provider_setup_facts.py`. `Tests/Chat/test_provider_setup_facts.py` requires every keyed provider in one of the two.

The default config template also names the preset twice: its model list under `[providers]`, and its `[api_settings.<key>]` section. AC #1 is read strictly: "its config template section" is the `[api_settings.<key>]` section, so the `[providers]` model list counts as a second place too, unless the owner rules otherwise. TASK-36946.2's notes do not include the demonstration the parent's criterion asks for.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

1. Probe: add a scratch preset (record + `[api_settings]` section only) on the base and run the registry, setup-facts, dispatch and provider-sweep tests, to list every hand-kept place a new preset still needs (beyond the three in the description).
2. `ContinuationProvider`: drop the hand `Literal`; the closed set is the registry-derived `CONTINUATION_PROVIDER_KEYS` that `_PAIRINGS` enforces.
3. Setup facts: `KEY_URL_UNCONFIRMED` = keyed providers without a sourced `KEY_URLS` row (registry-derived); per-account base-URL label/example move onto the record so `BASE_URL_FIELDS` derives too.
4. `[providers]` model lists of the engine presets: a `seed_models` record field, rendered into the template in place of one placeholder comment (values and key order unchanged; show the written-file diff).
5. Any other hand list or frozen test pin the probe finds (auto-refresh list, readiness/display-name pins): derive it, or retarget the pin to "base values unchanged, new presets come from the record".
6. Re-run the probe after the change (AC #2), then remove the scratch preset; update ADR-179, CLAUDE.md and the provider architecture doc.
