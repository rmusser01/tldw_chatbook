## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-33006.3's review (fix round 1, 2026-10-02) found three nodes failing inside the sets that TASK-33006.3 AC#4 (credential round trip) and AC#7 (TASK-30014 AC#1-3, the paid generation test) say still pass. They fail identically on a clean origin/dev worktree at acc45cdc2e, run serially with `PYTHONPATH` set to that tree, so they predate Phase 6:

- `Tests/UI/test_console_session_settings.py::test_generation_test_model_edit_cancels_and_rejects_late_result[select]` and `[input]`: `assert 'Cancel test' == 'Test generation'`. The test drives the model change by calling `_model_select_changed` with an event whose value the Select does not hold (the handler now drops that as a stale echo), and by setting the model Input outside custom mode (the handler only schedules a debounced readiness sync). So neither path reaches `_cancel_connection_probe`. The `picker_selected` and `picker_value_changed` params still pass. It is not yet known whether a real Select or Input edit during a running paid test cancels it; that has to be checked before the test is changed.
- `Tests/State/test_screen_state_store.py::test_native_console_state_keeps_suspended_settings_draft_process_local`: `AttributeError: 'types.SimpleNamespace' object has no attribute 'stage_console_staged_evidence'`. The test's bare `ChatScreen` gives `_console_runtime_ref` a `SimpleNamespace` without that method, and the `_pending_console_launch_context` setter (chat_screen.py, added by b7dd8e53f2 on 2026-09-08) now calls it.

TASK-33006.4 deletes the model Select and Input adapters, so the first two may be rewritten or dropped there; this rider makes sure the cancel-on-model-change guarantee still has a passing test either way.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Done in the Phase 6 final fix wave (final review I2), so the phase's PR carries every subtask.

- **AC#1.** A real model change during the paid test cancels it. TASK-33006.4 deleted the model Select and Input, so pick mode is the only model edit left. New `Tests/UI/test_console_settings_model_change.py::test_a_pick_during_the_paid_test_cancels_it_and_keeps_the_billing_warning` drives it with real keys: Change, "model-b" in Find, Enter. It runs while a paid test is in flight whose tester ignores cancellation. The test then asserts the test button is back, the status keeps "Stopped waiting … may still be billed", and the late "succeeded" never reaches readiness. It waits on pauses, not on workers, because the tester never ends. Negative control: with `_cancel_generation_test` a no-op it fails (`'Cancel test' == 'Test generation'`).
- **AC#2.** `Tests/State/test_screen_state_store.py::test_native_console_state_keeps_suspended_settings_draft_process_local` failed because its bare runtime had no `stage_console_staged_evidence`. The `_pending_console_launch_context` setter has called that since b7dd8e53f2. The bare screen now gets a `_BareRuntime` whose four staged-evidence methods are `ConsoleRuntime`'s own, over a real `_ConsoleStagedEvidenceState`. So the setter and the restore run the production code, and nothing is bypassed. The file passes 43/43 serially at the rebased head.
- **AC#3.** The `[select]` and `[input]` params of `Tests/UI/test_console_session_settings.py::test_generation_test_model_edit_cancels_and_rejects_late_result` are replaced, not repaired. TASK-33006.4 turned the node into one unparametrized test through pick mode's `_model_picked`, and it passes. The real-key test above now covers the same guarantee end to end. The state-store node passes (AC#2).
