## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: PR #3423 review I-2 sent the select-mode bulk Add/Remove keyword through `NotesScopeService.change_local_note_keyword`, so each note takes the editor's keyword path, which applies the policy gate and records the Sync v2 organization intents. Before that, the change never reached another device.

Measured on a real database (2026-11-06): with a ready Sync v2 local-first profile, 50 notes take 10.8 s to add a keyword and 10.3 s to remove it, against 135 ms without Sync v2. Each note pays four private-SQLite opens in `SyncStateRepository`, the same cost one editor save pays once. The Notes single-writer interlock is held for the whole run, so every other Notes change waits behind it. The result is correct, but a user who checks many notes waits several seconds with Notes locked.
