## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the PR #2938 thread triage and its checkpoint review. After the first interaction with the provider list, one arrow press or one click reaches _select_provider_option twice. Textual's OptionList posts OptionHighlighted, then ProviderChoiceList.Interacted on a key, or OptionSelected on a click. If the first pass fails after selected_provider_key moved (e.g. capture_provider_config_precondition raising OSError), the second pass is a no-op re-pick, and first_run_step_guard.provider_switch calls clear_contained_error, which removes the line. The error is logged and commit re-runs discovery, but the user is never told. Only the very first interaction, and Enter/Space on the already-highlighted row, dispatch once. PR #2938's User Guide sentence ('A failure after the new provider is already selected leaves it selected, and the line then names no other provider') and the provider_switch docstring ('its line names none') therefore describe a line that most paths never show. Evidence: scratchpad logs TT-2938-red.log (keyboard variant: assert 'went wrong' in ''), TT-2938-rev-probe-dispatch.log.
<!-- SECTION:DESCRIPTION:END -->
