- Byte identity at 88af9f9379 before vs after, through run.sh: resolved `CONFIG_TOML_CONTENT` sha256 1d589156...995a9 (118890 chars) and the `DEFAULT_CONFIG_FROM_TOML` hash 3e0ce287...6dac both identical. The resolved constant is also what a fresh install writes.
- config.py 12285 -> 9668 lines (-2,617); module-size row lowered.
- Packaging: pyproject package-data, MANIFEST.in, `Packaging/check_manifest.py` (sdist + wheel required paths) name the file.
- Tests (`Tests/test_config_load_settings_table_guard.py`): sha256 pin of the data file, constant == file + substitutions, config.py no longer embeds the template, packaging config names the file, and a profile-path pin (below). Red: appending one space to the data file fails `test_default_config_template_bytes_are_unchanged`; reverted.
- Ripple edits:
  - `scripts/check_profile_owned_path_inventory.py`: removed the 14 `module:CONFIG_TOML_CONTENT` PERSISTED_DEFAULT rules (the scanner reads Python; with no literal left they would be reported stale).   - `test_shared_asset_exceptions_are_explicit`: dropped the embedding-cache rule lookup; the `models/embeddings` PERSISTED_DEFAULT claim is now one member of that TOML pin.
  - `test_task2062_3_legacy_downloader_retirement`: `config.py` leaves the model_download_dir owner set (the mention is TOML now); the default-text assertion reads the TOML file instead of config.py.
  - `Tests/MCP/test_mcp_documentation_contract.py` (`CONFIG_TEMPLATE`) and `Tests/fixtures/cloud_live/capture.py` (`_config_seeds`) read the template text out of config.py; both now read the TOML file (81 `key = [...]` seed lines identical to before). Found by comparing failures with a clean base run; the first attempt missed them.
