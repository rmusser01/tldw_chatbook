## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The Console Conversation settings modal still offers Minimal as Reasoning effort for llama.cpp and other strict local templates (console_settings_modal.py `_PROVIDER_CHOICE_VALUES`, from `_SNAPSHOT_SETTING_CHOICE_DOMAINS`), and `build_local_thinking_payload_fields` drops it with only a debug log. Settings narrowed its list in TASK-33002.1 (`reasoning_effort_values_sent`); the modal did not, because console_settings_modal.py had no ratchet headroom. Save as model default from the modal can also write the dropped value. Found by the TASK-33002 final review (Task 1 rider edge a).
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Chat settings' Reasoning effort list now comes from the same request-side decision Settings uses, `console_provider_support.reasoning_effort_values_sent` (which asks `build_local_thinking_payload_fields`, the real local request builder, which levels it sends).

- `console_settings_field_row.py` (the modal has no headroom): `_choice_options(control_id, value)` builds a choice Select's options for the draft's provider: Reasoning effort keeps only the levels sent (llama.cpp and a llama.cpp registry entry: none, low, medium, high, x-high; OpenAI all six), and a saved level outside them is appended as "Minimal (not supported here)", Settings' wording (AC#2). `_show_choice(select, value)` re-lists a mounted Select before setting its value, only when its options change (`set_options` resets the value), so a pick or a restore never raises `InvalidSelectValueError` on a carried "minimal". `_field_help` replaces the row's help with `UNSENT_CHOICE_COPY` ("Minimal is not supported here, so it is not sent.") while that option is selected: the closed 13-cell Select cannot show the suffix, the help line can.
- `console_settings_modal.py` keeps only the wiring, net -6 lines (6,159 to 6,153; AC#3): compose builds its options with `_choice_options`; the suspended-draft restore and `_apply_rebased_state` set the value through `_show_choice`; the tooltip and the obsolete-value copy ("Choose one of: …") list the levels offered rather than the whole domain. Review fix: `PROVIDER_CHOICE_INPUTS`, whose domain-joined placeholders lost their only reader, is gone; the tooltip loop walks `_PROVIDER_CHOICE_VALUES`.
- Apply keeps a saved "minimal" (it is still the draft's value); it is not silently cleared. The request still drops it, which the row now says.
- Tests (Tests/UI/test_console_settings_hidden_fields.py, whole file in the UI PR census), all red before the fix: `test_reasoning_effort_offers_only_the_levels_the_request_sends[llama_cpp|custom-ep:gpu-box|openai]`, `test_a_saved_level_the_request_drops_stays_selected_and_says_so` (value kept, labelled option, help painted at 211x44, Apply keeps it, picking Low restores the field's help), `test_a_pick_re_lists_reasoning_effort_for_the_new_provider` (OpenAI "minimal" carried to llama.cpp is labelled; back on OpenAI the list is whole again). Review fix: `test_a_restored_draft_keeps_a_carried_level_the_request_drops` covers the restore half (a suspended draft carrying "minimal" onto llama.cpp reopens with it selected, labelled and explained); red with the restore set back to `control.value = normalized` (`InvalidSelectValueError`). `test_hidden_set_and_line_come_from_the_shared_support_functions` now also asserts `PROVIDER_CHOICE_INPUTS` is gone. Rewritten on purpose: `Tests/UI/test_console_session_settings.py::test_console_settings_modal_enumerated_inputs_list_accepted_values` pinned llama.cpp's list and tooltip with "minimal"; it now pins the five levels sent.
- Docs/User_Guide/console.md says the list leaves out dropped levels and how a saved one shows.
