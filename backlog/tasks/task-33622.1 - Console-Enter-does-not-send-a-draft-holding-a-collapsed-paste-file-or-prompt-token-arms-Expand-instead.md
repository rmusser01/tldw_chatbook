## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** A common power-user flow is to paste a log, insert a file or run `/prompt`, type a question and press Enter. When the draft holds any collapsed token (a paste over 50 chars, an inline text-file token, or a /prompt insert), Enter does not send. Each Enter moves the first remaining token one step, collapsed -> orange 'Expand?' (the file name disappears) -> expanded into the draft. So N tokens need 2N+1 Enters: 3 for one paste, 5 for two file tokens. Esc does not clear a pending 'Expand?'. Nothing is lost, because the sent message carries the full content, but the core send gesture silently fails twice and rearranges the draft. Users conclude the app ignores Enter. Verified live on dev 64579cce2c at 235x52 (live, code and skeptic all CONFIRMED). The same capture also hijacks Enter/Space on the keyboard-focused Send button, which is the composer-button capture defect filed alongside this one.

**Severity / prior art.** P1. Triage BY_DESIGN: the two-step unfurl-on-Enter was added deliberately in git a486ab55ed (`activate_focused_paste_token` on the Enter path in `chat_screen.py`). It is documented in `Docs/User_Guide/console/chat-basics.md` 'Large pastes' and pinned by the 2026-05-08 large-paste-collapse plan and TASK-74 (Done, CDP QA of the unfurl flow). This task deliberately reverses that design, and its docs and tests must change with it.

**Suggested direction.** Take the token-unfurl step off the Enter/send path so Enter always sends the canonical draft, tokens in full. Expanding a token becomes a separate explicit action: a click, or a dedicated key while the caret is on or next to the token. The chip should name that affordance. Esc resets a pending confirm. The confirm label keeps the token's name (e.g. 'Expand photosynthesis.md?'). Replace the test that pins the 3-Enter flow (`Tests/UI/test_console_send_draft_snapshot.py`). The user guide's 'Large pastes' section is also stale on the 'Unfurl?' / 'Pasted Text: N Characters' copy.

**AC amendment, 2026-10-29.** #1-#4 and #6 were amended before implementation to
follow the owner decision of 2026-10-27 on this task (Console UX review P1s): Enter
expands a token ONLY when the caret is on the token; otherwise Enter sends. The
caret can never sit inside a collapsed token (it snaps to the token's edges), so
"on the token" is implemented as "on or immediately next to it". The original
proposal (Enter always sends; a separate expand key) was the option the owner did
not pick.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 With the composer focused, a draft holding one or more collapsed tokens (a paste over the collapse threshold, an inserted file, or a /prompt insert) and the caret not on or immediately next to any collapsed token, a single Enter dispatches exactly one send, and the sent message carries every token's full content
- [ ] #2 Enter with the caret away from every collapsed token never changes a token's state (collapsed, confirm or expanded) and never splices token content into the visible draft. Enter with the caret on or immediately next to a collapsed token advances that token only (collapsed -> confirm -> expanded), never another token, and does not send
- [ ] #3 A token can be expanded by an explicit action on the token: a click, or Enter while the caret is on or immediately next to it. A click also puts the caret on that token, so the Enter that follows answers its confirm. Every collapsed chip, paste and inserted file alike, ends in 'Expand', naming that affordance
- [ ] #4 While a token is in its expand-confirm state, Esc returns it to collapsed, and the confirm label keeps the token's name (e.g. 'Expand pasted text (N characters)?', 'Expand <file label>?') and names the keys that answer it, instead of a bare 'Expand?'
- [ ] #5 A Pilot test on the real ChatScreen and composer pastes more than the collapse threshold, types a question and presses Enter once, then asserts exactly one dispatch with the full text. The test fails on the pre-fix code, and the old test pinning the 3-Enter flow is replaced rather than deleted
- [ ] #6 Docs/User_Guide/console/chat-basics.md 'Large pastes' describes the new send/expand behaviour (including that Send always sends, whatever the caret is on) and no longer mentions the retired 'Unfurl?' / 'Pasted Text: N Characters' copy
<!-- AC:END -->
