## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** A common power-user flow is to paste a log, insert a file or run `/prompt`, type a question and press Enter. When the draft holds any collapsed token (a paste over 50 chars, an inline text-file token, or a /prompt insert), Enter does not send. Each Enter moves the first remaining token one step, collapsed -> orange 'Expand?' (the file name disappears) -> expanded into the draft. So N tokens need 2N+1 Enters: 3 for one paste, 5 for two file tokens. Esc does not clear a pending 'Expand?'. Nothing is lost, because the sent message carries the full content, but the core send gesture silently fails twice and rearranges the draft. Users conclude the app ignores Enter. Verified live on dev 64579cce2c at 235x52 (live, code and skeptic all CONFIRMED). The same capture also hijacks Enter/Space on the keyboard-focused Send button, which is the composer-button capture defect filed alongside this one.

**Severity / prior art.** P1. Triage BY_DESIGN: the two-step unfurl-on-Enter was added deliberately in git a486ab55ed (`activate_focused_paste_token` on the Enter path in `chat_screen.py`). It is documented in `Docs/User_Guide/console/chat-basics.md` 'Large pastes' and pinned by the 2026-05-08 large-paste-collapse plan and TASK-74 (Done, CDP QA of the unfurl flow). This task deliberately reverses that design, and its docs and tests must change with it.

**Suggested direction.** Take the token-unfurl step off the Enter/send path so Enter always sends the canonical draft, tokens in full. Expanding a token becomes a separate explicit action: a click, or a dedicated key while the caret is on or next to the token. The chip should name that affordance. Esc resets a pending confirm. The confirm label keeps the token's name (e.g. 'Expand photosynthesis.md?'). Replace the test that pins the 3-Enter flow (`Tests/UI/test_console_send_draft_snapshot.py`). The user guide's 'Large pastes' section is also stale on the 'Unfurl?' / 'Pasted Text: N Characters' copy.

**AC amendment, 2026-10-29.** #1-#4 and #6 were amended before implementation to
follow the owner decision of 2026-10-27 on this task (Console UX review P1s): Enter
expands a token ONLY when the caret is on the token; otherwise Enter sends. The
caret can never sit inside a collapsed token (it snaps to the token's edges), so
"on the token" is implemented as "on or immediately next to it". The original
proposal (Enter always sends; a separate expand key) was the option the owner did
not pick.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 With the composer focused, a draft holding one or more collapsed tokens (a paste over the collapse threshold, an inserted file, or a /prompt insert) and the caret not on or immediately next to any collapsed token, a single Enter dispatches exactly one send, and the sent message carries every token's full content
- [x] #2 Enter with the caret away from every collapsed token never changes a token's state (collapsed, confirm or expanded) and never splices token content into the visible draft. Enter with the caret on or immediately next to a collapsed token advances that token only (collapsed -> confirm -> expanded), never another token, and does not send
- [x] #3 A token can be expanded by an explicit action on the token: a click, or Enter while the caret is on or immediately next to it. A click also puts the caret on that token, so the Enter that follows answers its confirm. Every collapsed chip, paste and inserted file alike, ends in 'Expand', naming that affordance
- [x] #4 While a token is in its expand-confirm state, Esc returns it to collapsed, and the confirm label keeps the token's name (e.g. 'Expand pasted text (N characters)?', 'Expand <file label>?') and names the keys that answer it, instead of a bare 'Expand?'
- [x] #5 A Pilot test on the real ChatScreen and composer pastes more than the collapse threshold, types a question and presses Enter once, then asserts exactly one dispatch with the full text. The test fails on the pre-fix code, and the old test pinning the 3-Enter flow is replaced rather than deleted
- [x] #6 Docs/User_Guide/console/chat-basics.md 'Large pastes' describes the new send/expand behaviour (including that Send always sends, whatever the caret is on) and no longer mentions the retired 'Unfurl?' / 'Pasted Text: N Characters' copy

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Enter now steps only the collapsed token the caret is on (either edge;
`ConsoleComposerBar._caret_token`), per the owner decision of 2026-10-27. With the
caret anywhere else `activate_focused_paste_token` returns False and ChatScreen's
Enter sends the canonical draft, every token in full. One confirm at a time; Esc
(`handle_console_key`) and any caret move off the token (`_move_cursor_to`) return a
pending confirm to the chip; a click on a token also puts the caret on it, so the
Enter its confirm names answers that token. Labelled (file) chips now end in
"| Expand" like paste chips, and the confirm reads "Expand pasted text (N
characters)? Enter: yes · Esc: no" or "Expand <file label>? Enter: yes · Esc: no".

**Tests.** New `Tests/UI/test_console_composer_token_enter.py` (7 cases on the real
ChatScreen and composer with real keys). The AC#5 case pastes through the app (or
inserts a file token), types " why", presses Enter once and asserts one provider
stream call carrying the full text. All 7 fail on dev 38c9d2edcf for the right
reason (the send case: "one Enter did not send; the draft shows 'Expand? why'").
The 3-Enter pin in `test_console_send_draft_snapshot.py` is replaced in place, not
deleted. Copy pins updated in `test_console_internals_decomposition.py` (made
wrap-tolerant: the named confirm can soft-wrap where "Expand?" never did; one click
test now also pins the caret landing on the token), `test_console_composer_keymap.py`
and `test_console_native_chat_flow.py`. Reds compared by test id against a detached
origin/dev worktree: no new reds (the decomposition file's setup-modal and
caret-blink cases flip run to run on dev as well).

**Live** (real app, Anthropic claude-haiku-4-5 via the review proxy, isolated
profile, null keyring, 160x45). Dev 38c9d2edcf: paste + " Summarize in 3 words." took
three Enters (Enter 1 showed "Expand? Summarize in 3 words.", Enter 2 spliced the
paste open, Enter 3 sent). Fix: one Enter sent, and the model's reply listed all four
pasted lines. With the caret right after a token, Enter showed "Expand pasted text
(82 characters)? Enter: yes · Esc: no", Esc restored the chip, and two Enters
expanded it in place. Evidence: `tools/evidence/bd5/U11/01-02*`, `20-25*`.

**Left for the owner.** With the caret right after a token at the end of the draft
(paste, then Enter at once), Enter arms the expand rather than sending; Send, or
moving the caret off the token, sends. That follows the decision as given, and the
User Guide says so.

**Docs and ratchets.** User Guide `console/chat-basics.md` 'Large pastes' rewritten
(the retired 'Unfurl?' / 'Pasted Text: N Characters' copy is gone);
`console/context-and-rag.md`'s `/prompt` sentence updated. The
`console_composer_bar.py` module-size row rose 7043 -> 7074 with a dated owner-rule
