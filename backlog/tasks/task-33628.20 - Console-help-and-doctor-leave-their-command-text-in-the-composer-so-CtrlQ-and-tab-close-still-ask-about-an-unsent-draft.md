## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while live-verifying TASK-33628.16 (2026-11-06, origin/dev 8ae979d81b plus that fix). After /help or /doctor runs, its command text ("/help", "/doctor") stays in the composer. Since TASK-33628.16 the output row no longer counts as loss (owner decision 2026-10-29), but the leftover text is an ordinary draft, so Ctrl+Q right after /help still asks "Quit Chatbook?" with "Unsent drafts: 1", and tab close asks "Unsent draft: yes". The user has to clear the composer (Ctrl+U) before either closes without a question. Other commands drop their text once they run (a typed action command such as /model clears the draft; /prefill clears it on a handled outcome and keeps it only after an error, for correction). Whether /help and /doctor should do the same, and whether leftover text from a command that already ran should count as an unsent draft, is an owner call.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Decision (AC#1).** Owner decision 2026-11-12, "Clear it after running": a slash command that ran (/help, /doctor) leaves an empty composer, the same as a sent message. A refused or unknown command keeps its text so it can be corrected. Text a command did not take (a refused or unknown command, or anything typed after Enter) is an ordinary unsent draft, and the close and quit dialogs still count it.

**Approach.** One helper, `take_ran_command_draft(owner)` in `UI/Console_Modules/command_draft.py`, called on each command's success path. It takes only the revision the send captured (`take_command_draft`): text typed after Enter stays, and a composer that moved to another chat is left alone. Outside a sent command (a button, the palette, a direct call) there is no captured draft, so it takes nothing. `ran_command_draft_taker(owner)` holds the captured draft for a dialog that finishes the command later.

- Taken once the command answers or opens: `/help` and `/help <command>` (`/help <unknown>` keeps it; `find_command` added to `Chat/console_help.py`), `/doctor` (also when a check fails), `/research` once its run starts, `/skills` listing (`/skills <name>` keeps it), `/rules` once the manager opens, `/stream-video` once the player opens, bare `/workflow` once history opens, `/rewind <args>` once its menu opens (the send already did this for a bare `/rewind`).
- Taken once the dialog applies or starts something, kept on Cancel or Escape: `/system` editor (Apply or Clear), `/system <query>` picker, `/goal` (Start; User Guide already said Cancel keeps the draft), `/workflow new` (start).
- Unchanged: the commands that already removed their text (`/prefill`, `/steer`, `/redirect`, `/stop`, `/emergency-stop`, `/omfg`, `/fewer-permission-prompts`, the action commands, `/generate-image`, `/generate-video`, named `/system <name>`), and `/prompt`, whose result replaces the draft and whose picker Cancel keeps it.
- `/skills` takes inside the skill controller (an injected `take_ran_command_draft`), because the wave-6 architecture contract keeps `ChatScreen._console_command_skills` a one-line delegate.

**Tests (test-first).** `Tests/UI/test_console_command_clears_composer.py`, on the real Console path with real keys: a command that ran leaves an empty composer (/help, /help prefill, /skills, /research, /stream-video); Ctrl+Q right after /help or /doctor in a saved chat quits without asking; tab close right after /help closes without asking; /help <unknown>, /prefill pin, /skills <name>, /research and /stream-video usage errors and an unknown /command keep their text. Pins flipped to the new rule: `test_console_system_prompt.py` (editor apply and picker apply take the text; open and Escape keep it), `test_console_goal_command.py` (a started goal), `test_console_workflow_command.py` (a started workflow, run by the controls and navigation files), `test_console_rewind_restore.py` (`/rewind <args>` keeps only what was typed after Enter), `test_console_response_rules.py` (`/rules` takes it, `/rules everywhere` keeps it). Three nodes joined the UI PR lane census.

Every "keeps" guard passed. On the branch all 14 new tests pass. The affected files were run per file on both trees and compared by test id, and no id failed only on the branch. In the same profile, an unknown `/nosuchcommand` kept its text, and Ctrl+Q asked "Quit Chatbook?" with "Unsent drafts: 1".
