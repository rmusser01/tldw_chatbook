## Implementation Notes

Implemented the Media_Playback package and in-card silent preview (ADR-044 §5A; textual-video architecture reused clean-room -- its LICENSE verified MIT 2026-08-08, satisfying the vendoring clause without copying any code). Media_Playback/: preview_policy.py (pure caps -- 30s duration / 2560x1440 source / 12fps target -- checked twice: metadata at compose, probed shape at open); availability.py (av + textual-canvas probes, video_playback install guidance); frame_source.py (VideoFrameSource protocol + av-gated AvFrameSource: probe-without-decode, wall-clock-paced frame iterator -- sleeps when decode outruns playback, drops forward when it lags, abandons cleanly on pause). Widgets/Console/console_video_preview.py: paused-by-default (zero decode until an explicit click), click toggles play/pause, one-active-preview registry (playing one pauses any other), 0.5s off-screen pause via region-vs-viewport check, worker-thread decode pushing PIL frames through call_from_thread into rich_pixels at the inline-image cell bounds, text progress bar (no canvas dependency), unmount cleanup. Ready video cards mount the preview above status/details; expired cards and the card signature are untouched (playback state is widget-local). Deps: textual_canvas slot + video_playback OptionalFeatureInfo in optional_deps; pyproject video_playback extra (av, textual-canvas). Self-review caught three real bugs the tests then proved: an inverted eligibility-reason ternary in the widget constructor, a throttle that skipped frames instead of pacing (fast decode collapsed to one emitted frame), and a poster hint tied to pixels instead of state.
