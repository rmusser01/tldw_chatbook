## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found reviewing TASK-33620.15.24. Shutdown (app_lifecycle.py) cancels the scheduler worker and awaits scheduler_worker.wait(). SchedulerLoop._offload shields its worker hops so the maintenance drain owns them, but nothing at shutdown awaits SchedulerLoop._maintenance_db_tasks. If the cancellation lands while a hop runs (since TASK-33620.15.24 that includes a storage-admission entry), shutdown proceeds while the hop is still acquiring or using storage on a worker. Today this is benign: the hop closes its own lease before the executor join and the atexit shutdown. The gap predates TASK-33620.15.24 for the loop's other hops (queue loads, heartbeat writes, stop-state reads).
