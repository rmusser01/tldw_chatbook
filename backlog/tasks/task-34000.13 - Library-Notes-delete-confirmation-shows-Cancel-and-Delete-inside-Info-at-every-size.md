## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The confirmation for a destructive action cannot be seen. At 120x36 a first-timer presses Info ▸ Delete and only the footer changes. A keyboard-only, low-vision user Tabs between Cancel and Delete and nothing on screen changes. Their only guide is a footer chip ("enter cancel" / "enter delete"), so they press Enter blind. Undo exists, but the user cannot tell what they just confirmed.

Observed at 120x36:
- After Info ▸ Delete and one Tab, Info ends at "Delete this note? Undo will be available" and no buttons are drawn. The footer reads "enter delete | tab switch button | esc cancel" (`verify/nl-v-n-10/07b-after-tab-120x36.ansi`).
- A blind Enter deleted the note: "✓ deleted · Advisor meeting 2026-09-24" with Undo (`08-after-blind-enter-120x36.txt`).

Other sizes:
- At 80x24 the buttons appeared only after a manual wheel scroll.
- At 160x45 "Cancel ┃ Delete" is visible.

What triggers it is the pane's height, not its width: it depends on how much Info content sits above Danger. The captured note has a "Linked from (1)" entry.

Verified cause (origin/dev 2d34cbf80d):
- The confirmation is a `Vertical`, `#library-note-delete-confirmation`, composed inside Info's Danger section (`_compose_delete_confirmation`, `Widgets/Library/library_notes_canvas.py:3099-3123`). It is mounted at :3006, inside the `#library-note-context-region` VerticalScroll (:2914).
- Only the compact layout gives it a size (`css/features/_library.tcss:1197-1201`). In the wide layout it keeps Textual's default for a Vertical (`height: 1fr; overflow: hidden`).
- Inside a scrolling parent, a 1fr height gets only the rows left over. At 120x36 that is one row, so the button row is clipped.
- Focus moves to Cancel, but the block is not scrolled into view.

This is a regression of TASK-32268 (Done; it moved the prompt inside Info) and of the Info densification in TASK-32642 (Done).

Suggested direction (a direction, not a mandate):
- Add a base rule `#library-note-delete-confirmation { height: auto; }`. Edit the source `.tcss` and regenerate the bundle.
- Then show the block, scroll it into view after refresh, and focus Cancel.
- Keep TASK-32268's placement and its cancel-restores-scroll behaviour.

Review finding(s): N-10. Source: qa/notes-library-ux-review-2026-10-02/report.md

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** The prompt now sizes to its content at every width and Info is scrolled to it after the refresh, so
the copy, Cancel and Delete are inside the Info box the moment Delete is pressed; a resize while it is open keeps
it there. Delete semantics, copy, soft-delete path, the task-32132 Tab trap and task-32268's placement +
cancel-restores-scroll are unchanged.

**Cause (verified on base `0467e105e7`).** `#library-note-delete-confirmation` is a `Vertical` inside Info's
`VerticalScroll`; only the compact rule gave it a height, so on the wide stage it kept `height: 1fr; overflow:
hidden` = the leftover rows (one at 120x36: prompt `region h=1, styles.height=1fr`, Cancel/Delete at y=35 outside
Info rows 15-33, `max_scroll_y=0`). At 80x24 the compact 2-row box existed (y=25-26 of a 24-row screen,
`max_scroll_y=5`) but nothing scrolled Info to it: `focus()` runs before the prompt has geometry.
