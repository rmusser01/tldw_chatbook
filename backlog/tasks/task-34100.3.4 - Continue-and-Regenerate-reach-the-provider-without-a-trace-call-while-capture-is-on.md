## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by TASK-34100.3's review round v5r1 (finding F6), outside that task's diff. With trace capture on (the default), Continue and Regenerate in a saved Kimi chat reached Moonshot and stored their replies, but recorded no row in `console_trace_calls`, so the Trace view cannot show those calls. `CONSOLE_REQUEST_ROUTE_CENSUS` in `Chat/console_trace_provenance.py` marks both the CONTINUE and REGENERATE routes `CONVERSATION_TRACE`, so the census and the observed behaviour disagree. One live reviewer read the gap as deliberate (Continue and Regenerate run with capture off); nothing in the code or the User Guide says so. Not yet checked with a non-Kimi provider.

Evidence (setup-wizard-ux-qa): `evidence/g3bv5-k3/15-db-after-continue-regenerate-turn-six.txt` (8 provider requests: 5 turns, Continue, Regenerate, turn 6; 6 trace calls, all `agent_first`), the matching app log (`homes/g3bv5-k3/.../tldw_cli_app.log` 23:49:27-23:49:57: the Continue and Regenerate calls have no capture_policy or trace_reservation stages), and `evidence/g3bv5r1f-k31/10-db-after-continue.txt` (Continue on kimi-k3.1-pro: 4 runs `done`, 3 trace calls).
