## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Review of batch 1 (PRs #2931-#2934) found that most of the new P0 regression tests run in no pull-request CI lane. The UI Fast Lane runs only the files listed in scripts/ui_pr_gate_census.txt, and Tests/Architecture runs in no PR lane. The rest are the Save .md crash test, the Stop reachability and composer-button tests, the keep-alive and Choose folder tests, and the tool-schema conformance test. Until they are gated, each of these P0s can regress unnoticed.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** The Console review's P0 regression tests now run on every pull request inside the required `Derived artifacts reproduce from their sources` check. There are two homes:
- Mounted private-profile tests run as node ids in the UI Fast Lane census.
- Everything else runs in a new parallel job, `console-p0-gate` ("Console P0 regression gate"). The required aggregate needs that job, like the other two lanes.

`Tests/CI/test_console_p0_regression_gate.py` pins where every P0 test runs.

**Approach**
- **Inventory.** The regression tests come from the notes of every review P0: TASK-33621.1, .2, .3, .12, .13, .14, .15, .28 and TASK-33625.1. Before this task only the tab-close file (census) and the self-attribute guard (PR Fast Lane) were gated.
- **Measurement.** Each candidate was timed alone with CI's plugin set (pytest-asyncio and pytest-timeout only) on a host at load average 35-60, reading pytest's own duration. The gated `test_console_send_acknowledgement.py` was the reference: about 10 s idle and under 6 s in CI, against 17 s here.
- **Whole file or node ids.** A whole file is gated when it measured about 30 s or less. A slower file is gated only by the node ids that pin the P0 itself.
- **Census node ids.** `scripts/check_ui_pr_gate_census.py` accepts node ids. `resolve_node` checks that the test and its parametrize id still exist: it resolves literal parametrize ids statically and refuses ids built by code. `overlapping_targets` refuses duplicates, a node id beside its whole file, and anything under a listed directory.
  - The 12 entries sit mid-file, a multiple of the 4 shards, so no other file changes shard.
  - `MINIMUM_FILES` is dev's 163 + 12 = 175.
- **The P0 job (review round 3).**
  - **Why a separate job.** The P0 targets first went into the PR Fast Lane, which then took 33m41s of its 35-min cap (run 38064483856). The admission step took 19m30s there, 3m01s of it the P0 block.
  - **Design.** `console-p0-gate` uses the same install line and serial pytest as the PR Fast Lane. Its sandboxed step holds the unit, DB, private-profile and in-process tests. Its admission-sensitive step (`if: always()`) holds the bootstrap_profile ones (TASK-32873).
  - **Timeout.** 20 min, against about 9 min of work, with the arithmetic in the workflow comment.
  - **Cost.** One more concurrent runner per PR. The ADR-103 note is updated.
  - **PR Fast Lane.** It is identical to dev's again.
- **Pins.**
  - **Lanes.** The pin test fails, naming the P0, when a target runs in no lane, or in two lanes in either direction (a whole file in one lane and a node of it in another). It also fails when a bootstrap_profile target (marker read by AST, plus the conftest's filename set) runs in a sandboxed step, or when a target no longer resolves. The census is allowed bootstrap files: it already runs bootstrap-marked files green.
  - **Overlap.** `Tests/CI/test_derived_artifacts_workflow.py` applies the census overlap helper and the node-id resolver to every pytest step of pr-fast-lane and console-p0-gate.
