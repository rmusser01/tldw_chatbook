## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Review of batch 1 (PRs #2931-#2934) found that most of the new P0 regression tests run in no pull-request CI lane. The UI Fast Lane runs only the files listed in scripts/ui_pr_gate_census.txt, and Tests/Architecture runs in no PR lane. PR #2933 added its tab-close tests to the census, the first file there that needs a private profile. The rest are the Save .md crash test, the Stop reachability and composer-button tests, the keep-alive and Choose folder tests, and the tool-schema conformance test. Until they are gated, each of these P0s can regress unnoticed.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** The Console review's P0 regression tests now run on every pull request inside the required `Derived artifacts reproduce from their sources` check. They are split across the UI Fast Lane census and both PR Fast Lane steps. `Tests/CI/test_console_p0_regression_gate.py` pins where each one runs.

**Approach**
- **Inventory.** I took the regression tests from the notes of every P0 in the review: TASK-33621.1, .2, .3, .12, .13, .14, .15, .28 and TASK-33625.1. Only the tab-close file (`ui_pr_gate_census.txt`) and the self-attribute AST guard (sandboxed fast-lane step) were already gated.
- **Measurement.** Each file was run alone on this branch's base (ebd4b7ddee) with CI's plugin set only (pytest-asyncio and pytest-timeout, autoload off), serially, with `--timeout=180`. The host was at load average 35-60. As a reference, the gated `Tests/UI/test_console_send_acknowledgement.py` (about 10 s on an idle laptop, under 6 s in CI) took 17 s. Times below are pytest's own `in N s`. Wall clock was unusable: processes hung at exit for up to 30 minutes after printing their summary.
- **Placement, by profile need.**
  - Plain unit files go to the sandboxed "Run fast PR contract" step.
  - `bootstrap_profile` files go to the "Run admission-sensitive suites" step (TASK-32873), inserted before its last file so dev's tail additions don't conflict.
  - Private-profile mounted tests go to the UI census.
- **Whole file or node ids.** A whole file is gated when it measured about 30 s or less. A slower file is gated only by the node ids that pin the P0 itself.
- **Census node ids (deviation from plan step 3).** The plan put slow-file node ids in the PR Fast Lane, the only lane that took them. That lane runs about 23-24 min against its 30-min cap (35 on dev), and the private-profile tests are UI tests. So `scripts/check_ui_pr_gate_census.py` now also accepts a node-id entry. The checker requires that the file still defines the test (an AST check, install-free), that the entry has no whitespace, and that the node id does not sit beside its own whole file (ADR-103's overlap rule). The lane workflow is unchanged.
  - The 12 entries are inserted mid-file, a multiple of the 4 shards, so no other file changes shard and the tail does not conflict.
  - The heaviest three land in shard 2, the lightest (about 6 min in CI).
  - `MINIMUM_FILES` goes from 159 to 171.
- **Pin.** `Tests/CI/test_console_p0_regression_gate.py` lists each P0's gated targets. It fails, naming the P0, when:
  - a target leaves every lane;
  - a target runs in two lanes;
  - a `bootstrap_profile` target is outside the admission-sensitive step;
  - a node id names a test its file no longer defines.

  Before the lanes were wired, it failed for every new target.
