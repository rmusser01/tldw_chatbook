## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** A Library search stages 1 source: the strip reads 'Staged for next send · 1 source · Un-stage', the chip 'Sources: 1', Inspect 'Sources: 1 staged'. The next send consumes it. The reply cites [S1], the chip drops to 'Sources: 0', and Inspect says 'Sources: None staged'.

The strip, however:
- keeps saying 'Staged for next send · 1 source' after 20 s and after further sourceless sends;
- after Un-stage, which removes nothing because nothing is staged, turns into 'Evidence sent with this message · 1 source' and is never cleared;
- carries into a sourceless turn, a new Ctrl+T tab showing 'No messages yet.', and a newly entered workspace chat.

Inspect contradicts itself too: stale 'Sources — next send 1 · Ready' and 'Live work sources ... Status: staged' cards sit next to 'None staged'. The Run card's 'sources sent with the last message · 1 source' persists into empty new chats. The promise is also false going forward: the next send carries no source. For a researcher, 'which sources did this answer use' is the key trust question.

**Severity / prior art.** P1, confirmed by all three verifiers. This is a **REGRESSION of TASK-2370 (Done**: tray and inspector told two truths), **TASK-2372 (Done**: staged evidence and sent-notice across navigation) and **TASK-3170 (Done)**. TASK-2210 (To Do) is adjacent: it covers the concurrent-send double spend, not this.

Root-cause correction: the strip headings in `console_display_state.py` are correct. In commit b7dd8e53f2 the state moved into ConsoleRuntime, where staged evidence and its sent-notice are one app-wide value rather than one per session. The runtime's release path refreshes no view, and custodied sends never clear the notice.

**Suggested direction.** Key the staged launch and the sent-source receipt by session, and tie the receipt to the turn it belongs to. Notify the view after release. Clear the receipt when a new turn is admitted. Move the post-send claim onto the assistant turn as 'Sources (N)'. Reset the strip and the Inspect source cards on session, tab and workspace switch. Make Un-stage on a stale strip hide it.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G2-08 (source J4-04). Files: evidence/evidence__J4__56-rag-reply.txt, evidence/evidence__J4__57-unstaged.txt, evidence/evidence__J4__78-new-tab.txt, evidence/evidence__J4__89-ws-created.txt, evidence/evidence__J4__90-inspect-ws.txt.

**Changes (one commit per fix).**
- `ConsoleRuntime` keeps staged evidence and the sent-source receipt per chat session (`_staged_evidence` dict) under one app-wide revision fence, so one chat's revision never releases another's launch. Every send-time read takes its own session (wiring admission, received-intent checks, composer preparing check, voice, live seam, custody release).
- The runtime asks the attached view to redraw the staged-evidence surfaces (new runtime-routed `staged_evidence` view hook -> `_sync_console_pending_launch_surfaces`) after a release, a chat switch, or a reattach; on a switch or reattach only when some chat shows evidence (a boot-time redraw crashed the UI-ready census with MountError in the Inspect card swap, which now also returns while its viewport is mounting).

The reply carries a dim "Sources (N) · sent with this turn" line from a session-only `ConsoleChatMessage.evidence_source_count`, recorded by the controller at both acceptance points (durable postcommit `clear_staged_input` and the non-durable path) just before the evidence leases release; the count is the shared `console_sent_source_count` (repair-contract ordinals, else the prompted estimate).
- Admitting a turn clears its chat's receipt, so a sourceless send leaves no "sources sent" line in Inspect's Run card.
- Un-stage with nothing staged redraws every staged-evidence surface (not only the strip).
