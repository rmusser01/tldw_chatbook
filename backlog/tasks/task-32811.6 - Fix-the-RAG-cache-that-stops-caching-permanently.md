## Description

The asynchronous prune deletes expired entries without decrementing the memory counter, while every other removal path does. The counter therefore ratchets to the cap and the cache silently stops accepting writes. Reproduced: dead at prune cycle 42 with zero entries cached and the counter pinned at 1,022 KB of a 1,024 KB cap, with no recovery path -- so every search after that point is a cold search for the rest of the process.
