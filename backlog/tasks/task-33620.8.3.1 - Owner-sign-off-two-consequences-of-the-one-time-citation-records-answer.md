## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-33620.8.3 asks installs that still carry the old shipped `[rag_citations] canonical_writes_enabled = false` once whether to keep citation records (owner decision 2026-10-30). Its review found two consequences the owner has not explicitly accepted, and ADR-024's 2026-11-06 amendment records them as pending this sign-off:

1. A profile on the new default that is set to `false` in config.toml before it ever keeps a citation record is asked once. Without a config migration (rejected by the owner) it cannot be told apart from the old shipped `false`.
2. After a saved **Keep**, setting `canonical_writes_enabled = false` in config.toml no longer turns records off: the answer outranks that exact `false`. The recovery switch still works through the palette entry ("Console: Citation records…" then Don't keep) or any non-exact off value.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Owner decision 2026-11-12 (relayed for PR #3455): both consequences are accepted as designed.

1. Accepted: a profile on the new default that is set to `false` in config.toml before it ever keeps a citation record is asked once, like an older install.
2. Accepted: after a saved **Keep**, config.toml's exact `false` no longer turns records off; the way to turn them off is the palette entry ("Console: Citation records…" then **Don't keep**). The User Guide's Older installs paragraph (Docs/User_Guide/console/context-and-rag.md) says so.

ADR-024's 2026-11-06 amendment now records both consequences as accepted by the owner on 2026-11-12 instead of pending this sign-off.
