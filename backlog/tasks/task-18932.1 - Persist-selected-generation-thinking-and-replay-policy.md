## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Create the bounded thinking-envelope and conversation replay-policy foundation for Console Assistant generations. Persist the selected answer and its displayable or content-free proprietary evidence together, keep ADR-063 continuation separate, preserve unknown durable versions on unrelated writes, and carry the supported fields through local persistence, dispatch recovery, sync, conflicts, and versioned backend capability checks.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A bounded, versioned thinking-envelope parser accepts only ordered displayable or structurally text-free proprietary blocks, emits content-free diagnostics, and preserves unsupported durable versions opaquely while imports/incoming sync reject them.
- [x] #2 ChaChaNotes adds nullable `messages.thinking_blocks_json` and nullable `conversations.thinking_history_policy`; existing rows receive no synthesized evidence and missing policy resolves to Auto.
- [x] #3 Normal assistant creation, terminal update, stop/failure settlement, dispatch recovery, hydration, deletion, and generic unrelated content writes preserve or clear thinking exactly according to the approved generation-ownership rules.
- [x] #4 Every live Console variant and regeneration snapshot owns answer, thinking, usage, and separate continuation/provenance state; selecting or abandoning a variant cannot pair one attempt's answer with another attempt's thinking or continuation.
- [x] #5 The selected answer, terminal thinking envelope, and continuation projection update as one durable generation projection; sync payloads, hashes, conflict handling, and tombstones treat them as one whole-record owner without claiming a cross-database transaction.
- [x] #6 Conversation replay policy round-trips through conversation persistence and existing conversation synchronization surfaces, while the device-local display preference remains absent from those records.
- [x] #7 Persistent adapters advertise a versioned thinking round-trip capability; an opted-in thinking-capable persistent path without required support fails locally before any provider contact, while unaffected legacy/non-thinking and ephemeral paths retain compatibility.
- [x] #8 Genuine historical migration, envelope mutation/negative, variant, stopped/failed, preservation, sync-owner, conflict, and backend-capability tests pass without pinning a provisional final schema number.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Define and test the bounded displayable/proprietary thinking envelope and replay-policy normalizer.
2. Add nullable ChaChaNotes message/conversation fields with a genuine historical migration and atomic selected-generation persistence.
3. Extend Console message, live-variant, regeneration, dispatch, and hydration ownership so selected generations remain paired.
4. Carry the fields through Sync v2 and enforce versioned persistence capability before provider contact.
5. Run the targeted foundation suites and static checks, document exact evidence, and complete the task only after scoped and final review.
