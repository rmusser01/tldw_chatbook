## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Foundation for the phase. Today connection-test evidence cannot cross surfaces, for three reasons:
- Each surface owns a private store: the Chat settings modal (console_settings_modal.py:1304) and Settings (settings_screen.py:2949 and :13313-13318). Settings also copies its store into a cross-visit snapshot (:12854-12855, restored at :12950-12952), so every visit forks it.
- ProviderTestEvidenceStore is single-slot. It keeps one identity's evidence, clears it when another identity begins, and rejects older draft generations (provider_test_evidence.py:564-620, :996-1019).
- Each surface stamps its own counters into ProviderDraftIdentity: the modal uses _model_discovery_generation and its entry credential revision (console_settings_modal.py:5807-5814), and Settings uses _provider_draft_generation and _provider_credential_revision (settings_screen.py:13401-13436). So identical saved configuration never compares equal across surfaces.

The evidence record has no observation time (ProviderTestEvidence, provider_test_evidence.py:461), yet the readiness words need one.

ADR-033 permits a narrow process-memory owner but no new root application-state object. The TTS provider-test evidence store is the in-repo precedent: it is process-scoped and keyed by a fingerprint that includes the saved revision (ProcessProviderTestEvidenceStore and process_provider_test_evidence_store, settings_speech_tts.py:604 and :731-742).
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Shared connection evidence now lives in one process-memory owner per app; each surface keeps its own draft-scoped store in front of it.

Approach
- `Chat/provider_test_evidence.py`:
  - `ProviderConnectionEvidence` holds settled evidence per connection. The key is a `ProviderDraftIdentity` without its surface-local `draft_generation`: provider, custom endpoint id, canonical endpoint, credential source and credential revision.
  - Only terminal facts merge, one facet at a time (endpoint or generation). An older observation never overwrites a newer one.
  - Asking about another connection of the same provider returns the last record unchanged. Its identity no longer matches, so `ProviderReadiness.snapshot` and `build_console_settings_readiness` project it as changed since test and never reuse it (AC#4).
  - `provider_connection_evidence(app)` attaches the owner as one private attribute on the running app, mirroring the TTS `process_provider_test_evidence_store`. No root state object (ADR-033), and nothing is persisted.
  - `version` counts publications, for TASK-33005.2's idle-poll tuple.
- `ProviderTestEvidenceStore(app=...)` stays single-slot and draft-scoped (controller ruling 1).
  - Every successful `settle` / `settle_generation` / preserving `rebase_after_save` publishes the settled facet.
  - `evidence_for` falls back to the owner for an exact connection only, re-stamped with the asker's identity. It never does so for an identity `begin` would refuse, so TASK-33001.3's invariant holds.
  - Settings' no-argument `invalidate()` now clears only the Settings draft, never another surface's result.
- `ProviderTestEvidence.observed_at`: an aware local datetime, excluded from equality and appended last, so positional constructors keep their meaning. It is stamped at settlement. A rebound earlier observation passed as a `ProviderTestEvidence` keeps its own time; `settle_generation` now accepts that form too.
- `connection_credential_revision(key)`: a process-salted HMAC of the key a send would use (0 when none). Every surface now stamps it (ruling 2):
  - Chat settings: `ProviderReadiness.api_key`, or the entry's own credential. It was always 0.
  - Settings: `_provider_draft_credential_revision` gives the readiness key for an untouched credential, the typed key for a draft, and the named env var's value. This replaces the edit counter `_provider_credential_revision`, which was removed.
- Chat settings modal: constructor link, canonical revision, and the two rebinding sites pass the prior evidence so its observation time survives. The file went from 7,761 to 7,753 lines.
- Settings:
  - Linked store.
  - `_VllmDefaultPresentationSnapshot` no longer carries the store or the credential counter (ruling 3).
  - On a visit whose Test result is still "has not run", the Test rows and the Overview headline adopt the saved connection's shared result (AC#6).
- Docs: `Docs/User_Guide/settings.md` Test Provider paragraph says the last result is kept for the session, across surfaces, and is not saved.

- New UI tests:
  - Settings to Chat settings, for the same connection.
  - Chat settings publishing to the owner.
  - The modal's and Settings' canonical revisions.
  - Returning to Settings, with the Overview headline.
  - The snapshot field list.
- Rewritten on purpose:
  - `Tests/Chat/test_provider_test_evidence.py::test_extended_records_remain_frozen_and_slotted` and `Tests/Chat/test_provider_readiness.py::test_evidence_records_are_frozen_slotted_and_secret_free`: the field list gains `observed_at`.
  - `Tests/UI/test_console_provider_apply_defaults_flow.py::test_vllm_default_late_ack_failure_restores_complete_provider_presentation`: the restore keeps the live store and the shared result instead of swapping in a private copy.
  - `Tests/UI/test_settings_provider_switch_atomic.py::test_provider_save_writer_exception_fails_closed_and_settles_lease`: a failed save still clears the Settings draft store and its lease. The shared observation of the unchanged draft connection now survives, because identical values are the same connection (AC#1).
- No test pinned cross-provider eviction by the single slot: the draft stores keep that behavior, and the shared owner is per connection.

Deviations and rulings
- Ruling: every surface publishes all settled evidence keyed by its exact values, rather than only identities that equal the saved connection. Why: identity equality already confines a draft's result to identical values (AC#1/AC#3), and checking "saved" in the modal would have meant re-resolving the session endpoint there. Cost if wrong: an untested saved connection can read "changed since test" after a draft of another endpoint or key was tested.
- Ruling: Settings' edit counter `_provider_credential_revision` was retired, not kept in the snapshot. Why: the canonical revision is computed, not counted, so nothing remains to restore. Cost if wrong: none observed; the late-handoff restore keeps `provider_draft_generation`.
- Left for TASK-33005.2: Chat settings stamps a sentinel endpoint (`https://provider-default.invalid`) for providers without a base-URL field, and Settings has no identity when its Endpoint field is empty. The Console must use the same rule for cloud providers, or align both.
