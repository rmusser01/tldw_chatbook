## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Fix generated-video identity persistence so the directory key used to store bytes is the same ID persisted for the owning Console message. Live UAT observed different IDs, leaving TTL-retained bytes present but unresolvable after restart.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The persisted video message ID matches the VideoStore directory key used for its bytes.
- [ ] #2 Ready cards, Play, and Save copy resolve stored video from the durable message record while native message IDs continue to address Console actions.
- [ ] #3 TTL-retained generated cards remain ready after app restart.
- [ ] #4 Focused automated tests cover identity persistence and TTL restart resolution.
<!-- AC:END -->

## Implementation Plan

1. Follow the existing ADR-044 stable-message-ID persistence seam for video messages.
2. Resolve generated-video files by durable message ID with a native-ID fallback for non-persisted live messages.
3. Add focused RED/GREEN coverage for persistence identity, real-DB TTL restart resolution, card/action resolution, and explicit-ID conflict behavior.
4. Mutation-check the persistence and durable-resolution guards, then run only the affected test and static-analysis scopes.
