## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Twenty-one private boolean coercers re-roll a public helper that has 24 importers, and they disagree about the integer 1 -- SQLite's boolean -- which is true in five of eight measured copies and the caller's fallback in two. The canonical copy has the strangest vocabulary (it rejects 'on') and returns `None` rather than the default for a `None` input, despite annotating a boolean return; one caller already carries a hand-written workaround comment saying exactly that.

Source: core-runtime code review 2026-09-17 — `qa/core-code-review-2026-09-17/report.md`; per-slice evidence in `qa/core-code-review-2026-09-17/slices/`, reproductions in `qa/core-code-review-2026-09-17/phase4-verification.md`.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
PR #2745, all ACs done.

AC#1 (None → default): `coerce_bool_setting(None, default)` now returns `default`
(was `None`, violating its `-> bool`); the `change_review_screen` hand-written
workaround was removed; tested.

AC#2-4 (owner decision 2026-09-20, "consolidate non-security sites only"):
investigation found the ~21 "private coercers" are NOT one vocabulary. Two
`coerce_bool_setting` tests deliberately pin its narrow fail-closed vocabulary
(no "on"; unrecognized → False) as intentional for config/security gates — the
git-actions kill switch (`test_git_actions_enabled_coerces_a_string_true`) and
the metrics bind gate (`test_unrecognised_enabled_value_fails_closed`). Merging
everything to one vocabulary would flip behaviour at those security boundaries,
which the owner declined.

So the consolidation is scoped to the THREE standalone duplicate functions that
had each copied the SAME wide vocabulary verbatim
(`{true,1,yes,on}`/`{false,0,no,off}`, unrecognized → default):
`Utils/console_background_effects._coerce_bool`,
`Image_Generation/config._coerce_bool`, `Chat/character_expression_playback._bool`.
Extracted one shared `Utils.Utils.coerce_bool_flag(value, default)`, adopted it
at all three, removed the three copies. `_bool` gained `.strip()` (a harmless
correctness fix; the other two already had it). The integer 1 is unambiguously
true in both `coerce_bool_flag` and `coerce_bool_setting` (AC#3). The result is
TWO documented, intentionally-distinct vocabularies (wide feature-flag vs narrow
gate), each with the correct fail direction for its use — recorded in both
helpers' docstrings and pinned by `Tests/Utils/test_coerce_bool_flag.py`
(which asserts "on" → True in the flag helper and False in the gate helper).

Left as-is by the decision: the security-gate readers (egress, tls_trust,
metrics, git-actions) and the scattered INLINE ad-hoc `lower() in {...}`
coercions whose semantics diverge (allowlist-true/default-false vs
blocklist-false/default-true) — those are not verbatim copies of a helper and
consolidating them would change unknown-value behaviour per site.

Modified: `tldw_chatbook/Utils/Utils.py`,
`tldw_chatbook/Utils/console_background_effects.py`,
`tldw_chatbook/Image_Generation/config.py`,
`tldw_chatbook/Chat/character_expression_playback.py`,
`Tests/Utils/test_coerce_bool_flag.py`.
