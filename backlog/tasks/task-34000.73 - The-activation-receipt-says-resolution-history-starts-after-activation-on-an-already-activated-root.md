## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: the receipt that follows "Activate reviewed root" reads "Sync root activated. 3 applied · listed under Receipts" and, directly beneath, "Resolution history unavailable — it starts after this root is activated", with the bar's "○ Resolution history" disabled for the same reason. The root HAS just been activated -- the sentence contradicts the heading above it. The copy comes from the receipt bar's `history_reachable = review.source in {"root", "migration"}` gate and its disabled-reason tooltip: a setup activation leaves `review.source == "setup"`, so the receipt treats the root as not yet activated even though the activation it is reporting succeeded.

Seen on both live captures of TASK-34000.17 (160x45 and 100x30) and on the review's j3 captures 59-60. Either the receipt should offer Resolution history for the root it just activated (the root id is known: `_root_id()` resolves it), or the reason line should say what is actually true -- there is no resolution history yet because nothing has been resolved -- and the disabled control should say that too.
