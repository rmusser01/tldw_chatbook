## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
At common big-terminal sizes the note editor loses its explicit Save button and its main hand-off, "Use in Console". The User Guide's Save and Use in Console rows (`Docs/User_Guide/library/notes.md`) say both "remain visible" beside the mode controls. The live app breaks that promise for every persona:
- A first-timer told to press Save cannot find it (j1's task 9 failed).
- A keyboard-only user Tabs onto a Save that is not drawn anywhere; only the footer says "enter save note".
- The researcher clicked a clipped "Use in" and landed in Console without knowing why.

Observed:
- **120x36:** the header row shows only "Edit  Preview  Info". There is no Save and no Use in Console (`verify/nl-v-n-05/01-120x36-note-open.txt`).
- **160x45:** the row ends "Save         Use in", cut off at the pane edge.
- **200x50 with Nav open:** the row ends "Use in C".
- **New note:** "Discard new note" is off-screen.
- **Save state:** `#library-note-status` is squeezed into a strip one column wide. It paints "S" for Saved, or "U" above "c" for "Unsaved changes".
- **119x36:** the compact header fits everything. Save is boxed and "Use in Console" is whole (`09-119x36.txt`). So 120 columns is the worst width, and making the terminal one column wider removes controls.

Verified cause (origin/dev 2d34cbf80d):
- The save state, the mode controls and the task actions share one Horizontal, `#library-note-header-second-row` (`Widgets/Library/library_notes_canvas.py:2819-2870`).
- `#library-note-task-actions` has `min-width: $ds-library-note-task-actions-min-width`, which is 61 (`css/features/_library.tcss:951-953`, `css/core/_variables.tcss:145`). TASK-32623 added it so that toggling Discard does not move the mode controls.
- That minimum is lifted only when the shell is in its compact layout, below 120 columns. From 120 columns up it applies, even though the editor pane is only about 50 columns wide at 120 and about 86 at 160.
- F6's work-pane targets list `library-note-save` first (`UI/Screens/library_screen.py:1486-1494`), so F6 lands on the hidden Save.

Suggested direction (a direction, not a mandate):
- Pick the header's shape from the editor pane's own measured width, not from the shell's 120-column breakpoint.
- Do not reuse `_effective_pane_width()` (`library_notes_canvas.py:1347`). Verification found that it measures the list pane, not the editor. TASK-32811.4 (In Progress) owns that same defect for the location row.
- Below roughly 70 pane columns, use two rows: [Edit · Preview · Info] and [Save · Use in Console · Discard new note].
- Replace the 61-cell minimum with geometry that still keeps the mode controls from moving when Discard toggles.
- Never truncate "Use in Console".
- Make F6 skip any target that has no visible region.

Ownership:
- TASK-32513 (move the save state onto the chrome strip) and TASK-32514 (word the save state one way) own where the save state lives and how it is worded.
- This task owns the header's layout: which controls are visible, where Tab and F6 land, and the minimum width. On the save state it only requires that, while the state still sits in this row, it is not squeezed to one column.
- F6 pressed inside the body TextArea (which selects the line) is a separate review finding, N-32, and is out of scope here.

Review finding(s): N-05. Source: qa/notes-library-ux-review-2026-10-02/report.md

**What changed.** The editor header is shaped from the EDITOR pane's resolved width, not the shell's 120-column breakpoint, and it no longer pays for widths its labels do not need.

- `css/features/_library_panels.tcss`: the task-32127 content-sizing rule (`width: auto; min-width: 0`) now also covers `#library-note-work-pane .library-canvas-action`, so the six header Buttons drop Textual's 16-cell minimum (measured: `label + 4` each -- padding 0 1 plus `line-pad: 1`). Bundle regenerated.
- `css/features/_library.tcss` + `core/_variables.tcss`: the TASK-32623 `min-width: 61` reservation and `$ds-library-note-task-actions-min-width` are gone. The guarantee is kept by construction: Discard new note is hidden with `visible` (cells reserved), never `display`, so `#library-note-task-actions` is always its Discard-shown width. Textual 8.2.8 leaves an invisible node out of `focus_chain` and `get_widget_at`, so it is neither Tab-reachable nor clickable (pinned).
- `Widgets/Library/library_notes_canvas.py`: `_header_shape(work_width, compact)` beside `_toolbar_shape`, stacked when `0 < work_width < _HEADER_ONE_ROW_MIN_WIDTH` -- a constant DERIVED from the label tuples (`_HEADER_MODE_LABELS`, `_HEADER_TASK_LABELS`, which `compose` now reads), the measured button chrome, the toolbar gutters and the save state's 12-cell floor: 100. `apply_work_width` records the shell's `reader_width` (`_work_width`; the pane's own measured width is the fallback) and re-applies `apply_compact_presentation` IN PLACE when the answer flips -- no recompose, widget identity kept (pinned by the round-trip test). The stacked shape: the save state on its own full-width row (`h-1`, nowrap/ellipsis), then [Edit · Preview · Info], then [Save · Use in Console · Discard] -- three rows, the same height as the one-row strip.
