## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the 2026-11-28 re-triage of TASK-34100.4.1 (its survey, against dev 2df861ec7d). It is filed separately because it is an inbound credential, not an outbound one, so it is outside TASK-34100.4.1's ACs.

TASK-34100.4 made `enc:` ciphertext read as absent wherever a credential is resolved. The served web surface's admission credential does not follow that rule. `Canvas/web_auth.py`'s `resolve_web_access_token` (:165) returns the configured value as the credential whenever it is a non-empty string (:182-184), without a ciphertext screen. `access_token` matches `is_sensitive_config_key`, so enabling encryption encrypts it. The value reaches it from `Web_Server/serve.py:2369-2373` (`[web_server] access_token`) and from the remote-access policy, `Canvas/config_policy.py:203-206`.

So in the two cases TASK-34100.4.1 describes (encryption off with `enc:` values left behind, or a session that never ran the startup unlock), the ciphertext string becomes the token. A client is admitted only by presenting that string, and the remote-access policy counts a credential as configured.

Read, not reproduced live.
