## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Quick setup carries two steps most people do not need [coverage-16]. Voice preselects a local PocketTTS server most newcomers don't run, and Protect is empty for every keyless, local and environment-key user, while for cloud users it is where the password lock-out happened. Welcome still sells Quick as "provider, model, voice, protection".

The approved spec makes Quick four steps: Welcome, Connect, Model, Ready (decision D1). Voice moves to Full and becomes Ready's "Hear replies aloud…"; Protect becomes Ready's "Encrypt saved keys with a password…", shown when this run stored a plain-text key, which is the default for a typed key. This supersedes TASK-21148 AC#5's mechanism (Protect always on Quick) and keeps its guarantee as rule S1: once the user leaves Welcome, the step count never changes. Drafts saved by the old six-step Quick must resume rather than be silently dropped. It builds on the extracted steps (TASK-34100.1), the encryption lifecycle (TASK-34100.4), the honest Voice step (TASK-34100.8), the outcome record (TASK-34100.9), the setup core (TASK-34100.20) and the Ready screen (TASK-34100.23).

Spec: Docs/superpowers/specs/2026-10-03-first-run-setup-shape-design.md (revision 3, approved by the owner on 2026-10-03; ADR-217): D1, rule S1, §4.1, §4.4, §6, §10 F5.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Quick is Welcome, Connect, Model, Ready for every input (a key typed or cleared, an environment key, a local engine), and the tracker shows 'Step 1 of 4' before Next. An unknown track fails closed instead of falling back to Full
- [ ] #2 Once the user leaves Welcome, the step list never changes until they return to it, on both tracks. The SetupSession state-machine property covers encryption being enabled, both tracks and resume from a draft
- [ ] #3 Voice is no longer on Quick. When no voice is configured, Ready offers 'Hear replies aloud…', which opens a place that can set up a voice, registered in the exit-route table
- [ ] #4 Protect is no longer on Quick. Ready offers 'Encrypt saved keys with a password…' only when this run stored a provider key as plain text in config.toml, and it opens TASK-34100.4's password dialog in place. Keyless, local and environment-key runs never see an empty protection step
- [ ] #5 Welcome reads: 'Quick setup — connect AI and pick a model (recommended)' and 'Full setup — adds search, tools, voice, appearance, server', with the time line 'Quick takes about 2 minutes if you have an API key or a local AI server running. You can change any of this later by running setup again.' The Reduce motion row sits above Restore a backup
- [ ] #6 A version-1 draft saved at Voice or Protect on the old Quick resumes at Ready, and an old Full draft resumes at the first step of the new order not yet done. Choices that no longer have a step are named in the resume dialog. Nothing is written at boot: the migrated draft is saved as version 2 at the next normal checkpoint. The finish path records [first_run] last_track
- [ ] #7 The tests and User Guide passages that pinned six Quick steps (including the two PocketTTS integration tests, which move to Full) are rewritten to the new shape and RED-verified, not deleted
- [ ] #8 'About 2 minutes' holds: following the recommendations, a person reaches Ready ✓ in two minutes or less hands-on, once with a pasted key and once with a running local server, or the Welcome copy changes before release
