## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: import is the first thing a first-timer (Jordan) and a researcher (Priya) do, and what it produces decides whether the Library is worth using. Today every paper is filed under its filename. Web pages carry their site navigation into search answers. A mistaken 60-file import cannot be stopped. The first import quietly downloads a model from the internet and paints a log warning over the nav bar. The last of these undercuts the local-first promise (PRODUCT.md principles 2 and 8). Each has a workaround, hence P2. Causes are at origin/dev 2d34cbf80d.

L-20, imports are titled by filename stem. With Title left blank, the imported rows are 'paper-retrieval-practice' (pdf, author 'Unknown') and 'web-page-spaced-repetition' (html). The third is 'article-local-first', a Markdown file stored as plaintext whose first lines are '# The case for local-first software' and '*By A. Author, 2026*'. The PDF's metadata title is 'Retrieval practice improves long-term retention', with an author. Verified cause: when Title is blank, the title is set to the filename stem before any processor runs (Local_Ingestion/local_file_ingestion.py:1066-1067). The HTML branch's own <title> extraction is guarded by 'only if no title yet' (:1626-1628), so it can never run, and processor metadata is read only as a fallback to that pre-filled value (:1668-1670). Suggested direction: leave the title unset until the processor returns. Then prefer PDF Title/Author metadata, HTML <title>, og:title or the first h1, and Markdown front matter or the first H1, with the filename stem last. A user-entered Title or Author always wins.

L-21, local HTML import keeps site navigation, duplicates the heading and flattens tables. The imported 'web-page-spaced-repetition.html' shows 'Spaced repetition, explained' twice. Its table becomes one cell per line ('Interval / Days / 1 / 1 / 2 / 3'), and it ends with 'Site navigation that should be stripped'. That boilerplate then appears in RAG snippets and in exports. Verified cause: the local HTML branch (Local_Ingestion/local_file_ingestion.py:1607-1641) takes the whole document's text with BeautifulSoup, one element per line. URL imports instead go through trafilatura article extraction (Local_Ingestion/web_article_ingestion.py:145, which currently drops tables). Suggested direction: one shared extraction for local and URL HTML (trafilatura, tables kept, Markdown output). The BeautifulSoup fallback strips head, nav, header, footer and aside, and joins table cells with ' | '. trafilatura is optional, so check it through optional_deps.

L-30, a batch import has no cancel, and Enter imports while the footer says 'check this path'. Library > Import… > a folder of 60 .md files > Enter started the import while the footer chip read 'enter check this path'. The queue then showed 'bulk60 — 60 files · active · 3 parsing · 1 writing · 54 queued · 2 done' with no Cancel, and leaving with Esc let it run to 60/60. Verified cause: Cancel is offered only for an active local speech-to-text job (Library/library_ingest_state.py:2209-2221 and :2244-2250; Widgets/Library/library_ingest_canvas.py:924). Suggested direction: resync the footer on every path keystroke. The first Enter checks the path and shows the forecast, and the second imports. Add 'Cancel remaining (N)' to local batch rows, marking queued jobs cancelled and keeping finished ones. Finding L-05 ('~/' paths rejected, a fast Enter importing anyway) is owned by TASK-34000.20 and not in scope here.

L-33, the first import downloads an embedding model without saying so, and a Hugging Face warning is painted over the nav bar. On a fresh profile with an empty Hugging Face cache, the nav row was overwritten by '2026-10-03 00:32:39 [WARNING ] huggingface_hub.utils._http:904 - Warning: You are sending unauthenticated requests to the HF Hub. Please set a HF_TOKEN…'. The log shows the model load taking about 15.7 s, and nothing in the UI mentioned a download. It was raised from P3 because this is undisclosed network egress in a local-first product. Cause, as traced by the verifier: when Textual's output capture has no real file descriptor, protect_file_descriptors (Utils/fd_protection.py:63, fallback at :151) rebinds stdout/stderr to the raw terminal descriptors 1 and 2. Third-party writes then land on top of the TUI. Suggested direction: in that case bind to a descriptor-backed null device instead. Stop the logging bridge from echoing to stderr once the app is mounted. Show 'Preparing search index — one-time model download' on the import queue row while it happens.

Review finding(s): L-20, L-21, L-30, L-33. Source: qa/notes-library-ux-review-2026-10-02/report.md
