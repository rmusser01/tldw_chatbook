## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-33620.1's review saw Tests/Performance/test_ui_ready_module_census.py read 1032 against MAX_TLDW_MODULES_AT_UI_READY 1031 once, when run in the same pytest invocation as the architecture ratchets; it passed twice when run alone. The extra module was not one TASK-33620.1 added (emergency_stop_hold loads after first paint), so the census appears to sit exactly at its limit with one timing-dependent module. A PR that adds nothing can go red. Per ADR-097 the limit is never raised: the fix is to find the timing-dependent module and keep it out of the ui-ready window deterministically (TASK-31700, now Done, paid down the previous breach).
