## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Restore expressive user and assistant speaker coloring in Console without regressing theme contrast, while letting users choose neutral, role-accent, or fuller roleplay presentation.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Appearance settings offer Neutral, Role accents, and Immersive RP transcript styles, with Role accents as the default.
- [x] #2 Role accents visibly distinguish user and assistant or character speakers in generic and character-bound Console sessions through semantic theme-derived label and row treatments.
- [x] #3 Immersive RP additionally colors prose while preserving readable Markdown, code, links, tool, system, failed, streaming, and selected states.
- [x] #4 Saving the setting persists it and refreshes mounted Console transcripts without restarting the app.
- [x] #5 Compositor-painted tests prove speaker and prose contrast of at least 4.5:1 in supported dark and light themes, plus operational-state precedence.
- [x] #6 Configuration, Settings, transcript, generated CSS, and user documentation remain synchronized and focused verification passes.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Amend the existing roleplay display ADR to make transcript styling an explicit Appearance preference with semantic, theme-derived colors.
2. Extend Appearance defaults, validation, persistence, preview/reset/save, and mounted-screen refresh with a closed transcript-style vocabulary.
3. Thread the effective style through Console presentation context and render semantic user, assistant, and character classes in both plain and Markdown rows.
4. Add restrained row tints and accessible speaker accents for Role accents; add opt-in prose accents for Immersive RP while preserving operational-state precedence.
5. Regenerate the CSS bundle, update documentation, and verify settings persistence plus real compositor colors across dark and light themes.
