## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Two exact-pin AST ratchets were appended to `Tests/Architecture/test_screen_size_ratchet.py`, the file that already pins `LibraryScreen`'s lines and methods. No product code changed.

**Pins, measured at dev 26b2e677dd** (the roadmap's progress-measure source for the lambda count):
- `_LIBRARY_INIT_LAMBDAS = 416`: every `ast.Lambda` in `LibraryScreen.__init__`. All 416 are keyword arguments to controller or note-session constructors. The review's 413 at 7a5e2513c5 counted controllers only and left out 3 (`_LibraryDatabaseNoteSessionPort` 2, `DatabaseNoteSessionCoordinator` 1). This definition also gives 416 at 7a5e2513c5.
- `_LIBRARY_UNBOUND_TEST_CALLS = 594`, in 57 files: calls on the class under `Tests/**/*.py`. The count covers:
  - `LibraryScreen.m(...)` (580);
  - `mod.LibraryScreen.m(...)` (7);
  - `getattr(LibraryScreen, name)(...)` (2);
  - the same shapes inside string constants that parse as Python, which are subprocess child programs (5);
  - calls through an import alias (0 at base).

  Public handlers are counted. The review's 370 named private `_x(fake_self, ...)` calls only.

The counts were cross-checked with an over-inclusive `grep 'LibraryScreen\.\w+\('`, which found 597 hits. The only hits the AST does not count are docstring or comment prose and an f-string message.

Not counted, a known limit: method bindings that are never called in place, such as `MethodType(LibraryScreen.x, fake)`, `partial(...)` and `.__get__` (4 at base). A class kept in a variable is not followed either.

**Enforcement:** the house style of the TASK-36942.4 census. A count above its pin fails with "Do NOT raise". A count below its pin fails with "Lower <PIN> to N". Either pin can therefore only move down, in the same change. `test_unbound_class_call_counter_sees_each_shape` pins each counted and uncounted shape.

**CI lane:** checked, and `Tests/Architecture` does not run as a directory in any lane. Each guard file is listed by name. `test_screen_size_ratchet.py` runs whole-file in `derived-artifacts.yml` pr-fast-lane, so the new tests gate with no workflow or census edit. The scan adds about 3-5 s to that file.

**Red/green evidence** (run.sh, `-q`):
- Lambda pin: one temporary `self._ratchet_probe = lambda: None` at the end of `__init__` failed with `417 lambdas in LibraryScreen.__init__ (pinned 416, +1)`. Green after revert.
- Unbound-call pin: one temporary `LibraryScreen._end_library_structural_wait(object(), "owner")` in `Tests/UI/test_library_crit8_wait_riders.py` failed with `595 ... (pinned 594, +1)`. Green after revert.
- AC #3: temporary pins of 417 and 595 failed with `Lower _LIBRARY_INIT_LAMBDAS to 416` and `Lower _LIBRARY_UNBOUND_TEST_CALLS to 594`.
- Counter shapes: mutating the `getattr` branch and the string-program branch failed the two matching shape cases and the pin, which measured 587. Restored.
- Final: the screen-ratchet file passes 13/13, and preflight passes.
- `Tests/Architecture`, run serially, with load at 60-100:
  - The two runs together passed 1,332 of 1,365 tests. The only failures named in dev's own list (`arch-base-p4.txt`) are the two `test_timer_path_static_update_inventory` nodes and `test_reviewed_diagnostic_changes_are_metadata_only`.
  - The exception is `test_persistent_diagnostic_inventory.py`, whose inventory-building tests hit the 300 s pytest timeout under this load. The run was stopped there, with 20 of its 81 tests not run.
  - That file scans only `tldw_chatbook/` (`Tests/**` is excluded), so this change cannot affect it, and preflight's run of the same inventory check passed.
