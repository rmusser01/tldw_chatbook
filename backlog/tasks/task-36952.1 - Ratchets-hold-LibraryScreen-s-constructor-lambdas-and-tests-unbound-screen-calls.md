## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Two exact-pin AST ratchets were appended to `Tests/Architecture/test_screen_size_ratchet.py`, the file that already pins `LibraryScreen`'s lines and methods. No product code changed.

**Pins, measured at dev 26b2e677dd** (the roadmap's progress-measure source for the lambda count):
- `_LIBRARY_INIT_LAMBDAS = 416`: every `ast.Lambda` in `LibraryScreen.__init__`. All 416 are keyword arguments to controller or note-session constructors. The review's 413 at 7a5e2513c5 counted controllers only and left out 3 (`_LibraryDatabaseNoteSessionPort` 2, `DatabaseNoteSessionCoordinator` 1). This definition also gives 416 at 7a5e2513c5.
- `_LIBRARY_UNBOUND_TEST_CALLS = 724`, in 59 files: unbound uses of `LibraryScreen` methods under `Tests/**/*.py`. A method reference is `LibraryScreen.m`, `mod.LibraryScreen.m`, an import alias's `m`, or `getattr(LibraryScreen, name)`. The count covers:
  - **594 calls of a method reference** (`LibraryScreen.m(...)` 580, `mod.LibraryScreen.m(...)` 7, `getattr(...)(...)` 2, and 5 in subprocess child-program strings).
    - Public handlers are counted. The review's 370 named private `_x(fake_self, ...)` calls only.
    - 60 of them call `@staticmethod`/`@classmethod` helpers (no fake self), and 3 are `LibraryScreen.__new__(LibraryScreen)` constructions. Every one still reaches the screen class from a test instead of the code's owner, so read the pin as "test sites coupled to LibraryScreen". A static helper lowers it by moving to its owner.
  - **112 bindings of a method reference to a fake** (fix round 1, coordinator ruling on review I1):
    - 110 `MethodType(...)` (bare or `types.`; 10 of them through `getattr`);
    - 1 `partial(...)`;
    - 1 `.__get__(...)`.
  - **18 more, added in fix round 2 (re-review N1):**
    - 8 `LibraryScreen.m.__wrapped__(fake, ...)` calls, which run a decorated method's undecorated function. They are in 5 files: `Tests/Library/test_library_export_execution.py`, `Tests/UI/test_library_ingest_canvas.py`, `test_library_ingest_readiness.py` (3), `test_library_screen.py` (2) and `test_parakeet_v2_install_ui.py`.
    - 10 class-body bindings, `class Fake: m = LibraryScreen.m`. One is in `test_library_prompts_canvas.py` and nine are in `test_library_resize_focus_gates_t23025.py`.
  - Calls through an import alias: 0 at base.

The counts were cross-checked with an over-inclusive `grep 'LibraryScreen\.\w+\('`, which found 597 hits. The only hits the AST does not count are docstring or comment prose and an f-string message.

Not counted, a known limit (re-review N2):
- 18 method references handed to something that calls them later with the fake. These are 16 `_press(fake, LibraryScreen.handle_library_media_analyze_*)` in `Tests/UI/test_library_multiselect_media.py` and 2 `asyncio.to_thread(LibraryScreen._run_library_export_via_service, ...)` in `Tests/UI/test_library_prompts_canvas.py`. Counting every reference passed as an argument would also count introspection such as `inspect.getsource` and `signature`.
- A class kept in a variable (`LS = LibraryScreen`, a fixture, `type(screen)`), with 0 call sites at base.
- References only saved or inspected, such as `original = LibraryScreen.x` outside a class body. The first round documented the bindings as "4 at base" from a one-line grep; 98 of the 110 `MethodType` sites span two lines, and the AST count is 112.

**Lambda pin caveat** (pin comment): moving controller construction out of `__init__` into a builder lowers the count without decoupling (ChatScreen's wave 4 did this), so such a PR must point `_library_init_lambdas` at the builder in the same change. A missing class or `__init__` now fails with a message naming the stale pin.

**Enforcement:** the house style of the TASK-36942.4 census. A count above its pin fails with "Do NOT raise". A count below its pin fails with "Lower <PIN> to N". Either pin can therefore only move down, in the same change. `test_unbound_class_call_counter_sees_each_shape` pins each counted and uncounted shape.

**CI lane:** checked, and `Tests/Architecture` does not run as a directory in any lane. Each guard file is listed by name. `test_screen_size_ratchet.py` runs whole-file in `derived-artifacts.yml` pr-fast-lane, so the new tests gate with no workflow or census edit. The scan adds about 3-5 s to that file.
