## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Network renders, saves, reports unsaved state, reverts, labels and scopes itself through a registered panel; for a registered category every per-category answer the screen gives comes from the panel, and the screen has no Network arm left.

**Panel contract (TASK-1378.2 builds on this).** `UI/Settings_Modules/category_panels.py`:
- `SettingsCategoryPanel` Protocol, the roadmap's six members: `render(screen) -> ComposeResult`, `has_unsaved_changes(screen) -> bool`, `request_save(screen) -> None`, `revert(screen) -> None` (performs the screen's `r`, including any confirmation the panel needs; Network calls `screen._confirm_category_revert(category, discard)`), `scope_text(screen) -> ScopeText`, and `commit_model: CommitModel`.
- `ScopeText(banner, guided)`: one value for both surfaces; the State banner reads `.banner`, `_guided_action_message` (the guided row and `s` guidance) reads `.guided`.
- `CommitModel(kind, badge)` with derived `saves` / `reverts` (staged and raw_toml: yes; instant: no, ADR-303). The screen's save/revert capability (footer, F1, guided buttons) and the `s`/`r` actions read these, never `revert()`'s result.
- `CATEGORY_PANELS: dict[SettingsCategoryId, SettingsCategoryPanel]`.
- Screen seams panels use: `_category_panel_states` (per-category staged edits, shaped by the panel; `save_state`/`restore_state` keep them, so leaving Settings keeps the edit and the quit walk's "Network" stays true), `_settings_config_adapter()` (resolves `SettingsConfigAdapter` in settings_screen's namespace at call time, so the 38 `settings_screen.SettingsConfigAdapter` patches reach panel saves), `_confirm_category_revert`, `_update_draft_status_widgets`, `_app_config_mapping`, `_app_config_update_target`.

**Screen routing.** `_category_has_unsaved_changes` (rail `*`, banner count, quit guard), `_category_action_supported` save/revert, `action_settings_save_category`, `action_settings_revert_category`, `_render_detail_pane`, `_persistence_badge`, `_guided_action_message` and `_category_state_scope_text` all ask the panel first. The banner's "revert with r" now follows revert capability (same answer for every unregistered category).

**Network behaviour (deliberate change, ADR-303 staged).** An edit is now unsaved: compared by value (the Select and Input echo their seeded values on mount, which is no edit), so it marks the rail `*`, counts "1 unsaved · revert with r" on the banner, and the quit prompt names Network. `r` discards it after the shared confirmation and repaints the loaded values. The banner scope reads "Trust applies to new connections; open ones keep theirs." instead of the generic "Review readiness across Settings categories.". Its Select/Input handlers live on the `_NetworkCard` widget the panel renders. User Guide: Network's "Pending — save with s" row added to the badge table in `Docs/User_Guide/settings.md`.

**Fix round 2 (p3-settings-registry-rev2.md).**
- N1: an `ssl_verify` the loader reads as "invalid" (a configured CA file since moved, or a value of no known form) seeds the Select with "verify"; its mount `Changed` echo was staged, so opening Network showed a `*` that `r` re-raised on every rebuild, every quit asked, and Recovery's probe blocked maintenance. `_NetworkCard` now skips only each control's first `Changed`, and only when it equals the value the card seeded (Select and CA Input alike); the seed goes with that first `Changed`, so every later one is staged. This also ends the stale staged echo shadowing a `[network]` change made elsewhere in the session. `test_network_with_an_unreadable_ssl_verify_opens_clean_and_r_keeps_it_clean[moved-ca-file|not-a-mode]`: open is clean (no `*`, quit guard and kept Recovery probe silent), a Select choice is staged, `r` clears it and the rebuilt pane stays clean.
