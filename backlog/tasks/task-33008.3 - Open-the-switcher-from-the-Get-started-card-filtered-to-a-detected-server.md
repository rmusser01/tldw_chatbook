## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
'Use detected <provider>' calls _apply_detected_local_server (chat_screen.py:15397-15479). That adopts server.model_ids[0] without showing the choice, persists it and the endpoint as chat_defaults, and applies it to the chat. On a server with several models, the user never sees which one was picked. This path always persists the pair as the new-chat default today, which is right for first run and must now be said before Enter.

The card's 'Choose provider' and 'Choose model' actions open the full Chat settings modal: their recovery targets are 'console' in Widgets/Console/console_settings_summary.py:58-96, handled at chat_screen.py:20536-20541. After phase 4, though, a model is chosen as a provider·model pair in the switcher.

On first run there is no working new-chat default yet. A pick from the card that applied only to this chat would leave the next Ctrl+T chat blocked again.

task-16476 behaviour must survive: an endpoint that is already configured differently is kept, and the detected one is used for this session only (chat_screen.py:15424-15443).

Tests/UI/test_console_local_server_discovery_card.py:198 (test_pressing_detected_server_saves_config_and_unlocks_card) pins today's one-press adoption.

**Rulings**
- **One opener.** Alt+M and the card share `_open_switcher`. Why: they differ only in scope, default and adoption. Cost if wrong: split it into two functions.
- **The writer takes the committed settings.** Today's writer rebuilt defaults, which dropped the chat's system prompt and any value edited in the switcher. Cost if wrong: one line to rebuild from defaults.
- **The writer starts no `console-sync` worker.** The switcher's committed result starts one right after, and two exclusive starts in one group left a coroutine that was never awaited. Cost if wrong: one line.
- **A pair that cannot send is refused when the pick would set the default,** with Ctrl+N's "Unavailable: …" message. Why: otherwise a typed id on a provider with no key becomes every new chat's default. Cost if wrong: three lines.
- **In the detected server's switcher, a pick from another provider also becomes the default.** Why: the scope line is fixed when the switcher opens and has already said so. Cost if wrong: the scope line would have to follow the highlight.
- **Ctrl+N and Save as model default on the detected provider's pair adopt the server too.** Why: Ctrl+N alone would save a default without its endpoint. Cost if wrong: restrict adoption to Enter.
- **Card picks are not recorded as PREVIOUS.** Why: the pair the card replaces never worked, and Alt+M, Enter would swap back to it. Cost if wrong: one line.
- *(Superseded in fix round 1: the server's first model is highlighted.)* **First highlight follows the switcher's own rule.** On a first run the top row is the server's first model. If this chat's own pair is already on the detected provider, its current model stays first (ADR-020). Why: changing that needs a new popover argument. Cost if wrong: one Down in that case.
- *(Superseded in fix round 1: Choose model opens on the chat's provider.)* **Choose provider and Choose model open the switcher unfiltered.** Why: AC#4 says "open the switcher", and R11 defines a filter only for the detected server. Cost if wrong: when the chat's provider has no saved models, the first highlighted row belongs to another provider; pre-filling Find with the chat's provider is one line.
- **AC#8 injects discovery through `app.console_local_server_discovery`,** with the real `probe_models_endpoint` against the stub. Why: `discover_local_servers` always probes 8080, 9099 and 11434 first, so on a developer machine it returns someone's real server. Cost if wrong: the test does not cover the real discovery entry point (see below).
