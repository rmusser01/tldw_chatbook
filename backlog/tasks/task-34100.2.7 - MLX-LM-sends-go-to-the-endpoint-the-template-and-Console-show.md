## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
An MLX-LM chat ignores the address a user sees and edits. The shipped `[api_settings.local_mlx_lm]` table carries `api_url = "http://localhost:5678/v1/chat/completions"`, and the Console's endpoint resolver reads `api_url` like every other local provider. But `chat_with_mlx_lm` (`LLM_Calls/LLM_API_Calls_Local.py`) uses a URL only when one is passed to it, and the Console's gateway passes MLX-LM none (it is in no branch of the gateway's `api_base_url` forwarding). The handler then builds `http://{host}:{port}/v1` from the table, with defaults 127.0.0.1 and 8080, and neither key ships in the template.

Found by TASK-34100.2's live checks on 2026-11-05. A marked MLX-LM whose model was set by hand got a 404 at 127.0.0.1:8080, where another session's server answered. It replied only after `port = 5678` was added (`.worktrees/setup-wizard-ux-qa/evidence/g2cv5-vd-fresh/19-23`). TASK-34100.2's review v5r2 (G2C-R3-3) made the template-sample identity follow the handler (host/port). Its console.md tells users to point MLX-LM at a server with `host` and `port`. This task removes the mismatch, so that one key decides where an MLX-LM send goes.
<!-- SECTION:DESCRIPTION:END -->
