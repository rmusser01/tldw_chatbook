## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Finding A of TASK-19570. Every test that constructs a TldwCli reaches the host's real credential subsystem, because the app wires a server credential store unconditionally during __init__ and nothing in the test harness intercepts it. On macOS the first read can raise a Keychain consent dialog or block on a locked keychain, which under the suite's thread-based timeout kills the whole run rather than a single test. It also means test runs can read and write the developer's real stored credentials.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Tests never resolve the host's real keyring backend; the sandbox is established before any application import, as the config/HOME sandbox already is
- [x] #2 The production call path TldwCli.__init__ takes is proven to find no OS-backed credential store during tests, rather than only the environment variable being asserted
- [x] #3 A constructed test app records the credential store as unavailable and takes its documented fallback, so app construction still succeeds
- [x] #4 The guard is mutation-proven: with the sandbox lifted it goes red, and the failure demonstrates a real OS store was reachable
- [x] #5 A deliberate opt-out exists for anyone who needs a live backend, and the suite that is about keyring behaviour is unaffected
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Pinned `PYTHON_KEYRING_BACKEND=keyring.backends.null.Keyring` in `Tests/conftest.py`'s
import-time bootstrap — the same block that already sandboxes HOME/XDG/TLDW_CONFIG_PATH, and
for the same reason: it has to run before any application import. Added
`PYTHON_KEYRING_BACKEND` to `_SANDBOXED_ENV_NAMES` so `pytest_sessionfinish` restores it.

**Why it was reachable.** `TldwCli.__init__` calls `_wire_server_context_provider()`
(`app.py:5811`), which calls `build_default_server_credential_store()` (`app.py:6305`),
which calls `keyring.get_keyring()` (`runtime_policy/server_credentials.py:296-298`).
That path is unconditional and has no test seam — `Tests/UI/app_factory.py` contains no
`keyring` string at all. `PYTHON_KEYRING_BACKEND` appeared in zero conftests; its only two
occurrences were subprocess env dicts in `Tests/Packaging/`, which isolate a *spawned*
process, not the session that spawns it. The risk was known and simply never reached the
shared in-process seam.

**Evidence it was not theoretical.** With the sandbox lifted
(`TLDW_TEST_REAL_KEYRING=1`) on macOS 24.6.0, the seam test fails with
`DID NOT RAISE CredentialStoreUnavailable` — i.e. `build_default_server_credential_store()`
*succeeded* and returned a `KeyringServerCredentialStore` bound to the real macOS
Keychain. Every one of the ~620 files that mounts an app was doing this.

**Guard.** `Tests/test_keyring_isolation.py`, modelled on `Tests/test_network_guard.py`,
pins three levels so the fix cannot be removed silently: the mechanism (ambient backend is
null), the seam (the exact production call finds nothing secure), and the end state (a
constructed app holds `UnavailableServerCredentialStore` and records a reason).
The third is the one that would have caught the original gap, because it exercises
`_wire_server_context_provider` rather than the env var it depends on.

**Mutation-proven.** With the sandbox: 3 passed in 1.31s. With it lifted: 2 failed
(the third was withheld from the mutation run on purpose — it is the only one that could
have triggered a Keychain consent dialog, which under `timeout_method=thread` would kill
the run).

**Scope check.** No test needs a live backend: `Tests/Skills/test_skill_trust_keyring_autounlock.py`,
the one suite that is *about* keyring, injects its own `FakeSecureKeyring()`, and no test
calls `keyring.get_password`/`set_password` unpatched. App construction still succeeds —
`_wire_server_context_provider` already handles `CredentialStoreUnavailable` by installing
`UnavailableServerCredentialStore` (`app.py:6306-6313`). `TLDW_TEST_REAL_KEYRING=1` is the
opt-out.

Added: `Tests/test_keyring_isolation.py`. Modified: `Tests/conftest.py`.
