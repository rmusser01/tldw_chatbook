## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The per-call loop in `run_agent_loop` (`agent_runtime.py:2637-3506`) is 870 lines with 20 `call.name ==` and 3 `call.name in` branches. A dict dispatch already exists for message tools at `:3103-3108`.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F5; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).

## Implementation Plan

1. Add a `LoopState` dataclass in `agent_runtime.py` carrying the per-run loop variables the special-tool handlers read and write (config, deps, `add`, messages, active, spawned, load_batch_exclusive, current_call_correlation, display_call_arguments, output_observer). `run_agent_loop` builds it once and reads/writes those variables only through it.
2. Move each `elif call.name == ...` branch of the per-call dispatch chain into a module-level handler `(call, state)`; register them in one dict `SPECIAL_TOOL_HANDLERS` keyed by tool name. The message-tool dict dispatch becomes one handler registered under all four message-tool names. A handler whose dependency is absent returns `ORDINARY_TOOL`, so the call falls to the ordinary path exactly as the old chain fell through to `else`.
3. Replace the chain with one table lookup; leave `dispatch_refused`, `review_binding` and the ordinary path in the loop.
4. Pure moves only: same event, persistence and permission order. Verify with Tests/Agents plus every other test file naming `run_agent_loop`/`agent_runtime`, Tests/Architecture (serial), the import-footprint ratchet and preflight.
5. Direct handler tests in `Tests/Agents/test_install_skill_runtime_tool.py` (a lane-run file), one per handler shape, each shown red first.

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
`run_agent_loop`'s per-call `elif call.name == ...` chain (20 `==` and the message-tool `in` branch) is now one lookup in `SPECIAL_TOOL_HANDLERS`, a module-level dict of 23 names (19 handlers; `_dispatch_message_tool` is registered under the four message-tool names) in `tldw_chatbook/Agents/agent_runtime.py`. Each handler takes `(call, state)`.

- **`LoopState`** (slots dataclass) carries what the handlers read and write: `config`, `deps`, `add`, `messages`, `active`, `spawned`, `load_batch_exclusive` and the per-call `current_call_correlation`, `display_call_arguments` and `output_observer`. The loop's former locals for those six variables are gone: `add` and `_outcome` read `state.current_call_correlation` and `state.spawned`. `messages` and `active` stay loop locals that alias the same lists (they are only mutated in place, never rebound). TASK-36950.2 can extend the same object.
- **Fall-through:** a handler whose `LoopDeps` callable is `None` returns the `ORDINARY_TOOL` sentinel, and the loop then runs the unchanged ordinary path, as the chain used to fall to its `else`. A sentinel, not `None`, so a dep that wrongly returns `None` still fails as before instead of being invoked twice. `send_to_agent`'s two branches (wired / "Tool not permitted") are one handler. `prepare_managed_skill_promotion` keeps its blocked result when unwired, and `find_tools`/`load_tools`/`spawn` are always handled.
- **Pure move.** `dispatch_refused` and the `review_binding` role check still run first in the loop. Every event, record, permission and accounting step keeps its order. Tool names are disjoint, so the chain's branch order carried no meaning. `_dispatch_spawn` uses early returns where the chain assigned `result` in nested branches (same branches, same order, same increments). Deferred imports (`fleet_message_tools.refused`, `tool_output.tool_output_scope`) stay deferred inside their handlers, so the import footprint is unchanged.
- **Size:** `run_agent_loop` 2,576 -> 2,190 lines. File 3,671 -> 3,716 lines (no size row; under the 4,000-line row threshold). `call.name ==` in the file 23 -> 3. Ruff findings unchanged (same 6).
- **Tests (AC #2):** 13 new tests (26 nodes) in `Tests/Agents/test_install_skill_runtime_tool.py` (lane-run whole file). They call each handler directly with a stub `add`, one per handler shape: table coverage (`RUNTIME_TOOL_NAMES` + the two archive tools), every gated handler deferring when unwired, display-args vs raw-args recording, call-id binding (`request_conversation_restore`, `prepare_managed_skill_promotion`), blocked-not-deferred promotion, argument coercion (`wait_agents`, `merge_agent_worktree`), `send_to_agent` step index and refusal, message-tool callback choice and refusal, `find_tools` formatting, `load_tools` exclusivity and working-set replacement, `run_skill_script` output-observer binding, and `spawn` counting on `state.spawned` with the budget refusal.
- **Red evidence:** one temporary source edit per test (drop the `new_chat` row, `return None` for `ORDINARY_TOOL`, swap recorded args, blank call id, defer unwired promotion, drop `or None`, `index + 1`, swap a message callback, ignore the query, skip the `active[:]` write, `tool_output_scope(None)`, skip the spawn increment) turned all 26 nodes red, each on an assertion (the `new_chat` gated case on `KeyError`); restored byte-identical, then 26/26 green.
- **AC #3:** The covering set (Tests/Agents + 155 other files naming `run_agent_loop`/`agent_runtime`, 11,124 nodes) was run at head under load 40-90. Every head failure, plus the whole tail of the run that a hang left unrun, was rerun at base and head side by side (1,576 nodes): 1,215 vs 1,212 bad (Tests/Agents: 200 of 5,531 nodes bad, the same 200 at base). The 9 nodes that differed were rerun twice more on each side, and the 2 still differing six times more; each failed at base too, or passed at head on every rerun. Most head failures are the local `RecoveryRequired: raw_source_selection_changed` trap (642). Six `test_original_unknown_library_factory_is_opaque_before_construction[*]` nodes hang at base and head alike.
- Tests/Architecture (serial): failures = dev's base list plus 9 `test_task_15103_review_ledger_*` pytest-timeouts (>300 s AST scans under load). 7 passed on rerun, and the last 2 time out identically at base and head in the same minutes. Import-footprint ratchet green. Preflight passes.
