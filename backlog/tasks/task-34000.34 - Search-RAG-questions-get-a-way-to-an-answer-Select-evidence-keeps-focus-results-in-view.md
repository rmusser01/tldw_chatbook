## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: Search / RAG is where users check what the Library knows. Today a first-timer (Jordan) who asks a plain question is told there is no evidence, and concludes the import failed. Selecting a result throws keyboard users back to the top, and the next Enter silently narrows the search. At 100x30 the answer lands below the fold. For a power user (Morgan), one click on a 'Recent searches' entry spends money without saying so, against PRODUCT.md's rule that cost is visible before the action. Each has a workaround, hence P2. Causes are at origin/dev 2d34cbf80d.

L-13, Search mode answers a plain question with 'No evidence matched', and the rail box silently switches the mode. In Search mode, 'How much did retrieval practice improve retention?' returns 'No evidence matched 'How much did retrieval practice improve retention?'. Try broader terms.' (copy at Library/library_rag_state.py:1143-1145). Yet the imported PDF says 'Retrieval practice improved 7-day retention by 21 percentage points', and RAG Answer retrieves it as '#1 match: strong'. The query placeholder, 'Ask or search Library sources' (Widgets/Library/library_search_rag_panel.py:329), invites a question in either mode. Submitting from the rail's 'Search Library…' box changed the mode from '✓ RAG Answer' to '✓ Search' with no notice. Where the rail submit forces the mode was not traced. Suggested direction, refined by the verifier: for question-shaped queries, zero-result copy says Search matches every word as typed. It offers an 'Ask as RAG Answer' button that switches mode but does not run, because an Answer is a paid call. Use a placeholder per mode. When the rail forces Search, say so on the run's status line. The review deliberately does not suggest a silent fall-back to semantic retrieval. A single query grammar across Library filters is a strategic item (improvements/ranked.md R-13) and out of scope.

L-17, 'Select evidence' remounts the cards, so focus lands on a Sources checkbox and the panel jumps to the top. For 'thesis' (6 results), pressing 'Select evidence' on a lower card scrolled the panel back to Run and Sources, and the footer read 'enter toggle Prompts'. The next Enter would turn the Prompts source off and silently narrow the scope. Verified cause: _select_library_rag_result_by_index (UI/Library_Modules/library_rag_search_controller.py:1098-1122) records the selection and then rebuilds the panel's widgets, remounting every card, so focus falls to the next focusable control. Suggested direction: update the button label ('Selected evidence', Widgets/Library/library_search_rag_panel.py:1135) and its class in place. Otherwise, capture and restore both the focused control and the scroll offset.

L-23, Sources toggles take about 3 rows each and push the answer below the fold. At 100x30, after a RAG Answer run, the screen holds the mode line, the query, 'To openai: question + evidence', Run, and the four Sources toggles ('☑ Notes (122)', '☑ Media (24)', '☑ Conversations (12)', '☑ Prompts (10)'), each followed by blank rows. No Answer is visible. At 120x36, 'Evidence · top 15 per source' appeared only after 8 wheel ticks, while 160x45 shows about 8 answer rows. Suggested direction: lay the Sources toggles out in one reflowing row. When results arrive, bring the Answer or Evidence heading into view without breaking TASK-32751's contract (Done) that the focused control stays visibly painted after results arrive.

L-27, replaying a Recent search under RAG Answer silently makes a paid call. The steps were a Search for 'retrieval practice', a switch to RAG Answer, then a click on that Recent searches entry. That click raised the mock provider's request count from 11 to 12, and the cost line 'openai · gpt-5.6-terra · $0.0006 (94 tok)' appeared only afterwards. The history row shows neither mode nor cost. Its tooltip says 'Re-runs under the current mode (RAG Answer)' because entries are stored as bare strings with no mode (RAG-38 note at Widgets/Library/library_search_rag_panel.py:1329-1338). The verifier rated it P3, but it was kept at P2 because PRODUCT.md requires cost to be visible before the action. Suggested direction: in RAG Answer mode a history row only fills the query and focuses Run ('Press Run to ask <model> again'). Later, store the mode with each entry and mark paid ones 'RAG · paid'. Naming the configured provider and model before a paid Answer is finding L-06, owned by TASK-34000.21. This task's 'Press Run to ask <model>' copy should read the model from there.

Review finding(s): L-13, L-17, L-23, L-27. Source: qa/notes-library-ux-review-2026-10-02/report.md
