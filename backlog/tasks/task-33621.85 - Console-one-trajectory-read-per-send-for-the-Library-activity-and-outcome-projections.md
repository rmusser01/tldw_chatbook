## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
When a USER turn gets its durable id, TASK-33621.51's outcome-line projection reads the conversation's whole trajectory with get_trajectory_rows. During a send's start that read runs inline on the UI loop (the TASK-33620.15.4 policy), and the Library-activity controller reads the same rows separately, so each send pays one extra full trajectory read that grows with the chat. Separately, the projection's lines_for runs on every transcript sync (two function-level imports, a copy of the store's sessions, a dict over all active messages) even when the messages and session are unchanged; it does no DB work per tick. Measure on a long tool-heavy chat before changing anything.
<!-- SECTION:DESCRIPTION:END -->
