## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: the Notes navigator tree is where keyboard-only users (Sam) and Notes power users (Alex) spend most of their keystrokes, and it fights both. Arrow keys skip folders. Reaching a filtered result takes eight Tabs. F6 in the editor changes text instead of leaving. Filing a note into a nested folder fails or looks impossible. The stress tester (Riley) also watched a folder's notes seem to disappear after a move. Each problem below has a workaround, which is why they are P2, but together they make the tree slow and untrustworthy. All causes are at origin/dev 2d34cbf80d.

N-21, no fast path from a query to a note. After '/', 'start here' and Enter, the filter reads 'filter: start here · 1 result'. 'Clear filter' and '▾ Unfiled' sit between the field and the only row, 'Index — start here · Unfiled · 1d'. That row is 8 Tab stops away (New, Select, Add from files…, Export, New folder, Clear filter, ▾ Unfiled, row). Esc from the filter goes to the rail search, and ']' / '[' are bound only in Media. After following a backlink, the only way back is to search again. Going back one hop already costs only Esc+Enter, so the gaps are the filter-to-note path and a return after following a link. Suggested direction: Down in the filter focuses the first result row. Enter on an unchanged, already-applied filter opens the first result. Following a backlink shows a one-level '‹ <origin note>' back control. Defer an 'Open note…' palette provider. Do not use 'o', which already means 'open evidence'.

N-22, arrow keys skip folder rows. 'g' focuses '█▸ Agent_Lessons', then Down and Right change nothing, and the first note is about 17 Tab stops away. The User Guide promises ↑/↓ inside a Notes list. Verified cause: folder rows carry 'library-notes-folder-row' (Widgets/Library/library_notes_canvas.py:2387) and the pager carries 'library-notes-tree-pager' (:2352). Neither class is in _LIBRARY_LIST_ROW_CLASSES (UI/Library_Modules/screen_constants.py:434-450), so the shared Up/Down row walker skips them. Suggested direction: add both classes. On a focused folder row, Right expands the folder and Left collapses it, or jumps to the parent when it is already collapsed. Selecting a folder stays separate from toggling it.

N-23, folder pickers miss nested folders. On a fresh visit with every folder collapsed, Move note offers only Agent_Lessons, Journal, Meetings, Projects, Recipes, Research and Study. 'Projects / Thesis', 'Projects / App launch' and 'Study / Japanese' are missing until their parents are expanded in the tree. The dialog is titled only 'Move note'. Move folder and Add to folder have the same problem. Verified cause: _library_notes_folder_target_options (UI/Library_Modules/library_notes_controller.py:3250-3273) builds its choices from the tree branches already loaded in this visit. Suggested direction: a type-to-filter list over all active folders, shown 20 at a time with an exact total, titled 'Move "<title>" to…'.

N-24, 'Move note' fails intermittently with a false conflict. The verifier saw 4 of 7 moves fail. The notice read 'That folder changed elsewhere — refresh and try aga…', truncated, with no Refresh control, and nothing was written. 'Add to folder' worked 4 of 4 times for the same notes. The failure is not specific to Unfiled notes. The notice survived a successful Undo until restart. After a note was deleted, Move note and Add to folder stayed enabled for it. Verified: every FolderConflictError maps to that one generic sentence (UI/Screens/library_screen.py:18797-18801). Hypothesis, not verified: the move path raises it spuriously when SQLite reports BUSY/LOCKED on a borrowed stale transaction. Also a hypothesis: the placement selection is not cleared on delete. Suggested direction: diagnose and fix the spurious conflict first. Then give each conflict reason its own copy and a real Refresh button, clear the selection after a delete, and wrap the notice instead of truncating it.

N-28, moving a folder into a collapsed folder hides the destination's notes. The test moved Recipes into a collapsed Research folder. Eight seconds later, '▾ Research' shows only '▾ Recipes' and its two recipes, while the database holds 5 notes in Research. Collapsing and re-expanding shows them all. Suggested direction, from the verifier: the tree locator that expands the destination also loads the notes (placements) slice for every folder it newly expands, through one shared helper. Finding N-27 ('View imported notes' lands on a collapsed folder) uses the same locator. It is filed separately and builds on this fix.

N-30, the sort chooser leaves focus in the Filter. Tab to 'Sort: Newest' and press Enter. The '✓ Newest  Oldest  Title' strip opens, but focus stays in the Filter field. The footer then reads 'enter choose sort | esc cancel', although Enter would submit the filter, and Down/Right do nothing. Verified cause: handle_library_notes_sort (UI/Library_Modules/library_notes_controller.py:4917-4929) toggles the strip and re-syncs the canvas but never moves focus. Suggested direction: focus the active '✓' choice when the strip opens, and return focus to the Sort control when it closes.

N-32, F6 in the note body selects the current line. With focus in the body, F6 left focus where it was, gave line 1 the selection style and moved the cursor from 1:1 to 1:40, in 4 of 4 runs. The footer advertises 'F6 next pane', and the next keystroke replaces the selected line. Verified cause: Textual's TextArea binds f6 to select_line. The app's F6 binding (tldw_chatbook/app.py:935) is not priority, while Shift+F6 works because LibraryScreen declares it priority (UI/Screens/library_screen.py:1022-1028). Suggested direction: a priority F6 binding on LibraryScreen beside shift+f6. Do not change the app-level binding, because ADR-031 keeps the global F6 non-priority. Where F6 lands from other editor fields belongs to finding N-05, owned by TASK-34000.8.

Review finding(s): N-21, N-22, N-23, N-24, N-28, N-30, N-32. Source: qa/notes-library-ux-review-2026-10-02/report.md

## Acceptance Criteria

- [ ] #1 (N-21) With a filter applied, Down in the filter field moves focus to the first visible result row, and Enter on an unchanged, already-applied filter opens the first result in the editor
- [ ] #2 (N-21) After the user opens a note by following a backlink or note link, a visible '‹ <origin note title>' control returns to the originating note in one action
- [ ] #3 (N-22) Up/Down move focus through folder rows, note rows and the tree pager in visual order. On a focused folder row, Right expands it, and Left collapses it or, if it is already collapsed, moves focus to its parent folder
- [ ] #4 (N-23) On a fresh visit with every folder collapsed, the Move note, Move folder and Add to folder pickers offer every active folder at any depth, including 'Projects / Thesis', and can be narrowed by typing. A bounded list states the exact total, and each dialog title names the note or folder being moved
- [ ] #5 (N-24) Moving notes between folders succeeds on at least 10 consecutive attempts on the seeded power profile, including Unfiled notes, with no 'changed elsewhere' notice. The Implementation Notes record the root cause of the false conflict
- [ ] #6 (N-24) A genuine folder conflict shows copy that names what changed and offers a working Refresh control. The notice wraps instead of truncating and clears after the next successful folder operation, and after a note is deleted, Move note and Add to folder no longer act on it
- [ ] #7 (N-28) After a folder is moved into a collapsed folder, the destination lists its own notes as well as the moved folder, without the user collapsing and re-expanding it
- [ ] #8 (N-30) Opening the Notes sort chooser puts keyboard focus on the active '✓' option, so arrow keys and Enter choose a sort, and closing it returns focus to the Sort control
- [ ] #9 (N-32) F6 pressed in the note body moves focus to the next pane without selecting or changing any text. Shift+F6 still moves to the previous pane, and F6 outside Library behaves as before (ADR-031)
- [ ] #10 Regression tests (Pilot or unit) fail on current dev and pin each criterion above. They cover: folder rows in the arrow-key walk, picker options with collapsed branches, repeated moves without a false conflict, destination notes after a folder move, sort-chooser focus, F6 from the body TextArea, and the filter's Down/Enter path
