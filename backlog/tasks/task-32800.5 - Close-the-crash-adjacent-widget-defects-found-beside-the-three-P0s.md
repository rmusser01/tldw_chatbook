## Description

<!-- SECTION:DESCRIPTION:BEGIN -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Five fixes; one item deliberately declined.

notes_recovery_dialog.py: kept the set_interval handle and stop it (returning False from a Textual interval callback does NOT cancel it -- the value is ignored, so the poll ran for the whole mount). Extracted _set_approve_disabled/_set_status so all four child lookups are guarded, which also covers the three inside the confirm worker that sit after an await.

library_file_notes_git_panel.py: both worker coroutines (_render_commit_review_notes, _render_rows) opened with an unguarded query_one as the first statement -- in _render_rows it sat immediately OUTSIDE the try that guarded everything after it. Worker body + exit_on_error default True = app exit, not a dropped render. Both now query()/first() and return when detached.

speech_tts_settings_panel.py:5438: the package's ONLY run_worker(exclusive=True) without group=. Given a per-axis group, matching the per-axis _custom_id_rebuild_pending fence, so a model rebuild cannot cancel an in-flight voice rebuild.

library_file_notes_workspace.py: the pairing review paused the folder poll with no resume -- the file's single resume() is in the manual Refresh handler. The dialog was pushed with push_screen, which returns at mount, so the coroutine left the try while the review was still open. Now push_screen_wait plus a finally that resumes, covering the error path.

DECLINED with reason: console_session_switcher_modal's four bare asyncio.create_task calls. on_unmount already sets _closed, bumps _request_generation and signals _activation_cancellation, so late work is invalidated and the task is cooperatively cancelled. Converting to run_worker would be churn against a lifecycle that demonstrably works, and none of this task's ACs require it.
