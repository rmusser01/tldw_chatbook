## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: a profile with no lasting-sync root is every new user. In Library ▸ Notes ▸ Add from files… the chooser offers "○ Keep a folder synced" as inert, so the lasting setup flow (folder entry → Check → review) cannot be reached and the user can never create their first synced folder. The User Guide advertises that flow.

Root cause, verified in code (TASK-34000.17's review, 2026-10-22): boot's TASK-21247 gate neither constructs nor starts the notes-sync runtime when no root is configured; the Library screen later builds the owner lazily without starting it, so it sits at its constructor status "starting"; the setup gate accepts only "active" and "not_configured"; and the one force-start that would move it (`review_setup`) is reachable only after the user picks the option the gate refuses. A deadlock.

Ruling: schedule the owner's NON-forced start through the app's existing start-task bookkeeping when the Library side first needs the owner and the boot gate skipped it. Its start-evidence probe defers cheaply to "not_configured" without opening the state store, which the gate already accepts. Treating "starting" as setup-ready is rejected: it also matches a configured user's in-flight boot start and widens a shared status vocabulary.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Approach (a) from the brief: one entry point, `ServiceWiringMixin.ensure_notes_sync_runtime_started()` (`app_service_wiring.py`). It returns the recorded start task when boot already scheduled one (so a configured user's in-flight start is never doubled or re-reported, AC#5), reads the owner through the safe reader (no-op on a build failure or an owner double without `start`), and otherwise creates ONE non-forced `start()` task under the owner-construction lock with the boot path's task name and done-callback. The done-callback's `self.screen` read is guarded with `ScreenStackError` so a harness that mounts the Library over an un-run app cannot raise inside a callback.

Library side: `LibraryScreen.__init__` calls the entry point once it holds the app's owner (the first place the Library needs it); `handle_library_notes_add_from_files` calls it again (idempotent) and waits a bounded 0.5 s (`_NOTES_SYNC_START_SETTLE_SECONDS`, shielded, never cancelling the start) before `begin_add_from_files` re-reads availability. The existing settle path (`_observe_notes_sync_runtime_start` → `refresh_notes_sync_runtime` → `refresh_roots` → publish → canvas sync) repaints a chooser painted while a slow start was still in flight. `_SETUP_READY_STATUSES` is unchanged; `library_notes_sync_controller.py` is unchanged.

Tests: `Tests/UI/test_library_notes_keep_synced_without_a_root.py` boots the real `TldwCli` into Library over a per-test state-DB path with no root (bootstrap_profile, no plugin; RED on 50838c3452 with `'○ Keep a folder synced' (runtime status 'starting')`, GREEN after: chooser available → configure → Check → review, DB absent until the review, start task settled at exit, no unhandled loop errors; 11.4 s call, 13.1-13.3 s file, same with the w1b plugin). `Tests/App/test_notes_sync_lazy_start.py` (9 tests) covers the seam: idempotence, boot-task reuse (AC#5), build-failure/no-start/no-loop no-ops, the real owner deferring to `not_configured` without a store and shutting down cleanly, the done-callback refresh and its no-stack guard.
