## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: "demo" tells a user they can look without committing to anything. In Library ▸ Artifacts ▸ Reports, one press of "Try report demo" sets up a lasting watchlist instead. It fetches three live RSS feeds every hour and calls the user's paid LLM provider once a day, and it keeps doing so until the user finds and removes it in Watchlists. The power user in the review (Morgan, j4) found out only from the toast that appeared afterwards: "Your first daily report is ready -- see Artifacts → Reports. It refreshes daily from now on." A privacy- or cost-conscious user would never have agreed to that.

Observed (verified at 160x45, golden profile):
- Before the click, the Subscriptions DB held 0 watchlists, 0 briefings and 0 presets. One click created all of these (verify 08-subscriptions-db-after-demo):
  - a "Daily Brief" watchlist (active, `briefing_cadence_seconds` 86400);
  - 3 active RSS sources (hnrss.org, BBC World News, Ars Technica), each with `check_frequency` 3600, which is hourly;
  - a completed briefing;
  - 77 ingested items.
- The empty-state sentence "No reports yet. Open Watchlists or try the report demo." sits at the top of the list pane. The "Watchlists" and "Try report demo" buttons it refers to sit at the bottom-right of the other pane, about 38 rows away (verify 02-reports-empty).

Verified cause (origin/dev 2d34cbf80d):
- The Library button has no consequence copy at all: `Button("Try report demo", id="library-artifacts-demo")` at Widgets/Library/library_artifacts_widgets.py:210, with the empty-state sentence at :121.
- The press goes straight to `service.run_demo_detached()` with no confirm (UI/Library_Modules/library_artifacts_controller.py:568-583).
- ADR-079 (Consequences) states "The demo consumes real API quota (LLM + TTS); CTA copy says so". The Artifacts screen still carries that copy as `DAILY_REPORT_DEMO_TOOLTIP` (UI/Screens/artifacts_screen.py:85), but the copy was dropped when the CTA was ported into Library.
- Seeding constants are in Subscriptions/daily_report_demo.py (`DEMO_CADENCE_SECONDS` = 86_400 at :36, `DEMO_SOURCES` at :43-59). The hourly check is the sources' DB default.

Suggested direction (the review's refined fix):
- Relabel the button "Set up a daily brief…".
- Add an inline confirm that names the three feeds, the brief every 24 h, the hourly source checks, the provider and model that will be called (it spends API quota), and how to remove the setup (Watchlists).
- Put the CTA directly under the empty-state sentence.
- Share the consequence copy with artifacts_screen.py so the two entry points cannot drift.
- ADR-079 §2 makes the persistent seeding deliberate. This task changes disclosure and consent, not what gets seeded.

Owning-task note: TASK-21513 (Done) built the demo and TASK-31801 (Done) kept a retry CTA on the Artifacts screen. Neither covers the Library port, which lost the consequence copy and has no confirm.

Review finding(s): L-10. Source: qa/notes-library-ux-review-2026-10-02/report.md
