## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** When a send's durable commit fails, every later send in that conversation is refused. The run chip reads "Preparation ended.". The unsent-turn shelf offers the message with Restore and Discard, but Discard does not release the stuck send, so the user has no way out short of leaving the conversation.

**Where it was seen.** The TASK-33621.20 pre-merge review (2026-10-20) reproduced it on dev 2d071d6d71 and on that branch's head with an ordinary send (Library off), and on the head through the Library card's Retry. It predates TASK-33621.20; the card Retry is a new way to reach it. Reproduce before fixing.

**Cause, as reported.** The failed commit leaves the preparation in COMMITTING. The shelf may only release a pause it recognises (TASK-33621.20's shelf-releasable set: retrieval, destination changed, persistence), and COMMITTING is not a pause, so Discard drops the shelf entry and leaves the preparation in place.

**Gap in the existing test.** `test_a_card_retry_whose_durable_commit_fails_keeps_the_turn_on_the_shelf` checks that the turn is offered again after the failed commit. It does not check that the next send goes through.

**Suggested direction.** When the durable commit fails, move COMMITTING back to a shelf-releasable PAUSED(PERSISTENCE), so the card and the shelf can both end it.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
A durable commit that fails before the store reserves it now pauses the send as PERSISTENCE, like a commit that fails inside its transaction, so the card (Retry send / Cancel send) and the shelf (Restore / Discard) can all end it.

Measured first (dev 3efe8476ce): the store's own PERSISTENCE pause (_pause_failed_durable_commit_locked) runs only when its reservation exists. A failure in its preflight ('Durable identity owner changed.' and siblings) or the controller's 'The ordinary save returned no committed owner.' left the preparation COMMITTING. COMMITTING is not shelf-releasable, so Discard dropped only the shelf entry and every later send was refused ('Console session already has an admission owner.'). Every live failure seen (prior repro U01/r1-r2, and this round) was post-reservation, so this path was reproduced in tests that inject the failure inside the real store's commit before its reservation.

Change: console_native_commit._controller_accept_durable_turn's generic failure branch calls _pause_unreserved_failed_commit. Under the store's preparation lock it compare-and-sets COMMITTING -> PAUSED(PERSISTENCE) for the exact attempt, and only when no reservation is in flight and no commit is recorded (pausing under a live owner would let a second send start beside it). The chat-start (background start) path is unchanged. console_runtime._turn_recovery_offered's docstring no longer says a failed commit stays COMMITTING.

Tests (real ChatScreen/controller/store/runtime, in-memory ChaChaNotes): Tests/UI/test_console_durable_commit_failure_recovery.py (Discard and Restore each lead to one answered send; the card's Retry sends once; the failure reads 'Send could not be saved' with no live run) and Tests/UI/test_console_unreserved_commit_failure.py (pause, plus two negative controls that go red when the in-flight/recorded-owner guard is removed). Both existing commit-failure tests (test_console_library_pause_recovery card-Retry case = AC#2, test_console_send_acknowledgement_extended) now assert the release and the next answered send; all red on dev for the right reason. The guard file lives under Tests/UI so the census can gate it without editing derived-artifacts.yml (dev changed that workflow 25 times in the last week; a PR touching it is evicted by the queue). Census floor 1140 -> 1143.

Live (fix branch, real Anthropic haiku via the review proxy, isolated profile, evidence U01/r3-fix): a real commit failure (profile DB write lock held past the 15 s busy timeout) showed the card, header Blocked, 'Run: Blocked — send not saved' and the shelf; Retry send answered once; Discard then a new send answered; Restore then Enter answered once, saved once.

Follow-up filed: TASK-33621.56 (Enter while any paused send holds the chat toasts 'Draft or chat changed; Send again.'; pre-existing on dev for every pause kind).

AC#2 note: after a Library card's Retry whose commit fails, the card keeps covering the re-paused send ('Send could not be saved') and holds it off the shelf, per TASK-33621.20's one-surface rule, so there is no shelf Discard in that flow. The card's Cancel send is its release; the test asserts it puts the message back and the next send is accepted and answered.
