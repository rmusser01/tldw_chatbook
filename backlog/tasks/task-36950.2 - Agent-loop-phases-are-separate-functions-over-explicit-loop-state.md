## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Move every mutable `run_agent_loop` local (counters, sticky provider slots, continuation checkpoint, restore cursor, steps, per-turn batch values) onto `LoopState` as defaulted fields, so the loop has one state carrier; drop the `messages`/`active` loop-local aliases.
2. Turn the nested helper closures (`add` body, `trace`, `_outcome`, `continuation_error`, `persist_continuation`, `transition_call`, `expand_restore_history`, projections, budget helpers, `account_denial`, `reader_cycle_stuck`) into module functions over `state`; their `nonlocal` writes become `state.<field>` writes.
3. Cut the `while True` body into phase functions in `agent_runtime.py` (turn start, steering drain + model call with retry/fallback, redirect, continuation persistence, no-call terminal checks, model record, preparation, hook preparation, proposal, guard, review, before-dispatch, per-call dispatch and settlement, post-batch breaker). Each takes `state` and returns an explicit phase result: `None` to go on, a `RunOutcome` to end the run, or a sentinel to restart the turn or skip to the next call. `run_agent_loop` becomes a short driver.
4. Keep every event, record, hook, permission check, retry and fallback in its order; keep deferred imports deferred (inside the phase that uses them).
5. Add a direct phase-function test to `Tests/Agents/test_install_skill_runtime_tool.py` (lane-run), red first on an assertion.
6. A/B the covering tests (Tests/Agents + other files naming `run_agent_loop`/`agent_runtime`) against base with `-n 4`; Tests/Architecture serially; boot ratchets; preflight. Update `Docs/Architecture/agent-runtime.md`.

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
`run_agent_loop`'s `while True` body and its 19 nested closures are now module functions in `tldw_chatbook/Agents/agent_runtime.py`. `run_agent_loop` is a 102-line driver, most of it the unchanged docstring: it builds the run's `LoopState`, restores a provider continuation if asked, and runs 14 phase functions in order each turn.

- **Phases, in loop order:** `_phase_turn_start` (cancel, the four budgets, hook checkpoints, budget warning), `_phase_model_turn` (restored batch, or steering drain, the coherent boundary, context trace and the model call; `_recover_model_failure` does the retry and the ADR-110 fallback walk), `_phase_redirect` (fence parse, then an active-turn redirect), `_phase_persist_tool_batch`, `_phase_settle_text_turn` (late Stop, empty-turn guard, final continuation), `_phase_record_model_turn` (STEP_MODEL, `RUN_DONE`, assistant append), `_phase_prepare`, `_phase_prepare_hooks`, `_phase_propose`, `_phase_guard`, `_phase_review`, `_phase_before_dispatch`, `_phase_dispatch` (per call: `_dispatch_call` -> `_cycle_stuck`, `_settle_continuation_refusal`, `_execute_call`, `_settle_call`) and `_phase_denial_breaker`. The closures became `_add_step`, `_trace`, `_loop_outcome`, `_continuation_error`, `_persist_continuation`, `_transition_call`, `_expand_restore_history`, `_restore_provider_continuation`, the projection helpers, `_account_denial`, `_reader_cycle_stuck`, `_budget_fractions`, `_exhausted` and `_maybe_deliver_budget_warning`, each taking the state.
- **One state carrier.** `LoopState` (TASK-36950.1) gains every former loop local as a defaulted field: the run's counters, the sticky provider slots, the continuation checkpoint and restore cursor, `steps`, `coherent_len`, and the per-turn batch values (`turn`, `calls`, `restoring_batch`, the model steps, `preparation_refusals`, `call_trace`, `review_calls`, `guard_refusals`, `verdicts`). There is no second carrier. Per-call values (`verdict`, `result`, `content`, `tool_outcome`) are arguments between the per-call helpers, not state. The `messages`/`active` loop-local aliases are gone (the 36950.1 forward note): every phase and helper reads and writes `state.messages` and `state.active`, and the fallback projection still writes `state.messages[:]` in place.
- **Phase result, not the state.** Each phase takes the state and mutates it in place. It returns `None` (run the next phase), the new `NEXT_TURN` sentinel (the old `continue`), or a `RunOutcome` (the run ends). Returning the same object would carry no information, and the early exits needed an explicit result.
- **Closure-to-function traps handled:**
  - Late-bound locals: `_exhausted` used the sticky `active_call_model_with_continuation`, and `_outcome` used `coherent_len`, both read at call time. Both now read `state.<field>` at call time, so a fallback switch or a moved boundary is still seen. `add` stays a two-line closure in the driver that reads `state` at call time, as before. `publish_output` still binds its call and execution step through default arguments.
  - Nonlocal counters shared between closures: `trace_steps` (bumped by `trace` and by the loop's context-trace reservation), `owner_sequence`, `budget_steps`, `total_tokens` (`_exhausted` and the loop), `continuation_checkpoint` (`transition_call` and the loop), `restore_history_start`, `consecutive_denials` and `budget_warning_delivered` all live on the state. No phase keeps a local copy of a mutable scalar; only `deps`, `config` and `budget` (frozen or never rebound) are aliased locally.
  - Early exits: the body's five `continue`s (retry, fallback switch, redirect, empty turn, retry-with-context) return `NEXT_TURN`. The fallback walk's `switched` flag, `break` and `continue` collapse to one `return NEXT_TURN` at the same point. The per-call `continue` returns `None` from `_dispatch_call`, and every `return _outcome(...)` returns its `RunOutcome`. The bare `raise` stays in `_phase_model_turn`'s `except` block; `_recover_model_failure` returns `None` after tracing "Model request failed".
  - `try/finally` spanning phases: none existed. The only `with` (`tool_output_scope`) wraps one invoke inside `_execute_call`, and each `try/except` sits inside one phase.
- **Pure move, two equivalent reshapes.** The steering append, duplicated between the pre-call drain and the redirect, is one `_append_steering`. The drain still calls it inside its `try` (contained) and the redirect outside, as before. The loop-only deferred imports (`fallback_chain`, `Provider_Contract`, `history_projection`, `model_retry`) moved from the top of `run_agent_loop` into `_recover_model_failure`, and `Chat.local_reasoning` into `_exhausted`/`_append_steering`. They stay deferred, but now load on the first model failure or steering delivery instead of at run start. The `automatic_work_runtime`, `tool_output` and `fleet_message_tools` imports stay at their original points. `RetryPolicy(...)` is built at the retry point instead of once per run (same constants).
- **Equivalence check.** A token-normalized statement diff of the old function against the new code (comments stripped, `state.` prefixes and helper renames mapped back) shows only the intended moves, the `continue`-to-`NEXT_TURN` and guard-inversion rewrites, the steering dedupe and the import moves. No condition, argument or call order differs.
- **Monkeypatch sweep.** The phases stay in `agent_runtime.py`: the file is 3,954 lines, under the 4,000-line guard, so no sibling module and no new boot-time module. No test patches an `agent_runtime` attribute (grepped every `setattr`/`patch` on the module and its string paths). Ten sites patch `agent_service.run_agent_loop`, which `agent_service` reads from its own globals at call time; that name, signature and module are unchanged. The driver names its phases inline, not in a module-level table, so a future patch of a phase on the module still reaches the loop.
- **Size (AC #2):** `run_agent_loop` 2,190 -> 102 lines. Largest function in the module: `_settle_call` 241, then `_recover_model_failure` 182 and `_dispatch_spawn` 143 (unchanged). File 3,716 -> 3,954. Ruff: the same 6 B905 findings as base, F at zero.
- **Diagnostics:** two logger calls kept their original line wrapping, so `check_persistent_diagnostic_inventory --statements` reports all 12 agent_runtime diagnostics unchanged or moved/re-indented only (0 added, 0 removed). The inventory pin was regenerated for the new digest.
- Files: `tldw_chatbook/Agents/agent_runtime.py`, `Tests/Agents/test_install_skill_runtime_tool.py`, `Docs/Architecture/agent-runtime.md` (dataflow: steps 2–11 are phase functions), `Docs/security/production-diagnostic-inventory.json`.
- **New tests (AC #1, #3):** two tests in `Tests/Agents/test_install_skill_runtime_tool.py` (a whole file a lane runs) call phases on a bare `LoopState` with a stub `add` and no loop.
  - `test_denial_breaker_phase_keeps_every_settled_reply_and_ends_stuck`: below the limit the phase returns `None`. At the limit it returns `RUN_STUCK` with `denial_count`, and the boundary moves past the batch so the denied reply survives.
