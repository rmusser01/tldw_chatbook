## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: TASK-34000.2 fixed the common lasting-sync wedge, where a tail edit hit `postcondition_failed` and left the root on a false "Ready". It made the post-write check compare the bytes on disk with exactly what the writer produces for the note under the file's profile.

One corner remains, found in that task's review. Take a synced file that uses CRLF line endings and has no final newline. If its note is edited down to a single line with no newline, the written file has no line ending left to observe. On the next pass the file is therefore seen as `lf`. The profile check then fails with `postcondition_failed`, so the root is held again.

The obvious shortcut is to drop the profile-equality clause. That is wrong: it would commit the observed `lf` profile and silently flip the file's CRLF convention on its next multi-line write. The durable fix is to carry the reviewed newline profile forward at every binding-commit site. A file whose observed line ending is indeterminate (no line ending present at all) should keep its recorded profile instead of being re-profiled.
