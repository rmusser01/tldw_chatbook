## Implementation Notes (progress -- grab-bag, still open)

Landed on PR #2739 (`fix/core-review-loop`) so far:

- **180 ms emoji index** — the live path is `ConsoleAppearancePickerModal`
  (the report named `EmojiPickerScreen`, which has no caller and is left to
  the dead-code stream). The Console appearance-picker open handler now builds
  the emoji catalog with `asyncio.to_thread` and pushes the modal with the
  result injected, so the click no longer freezes the loop. Modal gained an
  optional `emojis=` param (self-builds when absent). Gate-free test:
  `Tests/Widgets/test_console_appearance_emoji_injection.py`.
- **9.6 ms file-picker construction** — done earlier (RecentLocations lazy).
- **[D2] per-message point read** — `_durable_context_snapshots` batched its
  N per-message `get_message_version` point reads into one chunked
  `get_message_versions_by_ids` (new `CharactersRAGDB` method + persistence
  wrapper), with a single-reader fallback for test doubles. Gate-free DB test:
  `Tests/ChaChaNotesDB/test_message_versions_batch.py`.
- **tag-vocabulary rebuild** — `build_keyword_tag_lister`'s `_tag_lister(query)`
  rebuilt the whole unioned usage vocabulary (~22 ms, ~50x at cap) per keystroke
  though `query` only drives the substring filter. Extracted `_build_counts()`
  and memoised it on the lister closure (once per modal). Gate-free test:
  `Tests/Chat/test_scope_picker_listers.py::test_keyword_tag_lister_builds_usage_counts_once_per_modal`.
- **directory-tool depth/scan caps** — `ListDirectoryTool` clamps `max_depth` to
  the schema max (5) and stops the recursive walk at `_LIST_DIR_MAX_SCAN_ENTRIES`
  (10_000), reporting `scan_truncated`, instead of stat()ing an unbounded tree
  before the 100-entry return cap. Gate-free tests in
  `Tests/Tools/test_file_tool_sandbox.py`.
- **three persona file writes / db reads** — `personas_screen.py`'s
  `_dictionary_export_worker`, `_export_expression_set`, and
  `_apply_pending_character_conversation_link` did sync file I/O / db reads on
  the loop; wrapped in `asyncio.to_thread`, mirroring `_lore_export_worker` and
  the conversation-link method's own sibling `to_thread` calls.
- **runtime-source-switch config write+reload** — `_perform_runtime_source_switch`
  (`settings_screen.py`) ran `save_settings_to_cli_config` (~64 ms) +
  `load_settings(force_reload=True)` (~42 ms) on the loop; now `asyncio.to_thread`.
  (The finding's other three one-shot settings actions -- the network-branch save
  and the two Diagnostics buttons -- need sync->async-worker restructuring, which
  risks gated tests that expect a synchronous result; left as follow-up.)
- **MCP `_sync_children` config reads** — the ~110 ms of it that was
  `tool_gate_breadcrumb` + `all_tool_gates` is closed by task-32804.7's
  `_gate_config_snapshot` (one load, not 11). `_collect_snapshots` (20.6 ms) is
  closed by task-32804.7 AC#2 (one config load, gated-test seam migrated).
- **unbounded chunk-template select** — `list_templates` ran a synchronous
  ChunkingTemplates SELECT on the loop. Generalised `rag_admin_scope_service`'s
  `_call_off_loop(service, method_name, **call_kwargs)` and routed
  `list_templates` through it (off-thread when `diagnostics_are_thread_safe()`,
  inline otherwise), the TASK-21126 precedent. Gate-free tests in
  `Tests/RAG_Admin/test_rag_admin_scope_service.py`.
- **attachment config readers** — the `[chat.images]` readers
  (`supported_image_formats`, `max_image_bytes`, `image_resize_max_dimension`)
  each ran a full `get_cli_setting("chat","images")` admission pass (~7 ms);
  per-attachment validation read the allowlist AND the size cap (2/image), and a
  payload build read the resize bound twice. Added `load_chat_images_config()`
  (one section fetch) + an optional `chat_images=` section param on the readers
  (unset = live read, byte-identical, no process caching so runtime edits still
  reflect — sidesteps the `_supported_patterns` lru_cache staleness tradeoff).
  Validation loads the section once; the payload build reads the bound once.
  Gate-free tests in `Tests/Chat/test_attachment_core.py`.

Still open (invasive/structural, gated verification, or product-decision):
control-plane per-call sync and the server nine-round-trip re-run
(access-context caching across 65 call sites) — the control plane is
constructed with ~10 distinct DB-backed `local_service` instances, each with
its own SQLite thread-affinity, so an off-loop hop needs a per-service
thread-safety declaration (like `diagnostics_are_thread_safe`) and cannot be
threaded blind (a loop-thread connection used off-thread crashes); and
settings-actions sites 2-4 (network-branch save + two Diagnostics buttons)
which need a sync→async-worker restructure that risks the gated tests
expecting a synchronous result.
