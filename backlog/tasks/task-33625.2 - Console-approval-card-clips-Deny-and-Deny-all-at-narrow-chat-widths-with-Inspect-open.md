## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** When the Inspect rail is open and the terminal is about 105 columns or narrower, the single-row approval card's fixed controls no longer fit the chat column. The safe choice is the one that disappears, while the risky one stays visible, which invites approval by default at the terminal size the product commits to supporting.
- 80x24 with Inspect open: the card is 44 columns wide. It shows `Approve on`, no per-row Deny, and `Approve all · Submit · De`.
- 90x30: only `Approve` shows on the row, and `Deny all` is gone entirely.
- 100x30: the per-row Deny is a 2-cell red sliver with no label.
- 110 columns and wider: everything fits.

The clipped fast Deny stays in the focus chain. Tab from `Approve once` moves to an invisible control with no visible change, and Enter there denies the call. A visible deny path still exists through the decision Select's fifth option plus Submit, and the timeout auto-denies.

**Mechanism.** Widths are fixed in `tldw_chatbook/css/components/_agentic_terminal.tcss`:
- `.approval-row-decision` is 27 cells and `.approval-row-fast-approve` / `.approval-row-fast-deny` are 14 each, 55 cells in total. They sit in a non-wrapping Horizontal.
- `#approval-batch-actions` needs about 48 cells.
- `chat_approval_card.py` composes Deny last in both rows, so right-edge clipping always removes Deny.
- `console_rail_state.py` honours an explicit Inspect open at 80 columns (ADR-043, `right_open_explicit`). Nothing collapses Inspect or reflows the card while a decision is pending.

Precondition: at the default 80x24 (transcript-only) the card is 78 columns wide and fully visible. The defect needs Inspect explicitly opened (Alt+I), which then persists across widths.

**Severity / prior art.** P1. The ledger triages this as REGRESSION against TASK-32287 (Done; AC#2 "At 80x24 a one-row card shows its action bar") and TASK-32278 (Done; AC#1 decision labels fit at the card's minimum supported width). The verifier notes that TASK-32287 AC#2 still holds in the default layout, and its test runs with Inspect closed. So this is best read as an uncovered, width-dependent case the earlier tasks did not test, not a code regression. Related: TASK-1845 (approval card decision safety), ADR-043. Verdicts: live PARTIAL, code PARTIAL, skeptic PARTIAL.

**Suggested direction.**
- Make the card respond to its own content width, not the terminal size. Below about 60 cells, stack the controls: the Select on its own line, then a Deny + Approve-once pair with Deny first or equally prominent.
- Order or wrap the batch bar so `Deny all` can never clip.
- Optionally, yield the Inspect rail while a decision is pending in the narrow bands, without writing the rail preference.

The general width-priority model belongs to the Theme 5 umbrella task.
