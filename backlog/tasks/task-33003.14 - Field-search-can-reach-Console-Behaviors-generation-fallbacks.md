## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
All 14 Console Behavior generation-fallback labels are identical to their Providers & Models labels, and _top_field_match is a label-substring match, so a '/' query always lands on the Providers & Models field. The fallbacks cannot be found through '/' at all. Found in TASK-33003.9 review round 0 (minor 5).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A '/' query can land on each Console Behavior generation fallback, for example through a qualified query or a choice between the two matches.
- [x] #2 '/' results for Providers & Models fields are unchanged, and Tests/UI/test_settings_search_index.py stays green.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Red tests: 'fallback <label>' opens Console Behavior on that fallback for each of the 14 shared-label fields; the bare label still opens Providers & Models on its own field; Enter on the mounted screen focuses the fallback.
2. In settings_search_index.py, give each `settings-console-default-*` row a qualified alias, "Global fallback <label>" (the section's title). The screen is untouched.
