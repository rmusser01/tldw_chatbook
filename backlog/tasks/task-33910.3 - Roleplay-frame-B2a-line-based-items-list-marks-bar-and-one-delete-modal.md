Replace the paged `ListView` with one line-based items list that loads database windows, so 5,000 items stay fast and every item takes one line. Spec §5.2 "B2a · Items list (D14 = A)"; see also §1.5 "Items list" and §1.5.6 "D14: one virtual list, loading database windows (decision A)". Size L (XL risk: the test migration). **Scope**
- `RoleplayItemList(OptionList)` keeping `#personas-library-rows`: markup-off prompts, density, the gutter (a click on column 2 marks), marks by id.
- Database windows of 200 rows with `add_options` and the §1.5.6 safety rules (no duplicate ids, the window fence, reload from the anchor after writes, load-through); prompt work that stays cheap with many rows loaded; personas paged until exhausted.
- The marks bar and the one delete modal (R32); border-title counts replace the pager and the count line (`#personas-library-pagebar`, `#personas-library-count`); today's toolbar rows stay until B2b.
- `space`, `m` and `s` move onto the list widget.
- The visit-lifecycle hooks (§4.11), created with their first duties: on leave, clear the marks and cancel the window worker.
- The 3 counted broad rules that leave with the `ListView` and its pager, with the ratchet lowered.
- Re-pins (census first): 91 `#personas-library-row-*` refs, 46 `ListView`-typed `#personas-library-rows` refs, `test_personas_library_pane.py`, `test_personas_library_pane_paging.py` (deleted; its `scripts/ui_pr_gate_census.txt` entry is replaced by `test_roleplay_item_list.py` in the same commit).
- `Tests/UI/roleplay_frame_harness.py` gains the list helpers (`select_roleplay_item`, `highlighted_item_id`, `visible_item_ids`, `item_at`, `list_state`).

**Interim (§5.3):** today's toolbar rows stay until B2b.

**Slice gates (card):** the `PersonasLibraryPane` boot segment (1,928 B) does not grow; pre-import +0; ADR-011 capture (retires the ListView path, adds a window worker). Fallback: D14-B if the census shows the migration cannot ride the slice.
