## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
This rider comes from the TASK-33002.12 review round 2 live check. With a hand-edited `[chat_defaults] provider = "custom-ep:gone[/]"` (a dangling registry id whose text is Textual markup), Console's workbench mode strip raises `MarkupError` at startup. The app log names `site_function=_sync_mode_label` (`UI/Workbench/workbench_widgets.py:398`, `label.update(mode.label)`) with `widget_type=ChatScreen`. The app survives only through task-32533's keep-alive, so the strip is left half-painted.

The mode label carries user text (the provider id) into a markup sink unescaped. TASK-33002.12 fixed the same class in Settings; this is the Console sink, which that task left out of scope.

A hand-edited config should degrade to an honest not-ready state, never raise.
