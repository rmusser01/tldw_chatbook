## Description

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F8; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Move the 63 learning methods (flashcards, decks, templates, quizzes, attempts, topics, stats) into DB/learning_repository.py as LearningRepository(db); only `self.<db member>` becomes `self.db.<member>`. 2. A cached `CharactersRAGDB.learning` property (lazy same-layer import); no forwarding delegates, so every caller, tests included, moves to `db.learning`. 3. Study services, study_screen and app.py call `db.learning`; retarget test callers and the one test that patches a moved name. 4. Tests: a learning write inside an outer `transaction()` commits and rolls back with it; CharactersRAGDB keeps no learning member. 5. Lower the ChaChaNotes_DB size row. ADR required: no; no schema change, repository joins the existing ChaChaNotes transaction (ADR-228 exception unchanged).
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Approach: the 63 learning methods and their 4 SQL/limit constants moved to `DB/learning_repository.py` as `LearningRepository(db)`. The bodies are byte-identical apart from `self.<db member>` becoming `self.db.<member>` (checked by diffing the removed block against the new module with `self.db.` folded back to `self.`). `CharactersRAGDB.learning` is a cached property with a lazy same-layer import. The repository opens no connection or transaction: it uses `db.get_connection()`, `db.execute_query()` and `db.transaction()`, so a learning write inside an outer `transaction()` joins it. No schema change. ADR-228's ChaChaNotes transaction exception is unchanged.

Decision: no forwarding delegates on `CharactersRAGDB`. The previous draft added 42 of them. Every in-repo caller, tests included, now goes through `db.learning`, so the delegates would have no caller. A guard test pins that `CharactersRAGDB` keeps none of the repository's members.

Callers: `Study_Interop/local_study_service.py` and `local_quiz_service.py` reach the repository through `self.learning` (`_require_db` became `_require_learning`). Production callers outside those two files:
- `UI/Screens/study_screen.py`: the dashboard fallback that runs when there are no scope services. It moved to `db.learning`.
- `app.py::_local_flashcards_due_count`: the Home due count. It moved to `db.learning`.

A repo-wide grep for the other matches of the 63 names found only scope-service, server-service, API-client, voice-process (`start_attempt`) or controller methods, not DB calls. One comment was updated in `UI/Study_Window.py`.

Tests retargeted to `db.learning.<name>` (16 files): ChaChaNotesDB study_functionality / flashcard_due_boundary / flashcard_update_helpers / sargable_timestamps (the SQL constants now come from `LearningRepository`); DB fts5_quoting_search_seams; Backup_Recovery core_owners; UI home_screen, library_shell, study_flashcard_create_drafts, study_flashcards_real_service_contract, study_flashcards_screen, study_quiz_attempt_retry, study_quiz_create_drafts, study_quiz_start_responsiveness, study_quiz_submit_lifetime. The two local-service `FakeDB`s expose `learning`.

Review Focus 1 (patches of moved names): a grep of Tests/, single-line and multi-line, found no `patch`, `patch.object` or `monkeypatch.setattr` of a moved name. The one dynamic patch is `Tests/Backup_Recovery/test_home_citation_retirement.py`, which runs `setattr(db, "count_due_flashcards", ...)`. It now targets `db.learning`, which reaches the code because the property is cached. `test_home_worker_retirement[success|error|cancel-flashcards]` pass.

Review Focus 2: new `TestLearningRepositoryTransactions` in `Tests/ChaChaNotesDB/test_study_functionality.py`:
- Commit case: a second sqlite connection does not see the deck until the outer transaction commits.
- Rollback case: a deck, a flashcard (and its `decks.card_count` recount) and an SM-2 review written inside an outer transaction are all gone after it raises, and the depth is back to 0.
- Cache/binding case.
- Guard: `CharactersRAGDB` keeps no learning member.

Red evidence:
- With `create_deck` temporarily writing on its own `sqlite3.connect`, the commit test failed (`'Joined' not in {'Joined'}`) and so did the rollback test (`['Doomed', 'Kept'] == ['Kept']`).
- With a temporary `create_deck` delegate on `CharactersRAGDB`, the guard failed (`['create_deck'] == []`).
- Both edits were reverted, and all 4 tests then passed.

The failure ids and messages are identical once xdist's interleaved log suffixes are stripped from the ids.
