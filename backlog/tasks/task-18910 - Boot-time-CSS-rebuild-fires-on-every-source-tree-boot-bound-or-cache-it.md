## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Measured 2026-08-19 (TASK-18908 spike): _generated_css_is_stale (app.py) reports stale=True on a freshly-cloned/pulled checkout because .tcss/BUNDLED_CSS-carrying files get newer mtimes than the generated sheets after any pull touching them; every boot then runs a synchronous subprocess build_css.py BEFORE the app starts. The staleness walk itself is cheap (0.2ms warm, ~1713 files) - the cost is the rebuild subprocess (Python interpreter spawn + full parse) on every boot for source-tree users, worst on Windows (Defender scans). Wheel installs are unaffected (_is_source_tree gate).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- Frequency CORRECTED by measurement (the description overstated): rebuild = 0.71s, fires once per real edit then self-heals; a fresh worktree is clean. The real waste was the pure-mtime staleness rule: branch switch / `git checkout` / stash pop rewrite mtimes without changing content → spurious 0.71s on the next boot, every time.
- Fix (PR #1831): `build_css.py` writes `.css-build-manifest.json` (gitignored) recording `[sha256, mtime]` per input; `_generated_css_is_stale` is manifest-authoritative, mtime-first — hash only when mtime moved. Steady state 25.8ms (vs 7ms mtime-only); worst case 208ms vs the 700ms spurious rebuild.
- Stronger, not just cheaper: catches (a) the pure-mtime rule's masking gap — a real edit made while sheets were regenerated by a pull (edit not "newer than the build"), and (b) deletion of a recorded input (the old rule's documented "Known gap"). Found while testing: the first naive implementation (hash-only-when-mtime-moved, keeping mtime as the pre-filter) reintroduced the masking gap — the manifest must be authoritative, with mtime as a per-entry fast path.
- Fail-safe: missing/corrupt manifest falls back to the legacy mtime rule; a broken manifest costs one spurious rebuild, never a missed one.
- Tests: 8 new pins (all seven behaviours); CSS suites 52 passed. ADR: not required — dev-loop staleness mechanics, no shipped-boundary change.
