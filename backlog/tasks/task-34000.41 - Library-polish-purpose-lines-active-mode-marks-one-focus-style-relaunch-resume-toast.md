## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Six polish findings across the Library shell. Each has a workaround. Together they make the destination harder to learn for:
- a first-timer (Jordan);
- a low-vision keyboard user (Sam);
- a daily Notes user (Alex).

The house grammar already has the right pieces (✓ marks, the █ focus bar, Undo receipts). They are applied inconsistently.

**L-36 (P3) · Help and empty states never say what Library, Prompts or Skills are.** On an empty profile at 120x36, F1 on the landing shows "Library Shortcuts — Landing" with three keys ("i: import content", "ctrl+n: new note", "F6: next pane") in an otherwise empty frame of about 30 rows. Then:
- The Prompts empty state says "No prompts yet. Create or import a prompt to begin." but never says what a prompt is.
- Skills shows "Skill trust isn't set up, so every skill you added reads "needs review"…" even with zero user-added skills.
- Skill rows read "invocable: user & agent".

Suggested direction:
- Add a one-sentence "What this is" per surface through `WorkbenchHelpState.notes`. TASK-34000.37 (S-15) adds the Notes "how it works" block through the same notes.
- Define a prompt in the Prompts empty state.
- Use "Can be run by: you or the agent" instead of "invocable: user & agent".
- Show the trust banner only when user-added skills exist.

The banner's wording is partly a harness artefact (null keyring). Showing it with zero user skills is product behaviour.

**S-12 (P3) · The active mode is invisible on several mode and segment strips.**
- In a note's Preview, "Edit / Preview / Info" are all bold #e1e1e1 on #1e1e1e.
- "Library notes | Folder files" looks the same in both states, and so does Conversations' "Read / Info".
- The active Skills tab is dimmed to #a2a2a2 on #1a1a1a, so it looks disabled.

Media's "Read (selected)" and Collections' "✓ Read" / "✓ Newest" already do this right.

Verified cause:
- Notes sets an `is-active` class that no stylesheet styles (`Widgets/Library/library_notes_canvas.py:3536-3541`).
- The source strip's `Button.-selected { text-style: bold }` (`css/widget_defaults_scoped.tcss:874`) is a no-op on Buttons that are already bold.
- Skills marks its active tab with `-active` (`Widgets/Library/library_skill_work_pane.py:191`), which is Textual's press-flash class.

Suggested direction: prefix the active option of every mode or segment strip with "✓ ", and pad the others so labels do not shift. Rename the Skills class to `is-active` and give it a real style. TASK-34000.32 (S-16) may shorten Media's " (selected)" to a leading "✓ ". Keep the two consistent. Lowered: each mode's content differs enough to tell where you are.

**S-14 (P3) · Six focus-indicator dialects.** Sam, who relies on seeing focus, meets all of these:
- The rail's "x" shows focus as a one-cell underline.
- Landing quick actions, Conversations scope chips and Search sources show underline plus a tint of 1.37, 1.64 and 1.34:1.
- Skills rows lack the █ bar that other rows have. TASK-31983 (Done) added that bar to media, notes, prompts and conversations rows only.
- The Reader uses an amber border, against blue elsewhere.
- Container stops show only a 1-column │ or ┐.
- "┃ New ┃" brackets sit beside buttons with only an underline.

Suggested direction:
- Use two dialects: a thick left edge for rows (extend TASK-31983's bar to Skills and Collections rows), and a "┃label┃" outline for one-row buttons and toggles.
- Make the Reader use `$ds-action-focus`.
- Make scroll containers that are not a pane's only target non-focusable.
- Generalise the stop-enumeration test. TASK-32613 (In Progress) owns that test for the Notes surface; this extends it to the other Library destinations.

Lowered: every stop changes something visible, so WCAG 2.4.7 is met.

**S-22 (P3) · A relaunch drops the working context.** Alex opens a note with a filter and expanded folders, stages a note for Console, quits and relaunches. Then:
- The app lands on Console with "Sources: 0".
- The Library landing has no Continue.
- "From your Library" shows only the newest items ("Notes · Ideas inbox", …).
- The open note, the filter and the expanded folders are gone.

Verified cause: screen snapshots are memory-only by design. ADR-033 (`backlog/decisions/033-application-session-state-ownership.md`) says "Screen snapshots remain memory-only."

Suggested direction: amend ADR-033 for an ids-only resume pointer (route, note id, expanded folders) that feeds the landing's Continue slot. Never persist staged sources or filter text. The ADR amendment and owner approval come before any implementation. Lowered: memory-only state is ADR-033 by design, and "From your Library" already lists the newest note.

**S-25 (P3) · Toast placement and copy polish.**
- (a) At 120x36, Esc on a prompt with unsaved changes raises the toast "Unsaved Prompt changes — Save or Discard changes first.". The toast is drawn over the "Save changes" button it names; only "Discard changes" stays visible.
- (b) The note delete receipt "✓ deleted · <title>" never says where the note went. The receipt itself stays, per ADR-055.
- (c) Study's F1 says "esc: back to hub" (`UI/Screens/library_screen.py:4257-4267`), under a generic "Library Shortcuts" title, because Study has no entry in `_LIBRARY_HELP_SURFACE_LABELS`.
- (d) The verifier refuted the claim that "Next: Start typing." goes stale. It shows only while the body is empty.

Suggested direction:
- Dock toasts away from action rows.
- Make the receipt "✓ deleted · <title> · in Recently deleted".
- Change "back to hub" to "back to Library", and add Study help labels.
- When a title exists and the body is empty, say "Next: Write the body below the title.".

**S-27 (P3) · The Items grip label goes stale across routes.** Moving between Notes and Media, the vertical grip can keep the previous route's label. At 160x45 "Items" was painted on the Notes route; in the journey, "Notes" was painted on Media. It is intermittent.

Verified cause: `Widgets/Library/library_browse_reader_shell.py:197-198` assigns `items_grip.pane_label` without a refresh. `LibraryAdaptiveReaderPaneGrip.sync_open` repaints only when the arrow changes (`Widgets/Library/library_adaptive_reader_shell.py:142-170`).

Suggested direction: add `LibraryAdaptiveReaderPaneGrip.set_pane_label()`, which syncs and calls `refresh()`, with a mounted test.

S-23 (P3, residue that outlived done TASK-32126 and TASK-32355). Once notes exist, the app-created 'Agent_Lessons' folder appears in the Notes tree with no explanation (the gloss shows only in an empty library). Markdown task items render as literal '[ ]' boxes in Preview. Evidence: qa/notes-library-ux-review-2026-10-02/verify/nl-vb-14/s23-06-agent-lessons-expanded-120x36.txt and qa/notes-library-ux-review-2026-10-02/verify/nl-vb-14/s23-04-preview-120x36.txt. Grip glyphs stay as ADR-086 specifies.

Review finding(s): L-36, S-12, S-14, S-22, S-25, S-27, S-23. Source: qa/notes-library-ux-review-2026-10-02/report.md
