## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In Chat settings, capture_suspended_draft writes raw_values['console-settings-streaming'] = None when the Streaming control is Inherit (no per-chat override), and ConsoleSettingsDraftSnapshot.__post_init__ accepts only a bool there, so it raises ValueError('raw modal values are invalid'). The ValueError is unhandled in the Configure credential button handler, so the app exits. It reproduces on origin/dev 88e6967590 and at the TASK-33003.5 base: production app, a llama.cpp chat switched to OpenAI with no key (the switch sets Streaming to Inherit), then Configure credential. The Phase 3 final review found that any Inherit Streaming draft reaches it; the provider switch is only one way there. This is the headline credential round-trip flow. Found in TASK-33003.5 review round 2.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** Configure credential no longer exits the app when Streaming is Inherit. The fix covers two more crashes of the same kind in the same round trip. The handler now shows a notice, and keeps the draft, if a snapshot is ever refused.

**Root cause.**
- Streaming is a three-state control: Inherit, On and Off. `capture_suspended_draft` writes Inherit as `None`, but `ConsoleSettingsDraftSnapshot.__post_init__` accepted only a bool, so it raised `ValueError`.
- Two restore paths also dropped Inherit. `__init__` ignored a `None` in the snapshot and fell back to the profile override. `_restore_suspended_draft` applied `bool()`, so Inherit came back as Off.

**Fix (console_settings_modal.py, net 0 lines, the ratchet row stays 7,764).**
- The snapshot accepts `None` for `console-settings-streaming`, and still refuses any other non-bool value.
- Both restore paths use the stored value unchanged.
- `_configure_credential` catches `ValueError` from `credential_request()`. It shows "Settings could not open; your edits are kept." and leaves the modal open.

**Sweep: the same mismatch elsewhere.**
- Streaming is the only three-state raw value. Inputs and Selects capture as strings. The provider-choice Selects (reasoning effort and the like) already restore a blank as `Select.NULL`.
- Crash 2, the focus handoff, found by the new real-router test once the Streaming fix landed. The return intent's focus allowlist (`conversation_settings_navigation._FOCUS_CONTROL_IDS`) was missing 13 focus targets that the snapshot accepts. They include the provider picker, which holds focus right after a provider switch. Staging the handoff raised `ValueError` in the app's callback, so the app exited even with Streaming fixed. All 13 are now on the allowlist. A new test builds a return intent for every snapshot focus target, so the two lists cannot drift apart again.
- Crash 3, blank context Selects. The four context Selects allow a blank, which is captured as `""`. The reopened modal then raised `InvalidSelectValueError` when it assigned that value back. It now restores the blank (`value or Select.NULL`).

**Tests (Tests/UI/test_console_settings_unsaved_guard.py).**
- `test_inherit_streaming_survives_the_suspended_draft_round_trip`: mounted, on the real capture path.
- `test_snapshot_carries_each_streaming_state_and_refuses_a_malformed_one`: None, True and False round-trip; `""`, `"inherit"`, `"true"`, 0 and 1 are refused.
- `test_configure_credential_with_inherit_streaming_keeps_the_app_up`: a private-profile, real-router test of the reported repro. A llama.cpp chat is switched to OpenAI, which lands on Inherit. Then Configure credential, Settings, save and Return. The app is still running, and the reopened modal shows OpenAI with Streaming at Inherit.
- `test_configure_credential_keeps_the_draft_when_the_snapshot_refuses_it`: the guard.
- `test_every_snapshot_focus_target_survives_the_credential_handoff`: the drift guard for the focus allowlists.
- `test_blank_context_choice_survives_the_suspended_draft_round_trip`: four parameters.
