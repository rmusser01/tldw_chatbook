## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in the independent review of TASK-33621.21 (2026-11-22). The Buddy conversation's microphone runs the same `ConsoleStreamingDictationSession` as Console dictation, so it goes through the same model preparation (minutes on a first run, no automatic bound under ADR-284). But `UI/Navigation/buddy_conversation.py` builds the session with `on_event=lambda _session, _event: None` (line 446), so it never sees `VoiceModelPreparing`: no "Preparing/Loading speech model…", no "Still preparing… or Cancel" note. And `request_voice` only acts on an existing capture whose status is "recording" (line 423), so pressing the microphone again while it is still starting does nothing: there is no way to cancel a long preparation from the Buddy.
<!-- SECTION:DESCRIPTION:END -->
