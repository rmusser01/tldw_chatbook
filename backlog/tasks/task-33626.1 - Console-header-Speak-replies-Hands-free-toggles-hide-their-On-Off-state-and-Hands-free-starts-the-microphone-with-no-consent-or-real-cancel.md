## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Speak replies sends reply audio to a cloud provider (and can cost money); Hands-free is a listening mode. Today a user cannot tell whether either one is on, and a single keypress on Hands-free starts a privacy-relevant microphone pipeline that Esc does not actually stop.

**Verified behaviour (live on 64579cce2c, 235x52):**
- Header row 4 reads 'Speak replies ▌  Hands-free ▌  Ready'. Both controls are Textual Switches squeezed to one row with no border or padding (`_size_switch` in `Widgets/Console/console_speech_controls.py`). Neither shows a state word, and the text row is byte-identical for Off and On.
- The Off track measures 1.42:1 against the header (#000f18 on #242f38) and the Off knob 1.22:1. On is a green knob, so On and Off differ only by colour and knob position.
- When focused, the switch shows only '┌───┐' (2.19:1), which replaces the knob. Focused-Off and focused-On captures differ in zero cells, so a keyboard user cannot see the value while the switch has focus.
- Speak replies has a consent dialog (provider, destination, charges). Hands-free has none. Pressing Enter on the focused Hands-free switch immediately starts dictation, audio init and the Parakeet model load. Hands-free reply speech then goes through the same TTS provider, so it skips that cost consent.
- Esc ends the Hands-free loop and the switch goes back to Off, but model preparation carries on: the chip still read '◐ Preparing speech model…' 80 s after Esc. From reading the code (not seen live), close-capture does nothing unless the state is 'recording', so a late start could still open the microphone after the user has exited. The only cancel is the composer's 'Dictate' button, which keeps its idle label; 'press to cancel' appears only in its tooltip.
- Ctrl+Shift+H appears only in a tooltip, not in F1 help. After a failure, a 'Retry speech / Resume auto-speak' row does appear, but the header switch stays green (On) while auto-speak is paused.

**Severity / prior art:** P1, triage NEW (verdicts: live, code and skeptic all PARTIAL). Related Done work: TASK-21201 (moved these toggles into the header), TASK-32495, TASK-32496, TASK-32509, TASK-24417, TASK-1561 and TASK-1586. DESIGN.md's dense-form rule ('Toggles and switches: always paired with a text-state word') comes from the Settings convention; this task extends it to the Console header. This finding belongs to both the styling-tier theme (state and focus visibility) and the consequential-actions theme (Hands-free consent and cancel).

**Suggested direction:** Replace the squeezed Switches with one-row labelled toggles whose word carries the state ('Speak replies: Off/On/Paused', 'Hands-free: Off/Starting…/On'). Give them a focus cue that never replaces the value, and share the component with the Settings dense-form toggle. Make every Hands-free exit (Esc, the toggle, Ctrl+Shift+H) run the existing dictation-cancel path while dictation is 'starting'. While preparing, show a visible 'Starting… (Esc to cancel)' or relabel the mic button to 'Cancel'. Put Hands-free entry behind the Speak replies TTS consent. List Ctrl+Shift+H in F1.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G2-01 (source ids J1-10, J6-05, J7-09, J8-10, L3-19); qa/console-ux-review-2026-09-29/evidence/evidence__J7__09-state-235x52.png and .ansi (row 4, columns 206/223, 1.42:1); evidence__J8__48-before-speak.ansi, evidence__J8__52-speak-on-unfocused.ansi, evidence__J8__121-tab-4.ansi (focused switch).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The two header Switches are now `ConsoleStateToggle`s (`Widgets/Console/console_speech_controls.py`): a Switch subclass that keeps Switch's keys, click, `value` and `Changed` (so every caller is unchanged) but paints its state word, sized to the word so nothing clips. The row reads "Speak replies: Off/On/Paused" and "Hands-free: Off/Starting…/On". `_console.tcss` (bundle rebuilt with `build_css.py`) colours the word with theme tokens: `$text-muted` Off, AA-pinned `$text-success` On, `$text-warning` Paused/Starting…; focus drops the `*:focus` outline and inverts the word into a `$ds-active-fg` bar, so the value stays visible. `sync_auto_speak` shows Paused when auto-speak is enabled but paused; `sync_hands_free_state(active, starting=)` shows Starting… while the pipeline loop's capture is `starting` (the dictation controller now reports every state change through `on_state_changed`).

Consent: the header control, Ctrl+Shift+H and the spoken "hands free" command go through `ConsoleHandsFreeController.request_console_hands_free_toggle` / `request_console_hands_free_entry`. Exit is immediate; entry first runs the checks that need no audio (meeting in progress, forced-but-disabled realtime, dictation probe), then asks `ConsoleAutoSpeakCoordinator.request_hands_free_consent`, which resolves the TTS destination exactly as Speak replies does and opens `AutoSpeakConsentModal(hands_free=True)` (provider, destination, charges; the realtime engine's provider when that engine will run; "replies will not be spoken" when no TTS destination resolves). Nothing of the pipeline starts before Enable; Cancel/Esc/a conversation switch leaves Hands-free Off. The control no longer repaints itself On from the request (it reflects the session, like Speak replies). `action_toggle_console_hands_free` on the controller stays the consent-free mechanism the gestures end in. ChatScreen's suspend keeps a live one-shot capture alive under this one modal, so accepting can adopt it as the loop's first turn.

Cancel: `_console_hands_free_close_capture` now cancels a `starting` capture (quietly: `_request_console_dictation_cancel(announce=False)`), so Esc, the control and Ctrl+Shift+H all return dictation to idle during model preparation and the start worker discards whatever it opens. The composer mic button reads "Cancel" while starting (was "Dictate…" with the cancel only in the tooltip). F1 help lists Ctrl+Shift+H. User Guide: `console/voice-and-hands-free.md` and `console/attachments-images-voice.md` (whose button table still described the old Mic/Rec labels).

Tests: `Tests/UI/test_console_speech_header_state.py` mounts the real ChatScreen (production stylesheets) with real key routing and the real dictation state machine; only the dictation *session* (microphone + model) is a fake whose start blocks like a first-run load. It asserts the words and their contrast in every state at 235x52 and 80x24 in textual-dark and textual-light (Speak replies driven through the real store and coordinator), focus keeping the value with a >= 3:1 cue, Enter on the focused control raising the consent with nothing started and Esc leaving it Off, exit by Esc / Enter on the control / Ctrl+Shift+H during preparation ending idle with no "Preparing speech model" chip and a late start completing into a discard, never `recording`, and F1 listing Ctrl+Shift+H. Mutation: dropping only the `starting` branch of `_console_hands_free_close_capture` fails the three exit cases on `dictation_state == 'starting'`. Tests that drove the loop through the old consent-free screen action now call the controller mechanism, or press Enable on the real consent (`Tests/UI/hands_free_consent_support.py`).
