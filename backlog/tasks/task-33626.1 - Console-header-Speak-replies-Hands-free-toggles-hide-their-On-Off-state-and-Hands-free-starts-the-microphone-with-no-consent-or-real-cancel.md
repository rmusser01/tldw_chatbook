## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Speak replies sends reply audio to a cloud provider (and can cost money); Hands-free is a listening mode. Today a user cannot tell whether either one is on, and a single keypress on Hands-free starts a privacy-relevant microphone pipeline that Esc does not actually stop.

**Verified behaviour (live on 64579cce2c, 235x52):**
- Header row 4 reads 'Speak replies ▌  Hands-free ▌  Ready'. Both controls are Textual Switches squeezed to one row with no border or padding (`_size_switch` in `Widgets/Console/console_speech_controls.py`). Neither shows a state word, and the text row is byte-identical for Off and On.
- The Off track measures 1.42:1 against the header (#000f18 on #242f38) and the Off knob 1.22:1. On is a green knob, so On and Off differ only by colour and knob position.
- When focused, the switch shows only '┌───┐' (2.19:1), which replaces the knob. Focused-Off and focused-On captures differ in zero cells, so a keyboard user cannot see the value while the switch has focus.
- Speak replies has a consent dialog (provider, destination, charges). Hands-free has none. Pressing Enter on the focused Hands-free switch immediately starts dictation, audio init and the Parakeet model load. Hands-free reply speech then goes through the same TTS provider, so it skips that cost consent.
- Esc ends the Hands-free loop and the switch goes back to Off, but model preparation carries on: the chip still read '◐ Preparing speech model…' 80 s after Esc. From reading the code (not seen live), close-capture does nothing unless the state is 'recording', so a late start could still open the microphone after the user has exited. The only cancel is the composer's 'Dictate' button, which keeps its idle label; 'press to cancel' appears only in its tooltip.
- Ctrl+Shift+H appears only in a tooltip, not in F1 help. After a failure, a 'Retry speech / Resume auto-speak' row does appear, but the header switch stays green (On) while auto-speak is paused.

**Severity / prior art:** P1, triage NEW (verdicts: live, code and skeptic all PARTIAL). Related Done work: TASK-21201 (moved these toggles into the header), TASK-32495, TASK-32496, TASK-32509, TASK-24417, TASK-1561 and TASK-1586. DESIGN.md's dense-form rule ('Toggles and switches: always paired with a text-state word') comes from the Settings convention; this task extends it to the Console header. This finding belongs to both the styling-tier theme (state and focus visibility) and the consequential-actions theme (Hands-free consent and cancel).

**Suggested direction:** Replace the squeezed Switches with one-row labelled toggles whose word carries the state ('Speak replies: Off/On/Paused', 'Hands-free: Off/Starting…/On'). Give them a focus cue that never replaces the value, and share the component with the Settings dense-form toggle. Make every Hands-free exit (Esc, the toggle, Ctrl+Shift+H) run the existing dictation-cancel path while dictation is 'starting'. While preparing, show a visible 'Starting… (Esc to cancel)' or relabel the mic button to 'Cancel'. Put Hands-free entry behind the Speak replies TTS consent. List Ctrl+Shift+H in F1.
