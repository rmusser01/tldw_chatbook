## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Several file paths have no bound or no atomicity: a read tool returns an entire file as its result with no size cap and both read families materialise the whole file before slicing; a directory tool ignores its own documented depth maximum and caps entries only after a full recursive scan; three editing tools write in place without fsync and follow symlinks while a sibling in the same module writes atomically; character-card import reads a user-picked file into memory with no byte cap although two sibling importers cap at 10 MB; and a trajectory import reads a user-picked file with no ceiling and lets decode and recursion errors escape its seam.

Source: core-runtime code review 2026-09-17 — `qa/core-code-review-2026-09-17/report.md`; per-slice evidence in `qa/core-code-review-2026-09-17/slices/`, reproductions in `qa/core-code-review-2026-09-17/phase4-verification.md`.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Each named read applies a size ceiling before materialising the file
- [ ] #2 The directory scan respects its documented depth maximum and caps the scan itself
- [ ] #3 In-place writes become atomic, matching the sibling that already is
- [ ] #4 Import seams convert decode and recursion errors into their own error type
