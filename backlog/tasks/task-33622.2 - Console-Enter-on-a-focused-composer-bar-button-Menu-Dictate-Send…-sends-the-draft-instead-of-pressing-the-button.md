## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** A keyboard user who tabs from the composer to 'Menu' (Tab Tab; the button shows its focus cue) and presses Enter fires a paid provider request with the half-written draft. The user turn 'hello menu test' appeared, the Assistant row showed 'Connecting tools…', and `console_send_stage phase=provider_entry status=entered` was logged. With a blank draft, Enter logs `phase=ui_action status=not_dispatched`, no menu opens, and focus leaves Menu. Space on the focused Menu types a space into the draft, which does not have focus. Enter on 'Dictate' likewise goes down the send path and never starts dictation. Every composer-bar button except Composer ▾, Expand and the collapsed-mode Stop is affected, including Send (Enter arms a paste token instead of sending; see the paste-token finding G1-06). The Composer actions menu therefore opens only with the mouse. Attach file, Save as Chatbook, Generate Caption, Impersonate, Buddy… and 'Improve current draft…' have no palette or binding route, so they are mouse-only. While a button has the focus ring the draft keeps painting its caret, so two focus cues show at once. Verified live on dev 64579cce2c at 160x45 (live, code and skeptic all CONFIRMED).

**Cause.** `_should_capture_console_input` in `chat_screen.py` treats any composer descendant except a three-id allowlist (collapse/expand/stop, from TASK-15704) as the text target. The screen `on_key` Enter branch therefore stops the event and runs send before the Button's own Enter binding can fire.

**Severity / prior art.** P1, triage NEW. Related: TASK-15704 (Done, introduced the allowlist), TASK-25825, TASK-2154.14.

**Suggested direction.** Stop capturing when focus is on a control inside the composer rather than on the draft surface: capture only when focus is the draft (or nothing), instead of extending the id allowlist. Keep global chords (paging, undo/redo) routed as intended. Keys must never edit a draft that lacks focus. Stop painting the draft caret while a sibling control holds focus. Add a 'Console: Open composer menu' palette command, plus palette entries for the Menu-only actions. Space activation is optional: it is a web/ARIA convention, not a Textual Button default.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G1-07 (source J6-01)
