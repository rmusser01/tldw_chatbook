## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Every Context and memory label now ends at least one blank cell before its control, and the defaults-scope line shows only beside a defaults action.

**Approach**
- Labels (AC#1). `_modal_label` and `_sync_responsive_layout` set each label's width, min-width and max-width inline (23, or 16 in the compact tier). Inline styles win over every stylesheet rule in Textual, `!important` included, so no CSS could widen the Context view's column. Those writes are gone (12 lines); `_console_panels.tcss` now owns the column: the shared 23-cell `.console-settings-modal-label` rule is unchanged, `.-context-view .console-settings-modal-label` widens it to `$ds-size-24` (the `-context-view` class the modal frame already carries), and `ConsoleSettingsModal.-conversation-settings-compact .console-settings-modal-label` keeps `$ds-size-16`, more specific so the compact tier stays at 16 in both views. The Model view's Endpoint label keeps 23. `MODAL_LABEL_WIDTH` stays as the documented 23-cell column that `test_model_config_field_labels.py` checks labels against.
- Defaults line (AC#2). The line was stale, not wrongly computed: `_sync_default_readiness` hides it outside the Model view, but `_show_settings_view` never called it, so a switch to Context and memory kept the Model view's line (and a switch back showed Save as model default even when no saved default differed). `_show_settings_view` now ends with `_sync_default_readiness()`, which re-derives Save as model default, Apply, the line and the readiness block from the draft; its own Save and Apply display writes, now duplicates, are gone. The line's display is also tied to the button: `bool(scope_copy) and save_button.display`, so it cannot show while a recovery hides the button.
- Sizes: `console_settings_modal.py` 6,156 -> 6,143 (ratchet row lowered); the bundle grows 214 B and the boot CSS budget test passes; no new `styles.*` write, no DEFAULT_CSS geometry.

**Tests (AC#3)**
