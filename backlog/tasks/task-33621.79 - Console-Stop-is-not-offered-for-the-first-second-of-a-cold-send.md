## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while verifying TASK-33621.22 live (fix branch over dev ed7481a30c, Anthropic haiku, 235x52, fresh profile). On a cold first send, Ctrl+G pressed 0.70 s after Enter did nothing, although the app log already showed "console agent reply start": the turn went on to the provider and completed. The composer's Stop control and the "Connecting tools…" label only appeared about 0.8-1.0 s after Enter, and Ctrl+G works only while Stop is shown (`composer_run_controls.stop_available` reads the composer's `run_active`). For most of the cold pre-provider window a user has no way to stop a turn they have just sent. Evidence: the u03c round in the TASK-33621.22 live notes.

From the TASK-33621.22 review: since that task, ConsoleRuntime.cancel_received_intents skips durably accepted custody, so in the gap between acceptance and the reply registering its run stop_active_run() does nothing and returns False. The turn then completes and the next send works (before TASK-33621.22 the same Stop wedged the tab), and the Stop button is hidden there, but the mobile cancel endpoint (Web_Server/mobile_service.py) calls stop_active_run directly and now reports stopped=false. AC #4 covers giving that gap a Stop owner.
