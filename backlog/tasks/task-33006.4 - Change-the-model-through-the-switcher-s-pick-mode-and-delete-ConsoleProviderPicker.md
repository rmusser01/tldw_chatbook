## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The judge's rule 1 is pairs only: wherever a model is chosen, the user picks a provider·model pair.

In the modal, choosing a provider rebases with model=None (_switch_provider → _rebase_to, console_settings_modal.py:5357-5373). That is the UI path to C7(a); the data root cause is fixed in P1.

ConsoleProviderPicker (console_provider_picker.py, 455 lines) is used only by this modal (:156, :1725). It is also referenced by:
- Tests/Widgets/test_console_provider_picker.py
- Tests/Packaging/test_conversation_settings_boot_closure.py:48-65
- Tests/UI/test_css_parse_cache_modal_probe.py:138
- The generated tldw_chatbook/css/widget_defaults_self.tcss (:1450-1470).
- The boot-CSS snapshot Tests/Performance/boot_budget_snapshots/boot_css_bytes.json (:196, 494 bytes).

P4 provides the switcher's pick-only mode. ADR-031's task-16211 refinement requires dismissal inventory coverage for modal-to-modal launches (Tests/UI/test_console_modal_dismissal.py). Alt on macOS types composed characters unless Option-as-Meta is on (chat_screen.py:1333-1339), so the Change button must work without Alt.

Hand-off from TASK-33006.2 (review round 1): its AC#6 test, `test_changing_the_model_updates_the_hidden_set_and_line_at_once` in Tests/UI/test_console_settings_hidden_fields.py, drives `_rebase_to` with the real controller rebaser, because pick mode was not wired yet. The support sync that re-decides the hidden rows and the Sampling line runs in `_apply_rebased_state`, where `_rebase_to` lands. Pick mode must land through `_rebase_to` (AC#2's controller rebaser), and that test is re-pointed at the Change gesture under AC#7.

## Implementation Notes

Chat settings changes the model only through Switch model's pick mode: the MODEL row's **Change  Alt+M** opens the switcher pick-only over the modal, and the picked provider·model pair rebases the draft through the controller's rebaser. ConsoleProviderPicker, the modal's own model search and everything that only they used are deleted.

**Approach**
- `UI/Console_Modules/model_switcher.py`: `open_model_picker(screen, origin, draft, query, on_pick)` pushes `ConsoleModelPopover(pick_only=True)` with the same sources Alt+M uses (`_switcher_sources`, now shared with `open_model_switcher`: configuration, saved and cached catalogs, readiness, RECENT/PREVIOUS, the local probe). `chat_screen.py` passes it to the modal as `model_picker` (lazy import inside `_open_console_settings`) and drops its now-dead raw-provider read: net -2 lines (R1).
- `Widgets/Console/console_settings_field_row.py` (no ratchet row): the MODEL row is model · provider display name | Source word (*this chat*, or *edited \** once the pair changes, from `CONSOLE_VALUE_SOURCE_WORDS`) | readiness word · context window (`_context_copy`) | **Change Alt+M** (compact Button). `_open_model_picker` (Change, Alt+M, New endpoint…), `_model_picked` (a pick lands through `_rebase_to`, which cancels a running probe and keeps a still-valid listing; Esc changes nothing) and `_focus_change` (focus returns to Change after a pick or Esc). A missing model (`select_model`) opens on Change; a missing or unavailable restored focus target falls back to Change (the old fallback was Connection's provider picker).
- `console_settings_modal.py`: `model_picker` kwarg; `Binding("alt+m", priority=True)` (a terminal's Alt+M carries the character "m", which a focused Input would type: found live, pinned by a test that posts the terminal's event); the pair is the draft's (`_current_model_value` reads `self._draft`, `_build_draft` uses `_active_provider`). Deleted: the provider picker and its hidden Select adapter, `ModelSearchPicker`, the hidden model Select/Input adapters, Custom model, Keep unverified, provenance copy, `_switch_provider`, `_provider_changed`, the sentinel flow and 30-odd helpers only they used. `_rebase_to` now requires the exact pair (no `model=None`). A models listing reports what it found ("2 models listed") but never selects a model, even a sole one (spec rule 1, parent AC#4). New endpoint… pushes the template modal with a callback; a created entry opens pick mode with "<entry name> " in Find, and its first probe runs once a pick lands on it; Esc keeps the chat's pair, so no path lands on a provider without a model (R9). After a rebase the Base URL shows what compose shows (an entry's own URL, else the rebased or configured URL), the paid-test action is re-synced, and a still-valid listing's status line stays. 7,410 -> 6,201 lines; ratchet row lowered to 6,201.
- Snapshot and navigation: the raw "console-settings-provider"/"console-settings-model-picker" keys and the picker focus ids are gone from `_SNAPSHOT_RAW_VALUE_IDS`, `_SNAPSHOT_FOCUS_CONTROL_IDS` and `conversation_settings_navigation._FOCUS_CONTROL_IDS`; `console-settings-model-change` is added to both focus sets (R8). The unsaved guard treats the pair as one field, "Model", the MODEL row's label (it named "Provider", which no longer renders).
- CSS: the picker rules and the Connection setup-emphasis rule are removed; the MODEL row summary takes the row's free width (review round 1; it was content-wide up to 48 with an end ellipsis), and below 100 columns (compact, not redesigned) only the pair and Change show so Change stays reachable. `css/build_css.py` regenerated the bundle and `widget_defaults_self.tcss` (the ConsoleProviderPicker block is gone).
