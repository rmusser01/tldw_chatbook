## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in the TASK-33620.8 review (2026-10-30). To create the citation fingerprint key safely, Chatbook opens a write transaction that proves no saved record depends on an older key, and reads and writes the keyring inside it. Before TASK-33620.8 this ran at boot; it now runs on the first cited send. If the system keyring shows an unlock prompt at that moment, every other writer to the chat database waits on the lock until the user answers or the busy timeout expires.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 No keyring call runs while the citation write transaction is open
- [x] #2 Key creation stays safe under a race: a record written by another writer between the keyring call and the commit is detected, and a key that records depend on is never replaced
- [x] #3 A test holds the keyring call open and shows a second database writer is not blocked
