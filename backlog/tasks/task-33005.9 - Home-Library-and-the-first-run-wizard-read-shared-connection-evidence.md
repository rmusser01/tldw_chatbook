## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Home, the Library "Use in Console" lock pre-check and the first-run wizard now share the Console's connection evidence.

- Home (`HomeScreen._home_console_provider_ready`) and the Library pre-check (`LibraryScreen._console_setup_would_block`, the readiness call only, with a function-local import) pass `connection_evidence=shared_connection_evidence(lambda: self.app)`, as the Console's own builders do. The owner is process memory, so a read makes no request (the test fails on any `httpx` send). After a refused test of the default connection Home's Model reads "Not set up" and the Library toast fires, as the Console reads Not ready.
- The wizard: the plan's premise holds (UI/Wizards/first_run_provider_step.py built a private `ProviderTestEvidenceStore()`). Linking it was not enough: the step's `ProviderDraftIdentity.credential_revision` is an edit counter (pinned monotonic by its tests and used by its discovery keys and write guard), not `connection_credential_revision`, so its facts would key no connection the Console reads, and a counter of 0 would key the keyless connection. `ProviderTestEvidenceStore` gains `credential_of`: the key a probe begun now sends. `begin` records the connection (the identity with that key's digest) and `settle` publishes under it; `rebase_after_save` carries a saved typed key from the draft to the stored connection; and such a store reads no facts back (`evidence_for` has no shared fallback), because its identities are not connections and an invalidated result would be read back for the identity it tested (the wizard's tests assert None there). If `credential_of` raises, the probe runs and its result stays private. Other stores are unchanged (`_shared_identity` is the identity itself). The step's store is `ProviderTestEvidenceStore(lambda: self.app, credential_of=lambda: self._credential_at_request_boundary()[1])`; the file stays at 2,454 lines (one comment reflowed).
