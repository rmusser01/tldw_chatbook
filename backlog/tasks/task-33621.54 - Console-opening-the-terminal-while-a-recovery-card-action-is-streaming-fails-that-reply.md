## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** A pre-dispatch recovery card (Library pause, trace capture blocked, context hold) runs its action, such as Retry or Send once without Library, as a worker on the card itself. Anything that removes the card while the action runs cancels that worker. Opening the Console terminal swaps the transcript region out and removes the card. If the action has already sent the message and its reply is streaming, the stream is killed with it. The reply ends as failed ("Accepted turn failed during provider dispatch."): the user row is saved and the assistant row is empty. The user only wanted to look at the terminal.

**What is pinned today.** TASK-33621.20 made the search phase safe (an interrupted Retry search pauses as "Library search stopped" and is offered again) and documents the streaming case as it behaves. `test_a_card_action_interrupted_after_its_send_went_out_fails_that_reply` pins it for both Library card actions: the reply fails, nothing jams, and the next send goes through. That test should change when this is fixed.

**Suggested direction.** Once a card action's send is accepted, run the rest of it on a task the controller or app owns, not on the card's worker, so a center swap or a card repaint cannot cancel it. Stop should remain the way to end it.
