## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Rider from TASK-33001.5 (review fix round 1). On a fresh profile, first-run setup's "Start chatting" stages the Console first-chat handoff at the config generation its commit published. Console then mounts for the first time. Its compose builds the rail state, finds no saved rail scope and writes one to the config file on a worker (`_ensure_console_rail_scope_seed` -> `_save_console_rail_preferences`). That write lands before `on_mount` consumes the handoff, so the handoff's generation fence releases it and Console shows "Provider settings changed before Console opened. Review setup and try again."

Verified live on 2026-09-26 in tmux on a scratch profile (llama.cpp against a local models stub), on BASE 7335d3edad and on e9cc14ba3e alike. The app log orders the setup_completed write, then "Navigating to screen: chat", then the rail_state write, then "Screen chat mounted". The chat does show setup's provider and model, because TASK-33001.5's convergence delivers them. So the warning tells a user whose setup worked to redo it, and the released handoff stays pending, with no effect, for the rest of the session.

The existing handoff tests open the wizard over an already-mounted Console. Its rail scope already exists there, so no write sits between stage and consume. The generation fence is deliberate and pinned (`test_generation_advance_after_stage_before_consume_never_mutates_console`), so the fix needs a choice. Options: order the first mount's rail write after the consume; fence the handoff on the saved provider and model instead of every config write; or stay silent when the current saved defaults still match the intent.
