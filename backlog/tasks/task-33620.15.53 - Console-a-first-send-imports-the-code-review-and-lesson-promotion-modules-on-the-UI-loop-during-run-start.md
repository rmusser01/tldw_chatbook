## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
An ordinary Console agent turn no longer loads the code-review service at run start, a review turn loads it on its composition's worker thread, and `Agents.agent_lesson_promotion` joins the idle first-send warm-up (its ADR-097 row reads 94/94, not raised). A first send after the warm-up now loads none of the review family on the UI loop.

**Measured first (AC#1, live).** Anthropic claude-haiku-4-5 via the review proxy, 160x45, a fresh isolated profile per launch, the first send after the idle warm-up had finished, every cold module load recorded with its thread (import probe in tools/evidence/bd5/I53/kit):
- origin/dev e8eeae7db9 (I53/base): the review family loaded on the UI loop in 7 of 7 first sends. `Chat.console_code_review`, with `Agents.code_review_service`, `_source`, `_store` and `_guide` nested in it, took a median of 18.7 ms at load1 18-21 (3 sends) and 116.9 ms at load1 115-127 (4 sends, max 159 ms). `agent_lesson_promotion` took 5.5 / 3.6 ms and `console_review_delivery` about 1 ms. The import came from `console_agent_reply._run_agent_reply` -> `console_review_delivery.compose_turn_review_provider`, before its `to_thread` hop. `agent_lesson_promotion` came in through the capacity check's tool-surface preview and run start's managed-skill gate.
- Re-measured after the rebase on origin/dev 2684e5453f (I53/v2implo, v2imphi): dev loaded the same 6 modules on the loop in 4 of 4 first sends (`console_code_review` 22 / 10 ms at load1 10-11, 256 / 116 ms at load1 113-116). The branch loaded them in 0 of 4.

**Change.**
- `Agents/code_review_models.review_turn_possible(text, review_owner=, wake_authorization=)` is false only when the turn has no accepted review wake and the controller has no built review coordinator (an offer answer or a stage control needs one), and the text names none of `REVIEW_REQUEST_WORDS` (review/verify/consolidate/retry). Run start checks it before it imports `console_review_delivery`, so an ordinary turn makes no composition, no imports and no worker hop for review. `classify_review_turn` checks it first. `_explicit_stages` returns no stage for text without such a word, before it parses anything, so the check is a necessary condition of every stage. A Hypothesis test checks that forcing the gate open finds the same stages for every text. Content that is not a string still goes on to composition (the old failure path, logged and never fatal to the turn).
- `compose_turn_review_provider` imports `console_code_review` inside the worker hop (`_compose_native_review_provider`).
- `agent_lesson_promotion` is in `FIRST_SEND_MODULES`. Its `Notes.agent_lessons` import moved into `assess_promotion_evidence`, so the warm-up census counts one module, not two (93 -> 94 of 94). The census starts from app + chat, where `Notes.agent_lessons` is not yet loaded.
- `console_agent_reply.py` size row: 1156 -> 1165 (+9, the branch's own growth), with a dated owner-decision comment. `first_send_warmup.json` was re-pinned with `scripts/update_boot_budget_snapshots.py --only first-send`.

**Tests.** `Tests/Chat/test_console_first_send_review_imports.py` (bootstrap_profile) runs one send in a fresh interpreter after the pre-import pass (screen routes, then the warm-up list), on a real controller with the agent runtime, a real agent bridge and a Library provider. It checks that an ordinary send loads no review-family module on the UI loop and that "Review my changes" loads the review service on a worker thread. Unit tests cover the predicate and the stage parser's gate. On origin/dev 2684e5453f both integration tests are red and list each review module with its importing stack. The unit tests are red with ImportError (no `review_turn_possible`).

**AC#3.** `MAX_TLDW_MODULES_AT_UI_READY`, the boot CSS budget, `MAX_PASS_ADDED_*` and `MAX_FIRST_SEND_WARMUP_ADDED_MODULES` are unchanged. The UI-ready census, CSS budget, pre-import and warm-up budget tests pass on the branch (the warm-up census reads 94/94, dev 93/94).

**AC#4 (paired ABBA, timing hook only, no import probe, origin/dev 2684e5453f vs the rebased branch; I53/v2summary.txt):**
- load1 2.5-9.4: 9 pairs, dev median 1328.9 ms vs branch 1331.8 ms. Paired diff median +10.0 ms, mean +17.8 ms (sd 98). The branch was faster in 4 of 9.
- load1 7-31: 5 pairs, paired diff median 0.0 ms (sd 561).
- load1 98-108: 7 pairs, dev median 6725 ms vs branch 6485 ms. Paired diff median -240 ms (sd 896). The branch was faster in 4 of 7.

There is no regression. The loop time saved (10-34 ms at low load, 116-256 ms at high load) is below Enter-to-POST's noise floor, because that interval is dominated by worker-side preparation. At high load the saving shows as the end of a 100-250 ms UI-loop block during the send.
