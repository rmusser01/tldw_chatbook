## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`SubscriptionsDB.transaction()` rolls back only on `Exception`, on a thread-local connection that is reused and uses implicit BEGIN. When a `BaseException` (KeyboardInterrupt, SystemExit, GeneratorExit) leaves the block, the depth counter resets while the SQLite transaction stays open: a sandboxed probe showed `in_transaction=True` afterwards and the next `transaction(immediate=True)` failing with 'cannot start a transaction within a transaction'; with a plain `transaction()` the abandoned writes are committed by the next caller. Kanban and Scheduling close their connection in `finally` and are not affected. Related: TASK-34905 and TASK-33132 own the wider consolidation.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F13; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

1. Change `except Exception` to `except BaseException` in `SubscriptionsDB.transaction()`.
2. Parametrized regression test (plain/immediate) in `Tests/DB/test_subscriptions_db.py`.
3. Audit the other hand-rolled transaction managers.
