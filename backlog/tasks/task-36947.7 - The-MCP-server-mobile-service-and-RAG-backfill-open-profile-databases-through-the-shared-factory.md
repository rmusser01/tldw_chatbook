## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ADR-250 (accepted 2026-10-27) adopts one shared profile-storage factory, so that every composition root opens the profile databases with the same options. Today the standalone MCP server, the mobile web service and the RAG backfill CLI each construct their databases ad hoc, with options that differ from root to root. The owner ruled (ADR-250 Q5) that one task, separate from TASK-36947.2, moves these three roots onto the factory. The owner also ruled (Q2) that the roughly 30 ad hoc database constructions inside the app stay as they are, held by a census so that their count cannot grow.

Source: ADR-250 §6 and its owner rulings; architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F1 and §F9.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The standalone MCP server, the mobile web service (its chat engine and its reading path) and the RAG backfill CLI construct no database class directly; each gets its profile databases from the shared factory (ADR-250 §6)
- [ ] #2 When each of the three roots shuts down, it closes every database it opened, and the mobile engine still quiesces its chat database before closing it
- [ ] #3 A profile database that has not been upgraded and is first opened through the mobile reading path migrates with the Console Library migration seed applied, as it does through the other roots
- [ ] #4 A census pins the count of ad hoc profile-database constructions inside the app, and a new one fails a check that CI runs
<!-- AC:END -->
