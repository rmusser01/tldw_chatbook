## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
ADR-250 (accepted 2026-10-27) adopts one shared profile-storage factory, so that every composition root opens the profile databases with the same options. Today the standalone MCP server, the mobile web service and the RAG backfill CLI each construct their databases ad hoc, with options that differ from root to root. The owner ruled (ADR-250 Q5) that one task, separate from TASK-36947.2, moves these three roots onto the factory. The owner also ruled (Q2) that the roughly 30 ad hoc database constructions inside the app stay as they are, held by a census so that their count cannot grow.

Source: ADR-250 §6 and its owner rulings; architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F1 and §F9.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The standalone MCP server, the mobile web service (its chat engine and its reading path) and the RAG backfill CLI construct no database class directly; each gets its profile databases from the shared factory (ADR-250 §6)
- [x] #2 When each of the three roots shuts down, it closes every database it opened, and the mobile engine still quiesces its chat database before closing it
- [x] #3 A profile database that has not been upgraded and is first opened through the mobile reading path migrates with the Console Library migration seed applied, as it does through the other roots
- [x] #4 A census pins the count of ad hoc profile-database constructions inside the app, and a new one fails a check that CI runs
<!-- AC:END -->

## Implementation Plan

1. `app_services.py`: add `ProfileStorage.close()` (closes each opened database's calling-thread connection, logs failures by type name, never raises), one opener per database (`open_chachanotes_db`, `open_media_db`, `open_prompts_db`, `open_workspace_db`, `open_agent_runs_db`; DB classes imported inside them; ChaChaNotes always gets the Console Library migration seed, `check_integrity` as given, built-ins only when `seed_builtin_content`), and `open_profile_storage(...)` with the ADR-250 section 6 signature (closes what it opened and re-raises on a failure).
2. Standalone MCP server: `_init_databases` gets ChaChaNotes and Media from `open_profile_storage`; `main()` closes the storage in a `finally`.
3. Mobile service: the engine opens chat/workspaces/runs through the factory and keeps the storage on `_Engine`; shutdown stops the controller, quiesces the chat DB, then calls `storage.close()`. The reading path opens notes+media through the factory (gaining the migration seed); shutdown closes that storage.
4. RAG backfill CLI: open only the needed paths through the factory and close in a `finally`.
5. Census (Q2): a test in `Tests/Architecture/test_application_services_bundle.py` pins per-file counts of constructions of the five ProfileStorage database classes outside the openers; a new one fails.
6. Tests: factory (opens, failure closes and re-raises, close never raises), each root's shutdown closes what it opened, mobile reading path migrates a v47 database with the seed (red at base). Run covering tests, Tests/Architecture serially, preflight, size and boot-import ratchets.

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
- **Factory** (`tldw_chatbook/app_services.py`, ADR-250 s6): `open_profile_storage(*, client_id, chachanotes, media, prompts, workspaces, agent_runs, seed_builtin_content=False, check_integrity=False)` with the exact s6 signature, one opener per database (`open_chachanotes_db`, `open_media_db`, `open_prompts_db`, `open_workspaces_db`, `open_agent_runs_db`; each imports its DB class in its body, so module level stays stdlib-only), and `ProfileStorage.close()` (closes the calling thread's connection on each opened DB, logs a failure as `database=<type> error=<type>`, never raises). ChaChaNotes always gets `config.load_console_library_migration_seed()`; `check_integrity` reaches the three DBs that have a startup check; built-ins are seeded only when `seed_builtin_content` is set (no caller sets it yet; the TUI's opens move in TASK-36947.6). If an opener raises, the factory closes what it already opened and re-raises.
- **MCP server** (`MCP/server.py`): `_init_databases` sets `self.storage = open_profile_storage(client_id=CLI_APP_CLIENT_ID, chachanotes=..., media=...)` and aliases `chachanotes_db`/`media_db` to it; `main()` closes it in a `finally`.
- **Mobile service** (`Web_Server/mobile_service.py`): the engine opens chat/workspaces/runs through the factory and keeps `storage` on `_Engine` (replacing `workspace_db`/`agent_runs_db`); the reading path keeps one `_reading_storage` (notes + media), so a not-upgraded profile DB first opened there now migrates with the seed. `shutdown()` closes the reading storage first (as before), then stops the controller, quiesces the chat DB (`quiesce_connections(timeout_seconds=5)`), then `engine.storage.close()`. As before, a chat DB whose quiesce raises is not closed (`replace(storage, chachanotes=None)`); the workspaces and runs DBs still close. Closing after a failed quiesce is not clearly safe: the quiesce raises when active use has not drained (`TimeoutError`), when another barrier is active, or partway through `close_registered`, and a close after a partial `close_registered` could meet a handle it already closed. So today's skip is kept (ADR-250 s6: "keeps today's order").
- **RAG backfill** (`RAG_Search/backfill.py`): opens only the paths its item types need and closes the storage in a `finally` (it never closed before).
- **Census (AC#4, Q2)**: `test_no_new_ad_hoc_profile_database_construction` in `Tests/Architecture/test_application_services_bundle.py` pins per-file counts of constructions of the five ProfileStorage classes (`CharactersRAGDB`, `MediaDatabase`, `PromptsDatabase`, `WorkspaceDB`, `AgentRunsDB`, aliased imports included) outside the openers' bodies: 37 sites in 16 files. - **Follow-up (not filed; for the coordinator): close the MCP server's off-thread handles.** The MCP note tools reach `NotesInteropService._get_db(user_id)` through `asyncio.to_thread`, and every close here is thread-local: `NotesInteropService.close_all_user_connections()` and `close_user_connection()` exist, but called from `main()` they would release nothing the worker threads hold. The same applies to `storage.close()` in `main()` (ADR-250 s5: "the calling thread's connection"). Releasing those needs a quiesce-style close (`quiesce_connections` closes every registered same-file handle), not another call to the existing close methods.
- **Open owner question (ADR-250, not resolved here): the MCP server's read-only `SubscriptionsDB`** (`MCP/local_server_tools.py:116`, in a provider shared with the in-app Hub). s2 rule 3 says: "A database that a second root starts opening moves into `storage` when that root migrates. The one case today is the MCP server's read-only `SubscriptionsDB` (`MCP/local_server_tools.py:116`)." This task migrates that root, but the s6 signature, `open_profile_storage(*, client_id, chachanotes, media, prompts, workspaces, agent_runs, seed_builtin_content=False, check_integrity=False)`, has no subscriptions path, and the s6 table gives the MCP server `open_profile_storage(client_id=CLI_APP_CLIENT_ID, chachanotes=get_chachanotes_db_path(), media=get_media_db_path())`. Either the signature gains a read-only subscriptions path or rule 3 is amended. `SubscriptionsDB` is not one of the five census classes.
