## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Three gestures reach _request_settings_close (:4041-4054) through request_safe_cancel: Esc (bound at Widgets/Console/console_settings_modal.py:1140), a backdrop click, and the Cancel button (:4250-4253). That method checks only for a pending memory reset or a running compaction, then dismisses. An edited draft is therefore thrown away without a word (C8(2)).

ADR-031's task-16211 refinement sets three rules:
- A generic gesture never discards by itself.
- The modal owns its dirty guards.
- Any displayed Escape hint must describe the action that is actually active.

No existing task covers this: task-32864 lists this modal as out of scope (:27).

The existing close guard (#console-settings-close-guard, :2611-2631), with its reset and compaction modes, is the seam to extend. The only tests that pin this path use unedited drafts: test_console_settings_modal_cancel_discards_draft (Tests/UI/test_console_session_settings.py:5254) and test_console_settings_modal_escape_dismisses_none (:5302).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Esc, a backdrop click and Cancel now ask before an edited Chat settings draft is thrown away; an unedited draft still closes at once.

**Approach.** The logic lives in a new module, `Widgets/Console/console_settings_unsaved.py`, imported only by the modal (it stays off the `_ui_ready` path). It holds pure helpers and a mixin that `ConsoleSettingsModal` inherits. The modal keeps only the wiring: +9 lines, 7,751 -> 7,760, ratchet row 7,790 untouched.
- **What counts as an edit.** Everything Apply to this chat commits: provider, model, endpoint, the 14 generation fields, the 9 context-policy fields and "Your name in this chat". Values are compared by effective value (0.70 == 0.7; putting the old value back is not an edit). A field's baseline is the chat's committed value when the modal opened with it already changed (a quick-surface transfer or a suspended draft). Otherwise it is the value the controls show once the modal's initial sync finishes (`_finish_initial_feedback_sync`). The second rule stops values the controls only normalize at mount from reading as edits, such as a blank committed endpoint shown as its configured default; a committed-only baseline fails 4 tests. An invalid Context value counts as one edit, "Context and memory".
- **ChatScreen** now passes the chat's committed settings as the modal's existing `settings=` argument (one changed line, no added line; the modal already takes its draft from `transfer`/`suspended_draft` when either is given). So an edit carried in from Alt+M counts.
- **The prompt** is a third mode of the existing close guard, after the memory-reset and compaction modes. It names the edited fields, prints "Enter apply · d discard · Esc keep editing", and shows **Apply to this chat** (focused), **Discard** and **Keep editing** (the Return button, relabelled). Esc or a backdrop click inside the prompt means Keep editing. `d` discards only while a prompt button has focus. Apply runs `_submit(APPLY_TO_CHAT)`, the footer Apply's own path; an invalid draft keeps the modal open with its validation summary and focus back on the edited field. When the footer's Apply is unavailable (disabled or hidden), the prompt's Apply is disabled, focus lands on Keep editing, and the key line drops "Enter apply".
- **Precedence.** Reset first, then compaction, then unsaved. Their copy and buttons are unchanged. Answering the reset guard ("Undo and close" / "Keep reset and close"), or the compaction guard's "Close anyway", now opens the unsaved prompt instead of closing. Discard then runs the original close.
- **Esc hint.** A footer label left of Cancel reads "Esc close", or "Esc close (asks: N unsaved)". It re-reads after every Input/Select change and button press (named `on_*` handlers in the mixin; a plain mixin cannot carry `@on`). It is a `Label`, so it is auto-width under every stylesheet. No CSS was added.

**Rulings.**
- The Apply button reads "Apply to this chat" as AC#2 says, although the footer button's runtime label is "Use for this conversation" (`_sync_action_copy`).
- Enter activates the focused prompt button. Apply is focused by default, so after a Tab, Enter follows the focused button.
- The Esc hint covers unsaved edits only (AC#6). While a memory reset is pending or compaction is running, it still reads "Esc close" even though Esc then opens that guard. That was already true before this task, which added the hint.
- AC#7: `Tests/UI/test_console_modal_dismissal.py` has 6 red nodes. The same 6 fail on the same assertions at the task base (735295adbb) and at the phase base (d6c3faed60). This task adds none.
