## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
F6 is the app-global 'next pane' key and is advertised in the footer (app.py:7750; ADR-031 rule 1). The app hands it to the active screen's action_focus_next_workbench_pane and otherwise shows 'No workbench pane focus target is available.' (app.py:20175-20186). SettingsScreen (UI/Screens/settings_screen.py:2731) defines no handler, so on Settings F6 only shows that notice. Docs/User_Guide/settings.md:877 records this as a known limitation.

This breaks ADR-031 rule 4, which says advertised keys must work. It also leaves Settings as the one workbench whose panes can be reached only with Tab: Model is Tab stop 23.

Personas, Library and Workflows already cycle panes with the shared focus_relative_workbench_pane helper (Widgets/workbench_focus.py:20). See personas_screen.py:16333-16347, and its shift+f6 binding at :1086. The Settings panes are #settings-category-pane, #settings-detail-pane and #settings-impact-pane (settings_screen.py:22436-22476). Related: TASK-2831 (category focus intent lost in recompose races) touches the same rail focus path.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- Root cause: SettingsScreen had no action_focus_next_workbench_pane, so the app-global F6 (app.py action_focus_next_workbench_pane) fell through to its 'No workbench pane focus target is available.' notice, and nothing bound Shift+F6.
- Fix (UI/Screens/settings_screen.py): action_focus_next_workbench_pane / action_focus_previous_workbench_pane over the shared focus_relative_workbench_pane helper, which is unchanged (ruling R13). The targets are rebuilt on every press by _workbench_focus_targets: the rail's ACTIVE category row, falling back to the category filter when a search hides that row; the detail pane and the inspector each get their first focusable control in focus-chain (Tab) order, with the pane's plain VerticalScroll body sorted last, so the body is the stop only for a pane with no control (a read-only inspector, where focus still lets the arrow keys scroll it). Per-press targets are what make AC#2 hold right after a category switch; a static tuple would aim at the previous category. Shift+F6 is a screen binding (show=False, priority=True, Personas precedent); F6 stays app-global (ADR-031 rule 1 reserves it), and the app already delegates it to the screen.
- Test: test_settings_f6_and_shift_f6_cycle_rail_detail_and_inspector in Tests/UI/test_workbench_pane_focus.py, under private_profile_test so it runs locally despite ADR-126. It boots the production app on Settings at 211x44 and uses real key presses only: F6 x4 (rail active row, detail control, inspector, wrap), Shift+F6 x3, a category switch with Down/Enter, F6 from the Appearance font-size field (value unchanged), F6 back into the rail on the new active row, and '/privacy' hiding the active row (rail stop = the filter). It records app.notify and asserts the notice never fired. RED at BASE: F6 left focus on nav-home. Negative controls: a static rail id, dropping the body sort, and dropping the filter fallback each fail it.
- Regression: 12 related files (Settings keyboard/footer/help/hub/destination shells plus the workbench focus suites) have identical failure name sets at BASE and HEAD (447 each, 443 of them ADR-126 RecoveryRequired, 4 pre-existing assertions); the only new test passes.
- Live (AC#6): tmux at 211x44 on a scratch profile (users_name verify_mc33001_t4). From the nav bar F6 went Overview row -> Backup & Restore -> Open Theme editor -> Overview; Shift+F6 reversed it. After Down x4 + Enter opened Appearance, F6 reached the Theme select (inspector: 'Focused setting: Theme'), Tab reached Palette limit, F6 moved to the inspector with the field still reading 1, and the next F6 landed on the Appearance row. Each stop was confirmed by the focus-help line and by the focus tint (48;2;39;39;39) moving onto that row; the notice never appeared. The real profile's mtime fingerprint (153 entries) was identical before and after.
- Docs/User_Guide/settings.md: the 'F6 does nothing' paragraph is replaced by F6 and Shift+F6 rows in the keys table; the F1 sentence that shared the paragraph is kept as its own paragraph; a Verified-against stamp records the live drive.
