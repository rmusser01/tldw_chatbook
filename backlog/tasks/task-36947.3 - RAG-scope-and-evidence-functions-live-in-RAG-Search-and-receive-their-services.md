## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`Event_Handlers/Chat_Events/chat_rag_events.py` is a RAG application service: 22 of its 36 functions take the whole app, and `RAG_Search/pipeline_loader.py:23` imports it at top level, so the RAG pipeline depends on an event-handler module.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F1, F15; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The RAG scope, evidence and authorization functions live in RAG_Search and take explicit dependencies instead of the app
- [x] #2 RAG_Search no longer imports Event_Handlers
- [x] #3 The app string-lookup ratchet is lowered by the lookups this removes
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. New `RAG_Search/scope_evidence.py`: the scope resolution, prompt-boundary authorization and evidence capture code from `chat_rag_events.py`, taking `storage` (ProfileStorage), `workspace` (WorkspaceServices), `citation_trace_repository` and a lazy scope-cache callable instead of the app. Imported lazily by the event wiring so it does not join the UI-ready module set.
2. The pipeline search entry points (`perform_*`, `format_results_for_llm`) move next to `execute_pipeline` in `RAG_Search/pipeline_builder_simple.py`; `pipeline_loader` imports them from there, so RAG_Search no longer imports Event_Handlers. Delete the two layer allowlist rows.
3. `chat_rag_events.py` keeps the event wiring only: active-session lookup, the app-attached scope cache, notifications, the legacy sidebar entry point, and app-taking wrappers that pass slices from `app.services`.
4. Retarget test patches of moved names; give app doubles a `services` view; re-publish the bundle in tests that swap DB aliases on a real app. Prove each retargeted patch is still reached.
5. Lower the Event_Handlers row of the app string-lookup census by the measured drop; run boot-import censuses (twice for ui-ready), covering tests, Tests/Architecture serially, preflight.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
- New `tldw_chatbook/RAG_Search/scope_evidence.py`: scope resolution (`resolve_scope_for_session`, the existence and fresh-authority reads, `ScopeResolution`), prompt-boundary authorization (`authorize_local_results_for_prompt`, `assemble_local_evidence_for_prompt`) and evidence capture (`capture_local_pipeline_results`, `capture_console_staged_evidence`, `capture_console_prepared_evidence`, `create_local_capture_builder`, `LocalRagContextResult`, `RequestScopeSession`). Each takes the ADR-250 §7 slices (`storage: ProfileStorage`, `workspace: WorkspaceServices`, the citation trace repository) plus narrow callables (`scope_cache`, `active_session`); none takes the app. Bodies are moved verbatim apart from the dependency reads; all 30 moved diagnostics keep their statement digests (checked with `check_persistent_diagnostic_inventory.py --statements --since 5a024396fc`; removed and added multisets equal), and the inventory was regenerated.
- The pipeline search entry points (`perform_plain_rag_search`, `perform_full_rag_pipeline`, `perform_hybrid_rag_search`, `perform_search_with_pipeline`, `format_results_for_llm`) moved next to `execute_pipeline` in `RAG_Search/pipeline_builder_simple.py`. They still forward the pipeline's `app` argument, because `execute_pipeline` and the pipeline loader's `func(app, query, sources)` contract already take it inside RAG_Search; narrowing that is outside this task's scope/evidence/authorization criterion.
- `Event_Handlers/Chat_Events/chat_rag_events.py` (2,220 -> 769 lines) keeps the wiring only: the app-taking wrappers (same names and signatures, so `retrieval.py` and `console_runtime.py` are unchanged) read `app.services.storage`, `.workspace` and `.chat.citation_trace_repository`; `_active_console_session`, the app-attached `_scope_cache_for` (passed as a lazy callable, so a cancelled resolution still never attaches a cache), notifications, the legacy sidebar entry point, and the RAG-availability probe. It imports `scope_evidence` inside each wrapper, so the module stays off the UI-ready set; it is listed in `Chat/console_first_send_modules.py` because an evidence-bearing send imports it.
- AC#2: `pipeline_loader.py` imports `pipeline_builder_simple` instead of `chat_rag_events`; no RAG_Search module imports Event_Handlers. Both `pipeline_loader -> chat_rag_events` rows (top and lazy) are deleted from `layer_direction_allowlist.tsv`; no row added. Red: re-adding the top-level import fails `test_no_new_upward_import` (domain -> presentation); green after revert.
- AC#3: `app_lookup_census.tsv` Event_Handlers 50 -> 41, measured (3 `media_db` + 4 `chachanotes_db` + `workspace_registry_service` + `citation_trace_repository` literal getattr lookups removed). RAG_Search stays 3.
- Tests: patches of moved names retargeted to `scope_evidence` / `pipeline_builder_simple` (`_resolve_scope_with_current_ids` x5, `_sensitive_fetchall` x3, `_read_fresh_conversation_metadata_sync`, `asyncio.to_thread`, `resolve_scope_for_session` x2, `_authorize_local_results_for_prompt`, `_current_local_evidence_ids`, `MarkerNamespace`, `execute_pipeline` x2). Patches of names still bound in `chat_rag_events` (`perform_*`, `capture_console_staged_evidence_for_chat`, `_active_console_session`, `resolve_semantic_rag_service`) still reach, because the wiring looks them up there at call time. Proof: each retargeted or kept patch site was neutralised in turn and its test run; 36 of 38 sites failed, the other two are the strict-xfail `test_rag_ui_integration` cases, which xfail either way. Two tests passed with their patch neutralised and were made discriminating: `test_failed_authority_or_existence_read_rejects_every_candidate` (now uses a readable media DB, so only the failed scope authority rejects the candidate) and `test_rerank_removal_does_not_mutate_global` (now asserts the patched pipeline ran without the rerank step).
- App doubles get the slices from new `Tests/app_services_doubles.py` (`AliasServices` reads the double's alias attributes at access time). Real factory apps that swap an alias call `app._publish_application_services()`; `attach_chachanotes_db` in `Tests/UI/app_factory.py` now does so.
- Boot: `test_app_import_own_module_count_stays_at_the_post_diet_size` 687/688; `test_ui_ready_module_census_stays_at_the_pinned_size` 1038, 1038, 1037 over three runs (drift +0); no pin raised.

Tests/Architecture serial: 7 failed, all in `arch-base-u-5ca7.txt`. Preflight passes.
