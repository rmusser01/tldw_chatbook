## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-34100.2's pre-merge review (M-5, 2026-11-12) found that the model switcher judges a model's capacity without knowing which endpoint the chat would send to. Its Enter and save refusal ("Replies fill <model>'s context window: lower Max tokens, then Enter.", `ConsoleModelPopover._submit` in `Widgets/Console/console_model_popover.py`) and its row words (`model_level_not_ready_words`, which Settings' Readiness row also uses) call `console_reply_capacity_exhausted` with no endpoint. `ConsoleSendOutcomes.window_for(..., None)` then accepts a context window that a different endpoint of the same provider reported. Readiness (the header's `capacity_exhausted` blocker) passes the send endpoint, so it does not.

The case is narrow: the same model id on two endpoints of one provider, for example two Custom OpenAI-compatible servers, or a local engine moved to a new port. There, a small window reported by server A can refuse Enter, or mark the row 'Not ready · window too small', for a chat that sends to server B, while the header says Ready. The reverse can also happen. The goal is that the switcher, Settings' Readiness row and the header judge a pair against the same endpoint's window, so they never disagree about whether a send would be refused.
<!-- SECTION:DESCRIPTION:END -->
