## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-33621.21 bounded 'Preparing speech model…' with a no-progress watchdog. It counts bytes landing in huggingface_hub's default cache (HF_HUB_CACHE) and ends the attempt after dictation.model_prepare_stall_seconds (default 120) without growth. Three working cases show no growth there: lightning-whisper-mlx downloads with hf_hub_download(local_dir='./mlx_models/<name>'); NeMo NGC model names download into NeMo's own cache; and a cached multi-gigabyte model can spend longer than the bound loading and transcribing silence with no bytes at all (qwen2audio on CPU). Each of these now ends as 'showed no download progress for 120 seconds'. The copy says what was measured and names the setting, but the user still loses a working attempt. Not a regression where dev hung forever (macOS), but a possible one for a slow cold load that used to finish.
<!-- SECTION:DESCRIPTION:END -->
