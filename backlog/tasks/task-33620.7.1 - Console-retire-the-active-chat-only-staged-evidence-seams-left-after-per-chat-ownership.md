## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-33620.7 moved staged evidence and its sent-sources receipt onto ConsoleRuntime, one value per chat. Two older seams still assume one app-wide value keyed to the active chat. The retrieval controller's capture and release paths (and ChatScreen's release/clear-receipt helpers) are overridden by the runtime seam in production, so they are effectively dead, but a future rewire would bring back the cross-chat behaviour TASK-33620.7 fixed. The navigation snapshot/restore payload also carries only the active chat's staged state: harmless while the runtime is app-owned (restore is a no-op), but a freshly built runtime would restore only one chat's staging.
