## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The TASK-33621.13 W003 investigation found that the check flagged the three hook-review freezes only by accident. It resolved ConsoleHooksController's self._review BY NAME to an unrelated BuddyManagementModal._review. It cannot follow the real chain, a lambda built in wiring.py, and it does not model push_screen(callback=) plus an awaited future, which is a deadlock rather than NoActiveWorker. Renaming the unrelated method would silently 'resolve' those census rows while the freeze remained.

Status after PR #2944 (TASK-33621.13, three checkpoint-reviewed rounds): ACs #1-#3 are delivered there.
- Rows are keyed by entry point plus push site.
- `self.x()` resolves through MRO, subclasses and mixin hosts, never to an unrelated class by name.
- Lambdas and local rename chains are followed.
- A future created, pushed with `callback=` and awaited in ONE function is flagged.

Tick #1-#3 when #2944 merges. What remains is #4: a hand-rolled wait split across functions. A helper creates the future, pushes with callback=, and returns it or stores it on self, and the caller awaits it. A scan found 5 such helper shapes in the package (buddy_speech._confirm_destination, chunking_lab_screen._dialog, ...). The strict xfail `test_w003_a_hand_rolled_wait_split_across_functions_is_a_known_miss` pins the gap (raised by a review thread on #2944).

From the PR #2944 round-6 review (after 901a2ab1a4, where a class body's bare name reads its own class first):
- Class-body assignments also enter the package-wide alias table, which a bare name's ('funcs', x) fallback reads. So an unrelated module's bare imported choose() can over-match another class's `choose = _pick`. This has no effect on the real tree.
- The rule that a class body never reads its base classes is not pinned by a test.
- A class defined inside a function cannot see the enclosing function's locals: _collect_module resets fn to None at a ClassDef, so `choose = _pick` naming a waiting nested function is missed.
