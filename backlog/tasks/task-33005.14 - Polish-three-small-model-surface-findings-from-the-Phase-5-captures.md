- AC#1: superseded by TASK-33007.2. Settings' key check is the compact `Test (t)` action (`KEY_CHECK_ACTION_LABEL`, UI/Settings_Modules/providers_models_card.py), deliberately not a Tab stop; `t` runs it. Nothing renders as a section heading any more.

- AC#2: the provider column of a pair row was a fixed 20 cells (`_PROVIDER_COLUMNS`), so "Custom OpenAI-compatible" and "Custom OpenAI-compatible #2" read "Custom OpenAI-co…ble" and "Custom OpenAI-co… #2" in the 140-column box. `_rebuild_rows` now sizes the column as it already sized the model column: the longest provider name the pair rows show, as far as the list still fits the whole row (model, context and readiness columns, `_OTHER_COLUMNS`, and the longest note), and never below 20. So at 211x44 and 235x52 (a 134-cell list, room for 39 beside a 28-cell model column and a 27-cell note) names show whole, while a narrower window, or a list widened by a long model id, keeps today's 20-cell cut in the middle (`_fit`) and every note whole. The list width is read where NOT RUNNING already read it (`_list_width`, shared with `_packed`); `on_resize` rebuilds the rows, so a resize re-sizes the column.
- A first version let the name take the room before the note did (the note was cut instead). It turned `Tests/UI/test_console_switcher_local_probe.py::test_the_not_running_line_wraps_so_every_name_shows_whole[120x44|211x44-shrunk-to-120x44]` red (a row's "Enter: add key in Sett…" ended in an ellipsis at 120 columns), so the note now keeps its room; that test passes unchanged.
- Tests (Tests/UI/test_console_model_switcher.py, gated whole): new `test_provider_names_show_whole_while_the_list_has_room[211x44|235x52|120x44]` reads the painted rows: both names whole at the two full-screen sizes, both cut in the middle at 120 columns, notes whole and readiness in one column on every row.
