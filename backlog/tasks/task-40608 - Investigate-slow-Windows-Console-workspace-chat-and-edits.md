## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
On Windows, a Console turn that answers a simple question about a bound README took over three minutes. A follow-up that reads, edits, and inspects the diff for a two-line Python file took nearly five minutes. Both turns completed successfully against a scripted HTTP provider on loopback. The timings include Chatbook, tool calls and approval handling. The time spent at each boundary is still unknown.

### Reproduction

1. Use Windows 10 build 19045 and Python 3.12.10. Start Chatbook with a fresh private profile, a local llama.cpp-compatible endpoint, and **Full agent tools** enabled. The measured build was [`b6b53f084a`](https://github.com/rmusser01/tldw_chatbook/commit/b6b53f084a63058ca4b4dac99e074cff42192f7e). For a controlled baseline, run `python -m pytest -q "Tests/QA/test_project_chat_uat.py::test_project_chat_uat[native]"` with the repository test dependencies and a private Windows test root.
2. Create a disposable Git repo in a folder with spaces and `é` in its name. Add a README with a unique verification code, an `AGENTS.md` that points to the README, and a `main.py` with `clamp_minutes(minutes)` returning `min(minutes, 60)`. Commit the fixture locally.
3. In Console, open **Workspaces → New**, add the folder, create and switch to the workspace, then open a new chat. Leave the folder read-only. Send “Inspect this project's README. Summarize what it does and include its verification code.” Proceed when the project-instruction disclosure appears. Time from Send to the completed answer and verify the exact code.
4. Open **Settings → Workspaces**, select the workspace and grant the folder read-write access. Return to the same chat. Send “Fix the negative-duration bug in main.py while keeping the 60 minute cap. Read the source, make the smallest change, then inspect the Git diff.” Use **Once** on the read, edit, and diff approvals with the default Ask posture. Time the turn and record the approval wait separately. Verify that only `main.py` changes and that a negative, ordinary, and over-cap input all pass their unit tests.
