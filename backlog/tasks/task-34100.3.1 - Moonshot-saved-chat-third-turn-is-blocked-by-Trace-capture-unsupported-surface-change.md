## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by TASK-34100.3's live verification. That task made Moonshot (Kimi) replies persist in a saved chat, which made a later turn reachable for the first time. The trace planner is not in that task's diff, so the defect is filed here rather than fixed there.

Every model Moonshot lists returns reasoning on each reply, and Console saves it with the reply so the next turn can replay it. With trace capture on (the default), turns 1 and 2 of a saved kimi-k3 chat reply normally. The third send stops before the provider: "Trace capture blocked · Problem: Trace capture could not be saved · Impact: The provider was not contacted", with Retry capture / Send without capture / Cancel send. The log records `phase=trace_reservation status=failed error_category=unsupported_surface_change exception_type=ValueError`. Send without capture then gets the right reply, so only the trace stage fails. A real OpenAI chat on the same build completes three turns, so the failure is specific to replayed continuations.

Likely mechanism (from `ConsoleTraceService` surface planning, `Chat/console_trace_service.py`, the `matches`/suffix loop that raises `unsupported_surface_change`): turn 2's request is [history…, continuation 1]; turn 3's is [history…, assistant 2, user 3, continuation 1, continuation 2]. The planner admits "new messages before an unchanged continuation suffix", but here the continuation list also grows, so the request has two change points and is refused. This is the same family as TASK-33621.29 (Compact now) and TASK-31742 (completed tool turn), whose notes record that a new admission shape changes the trace-admission contract governed by ADR-097 and needs design approval first.

Two more things seen in the same run, possibly related:
- On that blocked turn, **Cancel send** refused with "Trace reservation status is unavailable." Send without capture worked.
- After a relaunch, the earlier turn-2 assistant message showed an extra "▸ Error · failed" row. It comes from the blocked turn's agent run (`42a3245d…`, "unexpected provider error (Provider call trace persistence f…"), which is now drawn on the wrong message.

Evidence (setup-wizard-ux-qa): `evidence/g3-live/07-k3-saved-turn-two.txt`, `08-k3-saved-turn-three.txt`, `09-k3-turn-three-send-without-capture.txt`, `12-turn-four-cancelled.txt`, `18-relaunch-history-chat.txt`; `homes/g3-live1/.local/share/tldw_cli/default_user/tldw_cli_app.log` (`unsupported_surface_change` at 19:09:07); OpenAI control `evidence/g3-live-regress/06-08-openai-*.txt`.
