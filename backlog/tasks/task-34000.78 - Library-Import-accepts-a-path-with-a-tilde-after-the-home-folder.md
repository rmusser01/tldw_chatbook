## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: TASK-34000.20 made Library › Import expand a leading `~` before validation, so `~/Documents/x.md` is now read as the home folder. The pre-check still refuses a path whose expanded form contains the two characters `~/` anywhere AFTER the home folder -- `~/backup~/x.md`, `/Users/me/old~/notes.txt` -- because `validate_path_simple` in `Utils/path_validation.py` scans the whole string for the `"~/"` substring as a "dangerous pattern". A folder named `backup~` is an ordinary name (editors leave `name~` backups behind), and the file exists; the user is told it is a security risk.

This is pre-existing (found by the TASK-34000.20 review, 2026-10-23) and separate from the leading-`~` fix: the guard's intent (TASK-32927) is to refuse an UNEXPANDED home shorthand, which only a leading `~` can be. Any change must keep every other caller of `validate_path_simple` refusing an unexpanded leading `~/`.
<!-- SECTION:DESCRIPTION:END -->
