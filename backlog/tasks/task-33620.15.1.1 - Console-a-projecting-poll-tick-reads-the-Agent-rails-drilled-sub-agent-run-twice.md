## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in the pre-merge review of TASK-33620.15.1 (2026-10-20). The config-sync cadence reads the Agent rail's section lines and fleet rows as projection inputs on every 0.2 s poll tick, and a tick that projects then computes the same lines again to render them. While the rail is drilled into a sub-agent each computation makes one subagent-run DB read, so a projecting tick makes two where dev made one, and a skipped tick still makes one. The cost is small (one keyed read) but it runs at the poll's rate during a run and is pure duplication.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** A Console poll tick now reads the Agent rail's drilled sub-agent run once. The tick (`config_sync.project_console_tick`) runs its input read and its projection inside the Agent controller's `tick_reads_shared()` scope, and the render reuses the record the input read (`ConsoleAgentController._drilled_run_record`). Outside a tick every computation reads the record afresh, as before.

**Measured first (dev 3be493413a).** A mounted Console drilled into a real `AgentRunsDB` sub-agent run, ticks driven through `project_console_tick` and counted on the loop thread: a projecting tick read the run 2 times (the input read and the render), a skipped tick once.

**Why the decision stays correct.** Both reads happened in the same synchronous tick, so nothing on the loop could change in between. The render now shows exactly the lines the cadence recorded as its inputs, so the next tick's comparison is against what is on screen. A record that the agent's worker updates after the tick is the next tick's input change, which projects it, as before.

**Tests.** New `Tests/UI/test_console_agent_drill_tick_reads.py` (2 cases, plain and resumed run, the second also reads the continuation budget inside the same read), `bootstrap_profile`, passes under the plain command. On dev both fail at `assert 2 == 1` ("a projecting tick read the drilled run 2 times"). Mutation: making `_drilled_run_record` always read turns both red again. One node id is added to the UI PR gate census tail (floor 908 -> 909).
