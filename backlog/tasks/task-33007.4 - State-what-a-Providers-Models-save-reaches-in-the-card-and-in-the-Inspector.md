## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Nothing on the card says who a save affects.
- The Inspector for this category leads with 'Affects Console and provider-backed generation.' (settings_screen.py:22230-22240).
- The card ends in catalog, key-policy, manual-entry and sampling-route prose plus a raw endpoint-key row (:17410-17438). The review scored these as config keys in the UI.

The scope depends on the state of the open chat:
- ADR-095 (095:23-28) keeps open conversations that hold work on their own settings.
- Owner decision D1 (shipped in phase 1) makes an untouched open chat converge to newly saved defaults whatever its readiness. An untouched chat has no messages and no edited fields.
- The copy must therefore name the open chat and say which case applies to it. The per-chat way to switch is Switch model (Alt+M, phase 4).

Precedent: Settings already reads the active Console session through the app's console runtime (_current_reasoning_target, :6094-6108).

Two tests pin the prose inside the card:
- Tests/UI/test_settings_configuration_hub.py:3635 (test_settings_provider_category_lists_console_supported_catalog; it reads #settings-provider-catalog at :3658).
- :4366 (test_settings_provider_model_defaults_appear_before_reference_copy).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The card and the Inspector now say who a Providers & Models save reaches, and the
card's reference prose moved into one closed "config key" disclosure in the Inspector.

- **Applies-to row (AC#1).** Directly under the Default model row (`#settings-model-applies-row`,
  text `#settings-model-applies-to`): "new chats (Ctrl+T, temporary, workspace)." then the
  open Console chat by title and the provider · model it will use: the card's pair when the
  chat follows the saved defaults ("Open chat “Chat 1” is unused and will use OpenAI ·
  gpt-4.1."), its own pair when it holds work ("Open chat “Refactor plan” keeps Ollama ·
  qwen3:32b."), or "No Console chat is open." Refreshed with the card's dynamic rows
  (provider/model change, save, revert). A title over 24 characters is cut with "…", and
  the row wraps to a second line rather than cutting off the pair.
- **One D1 predicate.** The convergence test moved out of
  `_maybe_refresh_stale_default_console_settings` into the module-level
  `follows_saved_defaults(store, session, default_generation)` in
  `UI/Console_Modules/session.py` (behaviour-identical: generation, settings None,
  user work / baseline, messages). The Console's convergence and the Settings row both call
  it, so the row cannot say something the Console then does not do.
- **Inspector (AC#2-#4), spec mock (c) order** (`compose_providers_models_inspector` in
  `providers_models_card.py`, imported lazily): **Applies to** (New chats · Unused open
  chats · Chats with work + Alt+M · Model defaults reach chats that switch to this model),
  **Next new chat will use** (`blank_console_session_settings` over the saved config, the
  function a Ctrl+T chat is built with: pair, then "T · max · stream"; "Unsaved edits apply
  only after save (s)." while the category is dirty; re-said after a save), **Focused field
  guide** (the phase-2 field-table help and range; the "Saved as" row is no longer shown),
  then the closed one-row **config key** disclosure, then **Key** (the readiness label moved
  here from under the old "Affects Console and provider-backed generation." header, which
  is gone).
- **config key disclosure (AC#4, AC#5, R7).** `SettingsScreen._config_key_disclosure(*rows,
  identifier=...)` (a collapsed `Collapsible` titled "config key", class
  `settings-config-key-disclosure`) and `_split_config_key_row` are generic, for T7's
  Console Behavior branch. It holds the focused field's "Saved as" key, then the endpoint
  key, provider catalog, credential policy, manual-entry and sampling-route rows the card
  used to print (same ids, so readers by id keep working). Focus inside the disclosure no
  longer resets the focused field (`handle_descendant_focus`), so opening it names the
  field the user was on. A Settings-scoped CSS rule drops the global Collapsible frame so
  it costs one row closed.

### Rulings

- Ruling: the D1 predicate lives in `UI/Console_Modules/session.py`, not in
  `console_chat_store.py` as the plan said -- `console_chat_store.py` is already over its
  size-ratchet row at base (22,491 vs 22,344) and ratchets never rise; session.py is
  ui-ready resident, so the lazy import from Settings adds no module -- cost if wrong: one
  function moves.
- Ruling: the Applies-to text wraps instead of `nowrap` + ellipsis -- at 211x44 the text
  column is about 93 cells and a 23-character title plus a pair overflows it; the pair is
  the point of the row -- cost if wrong: one CSS rule (and the long-title test).
- Ruling: the copy reuses the State line's vocabulary ("unused" / "chats with work")
  rather than the AC's "untouched", so no two surfaces name the same case differently --
  cost if wrong: four strings.
- Ruling: the "Focused field guide" heading and its "Focused setting:" row stay as they
  are rather than the mock's "FOCUSED FIELD · Temperature" heading -- the guide rows are
  pinned by the in-view tests for every category and the heading is cosmetic -- cost if
  wrong: one heading refresh.
- Ruling: the moved rows keep their ids (`settings-provider-catalog`,
  `-catalog-policy`, `-manual-entry-policy`, `-sampling-route`, `-endpoint-key`) inside the
  disclosure -- tests and refreshers read them by id -- cost if wrong: id renames.
- Out of scope, unchanged: the generic ownership tail under every category's inspector
  ("Owns: chat_defaults.provider ...") still prints config section names outside a
  disclosure; AC#4 covers the focused-field guide.
