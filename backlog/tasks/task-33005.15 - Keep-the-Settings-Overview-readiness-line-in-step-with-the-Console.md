## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: the Phase 5 capture-checkpoint fix (2026-10-02) made the Settings Overview status line use the shared readiness words and connection evidence the Console uses. The fix implementer reported three gaps it left open:

- **Model fallback can disagree.** The Overview keeps TASK-31805's rule of reading the model it displays. With `chat_defaults.model = ""` and a model set in the provider table, the Overview says "Not ready · no model", while a new Console chat may fall back to the table's model and read Ready. That is the same-moment contradiction Phase 5 exists to remove.
- **No in-place refresh.** When connection evidence changes while the Overview is on screen (for example a Switch model probe, or Chat settings' test), the status line does not update until the next visit. The Overview's poll watches only subscription state.
- **Untested filtering.** Nothing tests filtering the switcher's new NOT RUNNING group by a typed provider name.

The Settings UX review of 2026-10-14 found a fourth gap (finding B5, AC#4): while Providers & Models holds an unsaved draft, the Overview shows the draft as the Configuration, because its presentation reads the draft-overlaid resolver.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 With a blank chat-default model and a model in the provider table, the Settings Overview and a new Console chat give the same readiness words; a test pins it.
- [x] #2 A connection-evidence change made elsewhere while the Overview is visible updates its status line without leaving the screen, and adds no new timer (reuse an existing poll or event); a test pins it.

- [x] #4 While Providers & Models holds an unsaved draft, the Settings Overview's Configuration row and its Status describe the saved provider and model, and name the unsaved draft separately; a test pins it (Settings UX review 2026-10-14, finding B5, plan-2026-10-14-settings-save-honesty.md OD-4).
