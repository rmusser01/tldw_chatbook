## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while verifying TASK-33621.23 live, on dev 1eaa6a9429 and on its fix branch. In a named workspace with a bound folder, a chat's first send shows 'Send project instructions?'. Choosing Cancel or Disable (also Esc, or letting it time out) ends the turn as 'Assistant · Failed / Response failed.'. Nothing says the user declined. The log reads only 'Console submit requires attention | accepted=True status=failed'. AgentService turns every non-proceed decision into RUN_CANCELLED, and the controller's _finalize_agent_cancelled marks the reply failed, with run copy 'Response stopped/cancelled.'. Disable also turns project instructions off for the chat, yet the message is dropped rather than sent without them. Evidence: the console UX review evidence folder bd5/U08, shots dev-04-cancel-project-instructions and dev-08-disable-project-instructions.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Fix:** `Chat/console_project_dispatch.py` records the user's own Cancel/Disable answer (also Escape, timeout, and no callback), keyed by session, when the decision committed is the one the user gave. An automatic cancel (selection drift, chat already accepted) is not recorded. `ConsoleChatController._finalize_agent_reply` claims that record before any branch, so a racing Stop cannot strand it, and turns its RUN_CANCELLED into `finalize_declined_notice`. That marks the placeholder failed, records the run message, appends a "Not sent: ..." system row, sets the run state BLOCKED, and returns blocker `ConsoleSubmitBlocker.PROJECT_INSTRUCTIONS_DECLINED`. The log now reads `status=blocked blocker=project_instructions_declined`. Drift cancels still end FAILED; the existing drift test still pins that. The controller grew 4 lines (28762 of 28764).

Copy: Cancel gives "Not sent: this folder's project instructions were not approved. Retry to answer again: Proceed sends them, Disable turns them off for this chat." Disable gives "Not sent: project instructions are now off for this chat. Retry to send without them." This follows the spec (plan 2026-08-20-agents-md-support: "cancel aborts the send ...; disable does the same and turns the feature off"). Disable says the turn was not sent rather than sending it, which satisfies AC #2.

**Test:** `Tests/Chat/test_console_agent_project_instructions.py::test_declined_notice_blocks_the_turn_and_names_the_decline` (cancel and disable) checks the blocker, BLOCKED state, a last row that is SYSTEM with the copy, and that the next send is not held. On base the blocker was `None`. The bridge is a double that forwards the real dispatch callback and returns RUN_CANCELLED on a decline, which is what `AgentService.run_turn` does. That half is pinned by `test_cancel_and_disable_abort_before_provider_and_discard_snapshot` with the real AgentService. AC #4 was reworded to match.

**Live (Linux, 2026-11-20):**
- Escape on the notice gave the "Not sent" row and `blocker=project_instructions_declined`. Retry on the turn asked again, and Proceed then Allow edited the file.
- Disable gave its row. Retry went straight to the approval card with no notice, and the file was edited.
