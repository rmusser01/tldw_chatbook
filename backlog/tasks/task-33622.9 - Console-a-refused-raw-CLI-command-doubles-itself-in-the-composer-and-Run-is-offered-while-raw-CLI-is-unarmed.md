## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** With `raw_cli_permitted=true` and nothing armed, typing '! git status --short' switches the composer to 'RAW CLI · HOST ACCESS' with an enabled primary 'Run' button. The styling is identical to the armed state, so nothing says it is unarmed. Pressing Enter refuses: 'Raw CLI is Unlocked but not armed for this launch. Arm it in Settings > Privacy & Security. The exact draft was restored.' That claim is false. The captured draft is prepended to the live draft that is still in the composer, giving '! git status --short! git status --short', and each further Enter doubles it again (1, 2, 4 copies). Clicking 'Run' with the mouse restores the draft verbatim, so only the Enter path is broken. A sibling symptom with the same root: a successful Enter-run leaves the command in the composer. A host-shell command with host-user authority is being silently corrupted. The feared 'arm then Enter runs concatenated text' did not reproduce, but only because a separate defect masked it: raw CLI refuses 'could not persist this command locally' whenever the active leaf is a local System row or raw marker. That defect is out of scope here and should be filed separately. Verdicts: live PARTIAL, code CONFIRMED, skeptic PARTIAL, on dev 64579cce2c.

**Severity / prior art.** P1, triage NEW. Same append class as G1-37, for shell commands. Related: TASK-18926 (raw CLI executor), ADR-094 (raw/virtual CLI boundaries), ADR-099 and TASK-26034. The separate arms for raw CLI and Terminal are deliberate (ADR-099; the Settings card says 'Each feature still arms separately'). This task keeps them separate; it does not merge them into one arm.

**Suggested direction.** Make the Enter raw-CLI branch own its capture as the mouse path does: clear the composer on an accepted run, and restore idempotently (replace, never prepend) on refusal. Make the composer read the raw-CLI armed state. When unarmed, show a distinct 'not armed' state with an in-place 'Arm…' action reusing the Terminal disclosure pattern, and label the primary action 'Run' only when armed.

Evidence: qa/console-ux-review-2026-09-29/findings.md → GAP4-06

Review finding ids: GAP4-06 — see qa/console-ux-review-2026-09-29/findings.md.

**Measured first.** Live on dev 38c9d2edcf (raw CLI unlocked, nothing armed),
`! git status --short` showed "RAW CLI · HOST ACCESS" with an enabled "Run"; three
Enters each refused and left exactly one copy of the draft. So the doubling (#1-#3,

**Fix.** `ConsoleComposerBar` takes a `raw_cli_authority_provider` (ChatScreen wires
`raw_cli_authority(app.raw_cli_runtime)` from `Chat/console_raw_cli.py`; an unwired
composer reads as locked) and shows each state from one table: armed "RAW CLI · HOST
ACCESS" / Run, unlocked-not-armed "RAW CLI · NOT ARMED" / Arm…, locked "RAW CLI ·
LOCKED" / Locked. Per the owner decision of 2026-10-27, Arm… arms in place:
`request_visible_send` (where Enter, Send and the Workbench's send converge) sends an
unarmed raw draft to `ConsoleRawCliController.request_arm`, which opens the same
ConfirmationDialog as Settings > Privacy & Security's Arm (title, "Arm host access",
Cancel focused) and arms the runtime on confirm, leaving the draft for an explicit
Run. Both arm confirmations now add the ADR-093 line that arming gives models the
host-shell tool `shell_exec` (Ask only, no permanent Allow); the disclosure tuple
moved from `settings_screen.py` to `Chat/console_raw_cli.py`, so the Console does not
import Settings and the Settings card's static lines are unchanged. ChatScreen's
`on_screen_resume` repaints a raw draft, so an arm or disarm made in Settings shows on
return. The unarmed refusal copy (now reachable only by a race) names the in-place
Arm….
