## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: taking notes while reading is the core loop for the researcher (Priya, j7) and the PKM power user (Alex, j3). In Library the reader and a note editor share one work pane, so the user has to switch back and forth, and every switch throws state away in both directions:
- Back on Media, the reader is blank: "Select a media item to read it here." The item has to be found and reopened, on the last-used tab rather than the one the user left, and re-scrolled.
- Back on Notes, a note created with New note has closed: "Select a note to edit it here."
- Media has no capture key: in the Media list and reader, n and Ctrl+N do nothing and give no feedback.

j7 measured one note-taking round trip at about 8 clicks plus 5 keys plus re-scrolling, and its task "read it and take notes at the same time" failed outright.

Observed (verified at 160x45, golden profile; verify v2 captures):
- 13b-back-to-media-wait: after Media ▸ open item ▸ rail Notes ▸ rail Media, the reader shows "Select a media item to read it here." beside the list.
- 28-notes-return-from-create: a note created through Create ▸ New note ("S02 paper notes · now") is saved but closed after a round trip, and Notes shows "Select a note to edit it here."
- Notes opened from the list DO survive a switch; Blank-created notes do not.
- The verifier also found a separate false "changed elsewhere" conflict render on the retained-editor path. Its cause has not been traced (hypothesis).

Verified cause (origin/dev 2d34cbf80d):
- In the rail-switch seam, `retain_note_session` (UI/Screens/library_screen.py:22239-22259) requires `session_blank_id is None` (:22251). It also only applies between the Browse rows in `retained_reader_rows` (:22230-22237), which excludes Create ▸ New note. So a note born from New note is always reset (:22405-22407) even once it has saved content.
- The same seam deliberately resets Media to the list on every rail press (:22387-22399: "A rail-row press is always a fresh entry… must show the list, not the stale viewer"). This task reverses that recorded rule for Media, and the reversal should be documented where the rule lives.

Suggested direction (the review's refined fix; review question 4, recommended option (a)):
1. Keep a saved note session across rail switches: drop the blank-id gate once content is saved, and include the Create entry.
2. Keep the open media id, tab and scroll across rail presses, and focus its row.
3. Fix the false "changed elsewhere" render on the retained editor.
4. Add "Take note" (n) to the Media reader. It opens a new note that names the source item, and the user can return to the reader where they left it. Use n for capture, per the key-conflict note under R-15 in improvements/ranked.md.

OUT OF SCOPE: a side-by-side reading desk, with the note beside the reader in a split work pane (review improvement R-28). That needs an ADR-086 amendment (single-slot work pane) and an ADR-084 check (reader width priority). Under the standing rule that redesigned screens need explicit owner approval, it also needs the owner to approve the screen. This task keeps the one-pane layout.

Owning-task note: finding L-16 (a Media row marked "loaded" beside an empty reader) is a separate review finding. Restoring the reader here should also resolve it, so check before closing either. Finding S-03 (quote a passage with a source link) is also separate and not covered here.

Review finding(s): S-02. Source: qa/notes-library-ux-review-2026-10-02/report.md

## Implementation Notes
<!-- SECTION:NOTES:BEGIN -->
**Summary.** A rail press no longer resets an open Media Reader or closes a New-note note that has text; the Reader gains a **Note** button (`#library-media-take-note`) and the `n` key, which create a note titled after the document whose first line is `[<title>](media://<uuid>)` (reading-desk §5.1), with the caret after it; rail Media brings back the same item, tab and scroll. The review's false "changed elsewhere" render was reproduced live and fixed at its cause.

**Rail seam** (`library_screen.py`, `_select_library_rail_row_after_source_admission`): `_rail_switch_keeps_media_reader()` (viewer view, settled local item, no pending request, detail held) keeps `view`/`detail`/`composed_detail`/`content_mode`/`highlights`/`reader_session` and captures the reading position through the existing coalesced writer; edit/delete-confirm/analysis sub-states and Find still close. The Notes gate drops `session_blank_id is None` for the GC's own predicate (`gc_untouched_session_blank_note(discard=False)`): an effectively-empty session blank still takes the flush/GC branch, a blank with text is retained like a list note; `LIBRARY_ROW_CREATE_NOTE` is admitted as a start row. On return to Media the one restore owner runs through `_after_library_media_viewer_sync`. `swap_library_browse_route` admits the Media viewer view (only Trash is a different child), so the return stays on the cheap route swap; `swap_work` clears a focus inside the outgoing pane before removal (Textual's implicit successor was the first Items row, which the Media canvas read as arrow traversal and LOADED) and removes it under `batch_update` (the TASK-32114 teardown rule).

**Restore owner** (`_restore_library_media_loaded_progress`): a body with nothing laid out hands the continuation to the layout signal — `LibraryMediaContentBody.run_when_laid_out`, fed by the new `VirtualizedRawContent.Indexed` message and Textual's `Markdown.TableOfContentsUpdated` — because `call_after_refresh` is two message hops, not a layout pass (measured 48 of 48 re-applies at `max_scroll_y == 0`). Still one owner; the eight-refresh budget for a growing body is unchanged.

**Note action**: `Library/library_media_source_link.py` (pure; refuses anything but a uuid — never an integer id); `check_action("library_media_take_note")` = the Find fences + local item + no text field focused; `on_key` dispatches `n` to Notes or Media through the two gates; footer chip `n note` through the same gate; `_start_library_note_from_media_source` beside `_start_library_blank_note` (`blank=False`, `caret_at_end=True`); `LibraryNotesState.create_caret` tells both the create projection and the editor-ready hook where the caret lands; receipt "Note from <title> — Media keeps your place". Label is **Note** per desk §4.5 (controller ruling); the owner may prefer "Take note" — a one-word change in the viewer.

Version pins stay as the guard.

**Toolbar width**: the five label-sized buttons need exactly 46 cells and the Reader's content is 46 at 100x30, so both Reader toolbars drop their decorative 1-cell side gutter (`_library_panels.tcss`; bundle rebuilt).
