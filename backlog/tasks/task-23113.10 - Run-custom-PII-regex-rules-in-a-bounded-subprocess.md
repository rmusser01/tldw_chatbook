## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Extend trace masking with user-defined regular expressions evaluated under enforceable time, input, and output limits after the core ledger and built-in detectors are stable.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Validated custom PII rules execute as one disposable bounded-batch subprocess with enforceable batch deadline, input/field/rule/match counts, output size, and worker memory limits.
- [x] #2 Invalid, crashing, hanging, malformed, over-limit, or catastrophically backtracking batches fail closed by recording content-free omissions for affected components without blocking later trace viewing, copy, or export.
- [x] #3 Rule configuration is validated, versioned, and reported with actionable diagnostics without echoing matched secrets or PII.
- [x] #4 Successful custom detections irreversibly transform provider-only capture and create the same immutable frozen masks as built-ins for canonical references without mutating the saved transcript.
- [x] #5 Adversarial dense and catastrophic-backtracking fixtures verify bounded work using enforceable process limits rather than wall-clock assertions alone.
- [x] #6 ADR required: no; this is the deferred implementation of the bounded custom-regex policy already decided by ADR-097.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add validated, versioned custom-rule configuration with stable opaque identities and content-free diagnostics, following Task 28 of the approved semantic-trace implementation plan.
2. Add one disposable standard-library worker process per capture batch with parent-side byte/count/deadline/output limits and supported worker memory limits.
3. Fail closed for invalid, crashing, hanging, malformed, or over-limit batches, and merge successful custom spans through the existing immutable trace-mask path without changing canonical conversation content.
4. Expose the validated privacy posture in Settings, document the limits and omission behavior, and verify configuration, worker, masking, privacy-owner, viewer, copy, and export boundaries with targeted tests.

ADR required: no
ADR path: N/A (existing ADR-097 applies)
Reason: This task implements the bounded custom-regex policy already decided by ADR-097 without changing its storage, privacy, or runtime boundaries.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- Added strict Pydantic validation for the versioned ruleset envelope and individual rules, rejected zero-width patterns before worker execution, kept diagnostics content-free, and bounded the process-local revision registry; pattern and label text stay out of representations and diagnostics.
- Added an isolated disposable regex worker with parent and child input, field, rule, match, output, deadline, CPU, and supported memory limits. Its exact-schema response contains only structured field paths and codepoint ranges; invalid, malformed, crashing, hanging, or over-limit work fails closed.
- Composed custom spans with the built-in detector through the existing immutable mask model, froze the exact revision at admission across normalized and legacy capture, and persisted only masked artifacts and content-free spans while leaving saved conversation rows unchanged. Saved provider continuations are policy-owned artifacts anchored to their immutable message revision, so later viewing, copy, and export never need the ephemeral custom-regex registry; older revision-backed continuations use the durable revision-policy binding and fail closed if it is unavailable.
- Added targeted configuration, adversarial worker, masking, semantic-retirement, trace-service, controller, provider-gateway, Settings, copy, export, and viewer regression coverage. Documented configuration and platform limit behavior in the Console user guide and testing-evidence lessons; reviewed the new content-free warning and regenerated the production diagnostic inventory.
- ADR check: no new ADR. This is the deferred implementation of the policy already established by [ADR-097](../decisions/097-console-reference-backed-semantic-trace-ledger.md).
