## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Extend trace masking with user-defined regular expressions evaluated under enforceable time, input, and output limits after the core ledger and built-in detectors are stable.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] Validated custom PII rules execute as one disposable bounded-batch subprocess with enforceable batch deadline, input/field/rule/match counts, output size, and worker memory limits.
- [ ] Invalid, crashing, hanging, malformed, over-limit, or catastrophically backtracking batches fail closed by recording content-free omissions for affected components without blocking later trace viewing, copy, or export.
- [ ] Rule configuration is validated, versioned, and reported with actionable diagnostics without echoing matched secrets or PII.
- [ ] Successful custom detections irreversibly transform provider-only capture and create the same immutable frozen masks as built-ins for canonical references without mutating the saved transcript.
- [ ] Adversarial dense and catastrophic-backtracking fixtures verify bounded work using enforceable process limits rather than wall-clock assertions alone.
- [ ] ADR required: no; this is the deferred implementation of the bounded custom-regex policy already decided by ADR-097.
