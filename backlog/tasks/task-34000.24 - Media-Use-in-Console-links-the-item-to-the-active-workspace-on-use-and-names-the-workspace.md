## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: the product's core loop is to import something, then reason about it in Console. In the Media reader the obvious button for that, "Use in Console" (key c), always refuses. Three personas hit this: the first-timer (Jordan, j2), the power user (Morgan, j4) and the researcher (Priya, j7). The refusal names a workspace id the user has never seen and an action that does not exist anywhere for media. The same paper stages fine through Search ▸ Select evidence ▸ Use in Console (u), so the app also looks inconsistent. Every media item is affected, not just new imports. The refused button is styled as enabled, and the footer keeps advertising "c use in Console".

Observed (verified at 160x45, golden and empty profiles):
- Pressing the button shows the toast "Copy or link this media into workspace workspace-default before using it in Console." (verify 04-seeded-use-in-console-toast).
- The rail Details say "Handoff · N items can't be used in Console yet · not in this workspace · Copy or link them into this workspace", with no link or copy action for media.
- Search evidence 'u' on the same item opens Console with "Sources: 1 staged" (verify 17-search-use-in-console-result).
- The workspaces DB holds workspace-default (active, created at first boot) and 0 memberships.

Verified cause (origin/dev 2d34cbf80d):
- `_open_selected_media_handoff` (UI/Screens/library_screen.py:35518) refuses whenever the per-item gate fails (:35542-35550) and never links.
- Notes and conversations link on use instead:
  - notes: `_link_open_note_to_active_workspace`, UI/Library_Modules/library_notes_controller.py:4453-4500, called from the hand-off at :4590-4616, receipt "Linked to <workspace> · staged in Console";
  - conversations: library_screen.py:13906, per the TASK-32107 decision, with receipt and Undo link.
- The refusal sentence is built in Workspaces/eligibility.py:73-82, which interpolates the raw `active_id` at :79. That copy is shared by every item type.
- The Search evidence path (UI/Library_Modules/library_rag_search_controller.py:1238-1282) stages through `open_console_for_live_work` with no workspace rule at all.

OWNER RULING 2026-10-03 (encoded in the ACs):
- Using a media item in Console links it to the active workspace on use, exactly as notes and conversations already do.
- Any refusal or receipt copy shows the workspace display name (e.g. "Local Default"), never a raw id.
- Default-workspace semantics do not change: the TASK-32107 decision stands, and treating Default as "everything local" (review improvement R-23) is out of scope.

Suggested direction (the review's refined fix):
- Port link-on-use into the media hand-off: link the item, stage it, and show "Linked to Local Default · staged in Console", with a way to undo the link.
- Make the shared eligibility copy use the display name.
- Route Search 'u' through the same rule so both entry points agree.
- The rail's set-level `#library-use-in-console` keeps its pressable-with-reason grammar (TASK-716, recorded in TASK-32107) and is out of scope.

Owning-task note: TASK-32107 (Done) decided link-on-use for conversations only. TASK-32056 (Done) added the conversation reader's link affordance. No task covers media.

Review finding(s): S-01. Source: Docs/QA/notes-library-ux-review-2026-10-02/report.md

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Pressing 'Use in Console' (or c) in the Media reader on an item that is not in the active workspace links it to the active workspace and stages it in Console in one step. This holds for freshly imported items and for existing ones
- [x] #2 After the press, the user sees which workspace the item was linked to, by display name ('Linked to Local Default · staged in Console', or 'Already linked to …'). The link that press added can be undone from Library, as conversations already allow
- [x] #3 No refusal or receipt copy for any item type (media, notes, conversations) shows a raw workspace id such as 'workspace-default'; the shared eligibility copy names the workspace by its display name
- [x] #4 The Media reader ('c') and Search/RAG evidence ('u') give the same result for the same media item: both stage it and both leave it linked to the active workspace. Blocks that a link cannot resolve (e.g. no active workspace) still refuse, in plain language with a next step. Items that were never used stay unlinked, so Default-workspace semantics are unchanged
- [x] #5 A regression test (Pilot or unit) that fails on current dev pins that the media reader hand-off on an unlinked item ends with a workspace membership and a staged Console source, and that no hand-off copy contains a raw workspace id
- [x] #6 Verified live at 160x45 and 80x24 in an isolated empty profile: import a file, open it, press c, and Console shows it staged. The receipt names 'Local Default', and undoing the link removes the membership

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Media "Use in Console" (button and `c`) now links the open item to the active
workspace on use and stages it in one press, exactly as notes (task-32536) and
conversations (task-32107) do, through one new seam both the reader and Search
`u` share; the shared refusal copy names the workspace by display name.

**Approach.**
- `tldw_chatbook/Workspaces/link_on_use.py` (new): `link_item_to_active_workspace`
  (read memberships first, `link_membership` only when absent, display name via the
  hoisted `display_state.library_workspace_display_name`, never raises; every
  failure is a `blocked_reason` sentence), `unlink_item_from_workspace` (by the
  RECEIPT's workspace id), `LinkOnUseResult`, and `resolve_workspace_item_id`
  (maps a retrieval id such as `local:media:3` onto the id the row model reads, so
  Search `u` writes the membership under the same id the reader's gate checks).
- `Workspaces/eligibility.py`: `evaluate_workspace_eligibility(active_workspace_name="")`;
  the sentence is "Copy or link this {type} into the {name} workspace before using it
  in Console." with `name = display name or "active"`. `display_state.py` hoists the
  display-name rule above the row loop and passes it per row -- media, notes and
  conversations get the fix at the source.
- Media hand-off (`library_screen._open_selected_media_handoff`, a screen-resident
  wiring exclusion, rewritten in place): Console's availability read BEFORE the
  write; a linkable block (`not_in_active_workspace`/`cross_workspace`) is resolved
  through the seam, the depth state invalidated, the item staged, and a receipt
  recorded on `_media_state.link_receipt` (`LibraryMediaLinkReceipt`, cleared when a
  DIFFERENT item is selected); a non-linkable block keeps its own sentence; a
  membership this press added is unlinked again if Console refuses.
- Reader: `#library-media-link-receipt` + `#library-media-link-undo` under the primary
  toolbar (`library_media_viewer.py`), threaded through `_build_library_media_reader`
  and the unchanged-compare in `_sync_library_media_viewer_state`; visibility rule
  `_library_media_visible_link_receipt` (receipt names the open item AND its workspace
  is the active one -- the conversation reader's rule); Undo handler on the screen
  unlinks the receipt's workspace by id. One CSS block in
  `css/features/_library_panels.tcss` (id-scoped: `#library-media-viewer Static
  {width:100%}` beat a bare class and pushed Undo off the pane, found live).
- Search `u` (`library_rag_search_controller._link_library_rag_result_on_use`): for a
  local media/note/conversation row, resolve the row-model id, link through the seam,
  refuse a non-linkable block, notify `Linked to … · staged in Console` when a
  membership was written; two injected deps (depth state + invalidation) added to the
  controller's constructor.
