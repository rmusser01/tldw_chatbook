## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
All 12 inherited reds are fixed with test-only changes, on the TASK-33621.21 branch (PR #3708). The light tier would otherwise keep evicting that PR. No product code changed.

- Factory composition, 7 nodes. `_factory` now uses the real `console_voice_process.VoiceProcessSupervisor()` instead of `SimpleNamespace(retain=lambda _engine: None)`. A stub copy of the signature is what went stale when a102776f0d added `session_id`. The real `retain` only records the session and sets `_on_retired` on the fake endpoint, and the device lease is only held, so nothing native starts. There is no shared fake; `test_console_voice_preflight.py` also builds the real supervisor.
- Factory composition, the real-controller node. `@private_profile_test` with `request`, the seam TASK-36381 used for app-building tests. `ConsoleChatController.__init__` reads app config, and the shared bootstrap profile refuses that load (`raw_source_selection_changed`). The node failed before the change and passes after.
- The four lock-wait nodes. Each one now asserts `<controller>._model_preparation.done.wait(N)` before the next press. That event is the product's own signal: `_finish_model_preparation` sets it right after releasing `_MODEL_PREPARATION_ADMISSION`. The same files already used the pattern (for example the retry-after-disposal test). There are no sleeps, and the one-preparation-at-a-time rule is unchanged.
- Evidence (2026-11-24, macOS): each lock-wait node passed 10 of 10 runs alone. Each fixed file passed whole 3 of 3 times on the branch rebased onto dev 75bac413f5: voice_input 174 passed, dictation_firstrun 23 passed, factory_composition 10 passed. On dev 75bac413f5 the same files gave 8 failed / 2 passed, 2 failed / 170 passed, and 3 failed / 16 passed. The whole light-tier selection for #3708 had no reds on the branch. Per file: module ratchet 213, capture_send_triggers 9, voice_capture 27, voice_privacy_integration 24, app_wide_tqdm_lock 4, approval_scope_journeys 15, smoke 16, approval_timeout_policy 21, and the 2 chat_functions nodes (128 parametrized cases).

Lesson (from #3708's two evictions). Under the light tier, a PR inherits the dev reds of every test file it edits, plus those of every test file that imports one. #3708 edited `test_console_voice_capture.py`, and `test_console_voice_factory_composition.py` imports one helper from it, so that file's 8 reds became #3708's. The PR's own "branch vs dev by test id" comparison had recorded those as shared reds and not counted them against it, but the queue fails on a shared red. Before arming, compute the selection with `scripts/ci/tier_policy.py` (`select_changes(changed_paths(<merge-base sha>, <head sha>), Path.cwd())`; both must be full SHAs) and run each selected file. Recorded in `backlog/docs/lessons-testing-evidence.md`.
