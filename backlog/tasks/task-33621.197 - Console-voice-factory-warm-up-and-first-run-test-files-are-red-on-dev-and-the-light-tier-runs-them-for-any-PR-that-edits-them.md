Found re-syncing PR #3708 (TASK-33621.21) on 2026-11-24, after the merge queue evicted it on its second failure of the required check (run 45362116936, job "Dev smoke and affected contracts"). The light CI tier (TASK-42521, 2026-11-23) runs a dev PR's changed test files whole, plus the test files that import them. Three Console voice test files that no PR lane ran before are red on dev 9fa2bf1b1d with the same test ids with or without that PR. Any PR that edits `Tests/Chat/test_console_voice_input.py`, `Tests/UI/test_console_dictation_firstrun.py` or `Tests/Chat/test_console_voice_capture.py` (which `test_console_voice_factory_composition.py` imports) inherits these reds and is evicted.

Reds on dev 9fa2bf1b1d (local macOS by file; the same ids failed in the Linux CI job):

- `Tests/Chat/test_console_voice_factory_composition.py`, 8 of 10. Seven nodes (`test_factory_consumes_frozen_privacy_only_after_winning_claim[False|True]`, `test_factory_imports_actual_trace_only_after_actual_pair_commit[False|True]`, `test_factory_does_not_consume_foreign_or_unclaimed_next_privacy[refused|stale_slot|replayed_winner]`) raise `TypeError: _factory.<locals>.<lambda>() got an unexpected keyword argument 'session_id'`. The `_factory` fixture's supervisor stub is `retain=lambda _engine: None`. Since a102776f0d (2026-09-10), `create_console_speculative_voice_session` calls `supervisor.retain(engine, session_id=session_id)`. The test file was last changed on 2026-09-08 (b7dd8e53f2). The eighth node, `test_real_saved_controller_sealed_headers_import_through_winning_claim`, raises `RecoveryRequired: raw_source_selection_changed` from `ConsoleChatController.__init__` -> `get_cli_setting` -> the config bootstrap. It fails when run alone too, the same shape as TASK-36381's Settings nodes that lacked the private-profile isolation.
- `Tests/Chat/test_console_voice_input.py`: `test_the_first_run_message_differs_from_later_presses` (IndexError, 3 of 3 runs alone) and `test_a_failed_warm_up_is_still_a_first_run_next_time` (2 of 3 alone). `Tests/UI/test_console_dictation_firstrun.py`: `test_the_three_empty_capture_messages_are_all_different` and `test_a_service_reporting_nothing_falls_back_to_the_recognizer_flag` (`RuntimeError: Speech model preparation is still finishing...`). Each test presses start again right after the previous attempt ends. Since da28a28595 and 79c1b9bd21 (2026-11-01), the process-wide `_MODEL_PREPARATION_ADMISSION` is released only by the previous attempt's warm-up daemon (`_finish_model_preparation`), so the next press can be refused as still preparing, as designed. A probe on dev showed the race. After `start()`/`stop()`, admission was still held. The second press emitted `VoiceStateChanged, VoiceFailed, VoiceStateChanged` and no `VoiceModelPreparing`. After the probe waited for admission to free, the third press emitted `VoiceModelPreparing('Loading speech model…')`.

Not in scope: `test_a_slow_first_run_shows_the_preparing_message_not_a_frozen_button` and `test_an_unrelated_ui_refresh_cannot_wipe_the_preparing_message` in the same first-run file are TASK-33621.191, the first-run copy that the quiet-loading poll replaces.
