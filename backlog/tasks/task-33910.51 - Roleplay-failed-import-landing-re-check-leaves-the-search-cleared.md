## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Fixed in burn-down PR 5 of the B2b follow-ups (stacked on PR #3441). Restore, not a toast (the triage's recommendation; no new copy).

- **On dev:** present. The same-kind branch of `_land_import`'s `select` cleared the search, wrote the box (with no `prevent`) and reset a relevance sort to name, then returned when its second decision failed, leaving all of it applied. On the base the new test read `('', '', 'name_asc')` after a draft was started during the landing's refresh.
- **Fix (`personas_screen.py`):** `_clear_search_for_import_landing` snapshots the search, sort, tag and box value, clears them, and writes the box under `prevent(Input.Changed)` (the TASK-33910.39 idiom; on dev the write posted it, which armed a second debounced read). When the second decision fails, `_restore_search_after_import_landing` puts the state back first, writes the box under `prevent(Input.Changed)` (a restore is no newer intent) and starts one read through the search worker, whose currency check lets a later typed search supersede it. The import intent cannot tell a draft started meanwhile (restore) from a search typed meanwhile (keep), so the restore is skipped when the kind, search, box, sort or tag is no longer what the clear left. That is how the brief's "re-check the import intent; skip if the user typed" is implemented.
- **Test:** `test_a_landing_that_then_toasts_restores_the_search_and_sort_it_cleared[draft|search]` (`Tests/UI/test_roleplay_import_app.py`, with `_hold_the_landing_refresh`): a relevance search for "Abel", an import whose landing refresh is held, then a draft (search, box and sort come back, the list is read once with "Abel" and shows one row, the draft is kept) or a newer search "Zed" (it stays, and no read of "Abel" happens). Mutations: M51-A (no restore) and M51-C (the restore's box write posts `Input.Changed`: reads `['', 'Abel', 'Abel']`) turn the draft case red; M51-B (no newer-change check) turns the search case red at `('Abel', 'Abel') == ('Zed', 'Zed')`.
- **Live (mounted harness, 120x36):** after the failed landing, the box reads "Abel", the sort chip "Relevance", the list title "Characters 1 of 3" with only Abel Host, and the "Draft Hero" draft is kept with "Unsaved changes" (`.b2b-evidence/followups/fu-landing-evidence/live/head-search-restored.*`).
