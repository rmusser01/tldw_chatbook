## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
PR #2745. AC#1 done (scoped by a per-site sweep). The review named "four sites"
dividing char count by four; verification found only ONE is a genuine adoptable
re-roll:

- **Character_Chat/world_info_processor._estimate_entry_tokens** — was
  `max(1, len(content)//4)`, feeding `_apply_token_budget` for lorebook
  injection. Plain len//4 under-counts CJK (~1 token/char), so a CJK entry could
  pass the budget then overflow the real context window. Now routes through
  `Utils.token_counter.estimate_tokens` (CJK-weighted, headroom), keeping the
  `max(1, ...)` floor. Gate-free test pins CJK > len//4 floor and > equal-length
  ASCII (Tests/Character_Chat/test_world_info.py).

The other three are NOT adoptable re-rolls and were deliberately left:
- **Chat/usage_recorder.estimate_tokens** — a DELIBERATE 4-chars/token contract
  pinned by `test_estimate_tokens_is_four_chars_per_token_minimum_one`
  (`"a"*400 == 100`); changing it breaks that test and shifts cost-accounting
  numbers.
- **Subscriptions/token_manager** — blends char and word estimates (a different
  algorithm, not len//4).
- **Widgets/chunk_preview** — `len//4` bounds an overlap CHARACTER count for a
  preview, not a token estimate (a report false positive).

AC#2 (Library full-text search adopts the shared match-form builder) and AC#3
(tokenisation-case test) REMAIN — separate from the estimator adoption.
