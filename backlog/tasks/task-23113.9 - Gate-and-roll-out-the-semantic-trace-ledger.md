## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add bounded performance and storage acceptance gates, complete the compatibility rollout, switch normalized capture on by default, retire the quadratic writer, and document operator-visible behavior.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] On the canonical 200-turn fixture, second-half trace-owned bytes and rows are no more than 1.25 times the first half and total trace-owned storage is no more than 2 MiB.
- [ ] The fixture covers edits, regeneration, retries, tools, RAG or project context, forks, failures, credential filtering, migration, and logical garbage collection.
- [ ] Normalized writes can be enabled independently of reads, observed through compatibility metrics, and rolled back without losing readable trace history.
- [ ] After gates pass, normalized capture becomes the default and the old repeated-transcript writer is disabled while dual-read compatibility remains.
- [ ] User and operator documentation explains capture behavior, temporary-chat Save & Send, Safe and Full views, masks, legacy snapshots, storage ownership, and deletion semantics.
- [ ] Targeted Console, DB migration, privacy, packaging, and benchmark suites pass; any requested full-suite result is recorded separately.
- [ ] ADR required: yes; this task completes the staged rollout defined by ADR-097.
