## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add bounded performance and storage acceptance gates, complete the compatibility rollout, switch normalized capture on by default, retire the quadratic writer, and document operator-visible behavior.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 On the canonical 200-turn fixture, second-half trace-owned bytes and rows are no more than 1.25 times the first half and total trace-owned storage is no more than 2 MiB.
- [x] #2 The fixture covers edits, regeneration, retries, tools, RAG or project context, forks, failures, credential filtering, migration, and logical garbage collection.
- [x] #3 Normalized writes can be enabled independently of reads, observed through compatibility metrics, and rolled back without losing readable trace history.
- [x] #4 After gates pass, normalized capture becomes the default and the old repeated-transcript writer is disabled while dual-read compatibility remains.
- [x] #5 User and operator documentation explains capture behavior, temporary-chat Save & Send, Safe and Full views, masks, legacy snapshots, storage ownership, and deletion semantics.
- [x] #6 Targeted Console, DB migration, privacy, packaging, and benchmark suites pass; any requested full-suite result is recorded separately.
- [x] #7 ADR required: yes; this task completes the staged rollout defined by ADR-097.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add a deterministic, versioned 200-turn fixture and trace-owned storage metrics, then drive five fresh databases through the real ConsoleProviderGateway and enforce median linear-growth and 2 MiB release gates.
2. Add the replacement-heavy gateway fixture and scenario coverage for edits, regeneration, retries, tools, RAG/project context, forks, failures, credential filtering, legacy migration, and logical garbage collection.
3. Introduce independent normalized-write and normalized-read rollout controls plus compatibility metrics; default normalized writes on, keep dual reads, and stop new repeated-transcript message_exchanges writes while preserving legacy decoding and rollback readability.
4. Update Privacy & Security settings, Inspector help, and user/operator documentation for capture, temporary Save & Send, Safe/Full disclosure, masks, ownership, forks, legacy snapshots, reclamation, purge, export, and rollback semantics.
