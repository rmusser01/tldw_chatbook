## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: if you create a new note, type into it, wait for autosave, and then empty it again, going back should remove that empty note. Often it doesn't. The garbage collector soft-deletes the note using the version it last saw, but autosave has just bumped that version. The database refuses the delete as a version mismatch, and the empty note stays behind. Nothing is lost, but an empty note the user discarded is left behind.

The adapt batch's paired-arm check found it. `test_library_shell.py::test_library_shell_blank_note_autosaved_then_emptied_still_gcs_on_back` failed 6 of 10 runs alone on dev 46c3959526, and 8 of 10 on the adapt branch, which is not a significant difference. The log shows `ConflictError: Soft delete for Note ID … failed: version mismatch (db has 3, client expected 2)`.
<!-- SECTION:DESCRIPTION:END -->
