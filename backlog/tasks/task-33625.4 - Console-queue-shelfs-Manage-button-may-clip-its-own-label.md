## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the PR #2943 boot-CSS round's behaviour probe (2026-10-02); predates that PR. Mounted on the real Console, the prompt-queue shelf's #console-prompt-queue-manage button rendered '  Mana' instead of 'Manage'. The likely cause: the fixed width 8, minus padding 0 1, minus Button's own line-pad 1, leaves about 4 cells for a 6-letter label, and 'Restore' would clip the same way. Not yet confirmed on a live screen. TASK-33625's rule is that controls never clip.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Confirmed real, then fixed. Live (tmux, isolated profile, origin/dev f80d3e0090 code) the shelf painted 'Mana' at 80/100/120/160/235 columns, and 'Keep' for 'Keep draining' after pressing Pause during a run. A mounted harness under every app sheet showed the same for every width 60-235.

Two causes, both fixed in tldw_chatbook/UI/Console_Modules/prompt_queue.py:
- CSS: the fixed widths (Manage 8, Pause 15) minus padding 0 1 minus Button's line-pad 1 left 4 and 11 cells. Removing the two width lines lets Button's own width:auto size each slot to its label. min-width 8 stays (it undoes Button's 16) and Pause keeps min-width 15 so short labels don't shift Manage. Boot CSS shrinks by 37 B (widget_defaults_scoped.tcss 80,205 -> 80,168), rebuilt via build_css.py.
- Layout: a relabelled Button kept its old width, because Textual 8 caches a box model per the widget's OWN layout count and the shelf only refreshed itself. sync_presentation now calls refresh(layout=True) on both buttons.

Tests (Tests/UI/test_console_prompt_queue.py):
- New test_every_shelf_button_paints_its_whole_label walks every shelf state presentation_for can project (draining, pause-after-turn, each pause reason with the failed turn named at the production preview budget, response-recovery-blocked, unsent-turn recovery) on ONE mounted shelf at 60/80/91/92/100/120/160/235. For both buttons it asserts the button's render_line(0) text equals the label, and that the label is painted in the screen compositor row inside the button's columns, within the shelf.
- test_mounted_shelf_and_neighboring_composer_fit_terminal (real Console) now asserts the painted Manage/Pause text too, and runs at 80/100/120/160/235.
Red then green, with mutation checks: restoring width 8 fails the test on 'Mana', restoring width 15 fails it on 'Keep', and dropping the button refreshes fails it on 'Keep'.

Docs: chat-basics.md now names the Pausing / Keep draining state, which is visible in full for the first time.

Not in scope: the shelf's dispatch-recovery branch (Retry anyway / Retry response / Unavailable) now paints its labels in full. presentation_for never passes dispatch_recovery, so production cannot reach that branch. With its 70-cell copy it would still push Discard past the edge on a 92-101 cell wide-mode shelf.
