## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the PR #2943 boot-CSS round's behaviour probe (2026-10-02); predates that PR. Mounted on the real Console, the prompt-queue shelf's #console-prompt-queue-manage button rendered '  Mana' instead of 'Manage'. ## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The clip was real, and I fixed it. On origin/dev f80d3e0090 code (tmux, isolated profile), the shelf painted 'Mana' at 80/100/120/160/235 columns. After pressing Pause during a run it painted 'Keep' for 'Keep draining'. A mounted harness under every app sheet showed the same at every width from 60 to 235.

There were three causes, all fixed in tldw_chatbook/UI/Console_Modules/prompt_queue.py:
- **CSS:** the fixed widths (Manage 8, Pause 15), minus padding 0 1, minus Button's line-pad 1, left 4 and 11 cells. Removing the two width lines lets Button's own width:auto size each slot to its label. min-width 8 stays because it undoes Button's 16, and Pause keeps min-width 15 so short labels don't shift Manage.
- **Layout:** a relabelled Button kept its old width, because Textual 8 caches a box model per the widget's OWN layout count and the shelf only refreshed itself. sync_presentation now calls refresh(layout=True) on both buttons.
- **Narrow shelf (review round):** the auto-width buttons need 25-27 cells, and the narrow summary's min-width 20 made the row need 45-47. Any narrower shelf pushed the right-hand button past the edge. On the pre-review commit, 40 and 44 columns live painted 'Keep dra' and 'Keep drainin'.
  - The -narrow summary now sets min-width 0 and ellipsizes instead.
  - The shelf spans the whole Console shell, rails open or not. Live at 80x24 with the Inspector open, the shelf is 80 cells.
  - So this binds only in terminals under 47 columns, below the supported 80. At 47 and up nothing changes.

Boot CSS: net -15 B against origin/dev (widget_defaults_scoped -37 B, widget_defaults_self +22 B), rebuilt via build_css.py.

Tests, in Tests/UI/test_console_prompt_queue.py:
- **New: test_every_shelf_button_paints_its_whole_label.** It walks the shelf states presentation_for can project, all on ONE mounted shelf, at 40/44/46/47/60/80/91/92/100/120/160/235:
  - draining and pause-after-turn;
  - each pause reason, with the failed turn named at the production preview budget;
  - response-recovery-blocked and unsent-turn recovery.

  For both buttons it asserts that the button's render_line(0) text equals the label. It also asserts that the label is painted in the screen compositor row, inside the button's columns and within the shelf.
- **Changed: test_mounted_shelf_and_neighboring_composer_fit_terminal (real Console).** It now asserts the painted Manage/Pause text too, at 80/100/120/160/235.

The tests went red, then green. All 17 new or changed cases fail on origin/dev ('Mana'). Mutation checks, each of which makes the tests fail again:
- restoring width 8 fails on 'Mana';
- restoring width 15 fails on 'Keep';
- dropping the button refreshes fails on 'Keep';
- removing min-width 0 fails the 40/44/46 cases, with Pause ending past the shelf's edge.

Live evidence: Manage, Pause, Keep draining and Resume at 80-235 columns and at 91/92, and Keep draining and Resume at 40/44/46 columns. Restore/Discard (unsent-turn recovery) and the other recovery labels are covered only by the mounted harness, not by a live capture.

Docs: chat-basics.md now names the Pausing / Keep draining state, which shows in full for the first time. lessons-testing-evidence.md gets a 'Recurred' paragraph on the dynamic-Button-label lesson.

Not in scope: the shelf's dispatch-recovery branch (Retry anyway / Retry response / Unavailable) now paints its labels in full. But presentation_for never passes dispatch_recovery, so production cannot reach that branch. With its 70-cell copy it would still push Discard past the edge on a 92-101 cell wide-mode shelf.
