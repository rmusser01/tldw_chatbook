## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Setup says "done" without ever sending a message, so key, model, streaming and persistence defects surface only in Console, after setup is over; one review persona needed 20 recovery actions and 621 seconds to get a first reply. The approved spec adds an optional test message ("Say hello") that is a real Console turn, not a wizard copy of the request path (decision D5). Console has no way to run such a turn safely from setup: there is no origin that skips the hidden-turn notice, no turn-scoped profile that drops tools, retrieval and history, no streaming observer that works without a Console view, and no way to estimate the request's cost without sending it.

This slice builds those seams, as a spike first, entirely in new modules: console_chat_controller.py and console_chat_store.py are already over their size budgets on dev. It depends on the shared readiness verdict (TASK-34100.2) and on TASK-34100.5's error categories, first-send trace fix and toast rule.

Spec: Docs/superpowers/specs/2026-10-03-first-run-setup-shape-design.md (revision 3, approved by the owner on 2026-10-03; ADR-217): D5, §4.7 item 5, §8.1 (Say hello), §8.2, §10 F9a.

## Acceptance Criteria

- [ ] #1 Before production code, a spike recorded in Implementation Notes shows each seam can live in new modules. If any seam would need to grow console_chat_controller.py or console_chat_store.py, the task stops and reports instead of raising a ratchet
- [ ] #2 A SETUP_PROBE submission origin raises no hidden-turn notice or nav badge, never enters prompt history, never clears the composer, and changes shared readiness only under TASK-34100.2 AC#2's own rules
- [ ] #3 A probe turn sends no tools or agent surface, no retrieval, no project, workspace or persona instructions, a minimal system prompt and no prior turns. Its reply cap is model-aware: 256 output tokens for ordinary models; the lowest reasoning effort, or thinking off, where the provider allows; the provider's minimum thinking budget plus 256 where a budget is required. None of this is persisted, so the next normal turn uses the session's own settings
- [ ] #4 The reply streams to a subscriber with no Console view mounted. If the spike shows a viewless streaming observer cannot be added safely, the reply is delivered on completion with elapsed time instead (the non-streaming fallback)
- [ ] #5 A prepare-only estimate returns the probe's input tokens and reply cap without sending anything, and the input tokens actually sent never exceed it
- [ ] #6 The probe turn is saved to a conversation titled 'Setup test · <provider> · <model>', reused for later tests of the same provider and model
- [ ] #7 Provider failures map to the spec's D5 categories (key rejected, no credit or quota, rate limited, model not found, local server not answering, local model not downloaded, first token too slow, a 400 naming a probe-only parameter, reply not saved, anything else).
