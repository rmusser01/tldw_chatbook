## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
C7(d): Console prints raw provider spellings in several places.
- The status-row chip uses selection.provider, a config key, or the saved chat_defaults spelling (UI/Screens/chat_screen.py:9826-9831), rendered as 'Provider: {raw}' (Chat/console_display_state.py:776). The inspector and pickers already show catalog names.
- The task-16475 swap notice prints raw keys (UI/Console_Modules/session.py:3846). Phase 1's D1 convergence makes that notice fire more often.

The shipped [providers] table (config.py:4120-4151) spells keys such as 'Llama_cpp', 'local-llm', 'local_onnx' and 'local_transformers'. provider_display_name looks up the key exactly (Chat/provider_catalog.py:71-82), so these render raw.

Chat/console_provider_support.py:79-108 keeps a second display-name map with a title-case fallback. It uses different names ('Google' against 'Google Gemini', 'Custom OpenAI' against 'Custom OpenAI-compatible') and feeds the Console-compatible provider options at :391. So Settings lists and Console pickers disagree.

The provider value returned by _active_console_provider_model_display is also used as an identity, for example for Settings recovery navigation (chat_screen.py:20543-20553). So only rendered labels may change.

The 25-character model-chip cap is user-requested (TASK-1671, css/features/_console.tcss:253) and stays. Legacy aliases stay selectable (ADR-066, task-180). TASK-194 (the popover's own rows) is not closed here.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
One display-name catalog now serves the Console chip, the swap notice, the Console catalog, Settings and the First-run list.

- `Chat/provider_catalog.py`: `provider_display_name(key, app_config=None)` looks up `normalize_provider_config_key(key)`, so every shipped spelling (Llama_cpp, local-llm, HuggingFace, MistralAI, ZAI, Custom_2, ...) resolves; an unmapped key comes back unchanged, so a custom-ep id is never mangled. With `app_config`, a `custom-ep:<slug>` id renders as its registry entry's name. Added `local_onnx` ("ONNX Runtime (local)"), `local_transformers` ("Transformers (local)") and `custom_hosted` ("Custom Hosted", the name the First-run list already showed; without it the list would have shown the raw key once the private map went).
- `Chat/console_provider_support.py`: the private `_PROVIDER_DISPLAY_NAMES` map and its title-case fallback are deleted; `supported_console_provider_catalog` labels entries with `provider_display_name`.
- `Chat/console_display_state.py`: `ConsoleControlState.from_values` maps the chip name (new `app_config` kwarg, for custom endpoints). `chat_screen.py` passes the config on the existing `provider=` line (net 0 lines, 0 methods); `_active_console_provider_model_display` is untouched, so recovery navigation, readiness, token/cost estimates and prompts still get the key.
- `UI/Console_Modules/session.py`: the stale-default swap notice reads "Console provider changed OpenAI -> llama.cpp: ...".
- `UI/Screens/settings_screen.py`: `_provider_display_name` is now one call to `provider_display_name` (the catalog loop it fell back to is redundant).
- `provider_registry.py`: docstring only; its `display_name` values are engine error-copy prefixes and stay (rider).

Relabels (controller ruling 19, spec rule 2): the Settings provider picker and the First-run list move from the private names to the catalog's: Google -> Google Gemini, Moonshot -> Moonshot AI, MistralAI -> Mistral AI, Custom OpenAI (2) -> Custom OpenAI-compatible (#2), Aphrodite -> Aphrodite Engine, Koboldcpp -> KoboldCpp, and the legacy aliases gain "(legacy alias)". FirstRunSetupWizard.py is not edited. The chip cap is unchanged (no .tcss touched); long names ellipsize.

Tests: new `Tests/Chat/test_provider_catalog.py` (shipped-table walk, saved spellings, unmapped ids, custom-ep names, Console catalog from the shared map); chip tests in `Tests/Chat/test_console_display_state.py`; a real-ChatScreen custom-ep chip test (config wired as in production) in `Tests/UI/test_console_session_settings.py`. Rewritten on purpose: `test_console_readiness_uses_saved_session_settings_over_stale_global_provider` and `test_console_control_and_inspector_share_effective_provider_model_sources` ('Provider: llama_cpp' -> 'Provider: llama.cpp', plus an identity-still-key assertion), `test_stale_default_refresh_swap_is_visible` (display names, not keys), `test_display_name_and_endpoint_doc_entries` (private map import), and the hub coverage test now imports the map from provider_catalog. The four env-gated UI tests run under `@private_profile_test`.

Captures in `qa/model-config-p2-2026-09-27/task-5/`. Docs: `Docs/User_Guide/console.md` (status-chip row, stamp) and `settings.md` (Moonshot AI / Z.ai, relabel stamp).
