## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by TASK-36511's stress stacks (2026-11-03). The 0.25 s credential-readiness poll (`_poll_console_credential_readiness`) still enters `run_console_config_sync` and `operation(config)` on the UI loop when config is cold. It showed up in 1 of 6 stress stacks. TASK-36511 bounded cold deferral for the full sync's core-state push and for `retry_after_config_rebuild` refreshes, but not for this poll.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 When config is cold, the credential poll does not rebuild config on the UI loop while the off-loop warm can succeed; it defers its first cold read per episode and starts the off-loop warm, as the TASK-36511 helper `defer_cold_live_read` does
- [x] #2 With an unparseable config.toml the poll stays bounded: no repeated UI-loop rebuilds while idle
- [x] #3 A test pins both behaviours
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Measure on dev: a mounted Console with a cold (externally edited) config, poll forced past its pre-gate; count UI-thread `_load_settings_uncached` calls under `_poll_console_credential_readiness` and time the tick.
2. Fix in the poll's locked section: while it holds both config locks, ask `defer_cold_live_read` (owner = the poll); on a deferral kick the readiness projection's off-loop read and return without committing the pre-gate, so the next tick retries; otherwise keep the existing route.
3. Pin both behaviours in a unit test in `Tests/UI/test_console_projection_reads_off_loop.py` (census-run file): first cold tick defers and kicks the warm, a warm retry renders; a config that stays cold reads live once on the second tick, commits the pre-gate, and idle ticks then do nothing. Show it red on dev (AC#1) and under a defer-always source edit (AC#2).
4. Re-measure, run covering tests, size ratchet.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Approach.** Two changes in `ChatScreen._poll_console_credential_readiness`, base dev bb80905eb3:
- While it holds both config locks, the poll asks `spend.defer_cold_live_read(self, "_poll_console_credential_readiness")`, the TASK-36511 helper. On its first cold read per episode it starts the readiness projection's off-loop read (`ConsoleReadinessConfigProjection.for_screen(self).run(lambda: None)`, as `retry_after_config_rebuild` does) and returns without committing the pre-gate, so the next 0.25 s tick renders. A later cold tick in the same episode reads live, as before.
- A pass whose readiness snapshot was unchanged now commits the pre-gate too. It used to `return` before that commit. So whenever the pre-gate moved and the snapshot did not (for example a background status change the readiness snapshot does not carry), every later tick rebuilt readiness, and with cold config it rebuilt config on the UI loop every 0.25 s. AC#2 cannot hold without this. The deferral alone still measured 10 UI-loop rebuilds in 2.5 s.

**Measurement** (temporary mounted probe, not committed: the send harness at 160x45, caches dropped with `config._invalidate_config_caches()` after a file edit, the tick forced past its pre-gate, UI-thread `_load_settings_uncached` calls counted with `sys.setprofile`):
- Valid edit, cold. Dev's first tick rebuilt config on the UI loop: 147-222 ms wall, 147-183 ms CPU, load 8-11. Branch: the first tick deferred in 0.4-0.6 ms with 0 UI-loop rebuilds, and the next tick found config warm (7-13 ms, 0 rebuilds), at load 9-21.
- Unparseable file, idle: the real timer ran 2.5 s after one pre-gate change. UI-loop rebuilds under the poll: dev 9, deferral alone 10, branch 1 (the single live read after the deferral).

**Red/green.** `test_the_credential_poll_defers_a_cold_read_once_and_then_stays_idle` in `Tests/UI/test_console_projection_reads_off_loop.py` (census entry):
- red on dev: `(1, [True]) == (0, [])`, "the poll rebuilt cold config on the UI loop";
- red with only the deferral: `5 != 2`, "idle ticks kept reading cold config";
- red under a temporary defer-every-cold-read edit: "a still-cold tick deferred again";
- green on the branch.

**Regression check.** 13 covering files at `-n 4`: branch 26 failed / 214 passed at load 21-23; dev sources 25 / 215 on the same command. The only failure in one set and not the other is the new test (red on dev). The rest is `test_console_cost_chip_screen.py` load flakes, whose failing set changed run to run on both arms (dev alone: 3 and 13 failures at load 26-30; that file runs in no PR lane). `test_console_subscription_readiness.py` failed once on each arm under load, with different tests, then passed 9 of 9 interleaved runs per arm at load 13-48. A temporary log in the deferral branch showed the poll never defers in that file. Size ratchet re-pinned 24601 -> 24607 with a dated waiver comment (+6 lines, no methods). Preflight passes.

**Not changed (proposed follow-up).** `defer_cold_live_read` ends an episode only when some owner sees warm config. The poll reaches its locked section only after a pre-gate change. So after a broken config is fixed, the poll's entry can stay in the set until another owner sees warm config, and the first tick of a later cold episode then reads live once (seen in the probe's back-to-back unparseable rounds). The helper lives in `console_spend_projection.py`, which open PR #3396 edits, so it was left alone.
