## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** In a Temporary tab, every send stops before reaching the provider, not just the first one. An orange callout appears:

> 'Save chat to capture this send / Owner: This Console send / Problem: Temporary chats cannot store durable captures. / Impact: The provider was not contacted. Choose how to continue.'

The buttons:
- 'Save & Send' comes first and ends the chat's temporary status.
- 'Send without capture' has equal full-width orange weight, but it only covers the one message.
- 'Cancel send' is neutral.
- No button takes focus.

At the same time the rail shows ⛔ 'Blocked', the transcript edge shows 'blocked', and the queue shelf shows 'Unsent turn needs attention'. An explicit privacy choice is framed as an error, and the default action silently undoes it.

A separate defect was found while verifying (2 of 2 tries): 'Save & Send' saves the chat but never sends. The log shows 'Durable turn commit failed; turn refused (exception_type=RuntimeError)' after promoting the ephemeral session, and the proxy received no POST. The UI then sits for more than 60 s on:
- 'Run: Validating provider.' and 'Preparing…';
- the wrong composer hint 'Send blocked — finish provider setup to continue ›';
- 'Running' in the header.

A normal saved chat sent fine in the same session.

**Severity / prior art.** P1, BY_DESIGN for the pause itself: ADR-097 (lines 160-165) and TASK-23113.5 / TASK-23113.9 (Done) intend Save & Send for temporary chats. The UX critique targets choices the ADR does not decide: Capture On as the default for Temporary chats, the button order, the error framing, and the duplicate surfaces. ADR-097 already allows explicit Capture Off. Related: TASK-25814 (Done).

Related findings owned elsewhere:
- The stale queue shelf after a one-shot send: G1-13.
- The misleading 'finish provider setup' copy for commit failures: GAP2-16.

**Suggested direction.**
1. Set conversation-scoped Capture Off when a Temporary tab is created, with a quiet 'Temporary · traces off' chip and an optional 'Save chat (enables capture)' action.
2. If a choice is kept, make it once per chat. Put 'Keep temporary (no trace)' first and focus it, use neutral styling, and suppress the rail and shelf blocked surfaces for this pause kind.
3. Fix the durable-commit RuntimeError after promotion, so that Save & Send reaches the provider.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G2-06 (source J3-04); qa/console-ux-review-2026-09-29/evidence/evidence__J3__15-sent4.png, evidence__J3__15-sent4.txt.

Review finding ids: G2-06 — see qa/console-ux-review-2026-09-29/findings.md.

**Owner decision (2026-10-27, ACs 1-3 amended to match).** Option (a): Temporary tabs start with conversation-scoped Capture Off, show a quiet 'Temporary · traces off' chip and offer an optional 'Save chat (enables capture)' action; sends never pause on capture in a Temporary chat. ACs 4-6 stand: Save & Send stays reachable for someone who turns Capture On in a chat that is still temporary, and must work.

## Implementation Notes

Owner decision 2026-10-27 implemented as option (a); ACs 1-3 amended to it first (ad26dca62a).

**Reproduced live on dev 38c9d2edcf (160x45, real Anthropic via the review proxy).** A Temporary tab's first send stopped on 'Save chat to capture this send' with rail ⛔ Blocked, edge 'blocked', header Blocked and the shelf 'Not sent: Trace capture needs a saved chat'. Save & Send saved the chat and then refused the send; a temporary probe (reverted) logged `RuntimeError: Durable Console Library policy no longer matches acceptance` from chat_persistence_service.commit_durable_turn, with the acceptance's authority `source=temporary, policy_revision=None` against the saved row `(0, 0, 1)`.

**Save & Send (f12d750cf4).** The send's Library ceiling (`configuration.library_policy_maximum`) is frozen from the session's holder while the chat is temporary. `_capture_turn_library_authority` kept the ceiling's identity whenever the live policy was not narrower, so after promotion the commit checked a temporary identity against the durable row promotion had just written. A ceiling frozen as `temporary` now takes the live durable identity once the chat is saved (limits unchanged: promotion commits the temporary policy as it was). The existing controller test did freeze that ceiling (`submit_draft` resolves a turn configuration) and was red on dev at its own `source == "durable"` assertion under a bootstrapped profile; it went unseen because no CI lane runs its file and a plain local run stops earlier on `RecoveryRequired` / `Hooks unavailable`. (An earlier version of this note said the test froze no ceiling and stayed green; the pre-merge review disproved that.) Past that, its failing trace boundary reaches dev's documented TRACE_CALL pause (in dev since c78f641adf, before the test was written), so its tail now asserts that.

**Default Capture Off (9fcb7d5611).** `console_exchange_capture.temporary_chat_capture` resolves a Temporary chat's conversation Capture to Off unless someone chose one; applied at both controller resolutions (policy snapshot, stream signals). Resolved, not stored: saving the chat hands Capture back to the global setting ("Save chat (enables capture)"), and a PII-only Trace Privacy apply cannot pin Off into the saved chat (the dialog shows conversation scope Inherit with "Future trace: Capture Off"). Chip 'Temporary · traces off' (tab ◌ decode follows it); composer Menu row 'Save chat (enables capture)'; Trace Privacy guidance says traces are off until saved. Someone who turns Capture On in a still-temporary chat keeps the Save & Send card (its Blocked surfaces are TASK-33621.2's deliberate copy for that opt-in). Tests pinning the opt-in pause now choose Capture On explicitly.

**Tests.** New `Tests/UI/test_console_temporary_capture_flow.py` (stock received path, real ChatScreen/runtime/controller/store and file DB; only chat_api_call is a double; added to the UI PR gate census): default send goes out with no pause/shelf/Blocked, chip painted, Save chat re-enables capture (red before the default change: 'Trace capture needs a saved chat'); Save & Send replies with run COMPLETED and no Validating/Preparing (red on dev: the same durable_commit RuntimeError).
