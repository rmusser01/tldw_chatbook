## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** In a Temporary tab, every send stops before reaching the provider, not just the first one. An orange callout appears:

> 'Save chat to capture this send / Owner: This Console send / Problem: Temporary chats cannot store durable captures. / Impact: The provider was not contacted. Choose how to continue.'

The buttons:
- 'Save & Send' comes first and ends the chat's temporary status.
- 'Send without capture' has equal full-width orange weight, but it only covers the one message.
- 'Cancel send' is neutral.
- No button takes focus.

At the same time the rail shows ⛔ 'Blocked', the transcript edge shows 'blocked', and the queue shelf shows 'Unsent turn needs attention'. An explicit privacy choice is framed as an error, and the default action silently undoes it.

A separate defect was found while verifying (2 of 2 tries): 'Save & Send' saves the chat but never sends. The log shows 'Durable turn commit failed; turn refused (exception_type=RuntimeError)' after promoting the ephemeral session, and the proxy received no POST. The UI then sits for more than 60 s on:
- 'Run: Validating provider.' and 'Preparing…';
- the wrong composer hint 'Send blocked — finish provider setup to continue ›';
- 'Running' in the header.

A normal saved chat sent fine in the same session.

**Severity / prior art.** P1, BY_DESIGN for the pause itself: ADR-097 (lines 160-165) and TASK-23113.5 / TASK-23113.9 (Done) intend Save & Send for temporary chats. The UX critique targets choices the ADR does not decide: Capture On as the default for Temporary chats, the button order, the error framing, and the duplicate surfaces. ADR-097 already allows explicit Capture Off. Related: TASK-25814 (Done).

Related findings owned elsewhere:
- The stale queue shelf after a one-shot send: G1-13.
- The misleading 'finish provider setup' copy for commit failures: GAP2-16.

**Suggested direction.**
1. Set conversation-scoped Capture Off when a Temporary tab is created, with a quiet 'Temporary · traces off' chip and an optional 'Save chat (enables capture)' action.
2. If a choice is kept, make it once per chat. Put 'Keep temporary (no trace)' first and focus it, use neutral styling, and suppress the rail and shelf blocked surfaces for this pause kind.
3. Fix the durable-commit RuntimeError after promotion, so that Save & Send reaches the provider.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G2-06 (source J3-04); qa/console-ux-review-2026-09-29/evidence/evidence__J3__15-sent4.png, evidence__J3__15-sent4.txt.
