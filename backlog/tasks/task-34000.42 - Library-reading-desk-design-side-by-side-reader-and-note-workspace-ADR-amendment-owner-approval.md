## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: the review's researcher journey (Priya) and its first-timer and power-user journeys all hit the same wall: a source and a note are never on screen together. Taking a note while reading costs a rail switch, and the switch discards the reading position and closes a new note (S-02). Quotes and kept answers then lose their source (S-03, S-04). The read → note → ask → keep loop is the product's core researcher loop (PRODUCT.md: users "ingest or select sources, reason over them ... and preserve useful outputs"), and it breaks at the first step.

Owner ruling 2026-10-03: build a reading desk. That changes the Library's adaptive reader shell, whose layout ADR-086 (and ADR-084, the Library media reader IA — `084-library-media-reader-ia.md`; three ADRs share the number 84) fixes. By the standing owner rule, a redesigned screen or mode is approved explicitly from rendered mockups before implementation, in the existing Console/Settings/Library visual language.

This task produces the design, not the code:
- the desk's layout at the supported widths (at least 120x36, 160x45 and 200+ columns) and how it degrades below them;
- how a source and a note are opened, swapped and closed;
- keyboard ownership between the two panes (F6, Escape, Ctrl+S per the amended ADR-031);
- quote-to-note with a source link, which S-03 needs;
- what state survives navigation;
- the ADR-086/084 amendment text.

TASK-34000.25 (preserving reader and note state across rail switches, plus a Take note action) is the near-term fix and must not wait for the desk. The desk design must build on it, not replace it. Implementation tasks are filed only after approval.
