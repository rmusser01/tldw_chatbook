## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The roadmap's Phase 3 exit gate requires that ChaChaNotes_DB imports neither Chat nor Sync_Interop. TASK-36949.3 removed the semantic coordinator import, and TASK-36949.4 removed every Sync_Interop import. Seven Chat imports remain, and three layer-allowlist rows record them (`DB.ChaChaNotes_DB → Chat.assistant_generation_state / console_exchange_capture / console_library_policy`, all lazy):
- four lazy imports of `Chat.assistant_generation_state` in the message insert, update and projection writers;
- `Chat.console_library_policy`, under TYPE_CHECKING for the migration-seed annotation and in a migration;
- `Chat.console_exchange_capture`, in a migration.

The DB layer must not depend on the Chat feature package.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

1. `Chat/assistant_generation_state.py` is stdlib-only (the persisted lifecycle vocabulary and its pure helpers): `git mv` it to `DB/assistant_generation_state.py` and retarget every importer (production and tests). ChaChaNotes_DB imports `normalize_assistant_generation_state` once at top level from the sibling module instead of four lazy Chat imports. No shim; the boot module count is unchanged (the same module under a new name).
2. `ConsoleLibraryMigrationSeed` is a pure input contract of the v47->v48 migration: move the dataclass into `DB/ChaChaNotes_DB.py` beside the migration. `config.load_console_library_migration_seed` takes it from the `ChaChaNotes_DB` import config already makes at top level (no new edge; its own lazy `config -> Chat.console_library_policy` row goes stale and is deleted). Retarget the tests that build seeds.
3. The v52->v53 Safe-capture trim needs the Chat capture codec (decode, compact, re-encode through the credential sanitizer), which is Chat semantics and pulls `console_trace_redaction` and `console_project_instructions`: invert it with a DB-layer port in `DB/transaction_observer.py`, the same shape as the TASK-36949.3/.4 ports (process-wide slot, installer, fail-closed accessor). The port also defines the per-row "unreadable blob" error the migration skips; `CaptureUnavailableError` subclasses it so the skip set is unchanged. `console_exchange_capture` installs the port on import; every composition root that installs the other two ports installs this one; `Tests/conftest.py` installs a lazy real implementation. The accessor is reached only when a stored Safe blob is examined, so a fresh database never needs it; an uncomposed process upgrading a v52 database with Safe captures raises SchemaError and rolls back (the database stays v52).
4. Delete the three ChaChaNotes_DB -> Chat allowlist rows (and the stale config row). Add a guard in `Tests/Architecture/test_layer_direction.py` that ChaChaNotes_DB imports no `tldw_chatbook.Chat` module at any kind (top, TYPE_CHECKING, lazy, `import_module`), shown red at base.
5. Retarget the v53 sabotage monkeypatch and prove it still reaches the migration (neutralise -> red). Find and run fresh-interpreter children that upgrade a v52 database with Safe captures.
6. Re-pin size rows; run covering tests at base and head, serial Tests/Architecture, both boot-import ratchets (ui-ready twice), preflight.

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
ChaChaNotes_DB now imports no `tldw_chatbook.Chat` module of any kind. The seven imports go three ways:

- **Pure code moved down.** `Chat/assistant_generation_state.py` (stdlib-only) is now `DB/assistant_generation_state.py` (`git mv`); its 13 other production importers and 5 test files are retargeted, with no shim. ChaChaNotes_DB imports `normalize_assistant_generation_state` once at top level from the sibling module instead of 4 lazy Chat imports. The boot module set is unchanged apart from the rename: app-import 687/688 and ui-ready 1037/1038 in two runs. The two boot snapshots were regenerated with `scripts/update_boot_budget_snapshots.py`, and the diff is exactly that one renamed line in each.
- **The seed contract moved to its consumer.** `ConsoleLibraryMigrationSeed` (a pure dataclass, the v47->v48 migration's input) is now defined in `DB/ChaChaNotes_DB.py`. `config.py` gets it from the `ChaChaNotes_DB` import it already makes at top level. That adds no edge, and it removes config's own lazy `config -> Chat.console_library_policy` row (now stale) and its `TYPE_CHECKING` block. The 11 test files that build seeds are retargeted.
- **The capture codec is inverted through a port.** The v52->v53 trim needs the Console capture codec (decode, compact, re-encode through `CredentialSanitizer`), which is Chat semantics and pulls `console_trace_redaction` and `console_project_instructions`. Moving it down would have meant about 1.5k lines across three modules. Instead, `DB/transaction_observer.py` gains a third port in the TASK-36949.3/.4 shape: `install_safe_capture_trimmer` / `trim_stored_safe_capture`, `SafeCaptureTrimmingNotInstalledError`, and `UnreadableCaptureBlobError(ValueError)`. `CaptureUnavailableError` now subclasses `UnreadableCaptureBlobError`, so the per-row skip set is unchanged and the class is still a `ValueError`. `console_exchange_capture.install_safe_capture_trimming()` installs a lambda that looks up `trim_safe_capture_blob` on every call, so existing patches still reach it. It runs on import, at the 7 composition roots that install the other two ports (app_entry x3, MCP server, serve, mobile_service, RAG backfill), and in `Tests/conftest.py`.

**Behaviour change:** the slot is reached only for a stored Safe blob. A fresh database, and a database with no Safe captures, open without it; this includes the installed-wheel v35->current probe. An uncomposed process that upgrades a v52 database holding Safe captures now gets a `SchemaError`, and the step rolls back, leaving the database at v52 with byte-identical blobs. A composed process then upgrades it. The only fresh-interpreter test child that reaches the step, the v53 SIGKILL child, imports `console_exchange_capture` and so installs the port.

**Allowlist:** removed the three ChaChaNotes_DB -> Chat rows and the stale `config -> Chat.console_library_policy` row. No row was added.

**Size rows:** ChaChaNotes_DB goes +1 (24870 -> 24871 at the original base; 24908 -> 24909 after the coordinator's rebase onto TASK-36949.4's fix round, dated comment). The seed class (+12) and the port's error names in the v53 step outweigh the removed imports. config.py goes 8983 -> 8967, its exact measurement.

**Docs:** `Docs/Architecture/database-layer.md` gains rows for `transaction_observer.py` (the three ports) and `assistant_generation_state.py`.
