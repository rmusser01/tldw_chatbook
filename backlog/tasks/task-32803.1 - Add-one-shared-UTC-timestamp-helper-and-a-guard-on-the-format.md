## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Twelve distinct UTC string shapes are produced by 55 helper copies across the package, SQLite's `CURRENT_TIMESTAMP` adds a thirteenth in the 31 tables that default to it, and 100 sites compare the results lexically -- only two normalise. Three of those comparisons are already wrong for users. There is no shared time module in `Utils/` and no check anywhere on the format a timestamp is written in.

Source: core-runtime code review 2026-09-17 — `qa/core-code-review-2026-09-17/report.md`; per-slice evidence in `qa/core-code-review-2026-09-17/slices/`, reproductions in `qa/core-code-review-2026-09-17/phase4-verification.md`.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A single helper module provides UTC-now formatting, a parser that accepts every shape currently in the wild, and the SQLite text format
- [x] #2 A guard forbids the non-helper timestamp idioms (deprecated datetime.utcnow() outright; naive datetime.now().isoformat() ratcheted) so new writers must use the shared helper
- [x] #3 The guard runs in preflight and in the derived-artifacts CI job
- [x] #4 An ADR records the chosen storage format (ADR-173, Status: Proposed — pending owner ratification)

PR #2735 (`fix/core-review-time`). Delivered the helper + a draft ADR for

AC#1 — `tldw_chatbook/Utils/timestamps.py`: `utc_now()` (aware UTC),
`utc_now_iso()`/`to_utc_iso(dt)` (canonical shape), `parse_utc(value)` (tolerant
of every shape on disk — canonical, +00:00 ISO, T/space separator, sec/ms/us
precision, date-only, SQLite CURRENT_TIMESTAMP; naive interpreted as UTC).
Gate-free tests in `Tests/Utils/test_timestamps.py` (17 cases).

AC#4 — ADR-173 records the canonical stored shape `YYYY-MM-DDTHH:MM:SS.mmmZ`
(millisecond ISO-8601 UTC with Z; fixed 24 chars so TEXT sort == chronological
sort — the property whose absence caused the three shipped bugs in .2/.3/.4).
Status **Proposed**: the three earlier fixes each independently converged on
this shape; the ADR records it as the package contract. Alternatives
(microseconds, +00:00, epoch integers, per-module helpers) documented and
rejected.

AC#2/#3 — DEFERRED to ratification. The format guard (assert timestamp-bearing
writes route through the helper) wired into preflight + the derived-artifacts CI
job encodes the ratified decision, so it is built after the ADR is Accepted.

Modified: `tldw_chatbook/Utils/timestamps.py` (new),
`Tests/Utils/test_timestamps.py` (new),
`backlog/decisions/173-utc-timestamp-storage-format.md` (new).

REVIEW PASS 2026-09-20 (pre-ratification): tightened ADR-173 after a self-review
found the ordering guarantee oversold. The three SHIPPED bugs are SQL-level
comparisons (T-value vs CURRENT_TIMESTAMP space-value); a Python parse_utc can't
run in a SQL WHERE/ORDER BY. ADR now states the canonical write format is
necessary-not-sufficient, adds a "Guarantee scope" (free lexical order only on
all-canonical columns), and requires mixed-column comparisons to normalise both
sides — SQL via julianday()/datetime() (the console_trace_settlement precedent).
Tightened the parse_utc claim (stored/compared shapes, not display strftime;
raises ValueError otherwise). Added helper `is_canonical_utc(value)` + regex so
the deferred format guard (AC#2) has something to assert; test pins that
everything to_utc_iso emits IS canonical. Format decision unchanged.

GUARD DONE 2026-09-20 (AC#2/#3; task now Done): with ADR-173 Accepted, added
scripts/check_timestamp_writers.py (AST scan), wired into preflight AND the
"Derived artifacts reproduce from their sources" CI job. It (a) forbids
datetime.utcnow() outright — fixed the one genuine remaining call
(Chunking/engine/security_logger.py naive utcnow → utc_now_iso); (b) ratchets the
53 naive datetime.now().isoformat() writers in scripts/timestamp_writer_census.tsv
(keyed module::symbol::kind), failing on any new/grown one, shrinking as .5
adopts. Aware datetime.now(timezone.utc).isoformat() and display strftime are not
flagged (no false positives). Note on AC#2 shape: proving EVERY column write goes
through the helper is undecidable statically, so the guard enforces the
practical contract — new code cannot use the deprecated/naive idioms and must
reach for utc_now_iso()/to_utc_iso(). Tests: Tests/Scripts/test_check_timestamp_writers.py.
