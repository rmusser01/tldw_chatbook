## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Fixed on TASK-33621.50's branch, since it is the same code path. Both video adapters raised a plain VideoGenerationError('... cancelled by user') on Stop, and the Console's generic handler turned it into 'Video generation failed (VideoGenerationError)'. MiniMax and ComfyUI now raise the typed VideoGenerationCancelled. The Console's /generate-video and Regenerate handlers catch it before the failure handler and post a stop row: 'Video generation stopped.' for a local backend, or the MiniMax outcome rows described in TASK-33621.50. The resend hint and draft restore are unchanged.

AC#1/#2/#3 are pinned in Tests/UI/test_console_video_stop_outcome.py, which uses the real app, real Stop button, real MiniMax adapter and recorded responses. The two Stop tests are red on origin/dev with 'Video generation failed (VideoGenerationError).'. test_a_real_minimax_failure_still_reads_as_a_failure (HTTP 500 on poll, no Stop) keeps 'Video generation failed' and passes on dev and on the branch. Live, in the real app with real MiniMax, both Stop outcomes read as a stop, never a failure (see TASK-33621.50).

Merge evidence (2026-10-30, rebased onto origin/dev 7536ac3b87): following review, Regenerate's stop is now pinned too (Tests/Chat/test_console_video_controller.py: stop reads as a stop for cancelled and refused, and a real error still reads 'Video regeneration failed'). Live on the final head, both MiniMax Stop outcomes read as a stop, never a failure.
