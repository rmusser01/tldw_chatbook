## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Both Console editors rebase a provider change with no model: the Alt+M popover (Widgets/Console/console_model_popover.py:1090-1101) and the Conversation settings modal (Widgets/Console/console_settings_modal.py:5372-5373). Both go through ConsoleChatController.rebase_console_settings_draft (Chat/console_chat_controller.py:12946, :12982) to build_target_default_console_session_settings and then resolve_effective_chat_configuration (Chat/console_session_settings.py:1254). That resolver tries models in the order session, chat_defaults.model, provider model/api_model/default_model (:1269-1275). It applies chat_defaults.model without checking that the explicit provider is chat_defaults.provider. So every switched-to provider inherits the global default model. With the shipped default OpenAI / gpt-5.6-terra (config.py:4612-4613), switching llama.cpp to Anthropic yields gpt-5.6-terra.

This is not by design. ADR-006's precedence treats chat_defaults.model as belonging to chat_defaults.provider. The TASK-364 comment at console_model_popover.py:1097-1099 says a stale model from another provider must not linger. TASK-14812 AC#6 says a provider change cannot retain a model from the previous provider.

Tests pin only the same-provider precedence: test_chat_defaults_model_outranks_provider_fallback (Tests/Chat/test_console_session_settings.py:161). No test covers a cross-provider rebase with no model; Tests/Chat/test_console_settings_apply.py:763-775 asserts only the provider. The resolver already computes a canonical provider id (_canonical_chat_provider_id, console_session_settings.py:1970), which handles case, legacy aliases and custom-endpoint registry ids (ADR-146). Absorbs TASK-14812.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
- `resolve_effective_chat_configuration` now offers `chat_defaults.model` only when the resolved provider is canonically `chat_defaults.provider`. Both sides go through `_canonical_chat_provider_id`, which handles case, legacy aliases and registry ids, and are then compared with `provider_identity_key`, so `custom_ep:<slug>` equals `custom-ep:<slug>`. Otherwise the chain falls through to the target provider's `model` / `api_model` / `default_model`, or to no model (`model_source="none"`). The Alt+M popover and the Conversation settings modal both rebase through this resolver (`rebase_console_settings_draft` -> `build_target_default_console_session_settings`), so one guard fixes both.
- Per ruling R5, the other callers that pass an explicit provider and no model change with it: the controller's selection builder (used only for the `max_tokens` fallback), `agent_routing` (spawn sampling params), and `personas_preview` (unchanged in practice, because it passes its own defaults section). Each now reads the target provider's own model profile instead of the borrowed model's. Two more callers change the same way: `ChatScreen._console_default_readiness` (both editors' `default_readiness_resolver`) now reports a missing model for a provider with no configured model, and the agent `chat_create` routed settings (`model=target.model or None` in the controller) take the target's own model.
- A `chat_defaults.model` with no `chat_defaults.provider` is now not borrowed by an explicit provider (rule 1 is strict). Two QwenCloud fail-closed tests relied on that orphan model to pass validation. They were rewritten on purpose to name `provider = "qwencloud"`, and their intent (fail closed, no canary leak) is unchanged.
- New tests: resolver cases in `Tests/Chat/test_console_session_settings.py`, a mounted modal driving the real controller rebase, and the AC#5 new-chat test, which drives the real `ConsoleSessionController._default_console_session_settings` fed by the real `ChatScreen._effective_console_provider_model`. Real-path rebase tests in `Tests/Chat/test_console_settings_apply.py`: local-to-cloud for both editors' field sets, cloud-to-cloud, a provider with no model (validation "Model is required." and readiness `model_missing`), and the default provider keeping the default model.
- AC#5 holds by construction: Ctrl+T always passes an explicit model (the control model or `chat_defaults.model`), and the startup chat passes no provider.
- Rider TASK-33001.8: the sibling fallback in `resolve_effective_provider_model` is reachable today. The palette's Switch to llama_cpp (empty model list) followed by Ctrl+T opens a llama_cpp tab on `gpt-5.6-terra`.
- Fix round 1 (review): added a mounted Alt+M popover test driving the real controller rebase and the real `ChatScreen._console_default_readiness` (llama.cpp -> Anthropic fills Anthropic's model; Anthropic -> Moonshot with no configured model leaves the picker empty, Apply says "Choose a model.", Defaults says "Unavailable: choose a model first."). Both mounted tests now put the configured model second in the catalog, so a snap-to-first-catalog-model regression fails. Drove the popover live on a scratch profile (console.md stamp). The six Tests/UI files that exercise these editors run in this worktree: 553 pass, 390 fail with ADR-126 `RecoveryRequired` (CI-only), and 10 fail identically at BASE.
- Files: `tldw_chatbook/Chat/console_session_settings.py`, `Tests/Chat/test_console_session_settings.py`, `Tests/Chat/test_console_settings_apply.py`, `Docs/User_Guide/console.md`, the TASK-14812 file (closed), and the new TASK-33001.8 file.
