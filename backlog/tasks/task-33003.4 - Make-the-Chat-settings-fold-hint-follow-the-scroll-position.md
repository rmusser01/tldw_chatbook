## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The '▼ more — scroll for the rest' hint only checks whether the body overflows (_sync_fold_hint, Widgets/Console/console_settings_modal.py:3850-3866). None of its callers (:2709, :2716, :3216, :3361, :3574, :3672, :3677, :3892) runs on scroll, so the hint still promises more content after the user has reached the bottom (C5(c)). The sibling ConsoleBoundedSection already watches scroll_y (Widgets/Console/console_bounded_section.py:234). No test or ADR pins the hint at the bottom; existing tests pin only that it shows while the body overflows.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 When the content overflows, the fold hint is visible while content remains below the viewport and hidden once the body is scrolled to the bottom. Only scrolling drives this, proven by a pilot test that uses real scroll or key presses.
- [x] #2 Scrolling back up from the bottom shows the hint again, with no other trigger.
- [x] #3 The recovery-summary variant of the hint follows the same rule.
- [x] #4 The existing overflow pins stay green unchanged: Tests/UI/test_console_resize_reflow.py (:846-856) and Tests/UI/test_console_context_controls.py (:980-985).
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Write a failing pilot test under the production stylesheet: wheel events alone (no sync call) must hide the hint at the bottom and show it one notch back up, for the plain and the recovery-summary variants, at a forced-overflow 72x24.
2. Subscribe the modal to its body's scroll_y (self.watch, like ConsoleBoundedSection) and make _sync_fold_hint show the hint only while scroll_y < max_scroll_y, updating the text only when it changes so a scroll step does not relayout.
3. Keep the AC#4 overflow pins green unchanged.
4. Live-verify at 211x44 and 235x52 on a scratch profile; regression-compare the modal's test files against the task base; update the Console User Guide; preflight.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Fold hint follows the body scroll position and content growth; details below.

**Approach.** `ConsoleSettingsModal.on_mount` now watches its body (`#console-settings-body`) the way ConsoleBoundedSection watches its viewport: `scroll_y` calls `_sync_fold_hint` directly, and `virtual_size` calls it after the next refresh. `_sync_fold_hint` shows the hint only while `scroll_y < max_scroll_y` (content remains below) instead of whenever the body overflows, for both the plain copy and the recovery-summary copy, and calls `hint.update()` only when the copy changes so a wheel notch does not relayout the modal.

**Deviation from the plan (the `virtual_size` watch).** The live check at 211x44 showed the hint hidden on open with 9 rows below: the focused provider picker renders its results after the last existing caller ran, so no sync ever saw the overflow. The same was true at the base (Task 3's `live-chat-settings-model-open-211x44.txt` has no hint). AC#1 ("visible while content remains below") needs a re-sync when content grows. The call is deferred because Textual's `_size_updated` sets `virtual_size` before `_container_size`.

**Tests** (`Tests/UI/test_console_resize_reflow.py`, production stylesheet):
- `test_fold_hint_follows_the_body_scroll_position[model-view|recovery]` covers AC#1-#3. At 72x24, it uses only wheel events posted to the body: the hint shows before every notch, hides at the bottom, and shows again one notch up. The recovery copy is kept throughout.
- `test_fold_hint_follows_content_that_grows_without_a_scroll` works at 211x44 with only Tab and Shift+Tab. The picker results open (max_scroll_y 9, hint shown), close (0, hidden), and reopen (shown).
- RED before the change: the scroll test gave `assert not True` at the bottom. With only the scroll watch, the growth test gave `assert False` at open. Negative controls, run in a scratch tree: dropping the `scroll_y` watch, or restoring the old overflow rule, fails both scroll variants.
- AC#4 pins are unchanged and green: `test_blocked_quick_transfer_keeps_initial_model_focus_visible[60|72]`, `test_context_view_fits_narrow_terminal_and_keeps_focusable_controls`, and the recovery-copy pin `test_full_settings_recovery_actions_are_mouse_reachable_at_narrow_width` (11 passed).
