## Description

<!-- SECTION:DESCRIPTION:BEGIN -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented approach (a) from the persistent-rails spec, recorded in ADR-043 (accepted, indexed; spec compact-width paragraph amended with a pointer): the 150/100-col compact rail collapses are now the responsive DEFAULT, not a hard block. An explicit rail toggle is honored at any width, so no manual toggle can silently persist a preference with zero visual change (LY-11 fixed for BOTH rails).

Mechanism: right rail explicitness is value-based (default/explicit-false keep the collapse and the pending-launch auto-open suppression byte-identically; only right_open=True yields). Left rail explicitness uses a new additive payload marker left_open_explicit (console_rail_left_open_explicit helper owns the read): the left default is OPEN and every write serializes the full payload, so neither value nor key-presence can distinguish an explicit open (UAT p7c caught the key-presence variant opening the left rail at 80x24 after a right-rail chip click; regression-guarded by test). _set_console_rail_preference now writes through on explicit rail toggles (coerced-equal values persist) and stamps/preserves the marker. New *_compact_override flags on ConsoleRailState (computed only in build_console_rail_state, so the 118-128 band + pending-launch replace() paths keep their exact rendering) extend the single-pane min-width waiver to honored-below-threshold rails: the grid always resolves, rails keep standard mins 24/34.

DS-06: ConsoleSourcesChip/ConsoleToolsChip mirror the ConsoleRagChip activation contract (enter/space/click -> OpenRequested); both route to ChatScreen._reveal_console_inspector_rail(), which opens the rail through the same preference seam as the handle and focuses it, so activation is visible even when already open. Chips are the only Inspector route in single-pane mode (handles hide).
