## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Seen on 2026-11-06 in a live smoke run for TASK-33620.15.47 (origin/dev 2684e5453f plus that branch, which does not touch splash code). The randomly chosen `quantum_tunnel` card logged `Error updating animation frame: closing tag '[/bold]' does not match any open tag`, and the splash driver stopped the animation and showed the static fallback.

Cause: once the title starts to emerge (2 s after start), the card styles each title character `bold rgb(0,N,255)` but closes the tag with only the style's first word, `[/bold]`. Textual's markup parser, which `Static.update` uses, rejects that. A stand-alone check with `textual.content.Content.from_markup` agrees: `[bold rgb(0,128,255)]t[/bold]` raises `MarkupError`, while `[bold rgb(0,128,255)]t[/]` and the card's single-word styles (`[rgb(0,128,64)]*[/rgb(0,128,64)]`, `[cyan]s[/cyan]`) parse.

TASK-31001 covers five other cards with the same class of failure. `quantum_tunnel` is not in `KNOWN_BROKEN_EFFECT_CARDS`, and the playback smoke in `Tests/Widgets/test_splash_animation_playback.py` cannot catch it: the smoke renders five frames right after the animation starts, and the card reads wall-clock time, so those frames come long before the 2 s title and never reach the bad tag.
