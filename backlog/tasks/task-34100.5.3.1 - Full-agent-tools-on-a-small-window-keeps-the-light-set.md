## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-34100.5.3 gave plain Console chat a light tool set by default (date and time, calculator, ask-you-a-question) and a **Full agent tools** switch for the rest. Its review round 3 (finding R3-3) found that on a model with about 8,000 tokens of context, switching more on can leave chat with fewer tools than the default. The branch fixed this for single opt-in tools: the light set now stays when an opt-in tool no longer fits beside it. It did not fix it for Full agent tools.

With Full agent tools on, every tool-carrying plan also carries the agent runtime schemas (sub-agents, fleet, skills, run log) and the agent operating prompt. On such a window neither the direct set nor the find/load fallback fits, so the send goes out with no tools at all. Live on gpt-4 (8k) on 2026-10-19, "hi" went out as a 198-token tool-less request, while the same model with the switch off gets the three light tools. Live again on 2026-10-27 on a llama.cpp server started with `-c 8192`: with the switch on, the request carried only `read_agent_messages` on the plain prompt; with it off, the light set (evidence `setup-wizard-ux-qa/evidence/g53v5-llama/27-*`). The User Guide and the setup Summary now say so. Keeping the light set here means planning a runtime-free tier with the light prompt inside the full surface, and keeping the dispatch closures, the meter's re-plan and live sub-agent work consistent with it. That is a design choice for the owner, not a one-line fallback.
<!-- SECTION:DESCRIPTION:END -->
