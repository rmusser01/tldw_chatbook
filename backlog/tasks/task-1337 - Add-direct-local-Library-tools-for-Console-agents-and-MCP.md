## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Give Console agents and local MCP clients safe read-only access to factual local Library inventory and content without requiring semantic retrieval so users can count find and inspect their own Library items predictably.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Console agents and local MCP expose list get and lexical search for Media Notes Prompts Skills Conversations and Collections
- [ ] #2 List and search return bounded pages with exact distinct totals stable IDs deterministic pagination and keyword matches
- [ ] #3 Get requires a returned stable ID and chunks large text with revision-aware continuation below 32 KiB
- [ ] #4 Direct tools never use RAG embeddings or semantic similarity and never return binary data or filesystem paths
- [ ] #5 The Console direct-tools setting defaults on and off mode exposes bounded Library RAG with visible cloud-model privacy copy
- [ ] #6 Console mode cannot be bypassed by built-in MCP overlaps while MCP client compatibility remains unchanged
- [ ] #7 Automated tests cover contracts trust boundaries MCP bootstrap Console integration and settings behavior
- [ ] #8 ADR-030 design and implementation documentation are linked
<!-- AC:END -->

**2026-08-07 progress 5 (@kimi, branch feat/hub-local-agent-tools):** Plan Task 5 (shared 18-operation `LocalLibraryToolService`) landed, test-first (77 tests, red-then-green). New `tldw_chatbook/Library/local_library_tool_service.py`: dispatch over the Task-1 descriptor table's `type.operation` routes with strict argument-key validation; list/search normalize backend rows into the common brief (public ID `type:<base64url>`, 160 B display titles, 240-char previews, keywords ≤20×120 chars + exact `keyword_total`) sealed by `fit_page_payload`; gets parse public IDs fail-closed (wrong type/malformed → `invalid_argument`), resume via authenticated cursors with revision enforcement (`content_changed` + fresh-start hint), and byte-fit every response to the 32 KiB ceiling. Text reads (media/note/prompt-section/skill-file) use a largest-prefix binary search that measures the FULLY SEALED payload — continuation cursor minted inside the measurement — so a page never crosses the ceiling and continuation neither skips nor repeats characters (multibyte-pinned). Conversation gets page by message offset with within-message char continuation (cursor binds message id + revision token); the fit/derive loop refits with the previous round's cursor still in place so the minted cursor cannot push the page over. Collection gets page direct members with the opaque `source_ref` fallback for unsupported/unencodable sources. Prompt overview → section reads and skill manifest → `file_token` reads route trust-blocked skills to `feature_unavailable` without touching bodies/files. Backend datetime columns (PARSE_DECLTYPES connections) are coerced to ISO strings at the payload boundary (`_json_safe`), so responses stay wire-serializable. Errors: unknown tool/args → `invalid_argument`; missing backend seam → `feature_unavailable`; get-None → `not_found`; sqlite3/OSError/other → scrubbed retryable `storage_error` (no SQL, paths, or exception text); BaseException never caught. `include_rag_context` is always False. Tests: `Tests/Library/test_local_library_tool_service.py` — per-type mock-backend cases plus real-DB round trips (CharactersRAGDB notes/conversations incl. continuation + content-change detection, LibraryCollectionsDB collections); also fixed a pre-existing flaky assertion in the collections round trip (members tie-break on random membership_id when created_at ties at second granularity → assertions now order-agnostic).
