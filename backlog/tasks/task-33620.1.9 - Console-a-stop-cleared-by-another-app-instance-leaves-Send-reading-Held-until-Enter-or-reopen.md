## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by the independent review of TASK-33620.1's "Send button reads Held" change (2026-11-22). The Console caches the emergency stop's state and re-reads the file only on Console arrival, on its own stop/clear, and on a send. When another app instance on the same profile clears the stop, Send keeps reading "Held". It stays disabled, with the strip chip and header hold showing, until the user presses Enter (the send's own read lifts the hold, as TASK-33620.1's review round designed) or reopens the Console. Before "Held", the same lag showed as a disabled Send with the stop's reason. The label now makes it more visible, and a mouse user has no way to send.
