## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Opening Switch model probes each local server's model listing (TASK-33005.5), and the shared evidence keeps the model ids the server returned. The rows ignore them: Ollama's rows come from the shipped `[providers]` list (gemma3:12b, gemma3:4b, gemma3:27b, … in the capture checkpoint's captures 06 and 12) and never show `qwen2.5:0.5b`, the one model the running server actually listed. A user who just started a server sees models it does not have and misses the one it does.
<!-- SECTION:DESCRIPTION:END -->

<!-- AC:BEGIN -->

- [x] #2 With no listing yet (not probed, refused, or timed out), the rows keep today's saved and cached models

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
A server's switcher rows are now the models its last listing returned. All in tldw_chatbook/Widgets/Console/console_model_popover.py:
- `_server_listing(readiness)` reads the model ids from the evidence the provider's readiness already carries (`ConsoleSettingsReadiness.evidence`, TASK-33005.11), when the listing answered (`endpoint == "reachable"`) and the connection is a server's own: a URL-based provider or a registry entry, the same test `_retries_in_place` uses. A cloud key check's listing is not taken for a catalog. `_models_for` returns it ahead of the cached catalog and the saved list, so every reader of a provider's models (READY rows, NEEDS SETUP rows under a query, Find's count, the typed-id check, the representative model) sees what the server listed. A listing that answered with no models is an empty list (its "no models reported" line). `_catalog_status_rows` says nothing about a catalog while the listing fills the rows.
- Why it reached no row before: `_offer_probes` hands the prober `refresh_readiness`, and the re-read readiness carried the listing only into the readiness word (`model_readiness_words`).
- AC#2: not probed, refused (`unreachable`), timed out (`unreachable`), listing unavailable or not yet tested: no listing, so the rows are today's catalog or saved models.
- AC#3: nothing new is sent; the popover still makes no network call (`test_the_switcher_widget_makes_no_network_call_itself` passes, and the new test asserts one request per local server, as before). `connection_probe.switcher_probe_target` was not reused: the popover may not import Console_Modules (that same test).
- Not changed: this chat's own model stays listed first when the server does not list it (ADR-020), with the readiness word for an unlisted model. Phase 8's detected-server path (`served_models`, the card's catalog loader) already lists the server's models and agrees with this.

Test (Tests/UI/test_console_switcher_local_probe.py): `test_a_local_servers_rows_are_the_models_its_probe_listed[lists|lists-this-chat|not-probed|refused]` runs the real popover, the real Console probe seam and the real readiness builder over the shared evidence owner, with a stubbed Ollama listing only qwen2.5:0.5b beside a saved qwen3:4b and gemma3:12b (AC#4). Listed: Ollama's READY rows are qwen2.5:0.5b alone, reading "Ready · reachable HH:MM", and neither saved model is painted; an Ollama chat keeps qwen3:4b first, marked current, and loses gemma3:12b. Not probed: the saved two. Refused: no READY row, the saved two still behind it. Red at the base for the two listed cases (the saved models were listed), the others pass at both. 3 of 3 serial (~2.4 s); it joins the UI PR census (scripts/ui_pr_gate_census.txt, MINIMUM_FILES 351 -> 352), since the file is gated node by node. The local-probe, switcher, setup-card, registry-options, no-provider, context-window and geometry files: 184 passed.
