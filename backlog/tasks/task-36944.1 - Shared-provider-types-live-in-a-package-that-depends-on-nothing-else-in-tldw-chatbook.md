## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Agents and LLM_Calls import provider-level types and helpers from Chat (provider exceptions in `Chat_Deps`, `provider_continuation` with the `provider_endpoint_contract` it imports, `sampling_params`, `thinking_blocks` and similar leaf modules); `ChatProviderError` alone is imported by 12 LLM_Calls files. Each such import runs `Chat/__init__`, which loads ChaChaNotes_DB. A neutral package removes most of both mutual dependencies.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F7; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Importing the shared provider package loads none of tldw_chatbook's Chat, DB, Agents, LLM_Calls, UI, Widgets or Event_Handlers packages, nor config, textual, httpx or sqlite3, asserted by a test
- [x] #2 Agents and LLM_Calls import those types from the new package
- [x] #3 Every old import path still works through a re-export
<!-- AC:END -->

## Implementation Plan

1. Create `tldw_chatbook/Provider_Contract/`. Its `__init__.py` takes `Chat/Chat_Deps.py`'s content (the provider exceptions and their two helpers), so the package itself adds no extra module at boot. `git mv` `provider_continuation.py`, `provider_endpoint_contract.py`, `sampling_params.py` and `thinking_blocks.py` into it byte-for-byte; the only edit is `provider_continuation`'s import of its sibling `provider_endpoint_contract`.
2. Leave each old module as a three-line alias: `sys.modules[__name__]` becomes the moved module, so the old path is the same module object. Every old import path, private name, `isinstance` check and test patch through it keeps working.
3. Retarget every production import of the five modules (Agents and LLM_Calls as the criterion asks, plus Chat, DB, UI, Widgets and the rest), so production loads only the new names and the boot, `_ui_ready` and agent-runtime module counts do not grow by the alias keys. Prove with an AST scan that no production module imports an old path.
4. Add a fresh-subprocess test that imports the package and asserts none of Chat, DB, Agents, LLM_Calls, UI, Widgets, Event_Handlers, config, textual, httpx or sqlite3 is loaded, and that each old path is the same module object as its new one. Show it red under a temporary source edit.
5. Ratchets in the same commit: layer allowlist rows for the DB importers, the agent-runtime footprint pin, module-size rows, and the custom-literal allowlist path for `provider_endpoint_contract.py`. Run the boot-import, `_ui_ready` and pre-import guards before and after.
6. Grep Tests for patches on the moved names at the old paths; record each and why it still reaches the code.
7. Update `Docs/Architecture/llm-providers.md` and `CLAUDE.md` where they name `Chat/Chat_Deps.py`.

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Moved the provider exceptions (`Chat/Chat_Deps.py`) into `Provider_Contract/__init__.py` and `provider_continuation`, `provider_endpoint_contract`, `sampling_params`, `thinking_blocks` into `Provider_Contract/`. Each old `Chat/` path is a three-line alias (`sys.modules[__name__]` becomes the moved module), so old imports, `isinstance` checks and patches reach the same objects. Every production importer, Agents and LLM_Calls included, now imports from `tldw_chatbook.Provider_Contract`.

Rebase onto origin/dev 88af9f9379 (962 commits): dev had changed `Chat_Deps` (two `ChatAPIError` flags) and `provider_endpoint_contract`; both changes were re-applied to the package copies, so the moved definitions equal dev's current text (diffed: only the import lines differ). Deviation: dev's `provider_endpoint_contract` now imports `ROUTE_SUFFIXES` from `Chat/provider_setup_facts.py`, so that pure stdlib module moved too (alias left in `Chat/`); without it the package would import Chat and break AC#1. Dev's new importers (`first_run_provider_*`, `providers_models_card`, `console_provider_support`, `provider_setup_persistence`) were retargeted.

Tests (in `Tests/Architecture/test_agent_runtime_import_footprint.py`, a file the derived-artifacts lane already runs): fresh-subprocess check that importing the package loads none of Chat, DB, Agents, LLM_Calls, UI, Widgets, Event_Handlers, config, textual, httpx, sqlite3; old path is the same module object as the new one (old path imported first); AST scan that no production module imports an old path. Red evidence: before the retarget the AST scan listed the old-path importers, and the footprint pin failed on `Provider_Contract.provider_setup_facts` until pinned.

Ratchets: footprint pin re-pinned to the measured set (removed Chat.Chat_Deps, provider_continuation, provider_endpoint_contract, sampling_params, thinking_blocks; added Provider_Contract and its 4 modules plus provider_setup_facts; net +1 module in the pin; also dropped 10 entries dev had already stopped loading). Boot-import and `_ui_ready` snapshots renamed the same way (+1 each). `test_ui_ready_module_census` is red at plain origin/dev (1034 > 1031, shown red in a base worktree); here it is 1033. The 3 DB layer-allowlist rows were renamed, not deleted: Provider_Contract is a domain package under the layer map, so DB importing it is still upward. No module-size row names the moved files. Test patch targets at old paths: none exist (grepped `patch`/`setattr` strings); tests importing old paths now exercise the aliases.

Files: tldw_chatbook/Provider_Contract/*, the five `Chat/` aliases, ~25 production importers, the footprint pin and test, boot snapshots, layer allowlist, CLAUDE.md, Docs/Architecture/llm-providers.md.
