## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`InputError`, `ConflictError` and `SchemaError` are defined separately in ChaChaNotes_DB, Client_Media_DB_v2, Prompts_DB and Evals_DB. The names match but the classes don't. `SchemaError` and `ConflictError` have different bases per store (`CharactersRAGDBError`, each store's own `DatabaseError`, `EvalsDBError`), and the `ConflictError` constructors differ. `InputError` is a `ValueError` in all four. Code cannot catch, say, a conflict from any store with one handler. Well over 70 `except CharactersRAGDBError` handlers rely on the ChaChaNotes classes subclassing their store base, so the per-store hierarchy has to stay.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F13; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Added `DB/store_errors.py` (dependency-free): `StoreInputError(ValueError)`, `StoreConflictError(Exception)`, `StoreSchemaError(Exception)`. Each of the four stores' `ConflictError`/`SchemaError` gained the shared base as a second base (store base stays first; constructors untouched). Each `InputError` is now `InputError(StoreInputError)`: `(ValueError, StoreInputError)` is an MRO TypeError because the shared class is itself a ValueError, so it replaces the direct ValueError base; it is still a ValueError (`except ValueError` unchanged). No other module defines these class names.

Tests: `Tests/DB/test_store_error_bases.py` (real classes). Red: before the change the module import `tldw_chatbook.DB.store_errors` did not exist, so the file failed at collection. Green: 30 passed.
