## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The backend status rows in Settings ▸ Image Generation and Video Generation put each backend's name in a fixed 12-cell column (`.settings-imagegen-backend-row .settings-input-label { width: $ds-size-12 }`). A name of exactly 12 cells leaves no gap: the row reads "SD.cpp videoNot configured". A longer name is cut mid-word with no ellipsis: "ComfyUI (H3 image edit)" reads "ComfyUI (H3". The cubic review of PR #2937 found both in the Phase 3 captures. Neither the rule nor the row code changed in Phase 3 (both are identical at origin/dev 198a697e51), so the defect predates it.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 At 211x44 and 235x52, every Image Generation and Video Generation backend row shows the backend's full name, with at least one blank cell between the name and its status.
- [x] #2 The status column still starts at the same column in every row of a panel.
- [x] #3 A pilot test over every backend label fails before the fix and passes after it.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Write a pilot test over every backend label of both panels under the application stylesheet, and see it fail.
2. Measure the row's column budget at 120, 211 and 235 columns before choosing a width.
3. Widen the label column where the row has room, and keep the 120-column row as it is.
4. Rebuild the bundle and look at both panels in the running app, wide and narrow.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
At 150 columns and wider, every backend row shows its whole name. Phase 9, plan Task 10; base 10fead87cb.

**Cause.** `.settings-imagegen-backend-row .settings-input-label` pinned the name column at 12 cells. The longest names are 23 cells ("ComfyUI (H3 image edit)") in Image Generation and 22 ("ComfyUI (local server)") in Video Generation. The label wrapped inside its column and the row showed only the first line.

**Why the width depends on the terminal.** The row's budget was measured under the application stylesheet. At 120 columns the row is 52 cells. The default backend's row carries the status (14), the On/Off box (7), "★ Default" (9) and Test (6), which leaves 16 for the name. With a 24-cell column that row's Test button ends 8 cells past the row's edge and cannot be clicked. At 211 columns the row is 121 cells and at 235 it is 139.

**Fix (AC#1, AC#2).** css/features/_settings.tcss keeps the 12-cell column and, under `App.-wide-viewport` (the class the app sets from 150 columns, Constants.WIDE_VIEWPORT_COLUMNS), lets the name take what the row's other controls leave, up to 24 cells (`width: $ds-width-fill; max-width: $ds-size-24`; the 12-cell minimum stays). 24 is the shared `.settings-input-label` width: the longest name and one blank cell, which is the column's own right padding (round 2, below). At rest every status is at most 14 cells, so every row of a panel gets the 24 and the statuses start at one column.

**Why the wide column is not a fixed 24 (review fix, round 1).** The first version was. The status is `width: auto`, and an Image Generation probe writes its result into it in place (`_apply_image_gen_probe_result`). At 150 columns the row is 67 cells: the default backend's row ended 7 cells inside it and the others 15. "Reachable (auth unverified)" (27 cells, a success) put the whole Test button outside the default row, and "Unreachable: connection refused" (31) clipped Test on every other row. With the 12-cell column those rows had held 33 and 41 cells. Now a row whose result does not fit shortens its own name instead of losing Test, so until the next result or reopen that one row's status starts further left. Measured at 150x45 after the fix, as name width and cells between Test and the row's edge: 27-cell result, default row 18 and 0, other rows 24 and 2; 31 cells, 14 and 0, 22 and 0; 32 cells ("Binary missing or not executable"), 13 and 0, 21 and 0. The 37-cell "Unreachable: blocked by egress policy" still ends Test 4 cells past the default row, which is what a 12-cell name leaves it (at 149 columns, where the 12-cell rule applies, it measured 5 cells past a 66-cell row); the other rows hold it with a 16-cell name. At 160 columns every result fits, and at 170 with the whole name. Video Generation has no Test button and writes no probe result. Below 150 columns this task changes no width, and the row is tighter there: at 120, measured at the head, a result of 20 cells or more pushes Test past the default row. That is not fixed here.

**Why the blank cell is padding (review fix, round 2).** Until this round the blank cell was spare width and nothing more. The name wraps inside its column and the row shows the first line, so a column that came out exactly as wide as the name, or as its first wrapped line, painted the name flush to the status. That is the symptom in this rider's description, and at 780762e777 it was still there in two places.

- From 150 columns, in a row squeezed by a probe result. The review measured "SwarmUI (local)Unreachable: connection refused" and "ComfyUI (H3 image edit)Unreachable: connection refused" at 151 columns, "Gemini (AI Studio)Unreachable: blocked by egress policy" at 152, and the SwarmUI and ComfyUI rows with that result at 157. The extended test reproduced the first.
- Below 150 columns at rest, where the column is the 12 cells it always was: Video Generation painted "SD.cpp videoNot configured" at 120 and at 149 columns. The review did not look there; the test's new assertion found it.

The base rule now carries `padding-right: $ds-space-1` and the wide rule inherits it, so the last cell of the column is never text. The review proposed the padding on the wide rule alone. It went on the base rule because the 12-cell case is the same defect and the same one line fixes both. The padding is inside the column's width, so no column width and no control position changes at any size; the rules are in the lazy Settings sheet, so the boot bundle is byte-identical.

Measured after the fix under the application stylesheet, one app per width, with a scratch test (deleted, not committed):

- 150 to 171, 211 and 235 columns, every Image Generation row at rest and with nine probe results of 9 to 37 cells (2,160 row states): no name touches its status. At rest every name is whole in a 24-cell column and each width has one status column.
- 120 and 149 columns, both panels at rest (24 row states): none touches. One label paints differently from before: Video Generation's "SD.cpp video (local)" reads "SD.cpp" where it read "SD.cpp video".
- Test still ends past the row in four of the 2,160 states, all the 37-cell result on the default SwarmUI row, at 150, 151, 152 and 153 columns (4, 3, 2 and 1 cells past). That is the 12-cell minimum, as recorded in round 1; the padding does not move it.

Round 2 live, one launch on a scratch profile, resized in place. At 150x45 Image Gen at rest shows every name whole and the statuses at one column. At 151x45, Test pressed on the default SwarmUI row with nothing listening: the row read "SwarmUI        Unreachable: connection refused▐X▌ On ★ Default Test" and the other rows kept their whole names. At 120x45 Video Gen read "SD.cpp      Not configured▐X▌ Off ★ Default", and Image Gen "ComfyUI (H3 Not configured". At 211x44 Video Gen showed its three whole names before one status column.

**Ruling: below 150 columns the names stay cut, as before.** Why: the 120-column row cannot hold them, and the criteria name 211x44 and 235x52. Cost if wrong: a narrow terminal still reads "ComfyUI (H3"; wrapping the name onto a second row there would be a new rider. Round 2 keeps this: the column is still 12 cells there, and its last cell is now padding, which changes only the one name that filled all 12.

**The label's own class.** Both panels give the name `settings-imagegen-backend-label` beside `settings-input-label`, and both rules are keyed on it. The split build pins `settings-input-label` to the boot bundle because the Roleplay policy editor composes it, so the old rule was parsed at every boot. The two rules are now in the lazy Settings sheet with the rest of the row, which takes 113 B off the boot bundle: 608,076 B to 607,963 B against a limit of 608,090 B (see TASK-33003.22 for the budget). Both panels are composed only by settings_screen.py. The rules carry two classes, so they outrank the shared one-class rule whichever sheet loads last.

**Test (AC#3).** `Tests/UI/test_settings_image_gen_panel.py::test_backend_rows_paint_each_name_whole_before_one_status_column`, for both panels at 120x45, 149x45, 150x45, 211x44 and 235x52 (ten nodes). For every backend id it asserts that the row's last control ends inside the row and that every status of the panel starts at one column; from 150 columns, that the cells painted before the status start with the whole name and a blank cell; below 150, that the name column is 12 cells; and, since round 2, at every size that the cell painted just before the status is blank. The two narrow sizes were added in review: the six wide nodes pass with both rules deleted (the shared label rule gives 24 there), so they did not pin the 12-cell rule. With both rules deleted the four narrow nodes fail ("the name column is 24 cells below the wide tier, not 12"). `test_a_long_probe_result_shortens_the_name_and_keeps_test_in_the_row` writes the 27-cell and the 31-cell result into every Image Generation row through `_apply_image_gen_probe_result`, at 150x45 and since round 2 at 151x45 (two nodes), and asserts that Test ends inside its row and that the cell painted just before the status is blank; with the fixed 24 it failed ("swarmui with 'Reachable (auth unverified)': Test ends at 112, past the row's right edge (106)"). The host carries `WideViewportTierMixin` as `TldwCli` does. Before the first fix the four nodes then written failed: 'MiniMax H3  ' was painted for 'MiniMax H3 (cloud)' and 'SD.cpp      ' for 'SD.cpp (local)'. Round 2, red first: at 780762e777 the 151x45 node failed ("swarmui @ (151, 45) with 'Unreachable: connection refused': 'SwarmUI (local)' is painted right up to the status, with no blank cell"), and with the padding on the wide rule only the two narrow Video Generation nodes failed ("stable_diffusion_cpp @ (120, 45): 'SD.cpp video' is painted right up to the status, with no blank cell", and the same at 149). All twelve pass at the head.

**The row tests read a row only once it is in view (review fix, round 3; tests only).** Both tests read the line painted at the name's row. In Image Generation the lower rows start outside the scroll clip (by the review's count four at 120, 149 and 150 columns, three at 211x44, one at 235x52), and until `scroll_visible` lands the label's region is still out there: the line read at it is another widget's. Round 2 gave the long-result test a wait for that; the at-rest test still relied on a fixed 0.1 s pause. No run was seen failing. Both tests now share one wait, `_wait_until_the_name_line_can_be_read`: the label and the status are laid out and the label's region is inside its clip. Below 150 columns the at-rest test also asserts that the painted text is a non-empty start of the name; until this round the blank-cell check was its only painted-text assertion there, and a blank line passed it. Checked by removing lines for one run each (restored, not committed). Without the fixed pause the twelve nodes pass on the shared wait alone. Without the pause and the clip condition all five Image Generation at-rest nodes fail on a line that is not the row's: "together @ (120, 45): '────────────' is painted before the status, not the start of the name 'Together'", and at 149x45 the line read is twelve blanks, which the test passed before this round with no name read. Round 4 (tests only) deleted the fixed pause, which the wait had made idle: by the review's measurement the ten at-rest nodes passed 4 of 4 runs without it, every read taken after the scroll. The wait's timeout message now names both things it waits for ("the name's line was never laid out and scrolled into view"); it said only "never laid out", which is the wrong cause for a row that is laid out and still outside the clip.

**The 120-column guard.** `test_backend_row_controls_visible_and_clickable_under_real_css` errors at setup on this machine with `RecoveryRequired: raw_source_selection_changed`, at the base and at the head (an unmarked file; plan Task 14 owns that). The 120-column row was therefore measured with a scratch probe under the same harness and then live.

**Live.** At 211x44 on a scratch profile: Image Gen shows "ComfyUI (H3 image edit) Not configured" and Video Gen shows "MiniMax H3 (cloud)", "ComfyUI (local server)" and "SD.cpp video (local)", each followed by its status at one column. After resizing the same session to 120x45 the names are 12 cells wide again and the default backend's row still ends with "★ Default Test". Review fix, round 1, at 150x45 on a fresh scratch profile: at rest every name is whole in a 24-cell column.
