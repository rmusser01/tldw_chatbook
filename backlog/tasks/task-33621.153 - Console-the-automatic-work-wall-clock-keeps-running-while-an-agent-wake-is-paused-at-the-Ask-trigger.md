## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
From TASK-33621.80's review. A work chain's wall clock starts at its first accepted wake. When a later wake of the same chain is paused at the Ask compaction trigger (code compaction_ask), the clock keeps running while the chain waits for the user. A /compact long after the pause can then find the chain past its wall-clock budget: the retry is refused (wall_budget) and the fleet section changes from 'Paused: context limit' to 'Paused: time limit'. A chain's first wake is unaffected, because its clock has not started. Found in review by reading; not reproduced.
