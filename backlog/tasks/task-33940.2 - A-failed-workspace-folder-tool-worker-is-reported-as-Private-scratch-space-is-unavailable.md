## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
When the fs_*/git_* worker for an admitted workspace folder fails (for example `worker_crashed`), `_workspace_execution_error_result` maps every code other than root_pin_failed, invalid_request and tool_failure to the refusal "Private scratch space is unavailable; the tool was not run." The failing root is the workspace folder, not scratch, so the model is pointed at the wrong thing. Found live: a developer venv whose editable install pointed at a deleted worktree made every fs_* call fail this way. TASK-33621 lists this copy among the Console's untrue failure messages; this task fixes this one instance only.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

1. RED: provider-boundary tests for every executor failure code, for both the fs_* provider on an admitted workspace folder and `virtual_cli`, plus a control proving a real scratch-lease failure keeps the scratch copy.
2. Add `LOCAL_WORKER_FAILED_REFUSAL`, use it for executor failures in both providers, register it in the activity-presentation map next to its siblings.

## Implementation Notes

Executor failures (`worker_crashed`, `worker_timed_out`, `worker_failure`, `spawn_failed`, `protocol_failure`, `containment_unavailable`, `cleanup_unproven`) now reach the model as "The local file-tool worker failed before returning a result." The copy deliberately does not say the tool never ran, because some of those codes can arrive after the operation started. The outcome stays `blocked` and the internal reason code is unchanged; `LOCAL_AUTHORITY_UNAVAILABLE_REFUSAL` remains for genuine lease failures. Not changed here: the same scratch copy is still returned when an admitted root's dispatch specs vanish mid-run (`local_tool_provider.py`, the retire-race branch); that is part of TASK-33621's copy audit.

Evidence: `Tests/Agents/test_local_tool_worker_failure_copy.py` 15 tests (14 RED on dev, all GREEN); three `virtual_cli` expectations that pinned the old copy were updated. `Tests/Agents/test_local_tool_provider.py` (209), `Tests/Chat/test_console_local_review_hook.py` + `test_console_activity_presentation.py` (44) have identical failure sets on this branch and on clean origin/dev (sandboxed-config environment failure).
