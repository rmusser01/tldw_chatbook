## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: PR #3423 CI run 42429871004 timed out three polish-1b UI pins. Each one sent a Pilot key or click while the Library's Notes canvases were rebuilding, and the gesture was lost. The fix (`79461172da`, `c3ce909c05` after rebase 6) changed only the tests: they now wait for a settled Notes screen (`Tests/UI/library_notes_bulk_support.py::notes_settled`) before they send anything. The product still drops the same gesture from a real user.

What the user sees: for about a second after a dialog over the Library closes (the export file picker, F1, Move note), or after a Notes import ends under load, the Notes canvases rebuild 2-5 times (probe-logged in rebase 5). Each rebuild prunes the focused control, and focus parks on Textual's reset landing, the items pane grip, until the replay hands it back. The new controls have no region until the next layout. In that window:
- a key such as Enter on Export Markdown, or `r` on a Recently deleted row, reaches the grip and does nothing;
- a click lands where the control used to be, or at (0, 0), which is the Home tab and leaves Notes.

Focus always comes back, so nothing looks wrong. The user's action simply did not happen, and they have to notice and repeat it.

Cause: every Notes read that lands recomposes the canvas. This is already on dev (cited at `26b2e677dd`) and is not specific to PR #3423:
- `LibraryNotesCanvas.sync_state` (`tldw_chatbook/Widgets/Library/library_notes_canvas.py:2020`) ends in `self.refresh(recompose=True)` (`:2198`). It skips the rebuild only while the note editor has focus (task-32062, `:2174`) and for in-place Import or Add-from-files updates.
- The tree slice syncs the canvas: `LibraryScreen._apply_library_notes_tree_slice_page` calls `_sync_library_notes_tree_canvas_if_present` (`tldw_chatbook/UI/Screens/library_screen.py:18386`, `:18413`; defined at `:17918`).
- The Recently deleted read syncs it too: `LibraryNotesController._load_library_notes_trash` calls `_sync_library_canvas(self, "notes")` (`tldw_chatbook/UI/Library_Modules/library_notes_controller.py:7110`).
- A dialog's dismissal resumes the screen. `LibraryScreen.on_screen_resume` (`library_screen.py:9792`) runs `_refresh_library_visit_surfaces` (`:9842`), which re-requests the Notes tree (`:9958`).
- An import's end runs `_refresh_after_library_note_import` (`library_notes_controller.py:5910`), which reloads the tree (`:5913`).

PR #3423 adds more reads that land in the same window: the Recently deleted pager's reloads, and the single interlock release (`_release_library_notes_mutation`), which runs any owed tree or Trash reload and clears the Trash busy line. The window is therefore wider on that branch, but the mechanism is dev's recompose-per-sync design. Making the gesture survive likely means syncing the canvas in place, or holding input until the rebuild settles, rather than recomposing on every read.

The incident and how to force this rare race are recorded in `backlog/docs/lessons-testing-evidence.md` ("A Pilot key or click sent while a Notes canvas rebuilds is lost ...").
