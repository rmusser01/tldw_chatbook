## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Code reaches application services by string: 1,176 `getattr(app, "<name>")` lookups in UI (247 names, 71 private) and 222 outside UI across 71 modules, plus whole-app parameters in 352 non-UI functions. Nothing stops the count growing while the explicit-services work lands.

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F1; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 An architecture test counts literal-name `getattr`/`hasattr` lookups on app-like receivers per package and fails when a count rises
- [x] #2 A lookup of a private (underscore) app attribute that is not in a frozen list fails the test
- [x] #3 Lowering a count requires lowering the pinned value in the same change

## Implementation Plan

1. AST-scan `tldw_chatbook` for literal-name `getattr`/`hasattr` on app-like receivers, count per top-level package.
2. Pin counts in a TSV and private names in a frozen list; assert equality (up fails, down fails until the pin is lowered).

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
`Tests/Architecture/test_app_string_lookup_census.py` scans with stdlib `ast`; receiver is app-like when its last name segment is `app`, `app_instance`, `tldw_app`, `_app` or `_app_instance`. Pins: `app_lookup_census.tsv` (package, count; 1,683 total, UI 1,278 vs the report's 1,176 because the report's receiver set was narrower/at an older base) and `app_private_attrs.txt` (108 frozen private names). Red evidence: a temporary probe adding `getattr(app, "foo_new")` and `getattr(app, "_brand_new")` to `llm_screen.py` failed the UI count and the private-name test; a pin of 173 for a measured 172 failed with the lower-the-pin message. Added to the PR Fast Lane list in `derived-artifacts.yml`.
