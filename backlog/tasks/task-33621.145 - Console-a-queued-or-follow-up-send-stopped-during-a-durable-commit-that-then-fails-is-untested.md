## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found in the TASK-33621.59 review (2026-11-06). Since TASK-33621.59, Stop pressed while a send's durable commit runs, when that commit then fails, settles the send as stopped and gives its text and attachments back. That is pinned only for a manual send from the composer. For a queued prompt or a machine follow-up (origin is not manual), the store's cancel restores no draft, and by reading the prompt queue coordinator's after-turn and run loop hands the claim back as DISPATCH_REFUSED, not STOPPED. Nothing verifies what the queue entry then shows, or that a machine entry is not silently retired.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A test stops a queued prompt during its failing durable commit and asserts what the queue then shows: the entry is kept, and its pause reason and copy say it was stopped
- [ ] #2 A test does the same for a machine follow-up send and asserts the entry is not silently retired
- [ ] #3 Any defect found is fixed with a failing test first, or filed with evidence
