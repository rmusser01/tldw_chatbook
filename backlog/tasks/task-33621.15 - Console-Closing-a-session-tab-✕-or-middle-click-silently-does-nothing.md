## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** On dev @ 64579cce2c, no attempt to close a Console session tab ever closes it, and the user is never told why:
- **Saved idle tab or blank never-sent tab:** ✕ does nothing. There is no dialog and no toast.
- **Tab with an unsent draft:** the itemised 'Close Console session?' dialog appears, but clicking Close leaves both the tab and the draft in place.
- **Middle-click:** it switches to the tab and then fires the same broken close.
- **Keyboard:** there is no close shortcut or palette command.
- **Archive this chat:** not a workaround; its receipt says the open tab stays.

The cause is at `session.py:2796`: `_complete_close` calls `self._console_runtime().close_session(...)`, but the controller only has `self._console_runtime_accessor`. The close worker runs with `exit_on_error=False`, so the AttributeError is swallowed, and nothing reaches the UI or the log. Repeat presses each start a new worker and fail the same way (6 identical errors captured).

**Severity / prior art.** P1, REGRESSION from b7dd8e53f2 (2026-09-08) of Done close-flow work: TASK-28001 (saved conversations close without prompting), TASK-14806, TASK-2154.15, TASK-32274 and TASK-66. The existing close-tab tests in `Tests/UI/test_console_button_routing.py` already encode the expected outcome.

**Suggested direction.**
1. Call the injected runtime accessor.
2. Wrap the user-initiated close flow so any exception is logged with its type and context, and shown as a toast naming the tab.
3. Stop the middle-click branch from also activating the tab.

A watchdog is not needed; the flow does not hang. The dialog copy and approval enumeration are owned by the GAP1-05 finding.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G2-04 (source J3-01); qa/console-ux-review-2026-09-29/evidence/evidence__J3__66-close-tab.txt, evidence__J3__104-close-saved-b.txt, evidence__J3__73-middle-click.txt.
