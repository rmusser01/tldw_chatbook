## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** On dev @ 64579cce2c, no attempt to close a Console session tab ever closes it, and the user is never told why:
- **Saved idle tab or blank never-sent tab:** ✕ does nothing. There is no dialog and no toast.
- **Tab with an unsent draft:** the itemised 'Close Console session?' dialog appears, but clicking Close leaves both the tab and the draft in place.
- **Middle-click:** it switches to the tab and then fires the same broken close.
- **Keyboard:** there is no close shortcut or palette command.
- **Archive this chat:** not a workaround; its receipt says the open tab stays.

The cause is at `session.py:2796`: `_complete_close` calls `self._console_runtime().close_session(...)`, but the controller only has `self._console_runtime_accessor`. The close worker runs with `exit_on_error=False`, so the AttributeError is swallowed, and nothing reaches the UI or the log. Repeat presses each start a new worker and fail the same way (6 identical errors captured).

**Severity / prior art.** P1, REGRESSION from b7dd8e53f2 (2026-09-08) of Done close-flow work: TASK-28001 (saved conversations close without prompting), TASK-14806, TASK-2154.15, TASK-32274 and TASK-66. The existing close-tab tests in `Tests/UI/test_console_button_routing.py` already encode the expected outcome.

**Suggested direction.**
1. Call the injected runtime accessor.
2. Wrap the user-initiated close flow so any exception is logged with its type and context, and shown as a toast naming the tab.
3. Stop the middle-click branch from also activating the tab.

A watchdog is not needed; the flow does not hang. The dialog copy and approval enumeration are owned by the GAP1-05 finding.

Evidence: qa/console-ux-review-2026-09-29/findings.md → G2-04 (source J3-01); qa/console-ux-review-2026-09-29/evidence/evidence__J3__66-close-tab.txt, evidence__J3__104-close-saved-b.txt, evidence__J3__73-middle-click.txt.

## Implementation Notes

**Summary.** Closing a Console session tab works again: the ✕ click, middle-click, and Close in the "Close Console session?" dialog. No close attempt ends in silence. This fixes a regression from b7dd8e53f2: `ConsoleSessionController._complete_close` called `self._console_runtime()`, which the controller does not have. The close worker's `exit_on_error=False` swallowed the resulting `AttributeError`.

**Approach and changes**
- **tldw_chatbook/UI/Console_Modules/session.py**
  - The close now calls the injected `_console_runtime_accessor()`.
  - The close worker body catches every exception and calls `_report_session_close_failure`, which logs only the stage, the exception type and the origin function (never the exception text, per TASK-15103). If the session is still open, the user gets an error toast: `Couldn't close tab "<title>": <reason>`. If the store already dropped it, they get a warning, `Closed tab "<title>", but the Console did not finish updating (<Type>).`, and the strip is re-rendered once.
  - Reason text is shown only for the module's own `_SessionCloseIncomplete` and an allowlisted user-actionable refusal. Everything else becomes "An unexpected error occurred (<Type>)." An allowlist was chosen over a new typed exception because console_chat_controller.py and console_chat_store.py are already over their size budgets.
  - A worker that cannot be scheduled also gets a toast.
  - A store post-check catches a runtime close that returned without closing (for example, a voice publication that did not drain). It raises `_SessionCloseIncomplete`, and the still-open tab keeps its per-tab state.
  - If a close is requested for a session already gone from the store, the strip is re-rendered, so a stale ✕ heals itself instead of doing nothing.
- **tldw_chatbook/Widgets/Console/console_session_surface.py:** `ConsoleSessionTabButton._on_click` calls `event.prevent_default()`, so Textual's MRO dispatch no longer runs `Button._on_click` after our handler. On a middle-click, that handler used to activate the tab being closed.
- **Tests**
  - New Tests/UI/test_console_session_tab_close.py: 8 private-profile Pilot tests using real clicks on a mounted ChatScreen and the real worker, store, runtime and SQLite. It covers ACs #1-#5, including the failure paths.
  - New Tests/Architecture/test_console_controllers_define_their_self_attributes.py: an AST guard for undefined `self.<name>` reads in UI/Console_Modules classes. It scans 73 classes and finds 0 offenders.
  - Tests/UI/test_console_button_routing.py: the close tests wait for the ✕ to mount and poll for the close, instead of using fixed pauses.
- **Gate:** the new test file is added to scripts/ui_pr_gate_census.txt, and `MINIMUM_FILES` in scripts/check_ui_pr_gate_census.py goes from 118 to 119.
- **Docs:** Docs/User_Guide/console/sessions-tabs-workspaces.md tab-close rows and notes are corrected. Docs/security/production-diagnostic-inventory.json is regenerated (session.py 23→24 calls; the drift row was read first).
