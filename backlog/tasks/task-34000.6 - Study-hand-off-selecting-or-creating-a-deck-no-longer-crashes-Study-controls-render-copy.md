## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: making study material from a paper or note is a named job for the researcher persona (Priya). Every path from Library into Study ends badly:
- Library says the source snapshot "is ready", although local mode cannot generate from it.
- The Study Dashboard and Flashcards hide their controls.
- Creating or selecting a deck crashes the whole app.

Triage escalated this from P1 to P0 because an unhandled TypeError exits the app (2/2). The crash is in Study code, on the Library → Study path.

What was observed:
- **Crash.** Creating a deck, or selecting one, in Study ▸ Flashcards exits the app. The log shows `event=unhandled_exception ... exception_type=TypeError raise_function=refresh_cards raise_line=649 raise_module=tldw_chatbook.UI.Study_Modules.flashcards_handler`, then "Screen study unmounted" and "--- App Unmounting ---" (verify crash-excerpt.log, two runs).
- **Whole-Library scope.** The Library hand-off reads "Carries forward: … and 134 more · Source snapshot is ready · Continue in Study" (j7). That is the whole Library, not the paper or note in hand. Study then summarises the same scope as "+7 more" (STUDY_MATERIAL_TITLES_LIMIT = 10, UI/Screens/study_scope_models.py:12).
- **Clipped Dashboard.** It ends at "0 due today / No recent decks yet. / No recent quizzes yet.", even at 160x70 (capture 08). Resume last session, Open flashcards, Open quizzes and Generate source pack never render.
- **Clipped Flashcards.** The tab is a box holding only "Decks:" (j7). The empty deck list is partly a harness caveat, since no decks were seeded. The missing editor controls are not.
- **Server-only generation.** Study refuses with "Source generation requires server mode." (UI/Screens/study_screen.py:620-625), while Library says "Source snapshot is ready." (UI/Screens/library_screen.py:14464).

Verified cause (origin/dev 2d34cbf80d):
- `refresh_cards` calls `service.list_flashcards(mode=..., **self._scope_arguments(), deck_id=..., q=..., limit=100, offset=0)` (UI/Study_Modules/flashcards_handler.py:649-656).
- `_scope_arguments()` (:149-158) adds `scope_type` and `workspace_id`. `StudyScopeService.list_flashcards` (Study_Interop/study_scope_service.py:1052-1060) accepts neither, so the call raises TypeError.
- Code-traced, not reached live because the crash comes first: adding a card passes the same keywords to `StudyScopeService.create_flashcard` (flashcards_handler.py:749-751 → study_scope_service.py:1072-1082), which also lacks them. The same TypeError is waiting there.
- The clipping cause is a hypothesis. The Dashboard's columns `Horizontal()` (Widgets/Study/study_dashboard.py:73) and `.card-editor` (UI/Study_Window.py:117-121) set no `height: auto`, so they take `1fr` and hide what follows.

Suggested direction (a direction, not a mandate):
- Fix the crash first: drop the scope arguments from the list (and create) calls, or add those parameters to the service methods.
- Set `height: auto` on the dashboard columns row, `.study-dashboard-column` and `.card-editor`.
- Use honest local-mode hand-off copy, for example "Generating a pack from sources needs a tldw server; you can still make cards by hand in Study".
- Show the true scope instead of "… and 134 more".

Ownership: no open task owns this. Earlier Study hand-off and Study button tasks (TASK-2854, TASK-89.7, TASK-16845, TASK-19041) are Done and did not cover these defects.

Review finding(s): S-05. Source: qa/notes-library-ux-review-2026-10-02/report.md

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Fixed on branch `fix/task-34000-wave1b-crash-freeze` (base 68eee53e51; the crash was still live on origin/dev).

**Crash (AC#1).** `flashcards_handler.refresh_cards` and `create_card` spread `**self._scope_arguments()` into `StudyScopeService.list_flashcards` / `create_flashcard`, which take no `scope_type`/`workspace_id`. The call site was the wrong side: a card is scoped by its deck on both backends (`LocalStudyService.list_flashcards(deck_id=…)`, `ServerStudyService.list_flashcards(deck_id=…)` -> `TLDWAPIClient.list_flashcards(deck_id=…)`, no workspace parameter anywhere), the handler returns early without a selected deck, and that deck came from the scope-filtered `list_decks`. Dropping the redundant keywords loses no scope; adding ignored parameters to the service was rejected. All 13 other `_scope_arguments()` spreads (flashcards x5, quizzes x5, study_screen x1 and the `_workspace_create_arguments` / teardown spreads) target methods whose real signatures accept them.

**Guard (AC#5).** `Tests/Architecture/test_study_handler_service_keywords.py` derives every `service.<method>(…)` call in both Study handlers by AST, resolves `**` spreads through the handler's own helpers (including the pending-teardown attribute cycle), and checks keywords, positional arity and required keywords against `inspect.signature` of the real `StudyScopeService` / `QuizScopeService`; unresolvable spreads fail closed. Negative control in-test (`test_guard_fails_on_a_reintroduced_scope_spread`) and by hand: the re-inserted call is reported as `flashcards_handler_bad.py:656 service.list_flashcards(scope_type=...): … does not accept 'scope_type' (via **self._scope_arguments())`. Regression Pilot tests in `Tests/UI/test_study_flashcards_real_service_contract.py` run the full app with the production `StudyScopeService` over a real in-memory `CharactersRAGDB` (local) and the real `ServerStudyService` over a faked wire client (workspace scope); RED on base with `TypeError: StudyScopeService.list_flashcards() got an unexpected keyword argument 'scope_type'` from `refresh_cards` (:649); GREEN after, with the card row asserted in the DB. The old fakes in `test_study_flashcards_screen.py` now mirror the real signatures.

**Final-review split.** The gated `test_study_flashcards_real_service_contract.py` kept the 2 real-service crash tests (16.7 s / 18.2 s pytest, 23.3 s / 25.2 s wall); the six geometry parametrizations (dashboard buttons / Flashcards controls at 160x45, 160x70, 120x36) moved unchanged to the non-gated `Tests/UI/test_study_controls_geometry.py` (35 s pytest / 43 s wall), which imports the gated file's helpers. The 8 tests are 2 + 6.

**Clipping (AC#2), confirmed by real-CSS geometry before fixing** (full app, bundle loaded, 160x45): the dashboard columns `Horizontal` was `height: 1fr` spanning y=15..44 so the actions row sat at y=45 (off a 45-row screen); `.card-editor` was `1fr` (8 rows) with its children at y=23..65 under `overflow: hidden`.
