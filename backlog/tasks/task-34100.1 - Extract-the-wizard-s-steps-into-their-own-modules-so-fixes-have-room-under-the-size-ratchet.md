## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The whole first-run wizard lives in one module, FirstRunSetupWizard.py. TASK-33921 moved the Voice step out, and the module now sits exactly at its 9,866-line size budget (Tests/Architecture/test_module_size_ratchet.py:128). Every fix in this programme lands in that module, so with no room left a fix either cannot land or has to raise the budget. The module also keeps producing focus-loss, soft-lock and crash defects (11 or more Done incidents, from TASK-2040 to TASK-33621.14), because nothing owns the step lifecycle. 43 liveness checks read is_mounted, against 11 that use is_attached. Nothing restores focus after async work or after a modal closes. The provider tests that should catch regressions are red, with 41 failures. Users lose keystrokes, and each Next can block for seconds with no cue beyond disabled buttons that still look enabled.

This task implements enabler E-a (step-lifecycle controller and module split) from §5.2 of Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md. It resolves cross-cutting-17 and cross-cutting-14. It must not hold back the P0 and P1 fixes in the other subtasks, which may land before it. Its job is to give wave B room. The Protect relaunch crash and the Protect focus defects that cross-cutting-17 cites belong to the key-encryption subtask, not this one.

Coordination:
- Follow TASK-33921's recipe. Move whole step classes, so their @on handlers stay registered. Import them lazily and re-export them through a module __getattr__. Retarget test patches deliberately, and lower the ratchet rows.
- Open PR #2862 (stale, with conflicts) moves SetupRadioButton, SetupRadioSet, SetupStep and ProviderChoiceOption unchanged into UI/Wizards/first_run_setup_widgets.py. Use the same module name and content, so rebasing that PR is trivial.
- Take the wizard slice of TASK-33621.36 first: the 41 red provider tests, caused by RecoveryRequired fixture drift.
- Related open work: TASK-32809.2, TASK-32892 and TASK-32800.

1. 2. AC#2: move whole classes, in the order the dependency graph allows (steps depend only on the shared base; only the container references steps):
   - `first_run_setup_widgets.py` takes SetupRadioButton, `_radio_model_id`, SetupCheckbox, SetupRadioSet, the failure reasons, REQUIRED_STEP_MANUAL_SETTINGS_CATEGORIES, manual_settings_context_for_required_step, SetupStepFailure, SetupStep and ProviderChoiceOption.    - `first_run_model_discovery.py` takes the discovery helpers that Provider and Model share.
   - One module per step: `first_run_{welcome,provider,model,rag,speech,tools,notes,appearance,protect,summary}_step.py`. Voice already has its own module.
   - The wizard keeps the container, the progress widget, the nav bar, the dialog and the screen. It imports the step classes at the top, which is possible now that no step imports the wizard, and keeps `__getattr__` re-exports for the moved names it does not use itself.
   - Retarget test imports of private helpers, and test patches of moved names, to the owning module. A patch left on the wizard must raise AttributeError.
   - Pin @on and @work registration on the moved classes in a test. Update the path-keyed inventories (diagnostic inventory, census files). Lower the wizard's ratchet row and add a row for each new module.
3. AC#3: sweep every `is_mounted` read under UI/Wizards/ to `is_attached` (judged per site, including BaseWizard's two pre-mount guards), with a grep-based architecture test. Both always pass `exit_on_error=False` and report an escaped error on the pinned strip through `report_contained_error`. Route every first-run `run_worker` and `@work` through them, and pin that with an AST architecture test.
4. AC#5: once a Next has run for about 400 ms, `_set_advancing` shows a busy line that names the work: each step's `busy_label()`, or "Preparing the Full setup..." when Welcome chose Full. 5. AC#4: a keyboard-only Pilot walk of the Quick and Full tracks, with fakes for network work only. It asserts `app.focused` is attached and not None after every step change, every async completion (probe, discovery) and every modal dismissal (exit dialog, continue-anyway, password). 6. AC#7/#8: RED proof for each new test against base code; ratchet only lowered; update Docs/User_Guide/First_Run_Setup.md for the busy line and the Back/Forward reuse.
7. Gates: targeted wizard files against the recorded base (253 failed / 838 passed / 31 errors over 27 files); `pytest Tests --collect-only`; `scripts/preflight.sh`.
8. AC#6: live walk on a fresh isolated profile, with a real OpenAI key and the real llama.cpp server. Evidence goes under `setup-wizard-ux-qa/evidence/g1-*`.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**Summary.** FirstRunSetupWizard.py goes from 9,866 to 3,183 lines. Each first-run step now lives in its own module under UI/Wizards/. All wizard liveness reads use `is_attached`. All first-run background work goes through one helper that never exits the app. A slow Next names its work, disabled nav buttons are drawn dimmed, and Back/Forward reuses the Provider step's model discovery. The ratchet was only ever lowered.

**Approach and decisions.**
- AC#1 came first. The 41 `-k provider` reds were all `RecoveryRequired('raw_source_selection_changed')`. The suite is now marked `bootstrap_profile`, and a Tests/Wizards teardown restores the shared, temp-dir bootstrap `config.toml` through the guarded writer.
- AC#2 followed TASK-33921's recipe. Whole classes moved verbatim, so `@on` handlers and workers stay on their classes:
  - `first_run_setup_widgets.py` matches PR #2862 apart from dev's later `WizardErrorGuard` base and its import (diffed against `origin/codex/personal-context-memory-dev`).
  - `first_run_model_discovery.py` holds the helpers that Provider and Model share.
  - `first_run_{welcome,provider,model,rag,speech,tools,notes,appearance,protect,summary}_step.py` hold one step each.
  - Every public name the wizard defined on base still imports from it, through top-level imports (marked `X as X`) or the module `__getattr__`.
  - Private helpers and the two tunable timeouts (`MODEL_DISCOVERY_TIMEOUT_SECONDS`, `CLOUD_PROBE_TIMEOUT_SECONDS`) are deliberately not re-exported. A stale patch on the wizard raises AttributeError instead of silently missing. Test patches were retargeted to the owning modules.
- AC#2, ratchet: the wizard's row drops from 9,866 to 3,183. Each of the 13 new modules is born governed at its exact size, as the coordination note asks.
- AC#3: every `is_mounted` read was judged and moved to `is_attached`, with an architecture grep test. `run_wizard_worker` and `@wizard_work` in `first_run_step_guard.py` always pass `exit_on_error=False` and report an escaped error on the pinned strip. An AST test pins them as the only `run_worker` call site.
- AC#5: `SetupBusyStatus` reveals after 0.4 s and adds elapsed seconds after 2 s. Disabled first-run nav buttons get `text-style: dim` (bundle regenerated). `ProviderStep.commit` reuses a settled discovery, failed ones included, for the same provider identity.
- Late fix in this pass: three base public names did not resolve from the wizard (`ProviderEndpointCandidateList`, `ProviderEndpointCandidateOption`, `GENERIC_DISCOVERY_FAILURE_CATEGORY`). They are now re-exported and pinned by a test that was RED first. The split's four F401s are also gone: ruff F/E9 is clean on UI/Wizards/.
