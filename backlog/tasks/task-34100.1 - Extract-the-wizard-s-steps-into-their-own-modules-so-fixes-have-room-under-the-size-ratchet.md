## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The whole first-run wizard lives in one module, FirstRunSetupWizard.py. TASK-33921 moved the Voice step out, and the module now sits exactly at its 9,866-line size budget (Tests/Architecture/test_module_size_ratchet.py:128). Every fix in this programme lands in that module, so with no room left a fix either cannot land or has to raise the budget. The module also keeps producing focus-loss, soft-lock and crash defects (11 or more Done incidents, from TASK-2040 to TASK-33621.14), because nothing owns the step lifecycle. 43 liveness checks read is_mounted, against 11 that use is_attached. Nothing restores focus after async work or after a modal closes. The provider tests that should catch regressions are red, with 41 failures. Users lose keystrokes, and each Next can block for seconds with no cue beyond disabled buttons that still look enabled.

This task implements enabler E-a (step-lifecycle controller and module split) from §5.2 of Docs/superpowers/qa/first-run-wizard-ux-review-2026-10-02/README.md. It resolves cross-cutting-17 and cross-cutting-14. It must not hold back the P0 and P1 fixes in the other subtasks, which may land before it. Its job is to give wave B room. The Protect relaunch crash and the Protect focus defects that cross-cutting-17 cites belong to the key-encryption subtask, not this one.

Coordination:
- Follow TASK-33921's recipe. Move whole step classes, so their @on handlers stay registered. Import them lazily and re-export them through a module __getattr__. Retarget test patches deliberately, and lower the ratchet rows.
- Open PR #2862 (stale, with conflicts) moves SetupRadioButton, SetupRadioSet, SetupStep and ProviderChoiceOption unchanged into UI/Wizards/first_run_setup_widgets.py. Use the same module name and content, so rebasing that PR is trivial.
- Take the wizard slice of TASK-33621.36 first: the 41 red provider tests, caused by RecoveryRequired fixture drift.
- Related open work: TASK-32809.2, TASK-32892 and TASK-32800.
