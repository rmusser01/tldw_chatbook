## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found by live profiling on 2026-10-10 (160x45, Anthropic haiku through the review proxy, 56 sends over 10 launches; a PYTHONPATH-only probe timed every UI-loop callback of 10 ms or more, timed every collection per thread with `gc.callbacks`, and sampled the main thread every 4 ms). After a Console send is accepted, the longest UI-loop blocks are Textual screen updates, and 54% of that time is Python's generation-2 collection on the main thread: about 70 ms per send window, with single pauses of 23-65 ms at up to 16 turns and 78-122 ms at 31-46 turns (max 266-324 ms).

ADR-198 freezes the heap only at `_ui_ready` and after the screen pre-import. Every gen-2 pass therefore rescans everything the Console built after boot (about 590 widgets at about 50 turns, the transcript, the stores), and one runs about once per send. Within a launch the pauses grew with every send (36 ms on the first, 121 ms by the fifth). Worker-thread gen-2 passes (52-87 ms) hold the GIL as well.

Counterfactual on the same data: removing the main-thread collections alone takes the median longest loop callback after acceptance from 95 to 72 ms, and the sends with a block of 100 ms or more from 15/30 to 6/30. Together with moving the config projection's I/O off the loop (TASK-33620.15.4) it is 48 ms.

The risk to design for: `gc.freeze()` moves objects to the permanent generation, and frozen objects that later become unreachable cyclic garbage are never collected. Textual widgets are cyclic, so a conversation switch, a transcript trim or a recompose can leak whatever was frozen while it was live.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Policy (`Utils/ui_responsiveness.py`, one per process, like the frozen generation): `IdleHeapRefreezer`. An owner requests a re-freeze; it runs only when the owner reports itself not busy and no user input arrived for 2 s. A re-freeze collects the unfrozen heap in full (frozen objects are never scanned), then freezes the survivors, so cyclic garbage already in the old generation is reclaimed rather than frozen. Off under pytest like the screen pre-import; `TLDW_IDLE_HEAP_REFREEZE` overrides.
2. Leak bound: a frozen object that later becomes cyclic garbage is never collected, and Textual widgets are cyclic. Count what each re-freeze adds. Once that reaches 25% of the permanent generation measured after the last compaction (CPython's own full-collection ratio, with a 50K floor), the next 5 s quiet moment compacts instead: unfreeze, collect the whole heap, freeze the survivors. No re-freeze runs while a compaction is due, so frozen garbage stays within the budget plus one re-freeze.
3. Input tap: a `TextualAppGuards` mixin stamps every input event (keys, mouse, paste). No `app.py` line and no new boot module.
4. Console wiring (`Console_Modules/transcript.py`): request at the transcript poll's stop edge (a run settled) and when the transcript shows a different (session, conversation). Busy from Enter to a settled run (send flight, pending send, transcript poll, poll-needed), when the Console is not the top screen, and when it is torn down.

Tests first: scheduling with a fake clock, owner and collector; real collector with real Textual widgets for the leak (a negative control showing a frozen, switched-away transcript survives a full collection, the compaction reclaiming it, and a bounded frozen set over 24 switches); the input tap; a mounted Console test pinning the two request points and that nothing runs from Enter to the provider call. ## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Re-freezes the Console's long-lived heap at idle points with a bounded compaction; details below.

**Approach.** `IdleHeapRefreezer` (`Utils/ui_responsiveness.py`, one per process) runs a re-freeze when an owner asks for one, the owner reports itself not busy, and no user input arrived for 2 s. A re-freeze collects the unfrozen heap in full, then freezes the survivors, so old-generation cycles are reclaimed instead of frozen. The Console asks at two points (`Console_Modules/transcript.py`, two lines in `chat_screen.py`): when its transcript shows a different (session, conversation), and at the transcript poll's stop edge (a run settled). It is busy from Enter until the run settles: the send flight (pressed or deferred), a pending send, the transcript poll timer, a run still live before the poll starts (`_console_transcript_poll_needed`), another screen on top, or teardown. A busy owner drops the request and asks again when it next settles. `UserInputTap`, a `TextualAppGuards` mixin, stamps every key, mouse and paste event (no `app.py` line, no new boot module).

**Leak bound.** A frozen object that later becomes cyclic garbage is never collected, and Textual widgets are cyclic. A compaction (unfreeze, full collection, freeze the survivors) reclaims it, and runs after 5 s of quiet when either (a) the Console replaced a transcript that a freeze caught while it was shown (it records the process's freeze epoch with each painted conversation and calls `note_stranded()` when the epoch moved), or (b) the permanent generation, walked once after each re-freeze, has grown 25% (floor 50K) over its size after the last compaction. No re-freeze runs while a compaction is due, so the frozen set never exceeds its post-compaction size by more than the budget plus one re-freeze. A re-freeze or compaction requires CPython's generation-2 pass count to move (`gc.collect()` returns at once while another thread's pass runs); otherwise it reports `busy`, freezes nothing new, and a compaction stays owed. The collector is never disabled and its thresholds are untouched. Off under pytest (`PYTEST_CURRENT_TEST`); `TLDW_IDLE_HEAP_REFREEZE` overrides. ADR-198 is amended with the policy, the bound and its live evidence.

**Trade-off (measured, below).** Total main-thread collection CPU does not fall: the policy moves it out of send windows to idle points. A compaction is a longer single pause than any of dev's automatic passes (median 296 ms, max 492 ms CPU in round 9), but it only runs after 5 s without input and with nothing in flight.
