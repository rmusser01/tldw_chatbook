## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while measuring TASK-33620.15.19 (2026-10-30). With a conversation's Library Auto set to Automatic and the BM25 Only RAG profile active, the first send after launch spent 17-39 s between Enter and the provider request, 26 s even at host load 19. Almost all of it was the Library search service's prewarm, the shared RAG runtime build, which runs on a worker thread. The UI stays responsive, but the user watches 'Searching Library…' for tens of seconds before the model is asked anything. A BM25 Only profile needs no vectors, so it is not clear why this path builds the embedding runtime at all; TASK-3601 asks the same question for the Library screen's rag mode. TASK-33621.20 made a cold-start timeout pause with Retry / Send once without Library / Cancel, but did not address the build cost. Every number so far was taken while another session loaded the host heavily, so a load-free measurement comes first.
