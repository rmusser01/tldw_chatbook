## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Found while verifying TASK-33621.59 live (2026-11-06). The send acknowledgement paints 'running' straight to the Workbench header, past the push cache. When a send ended where it began (Stop over a failed save) and no whole sync had run during it, the release's sync derived exactly the state cached before Enter, skipped the push, and the header read 'Running' on an idle Console until the next send. The fix forgets the cached Workbench state on every send release. Two gaps remain: the unit test checks the cache field, not the visible header (the mounted harness runs whole syncs during the send and never showed the stale header), and the release now forces one Workbench and control-bar push per send even when nothing changed.
