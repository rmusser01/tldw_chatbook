## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-36571 measured the run projection by component on dev 7536ac3b87 (live, Anthropic haiku via the review proxy, 160x45) and cut its largest component, Textual restyles from state flips. What remains above its AC#2 bound is spread over derivations that run on every 0.2 s run tick. The largest is the workspace context build: about 8.8 ms of UI-loop CPU per send window (plus 15-30 ms wall in some windows when its synchronous send-start registry reads wait on the GIL). The projection asks for it only to read the workspace label (the Inspector's conversation rows and the rail state), but the run tick's Conversations tray push in the same tick needs the whole build, and the tick cache (TASK-22201) shares one build per tick, so reading the label more cheaply in the projection alone would move the cost, not remove it. A real cut needs the tray push to skip an unchanged build across ticks without letting the inputs its fingerprint leaves out (stars, unseen markers, attention facts and receipts, appearance, folder availability, fleet counts, collapse preferences, rail height) go staler than one poll interval behind dev, and without a carried build overwriting a fresher push made outside the tick. Next in size: the settings summary (about 7 ms per window; it re-derives the Agent section payload every projection), the composer action state's non-restyle work (about 5 ms) and about 390 query_one lookups per window (about 4 ms).
