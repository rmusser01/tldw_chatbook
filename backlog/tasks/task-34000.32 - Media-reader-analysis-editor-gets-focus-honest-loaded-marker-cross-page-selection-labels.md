## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: the Media reader is where a Library power user (Morgan) and a researcher (Priya) spend their reading time. In this batch, typed analysis text is lost and fires list commands, and a row claims to be 'loaded' beside an empty Reader. Selections vanish on a page turn, two menu items do nothing, and at 80 columns half the reader's controls are cut off without a sign. A keyboard-only user (Sam) at 80x24 cannot reach Info or More at all. Each has a workaround, hence P2. L-07 loses typed text, hence the data-loss label. Causes are at origin/dev 2d34cbf80d.

L-07, 'Add analysis' leaves focus on the first Items row, so typed text is lost. The steps are Media > open an item > Analysis > 'Add analysis' > Enter. The editor opens, but the '█' focus bar sits on the first Items row ('A field guide to Markdown tables') and the text box is unfocused. Typing 'Key takeaway: spacing…' opened the 'Import media' dialog at the 'i', and the text was lost. Other letters ('s', for one) fire list commands too. Trash, Console and read-later are gated off while editing, and clicking into the box works, hence P2. Verified cause: handle_library_media_analysis_edit (UI/Library_Modules/library_media_controller.py:4608-4617) sets the editing flag and re-syncs the viewer but never moves focus into the analysis text box. Edit metadata has the same gap. Suggested direction: after the viewer sync, focus the analysis text box, or the Title field for Edit metadata. Cancel and Save return focus to the button that opened the form. Escape discarding typed analysis without asking is finding L-08, owned by TASK-34000.22, and not in scope here.

L-16, returning to Media via the rail shows a row marked 'loaded' beside an empty Reader. The steps are Media > open an item > another rail row > Media again. The list then shows '█▸ A field guide to Markdown tables · article · updated 2d · loaded', while the Reader says 'Select a media item to read it here.', still after 7 seconds. The verifier found it happens only when the item was the first row, and did not confirm the earlier claim that c/t then act on it. Verified cause: the rail-switch reset (UI/Screens/library_screen.py:22387-22398) deliberately returns the viewer to the list ('a rail-row press is always a fresh entry'), but the row's 'loaded' marker survives the reset. Suggested direction (the verifier's): rebuild the reader session in the rail-switch reset after capturing reading progress, so the marker and the Reader agree. TASK-34000.25 (finding S-02) restores the open reader across rail switches, and its AC#2 already requires the 'loaded' marker to match the reader, so it should resolve L-16 as a side effect. This task keeps L-16 as a standalone guarantee, including the first-row case the verifier isolated. If TASK-34000.25 lands first, re-verify L-16 against it rather than building a second fix.

L-19, Media selection is cleared by any page turn, and there is no bulk keyword action. With 23 items, the steps were s, three rows selected ('3 selected   Select all 20 shown'), then Next. The result was the toast 'Selection cleared.', select mode exited, and the user landed on 'Page 2 of 2'. The select toolbar offers Clear, Export, Review, ○ Analyze and Delete, and tagging means Edit metadata one item at a time. Verified cause: _clear_library_media_selection_for_scope_change (UI/Screens/library_screen.py:16855-16873) runs on every page turn. Suggested direction: amend ADR-067 (Library top-level pagination contracts) to give Media the Prompts-style cross-page selection ('N selected · M on this page'). Add 'Keywords…' to the select toolbar, behind the overflow below 110 columns. The ADR amendment is needed before the cross-page half is built.

L-22, Reader 'Open original' and 'Open manager' do nothing for a local import. A local PDF import shows its source as 'file://…/paper-retrieval-practice.pdf'. More offers 'Edit metadata  Open original  Open manager  Move to trash'. Neither 'Open original' nor 'Open manager' changes anything or shows a message. Verified cause: handle_library_media_open_original (UI/Library_Modules/library_media_controller.py:4196-4203) opens only http(s) URLs. 'Open manager' (Widgets/Library/library_media_viewer.py:487) navigates from Library to Library. Suggested direction: for an existing file:// source, offer 'Show in Finder' / 'Show in folder', which reveals the file rather than opening it. Hide the action for local:// sources, and remove 'Open manager' from the Library reader.

S-16, at 80 columns the reader's mode and action rows are cut mid-word. At 80x24 the reader rows read 'Find  Read later  Use in Console  M' and 'Read (selected)  Analysis  Highligh'. Info and More are off-screen, and nothing signals that more exists. The list shows 'sort: New' and 'Title/keyw'. The review found the same mid-word cuts elsewhere in Library: '○ Server n' and '← Notes to folde' (sync setup), 'Review recovered pa' (Folder files at 60x24), 'Use it in Consol' (landing), 'Defaults to source nam' (import). The nav-bar cuts in the evidence are intentional clip-ghosts (task-3200) and out of scope. Suggested direction: mark the active mode with a leading '✓ ' instead of the longer ' (selected)'. How active state is marked across Library is finding S-12, filed separately, so stay consistent with it. Below about 90 columns, wrap the reader's mode and action rows instead of clipping them. Give single-line Library labels an ellipsis plus a tooltip; the precedent is .library-notes-trash-row-copy in css/features/_library_panels.tcss:573-577. Add an 80x24 label census test.

Review finding(s): L-07, L-16, L-19, L-22, S-16. Source: qa/notes-library-ux-review-2026-10-02/report.md
