## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: Found by reading during the polish-1b Task 6 re-review (TASK-34000.29), not yet reproduced in the app. `export_library_note_file` calls `resolve_export_destination` and `export_destination_exists` (`UI/Library_Modules/library_file_export.py`), and both document `OSError`. On Python 3.12, `Path.is_symlink()` and `Path.exists()` raise `PermissionError` for a path under a folder the process cannot search. `_write_library_note_export_file` runs through `call_after_refresh` and does not catch it. So a user who picks a destination inside such a folder would most likely see the error escape the callback (a crash or an unhandled-exception notice) instead of the honest "Export failed — choose another destination and try again." that a refused path gets today. This is the "fails" arm next to TASK-34000.29 AC#2, and it predates that task.
