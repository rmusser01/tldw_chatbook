## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Connecting a tldw server is hard to find. The only control is "Switch Source / Server", inside Settings' "Advanced / Diagnostics" collapsible, which starts collapsed [coverage-06]. Nothing on Settings' main page says whether chatbook is using a server at all, so a user who runs one cannot see whether they are connected, and a local-only user is never told that Library and notes stay on this computer.

The approved setup-shape spec moves the control into Settings ▸ Overview's main body as a "tldw server" row that states the current source (decision D3, part 5). It is the cheapest slice in the programme and depends on nothing.

Spec: Docs/superpowers/specs/2026-10-03-first-run-setup-shape-design.md (revision 3, approved by the owner on 2026-10-03; ADR-217): D3 part 5, §3.0 (area name "tldw server"), §10 F1.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Settings ▸ Overview's main body, never a collapsed section, shows a 'tldw server' row. With no server in use it reads 'tldw server: none — Library and notes stay on this computer' with [ Connect a tldw server… ]; with one in use it names the host and says 'connected' or 'not reachable now', with [ Switch source… ]
- [ ] #2 The row's value comes only from the runtime-source owner (RuntimePolicyContext, ADR-033). The [tldw_api] template values (base_url 127.0.0.1:8000 and the placeholder token) never make the row read as connected
- [ ] #3 The control moves rather than being duplicated: 'Switch Source / Server' no longer appears under Advanced / Diagnostics, and the moved control keeps the id settings-switch-runtime-source and opens the same switch flow as before
- [ ] #4 After any switch (connect, change, or back to local) the row shows the new state without reopening Settings
- [ ] #5 The row fits at 80x24 and 120x40 and carries its state as text, not colour alone
- [ ] #6 Verified live on a fresh isolated profile (TLDW_CONFIG_PATH and HOME set) through the real app, with real providers and the real llama.cpp server, never mock servers: local only; connect to a real tldw_server; switch back to local; and the server stopped while bound. Evidence is recorded in Implementation Notes
- [ ] #7 New behaviour is covered by tests that fail on the pre-change code (RED verified), and no module-size or ADR-097 ratchet is raised
- [ ] #8 The matching Docs/User_Guide page content is updated where behaviour changed (no 'Verified against' stamps)
