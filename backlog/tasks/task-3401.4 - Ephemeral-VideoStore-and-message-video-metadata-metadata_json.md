## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implements the core product constraint: videos never persist in the DB. Files live in a per-message directory (generated_videos/<message_id>/) under the user data dir keyed by the STABLE message id -- not the ephemeral console session id, which would orphan ttl-retained files across restarts. The message carries a [video] slug-name marker plus local-only metadata in the messages.metadata_json column (v31 precedent from task-2364: no migration required; no path and no URL stored). A runtime store resolves name to file and degrades to a named tombstone after restart or expiry; a total size cap with LRU eviction bounds disk use even within a running session. The v25 generation-metadata sidecar is NOT extended: its position column is defined by alignment with message attachments and video messages have none. ADR: backlog/decisions/044-ephemeral-generated-video-storage-playback-and-streaming.md
<!-- SECTION:DESCRIPTION:END -->
