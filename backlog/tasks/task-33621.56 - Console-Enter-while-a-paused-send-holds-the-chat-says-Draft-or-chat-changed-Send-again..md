## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact.** While a paused send holds a conversation (a Library pause, a provider-not-ready pause, a trace pause or a 'Send could not be saved' persistence pause), the composer still shows the sent text and Send looks available. Pressing Enter shows the toast 'Draft or chat changed; Send again.' Nothing changed, and sending again is refused the same way, so the user is told to repeat an action that cannot work instead of being pointed at the card's or the shelf's actions.

**Where it was seen.** Live on dev f9baac8706 (TASK-33620.3 repro, evidence U01/r2/13) and again on the TASK-33620.3 fix branch (U01/r3-fix/09, 2026-10-29) with a 'Send could not be saved' card on screen.

**Cause, as measured.** A composer send takes the received-intent path. Its claim (console_received_turn.claim_received_turn) returns None while any non-terminal preparation holds the session, and the runtime raises 'Console session already has an admission owner.' The three UI call sites that catch it (UI/Console_Modules/send_acknowledgement.py, composer_run_controls.py, wiring.py) all show the generic toast. The controller already has honest copy for exactly this state ('Last send is blocked; resolve it first.', TASK-33621.2), which the received path never reaches.

Found during TASK-33620.3 (it covers every pause kind, so it was kept out of that task's scope).
