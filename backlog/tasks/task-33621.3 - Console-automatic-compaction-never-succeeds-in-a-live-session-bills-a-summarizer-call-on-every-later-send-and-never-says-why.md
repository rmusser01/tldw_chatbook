## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact (P0).** Setup: an app-created chat, automatic compaction, a custom 6,000-token budget and the default stop_and_ask. The 7th send shows 'Running' / 'Run: Validating provider.' with nothing about summarizing, then ends at 'Response accepted; waiting for dispatch.' with Retry/Discard and 'Send blocked - resolve response recovery first'. Retry, a fresh send and Settings > Compact now each make another billed summarizer call and fail with 'Conversation compaction did not complete; the provider request was not sent.' There were four billed attempts, all status=failed (7,156 in / 111-115 out each). No memory was written, the log recorded no reason, and the attempts table has no reason column. The chat becomes unusable, and money is spent on every attempt.

**Verified cause.** Live-created messages keep `parent_message_id=None` in memory, because `_hydrate_durable_turn_owner_messages` sets only `persisted_message_id`. The commit's `durable_lineage` is built from those snapshots, so `_validate_branch_memory_commit_ownership` raises 'durable_lineage must be one ordered parent chain'. `compact()` swallows that as `memory_commit_failed` without logging it. The summaries themselves were valid, and after an app restart Compact now succeeded on the same chat. The same missing in-memory parent lineage also breaks Fork on fresh turns (finding G1-09(a)); coordinate so that one lineage fix serves both.

**Prior art:** REGRESSION of TASK-14811.2.1 (Done) AC#1 ('at most one automatic summary call per send') and AC#8 (failure paths stop or recover 'without retry loops or silent safety claims'); also TASK-14811.5 (Done).

**Suggested direction:**
- Set the in-memory parent ids when hydrating committed turn owners, or build lineage fences from persisted rows.
- Log `transaction.reason` and persist it on the attempt row.
- Map each reason to copy with a next step (send without older turns, raise the budget, turn compaction off, new chat).
- Disclose the spent tokens and cost.
- Suppress automatic re-attempts after a failure until the conversation or policy changes.
- Show 'Summarizing older turns (1 extra model call)' while the summarizer call runs.
- Replace 'the provider request was not sent' with 'your message was not sent'. In the Compact now context, say that compaction failed and nothing changed.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Fixes GAP2-01: in a live session, automatic compaction never committed, billed a summary call on every later send, and never said why.

**Root cause:** live durable-send turns keep `parent_message_id=None` in memory, because only the persisted id is hydrated. The compaction commit fence built `durable_lineage` from those snapshots, so `_validate_branch_memory_commit_ownership` raised after the billed call, and `compact()` swallowed the error as `memory_commit_failed`.

**Changes:**
- **Lineage** (`console_chat_controller.py`): when the live parent mirror is unset, the fence uses `store.durable_parent_for_message(native_id)`. The structural fence checks now also run before the billed call (`console_context_repository.validate_branch_memory_commit`, called from `ConsoleCompactionService._compact_once`), so a commit that can never land fails at no cost.
- **Reason recording** (`console_context_compaction.py`): the new `_end()` helper finishes every non-successful attempt with a content-free `failure_reason` and logs `console_compaction_failed reason=… status=… error_type=…` (STALE logs at info). `CompactionTransactionResult` gains `usage`, `attempted` and `suppressed`.
- **Schema v74:** the migration `chachanotes_v73_to_v74_auxiliary_failure_reason.sql` adds the column with a CHECK constraint (lowercase code, at most 64 characters). Also updated: `_CURRENT_SCHEMA_VERSION` and its migration step; the recovery snapshots in `recovery_core_schema.py` and `recovery_operations.py`; the expected version in `Backup_Recovery/sqlite_validation.py`. `ConsoleContextRepository.finish_auxiliary_attempt` validates the code and refuses one on a success.
- **Copy:** the new `Chat/console_compaction_failure.py` holds pure functions that map each reason to its copy.
  - It discloses the spend: tokens, and the cost via the pricing catalog when priced.
  - A send says "Your message was not sent"; Compact now says "Compaction failed and nothing changed"; "Nothing to compact yet" is used only for no_complete_durable_units.
  - It gives a next step, and states the pause for the app session.
  - The controller now writes the block note before `mark_message_failed`, and `_restore_dispatch_recovery_after_settlement_failure` keeps that block's own copy instead of the generic recovery text.
- **Retry latch** (`CompactionRetryFence` / `_FailedCompaction`): a billed FAILED attempt pauses automatic attempts for that conversation and route (provider/model). While paused, sends, Retry and micro-compaction make no call and write no ledger row, until any of these change:
  - the settings digest: provider, model, prompt, policy other than failure_behavior, model window, effective memory;
  - the durable history prefix.

  Compact now bypasses the latch; a success clears every route; STALE does not latch.
- **Omit older context:** Compact now always reports its failure. A billed automatic failure under Omit appends one transcript-only disclosure and sends the request uncompacted.
- **Docs:** User Guide `console/context-and-rag.md` gains "When compaction fails"; ADR-052 gains a 2026-09-30 amendment. The production-diagnostic inventory row for console_context_compaction.py was updated.

**Trade-offs:**
- The latch is in memory, so it lasts for the app session. Persisting it would mean more schema and recovery-snapshot work on a v74 migration that already collides with PR #2918.
- STALE results are not latched, so a legitimate resend is never blocked.
- The "Summarizing older turns" status was not added; it is not in the ACs.
