## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Impact (P0).** Setup: an app-created chat, automatic compaction, a custom 6,000-token budget and the default stop_and_ask. The 7th send shows 'Running' / 'Run: Validating provider.' with nothing about summarizing, then ends at 'Response accepted; waiting for dispatch.' with Retry/Discard and 'Send blocked - resolve response recovery first'. Retry, a fresh send and Settings > Compact now each make another billed summarizer call and fail with 'Conversation compaction did not complete; the provider request was not sent.' There were four billed attempts, all status=failed (7,156 in / 111-115 out each). No memory was written, the log recorded no reason, and the attempts table has no reason column. The chat becomes unusable, and money is spent on every attempt.

**Verified cause.** Live-created messages keep `parent_message_id=None` in memory, because `_hydrate_durable_turn_owner_messages` sets only `persisted_message_id`. The commit's `durable_lineage` is built from those snapshots, so `_validate_branch_memory_commit_ownership` raises 'durable_lineage must be one ordered parent chain'. `compact()` swallows that as `memory_commit_failed` without logging it. The summaries themselves were valid, and after an app restart Compact now succeeded on the same chat. The same missing in-memory parent lineage also breaks Fork on fresh turns (finding G1-09(a)); coordinate so that one lineage fix serves both.

**Prior art:** REGRESSION of TASK-14811.2.1 (Done) AC#1 ('at most one automatic summary call per send') and AC#8 (failure paths stop or recover 'without retry loops or silent safety claims'); also TASK-14811.5 (Done).

**Suggested direction:**
- Set the in-memory parent ids when hydrating committed turn owners, or build lineage fences from persisted rows.
- Log `transaction.reason` and persist it on the attempt row.
- Map each reason to copy with a next step (send without older turns, raise the budget, turn compaction off, new chat).
- Disclose the spent tokens and cost.
- Suppress automatic re-attempts after a failure until the conversation or policy changes.
- Show 'Summarizing older turns (1 extra model call)' while the summarizer call runs.
- Replace 'the provider request was not sent' with 'your message was not sent'. In the Compact now context, say that compaction failed and nothing changed.
