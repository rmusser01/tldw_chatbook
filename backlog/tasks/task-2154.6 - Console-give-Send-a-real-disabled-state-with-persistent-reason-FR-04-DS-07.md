**Approach.** Send now carries a real Textual `disabled` state driven by the same `has_draft`/`send_blocked` inputs the old CSS-only subdual already computed; the previously dormant `#console-send-disabled-reason` Static is display-toggled inline (the `1fr` draft yields the cells; the fixed 26-cell actions budget and the one-row height are untouched) with copy from the already-tested `build_console_disabled_reason` helper. The Enter hotkey's `Button.press()` funnel got a disabled-aware dispatch branch so the blocked-attempt feedback survives. DS-07 resolved by deleting the unreachable idle Stop tooltip.

**Changes by file.**
- `tldw_chatbook/Widgets/Console/console_composer_bar.py`: `sync_action_state` sets `send_button.disabled = not send_ready`; empty-draft tooltip `"Type a message to send."` (was `None`); new `_sync_send_disabled_reason()` (Content update, `display`/`width: auto` toggle capped at `SEND_REASON_MAX_WIDTH=52`, muted `-idle` class for non-blocker guidance); `_sync_current_action_state` counts a staged attachment as draft content (matches the screen's own sync, kills per-keystroke disabled flicker while an image is staged); `compose()` builds Send with `disabled=True` (fresh composer = empty draft); idle Stop tooltip removed (DS-07); `call_after_refresh(self._refresh_visible_draft)` re-windows the draft on reason change (synchronous refresh would read the pre-toggle width, same reason `set_pending_attachment_label` doesn't re-window inline).
- `tldw_chatbook/Chat/console_display_state.py`: `build_console_disabled_reason` gains a run-blocked branch (`"Send blocked — wait for the active run to finish"`) between the setup branch and the `has_draft` check; every previously pinned branch byte-identical.
