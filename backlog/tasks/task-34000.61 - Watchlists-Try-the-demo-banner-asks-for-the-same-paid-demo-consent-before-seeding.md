## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Why: TASK-34000.23 put a consent step in front of the Library Reports "Set up a daily brief…" CTA, so one press no longer seeds a lasting Daily Brief watchlist, three hourly RSS checks, a 24 h briefing cadence and a paid LLM (plus cast-script and TTS) run. The third entry point to the same demo, the Watchlists banner's "Try the demo" (UI/Screens/watchlists_collections_screen.py, tooltip "Generate a sample daily brief from your watchlists."), still starts `run_demo_detached()` on the first press with weaker copy than ADR-079's "CTA copy says so" asks for. A user who meets the demo there first gets exactly the surprise .23 removed from Library.

The consequence copy now has one shared source (`Subscriptions/daily_report_demo.py`: `daily_report_demo_consequences()` / `daily_report_demo_tooltip()`), so the banner should render the same facts and the same consent shape rather than its own wording. ADR-079 §2 (the demo seeds real, persistent setup by design) and §5 (the banner is hidden while any briefing schedule exists; dismissal persists) are unchanged: this task changes disclosure and consent, not what is seeded or when the banner shows.

## Acceptance Criteria

- [ ] #4 The banner copy and the Library Reports consent copy come from the same source, so the two cannot drift
- [ ] #5 Verified live in an isolated profile with a real provider key: the consent names the feeds, cadence and model; Cancel leaves the DB empty (`subs_demo_state.py --report` all zero); if the Confirm path is exercised it is purged afterwards (`--purge`, counts pasted, all zero) and the profile deleted
