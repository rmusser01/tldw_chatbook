## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Give slow Send preparation one admission owner from the moment input is received, so immediate feedback can precede checked preparation without duplicate sends, stale draft changes or gaps in cancellation ownership.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Existing complete runtime requests synchronously reserve the same per-session admission owner used by preparations, and promotion never releases and reacquires that slot.
- [x] #2 Direct, queued, retry and background admission paths respect the received claim and their existing origin authorization; stale cleanup cannot release a successor.
- [ ] #3 Runtime custody, activity, Stop, Close, archive and shutdown account for received work before preparation; issued native work remains owned until retirement.
- [x] #4 Scheduling or preparation failure preserves existing complete-request attachment-prefix, input recovery, durable acceptance and callback contracts.
- [x] #5 Targeted controls demonstrate duplicate admission, store races, promotion, cancellation and cleanup; unconfigured UI intake/input revisions and actual feedback/timing remain separately unqualified.
<!-- AC:END -->
