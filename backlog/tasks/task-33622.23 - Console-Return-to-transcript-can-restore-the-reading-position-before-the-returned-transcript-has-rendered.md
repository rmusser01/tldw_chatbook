## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
After Return to transcript (TASK-33622.8), the reading position is restored one refresh after the native session sync is awaited. That sync can return without rendering: it is held for a durable commit, paused for maintenance, replaying the control bar, or already in progress. A later poll tick then renders the transcript. In those cases the restore runs against a transcript that has not been filled yet, so the saved offset can be clamped or lost and the reader lands at the live tail instead of where they were reading. The position is already scoped to the conversation it came from; what is missing is waiting for a real render.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 When the post-return sync is deferred (held, maintenance-paused or already in progress), the captured reading position is applied after the transcript has actually rendered the conversation, not before
- [ ] #2 A position captured for one conversation is still never applied to another
- [ ] #3 A mounted test on the real ChatScreen forces a deferred sync on return and asserts the restored scroll position; it fails on the pre-fix code
<!-- AC:END -->
