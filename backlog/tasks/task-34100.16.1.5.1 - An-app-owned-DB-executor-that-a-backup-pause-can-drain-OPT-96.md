## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Filed on 2026-11-28 per the owner's ruling on TASK-34100.16.1.5 ("per site plus a census"). That task wraps each user-reachable bare offload of the ChaChaNotes and Media stores in `participants.run_finite_local_worker`, so the offload leaves no pool-thread lease that a backup's local pause cannot revoke. The cost of the wrapping is one connection open per offloaded read.

Measured in TASK-34100.16.1's pre-merge review (2026-11-13; `.worktrees/setup-wizard-ux-qa/evidence/g161v5-pm/bench_reads.py`, real DBs under an isolated HOME, startup admission held, medians in ms). A wrapped read costs one connection open, about 40-50 ms. A bare read on a warm cached connection took 0.3-4 ms:
- ChaChaNotes `list_notes`: 0.5 → 46.9
- Media `get_keyword_usage_stats`: 1.1 → 39.5
- the `[[` picker: 0.6 → 48.0
- backlinks: 0.3 → 48.4

That is about 45 ms on every offloaded read that the wrapping covers.

OPT-96 (Docs/Development/console-optimization-review-list.md:313) is the alternative that removes that cost: a small application-owned DB executor that keeps warm connections, and whose threads a backup's local pause can ask to retire their own caches. It is not built today, because it needs contracts the app does not have yet. OPT-96 lists them: proven cancellation, queue, pause/drain, thread-affine close and uncertain-retirement. It also warns: "Do not silently retain handles or remove finite cleanup."
