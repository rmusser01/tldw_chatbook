## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
When a category has unsaved edits, the State line drops its save-model badge and reads 'State: Unsaved changes | Save (s) or Revert (r) — switching categories keeps this draft.' (UI/Screens/settings_screen.py:9391-9400). The badge ('Draft — save with s', from _persistence_badge at :9408-9446) appears only when the category is clean.

The badge is ADR-033's honest label for the category's commit model (task-1717, DESIGN.md:272-278). It must stay visible and truthful. Users also cannot see how much is unsaved.

The judge's and the spec's rule: keep the badge and add a count, for example 'Draft — save with s · 2 unsaved', rather than replacing it with a dirty flag.

Tests that pin today's copy: test_state_banner_dirty_branch_keeps_priority (Tests/UI/test_settings_configuration_hub.py:12047), and, for Speech & TTS's leave-resolution wording (task-2708), test_speech_tts_dirty_banner_names_leave_resolution (:12062).
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The dirty State line keeps ADR-033's badge and counts unsaved fields (`UI/Screens/settings_screen.py`):
- Guided categories: "State: Draft — save with s · 2 unsaved · revert with r | {scope}" (was "State: Unsaved changes | Save (s) or Revert (r) — switching categories keeps this draft.").
- Providers & Models: "State: Draft — save with s · N unsaved | {scope}". No "revert with r": the T3 scope fills the 120-cell row at 211x44 (controller ruling 9).
- Speech & TTS: "State: Draft — save with s · N unsaved | Leaving Speech & TTS resolves this draft: save or discard first." The leave wording keeps its place; "revert with r" would push the 99-unsaved line to two rows.
- Image Gen / Video Gen: "State: Draft — save/revert below · N unsaved | {scope}" (their badge already names Save/Revert; s/r are not their keys).
- Advanced Config: "State: Validate, then Save · 1 unsaved | Draft kept when you leave; use raw editor controls." (was "State: Unsaved raw TOML | …").
- Unchanged: clean lines for every category (AC#4) and the "State: Needs correction | …" line for an invalid Appearance, Library & RAG or Storage draft.

The count (`_category_unsaved_count`) is fields that differ from saved, recomputed on every draft refresh, so it goes up and down as fields are edited and set back:
- Providers & Models: distinct dirty field names from `_provider_return_dirty_field_names` (context window + reset = 1), plus each snapshot preference (enabled, keep count) that differs (`_snapshot_preferences_dirty_count`).
- Speech & TTS: the panel kept one sentinel draft key, so the count comes from the panel snapshot. `count_global_speech_tts_unsaved_fields` (`settings_speech_tts.py`) compares defaults and provider values validated where they validate (Input text that parses to the saved value is clean), raw otherwise; `SpeechTTSPanelDraftSnapshot.unsaved_field_count` adds the realtime and pipeline-voice fields.
- Every other category: its dirty draft keys (one per field). Advanced Config has no per-field keys and counts 1. Never below 1 while dirty.
