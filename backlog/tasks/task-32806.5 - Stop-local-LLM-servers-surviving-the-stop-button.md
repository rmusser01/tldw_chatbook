## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Every local LLM server is spawned without a process group and stopped with a bare `terminate()`, so a forked worker survives while the app clears the handle and reports the server stopped -- with the port still held. Nine other subprocess sites in this repo already use a new session and a process-group kill. Nothing in unmount stops these at all, so quitting the app orphans every running server.

## Two more spawns in the same class, and a warning about the one-line fix (TASK-32901, tier-2 review S03/S04)
<!-- Added 2026-09-22 by the tier-2 P2 burn-down, which closed this finding to
this task rather than adding the flag on its own. -->

Neither TTS subprocess spawn passes `start_new_session`:

- `TTS/audio_cpp_supervisor.py:480` (`asyncio.create_subprocess_exec`)
- `TTS/backends/chatterbox.py:284` (same; runs `sys.executable` under torch)

**Half of this task's framing does NOT apply here**: the app does stop the
supervisor at exit (`app.py` -> `close_tts_resources()` -> `TTS_Generation.py`
-> `adapters/audio_cpp.py` `await supervisor.stop(...)`), so these are not the
"nothing in unmount stops them" shape. Only the process-group half applies.

**Do not add `start_new_session=True` here on its own.** Both teardowns
(`chatterbox._discard_process`, the supervisor's stop ladder) reach only the
DIRECT child -- `terminate()`, wait, `kill()`, and no `killpg` anywhere. Adding
the flag without a matching process-group kill is a net negative: it removes
the terminal foreground group's SIGHUP/SIGINT, which is currently the only
thing that reaps these children when the terminal dies, and buys no new reach
for teardown. The flag and a `killpg` have to land together.

Related and higher severity, owned elsewhere: the S03 **P0** at
`TTS/audio_player.py:556` calls `os.killpg(os.getpgid(child), SIGKILL)` on
children spawned WITHOUT `start_new_session`, so its pgid is the app's own --
pressing Stop on TTS playback SIGKILLs the whole TUI. Fixing that one requires
the same pairing, which is why these two belong in the same change.
