## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The State line's unsaved count (TASK-33002.4) counts draft keys on Image Gen and Video Gen, not fields that differ from their saved values, which contradicts `_category_unsaved_count`'s own docstring. Found by the TASK-33002 final review (Task 4 rider).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 On Image Gen and Video Gen the count equals the number of fields that differ from their saved values, and drops when a field is set back by hand
- [x] #2 A test pins the count for one edit that touches two draft keys
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
The Image Gen and Video Gen unsaved count counts fields, not draft keys.

- `settings_image_gen_defaults.unsaved_field_count(dirty_keys)`: `field::<backend>::<key>` and `cleared::<backend>::<key>` are one field, and `cleared::swarmui::api_key` (the legacy spelling SwarmUI's token Clear also deletes) is the token field. Any other key is a field of its own, so the other draft categories that share the fallback branch count as before.
- `SettingsScreen._category_unsaved_count`'s fallback branch counts through it. A key set back by hand already leaves `SettingsDraft.dirty_keys`, so the count drops.
- Premise check at HEAD: an edit and a Clear of one field do not both stay dirty today (each unstages the other), so the case that counted 2 was SwarmUI's token Clear. The helper covers both shapes.
