## Description

<!-- SECTION:DESCRIPTION:BEGIN -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Four media tests now call `LibraryMediaController` methods on their existing controller seams instead of reaching them through `LibraryScreen`, and `_LIBRARY_UNBOUND_TEST_CALLS` drops from 724 to 722. Test-only: no product code changed. Every other media test that reaches the screen reaches a method whose body still lives on `LibraryScreen`, so it cannot be pointed at the controller yet; those form the TASK-36952.3 worklist summarized below.

**Census** (`ast`, dev ecad404bd4, the ratchet's own counting rules plus the shapes it leaves out):
- `LibraryScreen` has 106 one-line delegators to `self._media_controller` and 3 static delegators that return `LibraryMediaController.<same name>(...)`.
- 212 of the 724 counted sites name a media method (name contains "media"):
  - 2 reach a delegator, `LibraryScreen.handle_library_media_reader_more(fake, ...)`. Retargeted.
  - 1 calls the static delegator `_restore_library_media_scope` inside a subprocess program in `Tests/Packaging/test_library_preimport_closure.py`. Left as is: that test pins that the screen's static restore entry runs before any controller module is imported, so the screen method is its subject.
  - 209 reach a body that still lives on the screen. Worklist.
- The other 512 counted sites name non-media methods (review sets, `check_action`, notes, prompts, skills, export and shell helpers). Out of scope.
- Shapes the ratchet does not count: the 16 `_press(fake, LibraryScreen.handle_library_media_analyze_*)` references reach screen bodies (worklist). The 2 `asyncio.to_thread(LibraryScreen._run_library_export_via_service, ...)` references are export, not media. Two string-dispatched `MethodType(getattr(LibraryScreen, name), fake)` loops in `test_library_multiselect_media.py` bind 8 media methods by name; all 8 have screen bodies (worklist).
- `<x>._media_controller` paths: 23 sites in 7 files.
  - 6 are on fake screens (`test_library_media_reader_flow.py` 2, `test_review_set_walker.py` 4). Retargeted.
  - 17 are on real screens: `test_library_media_viewer_speaker_rename.py` 6, `test_library_media_return_settlement.py` 7, `test_library_rail_switch_keeps_reader_and_note.py` 2, `test_library_canvas_sync_gaps_t21242.py` 1, `test_external_action_workers.py` 1. Left as is. They already call the controller method at its one home: none of `_build_library_media_viewer_display_state`, `_handle_library_media_row_geometry_changed` or the two state reads has a screen method. The controller they address is the one `LibraryScreen.__init__` builds (`library_screen.py:3112`), the controller's only factory. Four of the five files drive a mounted screen through Pilot, where that live controller (and, in `test_external_action_workers.py`, `controller._screen is owner`) is what is under test.
- Why no test builds a real `LibraryMediaController`: its constructor (`library_media_controller.py:562`) takes `screen` plus 92 required keyword-only arguments, almost all of them screen callbacks. Building one by hand re-spells the screen coupling without removing any of it. TASK-36952.3 AC #2 is what makes direct construction practical.

**Retargets** (2 files, 4 tests):
- `Tests/UI/test_library_media_reader_flow.py::test_more_toggle_chains_the_restore_already_queued_on_the_viewer` and `::test_more_toggle_without_a_viewer_falls_back_to_the_screen_seam`.
  - Before: `LibraryScreen.handle_library_media_reader_more(fake, event)`, that is, the screen delegator (`library_screen.py:34661`), then `fake._media_controller`, then the seam.
  - After: `_MoreHandlerControllerFake(fake).handle_library_media_reader_more(event)`. The seam runs the real controller body (`library_media_controller.py:4614`), as before.
  - The fake screen no longer carries `_media_controller`, since nothing reads it now. The two `MethodType(LibraryScreen._after_library_media_viewer_sync / ._queue_after_library_media_viewer_recompose, fake)` bindings stay: both bodies live on the screen (worklist).
  - `_MoreHandlerControllerFake`'s docstring is updated; its code is unchanged (the class minus its docstring is AST-identical).
- `Tests/UI/test_review_set_walker.py::test_review_selected_handler_shares_the_one_id_coercion` and `::test_review_selected_handler_starts_nothing_when_no_id_coerces`: `fake._media_controller = _ReviewSelectedControllerFake(fake)` then `fake._media_controller.handle_library_media_review_selected(event)` becomes a local `controller` and `controller.handle_library_media_review_selected(event)`. The seam runs the real body (`library_media_controller.py:3653`).
- The seams were kept rather than replaced with real controller instances, for the 92-argument reason above. They call the real controller body on the controller class, which the ratchet does not count.

**AC #2 evidence** (mechanical): a script took every test function whose AST differs between ecad404bd4 and head (derived from `git diff`, not hand-listed) and compared, base against head, the `ast.dump` of every `Assert` node and the source text of every assert (`ast.get_source_segment`). All 4 functions matched on both (3, 4, 3 and 1 asserts). No other test function changed.

**Recipe §3 check:** none of the 4 tests calls `monkeypatch` or `patch`. The two seams still read through the fake screen at call time (`self._screen._media_state`, `self._screen._after_library_media_viewer_sync`, `self._screen._review_selected_worker`, `self._screen.run_worker`). Dropping `fake._media_controller` is safe: apart from the delegators, the only `LibraryScreen` methods that mention `_media_controller` are `__init__`, `compose_content`, the 3 static delegators and `handle_library_media_link_undo`, and none of those is bound to these fakes.

**AC #3:** `_LIBRARY_UNBOUND_TEST_CALLS` goes from 724 to 722: 600 calls (592 on the class and 8 `__wrapped__`), 122 bindings (unchanged), 59 files (unchanged). **Re-scope (coordinator ruling).** AC #1 originally read "Media tests construct or address the media controller directly". That wording assumed the media bodies already lived on the controller, and the census at ecad404bd4 shows they mostly do not. Of the 212 counted sites that name a media method:
- 2 reached a delegator to the controller, and are retargeted;
- 1 is the Packaging test of the screen's static restore entry, which tests the screen method itself and is kept by design;
- 209 reach bodies that still live on `LibraryScreen`.

The requirement is not dropped: it moves to TASK-36952.3 as an acceptance criterion, so each test is retargeted in the change that moves its body. A Pilot test that drives a mounted screen and calls its live `screen._media_controller.<m>` counts as addressing the controller directly, because the mounted controller is the object under test. AC #1 now reads "Media tests whose behaviour already lives on the media controller construct or address it directly".
