## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Media tests call LibraryScreen media methods unbound on fake screens or reach the controller through the screen; no test constructs LibraryMediaController directly. Retargeting fixtures first lets the bodies move without changing assertions (recipe §3).

Source: architecture review 2026-10-25, `Docs/QA/architecture-review-2026-10-25/report.md` §F2; claim-by-claim verification in `Docs/QA/architecture-review-2026-10-25/verification.md` (origin/dev 7a5e2513c5).
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Media tests whose behaviour already lives on the media controller construct or address it directly
- [x] #2 Every retargeted test keeps its assertions byte-for-byte
- [x] #3 The unbound-call ratchet is lowered
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Census, by `ast` at base ecad404bd4, every site the unbound-call ratchet counts (plus the 18 helper-passed references it does not) and every `<x>._media_controller.<m>` path under `Tests/`. Classify each screen method: a one-line delegator to `self._media_controller` (body on the controller), or a body still on `LibraryScreen`.
2. Retarget only the delegator sites and the fake-screen `_media_controller` paths: call the controller method on the existing controller seam, with no screen hop. Leave screen-bodied sites unchanged and record them as the TASK-36952.3 worklist.
3. Lower `_LIBRARY_UNBOUND_TEST_CALLS` to the measured count in the same commit.
4. Prove AC #2 mechanically: AST-dump every assert in each touched test function at base and head, and compare. Check each touched test's `monkeypatch.setattr` targets (recipe §3).
5. Verify: A/B each touched test file at base vs head (`-n 4`), `Tests/Architecture` serially, preflight.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Media tests now reach controller-resident behaviour on the controller instead of through `LibraryScreen`. Test-only: no product code changed.
- **Round 0:** 2 unbound `LibraryScreen.handle_library_media_reader_more(fake, ...)` calls now call the controller seam, and 2 fake-screen `_media_controller` hops were dropped. `_LIBRARY_UNBOUND_TEST_CALLS` goes from 724 to 722.
- **Fix round 1:** 84 bound `screen.<delegator>(...)` calls on real screens, in 22 files, now call `screen._media_controller.<same method>(...)`.
- **Left in place:** 20 bound calls. 17 sit inside `assert` statements, where AC #2 wins; 1 is the public seam; 2 are copies of production wiring. They are listed below.
- **The rest:** every other media test that reaches the screen reaches a method whose body still lives on `LibraryScreen`, the TASK-36952.3 worklist summarized below. Separately, two identity references to a delegator stay by design (listed below).

**Delegator set** (`ast`, dev ecad404bd4, re-derived for fix round 1):
- `LibraryScreen` has **106** methods whose body (docstring aside) is only `return [await] self._media_controller.<m>(...)`.
  - Every one forwards to the controller method of the same name.
  - Each passes its own parameters straight through, in order, with keywords as `k=k`.
  - One signature differs: the controller's `_request_library_media_filter` adds a keyword-only `clear_type=False`. All 4 test calls pass only `query`, so they get the same default the delegator gives.
- There are 3 more static delegators that return `LibraryMediaController.<same>(...)`: `_bounded_library_media_trash_title`, `_restore_library_media_scope` and `_valid_library_media_trash_delete_ack`.
- `request_library_media_layout_refresh` is one of the 106, but it is the public seam (`settings_screen.py` calls it on the screen through `getattr`), so it stays on the screen.

**Census of test sites** (the ratchet's own rules plus the shapes it leaves out):
- **Counted, named.** 212 of the 724 counted sites name a media method:
  - 2 reach a delegator (`handle_library_media_reader_more`). Retargeted in round 0.
  - 1 calls the static delegator `_restore_library_media_scope` in a `Tests/Packaging/test_library_preimport_closure.py` subprocess. Kept: that test pins that the screen's static restore entry runs before any controller module is imported, so the screen method is its subject.
  - 209 reach a body still on the screen. Worklist.
- **Counted, unnamed.** Of the other 512 counted sites, 2 are `MethodType(getattr(LibraryScreen, name), fake)` loops in `test_library_multiselect_media.py` (`_analyze_fake`, and `test_bulk_run_never_touches_reader_state_and_counts_a_failed_save`). The ratchet counts them, but the name is a loop variable, so the media count above cannot see them. They bind 8 media methods, all with screen bodies (worklist). The remaining 510 name non-media methods: review sets, `check_action`, notes, prompts, skills, export and shell helpers.
- **Uncounted:**
  - 16 `_press(fake, LibraryScreen.handle_library_media_analyze_*)` references reach screen bodies (worklist).
  - 2 method-in-a-variable calls reach screen bodies (worklist). At `test_library_media_trash.py:4073`/`:4075`, `handler = LibraryScreen.handle_library_media_trash_delete_confirm` / `..._trash_restore` is followed by `handler(fake, event)`.
  - 2 identity references to the delegator `_apply_library_media_list_return` (`test_library_media_trash.py:3557` stores it on a fake; `:3579` asserts on it). It is never called, and the assert stays under AC #2.

They go red loudly when the bodies move.

- **Why no test builds a `LibraryMediaController` by hand:** its constructor (`library_media_controller.py:562`) takes `screen` plus 92 required keyword-only arguments, almost all of them screen callbacks. TASK-36952.3 AC #2 is what makes that practical.

**Recipe §3 check** (fix round 1):
- **Why the call target is equivalent:** each delegator is a pure forward, so `screen.<d>(args)` and `screen._media_controller.<d>(args)` can differ only if the test patches `<d>` itself on the screen instance or the class.
- **What the patch search found:** a grep of all of `Tests/` for `setattr(..., "<d>"`, `patch.object(..., "<d>"` and `<x>.<d> = ` over the 36 names found no such patch in any test with a retargeted call to the same name. The hits are:
  - on `SimpleNamespace` fakes in other tests;
  - `screen._library_media_editor_dirty = lambda: ""` in tests whose `_library_media_editor_dirty` call is either absent or kept inside an assert;
  - `patch.object(controller, "_build_library_media_reader", ...)` in `test_library_canvas_sync_gaps_t21242.py`. That patch is on the controller, which both paths reach.
- **Round 0:** none of the 4 tests patches anything. The seams read through the fake screen at call time.
