# Closed native V2 compatibility barrier

This component implements [ADR-193](../decisions/193-native-v2-profile-compatibility-and-admission.md) Unit A and [TASK-25907.22](../tasks/task-25907.22%20-%20Add-a-closed-native-V2-profile-compatibility-barrier.md). **All production canonical Profile V2 use remains blocked.** Decoding a valid V2 fixture is validation evidence, never qualification, a grant or an activation permit.

## Behavior

The native codec decodes exact UTF-8 JSON with a 262,144-byte limit, 4,096-node limit and depth 20. It rejects duplicate keys, nonfinite values, unsupported selectors, wrong kinds and invalid semantics with `personal_context_payload_invalid`. V1 manifest/scope/record/proposal use their existing models and canonical bytes. V2 manifest/record/proposal use lazy explicit shared-library validation; V2 scope is unsupported. Numeric JSON integers 1.0/2.0 follow the existing shared contract; booleans and strings never select a version.

Canonical writes detach complete exact known V1 model state before fresh validation. Unknown model/enum/container subclasses, extra constructed fields and callback-shaped values cannot disappear through serialization. Portable aware stdlib/ZoneInfo timestamps remain supported. Incoming V2 is rejected before field consumption, key preparation, encryption or insertion, including nested outbox canonical bodies and incoming first-link snapshots. Local policy, binding, Undo and outbox serialization formats remain V1.

The compiled registry declares fixed native repository/service/bootstrap routes. Its revision/digest describe that inventory only. Compatibility has two states: `legacy_v1` and `v2_blocked`. There is no registration API, imported receipt, qualified state, config switch or caller flag that grants V2 access.

Every ordinary protected read checks the current supported storage marker and authenticated manifest before body authentication. The manifest must agree with current profile metadata. Bulk reads and export snapshots use one SQLite read generation; mutations check on their existing transaction connection before changes. Ordinary getters, empty metadata queries, local policies/bindings, proposals, interviews, Undo, outboxes and first-link content paths also deny. Genuine V1 envelope corruption and narrowly identified known-V1 field/semantic damage retain existing quarantine behavior; missing/extra/unknown selectors, nested future versions and privacy vocabulary remain unavailable without quarantine; compatibility denial never becomes an omitted row or quarantine write.

Service status recomputes compatibility and projects a present blocked profile through existing `LOCKED` state, with fixed reason `personal_context_compatibility_unavailable`; it does not cache compatibility failure as a key failure. Bootstrap returns an unavailable facade. Existing app reuse/retry, Settings owner snapshot, context explanations/tools, fixed/adaptive interview, proposal, export/recovery and Sync owners inherit denial. No automatic recreation, provider/source call, plaintext output or Sync staging/acknowledgement follows denial.

Existing content-free destruction and key-custody/freeze recovery controls retain their previous authority. The barrier does not advertise a newly qualified V2 maintenance workflow or claim that every record was deleted.
