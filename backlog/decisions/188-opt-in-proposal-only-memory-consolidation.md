## Context

Existing Personal Context proposals support foreground acceptance and exact base versions, but do not supply durable source-feed checkpoints, background idempotency or daily budgets. Their CREATE defaults are syncable and body-less ARCHIVE proposals can enter Sync. Existing automatic-work accounting provides native durable admission, physical-owner leases and conservative crash recovery; its broad defaults are not consolidation limits and token units are not billed currency. Accepted evidence, forgetting and disclosure designs are not shipped enforcement.

## Decision

Propose an off-by-default, explicitly enrolled bounded workflow using new exact native user-message revisions and the existing canonical proposal owner. Start with Run now; later native idle wakes may coalesce identical durable jobs. Reject hourly global rereading and a fourth memory/reflective store. Notes/Agent Lessons retain their foreground ADR-106 boundaries; no hidden procedural draft queue.

Enrollment selects exact conversation/workspace bindings through an inactive durable intent, exact source-owner watermark/authority receipt, and coordinator acknowledgement/activation under current reviewed epochs. The source-owner watermark transaction defines the cutoff. Each owner commits locally; no cross-database atomic enrollment is implied. Ambiguous/orphan/missing feed coverage refuses work and cannot silently recapture a later watermark. Old history is excluded in the first slice; later catch-up needs a separate finite qualified foreground review. Direct finalized user assertions may supply evidence; quotations, imported material, attachments, assistant outputs, prior proposals and repeated summaries are not independent user claims or instructions. Current exact source authority/version/span, root lineage, no-memory marks and family suppression apply under ADR-185/186. Trusted native capture provenance/structured source roles are required; imported sender/role=user or model attribution cannot establish a direct assertion. Unknown or ambiguous inputs abstain or defer for exact foreground review. Existing allowed records are comparison context only.

Propose a distinct consolidation purpose in ADR-187's unshipped vocabulary, versioning again if already shipped. Source authority, PROPOSE ceiling, feature enrollment and destination/purpose model permission are separate. The first slice permits only a qualified owned on-device model with known current input lineage or a reviewed clean owned process/slot. No paid/network route, child, general tool catalog or indirect publication is available to closed structured extraction.

Extend native operational owners with encrypted permitted source references, durable unique job/attempt identities, bounded enumeration, independent contiguous terminal checkpoints, counters and content-free receipts. No copied source/prompt/response cache or fact index is added. One active job per profile; shared custody across processes must share qualified transactional admission or refuse. Stable source-coverage/operation identities survive re-enrollment, catch-up and pipeline changes; a fresh job ID cannot republish already terminal work. Suppression or refused unknown coverage takes precedence when restricted receipts are retired. UI events are hints. At most 16 revisions per page/run and 64 pending revisions; overflow or checkpoint holes cannot skip unseen work. Missed wakes resume bounded feed enumeration.

Admission and final adapter entry check current source/record heads, disclosure/grant revisions, scope, lock and purge/retirement epochs. Revalidate after response and at proposal COMMIT. The complete validated batch of at most five proposals, unique job/ticket operation receipt, derivative edges and exact actual publication count share one all-or-none Personal Context owner transaction; separate coordinator acknowledgement recovers that complete exact batch from its content-free receipt. Required-input invalidation, conflict or quota failure publishes none. The automatic-work ledger authoritatively reserves up to five publication slots before the call in an immutable job/profile/epoch-bound ticket. Native publication holds that live claim through owner COMMIT/receipt. The ledger separately consumes the exact owner receipt once, charges actual publications and releases only proven unused slots. Ambiguous publication retains the full reservation; quota counts used plus reserved slots. Publication-window accounting uses the trusted proposal-owner COMMIT timestamp in its receipt, never reservation or acknowledgement time; unsettled slots cannot age out. Personal Context does not write ledger counters in its own transaction. No cross-database atomicity or exactly-once provider execution is claimed. Ambiguous prepared/accepted attempts require review, retain unknown spend and do not automatically replay. There is no partial candidate publication or durable response/candidate cache: a crash before batch commit pauses the whole uncertain attempt for review; after commit recovery never calls the model or republishes. Forgetting and revocation invalidate restricted receipts/edges and recovery, preserving permissible native suppression/idempotency only.

CREATE, exact correction UPDATE and ARCHIVE remain ordinary proposals. Correction uses ADR-185’s exact correction relation/effect; chronology does not invent change_from/transition_at. Duplicate merges are guidance plus individually reviewed UPDATE/ARCHIVE actions; no new merge operation or multi-object atomicity. The workflow cannot accept, direct-update, promote, rewrite goals, impersonate USER or alter instruction files. Native validation excludes new GOAL records and any UPDATE/ARCHIVE/merge target whose current kind is GOAL; ambiguous goal-like changes abstain. First-release automatic proposals have independently enforced device-only/model-deny custody, including ARCHIVE without proposed_record; default current Sync behavior cannot be reused. Foreground batch review binds at most five exact proposal/payload/target versions and separate owner preconditions. Acceptance grants no wider audience or source portability.

Narrow durable ceilings: one physical model call, 4,096 complete prepared-input tokens, 1,024 maximum output tokens, five publications and a 60-second cancellation deadline per run; four calls, 20,480 admission budget tokens and 20 publications per rolling 24-hour profile window. Lower existing limits remain binding. No paid/network model-service spend is allowed. Unknown tokenizer/output bounds refuse; oversized statements are not truncated. Whole-revision packing and compact transient source handles keep caps practical; native owners assemble canonical evidence/control metadata. Oversize input or malformed/truncated/schema-invalid/excess-candidate output becomes content-free deferred extraction with a held checkpoint, no partial publication, model repair, automatic retry or false no-change receipt. Exact foreground retry or reviewed skip resolves it. Known actual usage settles; genuine uncertainty remains held. Run now and idle wakes share counters. Clock discontinuity pauses admission; unsettled reservations remain held even past 24 hours. Every physical attempt is charged; canceled waiters/deadlines do not release leases before actual physical exit. Monetary, budget and measured usage fields remain distinct; paid releases require separate pricing/reservation qualification and cannot pretend estimates guarantee provider billing.

No work means no call; no change means no notification. Only new authorized usable batches or actionable recovery states notify, content-free. Stable state remains quiet. First release requires independently labelled family-disjoint synthetic comparison to manual proposals, exact useful/evidence labels, declared quality gates and hard zero-tolerance disclosure/self-approval/suppression failures. Repeated summaries do not count as evidence; rejection is reported separately from accuracy.

## Consequences and alternatives

Foreground manual-only proposals remain available and supply the control comparison. Signal-driven bounded work may reduce missed facts without giving background output final authority. It requires native compatibility/storage/source-feed/receipt/budget contracts before runtime code; generic scheduling and process-local quotas are insufficient. Global hourly rereading/free-form Dreams was rejected for repeated evidence, costs and conflicting authority. Separate procedural storage was rejected because Notes and Agent Lessons already own those domains.

The first slice is explicitly local and new-input-only. Its no-paid-provider scope does not measure electricity/hardware costs. Exact quote validity is evidence of a statement, not truth. Unknown provider state, legacy derivative coverage and incomplete owner recovery block enabling. A batch can partially conflict; there is no atomic multi-record merge. A cancellation cannot retract already begun model exposure or prove RAM erasure.

## Implementation and acceptance boundary

This ADR proposes design direction only. Implementation must be filed in atomic tasks across existing owners; each native/shared schema change needs its own version/migration/compatibility plan. Consolidation stays disabled until evidence, forgetting/suppression, disclosure and this workflow's source/checkpoint/publication/accounting recovery are **shipped and verified** through successful and refused native controls. Design-task completion cannot enable it. No worker, schedule, model/provider call, real profile, schema, permission or deletion changed here.

ADR-188 is a provisional local allocation checked against available refs and worktrees. Recheck at integration, including newly fetched refs/open PRs; no network allocation check was performed. The user said the written design looks good and requested review before continuing. That follow-up review resolved three verified gaps; the reviewer confirmed the fixes. This accepts design direction only, not implementation, schema or model permissions.
