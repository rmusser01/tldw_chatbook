## Data and validation

Append `max_wall_seconds: float | None = None` to frozen `AgentDefinition` (preserve existing positional fields). None means no additional definition restriction. Accept finite positive Python int/float values, explicitly reject bool before numeric checks; reject strings, containers, nonfinite, zero and negative values in `validate_agent_definition`. Protect conversion/isfinite against OverflowError from huge ints. No arbitrary upper bound and no 1-second lower bound: 0.25 is valid and must remain 0.25 at the admitted budget. Validation errors return through existing list[str] / CRUD ValueError conventions. Do not silently turn invalid explicit values into None.

Canonical Settings adds plain text Input `agents-wall-seconds-input`, label `Child time cap (seconds)`, placeholder `empty = existing child limit`. Strip; blank maps to None, otherwise parse float and use model validation. Boolean strings cannot parse; NaN/Infinity/overflow-to-inf must fail validation. Save errors preserve every persisted field and selected identity. Populate on selection; clear on New and every preset load; preset defaults remain None. Avoid Input numeric restrictions that hide malformed-input handling. Existing immediate Save/omitted-tools status composition remains intact.

AgentRunsDB receives nullable REAL `agent_definitions.max_wall_seconds` with NULL default. Existing definitions stay NULL; no seed rewrite. Update fresh CREATE, guarded PRAGMA/ALTER upgrade, CRUD bind lists, and version history. Reserve **19 -> 20**, because recovery work owns 18 -> 19; recheck actual head/schema before implementing. Add `DB/migrations/agent_runs_v19_to_v20_definition_wall_seconds.sql` following neighboring version SQL convention. Opening/reopening does not invoke recovery. `definition_from_row` uses `row.get('max_wall_seconds')` for pre-field fixtures; DB SELECT * conversion already carries the new column. Validate DB writes before transactions and validate numeric data at its model boundary, without creating a broad unrelated row-validation refactor.

## Fingerprints and compatibility

Keep the existing hash algorithm, JSON settings, field sorting, tool-list sorting, and 16 hex length. Build existing payload, then include `max_wall_seconds: float(value)` only when present. The omitted None key is the canonical absent encoding, intentionally preserving existing uncapped fingerprint bytes, including migrated rows and historical runs. Non-None 30 and 30.0 canonicalize identically. A cap change, cap addition, or removal changes the identity; names, descriptions, enabled remain excluded. Do not backfill agent_runs fingerprints. The fingerprint describes the current definition; the persisted run budget describes actual admitted policy (including a tighter ancestor/global bound).

## Admission and lifetime

Resolve named definitions only through the already frozen `_turn_definitions` / FirstRequestSchemaPlan path. Never re-read the DB within spawn or resume. Existing unknown-name and agent+allowed_tools refusals remain before slot consumption. First compute the existing branch budget: `clamp_child_budget` for `fleet is None or inline`, otherwise `contain_child_budget` with the existing global coercion. Then, only for a capped definition, `dataclasses.replace(child_budget, max_wall_seconds=min(child_budget.max_wall_seconds, resolved.max_wall_seconds))`. This post-helper minimum is essential: both existing helpers floor at 1s, which must not widen a smaller explicit cap.

The global child ceiling currently applies to threaded survivors; inline uses parent total/remainder with its historical 1s floor. Do not introduce the global ceiling into uncapped inline children or parent remainder into survivors. “All applicable bounds” means preserve that existing branch contract. A named cap only narrows the baseline each branch already admitted. Automatic-work ledger checks remain an independent elapsed-time authority: do not translate its deadline into a pausable tool clock, reset it on continuation, or remove approval/cancellation checks. The effective execution opportunity is the intersection of the per-run limit and automatic ledger authority.

The helpers currently rebuild RunBudget manually and already omit max_model_retries and budget_warning_fraction. Root reports a planned denial-limit field arriving concurrently. Implement the new cap adjustment using replace so it cannot drop any budget dimension. Preserve all RunBudget fields in the existing helpers using replace(child, max_wall_seconds=..., max_subagents=0) as part of enforcing the inheritance contract, with a regression test of all non-wall/non-spawn fields including the arriving denial limit. Recheck that field's actual name/default before code; do not invent its API.

## Continuation contract

Existing `_resume_retained_child` re-resolves instructions/tools/model from the current turn's frozen roster, checks vanished/disabled definition, and creates a fresh run. Keep that contract and fresh fingerprint. For a cap-controlled lineage, retain its **admitted per-run bound**, not the mutable definition cap and not elapsed remainder. A continuation gets fresh run time but cannot raise the inherited ceiling. Fresh explicit spawn is how a user starts a different lineage after raising/removing a definition cap.

Add optional `definition_wall_seconds: float | None = None` at the end of FleetHandle and RetainedTranscript. This is the admitted ceiling for a lineage that has encountered a definition cap, not simply the configured definition value. Generic children and lineages that never had a cap leave it None, preserving their existing behavior. Add keyword-only `definition_wall_seconds=None` to FleetCoordinator.reserve and copy it in `_retain_locked`; store it before a worker can finish. Extend local `_launch_fleet_child(..., isolation=None, *, definition_wall_seconds=None)` and pass to reserve. Do not put this coordinator-only argument into `_run_one` kwargs.

Fresh named capped spawn passes final child_budget.max_wall_seconds as lineage bound. Resume computes the normal current threaded budget, then minimum with the current frozen definition cap if any and retained.definition_wall_seconds if any. If either restriction exists, pass final budget maximum into the new handle; otherwise retain None. This handles cap removal, raising, lowering, and chains of continuations. A deleted/disabled definition still refuses. Existing retained fixtures lacking the new field default to None; no restart resurrection is introduced. The already persisted child `budget` JSON records the effective maximum without a second run-table field.

## Verification and limits

Real file-backed v19 database with live, disabled, and soft-deleted definitions upgrades to v20 retaining rows and NULLs, saves capped/uncapped records, reopens twice, and does not perform recovery. Also exercise guarded existing-column upgrade and standalone SQL migration once in order. Older-v15/draft migration assertions with hardcoded 18 need updating to actual current version without weakening preserved-column assertions.

Model cases: None; fractional positive; int/float equivalence; malformed types including bool, huge int, strings, nan, infinities, zero, negatives. Fingerprint test computes the pre-field JSON digest and proves exact uncapped compatibility. CRUD invalid update leaves previous full row unchanged.

Mounted canonical Settings cases: create/select/update/clear cap; malformed boolean/nonfinite/zero/negative input fails visibly with DB unchanged; New and each preset clear stale cap; no-DB behavior unchanged. Integrate with sibling Settings/preset edits instead of replacing their methods.

Real service/coordinator/SQLite gated runtime tests cover threaded and inline, generic and uncapped defaults, tighter/looser cap, subsecond cap, parent inline remainder, sibling isolation, and continuation cap lowering/raising/removal. Capture actual child budget from persisted rows and prove gated execution stops at runtime boundaries; recording a kwargs value alone is not runtime evidence. Frozen-roster test changes DB cap after schema planning and makes any further DB roster read raise.

Clock tests must preserve the actual distinction: `_effective_tool_timeout` intersects dispatch-time run remainder, `_call_with_timeout` pauses its execution deadline during `human_input_wait_active(run_id)`, but the run loop uses deps.clock elapsed time and automatic ledger includes human waits. A gate should show approval pauses only that child's tool deadline, sibling execution times out independently, release resumes the original remaining execution allowance, and the next run-loop boundary observes exhausted wall time. Separately show automatic deadline/explicit cancellation interrupts a paused capped child's wrapper while a blocked underlying worker continues to occupy its physical lease until finally released. Do not claim hard termination of Python workers or remote effects.
