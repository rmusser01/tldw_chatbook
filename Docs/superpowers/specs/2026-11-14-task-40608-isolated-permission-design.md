# TASK-40608: isolated stock permission persistence

Date: 2026-11-14
Status: Accepted for the scoped implementation and qualification below; production routing and the five-second requirement are not yet qualified.
Task: [TASK-40608](../../../backlog/tasks/task-40608%20-%20Investigate-slow-Windows-Console-workspace-chat-and-edits.md)
Decisions: [ADR-126](../../../backlog/decisions/126-complete-local-backup-and-recovery.md), [ADR-230](../../../backlog/decisions/230-console-send-preparation-and-io-ownership.md)
Plan: [Sub-five implementation](../plans/2026-11-13-task-40608-sub-five.md)

The scoped independent contract review resolved observation-time invalidation and per-command native retirement before implementation selection. This specification contains the reviewed corrected contract. Source-review approval supplies no native or latency evidence.

## Decision

Implement one private, contained, synchronous permission worker for an installed ordinary Windows permission path. Route the stock persistence surface through it, including mutations and malformed-input repair. Retain the original `MCPPermissionStore` object in the parent as the compatibility receiver and retain its existing resolved-path lock as the command admission/reservation fence. The child owns its own stock store, original native admission, complete command, physical retirement and persistence outcome. The parent owns the exact caller, source/config identity, service state, publication mirror and adoption of the result.

This is a deployable domain boundary, not a process pool, storage service, native rewrite or payload cache. The worker is private to its creating application process. It does not serialize independent application processes more strongly than today's process-local permission lock does. Native recovery admission remains the existing cross-process contract.

The next implementation slice must include the complete permission persistence adapter, publication/uncertainty mirroring, source-boundary rendezvous and maintenance teardown together. A production switch moving only `read_console_kill_switch` would leave the repair/write ordering problem unresolved. Implement and verify `get_kill_switch` and `set_kill_switch` first within that slice, but do not enable the route until the remaining stock persistence entry points use the same owner.

The mechanism isolates native calls from contention in the UI interpreter. The reviewed explicit worker now has command-level evidence: `t23compare2` recorded a .5898-second worker command with a busy parent and a 2.3639-second first call including construction/startup/handshake. Its stock arm exhausted the unchanged 60-second contender cap, so both rows remain invalid as a paired speedup comparison. The separately labeled `t23remaining1` completed the previously unrun idle/separate-process arms: all 12 samples settled and were usable, with worker calls .1451–.2139 seconds, stock calls .1240–.1591 seconds, first worker call 2.3280 seconds and shutdown .0934 seconds. This exposes startup and idle overhead; it supports integrating the complete surface, not a whole-journey performance claim. Child retirement enrollment counts are not equivalent to the separately profiled stock native API counts. Original Gate13 remains 77.9434/109.2945 seconds, and the sub-five-second journeys and final three pairs remain unqualified.

## Existing constraints that determine the design

* `MCP/permission_store.py:209` defines `_PermissionPathFence`: a resolved-path `RLock`, payload digest, opaque local token, pending bit and uncertainty bit. `begin()` invalidates before an effect; `complete()` does **not** publish a token; only a later positive observation does. These semantics must survive the process boundary.
* `Backup_Recovery/mcp_source_participants.py:83` returns a receipt containing real source/type/binding/config-module objects and the parent's `current_config_identity()`. None of those objects or their identity claims can be reconstructed by deserializing a child response.
* `permission_store._console_owned_load_current` is explicitly memory-only. `_permission_read_current` adds the original publication/helper definitions and source receipt. `_CapturedSources.require_current` is also a metadata/callback check. They can execute on the original parent worker while the child performs native IO.
* `raw_participants._permission_read_custody`, `_permission_read_boundary` and `_finish_permission_read` retain checks between entry, protected open, descriptor retirement and return. Repair switches back into ordinary checked raw writing. Moving only the outer call and checking the parent at its bookends loses those inner checks.
* `session_approval.apply_session_approval` holds `store.mutation_fence()` through strict-read validation and publication to `_session_approvals`. `UnifiedMCPControlPlaneService._captured_hub_test_profile_gate`, Tool Packs activation/binding/removal, and `UI/MCP_Modules/mcp_workbench.py` also use the fence outside individual store calls. Tool Packs binding deliberately holds it through a separate registry DB commit. A child-only mutex would break their ordering.
* `Agents/hooks_v2/mcp_executor.py::MCPHookPermission` captures the actual parent publication object and compares token identity, pending, uncertain and `_mcp_persistence_error`. Returning a boolean or child token is insufficient.
* Importing `config.py` calls `admit_startup()` at lines 4–6. `storage_admission._admit_startup` retains enrollment until process exit; `_LocalPause.retire_startup` requires an exact installed `RuntimeMaintenance`, so it is not an API that a lightweight child may casually call.

The living references are `Docs/Architecture/mcp-hub.md`, `backup-recovery.md`, ADR-126's explicit ordinary permission-read ownership amendment and ADR-230's finite IO/custody contract. The existing assessment's uncertain repair, startup hold and parent selected-boundary gaps are resolved below rather than deferred to a generic actor framework.

## Exact ownership and API surface

### Parent

Keep the original installed `MCPPermissionStore` receiver, `_BINDINGS` entry, source path, `_path_lock`, `_mutation_lock`, `_mcp_source_lock`, and `_permission_publication` object. Add a private weak association from eligible source/path to its broker; do not replace the class with a proxy subclass, because existing exact-class and captured-method checks depend on it.

The parent path lock remains the existing reentrant reservation fence. Every broker call holds it until the exact response is adopted or the uncertain outcome is latched. A caller already in `mutation_fence()` reenters on the same physical thread, so session approvals and Tool Packs retain their existing larger reservation. No remote lease or lock token is exposed to the caller. The child has a separate local lock; its single command loop never accepts a competing command during a parent reservation. This preserves current in-process ordering without moving the Tool Packs registry or session-grant memory to the child.

Keep pure resolvers, profile/persona composition, definitions, runtime decisions, approvals, session grants, provider/tool execution, local workspace authority and history/audit owners in the parent. `resolve_effective_state`, `resolve_builtin_state`, `resolve_effective_state_by_key`, `arg_rule_allows`, policy digests and ordinary result projections remain pure functions. Fresh reads at post-approval/final dispatch sites still happen; a detached result is not authority for a later invocation.

### Child

Own one stock `MCPPermissionStore` for the exact selected ordinary path, with its own installed binding, path fence, raw participants, canonical/member leases, pins/descriptors, temporary/backup files, payload parsing, schema/shape checks, profile CAS and persistence latch. Execute the actual stock bodies, not a second JSON implementation. A child-only execution marker prevents its wrapper from recursively invoking the broker; this marker is issued only by the fixed worker entry point and is not a general environment bypass.

The fixed protocol covers these existing public commands:

* Reads: `load`, `get_kill_switch`, `read_snapshot_strict`, `read_profile_inventory_snapshot`, `catalog_fingerprint`, `list_profiles`, `list_suggestion_dismissals`, `get_global_default`, `get_server_entry`, `get_tool_entry`, `has_current_tool_arg_rule`, `list_tool_arg_rules`.
* Mutations: `save`, `set_kill_switch`, `ensure_profile`, `set_global_default`, `set_server_default`, `set_tool_state`, `add_tool_arg_rule`, `remove_tool_arg_rule`, `mark_config_changed`, `dismiss_suggestion`, `restore_suggestion`, `clear_suggestion_dismissals`, `install_profile_if_absent`, `update_imported_profile`, `replace_profile_with_tombstone`.
* One internal captured `load` mode with `publish=False`, selected only by the existing captured Console reader.

Use a literal command-to-original-function table and explicit argument/result schemas. Do not use wire `getattr`, pickle, source text, import names or callback dispatch. Private `_load_locked`, `_save_locked`, `_mutate_locked`, `_mutate_profile_locked`, `_backup_corrupt_file` remain child implementation details for routed commands. The local closure used by `set_kill_switch` is created by the original child body; it never crosses IPC. Public unusual/custom argument protocols are selected onto the original compatibility route before serialization, rather than coerced into different semantics. The stock JSON-like inputs receive a detached copy; preserve existing optional/keyword defaults, typed mutation/snapshot errors, tuples and frozen snapshot reconstruction.

`save(payload)` has an additional observable contract: it stamps the caller's dictionary only after successful native retirement. Return the actual stamped value and apply it to that exact captured parent dictionary only on positive settlement, under the reservation; never mutate the caller's object on a failed or merely received child result.

### Compatibility and routing

Intercept eligible top-level calls in `mcp_source_participants.guarded` **before** creating a parent `raw.scope`. Add the corresponding explicit forwarding entry to unguarded public getters that otherwise delegate internally. Preserve method signatures and exact wrapper identity captures by updating their frozen qualification tables with the implementation, not monkeypatching at runtime.

Eligibility is exact stock type, original method/helper/parser/publication definitions, installed ordinary Windows binding, unchanged selected canonical path, supported argument values and a healthy broker. Initialization and lazy publication still use the existing parent `permission_owner`/service logic; charge their native/setup cost. After installation, ordinary permission commands execute in the child. Do not change all five MCP source kinds to remote sources.

Custom, uninstalled, non-Windows and recovery-selected sources use the original checked route. Their supported `mutation_fence()` continues sharing the parent lock, so they cannot overlap a child command for the same resolved path. A pre-selection decision may choose compatibility. A selected request that drifts, fails, loses transport or has uncertain retirement must refuse; it must not retry locally. Retire a previously healthy idle helper before changing its path/profile binding. Arbitrary injected custom code that ignores the existing fence does not gain a new serialization guarantee.

`_CapturedSources.read_permission_payload` gets an explicit broker branch preserving `publish=False` and the captured parent's receipt. Its fallback remains intact. `_CapturedSources.permission_call` has two actual uses: effective-state computation and config-change audit stamping (`console_snapshot.py:703`, `console_tool_preparation.py:382`). For an eligible remote permission source, replace its outer permission `raw.scope` with the parent reservation and boundary callback context; keep the Python callback in the parent. Each store call within it routes separately; audit/log writes remain under their own original owner and ordering. This avoids holding a parent permission native scope around the child or sending arbitrary callbacks.

## Source currentness at the real boundaries

Use a synchronous, ordered boundary rendezvous on the existing request's private pipes. The child parks at a named source-currentness check and sends `Check(request_id, ordinal, site, source_facts)`. The original issuing parent worker reads that frame and runs the locally captured checker on the real original receiver. It returns `Continue` or `Refuse` for precisely that ordinal. A result reader in a different thread cannot grant continuation or adopt the result.

The parent checker includes the current `_permission_read_current` predicates for read commands, the equivalent exact stock method/body/input captures for other commands, source receipt equality, the installed path/fence identity, producer/caller validity and any `_CapturedSources.require_current` callback. It must use the originally captured callbacks and their code/default/closure checks. A class/instance replacement after selection refuses; a matching path string never substitutes for the source object. Parent config generation is checked only in the parent, never compared numerically with the child's unrelated generation counter.

Install the rendezvous as a private registered command context in these concrete places:

1. Child entry after source installation and after command/path-lock acquisition, before metadata use.
2. `_permission_read_custody` at the existing source-current checks, including the preflight/metadata borrows and the protected-open path. The child still performs all its own local custody predicates.
3. `_source_custody_check` around source selection for ordinary mutation/repair paths, before `_check_parent_pins`; also the existing final live-state recheck. The callback is active only for the exact registered permission command, not other raw owners.
4. `_finish_permission_read` / final native source proof and the publication point. Repair obtains a new checked boundary after ending the read phase.
5. A final parent check after positive native retirement, before returning detached data or creating a local publication token.

The callback must not acquire a child lock or submit another permission request. It reads parent metadata only. Conversely, the parent must not rerun native `binding()`/`_selected()` walks as the rendezvous: those are child checks. `source_receipt`, `_console_owned_load_current` and `_CapturedSources.require_current` already provide the needed memory checks. Capture lexical selector/bootstrap/canonical path and relevant config source-selection fields; child independently reads configuration through its original admitted setup, derives the canonical/selected paths and verifies those facts. `profile_paths.user_data_dir` can probe the default-root fallback, so keep that native derivation in the child; preserve parent relevant config field identity/value checks rather than calling it repeatedly in the parent.

This is not a command-entry/command-exit sandwich: a source/config/callback change while the child waits for admission or performs a native observation is seen at the next original check, before the corresponding effect/publication. Every original source check has an explicit parent execution site, and native checks stay at their original child sites. A checkpoint is valid only for its current request and ordinal; it is not reused at the next site or after a repair/lock wait.

The guarantee remains sampled currentness at those boundaries. Neither existing code nor this protocol atomically freezes arbitrary Python monkeypatches or external filesystem writers through an OS syscall. IPC adds scheduling between the synchronous check and dependent native work; do not claim a linearizable global config transaction. Qualify changes deliberately injected while waiting for `Check`, during native IO and before final adoption. If implementation collapses these callbacks to three outer checks, it is not this design. Parent/child source observations must be checked again after a rendezvous wait before consuming earlier native evidence; no pre-wait native observation becomes the protected-effect proof.

## Narrow protocol and process lifetime

Use a fixed entry module, for example `MCP.permission_worker`, and one parent adapter/protocol module, `MCP.permission_process`. Reuse the scanner's direct base-interpreter launch and `STT.executor_process_tree.ExecutorProcessTree` containment. Launch hidden, `shell=False`, private stdin/stdout, bounded drained stderr, no listening socket and no workspace/config/payload bodies in argv. Do not copy the scanner's stop-immediately kill policy into a reset-capable permission operation.

Use length-prefixed, strict JSON frames with duplicate-key/NaN rejection, exact field sets and bounded lengths/nesting. The scanner's framing implementation is a pattern; do not accept its unrelated scan command schema or create a universal RPC library. Large valid payloads require bounded chunk frames and streaming reassembly, not silently truncating or adding an undocumented store-size limit. Results remain bounded by explicit protocol handling; impossible/unsupported serialization is a pre-issue compatibility decision when known, or a typed selected failure, never replay.

Request identity is a random broker epoch plus a random per-command ID and monotonic frame/check ordinal. The parent retains a local record containing the exact creator, issuing process/thread/task lineage, source capture, argument objects and pending result. The child cannot choose a new caller, publish into a different request, or reuse an old ID. This identity is correlation/custody, not a transferable native capability.

Frames are limited to `Initialize/Ready`, `Command`, `Check/Continue/Refuse`, `MutationBegin/Acknowledge`, `Observe/Acknowledge`, `Settled`, and `Shutdown/Drained`. `Settled` carries a typed success/refusal/error, detached value, checked scalar source facts, publication reconciliation and the command-local positive retirement receipt described below. No wire lease, handle, Python exception object or publication token exists. Exactly one command is active; waiting callers wait on the existing parent reservation rather than growing an unbounded child queue.

For every native persistence effect, including malformed-load `.bak`, the child calls the existing `permission_mutation` path and first requests `MutationBegin`. The parent invalidates the mirror under its existing path fence and acknowledges before the child effect may proceed. This prevents a hook memory check from accepting the previous publication while a child repair/write is in flight. A read-only unsuccessful command need not fabricate a mutation. A lost acknowledgement after invalidation is conservatively unresolved; a read command is not assumed effect-free.

At every actual stock `_PermissionPathFence.observe` site, including a public load inside a no-op mutator, an eligible observation sends `Observe(request_id, ordinal, digest)` and waits for the issuing parent's acknowledgement before returning from that site. A changed observation must invalidate the old parent token before any child continuation or retirement. This is necessary even when no disk mutation occurs: `MCPHookPermission.check_memory` reads the token without taking the parent reservation. The detailed unchanged/suppressed cases below are part of this handshake, not terminal event replay.

The child runs a synchronous finite command. It may block on bounded internal IPC rendezvous while retaining its own counted operation, just as it can block inside a finite native call; it never exports that operation or retains it across provider/human waits. The parent has no permission native lease across its async await. This new internal wait is explicitly covered by the ADR amendment and must revalidate native evidence after waking.

### Cancellation, errors and publication

Wrap the synchronous broker call with the existing `run_preparation_read`/`_owned_worker` where callers are async, retaining the actual physical future through repeated cancellation. Keep `service._producer_lifetime.operation()` around the full accepted call, and give direct store/broker calls their own producer count so a public caller outside the service is covered too. Do not interpret cancellation of the coroutine as cancellation of the disk effect.

The original issuing worker services check frames and settlement even when the UI awaiter is cancelled. It may update the persistence mirror to the actual known outcome, but no cancelled/stale UI creator receives a normal domain publication. The next operation cannot use the path until that physical command settles. A queued command cancelled before submission has no disk outcome and is removed without issuing an ID to the worker.

Normal success requires an explicit command-local positive retirement receipt after the stock wrapper exits and before successful `Settled`, caller stamping or parent pending-clear. Raw-scope exit and `_retire(state) == True` alone are insufficient: `_retire` closes leases without examining the resulting hold error, and `StorageLease.close` can leave a failed hold in `_retiring_holds` without raising. A plain returned Python value, zero raw-operation count or removed lease is not a settled response.

The fixed child command context retains the exact raw-state/operation objects, acquisitions (including canonical preparation), native descriptors/pins, leases and underlying hold objects as they are enrolled, before close can erase their registry membership or lease key. Register these through the existing acquisition/raw enrollment sites only while the exact permission-command context is active; do not infer ownership from aggregate count differences. At command entry, record the exact deliberately retained healthy startup lease and hold as the only permitted idle native baseline. The dispatcher retains the child source/path lock through stock execution, receipt validation and deferred completion.

After the stock wrapper exits, verify the receipt against those retained objects under the storage bookkeeping lock: all command acquisitions are unregistered; each command raw operation is absent from both raw registries and has no unresolved/uncertain state, file, descriptor, pin or companion guard; every command lease is removed from `_live_leases` and has released its reference. For each captured last-reference hold, require its thread to have joined, no remaining active/retiring registration, and the same permitted terminal outcome as the existing close owner (no error, or the existing benign `AdmissionCancelled` terminal classification). Any retained errored hold fails the receipt, including a close failure that did not raise. A hold shared with startup may remain live only as the same registered, healthy startup hold with exactly the expected startup-owned reference(s), no command references, no stop/error/retiring state and a live enrollment thread. Never require global emptiness for a healthy warm command. Unknown surviving ownership or a failed hold outside the permitted healthy baseline also refuses settlement rather than being silently excluded from the receipt.

For this registered child-command route only, defer `mcp_source_participants.complete(state)` effects: retain its exact pending payload/stamp updates and completion intent in the command context instead of stamping or clearing pending during the stock raw finalizer. After wrapper exit **and** positive receipt validation, apply those original completion effects once, under the retained child source lock, and emit the receipt-bearing terminal result. This narrowly gates IPC completion; it does not rewrite generic storage retirement or other callers' `complete`. If validation fails, withhold completion, return no success value or caller stamp, mark child and parent path publication uncertain, poison every registered same-path source, retain the exact unresolved command/hold records, and forbid replacement/replay. Retain any failed native ownership even if the raw wrapper already removed its normal raw-state registry entry. A later helper exit does not retroactively establish a successful command.

On dropped/truncated transport, worker death, protocol violation, timeout or failed native retirement: invalidate the parent token, latch path uncertainty and retain an explicit unresolved owner record. Do not launch a replacement to replay the command, retry via compatibility, or infer rollback from process exit. Killing a process can prove process containment but cannot prove whether its replace/fsync happened. Forced termination leaves the persistence outcome unresolved and normal maintenance capture unavailable until the existing explicit recovery path resolves it. Positively settled pre-effect refusals keep their existing categories; strict snapshot errors and best-effort getter policies remain distinct. Do not turn every application error into an uncertainty latch, nor turn an uncertain result into a missing-file default.

### Publication receipts

Keep child persistence publication authoritative and maintain the existing parent `_PermissionPathFence` as a conservative mirror for local consumers. Transfer the actual observation digest and its ordering, never its `object()` token. The digest is the existing `sha256(json.dumps(payload, sort_keys=True, allow_nan=False).encode('utf-8'))`, not the strict snapshot's raw-byte generation hash or the profile-policy digest. The original observer's pending/uncertain suppression is evaluated at the actual observation site: a suppressed observer produces no routine `Observe` transition. Otherwise the child waits for acknowledgement at that site before continuing, including before native retirement.

On `Observe`, the issuing parent validates the live request/epoch/ordinal and source capture, then compares the digest with its real shared fence under the existing reservation. If pending or uncertain is already set, it must not clear either bit or create/restore a token; a contradictory child/parent publication state refuses continuation. If the digest is unchanged and a valid token exists, retain that exact token. If the digest changed, clear the obsolete token before acknowledgement, record the new digest and a command-local candidate observation, and withhold a fresh usable token until positive command settlement. If the digest is unchanged but no token exists, it stays unavailable until a valid positive settlement permits creation. Do not set the mutation `pending` bit merely to represent an observation candidate. A later `MutationBegin` clears any candidate observation as well as the mirror token/digest. Thus a changed observation followed by a no-op mutator still invalidates the old hook receipt immediately, whereas an unchanged observation preserves its identity.

At successful `Settled`, require the command-local retirement receipt, current source, matching last acknowledged publication ordinal and exact final state. Only then may the creator issue a **parent-local** token for an unsuppressed candidate observation that remains current and has not been followed by mutation, uncertainty or another incompatible transition. Validate the digest against a returned payload when available; the scalar getter returns the child-calculated digest from the same payload as its scalar. Terminal event history reconciles already acknowledged transitions; it is never the first invalidation of a known-obsolete receipt. Delayed/duplicate events cannot clear pending/uncertain or resurrect an earlier token.

`publish=False` emits no routine observation or token transition. It still sends mutation invalidation and uncertainty for repair. A successful mutation clears pending only after the positive command-local retirement receipt and leaves token/observed unset until a subsequent positive read; an observation made before `MutationBegin` cannot republish it. A later failure, including non-raising native hold retirement failure, poisons both sides. Parent `_mcp_persistence_error` and the path mirror must cover every registered same-path source, not just the instance making the call.

Return scalar canonical/selected path, selector/bootstrap facts, worker epoch and operation outcome as comparison metadata. Keep the real parent `source_receipt` locally and return that exact checked receipt to captured Console consumers; do not synthesize a receipt using child source IDs. Strict snapshot `generation`, `file_exists`, profile revisions, CAS errors and mutation results retain their original meanings. Hook `MCPHookPermission.refresh/check_memory` continues observing the same parent fence object; only the origin of its ordered updates changes.

### Startup, idle and maintenance

The smallest safe resident helper retains its normal startup enrollment while idle, exactly as `config.py` requires. It retains **no command scope, payload descriptor, member lease or permission verdict** while idle. This startup lease is visible native enrollment and can obstruct exclusive maintenance; that fact must not be hidden by a zero-command count.

Integrate the broker as an exact installed maintenance participant after upstream MCP/UI/Tool Packs producers settle and before the parent's local pause/native drain. Close new broker intake, finish accepted requests/reservations, request graceful worker shutdown, then require the child to retire its startup lease through its normal shutdown path, positively finish the process and close pipes/monitor. `RuntimeMaintenance` owner census must include this broker even if it was created by a direct store call. The unified service hooks alone are insufficient. Do not call `_shutdown()` behind a live idle worker or fake `RuntimeMaintenance` to invoke `retire_startup`.

Maintenance resume starts a fresh worker lazily, after parent admission has reopened; no automatic replay or payload retention occurs. Healthy explicit close also exits the helper. Profile change retires the old helper before a new one is admitted. External maintenance remains blocked by an enrolled running app/helper until normal close or the existing app-coordinated capture flow; this design promises no new remote pause service. A worker that cannot retire positively causes drain to fail honestly.

Make the terminating handshake explicit rather than trusting an exit code or `atexit`: after permanently closing its command loop, the child invokes the existing startup shutdown/lease-close path, verifies no pending acquisitions, raw operations, live leases, holds or `_retiring_holds` remain, then sends `Drained` and exits. `StorageLease.close` joins the retiring thread but can retain an errored hold without raising (`storage_admission.py:779–802`); the empty-retiring-holds check is essential. A failed check sends no successful `Drained`. This is final process teardown, never an API for dropping startup enrollment and continuing to serve requests.

## Two complete traces

### Public `get_kill_switch`

1. `UnifiedMCPControlPlaneService.get_kill_switch` (`unified_control_plane_service.py:5785`) obtains the actual store; its original guarded `get_kill_switch` entry selects the broker before parent raw acquisition. Capture the exact source/read entry and acquire the existing path reservation. Initialize/admit the contained child if necessary; include that elapsed cost.
2. Send fixed `get_kill_switch`, `publish=True`, expected source facts and request ID. The child verifies its independently installed ordinary source and calls the stock read entry/`_run_permission_read`, with its own captured `_PermissionReadEntry` and local lock. Parent memory check rendezvous occurs at each named source boundary.
3. Child raw scope acquires canonical/member leases and preflight identities; original entry, protected payload-open and final activation/control/registry/parent/destination proofs run. Original parser rejects duplicate keys/non-finite constants, preserves missing/default distinctions and normalizes only the existing allowed shapes. Corruption ends the read phase, sends `MutationBegin` to invalidate the parent mirror, runs original backup/replace/fsync, then obtains the fresh final proof.
4. At the actual `observe` site, only in `publish=True` mode and when unsuppressed, the child sends the digest and waits for parent acknowledgement. A changed digest invalidates the old parent token now; an unchanged digest preserves it. The child projects the boolean from that same payload, exits the stock wrapper, validates the command-local positive retirement receipt (including captured lease/hold outcomes) and applies deferred completion. It emits receipt-bearing `Settled` with the scalar and acknowledged publication state. The parent checks its original source again and may create a fresh local token for the still-current observation candidate before returning the boolean. Any late drift refuses the return; any actual effect/uncertain outcome stays recorded.
5. The captured Console variant sends `load/publish=False`, receives detached payload, preserves the original parent receipt and projects the compose-time switch in `read_console_kill_switch`. It does not accidentally publish a digest merely because the worker supports public reads.

### `set_kill_switch(True)`

1. The exact public method is selected before parent native scope, under the same parent path reservation used by reads and all same-path stores. The child receives the fixed boolean command; the original child method constructs its local `change` closure and enters `_mutate_locked`/`mutation_fence`.
2. Original `load` observes current disk state under that lock. It may itself repair corruption using the preceding protocol. Its unsuppressed observation must be acknowledged at the original observation site: changed policy invalidates an old parent token even if the requested boolean already matches and the mutator makes no write. An unchanged observation retains its token. Preserve no-op behavior without fabricating `MutationBegin` for an effect that never begins.
3. If changed, `_save_locked` runs `require_store_write`, obtains fresh ordinary source/custody checks, and calls `permission_mutation`. Parent invalidation acknowledgement precedes effect. Original `write_json` uses the admitted `.tmp`, native file/ACL/nofollow checks, descriptor close, destination-identity check, checked replace, directory durability and cleanup. Parent callbacks are serviced at the mutation's original source boundaries. Profile mutators use the same command mechanism while retaining their current generation/revision/digest checks.
4. Raw wrapper exit alone does not clear pending or authorize success: the child-command route has deferred `complete`. Validate the exact command-local retirement receipt, including non-raising lease/hold close outcomes and the healthy startup baseline, before applying completion or emitting successful `Settled`. Parent mirror remains tokenless until a later positive read. A retained failed hold poisons both sides, withholds the parent caller stamp and success result, retains unresolved ownership and makes maintenance refuse. Cancellation still settles this exact mutation; lost transport leaves an uncertain mutation and is not replayed. Session approvals, workspace registry commits and audit history have not moved, and retain their parent reservation and existing ordering.

## Concrete implementation changes

1. **New `MCP/permission_process.py` and `MCP/permission_worker.py`:** fixed frame schemas/command table, exact broker registry, contained launch, currentness rendezvous, ordered publication deltas and physical process drain. Keep these permission-specific. Use existing `ExecutorProcessTree`, `_PopenProcessAdapter`, `ProducerLifetime` and preparation future custody rather than inventing another scheduler.
2. **`MCP/permission_store.py` and `Backup_Recovery/mcp_source_participants.py`:** early stock routing, explicit command definition captures, parent mirror adoption, original body execution in child, before-effect invalidation handshake in `permission_mutation`, and acknowledged observation transitions at the actual `_PermissionPathFence.observe` site. Suppress routine transitions exactly where the original observer suppresses them. Defer `complete` effects only for the registered child command until its positive retirement receipt. Preserve signatures, public/custom branch, original validators and caller payload stamping. Qualification must include helpers actually used by mutators, not merely the current read-only helper table.

## Free-threaded runtime alternative

A free-threaded interpreter would be fewer product edits if the entire selected dependency stack and application concurrency contract were already qualified for it. They are not established here. The root agent's installed-runtime inspection found Python 3.13.3 with `Py_GIL_DISABLED=0` and the GIL enabled; this source task did not run a different interpreter. Merely selecting that executable therefore does not remove the measured contention. A free-threaded build additionally requires checking actual GIL state after loading native extensions, selected dependency availability, context propagation, and source/publication ownership under concurrent Python mutation. Existing metadata checks rely on exact object relationships and multi-step observations, so absence of a GIL cannot be treated as a transparent performance flag.

Python's [free-threading guidance](https://docs.python.org/3/howto/free-threading-python.html) documents automatic GIL re-enablement by unsupported extensions and different default thread-context inheritance. These are runtime qualification requirements, not evidence that this application's current dependencies are incompatible.

That alternative has a broader qualification surface than the permission-only worker and is not presently a smaller **viable** replacement. Do not install or migrate the runtime as part of this slice. If independently pursued, its first check is the actual installed extension set with the GIL still disabled, followed by existing ownership/refusal controls and unchanged journeys; it is not evidence supplied by a `--disable-gil` build label alone.
