## Actual RawCLI frame and lifetime

`ChatScreen._send_console_message_from_visible_action_observed` takes the original pending-send stash (non-destructive capture), validates visible/origin session, then calls `raw_cli.prepare_visible_send` before normal received/mounted dispatch. For a captured trusted raw stash that helper calls `commit_captured` BEFORE `start_user_command`; for a mouse/workbench live draft it calls destructive `stash_raw_cli_draft_for_send` BEFORE start. Thus guarding only `NativeRawCliSource.capture` is too late to meet the no-transfer boundary. Initial proposal (superseded by the raw-only amendment below): the UI frame would enter the metadata scope before this helper and leave after it returns; an elected-save refusal at scope entry gives the original visible warning and returns without committing/stashing the draft. Removing the pending-send token alone does not remove the composer's original draft.

`ConsoleRawCliController.start_user_command` classifies trusted provenance, validates permitted/armed/session, then calls native `capture`, chooses original leaf/root/scratch, validates the actual request, and enqueues the existing nonexclusive worker. Native capture constructs `_UserRawCliCall` (including generation/app/store/storage source), activates original storage, acquires its one OPAQUE claim/owner/tool operation, and publishes that exact call into its original issuer.pending under the runtime capacity lock. Publication currently neither fences construction nor counts pending. A separately guarded source.capture is required for non-UI direct callers.

The existing `_execute` starts the original call, retains activation across actual `_execute_command`, terminal persistence/readback and synchronous host deliveries, then calls `finish_operation` before activation exits. `finish_operation` waits for original required/physical/host proof and the actual `operation.finish()` RETURN; unknown proof retains original worker/scopes. `finish` runs after activation/DB unwind, returns scratch, calls original owner.finish_root and claim.settle, removes original pending and sets retired. Unstarted/refused paths use the same finish path; drain calls cancel_unstarted and waits exact retired events. No new cleanup framework is needed.

## Proposed smallest complete change

Ruling proposed: WHAT — reuse the existing `_first_send_source_scope` before visible raw draft transfer and inside original native capture, then transfer one metadata count into the existing original pending membership under the SAME `_execution_capacity_lock`. Release that count only when the original pending member retires after actual physical/required/host/operation-finish/storage/scratch/root/claim return, then wake the SAME pending save. WHY — direct commands otherwise capture during an elected save or remain uncounted after capture, so self-generated config publication can discard original output/terminal callbacks. COST — no new owner, claim, carrier, registry, poller, journal or generation exemption; an admitted command delays the same save and a new synchronous attempt briefly refuses before input transfer.

Exact handoff: `with runtime._first_send_source_scope()` spans `_UserRawCliCall` construction through capture's actual return. At successful `issuer.pending.add(call)`, increment runtime._first_send_sources inside that same bookkeeping lock, before the attempt scope exits. The pending membership itself owns this second count; no new field/token reconstructs authority. At native `finish`, only if this exact original call remains in its original issuer.pending, remove it and decrement inside the same lock after existing finish/cleanup. The existing settling latch makes release once-only. Wake outside lock after retired publication. Election already requires this counter zero, so it cannot accidentally trust a replaced runtime source pointer/new empty pending set; a lost original pending member conservatively leaves its count held. No IO/callback under bookkeeping lock. Source/permission/config-generation/DB/scratch/root/host checks remain unchanged. Model/Task7 RawCLI continues its original borrowed operation/tree path with no new count/claim/owner.

## Bounded connected-source disposition: native Undo

`NativeUndoIssuer` is the other directly connected runtime-owned generation-sensitive source outside ordinary trees. `capture_undo` constructs `_UndoConfirmation` before its original metadata/preflight/confirmation flow; `_UndoConfirmation._admit` runs the existing preparation-owned worker and `_UndoCall.admit` adds the exact call to issuer.pending under the same runtime lock. Native `retire` executes after required/host/operation finish and storage/scratch unwind, then original root/claim, removes pending and sets retired. Therefore the same omission is real source structure, not a hypothetical name match.

Apply the SAME finite protocol there: a synchronous source gate before `_UndoConfirmation` construction, an async gate around `_admit` before its preparation worker (waiting before taking its own metadata count), and a metadata count owned by the exact existing pending membership until original `retire`, with the same wakeup. The modal confirmation object itself is unadmitted metadata: gaps between preflight and a later user's confirmation are not accepted execution. If publication occurs in such a gap, its existing original-source checks refuse confirmation/apply before effects; no current-source adoption or new long-lived modal owner is introduced. The initial capture/read checks remain strict. No additional arbitrary source catalog is proposed. SSH model calls use current ordinary tree/operation source rather than a separate user pending source; the already-reviewed ordinary capture/tree protocol covers those.
