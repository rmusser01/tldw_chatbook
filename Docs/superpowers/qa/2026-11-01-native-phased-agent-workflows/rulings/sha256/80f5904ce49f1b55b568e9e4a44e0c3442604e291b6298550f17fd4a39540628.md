## Proposed correction, awaiting root ruling

Reuse existing `Backup_Recovery.participants.run_finite_local_worker` at this exact original finite retention callback boundary. Import that helper inside `_perform_sync_log_retention`. Change only the to_thread submission to `await asyncio.to_thread(run_finite_local_worker, db.delete_sync_log_entries_older_than, cutoff)`.

The existing helper records already-held caches on its original worker, runs the exact callback, and uses original owner close APIs in its finally for newly acquired installed file-backed caches after that callback's real return. It preserves custom/in-memory owners, preexisting/foreign handles, active operations, live transactions and uncertain native closes. Cancellation of the awaiting async task leaves the original worker alive through callback and cleanup. The retention query, cutoff, configured disabled path, error policy, timer schedule, DB schema and default-executor lifecycle keep their existing behavior. Ordinary retention callers gain the same finite cache ownership already used by native Library workers. No new framework, permission/storage owner or global drain is introduced.
