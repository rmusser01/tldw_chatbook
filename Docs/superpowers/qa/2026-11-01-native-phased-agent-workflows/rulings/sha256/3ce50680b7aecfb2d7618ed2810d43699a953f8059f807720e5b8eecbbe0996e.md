## Actual API and lifetime

- `ConsoleRuntime.__init__` creates the sticky `NativePluginHookPreparation` metadata attachment only under the existing `console_workflow_runs.native_workflow_qualified()` predicate. Construction performs no config/DB/capacity read. `capture_hook_preparation_source()` pins already-created original capacity/activity references before external preparation reads.
- `prepare_submission_hooks()` binds the **original issuing Task, controller, session, configuration and exact ConsoleSubmissionOrigin enum** through `submission_origin(...)`. A caller's `initiator="manual"`, session/run ID, or absence of automatic context cannot mint manual capacity. Unbound direct preparation defaults automatic; an actual admitted matching native parent can supply origin. Covering-tree borrowing remains a later obligation.
- `NativePluginHookPreparation.capture(source, service, configuration, review)` creates one retained existing `ConsolePreparationRead` record, observed by original runtime and controller, then performs finite native admission off the host loop. It returns the **actual NativeHooks result and its finite request** to the existing host. No fake hook event, Chat, AgentRun, model request or coordinator slot is allocated.
- `_Preparation.admit()` checks the original published permission/config and source before reserving one OPAQUE worktree claim, one genuine non-child execution owner and one tool operation. It repeats source checks after reservation and before publication. Admission and release callbacks use the existing default executor; no new executor, queue, worker manager, retry journal or poller exists.
- `PluginService.hook_configuration(maximum)` still calls original `component_snapshots` → `admit` → `_checked` → `NativeHooks`. The native preparation ContextVar reaches its original `_call` / `_invoke` through `run_coroutine_threadsafe`. `_call` checks source before start, after readiness, and with pure published checks under its existing publication lock; `_invoke` checks before invoking the actual callback. No admission/schema/permission decision is synthesized from a ceiling.
- Source custody retains the original Runtime/app/controller/store/session/permissions and activation inputs, original skill/local/service instances, callback, maximum reference and detached normalized value, published snapshot map and selected snapshot references, worker thread/loop/readiness/coordinator/admission/fences/root/workspace lookup, and coordinator owner/registry/authority. Live published revisions/generations and revocation fences are checked without filesystem/SQLite reads under bookkeeping locks.
- `_Preparation.join()` shields and joins the **original concurrent service Future**. Repeated cancellation of either issuing Task or retained invoke Task cannot cancel that underlying job and stand in for callback return. Cancellation seals the request, marks its operation stopping and prevents later `_call` admission. Existing service return/exception is consumed before cancellation is re-delivered.
- The `prepare_hooks_v2()` AsyncExitStack extends this same request through the actual host block: signature/absence decision, awaited original host context read, configuration replacement, final source check and actual `engine.native_plugins = native` installation (or existing-engine discard). It closes **before lifecycle creation/SessionStart execution**. A source check immediately after `await hook_configuration` alone is not acceptance. No extra tool operation is charged for this host interval.
- The context's finally joins original `OwnedOperation.finish()` return before settling the activity claim/root and retiring the original read record. Tool count reaching zero is not callback retirement. Failed release retains the claim rather than inventing success. This finite request's completion does not terminate the service's long-lived storage thread.
- Existing runtime/session admission fences and `_disposed` state seal preparation before capacity close. Existing `drain_preparation_reads` waits the original issuing request and release callback through repeated cancellation before original storage disposal. No additional SessionEnd behavior is introduced here.
- No eligible plugin-owned rows (including installed-but-disabled rows) leaves native capacity/activity cold. Unqualified ordinary preparation retains its previous PluginService path. Standalone PluginService `_call` / `_invoke` with no native context keeps its original behavior.
