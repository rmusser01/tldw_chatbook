### Important

**I1 — A saved PREPARED command skips fresh validation and can mint a new capability.**

Location: `tldw_chatbook/Chat/console_workflow_runs.py:585–609`, especially `:590`; connected receivers `tldw_chatbook/DB/automatic_work.py:2172–2197`, `:1901–1957`, and `console_workflow_runs.py:405–447`.

The read calls `validate_remaining_decision` only when no command row exists. An existing row is not necessarily an inert accepted duplicate: `_prepare_workflow` can have committed the decision/attempt and then the original invocation can fail at `current()` before acceptance. The passive preparation API can also create that state; the new test explicitly does so at `Tests/Agents/test_workflow_partial_attempts.py:114–128`.

On a later call with that command and identical saved decision, `_prepare_workflow` only compares the recorded identities/payload and returns the PREPARED attempt. The new read cell then satisfies `_accept_workflow_phase`'s physical receiver, and `_accept_attempt` changes PREPARED to ACCEPTED and consumes the generation. None of those receivers recomputes the input manifest, retained sibling freshness, native check evidence or complete decision digest on this branch. Changing a retained sibling output or a remaining-task input between preparation and retry therefore does not stop acceptance. Independent remaining tasks can proceed with their newly collected inputs despite approval being tied to the old evidence; eventual quality failure is too late to supply the missing pre-execution decision.

This is distinct from the tested already-ACCEPTED duplicate, for which `_accept_attempt` returns False and no capability is issued. The direct-ID negative at `test_workflow_partial_attempts.py:127` does not exercise this owned-reader retry.

Fix the duplicate branch according to its actual native state. An already accepted/settled exact duplicate may remain lookup-only. A saved PREPARED attempt must either refuse capability creation or undergo a fresh, exact validation that handles its already-advanced control revision without treating stored evidence as current. Keep command identity and all existing charges. Add a focused native control that prepares but does not accept, changes retained/current evidence, and retries the same command through `_accept_remaining_workflow_phase`; it must issue no capability or new charge. Source-proven finding; no new dynamic reproduction was run during review.

**I2 — Context exit is mistaken for actual native storage retirement in the new acceptance read.**

The native `SQLiteStoreKernel.close` explicitly returns normally when close is disallowed or `conn.close()` raises, retaining the cached connection. Both AgentRunsDB and WorkspaceDB use this kernel. The new review reads those databases through its real service and binding guard.

Preserve borrowed handles, and retain the exact owner/claim/cell on failed or unknown return. Reuse the existing narrow handle-return pattern; do not change the global native close contract or introduce a cleanup reaper. The source path is conclusive; the earlier wave fault receipt is precedent for the close contract, not an executed E reproduction.
