# Root ruling — original cleanup may charge after revocation or budget exhaustion

Ruling: the proposed private cleanup-only accounting branch in the SAME native resume receiver follows `root-i2-accounting-ruling.md`, with the constraints below. It may bypass current dispatch revision and execution-budget admission only for charging necessary cleanup of resources already owned by the original invocation. It grants no permission to start new work. The pre-revocation Stop transaction alone is not sufficient for Pause, shutdown and other original close paths, so that narrower alternative does not cover the required contract.

Root read the complete concrete consumer/context appendix, `resume_workflow_phase`, `_resume_workflow_dispatch` and `_start_automatic`. For a workflow, the latter only ensures an existing active-time interval is open; it does not reset the chain deadline or replenish resource counters. Reuse that workflow-specific branch rather than creating another ledger or execution owner.

Required boundaries:

- Before ordinary B/capture, finite preparation, provider/tool/child work resumes, retain all normal current owner, control revision, budget, source, binding and dispatch/admission checks. An existing original phase context may supply the accounting receiver before a child dispatch exists, but it cannot supply permission to bypass those work gates. Do not classify preparation or capture as cleanup to avoid a refusal.
- The cleanup branch must require the exact original phase/preparation that already owns the cleanup, the same positive original wait/interval record, the current runtime owner, and the definition-time original native close/terminal caller and receiving source. A flag, workflow ID, supplied owner ID, copied record or ordinary caller context alone is insufficient. It does not accept a reconstructed phase or grant authority to a new cleanup owner.
- Within the original FULL off-loop transaction, it may open the existing workflow interval and make the retirement transition appropriate to that newly active original cleanup. Preserve all prior interval charges. Do not clear actual unknown cleanup/source/error, chain review-required state, uncertain reservations, recovery or unrelated phase uncertainty. No workflow/control status change, new reservation, counter/limit change, MODEL/tool/child launch, fresh acceptance or returned launch capability. A later COMMIT/wrapper failure retains the original source/cell; an opened interval continues charging and must not be put back to idle.
- The positive record proves the previous closed interval; it must cease granting an *idle* disposition when cleanup begins. The consuming original read and its actual return remain tracked. Only genuine final original cleanup/settlement may retire the retained resources. Reopening accounting is not physical drain evidence.
- If clock/ledger/source proof is absent or the bookkeeping write fails, keep unknown accounting/refused new admission; never invent exact time or claim successful release. Do not make existing necessary physical cancellation/reap/close contingent on a successful accounting write: continue only the cleanup already authorized by its own original native custody where that contract permits, retain the error and all unproven custody, and never manufacture a new cleanup path or capability. Cleanup and proof of successful retirement remain separate obligations.

This is a narrow exception for negative bookkeeping after Stop/revocation or budget exhaustion, not an exception to permissions or native source identity. An expired allowance must stop new work while the already-owned work can be cleaned up and remains charged. Other normal/direct native resume paths retain their established contract.

Cost if wrong: reusing the cleanup branch for preparation/dispatch could evade a stopped revision or exhausted allowance; improper clearing could hide uncertainty. The implementation adds one guarded private branch and must preserve error/cleanup ordering. Cover expired-budget and revoked-Stop cleanup, no new reservations/counts/status/launch, direct misuse refusal, positive return versus late wrapper failure, continuing charges while cleanup is held, and no false clean restart. Source/gate inventory plus ADR285/spec/plan/task amendment/readback precede behavior; independent scoped review must inspect the complete receiving chain.
