## Why the callback boundary cannot be waived

`OwnedOperation.finish` (`Agents/execution_capacity.py:375–382`) prunes under the original capacity lock, invokes every owner drain callback, THEN notifies tool availability. Native callbacks include activity `record_drain` (`Workspaces/worktree_activity.py:301–316,360–398`), ordinary tree `_drained` (`console_ordinary_tree.py:576,603–627,657`), and, where agent worktree ownership exists, required original DB `persist_actual_drain` (`Agents/agent_service.py:4866–4891`). Dropping activation around all callbacks would also drop the original journal's operation-owned DB context.

The ordinary source scope postpones scratch settlement until its finally (`console_ordinary_tree.py:588–601`); `_retire_scratch` then releases the lease and settles all members before `retired.set_result` (`:608–631`). This finally currently runs INSIDE the outer execution/DB activation stack (`console_agent_sources.py:216–234`). Both activity retirement (`worktree_activity.py:389–412`) and tool availability (`execution_capacity.py:119–128`) invoke subscribers. Native ChangeReview subscribers (`Workspaces/change_review_finalization.py:331–338`) enqueue retry through `:793–806`; its existing publisher can subsequently admit and queue discover/baseline/finalize E at `:808–849`. Therefore callbacks are not a closed readback/journal-only set. The native subscriber queues work; it is not itself a synchronous Git call. A generic callback API also cannot be presumed permanently closed to other subscribers.
