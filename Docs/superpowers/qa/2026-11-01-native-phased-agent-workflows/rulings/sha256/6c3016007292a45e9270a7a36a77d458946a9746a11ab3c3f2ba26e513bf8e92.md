## Process, mutation and completion map

`preflight_revert` reads original changed_files/file_bytes and actual disk state. `revert_paths` uses historical checkout for M/D/R, baseline-guarded unlink/rmdir for A and rename destinations, and original post-revert snapshot. `ShadowRepoService.repo_for_root` and `ShadowRepo._run` validate the original Undo root; `_run_process` hands every actual Undo subprocess to existing `run_native_git` with the same original owner/operation, exact historical argv/env/stdin/text behavior. It does not invoke D1 `qualified_git_command`, refuse checkout/filters or create a snapshot ticket. Actual diff/show/checkout and post-snapshot init/config/index/add/rm/diff/commit/rev-parse commands and their managed descendants use that existing transport. D1 qualification remains separate and was covered by the affected selection.

The unchanged transport joins communication, managed process tree and handle return, retaining original worker scopes after timeout/TERM/KILL until actual late proof. Cancellation/UI pop is not cleanup. Its managed-group boundary is not a security sandbox against escaped host processes. Historical smudge probes really transform baseline bytes to FILTERED; the timeout control deliberately makes stop requests ineffective so the original helper must return after release.

Native `attempted` is set before any mutating entry. Even a checkout that writes and then raises requires the original post-snapshot when every path fails. Successful paths alone update the existing reverted history. An actual snapshot SHA return proves snapshot completion; an exception has no arbitrary-HEAD/retry proof. DB update returning None or throwing does not settle: `observe_reverted` reads the exact original joined row, requires all original fields and the exact expected reverted-path union. This proves a committed-then-raised update but refuses rollback/missing/mismatched outcomes. Standalone behavior/three-argument RevertOutcome construction and successful-path bookkeeping remain compatible; `settled=True` is an additive field. Native exceptions preserve per-path failure and snapshot obligation, without changing standalone exception behavior.

Unknown required outcome delivers honest partial UI results (`settled=False`, never fully Undone), then retains the same worker/source/storage/OPAQUE indefinitely. Subsequent rows cannot overwrite that unresolved state. There is no journal, replay, repair producer, arbitrary HEAD success inference or new poller. This deliberate limitation can block app disposal and later native work indefinitely.

`_UndoCall.run_entered` owns original activation/DB connections/shadow storage/scratch through synchronous original host callback RETURN and actual operation.finish RETURN, then closes scopes and retires root/claim. The host receives its originally captured context, because Textual copies ContextVars; native Undo authority also checks exact worker thread. Original screen-stack/provider/card/token checks establish acceptance or conclusive stale presentation discard. Already-started declared obligations may finish through disposal while every other original identity remains strict. New admission/confirmation remains sealed.

A proven activation-entry failure is distinct from callback failure: only after every partially entered scope closes normally, before any original effect callback, may the same thread finish and retire unused metadata. This also covers sealed/unstarted finalization whose activation cannot enter. A callback-body failure, uncertain unwind or missing finish return never takes that branch. Exact entry fault tests demonstrate original refusal, no disk effects, retirement and later independently confirmed success. Snapshot/DB after-entry negative tests demonstrate retention.
