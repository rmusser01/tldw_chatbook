## Actual implementation and consumers

- `ConsoleRuntime.ensure_run_hooks()` attaches `_NativeLegacyHookSource` to the original engine, retaining original runtime/app/permissions/callback references and already-existing capacity/activity without lazy resource acquisition. Attachment is sticky: source loss cannot become standalone execution.
- Each actual selected event captures original store/controller/session incarnation, binding/ephemeral/workspace identity, persistence/database, activation sources, targets and trusted origin before external dispatch. Genuine no-Chat events use empty metadata and create neither Chat nor AgentRun. Config/grant/path authority still comes from the original HookPermissions matching and launch guard. Pure reference/state checks repeat under the existing engine enqueue lock; external callbacks and native acquisition stay outside it.
- `RunHooksEngine._fire` and `notify` admit one complete `WorktreeFootprint(opaque=True)` claim and one genuine non-child `ExecutionOwner`. Each actual selected target reserves its own `OwnedOperation` before the existing blocking/notification enqueue. The notification coordinator has no extra tool charge. No model, child slot, separate queue, executor, poller, budget ledger or permission store is added.
- Each actual target re-enters captured activation and the original native owner inside its existing worker. `_capture_hook` marks process attempt, observes the original transport's independent `process_exited` plus return code, and requires original managed process-group absence. Pipe EOF/connection_lost, timeout, parsed result and bounded reap alone do not prove drain. The original bounded cleanup deadline is shared rather than starting another reap window. Process-group evidence failure marks the same native operation stopping and owner cleanup-unproven; PreToolUse refuses. A known pre-spawn failure can prove never-started. Native Windows commands refuse before spawn because this slice has no qualified Windows group evidence; standalone behavior remains unchanged.
- `_EventCustody` joins each actual callback and each original operation-release return with original host return before finishing its root/claim. Parallel targets share one event; first denial may return while sibling targets retain their own operations. Successfully cancelled queued futures unwind only never-started holds. Unknown physical cleanup retains the original operation/opaque protection; no new reaper invents later success.
- Notification lifetime includes the **original `_notification_done` callback's return**, including conclusive queue discard. `UserPromptSubmit` lifetime belongs to the actual submit scope. Empty/no-outcome completion is conclusive there; block/context outcomes remain owned through their original SYSTEM append. Manual source is issued from the original controller submission context; raw event strings do not select manual origin.
- Durable prompt context transfers the same pending handoff into the actual `_DurablePostcommitContinuation`. Deferral is set only after the original continuation registry publishes it. Construction failure therefore leaves the actual submit scope responsible for discard. Successful handoff occurs only after the existing `durable_owner_publication` effect (including original hook-context publication) returns. An existing recoverable failed optional audit publication keeps the same continuation/event for retry. Explicit discard and original continuation retirement close it; retirement schedules completion on the original loop outside the store lock. No hook payload is persisted universally.
- Applicable actual native commit failure calls `prompt_handed_off(required_write_ok=False)` and retains the event's opaque root. Known `ContinuationAdmissionRefused` transactional rollback keeps its existing conclusive discard path. Ordinary events declare `required_writes=()`; this is the absence of a new payload, **not** fabricated durable-write success. Worktree settlement docstrings qualify the existing `durable` flag without changing the ledger behavior or workflow durability.
- Runtime close seals original legacy ingress outside its bookkeeping lock, closes capacity under existing sequencing, permanently retires original never-resumable postcommit continuations, and retains one cancellation-safe drain of the original source before storage disposal. The final exceptional teardown path first drains native commits and retires continuations, then joins legacy custody. Repeated cancellation cannot detach actual callback/host cleanup. Unknown cleanup/failed required writes are reported and retained instead of hanging forever for nonexistent positive evidence.
