## Delivered contracts

`Agents/workflow_task_scope.py::_prepare_workflow_task(phase, *, task_id, registry, binding)` requires the original private `WorkflowPhaseAuthorization` and reciprocal live ConsoleRuntime/controller/bridge. It retrieves the saved task itself and uses the existing ledger task claim/reservation. It resolves immutable scopes against the actual admitted local binding, current exclusions, access and filesystem identity. Captured provider objects and schemas are immutable narrowing inputs. Duplicate preparation is refused. Preparation grants no invocation.

The host obtains `authorization.footprint`, reserves the actual runtime's WorktreeActivity claim using the native execution owner, and supplies that same owner, original activity claim, `authorization.claim.reservation_id` and `authorization.claim.launch_run_id` to existing `AgentService._run_owned`. New arguments are `workflow_task_authorization` and `workflow_activity_claim`; existing arguments remain `execution_owner`, `automatic_child_reservation`, `requested_run_id` (or genuine precreated row). Existing child capacity/reservation commit and existing run-row creation remain authoritative. `_run_one` calls `bind_native` immediately after its existing `owner.bind_run`. No additional row, executor, writer or permission store exists.

`bind_native` requires automatic child owner, exact runtime capacity, run ID and conversation, committed original reservation, and exact held activity claim. Existing `bind_workflow_task_run` validates durable lineage. It binds once. `WorktreeActivity.validate_claim` is a small query of original object, held state, member, owner and footprint; admission is checked before the activity lock, with no I/O, callbacks or nested capacity lock inside it.

`check_task_call(authorization, *, registry, call)` yields stable AutomaticWorkRefused errors. Invocation requires exact current owner/run, running native row, accepted task attempt, live phase/controller/binding/root and original activity claim. Task authorization is carried explicitly into native timeout threads and MCP main-loop coroutines. Shared providers never hold task state. IDs or task prose in model arguments cannot choose custody.

Discovery and active schemas intersect planned names and actual provider identities. Runtime restrictions precede lazy project-instruction preparation, hook transformation, permission review exemptions and final callbacks. Provider checks also run after permission waits, before actual handler/subprocess/remote execution, including promotion's early branch, promotion preview/apply and the existing CAS observation path. The existing Task4 atomic writer and existing permission floors remain unchanged.

## Approved decisions and limits

Parent rulings are retained in task-5-context.md and the progress ledger. ADR285 and the accepted spec were narrowly amended:

- An exclusive task requires the actual runtime-wide opaque/full selected-root claim. Serialization adds no OS confinement or permission grant. Shell arming and MCP tool permissions still apply.
- Active effectful legacy/v2 command/MCP hooks refuse workflow preparation/dispatch, including planning. Existing ordinary hooks/configuration/order remain intact. Current notification workers do not prove native owned lifetime. Tasks6/8 must wire that lifetime before enabling hooks or retain explicit unsupported refusal; a generic safe flag is insufficient.
- Workflow skill scripts refuse in both scoped and exclusive mode, before retained scratch creation or Popen. Phase context without bound task custody cannot fall back to ordinary script authority. Existing runner result cannot prove child reaping plus reader cleanup; no warning-text or exit-code inference was introduced. Task7 may enable this only after actual typed owned cleanup proof. Ordinary/Goal script behavior is preserved.
- Unknown/custom providers, alternate builtin file writers and skill-spawn/new-chat/fork/recursive child routes are unsupported. Pure calculator/date-time builtins remain eligible when planned. Known local nonpath effects, raw shell and MCP require exclusive mode and existing permission checks.
- Root aliases are explicit and must match; actual root object identity must match too. No `path_targets` hint grants permission. Glob/grep/Git discovery conservatively require full selected-root coverage. Scoped mkdir also covers missing parent directories.
