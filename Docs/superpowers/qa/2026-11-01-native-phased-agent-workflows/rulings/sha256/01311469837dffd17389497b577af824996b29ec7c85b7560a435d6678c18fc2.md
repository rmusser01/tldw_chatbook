### Important I1 — the shared engine accepts pre-confirmation native mutation

**Location:** `tldw_chatbook/Workspaces/change_revert.py:190` (native source check), `:215` (mutation entry), contrasted with `tldw_chatbook/UI/Screens/change_review_screen.py:530` and `tldw_chatbook/Workspaces/change_revert_ownership.py:357` (provider-only applying/confirmation/selection guard).

`revert_paths()` checks only that an existing native call refers to the same service and DB. It never requires `applying`, the original positive confirmation, exact selected row/path membership, the one-use row consumption, or unresolved-settlement refusal. Those checks exist only in `AgentRunsChangeReviewProvider.revert()`. A direct shared-engine call on the real native preparation worker therefore turns a finite pre-confirmation read into mutation; the engine also lacks selected-membership enforcement on an applying worker. The binding review context explicitly requires that enforcement at the shared native engine entry.

**Reproduction:** the ignored reviewer plugin `confirmed_undo_review_probe.py:5` was collected on the original `Tests/Workspaces/test_native_confirmed_undo.py` module so it uses that module's genuine `undo_host` fixture, supported `bootstrap_profile`, mounted Review, real SQLite, real shadow repository and actual native worker. Its preflight wrapper checks the real call is `applying=False`, then invokes the unchanged shared `revert_paths` API with the actual service/DB/row/path. It creates no issuer/ticket/confirmation and changes no product source. The engine returned `[True]` and the test file changed `after\n` to `before\n` before any positive modal response. `confirmed-undo-review-engine-probe2.log:38` retains the genuine failed assertion; the receipt is **1 failed, 28 deselected in 3.38s**. Runtime disposal completed normally.

This probe is an engine-boundary test using a callback wrapper; it does not claim the stock UI currently calls revert during preparation, nor that Python objects form an adversarial sandbox. The stock direct-provider refusal remains correctly enforced. The point is that the required shared native choke point permits preflight-only custody and accepts arbitrary membership if it is reached directly.

**Required correction:** enforce original active applying confirmation and exact membership in the native engine before its first repo/Git/mutation entry, retaining the provider's native-source/no-downgrade refusal and standalone behavior. Arrange once-only selection consumption in one place so moving the guard does not consume it twice. Promote the genuine pre-confirmation engine probe and a nonmember-row/path control; retain the existing successful provider path.
