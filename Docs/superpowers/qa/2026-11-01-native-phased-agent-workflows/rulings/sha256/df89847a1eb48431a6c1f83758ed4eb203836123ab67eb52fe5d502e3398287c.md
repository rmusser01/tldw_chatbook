## Important findings

### I1 — First-send publication invalidates legitimate surviving members and non-Stop retirement

**Primary location:** `tldw_chatbook/Chat/console_runtime.py:3064` (publication trigger), `:3132` (generation-changing publication). **Affected receiving locations:** `tldw_chatbook/Agents/agent_service.py:6438`, `tldw_chatbook/Agents/legacy_hook_ownership.py:323`, and `tldw_chatbook/Chat/console_agent_sources.py:204`.

A normal first manual send can spawn a threaded child, complete its parent response, and leave that child alive in the original ordinary tree. `_run_custodied_turn` awaits the parent prompt chain and checks the parent's `COMPLETED` state; it does not await the ordinary tree's `retired` future or remaining child members before `_record_successful_first_send`. The normal response branches in `console_chat_controller.py:27967`, `:27982`, and `:27993` set that completed state independently of survivor retirement. `run_prompt_chain` / `_after_turn` waits for prompt/Stop handling, not surviving child completion (`console_prompt_queue_coordinator.py:1510`, `:1697`). The existing survivor test itself demonstrates that parent return precedes the child return (`Tests/Chat/test_console_ordinary_tree.py:865`).

The first-send save then advances the configuration generation while the child still owns real resources. On its eventual return, `AgentService._finish_execution` enters `tree.source.activate()` **before** `tree.host_returned(owner)` and `owner.finish_root()`. `_AgentSources._check_original_sources` rejects the generation mismatch (`console_agent_sources.py:144`). This prevents canonical child settlement and root completion even when the actual child has finished and its required row/steps were successfully written. The ordinary tree remains retained, conflicting work stays refused, and `_drain_ordinary_turns` waits indefinitely during disposal. This is a normal native lifecycle, not failed cleanup or an arbitrary user changing configuration.

The special successor proof does not repair that case. It accepts only `_CommandCustody` whose event is exactly `Stop`; it has no child/member settlement route. Already-admitted non-Stop native hooks have the same problem: reconciliation encounters the new receipt, but `check_retirement` rejects `SubagentStop`, `PostToolUse`, `PostToolUseFailure`, and `PostCompact`. Legacy custody is rejected even earlier by the `_CommandCustody` receiver fence. This is not merely an absent test: the actual asynchronous producer/return paths are present. `HookLifecycle.install` sends a late SubagentStop through `_notify` after its parent checkpoint retires (`hooks_v2/lifecycle.py:364`); post-tool completion runs asynchronously (`tool_pipeline.py:690`), while MCP execution can publish a logical failure with `outstanding_cleanup` and leave its original reaper to report physical terminal return later (`mcp_executor.py:900-943`). That final callback invokes the same reconciliation path. PostCompact waits for its lifecycle future, which is a logical event outcome; that wait is not a universal physical-cleanup barrier.

The delivered direct-controller survivor and late-SubagentStop tests do not enter `ConsoleRuntime._run_custodied_turn`, so their successful drain does not contradict this sequence. The native first-send Stop control covers precisely the one event the new exception accepts.

**Smallest correction:** make the normal onboarding publication respect the lifetime of all admitted ordinary work. Prefer deferring its generation-changing persistence until the original tree has retired, without making the parent response wait for a survivor. If the early publication must remain, provide a narrowly proven lifecycle solution for every already-admitted receiving/settlement path that can legitimately return afterward; do not simply weaken normal source checks or extend a Stop retirement waiver to new dispatch. A runtime-owned first-send/surviving-child control, followed by real child canonical settlement and disposal, is the minimum regression case. Include at least one real non-Stop late physical hook return under that same publication ordering.

**Spec impact:** violates the binding requirement that a parent may return before a survivor/late hook while the original whole tree later retires after positive physical, host, and canonical-write proof. The paired-view mechanism and strict normal source checks are plan-mandated; the missing lifecycle coverage is still Important. Source confidence is high; this review did not execute the new regression scenario.

### Original I2 — Native Windows configuration can never produce the first-send retirement receipt

**Location:** `tldw_chatbook/Chat/console_first_send_retirement.py:68`.

`_plain` accepts the exact concrete `PosixPath` type only. Native `config.load_settings` creates `ACTUAL_PROJECT_ROOT` and `APP_COMPONENT_ROOT` with `Path(__file__).resolve()` (`config.py:2297-2300`) and installs both Path objects in the normalized configuration (`config.py:2757-2758`). On Windows these are `WindowsPath`, so `_plain(normalized)` always fails and `_views()` returns `None` (`console_first_send_retirement.py:141-145`). Consequently `first_send_source` cannot be captured on that supported platform.

The runtime nevertheless performs the fallback first-send save (`console_runtime.py:3097`, `:3111-3117`), advancing the generation without a retirement receipt. Thus even the **Stop** case addressed by this patch can remain permanently retained if its original physical/reconciliation return follows publication. This is a separate case from I1: it occurs with a Stop and no surviving child. V2 command execution has a Windows-specific launch refusal, but native v2 MCP hooks use the same `_CommandCustody` and retirement path and do not depend on the POSIX command launcher. Ordinary Windows support is explicit in `README.md:66`.

**Smallest correction:** if this paired-view mechanism remains, accept the exact native immutable concrete Windows path representation as well, preserving the existing exact-type/lexical-value comparison and refusing custom path objects. Qualify the native normalized view and first-send Stop/MCP retirement on Windows. If the lifecycle correction for I1 removes this receipt mechanism altogether, this defect disappears with it.

**Spec impact:** normal supported native configuration is treated as unverifiable, so the implemented positive retirement contract is platform-incomplete. The source amendment explicitly chose the observed PosixPath representation; that plan-mandated choice is insufficient for the application's supported platforms. Source confidence is high. No Windows execution was performed, and this finding does not claim Windows command-hook support.
