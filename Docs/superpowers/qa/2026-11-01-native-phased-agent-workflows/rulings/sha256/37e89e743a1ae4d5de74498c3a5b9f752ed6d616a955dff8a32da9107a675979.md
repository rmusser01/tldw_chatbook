WorkspaceRegistryService/WorkspaceDB and ConsoleRuntime. Binding is metadata-only:

publication callable is passed explicitly. D1 retains all strict bridge/store/
session/controller/coordinator checks. Actual Git runs through D1's existing
native source context and helper-refusing qualification. Each initializer holds
real config, workspaces DB and shadow-storage execution leases plus operation-owned
SQLite scope through callback, READY/FAILED/stale-discard handoff and scope exit.
The original finite claim/tool/root retire only afterward. Callback failure,
unavailable/raised SQLite completion, disabled/revised consent, replaced source,
helper refusal and close produce unsuccessful readiness or conclusive stale
discard. Observational claim settlement is not workflow/task success and adds no
fictional journal, no-run boolean or process receipt.

Explicit Settings toggle/retry is MANUAL; lazy `admit_turn` and durable binding
observation are AUTOMATIC. Capacity/activity busy becomes existing FAILED/busy
readiness with explicit Settings retry. No retry waiter, poller, release
subscription, duplicate capacity owner or additional execution queue was added.

Memory-only workspace epochs/toggle fences reject observations read before a
concurrent disable. Capability, registry reads, durable CAS, source capture,
filesystem checks and native admission all run outside the bookkeeping lock.
Successful durable toggles clear old readiness; stale durable CAS still conflicts.
An already admitted physical callback may return, but cannot publish READY after
its original revision/generation/source changes. The previous lock-timing test
was changed to this approved semantic requirement, rather than preserving a lock
across a user callback.

App shutdown now seals initializer ingress before Console capacity closure and
drops never-started queue work. Actual retained runtime cleanup joins existing
workers through callback and handoff return, surviving cancelled waiters.
`shutdown(timeout=...)` is still bounded and explicitly does not prove drain.
The existing lifecycle-order test double now includes the ingress seal; no UI
production code or appearance changed.

metadata or no-store dispatch refusal requirement. Preserve no-hook, disabled-hook,
ephemeral and storage-less ordinary behavior. Runtime-only coordination does not
exclude an unrelated surviving OS/remote effect after app crash; preserve workflow
recovery and fresh evidence, without calling arbitrary hook effects read-only.

producer/consumer before its later ordinary-tree integration. It is not implemented
here. Undo, references, children, phase-window storage, planning, controls, UI and
coordinator work are outside this delivery. Task 8 and capture-enabled workflow
