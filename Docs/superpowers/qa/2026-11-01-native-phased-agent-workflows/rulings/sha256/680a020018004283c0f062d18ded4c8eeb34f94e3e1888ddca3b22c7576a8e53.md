## Important findings

### I1 — Valid dependencies on earlier phases can never become ready

**Location:** `tldw_chatbook/Chat/console_workflow_runs.py:2093–2106`, especially `done` at 2101 and the readiness predicate at 2104.

**Trigger:** A valid two-phase plan has `phase-2/task-2` depend on `phase-1/task-1`. Complete task-1, explicitly accept its quality result, and approve phase-2 using the native prepared decision.

**Defect and consequence:** `_execute` selects only the current phase definition, then builds `done` only from tasks in that definition which are not in this attempt's task IDs. An earlier-phase task can never enter this set. Consequently every task that depends on a prior phase is blocked even when its result was successfully settled, reviewed, and accepted. The driver raises `ValueError("workflow dependencies blocked")` after phase acceptance. The workflow consumes its third generation, enters `recovery_required`, never prepares or starts task-2, and retains the original run so runtime shutdown refuses with `workflow_original_shutdown_unresolved`.

This is not invalid planner input: `tldw_chatbook/Agents/workflow_models.py:228–244` deliberately carries `seen` across phases and allows dependencies on earlier tasks; task input references also use that contract at 255–262. It is the common implementation → verification/handoff workflow. Spec §5 (194–207), §7 (269–275), Task 8 step 4, and task AC #2 require eligible approved dependent work to progress with fresh predecessor evidence.

**Direct evidence:** `task-8g-review-probe-2.log` records a real successful first task and quality acceptance followed by:

```text
ValueError: workflow dependencies blocked
REVIEW_PRIOR_PHASE_DEPENDENCY {"status":"recovery_required","provider_entries":["planning","task-1"],"pending_preparations":[],"generation":3,...}
REVIEW_RETAINED_CLOSE workflow_original_shutdown_unresolved
```

The isolated negative intentionally ends with `REVIEW_CONFIRMED_DEPENDENCY_RETAINED_NO_CREATOR_DRAIN`; it is a reproduced failure/retention, not a successful cleanup. All 8,316 pre/post pins match. The new next-phase journey at `Tests/Chat/test_console_workflow_dispatch.py:64–68` copies a dependency-free task, so its passing result does not cover this case.

**Required remedy:** Derive readiness from exact successful, fresh predecessor results already validated for the approved plan/phase, including earlier phases, while retaining the existing checks before dependent dispatch. Do not simply declare all task IDs outside the current phase successful. Add a native multi-phase dependency/handoff journey, with stale/failed predecessor refusal and actual final owner/creator drain. Preserve same-phase partial-resume semantics and accounting.

### I2 — Quiescent capacity waiting continues consuming the finite active-time budget

**Location:** `tldw_chatbook/Chat/console_workflow_runs.py:2138–2144`; connected ledger implementation `tldw_chatbook/DB/automatic_work.py:2449–2485,2607–2633`.
