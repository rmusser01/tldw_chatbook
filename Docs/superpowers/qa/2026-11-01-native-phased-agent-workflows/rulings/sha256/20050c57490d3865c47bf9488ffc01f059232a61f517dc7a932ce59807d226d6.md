# Root ruling — G FIX1 I2 quiescence accounting and return uncertainty

Ruling: accept Option B's exact-original positive-return contract, subject to the receiving-boundary requirements below. Option A is incomplete; a display override, durable drained marker or second acknowledgment write does not establish return. This is a governing source/design ruling, not a passing test or permission to bypass any existing native gate.

Root read `task-8g-fix1-source.md` I2 caller/schema/options, the actual ledger admission/snapshot/active-time/quiesce/reopen/recovery receivers, the workflow snapshot/review/runtime projection paths, and spec section6. The binding contract is: close execution time only with positive drain and durable settlement; unknown cleanup remains conservatively charged or exhausts remaining allowance; restored rows do not reconstruct live authority. Exact time and phase retirement must not be inferred from one another.

## Required disposition

1. G's native quiesce transaction may close the existing execution interval only after the already specified exact prior effect/model/tool/launch/source/owner/claim/B/E return proof. Keep that accepted phase durably `retirement='unknown'`, using the existing schema state. A COMMIT is not proof of the quiesce producer/outer wrapper's return. Existing direct quiesce callers retain their established contract; do not globally reinterpret every drained row.

2. Retain one bounded passive return record for the current quiescence on the SAME original phase/preparation. It must identify the exact interval/transaction, original issuer/callback/read/producer/retired handles and prior physical-return records, and become positive only after the entire original quiesce wrapper returns normally. Validate its definition-time and current receiving source. An interval ID, row state, Boolean, reconstructed object or another phase's proof cannot stand in for it.

3. Only a caller already holding the SAME original native phase/TaskAuth/dispatch, or an original metadata invocation that captured that same live G run/phase, may supply this context. The witness supplies return evidence; it creates no execution authority. Every owner, revision/fence, source, binding, freshness, budget and native dispatch gate still applies. Metadata with captured absence or a superseded/replaced run must not borrow current proof by looking up a workflow ID.

4. With the unchanged positive witness, native readers may treat that exact closed interval as settled and the original native dispatch transaction may reopen charging without replenishing prior charge. Without it, the unknown accepted phase must not yield an exact active-time value: use the existing `clock_unknown` refusal for admission/clock reads, and an uncertain accounting projection for readable history. Do not silently substitute zero or a known closed-interval sum. This conservatively denies the remaining execution allowance until genuine reconciliation; do not present an invented numeric ceiling as measured usage.

5. Carry the distinction through every relevant consumer, including `_workflow_active_seconds`, `_check_admission`, reservation/admission paths that run before reopen, `_snapshot`/workflow snapshot, `_prepare_review`/task-input revalidation and captured-run metadata get/publication. A live positively quiesced retry must remain possible; a passive reader without original proof remains uncertain. Only the new uncertainty contribution from that exact quiescence may be satisfied. Chain `review_required`, uncertain reservations, other phases/intervals, changed sources and prior recovery remain blocking. Never clear `snapshot.uncertain` globally or allow a generic caller override.

6. Proof cannot keep describing a phase as idle after execution or effectful cleanup re-enters. The actual native work/cleanup boundary must invalidate/consume the old idle disposition and restore charging through the existing native transaction where applicable. If return, cleanup or source becomes unproven, fall back to unknown/refusal and retain the original custody. Read-only metadata observation does not itself authorize execution or reopen time. A poll, reserve, user acknowledgment or quality acceptance cannot clear the durable marker or reset charge.

7. Only the SAME original native dispatch or positively proven terminal settlement may retire this live quiescence disposition through the existing native ledger path. No extra acknowledgment transaction, global witness registry, new scheduler/owner, generic callback or workflow-ID capability. On process restart the witness is absent, so an accepted unknown phase must be excluded from clean-boundary recovery and remain subject to original conservative recovery. Ordinary clean terminal/human-review waits retain their existing behavior.

## Scope, cost and evidence

This authorizes the smallest necessary original-context plumbing across the existing readers and native receivers; it does not authorize an unchecked implementation shape. Controller must record the exact context/receiver inventory and validate how the existing native dispatch, task-input and cleanup paths consume it before edits. Amend ADR285/spec/plan/task with this contract, reason and cost, and verify readback before I2 behavior changes. No new ADR or migration is required for the stated existing-state design; surface any actual schema/interface contradiction instead of guessing or expanding the mechanism.

Cost if wrong: incorrect witness association or overly broad exemption could undercharge active work or bypass uncertainty. The implementation adds cross-module context plumbing and makes DB-only readers conservative. Even a truly acknowledged idle wait followed by a process crash may require recovery because its live proof is lost. That is an explicit cost of retaining safe uncertainty with the existing schema, not a claim that all idle workflows can resume after a crash. No user acknowledgment may invent the lost proof.

Cover separately: stable positively drained native wait with no active-time increase; actual original dispatch/held work reopening and accumulating prior charge; live or uncertain prior cleanup refusing quiesce; post-COMMIT source/producer/retirement failure with no exact accounting or admission; plain passive clock/snapshot/review refusal/uncertainty; copied/mismatched/superseded witness refusal; repeated wait cycles and no refill; real cleanup after idle never falsely credited as idle; and restart of both the positive-live and failed-return durable unknown cases refusing clean recovery. Preserve direct native/ordinary contracts and all historical failed evidence. Fresh independent scoped review must judge the complete I2 fix alongside I1/I3/I4/I5.
