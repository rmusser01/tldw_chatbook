## Result and exact physical contract

The selected Git executable may be a legitimate delegating wrapper. Its version
and config output, and its leader exit, do not prove managed descendant drain.
`ShadowRepo._run_process` now routes all three native version/config/command
launches through the existing low-level `ProcessTreeController`, with a local
`asyncio.Runner` on the original synchronous initializer/filesystem/publisher
thread. The exact `_SnapshotTicket.activate()` carries its original source and
owner; no replacement owner, workflow/child row, application executor, queue,
reaper, trust/allowlist framework or journal is introduced.

The original activation and thread-owned SQLite scopes remain synchronous;
only process transport enters the coroutine. Each launch joins byte-stream
collection, actual direct-terminal plus native group-empty proof, and handle
close before returning. No next command can launch before its predecessor joins.
The original ticket then joins worker and original host acceptance/discard return,
then waits for `operation.finish()` RETURN before finishing its own root and
settling its opaque claim. Initializer readiness and final-snapshot publication
both use that same ticket activation.

On deadline/error the same original operation becomes stopping, requests bounded
TERM/KILL, and waits with the same controller for observable late proof while
its actual worker/source/storage scopes remain alive. Merely delayed cleanup does
not permanently mark uncertainty. If the proof mechanism itself becomes
unavailable, the owner is marked cleanup-unproven and the original callback,
operation and scopes remain retained indefinitely. A shutdown cancellation or
logical result cannot convert that to successful drain. This intentionally can
hold disposal indefinitely.

Only the two initial native attachments use the existing
`native_workflow_qualified()` policy. Ordinary unqualified platforms retain their
old consent/coordinator/Git path; a qualified source mismatch never downgrades.
Native POSIX input None inherits stdin as before; existing boolean low-level
controller callers keep PIPE/DEVNULL behavior. Output remains bytes or
locale/UTF-8-mode text with universal newline translation. Original environment,
argv, cwd, command deadlines, pins, filter/promisor refusal, ignore rules, privacy,
user Git state and historical content/restore behavior remain unchanged.

Actual production bridge capture supplies no owner/claim and these producers own
finite roots. Borrowed tickets remain supported without finishing/settling their
parent. Their future producer MUST retain its covering root/source/storage until
that exact ticket.retired, which follows host and operation.finish RETURN.
Premature parent-root finish is outside this producer contract; no general
ExecutionOwner framework was added. The existing borrowed control now explicitly
waits for its original ticket.retired and confirms the original parent remains live.

## Self review, costs and limits

Reviewed changed callers, activation identity, synchronous/async boundary, timeout
unwind, same-source publisher work, all three launch paths, borrowed ownership and
ordinary platform gating. Remaining old subprocess test observers were moved to
the real `_run_process` seam so helper-refusal controls did not silently go inert.
No user repository/config mutation, new dependency, cleanup or unrelated reformat.

Python3.12.11 / macOS26.5.2 arm64 uses stdlib ThreadedChildWatcher, which creates a
waitpid daemon thread per child. This is existing asyncio transport machinery,
not a new application work-producing executor/worker/reaper. Runner/group setup
adds per-launch cost. We do not claim Runner joins every internal waitpid thread;
physical proof is real direct terminal + group absent + streams/handle completion.
Managed groups are the boundary; no OS-escape resistance is claimed. Windows
native workflow execution remains unqualified; simulated ordinary policy and
existing Job adapter unit controls are separate from live Windows evidence.
Unknown cleanup can retain finite capacity/storage and hold disposal indefinitely.
No full-suite/Windows-live qualification, ordinary covering-tree producer,
reference/Undo integration or Task8 coordinator completion is claimed.

  producer/consumer report paths. `ticket.retired` follows every applicable
  callback and operation.finish RETURN. Future covering-parent producers keep
