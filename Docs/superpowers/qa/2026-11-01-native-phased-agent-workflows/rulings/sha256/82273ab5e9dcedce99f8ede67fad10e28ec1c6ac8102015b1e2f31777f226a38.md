## Implemented interfaces

- `WorktreeScope(path: Path, subtree: bool, root: DirectoryChain)` is an immutable dataclass (positional construction is also possible). `root` is a previously captured admitted root from `Utils.filesystem_identity.capture_directory_chain`; `path` must be the existing admitted resolver's absolute canonical target. Construction checks containment, safe complete ancestor identities and captures target device/inode metadata outside activity admission. Missing create targets are valid; unreadable/unknown metadata, symlink drift and reparse targets refuse. No heavy runtime/config imports occur when importing the activity module.
- `WorktreeFootprint(reads: tuple[WorktreeScope, ...] = (), writes: tuple[WorktreeScope, ...] = (), opaque: bool = False)` is immutable. Exact/subtree path overlap and captured root/ancestor identities reconcile canonical aliases, nested roots and renamed roots; existing target identities catch hardlinks. Casefolded suffix matching is deliberately conservative: case-only distinct names serialize even on a case-sensitive filesystem. Ordinary unclassified work must be constructed with a whole-root subtree write for every admitted root by Task 8; opaque-capable work must set `opaque=True` up front.
- `WorktreeActivity.try_acquire(*, owner: ExecutionOwner, footprint: WorktreeFootprint) -> WorktreeActivityClaim | None` is the requested convenience for an existing admitted native owner. It never launches work or consumes a budget.
- `WorktreeActivity.prelaunch(*, footprint: WorktreeFootprint)` is the controller-approved host-only context manager. It reserves the entire immutable footprint in one activity-lock section before native capacity; it yields a claim or `None`. A conflicting opaque claim is checked runtime-wide in the same atomic admission, before any root-specific state can be retained. There are no partial root locks, upgrades or waits. Context exit removes only its own never-bound reservation, including capacity refusal/exception/type-invalid-owner paths.
- `claim.bind_owner(actual_owner)` attaches the actual successful native capacity admission before any thread/effect starts. After binding, context exit and exceptions never release the claim. `claim.id` is an opaque host handle ID.
- `claim.settle(*, durable: bool)` settles only the primary journal. False is nonconclusive; true is monotonic. Positive native drain and durable settlement are independently required.
- `claim.attach_child(actual_native_child_owner) -> WorktreeActivitySettlement` retains the existing reservation without reacquiring conflicting scope. It accepts actual, admitted children from the same native capacity; repeated attachment returns the same child settlement handle. That returned handle's `.settle(durable=True)` is independently required in addition to that child's own positive physical drain. A parent journal cannot settle a survivor. New attachment after primary drain or claim retirement refuses.
- The internal `WorktreeActivity.record_drain(claim_id, *, proven: bool)` callback is idempotent. Each actual native owner registers `owner.on_drained(lambda proven: activity.record_drain(member_id, proven=proven))` outside the activity lock; the primary member ID is the claim ID. Negative cleanup proof never becomes positive or releases the claim. No public force-release path exists.
- `ExecutionOwner.is_admitted -> bool` is the controller-approved six-line metadata-only query under the existing capacity lock: actual membership persists through held physical operations and ends at retirement. Activity reads it before taking its own lock, rejecting fabricated/unregistered/already-retired owners. This is observation, not execution authority, and changes no capacity algorithm/accounting/dispatch.
- `ConsoleRuntime.worktree_activity -> WorktreeActivity` lazily constructs one owner under the existing `_execution_capacity_lock`. Disposal cannot create a fresh owner; an existing owner and its held reservations remain reachable after disposal. No global singleton, scheduler, extra execution loop, DB owner or allowance ledger was added.

Native launch custody usage for Task 8:

```python
with runtime.worktree_activity.prelaunch(footprint=complete_footprint) as claim:
    if claim is None:
        return busy
    # May raise CapacityRefused: context exit unwinds only the unbound footprint.
    owner = runtime.execution_capacity.begin_execution(..., child=True)
    claim.bind_owner(owner)
    # Trusted existing launch path starts only now.
# Every bound launch failure still needs finish_root + durable settlement.
# Ordinary children attach before thread start and retain their own settlement handle.
```
