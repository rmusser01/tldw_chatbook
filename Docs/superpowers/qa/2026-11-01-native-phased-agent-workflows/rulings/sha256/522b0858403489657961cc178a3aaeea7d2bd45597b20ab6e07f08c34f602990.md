`_UserRawCliCall.root` uses only the originally selected ready local binding or, when no binding was selected, the original scratch snapshot and real lease. A selected unavailable binding refuses. Directory chain and original metadata checks happen outside bookkeeping locks. `RawCliRuntime.execute` checks external source before the existing admission lock, then pure original identity inside the existing final launch fence. Existing disarm/cancel serialization is unchanged. Source replacement never reselects another runtime/store/profile/DB/binding.

The actual Textual worker callback calls `custody.start()` under a private start/cancel fence before activation. The actual wrapper task cancellation handler may prevent that callback; a late scheduled callback then returns without effects. If callback entry won the fence, cancellation only requests cancel and the existing worker remains custodian until its actual return. A cancelled asyncio/Textual wrapper or done flag is never itself accepted as physical return. Tests cover real Textual immediate cancellation and a retained late callback.

`_UserRawCliCall.activate` retains the captured recovery/source scopes and operation-owned DB handles; private optional run-log storage is pinned to the original selected data root, not resolved from a replacement configuration. `database_for_run` uses the original Runtime's activity receipt service/AgentRunsDB without constructing an agent/provider bridge. Original first Chat persistence is accepted only through its actual stable-binding return/publication; ephemeral refusal still creates no Chat or run. The actual `local_command` producer is unchanged except that it receives a private preselected UUID to identify a commit-then-raise create. The owner binds this real row exactly once.

The required-write rules are explicit:

- Before create, required proof is false. A create exception with an observed absent original UUID proves no-row refusal. An exact original row binds the owner and requires original error terminalization. Unreadable or conflicting observation stays unresolved.
- Initial-step failure observes actual `set_status(error)` True or exact original error-row readback; there is no shell launch without successful initial creation/step.
- Final `set_terminal_with_step` True proves the original transaction. False or exception requires exact original run fields/status/result and the canonical JSON terminal step. Status-only completion or Python's bool/int dictionary equality is insufficient. Committed-then-raised readback is tested using actual SQLite.
- There is no existing direct RawCLI retry/settlement producer. No new replay, poller, journal or synthetic row repairs the result. Missing/contradictory proof retains the existing original worker, storage, scratch lease, stopping operation and OPAQUE claim indefinitely. RunLogWriter stays best effort.

`RawShellExecutor.execute` wraps its same physical body and retains the actual existing admission Thread and `_QueueRelay` Thread handles. Native callers join their real returns in the original caller. Process-tree cleanup proof still comes from `_cleanup_tree`; exit, timeout and cancel alone are not proof. The returned cleanup flag and required-output seal are finalized after helper joins. Unqualified/standalone callers retain bounded joins but now honestly return cleanup_unproven if a helper is still running. This is an intentional compatibility cost: native corrupt/held helpers can retain their worker/storage indefinitely, while standalone no longer misreports physical completion.

The shared-call handoff is RawCLI-specific: AgentService captures the exact ToolCatalogRegistry selection, concrete RawShellToolProvider, original RawCliRuntime and catalog generation/snapshot. Its existing timeout-worker/inline branch binds its already-reserved operation. The actual provider binds its original validated request just before calling runtime.execute. The runtime consumes only matching objects; names/IDs alone confer nothing. Captured worker_guard enters the same accepted original storage context on the admission helper. No second tool slot, user owner, generic execution framework, hook ancestry activation, executor, queue or watcher was introduced. Existing Task7 native authority, task/child owner, OPAQUE claim, required evidence and output remain with the original caller.

Host publication still uses the original synchronous marshal/call_from_thread. `_UserRawCliCall.deliver` joins actual original store acceptance or conclusively discards stale presentation; refusals bank the exact original stash when that original runtime remains alive. Required admitted DB settlement continues after presentation source loss. Existing repaint locking joins an already-running synchronous flush; timer.cancel alone is not a receipt. The original worker checks all physical, required DB and host proof while its scopes are active. The corrected worker retains original source/storage scopes, live DB handles and scratch through actual operation.finish RETURN; then storage scopes exit and scratch/root/claim retire. Runtime seals admission before capacity close, drains exact pending calls through repeated cancellation before original store/DB close, and scratch tombstones cannot delete a leased generation. Its advisory bounded RawCliRuntime shutdown is not treated as final drain.
