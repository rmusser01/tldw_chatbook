# Root ruling — direct native launch and wave caller return are separate obligations

Ruling: accept Option A's original-invocation direct return boundary, with the constraints below. Preserve the existing bridge-prepared, capture-disabled direct launch contract and its real named callers. The SAME genuinely direct AgentService.launch_workflow_task invocation may finish its OWN original launch operation only after its original _core_operation and execution(self) scopes have both returned normally and exact native/source/operation associations remain valid. G/wave keeps its existing later caller-owned outer source/storage/worker return boundary unchanged. A service method cannot certify arbitrary caller-owned outer scopes; those remain independently owned by that caller and must never be described as covered by this direct receipt or child-owner callback.

Root read the complete fixed source appendix 'Actual direct dependency launch obligation and alternatives', actual launch_workflow_task, _WorkflowWave._open/_launch/run and source checker, _PreparedWorkflowReply require_current/check/close/_close_on_native_owner, actual native child owner source-close tail, execution and _core_operation/owned_goal_storage scopes, OwnedOperation.finish, every repository launch_workflow_task call site, named native-preparation/dependency/child-launch consumers, Task6 report/direct contract and living agent-runtime architecture. No Task8 test or probe was run by root. The observed dependency2ERROR identifies the SAME original retained _launch_operation after actual child return; that is evidence for this case, not a historical global regression attribution.

Required boundaries:

1. Classify the original invocation exactly once, from the SAME existing authorized preparation/native service and actual original bridge preparation at entry, before it may create a launch or reserve the operation. Distinguish no-bridge native calls, bridge-prepared direct calls, and actual existing wave-owned calls. A later mutable _wave=None, a flag/ID, copied preparation, reconstructed receipt or caller-selected mode must never convert a wave-owned call into direct. Revalidate unchanged original classification/associations at the receiving boundary; changed/unknown association retains the original obligation and refuses release.

2. Save the SAME actual operation when it is reserved under the original child owner. Finish ONLY that operation, on that invocation's positive original synchronous return after its own admitted source/core scopes, with original authorization/preparation/native service/owner and receiving sources unchanged. Check actual operation membership/owner and same current preparation field before consuming it; clear only after its actual original finish returns. Preserve the original native result/error precedence and source guard. An exception/unwind, failed/missing return proof, borrowed replacement or later method source change is not a normal return. Do not guess successful release from body result, child Thread exit, root_finished, a DB row, count or COMMIT.

3. Keep real wave orchestration exactly responsible for its original wider boundary: outer item.activate_source, phase/execution/owned_goal_storage and actual worker return, including known no-dispatch wait versus uncertain unwind. The direct service branch must NEVER finish or clear the wave operation early. Preserve the existing finite same-preparation wait receipts/physical owner+claim proof, no repeated admission/CAS or failure-to-retry conversion. Existing capture-enabled bridge launch without a real opened wave remains refused.

4. This changes the direct launch-operation responsibility to the finite service invocation, not the child cleanup obligation. The SAME native child close operation still owns its original frame/lifetime/tool/source return; ExecutionOwner.on_drained remains contingent on its real root and every remaining operation. Required durable checkpoint/claim settlement and final preparation/configuration/storage/runtime retirement stay separate. No direct launch receipt or owner callback alone proves a required result, caller-owned scope return, full phase completion, creator retirement or permission for dependent work. The ordinary caller's existing owned storage/phase/to_thread resources remain its responsibility; never add an implicit capability to manipulate them from a receipt.

5. Preserve supported no-bridge Task5/Task6 native direct behavior and duplicate receipt identity. A completed duplicate returns the same receipt without reserving or finishing another operation; an in-flight/failed/unknown attempt never replays or releases the original. Known pre-dispatch failures may release only after the actual invocation's own positive required scope return under the established native contract; if current control flow cannot prove that distinction, retain and surface the exact unresolved path rather than generalizing exception handling.

Required native covering controls: genuine existing bridge-prepared direct child + durable settlement and creator; original delayed native client cleanup keeps its close obligation until actual return; current failed dependency fixture reaches intended mutation/no-child-commit freshness refusal; no-bridge native caller and completed duplicate retain behavior. Positive direct service-call return must be observed separately from caller-owned outer scope return, not mislabelled as whole caller retirement. Direct receiving-source/own-scope-exit/operation/classification replacement negatives retain the original obligation and cannot execute replacements or become wave-to-direct fallback. Select focused existing/new controls for this exact changed branch; no broad predecessor replay/full suite or historical source swap. Negative isolated exits remain no creator-drain proof.

Alternatives considered: Option B alone uses existing wave correctly but removes direct-path coverage and leaves the current named direct native consumers unresolved, so it is not a complete compatibility repair. A future direct caller may deliberately choose wave orchestration, but replacing every test with it does not prove the present direct contract. A generic caller-return registry or fabricated post-call acknowledgment would add authority/plumbing without proving the original outer caller; reject it. Releasing all launch operations on current _wave=None or omitting their reservation hides uncertainty; reject it. Manually finishing an operation in a fixture or loosening checkpoint drain is not a product repair.

The implementation must keep those responsibilities explicit and test original wave retention. Direct callers that perform additional effectful work after the service returns must own that work independently; this API never supplies that broader lifetime. The change adds narrow original-invocation identity/source checks and targeted compatibility/negative tests, without changing permissions, reservations, limits, durable result policy or creating a new launch owner.
