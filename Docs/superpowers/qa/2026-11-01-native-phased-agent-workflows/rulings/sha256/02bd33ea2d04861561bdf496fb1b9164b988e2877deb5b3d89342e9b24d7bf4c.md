# FIX1 source proposal — first-send publication versus original custody

Status: proposal for controller/root adjudication; no behavior changed. FIX_BASE `5d5e6afe4c677dff3af3be9bc7d1e85f6e552ac0`. I2 is withdrawn. This proposes a publication-lifetime correction, not an expanded retirement exception.

## Actual boundaries and race

* `_run_custodied_turn` → `submit_draft` → `run_prompt_chain` returns on the parent's completed response and then calls `_record_successful_first_send`; neither this result nor `_after_turn` means the original tree retired. Its `save_setting_to_cli_config` worker changes global config identity while a child or a late hook still needs the strict original `_AgentSources.activate` / `host_returned` / `finish_root`. A matching Stop-only receipt cannot settle those other paths.
* `prepare_agent_sources` constructs `_AgentSources` and captures `config.current_config_identity()` **before** `admit_ordinary_turn`'s worker publishes the tree into runtime `_ordinary_turns`; checking an empty tree set is therefore insufficient. `issuing_agent_sources` retains source activation through `_submit_draft_body` and its ExitStack, including refusal/cancellation. `tree.retired` is signalled only after all original members have positive host, durable and drained proof, source scopes return, scratch lease exit and settlement callbacks return (`_retire_scratch`); its Future callback can execute on a worker thread. Runtime disposal shields `_drain_ordinary_turns` after admission has been closed.
* A managed source can exist earlier: `accept_received_intent` captures `ReceivedPreparationSource.config_identity` before registering its custody task; `run_received_intent` validates it through hook review, configuration capture and queue admission. Mounted fallback `wiring` captures `config_identity` before `capture_mounted_configuration_owned` and hands an `_OwnedTurnPreparation` to the existing builder. These may overlap a different session's active tree. `queue_prompt` transfers the exact pending witness into the actual `QueuedPrompt`; queued waiting/claimed entries survive the producing custody task, draft-only edit preserves the witness, return-to-head retains it, while consume/drop/config replacement/restore destroy that transfer. A quiescence test ignoring those entries invalidates already accepted queued work. Direct attached controller submissions also enter `issuing_agent_sources` and must participate; standalone controllers with no managed runtime retain their original behavior.
* The actual runtime has one app/controller/store and a lock-protected set of trees, while `_turn_custody` and queue registry are loop/owner-thread structures. Merely sampling them and then calling `to_thread` permits a new source capture before the worker's publication. `ConsolePromptQueueCoordinator._changed` is the existing owner-thread notification for coordinator and UI mutation (`publish_registry_change`); any exact path which bypasses it must notify the same runtime metadata reevaluation or keep the pending save conservatively deferred. No filesystem/config callback may run inside capacity or queue locks.

## Proposed correction

1. At the same successful manual-parent condition, update the same app-owned onboarding boolean immediately (and therefore current guidance/dedup behavior), but retain one runtime-owned pending **persistence intent**, not the old record/claim/owner as authority. Return the original parent result without awaiting child, hook, or disk. A single runtime-owned, cancellation-shielded finite task may perform the existing `save_setting_to_cli_config` once quiescence is proven; no unowned background callback or timer/poller. Multiple completions coalesce; preserve existing exception logging and session-only in-memory success when persistence fails.
2. Cover the *entire* managed original source lifetime, not just `_ordinary_turns`: establish private, non-authorizing metadata before source/config identity selection at the existing received intake and mounted precursor, and before `_AgentSources` construction for attached direct submissions. Carry the same metadata through the already-existing `_OwnedTurnPreparation`/received record, exact `QueuedPrompt` and issuing scope; transfer at actual queue acceptance, retain through draft-only edit/return-head, clear at consumption/drop/config replacement and on refusal/cancellation after the real producer returns. Original tree registration replaces neither this lifetime nor its strict source proof; the tree remains relevant through `retired`. Do not serialize the metadata or reconstruct it from IDs/config bytes. The carrier cannot authorize any read, dispatch, attach or retry.
3. Under the existing runtime capacity bookkeeping lock, a pure state transition elects publication only when **all** such managed source lifetimes, active original trees and in-flight native preparations are absent. Recheck the exact runtime/app/controller/store identity and pending intent on the loop. Mark the write in flight atomically against the earliest new managed source capture; while it is in flight the async entry points await its actual return and retry their ordinary source capture, and synchronous intake must refuse before claiming/transferring input (or use its existing async caller to wait before intake). No new capture can appear between the final quiescence check and the real save return. Preparation-read registration/capture and queue transfer must be covered without lock inversion; worker completion and queue/tree callbacks only signal the original runtime loop to reevaluate. The queue registry's existing owner-thread change path, exact issuer unwind, custody release, preparation-read retirement and tree retirement are the needed wakeups, not polling. This includes OTHER sessions and BOTH source-precapture and admission windows.
4. Outside all bookkeeping locks, execute the original native one-key save in the runtime-owned task. Do not repin any existing source, revive retired owner/claim, bypass current source/permission/root/DB/lease/required-write checks, or hold the parent response. An unrelated configuration mutation while work is live remains handled by existing strict refusal; it is not blessed by this intent. Check the original app/config/native save source at entry and on return; any lost or replaced source must refuse/retain the pending state rather than adopt a current pointer. Once the actual write returns, release the short publication fence; new attempts capture the new config normally. Existing Stop special proof is left in place initially until the replacement's full source/consumer scope and later deletion are separately adjudicated; it is never extended to other events.
5. Disposal first closes new admissions, drains exact existing preparation/custody and all original trees/physical hooks, then awaits any already-issued save to physical return before closing source/storage. If there is a pending intent and exact sources remain valid after these drains, the same runtime-owned path may save during disposal; if any original physical/required proof is unknown, it cannot write early or declare a drain. Outer cancellation is remembered and redelivered only after the owned save/normal drains return. A failed, replaced, or cancelled uncertain save is not reported persisted; retain existing session flag and log its failure, without manufacturing a retry or new source.

This is a single per-runtime metadata fence and one original save, not an activity owner, authority, extra execution reservation, new journal, reaper, or source waiver. COST: private lifecycle bookkeeping and potentially delayed persistence while a queued entry or survivor legitimately remains live; a crash before delayed persistence may show onboarding again next launch. New attempts may briefly wait/refuse during the actual disk save. Current app flag behavior remains immediate. Source/config changes by other actors remain strict and may refuse the queued work; the fence controls only this runtime's own first-send write.

## Source details requiring explicit adjudication before behavior

* All acquisition and release paths (including synchronous queue mutation, mounted builder reroute without acceptance, queue drop/shutdown, cancellation after worker enqueue, and direct managed submit) must share the same metadata ownership with no gap or double release; do not implement a narrower `_ordinary_turns` snapshot. `ReceivedPreparationSource` is selected synchronously before custody registration, and mounted `_OwnedTurnPreparation` can exist before any record. The carrier/clear plumbing above is the proposed solution; exact call-site audit is required when implementing it.
* The quiescence fence must account for existing managed preparation/queue witnesses that have already been selected when the first parent completes, not merely reject new admissions after the pending intent. If existing queue change notifications cannot cover a real removal path, retain the pending save until a proven wakeup/disposal rather than inventing a poller or saving early.
* The global config identity is process-wide. This proposal covers the app's managed Console original-source lifetimes. It does not claim to synchronize arbitrary non-Console settings writers or a second app/runtime. Those remain genuine source changes handled by existing strict guards; confirm whether a second simultaneous native runtime in one process is supported before claiming that this per-runtime fence covers it.
* Preserve the exact old writer's failure contract and cancellation behavior, and prove the write is completed/consumed by disposal; do not treat a scheduled Future, callback exception, or logical completion as physical return. UI screen's `_record_console_first_send` is a definition with no repository call site found; the runtime path is the observed producer, and this is not a claim about external callers.

### Mounted dispatcher precision

`ConsolePromptDispatchController.dispatch` obtains `prepared = await _precapture(...)`, then can await `withdraw_for_manual`, refuse on preparing/send-refusal, and in the queue case exits `with prepared()` *before* awaiting `controller.queue_prompt`. Thus entering/exiting `_OwnedTurnPreparation`'s `applied` ContextVar is not the lifetime: a source token must remain with the exact dispatch attempt across those paths and release in an outer `finally`, or transfer atomically on actual queue/normal acceptance. The existing REROUTE branch reuses `prepared` for `_stage_normal_chain`. This corrects any suggestion that the `with prepared()` exit alone permits first-send publication. A precapture that throws before returning must retire its physical worker before dropping its metadata; a cancelled/abandoned producer is not a successful capture.

## FIX1 source-closed removal of the superseded Stop successor

COST — delete the unused exceptional finish argument/caller fence and private journal metadata; old receipt-only tests must be replaced by strict lifetime ordering tests, not represented as passes. Runtime's unused old first-send producer records are removed. No general source check, original callback, execution owner, journal write or storage validation is deleted.
