### 1. Reminder bulk operation and selection ownership

[schedules_workbench.py:5125](https://github.com/rmusser01/tldw_chatbook/blob/df24de7ad71b95992f63a77fc5a19726e840849d/tldw_chatbook/UI/Screens/scheduling/schedules_workbench.py#L5125) and [schedules_workbench.py:5325](https://github.com/rmusser01/tldw_chatbook/blob/df24de7ad71b95992f63a77fc5a19726e840849d/tldw_chatbook/UI/Screens/scheduling/schedules_workbench.py#L5325) await each delete/update, use exclusive same-verb worker groups, and clear the entire current mark set on completion. The live `space` / `d` / `x` bindings and real confirmation path lead to those methods.

Mounted native private-profile diagnostics used actual keys/confirmation, real `SchedulingService` and file-backed SQLite. The server client was a controlled stand-in held with `asyncio.Event`, making overlap deterministic:

- Two marked reminders → Space; while the first server await is held, replace marks with the third reminder → Space. Calls are `srv0`, then `srv2`; `srv1` is never invoked. The first awaiter is cancelled, SQLite enabled states end `[true,true,false]`, and only “Toggled 1 marked task.” is reported.
- The same selection change with two real Delete confirmations calls `srv0`, then `srv2`, leaves the first two local reminder mirrors present and deletes the third; only “Deleted 1 marked task.” is reported.
- Letting the original toggle finish without another mutation toggles its two captured rows, leaves the third unchanged, and erases the third row's newer mark.

This timing requires a suspending server-owned path: local enabled/delete methods do not suspend and are not claimed affected. No external HTTP or physical remote side effect was exercised. Cancelling a coroutine waiter does not prove the remote operation stopped. The first Delete probe stopped in startup-drain setup before any target gesture; only its corrected retry qualifies.

Book: chapter7 printed p.149 / PDF p.158 (asynchronous handlers) and chapter17 printed p.326 / PDF p.335 (grouped exclusive weather refresh and late-result suppression). The book explains mechanics; the admitted-write and selection-ownership finding comes from the current service/UI behavior. A latest-result read example is not a mutation policy.
