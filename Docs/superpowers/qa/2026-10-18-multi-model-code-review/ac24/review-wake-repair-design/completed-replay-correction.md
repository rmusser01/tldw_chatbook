This supersedes the SYSTEM-carrier diagnosis and all carrier-specific production changes in `review-wake-repair-design.md`. The accepted-authority, pinned-capacity, postawait fences and actual post-plan stage-reachability requirements remain in force. This is a read-only source design; no tests, implementation, Git changes, network, configuration or credential reads were performed.

## Corrected facts and scope

The earlier diagnosis incorrectly treated the persisted wake SYSTEM row as the model row. The actual controller deliberately excludes transcript SYSTEM from ordinary history and appends the current AGENT_WAKE/GOAL notice as a trailing payload USER, after per-send transforms (`console_chat_controller.py`, original lines10942–10964). Acceptance separately persists the SYSTEM row with automatic origin. Keep both projections and their authority/provenance exactly as they are. The standalone mixed-carrier fake-HTTP case proves a separate edge, not this live wake's cause. Remove/revert the proposed late-SYSTEM distinct_roles selection and its associated Safe-capture change. Keep the strict engine system-carrier check unchanged.

The actual configured Console fixture now exposes the relevant replay mismatch: a completed first-primary private checkpoint reaches the real hosted handler, but saved model history has the collapsed final assistant row without its earlier native assistant/tool batches. `hosted_provider_engine._apply_continuations` requires an ordered exact owner for every checkpoint round and fails with `Custom Hosted continuation owner is missing` before physical HTTP. Do not drop the retained group or relax `_find_owner` to hide this mismatch.

## Smallest replay owner and algorithm

Keep controller history admission as the source of truth: `_provider_message_payloads` builds visible saved rows; `_provider_continuation_sidecar_for_session` selects active-path owners; `_provider_continuation_history_for_resolution` rejects active checkpoints without explicit recovery and filters complete groups against the frozen target. Gateway target checks retain raw selected provider, canonical execution family, protocol, model and normalized full base. Edited/deleted/inactive/mismatched owners must continue following their existing refusal/omission policy. The fix does not grant a stale checkpoint a replacement visible owner.

Reuse the canonical projection already implemented by `ConsoleProviderGateway.expand_provider_continuation` (approximately3646). It round-trips through the closed checkpoint validator, then emits each recorded assistant content/tool-call batch followed by its exact recorded tool results. It preserves IDs, function names and original argument strings; it intentionally does not put private reasoning into ordinary `content`. Its existing callers are the controller's explicit Resume path and `agent_runtime.expand_restore_history`. Leave those explicit active-Resume admission/side-effect semantics unchanged. Factor the pure canonical row projection into the existing continuation domain only if needed to avoid importing the gateway into the prepared serializer; preserve the existing gateway method/callers as delegates. This is a small reuse of one translator, not a new replay service or state store.

Choose the prepared-request serialization owner for historical expansion, not the transcript/store or mutable agent messages. A retained complete group attached to its exact collapsed saved assistant owner projects to its canonical ordered assistant/tool rows at that same position in the final provider payload. Replace that collapsed owner once; do not append both canonical final text and the old final row. Require the terminal canonical assistant content to agree with the currently admitted visible owner (including the existing revision/current-owner guards); refuse unexplained disagreement rather than invent text matching. The last canonical terminal row carries the final content exactly once. All preceding/following conversation rows stay in sequence. The engine still receives the matching checkpoint privately and attaches required reasoning at its existing exact-owner seam.

Restrict the new projection to completed retained history using the engine wire contract that currently expects explicit native owner rows. Do not change Moonshot/DeepSeek/local replay policy merely because they also have sidecars. A current active checkpoint already accompanies live native rows; it must not be re-expanded. A historical group already represented as the exact canonical sequence must either be recognized by full ordered equality and reused once or rejected as a malformed duplicate; no fuzzy substring/call-name matching. A serialized ID or arbitrary model text cannot select expansion. Explicit active Resume stays solely behind the existing restore gate. Completed history replay executes no tool and gives no renewed permission.

The bridge must preserve the selected complete groups alongside later active current-run groups. Its `continuation_groups` path normalizes owner keys before `ConsoleAgentTraceRequestFactory.build`; the constructor-sidecar fallback path is separate. Both must reach the same final serialization projection. Do not solve only the sidecar fallback, discard prior complete groups when a current group appears, or send a primary's history to a routed child. Use existing one-owner-per-group and immutable whole-unit rules, not additional marker fields or a new registry.

## Accounting and retention

Keep one collapsed semantic assistant owner plus its canonical private group as the budgeting/eviction unit. Expand only the selected final wire projection, after ordinary whole-unit selection but with counting using the same candidate projection during fit checks. Evict the entire owning conversation unit and its group together; no orphan tool rows or partially retained rounds. Input accounting must include the replayed assistant/tool bytes plus required private reasoning. Audit `_count_wire` and `count_provider_continuation_tokens`: they currently add a full private-round JSON charge on top of serialized messages. Replaying those same calls/results into messages must not silently double-charge them or omit reasoning; adjust only the completed-expanded contribution while leaving active/live accounting policy intact. Preserve final overflow refusal, response reserve, unknown capacity and normal safety windows. No larger context/default budget.

## Capture On is a real additional gate

Capture Off and On must share identical expanded provider values. Preserve saved semantic admission before expansion: a generated native tool row is not literally the saved final assistant revision. The prepared serializer/provenance projection must express each replayed row as a deterministic derivation of the exact saved assistant owner and its admitted CONTINUATION_ATTACHMENT under the same frozen policy. Use the existing derived-transform/artifact mechanism, retaining continuation ownership rather than forging SavedRevisionTraceProvenance on each expanded row. Reconstructed final kwargs, handler projection, Safe/Full capture, tool-loop indices and actual wire rows must agree; no post-shadow kwargs surgery. Private reasoning remains sidecar/trace data and never enters ordinary assistant text, logs, summaries or metadata. Safe policy continues redacting its governed material, with Full respecting existing capture authority.

Concrete source limitation requiring root assessment before adopting a trace edit: `CompletedToolTurnWitness.descriptor_count` and `matches_descriptors` (`console_trace_final_values.py`, approximately328–373) currently describe one saved assistant descriptor between source/current USER. `console_trace_runtime` constructs the witness from the immediately preceding saved assistant. `console_trace_service._validate_completed_tool_turn` checks that exact descriptor count, verified terminal response link, conversation/current turn and exact saved revision values. An expanded historical sequence cannot simply be inserted into controller/bridge rows and declared equivalent. The earlier suggestion that existing distinct_roles provenance was sufficient does not address this real replay boundary.

If final prepared replay projection requires an additional completed-turn alignment case, root must approve that exact narrowly derived case before implementation: validate the same terminal saved owner/revision and admitted private checkpoint, recompute the canonical expansion and compare every output row in order, and retain all current origin/terminal call, policy, sequence, range and closed/discarded/current-owner constraints. Do not accept an arbitrary span of TOOL_CALL/TOOL_RESULT artifacts, broaden completed-turn lineage, or call a still-running owner's custody historical authority. Reuse current bounded witness/surface machinery; no separate trace registry/schema/codec. If it cannot represent the deterministic projection without a new trace contract, report the exact blocked contract for a further root decision rather than weakening it.

The managed current-owner projection is distinct: durability may replace sensitive arguments/results with their policy projection (`agent_runtime.project_continuation_checkpoint`). Historical expansion consumes that actual admitted persisted checkpoint, including its stored projected bytes; it cannot recover raw data from an old live stream. The 923439 trace live-native-custody/acknowledgment mechanism is restricted to its active issuer/generation and must not be repurposed to resurrect a completed owner. Keep codec, GC, delta retention and live acknowledgment unchanged unless root explicitly assesses source-proven necessity.
