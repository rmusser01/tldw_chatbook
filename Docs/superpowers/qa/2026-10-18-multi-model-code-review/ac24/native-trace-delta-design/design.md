## Recommendation and evidence

Keep continuations in the semantic surface. Add one narrowly typed **live native continuation advance** to the existing admission/delta/capability machinery: replace exactly the active continuation node for one already-owned assistant while appending the newly admitted message suffix. It is distinct from `CompletedToolTurnWitness`, which requires a terminal preceding turn and `fresh`/`agent_first`; this operation is restricted to the existing `tool_loop` chain.

Do not move the evolving checkpoint to a call-header overlay. The rendered-system exception in ADR097 is a special first-slot override, not authority for private multi-owner continuation history. Endpoint projection was a separate final-values bug and its repair must remain scoped.

The supplied `native-after-endpoint2.log` contains the three actual-Console Capture On failures for `(rounds,batch)=(2,1),(3,1),(2,2)` before POST3. The parent and endpoint implementer independently established successful first two request shadows/headers. The reported changed-domain counts agree exactly with source: prior `messages=[USER,A1,T1], continuations=[C1]`; incoming `messages=[USER,A1,T1,A2,T2], continuations=[C2]`. Prefix 3, incoming changed 3, active changed 1; multicall prefix 4 and incoming changed 4. `prepare_current_surface_delta` compares domain order, and its `count_or_span` branch admits only one replacement or a completed-turn compound. A larger count limit alone proves neither ownership nor the two domains' ordinal semantics.

The source also establishes a second requirement: replacing C1 with the entire C2, then C3, repeats all prior rounds. Whole-artifact deduplication does not deduplicate different growing checkpoints. A complete repair meeting ADR097's storage requirement therefore needs a small continuation-specific stored delta projection as well as the typed admission. This is necessary representation work, not a general trace framework.

## Admission contract

The following are cumulative requirements, not alternatives:

1. Existing attached conversation/trace owner, segment and exact current predecessor head; same originating user semantic revision, exact actor+chain run, next logical call and `tool_loop` route. Prior call must be the latest eligible response-bearing call in that same chain, using current runtime rules. An ERROR retry cannot acquire this advance; it may only reuse the unchanged failed request. No new authority from equality of text, model or endpoint origin.
2. Exactly one changing live continuation group. It belongs to the host-admitted current assistant generation, on the same active path and accepted run. The assistant owns the already completed dispatch handoff; do not recreate deleted dispatch ownership. Recheck the current persisted message version, active checkpoint revision/state and generation custody. No remote/foreign/discarded/stopped/stale owner. A sidecar owner string alone is insufficient.
3. Exact raw selected-provider identity plus canonical provider/protocol/model/full continuation API-base tuple match the already captured host target and durable V3 binding. Origin-only disclosure endpoint and adapter API-base projection are not replay authority. No alias/config re-resolution, session-only destination upgrade, binding downgrade or managed-envelope removal. Existing legacy direct-provider eligibility remains unchanged; a pinless virtual owner gets no new admission.
4. Old message domain is an exact unchanged prefix of incoming messages, with existing provenance/value checks and the existing rendered-system exception only. No dropped/reordered call/result/user/steering rows, changed historical args/results, compaction, truncation or transformed-source repin. The append suffix is the exact host-prepared suffix. It contains exactly one newly finished native batch (one assistant plus its ordered tool-result rows), with matching call IDs, names, raw argument strings, exact capped results, and no pending/executing call. Any accompanying steering rows need their existing host provenance and exact position, never guessed from role/text. Bound suffix count to the existing 256-node admission bound; fail visibly outside it rather than split an unauthenticated operation.
5. In continuation-domain order, all other groups retain exact owner/order/descriptor/value. They may precede or follow the current group. Do not require that the current owner be the only continuation. The changing group's attachment is to the newest exact batch in the append suffix; the historical message prefix remains intact. Replacement targets precisely its old active continuation node: start=end, span=1, exact physical sequence and predecessor head. No neighboring continuation or message node is covered.
6. Strict raw checkpoint parse succeeds. New checkpoint keeps execution identity/schema binding and is active; its round count is old+1; **every old round including reasoning, assistant text, call order, arguments, states and results is exactly equal**. The added round exactly matches the batch/results above. Revision is the current durable acknowledged revision after legal transitions (not guessed from batch size). Current managed state is authenticated by the existing managed continuation owner, not by trace.
7. Same exact frozen within-run disclosure policy and preparation identity. Prove raw custody and prior raw-round equality before sanitization. Then independently verify the whole final semantic kwargs through the existing issued surface and shadow machinery. Comparing redacted bytes alone cannot prove raw identity. No trace-only checkpoint may authorize tool execution or Resume.
8. The admission is consumed once and revalidated under the existing transaction/custody fences at final dispatch binding. Changed predecessor, owner version, checkpoint revision, destination, policy or invocation revokes it. Lost/uncertain commit follows existing exact-reservation readback; it does not auto-redispatch. A rolled-back attempt may be retried only through the existing owned retry path.

First addition C1 has no replaced continuation and remains an append, but it must establish the same host-issued current-owner provenance used by the later advance. Do not infer the owner of an old untyped artifact after restart from matching bytes. Cold eligibility needs durable owner evidence already established by the earlier call, or the existing explicit recovery must re-establish custody. Historical calls without that evidence remain readable, not newly authoritative.

## Typed proof and who validates it

Use one small frozen, capture-only `LiveNativeContinuationWitness` (name provisional) next to `CompletedToolTurnWitness`, and the existing prepared-surface capability issuer. Required facts are bounded identities/scalars: exact current assistant persisted ID, current message/checkpoint versions, origin/previous call, run/turn/owner/segment, predecessor node and old continuation slot, current continuation ordinal, appended-message start/count, previous/new round counts, and the already frozen selected/canonical destination binding. Much is already in admission/reservation; reference it rather than duplicate it in a new serialized object. No transcript list, old-round list, private text, persistent body hash or owner registry.

It must also retain/identify the **existing host-owned invocation custody** that supplied the raw checkpoint. The store/bridge validates current generation and acknowledged persistence, including any tool-private projection and managed sealing. The trace factory validates call/run ancestry and plans the exact range. The trace service validates raw prefix/group/batch relation, policy and issued capability; the independent final-value verifier binds it to actual kwargs. Final persistence rechecks the same durable owner/version and predecessor in the caller transaction. Pure dataclass construction never grants authority.

Important existing mismatch to avoid: runtime raw checkpoints may differ from saved checkpoints because `project_continuation_checkpoint` removes sensitive tool bodies and the store signs managed envelopes. Do not weaken equality by broadly ignoring fields. Reuse the exact existing host projection/finalizer provenance to attest the relation, preserving raw full prefix comparison on the invocation-owned values. If that relation cannot be proven for a shape, refuse it. Do not compare a raw checkpoint directly with a differently projected durable checkpoint and then add ad hoc exceptions.

For this smallest repair, attach the prior live owner/custody facts to the existing service-issued parent capability when C1 is first admitted; extend that capability rather than introduce a registry. Do not add a durable receipt solely to invent cold live-advance authority. A lost invocation capability cannot authorize a new mixed advance from sanitized trace bytes alone: refuse that shape and retain existing explicit recovery. Cold historical reconstruction must work. An explicit Resume may establish a new eligible chain only through its existing admitted recovery path; this witness grants no extra Resume authority. Include a negative cold mixed-advance test and a positive existing explicit-Resume regression. If that existing Resume route itself requires cold mixed advancement, stop and amend the design with the exact missing durable source proof before claiming resume compatibility; do not silently broaden this live witness.

## Atomic delta and ordering algorithm

Use the existing two operations in one transaction, not a new generic event family:

- Prepare per-domain deltas `message_suffix` and one `continuation_replacement`. They are not a single contiguous provider-order slice. Keep the existing message-then-continuation canonical shadow order.
- The replacement carries `component_name=provider_continuations`, the exact continuation domain ordinal, its physical ordinal, and old-node span=1. `VerifiedSurfaceDelta.items` carries only new message items with ordinals beginning at the old message count. Do not force the replacement to be canonical `items[0]` or renumber all items from its ordinal.
- Validate all proof before writing. Append the new continuation node using the current replacement helper; append one existing `surface_replace` event referencing old node and predecessor head. Append each new message node and existing `surface_append` event in original suffix order. This physical continuation-first append is valid: reconstruction already groups domains while preserving order within a domain. Retained other continuation groups keep their original positions in the projection.
- Build child descriptor/value roots with one removed continuation and appended continuation/message descriptors. Preserve all old tool-loop message indexes and add the actual new tool/steering indexes at their message ordinals. Current continuation replacement code rejects any new tool-loop indexes; the narrow witness branch must compose them correctly.
- Persist verified header, final new surface head and reserved-call dispatch binding with those events in the existing transaction. No intermediate call head is exposed, and no call refers to a half-applied pair. Prior call heads/events/artifacts remain immutable. Rollback leaves neither replacement nor appends; ambiguous commit gets existing readback reconciliation.

Do not generalize completed-turn authorization. Keep both witness types mutually exclusive and use the same lower-level range/capability mechanisms. Existing plain append, no-op, one-value replacement and completed-turn behavior retain their contracts.

## Linear continuation storage and historical reconstruction

A full checkpoint artifact for every Cn would store O(sum n) prior rounds. A fixed 128-round ceiling bounds damage but does not establish ADR097's linear-growth guarantee. Likewise, an array of all prior round/artifact IDs in every header still creates quadratic metadata. Neither is an acceptable final implementation under the requested contract.

Smallest viable representation: use the **existing single-node replacement edge as the predecessor reference**, and a narrowly versioned continuation-advance artifact containing only the complete new top-level checkpoint metadata (excluding `rounds`), prior round count, and the one newly added sanitized round. Keep first checkpoint/full historical artifact reads unchanged. The storage encoding is trace-only; actual provider kwargs and current assistant checkpoint remain the existing full canonical format.

A distinct artifact normalization tag or equally unambiguous typed component is needed so ordinary user JSON cannot be interpreted as a delta. This small private storage format is justified by the observed growing checkpoint and linearity requirement; do not create generic JSON-patch machinery. It has no caller-chosen predecessor ID: resolve the predecessor from the existing `SurfaceReplacement` start=end edge for that exact replacement node. Require same continuation component, lineage, policy, monotone predecessor sequence and one unique matching edge. Stop at a full base artifact. Bound traversal and reconstructed payload by existing checkpoint limits (128 rounds, 128 calls, 8 MiB and existing reasoning/argument limits), reject cycles/missing/duplicate/wrong-domain edges, and decode sanitized history as a projection, never as execution-ready state.

Sanitize and PII-project the **full** candidate under the frozen policy first; verify its old projected rounds still equal the predecessor's projected rounds before storing just the new round. This matters when a newly known credential would otherwise change the old projection. If they differ, do not write an invalid delta or silently retain newly exposed secret bytes; take the existing honest unavailable/refusal path. Existing full-value sanitizer/alignment rules still run. The compact representation is selected only after final-value verification, and reconstruction must exactly equal that verified sanitized full checkpoint.

Service durable-value resolution/comparison and native reader must use one shared resolver for this representation. They must not accidentally expose the encoded delta as a provider checkpoint. Child capability values continue to carry full immutable dispatch values, so no raw provider input changes. A typed artifact keyed by its bytes must not be reused without the exact node/replacement context; decoding is node-aware.

GC already marks replacement predecessor/start/end/replacement nodes and recursively marks node predecessors (`console_trace_maintenance.py::_mark_surface_nodes`), then marks their artifacts. This reuses real reachability edges rather than hiding new artifact IDs in JSON. Verify archive/copy/fork routes keep the replacement relation; do not assume generic artifact copying alone preserves the representation. Detached-owner collection must retain a shared fork's prior rounds and reclaim them once the final owner disappears. No new mutable continuation table or persistent process registry.

Storage claim must be narrow and honest: new trace-owned retained bytes are O(unique newly captured round/message bytes + bounded per-call metadata), not O(round-count squared). Current assistant checkpoint, existing sync history, native runtime memory, and materializing a full request are separate owners/costs. No claim that all application storage or reconstruction CPU becomes linear. Measure actual trace blobs and metadata, not compressed DB size alone. Avoid a full checkpoint hidden in another header/debug artifact.

## Alternatives rejected and ADR/migration decision

- **Header placement like rendered system:** smaller admission patch but loses proper continuation surface ownership/replacement lineage, repeats growing content and does not solve raw/durable custody. No special endpoint position authorizes it.
- **Raise count limit / allow arbitrary replacement+append:** bypasses the missing owner/round/batch proof and current domain-index assumptions; changed ordinary history can be mislabeled as evolution.
- **Reuse completed-turn witness:** live response-bearing tool chain has no completed saved response/new-user transition. Faking one erases its security meaning.
- **Replace full checkpoint each time:** correct point-in-time values could be reconstructed, but repeated old rounds violate requested linear trace ownership. Cannot call the 128-round bound linearity evidence.
- **Reference only the mutable latest assistant checkpoint:** cannot reconstruct older calls after advancement; COW full old checkpoints merely moves repeated bytes to another trace-owned location.
- **Drop continuation / reset to omission / Capture Off / prune private groups:** changes requested fidelity and provider input, and weakens existing guards.
- **New generic registry, owner, patch engine or round table:** unnecessary; one existing owner, existing replacement edge and one typed private delta format suffice.

ADR required: **yes, amend ADR097 before implementation**; existing ADR063/179 own checkpoint custody and hosted transport, and ADR240 task notes must link the amendment. Record the narrow live proof, atomic mixed-domain operation, compact storage semantics, corruption/privacy behavior and rejected header/full-snapshot alternatives. Update the trace design spec and architecture callers. This is a new admission interface and stored semantic projection, not a routine count fix.

SQL migration: **not inherently required** if existing artifact normalization metadata and surface replacement edges carry the versioned format; preserve legacy full artifact reads and never reinterpret existing bytes. No new checkpoint JSON version is required (V3 current-owner format stays unchanged). Audit DB guards, artifact codecs and archive/import assumptions before asserting schema-free completion; if implementation needs a new constrained column/table, use the normal schema migration and revise this design first. The read/collector changes are part of the repair, not follow-up cleanup.
