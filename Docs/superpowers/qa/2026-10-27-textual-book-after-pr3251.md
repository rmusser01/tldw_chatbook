### 1. Evals: Save publication replaces newer child input

`UI/Evals/bench_editor.py:344–360,1326–1345,1435,1510` commits the form and posts `Saved(bench_id)`. `UI/Screens/evals_screen.py:949–960` reselects the bench; `select`/region swap at533–549/634–637 replaces its editor. With the parent pump held, the real Save button event commits `Saved`, and focused-child keys then produce `Saved-new`, dirty, focused, caret9. When the parent consumes the queued publication, a new Input contains `Saved`, caret5; DB still correctly contains the submitted `Saved`. Ordinary Save passes.

This establishes loss of **later accepted draft input**, not a failed DB write, natural race frequency or an observed character-bench failure. Save is the real button event via `.press()` and later input uses Textual Key messages; no OS/native terminal claim. The harness hold controls parent scheduling only. The existing voluntary discard of an already-present new-target mini-form is a separate boundary. Repair should keep submitted data committed and later data uncommitted while retaining editing context.
