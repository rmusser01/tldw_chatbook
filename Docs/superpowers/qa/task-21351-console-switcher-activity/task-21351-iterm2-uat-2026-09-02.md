# TASK-21351 iTerm2 native walkthrough — 2026-09-02

## Result

PASS for the available macOS half of equal-cell native-terminal parity. The
Ctrl+K switcher opened in iTerm2 at a 160×45 terminal canvas, preserved its
35-row ceiling, exposed Active and History without clipping the Cancel and
paging controls, targeted the most-recently-used other tab on blank Enter, and
opened the exact highlighted saved conversation from semantic History search.

The walkthrough also found and corrected one real defect: History forwarded
`workspace:roleplay` to conversation FTS, even though workspace labels are not
part of that index. The query therefore returned `No matches`. The repaired
path separates semantic tokens from FTS text, resolves workspace labels to
workspace IDs, supports the visible `Chats` label as the union of global and
default-workspace conversations, and consumes History's `saved` / `is:saved`
aliases. The fix is commit `c5e5918bf63f52f008f550d975cdf1155fcc0794`.

Windows Terminal remains the only native parity blocker. TASK-21351 and
TASK-21351.1 therefore remain In Progress.

## Walkthrough

1. Opened three native Console sessions, selected Chat 3, and invoked Ctrl+K.
   The switcher opened in Active and highlighted Chat 2 as the MRU other tab.
2. Pressed blank-query Enter. Chat 2 became current.
3. Reopened Ctrl+K. Chat 3 was now highlighted, confirming reciprocal MRU
   behavior rather than positional next/previous behavior.
4. Switched to History with F3. Eleven saved conversations rendered under the
   local `TODAY` calendar group with the footer controls still visible.
5. Entered `workspace:roleplay`. The first run exposed the FTS/domain-filter
   defect and displayed `No matches`.
6. Repeated the same query after the repair. Exactly two `Roleplay Tavern`
   conversations appeared: `Landscape roleplay scene` and
   `Portrait roleplay scene`.
7. Pressed Enter on the highlighted `Landscape roleplay scene`. The modal
   closed, the exact saved transcript loaded, and the Roleplay workspace became
   active.

The accessibility driver successfully delivered Ctrl+K, F3, Enter, and native
window snapshots. Its text-entry action moved the terminal cursor instead of
writing to Textual's input, so the semantic query bytes were delivered to the
same attached PTY with `tmux send-keys`; a fresh accessibility snapshot was
taken before and after each interaction. This limitation affects the automation
mechanism, not the application result.
