# Speech preload import follow-up

The lazy dictation level meter now uses its existing stdlib PCM16 RMS calculation. It no longer imports NumPy when the Speech screen is preloaded. Recording and transcription retain their existing NumPy requirements, privacy, callbacks and lifecycle. Empty or malformed meter input now consistently produces zero; buffer, captured-byte and queue flow are preserved.

A real current-source Windows capture found a background Speech preimport loading NumPy while the UI waited in thread startup and the original workspace worker was idle. This is one concurrent stack snapshot, not proof of the complete setup delay. Compute-only profiling measured the existing stdlib meter at median 15.9 microseconds for a 320-sample frame and 1.54 milliseconds for the 32,000-sample maximum. These are not UI latency measurements.

Original fresh-process module and Speech-route checks failed at the real NumPy import; the empty-input callback retained a stale level. The repaired source passes all 12 focused cases, including isolated real entrypoints, a capability-query versus actual-import control, and actual PCM callback values and flow. All socket operations in those children remain denied; only the exact already-refused urllib3 IPv6 capability probe is classified separately. No fake NumPy or route module is supplied.

Affected verification has 45 Audio passes and one passing preimport payload guard. Two capture-release constructor failures reproduce on unchanged dev8b before meter assertions. The Windows import count retains the same strict 688-limit failure as exact dev8b; no limit was raised. The product's existing E402 diagnostic is unchanged, and the new test passes Ruff and formatting. The required fast lane retains all 167 prior targets and appends this module; its missing-owner regression went RED to GREEN, and all 119 queue contracts pass. The UI census remains 1,816.

Independent source review is clear. Full-diff/AST comparison confirms the two intended source edits and unchanged unrelated UTF8 strings; an earlier encoding error was corrected from preserved original bytes before publication. The [source and receipt manifest](audio-meter-source-manifest.json) binds final files and retained evidence. Existing [ADR097](../../../../backlog/decisions/097-boot-budget-ratchets.md) and [ADR284](../../../../backlog/decisions/284-console-model-preparation-physical-ownership.md) apply; no new dependency, authority, storage or lifecycle boundary is introduced.

Native/browser timing remains unqualified with zero qualified samples. The PR stays draft and auto-merge stays off. A new source freeze and real capture are required after this repair; these unit/import results do not establish that the full Windows setup stall is resolved.
