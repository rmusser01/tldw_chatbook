# Execution decisions and costs

These are all rulings recorded during the approved implementation, in order. Their costs remain part of final review.

1. Ruling: Allow functional UX Tasks 2–5 after the supported private control and reviewed recorder, deferring unavailable native/browser presented-frame baseline qualification to the final gate — the binding spec requires evidence before choosing performance fixes and truthful final qualification, while the plan assumed an unavailable capture capability — cost if wrong: transport measurements may require later UX rework and final completion remains blocked; retain the unchanged source baseline and make no speed claim or speculative optimization.

2. Ruling: Allow an optional display-only captured authority constructor input for local/virtual providers, supplied by the owning turn controller with None retained for legacy callers — their authorization closures provide no readable profile identity and the spec requires truthful captured scope — cost if wrong: misleading scope or call-site breakage; validate default compatibility and unchanged gate/stamp behavior.

3. Ruling: Display Default for the actual default permission-profile key and the exact captured ID for named profiles — this permission store provides IDs as names and external MCP connection labels describe a different owner — cost if wrong: less friendly labels until a real owner naming API exists; no invented profile name or storage change.

4. Ruling: Include the shared high-risk reason-copy helper in chat_approval_card.py in Task2, limited to the already mandated truthful correction — the task file list omitted the widget that owns this existing copy — cost if wrong: a small shared copy regression; targeted reason tests cover it and controls remain Task3.

5. Ruling: Drop captured view/presentation_revision only from the existing settled, nonactionable finishing payload transitions — their filtered calls no longer match the approval snapshot, and decisions are disabled/refused in phase finishing — cost if wrong: a stale or incomplete finishing display; test actual filtering/nonactionability and retain the legacy changed-call guard. Any answerable replacement must instead receive a new owner-captured view/revision.

6. Ruling: Preserve separate original owner arguments before local approval-summary formatting, through an optional display-only pending capture field or equally small seam — existing local summaries cannot satisfy the approved complete/canonical snapshot contract — cost if wrong: body exposure or incorrect Details content; keep legacy summaries and authorization unchanged, exclude capture from repr/equality/serialization, and test omitted/transformed nested fields.

7. Ruling: Keep Task2 full completion open for unsupported actual Windows virtual dispatch, but allow independently specified controls/Details/feedback to use the reviewed capture foundation — guarded BASE/HEAD comparisons qualify all three local pending cases and attribute identical virtual refusal to the unchanged native/stat root-identity boundary; repairing that boundary would change a security/runtime contract outside this UX work — cost if wrong: later supported dispatch may reveal integration rework; preserve the open invocation requirement, all guards and final qualification, with no successful-dispatch or full-green claim.

8. Ruling: Paint captured action_label, identifying targets, profile/location and consent scope in Task3 compact rows when view is supplied — Task2 produces request facts and the approved card must show them before committing; the dispatch phrase feedback-owner projection referred only to Task5 receipt/settlement/grant/execution outcomes — cost if wrong: added row height can reintroduce clipping; use bounded literal previews, preserve raw viewport/legacy fallback and verify actual-owner compact hit targets. Full generic Arguments pages remain Task4.

9. Ruling: Continue approved tasks inline with executing-plans after both agent followup and replacement hit the harness thread limit — no functioning subagent dispatch remains, while reversible authorized work can proceed — cost if wrong: author-only verification is weaker than fresh independent review; preserve that limitation and make no independent-review completion claim.

10. Ruling: Add compatible optional actual_scope to publish_grant_application so actual writer reports what it wrote rather than inferring from selected UI scope — original Task5 helper lacked a scope input but explicitly requires actual coalesced scope evidence — cost if wrong: one extra display-only keyword/interface clarification; callers remain compatible, and scope values never authorize. ApprovalDecisions observational map is already a planned requirement, outside verdict entries/stamps/serialization.

11. Ruling: Add compatible optional confirmed_backend_start=False to ApprovalFeedback — execution_state alone loses real start evidence when a started call later fails or a start signal arrives after completion; preserve the fact without regressing the stage or deriving it from dispatch — cost if wrong: one extra display-only immutable field and projection validation; no gate or verdict changes. Implementer adding RED/GREEN terminal-copy/start-retention, observer-failure, fallback-transfer and nested-correlation tests before commit.

12. Ruling: Author independent Task6 guide/artwork and integration tests alongside Task5 final commit/review — approved public interfaces and functional behaviors are established, these edits do not change shared product behavior, and final integration still gates on the reviewed Task5 commit — cost if wrong: later documentation/test rework only; no qualification/completion claim until actual receipts. Native/browserAC3 remainsopen.

13. Ruling: Require explicit legacy_observation_key metadata for tool-name observation fallback; default false and excluded from equality/repr, set by the virtual owner only when the original call ID is absent. Register legacy keys separately from exact call aliases — guessing from ID text could attribute another call’s grant. Cost if wrong: extra display-only metadata plumbing; verdict/stamp keys and permission effects remain unchanged.

14. Ruling: For large grouped target lists, preserve all complete targets in the captured view and complete redacted Details, while showing a bounded initial preview with explicit remaining-target/continuation copy. This clarifies the earlier full-target row ruling against the spec’s large-list requirement; ordinary identifying targets must not be silently clipped. Cost if wrong: users may need an extra Details gesture to distinguish omitted targets; the count/omission marker and complete captured pages must make that visible before consent.

The temporary author-only review gap in decision 9 was subsequently closed by reusing completed reviewer threads for Task3 fix2 and Task4. Transport qualification remains open.
