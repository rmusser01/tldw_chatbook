# Stable private profile launch contract

Frozen source: HEAD 7d79700e025310e43ab9537ee65bb1792cfe2ba1. This is source-only launch/ownership evidence, not an executed recipe or performance finding.

## Conclusion

A supported stable profile can live entirely below this worktree's .superpowers/k5-scale/profile (or another caller-owned plan artifact directory). Select it in the *new process before app/config imports*, keep the same paths on every restart, and let the real config API select/create its DataRoot. For an app-factory test, pass that exact DataRoot as _build_test_app(user_data_dir=...). The factory parameter alone does not relocate the real project-index runtime: runtime._AdmittedStoreFactory.retain calls config.get_user_data_dir() later, outside the factory's constructor patch (tldw_chatbook/Workspaces/project_index/runtime.py:78-111; Tests/UI/app_factory.py:403-507).

3. With no [paths].data_dir override, the actual default base is <root>\home\.local\share\tldw_cli, and the shipped general.users_name is default_user, giving DataRoot <base>\default_user. Source: profile_paths.py:32-35, :77-90; tldw_chatbook/config.py:4064, :10888-10896, :11171-11193. 4. Restart sequentially with the identical environment and config path. App entry calls admit_startup before runtime/config imports, and that admits the selected profile or fails closed (app.py:1-20; tldw_chatbook/Backup_Recovery/storage_admission.py:1520-1554; tldw_chatbook/Backup_Recovery/bootstrap.py:501-554). Retire app workers, DBs and instance locks through their owners before restarting or cleaning; factory teardown explicitly orders runtime before DB/native handle close (Tests/conftest.py:463-493; Tests/UI/app_factory.py:218-255). Leave caller-owned profile bytes in place while comparing restarts. Delete only the specifically chosen private root after all processes/owners have retired.

## Pytest/app-factory variant

- Tests/conftest.py supports an externally supplied TLDW_TEST_CONFIG_ROOT. It uses that root (rather than mkdtemp), creates its own profile/config/home directories, sets HOME, USERPROFILE, XDG_CONFIG_HOME, XDG_DATA_HOME and TLDW_CONFIG_PATH *before importing app*, and only session-deletes a root it created itself (Tests/conftest.py:18-72, :1149-1170). A test needing the collection-time selected profile can use the registered bootstrap_profile marker; otherwise the autouse fixture may redirect to tmp_path and break source-bound config admission (Tests/conftest.py:1126-1138, :1270-1301, :1683-1706). The private_profile_test decorator deliberately launches into tmp_path/private-profile-process/profile and is unsuitable for a persistent cross-process corpus (Tests/private_profile.py:216-261).
- In that isolated process, obtain data_root = config.get_user_data_dir() from the *actual selected config* and pass _build_test_app(user_data_dir=data_root, preserve_profile_admission=as_needed). This is an existing supported caller-owned input: the path must already exist, resolves strictly, and is not appended to _created_dirs; factory-created defaults are appended and deleted by drain_created_dirs (Tests/UI/app_factory.py:277-348, :226-255). The factory still records and closes its constructor-owned DB handles and app instance lock, and its subscriptions path patch stays live until teardown (app_factory.py:34-54, :350-367, :507-519; Tests/conftest.py:426-493).
- The factory is a test app with many real I/O seams faked during __init__, including load_settings, local DB path getters, media/notes/providers and runtime policy (app_factory.py:285-333, :398-507). It is suitable only if the desired K5 path actually uses the real index runtime after construction. Its config_overrides change an in-memory snapshot, not durable config; use the real selected config file/config writers for settings the runtime rereads (app_factory.py:68-140, :143-175). The index runtime's own DataRoot lookup must equal the factory user_data_dir, and its retained activation/restore admission still governs actual operations (runtime.py:78-124; tldw_chatbook/Backup_Recovery/activation.py:183-221).

## Authority and unknowns

- TLDW_CONFIG_PATH (or --config) selects the config file, but the default bootstrap root follows Path.home at import time and the default DataRoot follows HOME at call time. Set HOME and USERPROFILE before Python import. Do not rely on a post-import env flip; the config module caches selected source and participants can refuse raw_source_selection_changed. Source: profile_paths.py:21-35; config.py:569-596, :10667-10689; Tests/Backup_Recovery/config_test_support.py:32-60; Tests/conftest.py:1270-1281.
- startup_permission inspects pending/profile/registry records and denies uncertain or pending overlapping recovery; execution_scope additionally checks exact retained storage scope, restored source overlap and activation_permission. Stable paths do not waive those checks (bootstrap.py:501-545; activation.py:50-137, :183-221). A real restored profile may require owner approval; no report step bypasses that.
- The exact ACL/privacy qualification of the chosen .superpowers directory and final app lifecycle behavior were not exercised here. The smallest next evidence is a fresh process read of get_cli_config_path(), bootstrap.default_bootstrap_root(), get_user_data_dir(), verified_data_identity() under the proposed environment, followed by a second sequential process with the same values and a normal owner-retirement record. Those calls must occur under ordinary app admission; no profile copying or private cleanup-list edits.
