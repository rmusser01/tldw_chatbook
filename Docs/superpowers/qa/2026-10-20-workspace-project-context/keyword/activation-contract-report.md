# Frozen-source activation contract inventory

Baseline: 7d79700e025310e43ab9537ee65bb1792cfe2ba1. Source-only; no phase-timing diagnosis or K5 UI review.

## Conclusion

No existing index-facing API lets the current writer skip its repeated store-method admission and activation checks while preserving all contracts. Narrower real APIs exist: acquire_storage(path) returns a counted StorageLease; execution_scope(..., retained=lease) can use a matching exact-path lease but still checks activation; nested same-participant repository operations reuse an operation on the same PID/thread/task. The index does not currently wire a retained store-path lease into its method wrapper. This is absence of a complete supported seam, not proof that a future reviewed seam is impossible or useful.

## Lifecycle and guards

- The idle app retains a service, not a forever authority lease. Each factory retain captures a data-root StorageLease, checks execution_scope with that retained lease, verifies selected config, root-chain and installation/generation identity, and binds an identity in thread-local state. Key mismatch rejects. Source: tldw_chatbook/Workspaces/project_index/runtime.py:36-60, :69-146, :149-188; backlog/decisions/240-workspace-project-context-and-folder-bound-index.md:154-173.
- Start takes the read slot, pin, service lock, store, stable native lifetime, registry fence and durable store claim. The management thread closes its own native DB connection before dispatching the same store object to writer and supervisor threads. Source: tldw_chatbook/Workspaces/project_index/service.py:565-673.
- The writer binds its pin and holds execution_scope for the store DB path during scan. Each unit uses a new _admitted registry fence and exact admit_job claim check. Each page recomputes capacity, then takes a new _admitted fence and calls commit_scan_page. Source: service.py:693-788. The registry fence takes a short BEGIN IMMEDIATE transaction, reads a live nonarchived binding, checks data identity/root chain, builds current exclusions, and must never cover scanning, chunking, joins or cleanup. Source: tldw_chatbook/Workspaces/registry_service.py:2668-2745. Post-commit binding hints only stop local work; durable fences remain authoritative (registry_service.py:2654-2659; service.py:836-840).
- The DB _activated decorator enters _core_operation(store), then a fresh execution_scope for the DB path, rejecting false activation. It decorates admit_job, commit_scan_page and connection opening, among other methods. pending_directories and load_status instead enter kernel transaction/connection, which are themselves core-operation wrapped. Source: tldw_chatbook/DB/Workspace_Project_Index_DB.py:113-128, :212-214, :265-266, :440-460, :598-628; tldw_chatbook/DB/store_kernel.py:103-115, :130-177.
- Page publication independently checks prepared type; under a transaction it checks current scope, enabled/building state, exact job ID/owner token/job revision/authority revision, duplicate digest and cap before writing. Source: Workspace_Project_Index_DB.py:599-667. The supervisor waits for actual writer exit and DB/scanner retirement, checks exact claim under _admitted, closes its thread's native connection, then releases the lifetime, pin and read slot. Source: service.py:799-835; tldw_chatbook/Workspaces/project_index/lifetime.py:24-32, :93-112, :132-148.

## Candidate seams and limits

1. Exact-path retained StorageLease: execution_scope(..., retained=lease) is a real supported parameter. StorageLease.execution_context checks live membership, exact captured PID/bootstrap-root/config selector and resolved selector, primary source and resolved source, then native hold readiness/group. execution_scope still checks selected config, restored shared-source scope, and activation_permission for every owner. Source: tldw_chatbook/Backup_Recovery/storage_admission.py:526-595; tldw_chatbook/Backup_Recovery/activation.py:50-137, :183-221. A data-root lease from _DataAuthorityPin cannot pass the DB-path selection. The outer writer execution_scope yields only bool, not its lease, and _activated calls execution_scope without retained. Current index cannot borrow it across methods without new reviewed plumbing. StorageLease fields and pin.stack are private, not a shortcut API.
2. Same-participant nested operation: _repository_operation reuses an outer operation only for the exact installed participant, checking PID/thread/task, path/parent identity, live lease, pause and native hold. An unrelated registry participant gets independent admission. Source: storage_admission.py:57-101, :112-189; tldw_chatbook/Backup_Recovery/participants.py:369-450. This is internal coordinator machinery, not an index-facing writer API. Even a correctly bounded outer operation leaves _activated's separate execution_scope acquisition/activation per method. _core_closing can refuse native close while a same-thread operation is active; no operation crosses to supervisor thread. Source: participants.py:463-509. The exact index type is installed via optional runtime declaration, not arbitrary subclass/caller name (participants.py:293-366).
3. Process hold/evidence: acquire_storage already shares a counted native _Hold. On eligible non-Windows calls, confirmed unchanged evidence may avoid full derivation while reobserving path/content stamps and epoch; mismatch falls back. Source: storage_admission.py:492-524, :1134-1220, :1376-1517; backlog/decisions/126-complete-local-backup-and-recovery.md:925-1029. This remains per acquisition with pause, participant, fork and selection gates; the shown reuse branch is disabled on Windows (storage_admission.py:1425-1430). It is automatic, not a caller-issued fast borrow.
4. Held SQLite connection: SQLiteStoreKernel holds a connection per thread with true autocommit, idle liveness check, explicit transactions and fail-loud nesting; it does not cache activation or registry decisions. Source: store_kernel.py:45-59, :130-213; backlog/decisions/228-sqlite-store-kernel.md:20-28. Private SQLite ties a counted ordinary lease to the actual native handle and retires it only after native close; failed close retains uncertainty. Source: tldw_chatbook/DB/private_sqlite.py:1479-1535, :1564-1595. No public connection-to-lease borrower is exposed. One transaction across scan units would extend locks over child work and collide with nested transactions and the short-fence rule (registry_service.py:2733-2745).

ADR-240 explicitly retains separately admitted per-store activation beneath the registry fence and rules out an unchecked borrow (lines 163-173). ADR-101's pinned one-shot workspace tool and ADR-102's run-admitted binding govern different filesystem tool execution, not cache SQLite authority (backlog/decisions/101-one-shot-pinned-workspace-tool-execution.md:10-34, :110-124; backlog/decisions/102-console-run-admitted-local-path-authority.md:17-30, :49-56). Architecture reference for kernel scope: Docs/Architecture/database-layer.md:9-13, :43-50.

## Unknowns and smallest follow-up evidence

- The slow phase is unknown from source. Combine this inventory with the implementer's phase profile before deciding whether any admission/activation seam matters.
- If repository-operation acquisition dominates, demonstrate an index-facing same-store owner-thread scope that exits before close_native; verify pause/drain, foreign registry admission and actual native close on targeted cases.
- If storage acquisition dominates, show ownership of an exact DB-path StorageLease and a supported route into _activated, preserving all repeated execution_scope/activation checks and positive retirement. No private token/hold/connection-map access.
- If activation_permission dominates, the inspected activation module exposes no retained approval-result API. A new contract needs explicit selector, restore-history, registry and invalidation proof; retained= only retains storage and still runs activation_permission (activation.py:183-221).
- No finding here weakens per-unit/page registry authority, job CAS, exclusions, maintenance, restore or native retirement.
