## Implemented contracts

ProjectIndexService(store_factory, scanner, authority_reader, authority_fence) implements the brief's enable/refresh/pause/resume/disable/clear/status/revoke/aclose signatures. Operations are synchronous off-thread except aclose. No tool, UI, semantic index, Library setting/scope, or Media/Notes creation changes.

runtime.get_project_index_service(app) lazily composes one owner; runtime.project_index_key(app, workspace_id, binding_id, root) derives an exact caller-selected key off-thread. close_project_index_service(app) never creates an owner and app_lifecycle calls it without requiring a Console. `_AdmittedStoreFactory.retain(key=None)` produces `_DataAuthorityPin`; its bind() exposes only a live frozen identity in thread-local memory, and close() releases the retained real StorageLease/execution_scope. There is no idle lease. Identity hashes selector, private data root identity chain, verified installation identity and restore/rollback generation. Every later operation reacquires/revalidates. Ordinary config saves do not change identity. The existing-owner export `isolated_restore.verified_data_identity()` delegates to the existing verified launch/replacement evidence; activation.replacement_installation_id() keeps its existing result contract via replacement_data_identity().

Paths: admitted data_root/project_index/sha256(canonical JSON(workspace_id,binding_id))/complete_key.namespace/workspace_project_index.db. The sibling sha256(data_authority_id)+'.lifetime.lock' is stable across root/locator changes. All generation children/control/sidecar/lease bytes count within that binding parent. Counting confers no authority. Legacy flat scaffolding is neither inferred nor migrated/deleted.

BindingLifetime uses Windows share-denying CreateFileW handles or POSIX flock open-description ownership. Inheritance occurs at native process creation (Windows STARTUPINFO handle_list, POSIX pass_fds), before child Python/handshake. Only native capability metadata is added to the fixed trusted -I -S base-interpreter bootstrap. Parent references close without POSIX LOCK_UN. Child raw reference remains through native exit. Windows hardlinks/reparse targets and POSIX aliases are refused. The fixed scanner creates no descendants.

The writer closes its actual thread-local native SQLite connection, and a separate supervisor joins the writer then verifies scanner retirement before releasing lifetime and data admission. Repeated aclose cancellation cannot release early. If supervisor creation fails after writer starts, the dispatch caller performs that same physical retirement synchronously. Failed physical proof retains capability/pin and refuses later work. Job exceptions can yield Error after successful native retirement without being misrepresented as native-lifetime failure.

Registry notifications are post-commit hints. Publication and state changes use registry-before-store fencing and exact authority/scope/job/token/revision checks. Chunk preparation, scan requests, binding-size snapshots, process waits, cleanup and identity capture are outside registry fences. Mandatory existing store execution_scope admission remains inside the established nested `_core_operation(store)` provenance seam; it can perform its existing config/activation checks. There is no new bypass or hard real-time fence guarantee.

Store schema v2 adds durable authority witness, scan_seen membership, and legacy-retirement quarantine. v1 claims never acquire native proof merely because a new lease can be opened; quarantine survives Disable/Clear. Incomplete directories retain unseen prior membership; completed directories retire missing direct members/subtrees. Hash-identical captures preserve chunk row IDs. Resume preserves durable frontier; explicit fresh Refresh from a retired partial/error job resets it only after exact native-proof claim CAS. Frontier pagination passes full pages of incomplete directories. Processing filters apply before lexical ranking; widened policy remains Paused until explicit Refresh.
