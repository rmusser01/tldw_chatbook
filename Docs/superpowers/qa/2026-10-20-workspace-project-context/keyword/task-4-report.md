## Implementation and interfaces

- `ProjectIndexService.search(authority: ProjectIndexSearchAuthority, query: str, *, limit: int = 10) -> ProjectSearchResult` reads metadata from the exact frozen scope, unions the run exclusion floor and durable current exclusions before SQL ranking, and accepts only same-read path/identity/hash/live text. Registry/store checks surround Capture without holding a registry transaction during worker I/O. Final disclosure checks scope, manifest, state and registry witness again. Coverage is deliberately None, never broader management totals.
- LocalToolProvider accepts optional `project_index_service` and immutable `project_index_scopes`. Each compatible alias gets an optional read-only `fs_search_index` spec. Composition checks exact workspace/binding, locator, captured DirectoryChain fingerprint and admitted run root identities. The first root may be Off while a later root is Ready; only compatible aliases enter this tool's schema, which retains existing definition-hash generation. Off, incompatible and SSH roots receive no spec. Ordinary tools remain available according to their existing policy.
- The private Capture callback uses a fresh ProjectScanner, exact executor chain, requesting guard and accumulated exclusions. `WorkspaceToolExecutor.local_authority_chain` is a read-only immutable snapshot accessor (None for SSH), no filesystem I/O or new grant. Absolute high-water exclusions become relative typed subtree exclusions, conservatively retaining deleted/file-to-directory exclusions.
- Conditional effective fs_read denial/Ask is resolved through the existing injected HubTool resolver at pending review and invocation, in addition to fs_search_index. Ask rows use the existing approval bridge and options approve_once/deny. `apply_index_read_decisions` records exact `(run_id, call_id, arguments)` decisions; consumption is one-call, stale name/session stamps are ignored, unanswered siblings refuse, broad forged approvals narrow to once without persistence. Single-call fallback also narrows and rechecks both current states. The existing runtime supplies synthesized IDs for id-less calls; no runtime protocol change was needed.
- Production `_compose_agent_request_providers` awaits `_prepare_project_index_scopes` through asyncio.to_thread after exact root capture. `_compose_local_provider` only consumes the prepared map. Final Console tool filtering controls the capability note, including its compatible alias subset. No active-workspace authority lookup, scan per send, automatic refresh, retrieval-policy mutation or instruction-body promotion was added.
- Query lifetime: `_search_store` retains the existing runtime operation pin, binds factory opens, closes the native store before ordinary pin release, and tracks at most two concurrent operations with a bounded semaphore. A code-owned `ProjectIndexRetirementUnproven` carries explicit scanner-retirement failure; its ownership record/pin/slot remain retained, affected key refuses more reads, and aclose reports unresolved retirement. Capture does not borrow cache handles and does not take the writer-exclusive BindingLifetime. aclose stops admission and waits actual reader callback completion and existing native writer supervisors despite repeated waiter cancellation.
