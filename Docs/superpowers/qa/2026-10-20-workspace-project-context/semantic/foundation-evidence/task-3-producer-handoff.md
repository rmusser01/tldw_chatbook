## Actual service and state surface

`ProjectIndexService` in `tldw_chatbook/Workspaces/project_index/service.py` owns authority, semantic jobs, queries, and retirement. The callable API is:

- `status(key: ProjectIndexKey) -> ProjectIndexStatus`: current keyword snapshot, including `scope.epoch` and keyword state.
- `semantic_state(key: ProjectIndexKey) -> ProjectSemanticState`: model-free read of separate consent/readiness. Fields: `scope`, `semantic_revision`, `enabled`, `settings`, `state`, safe `reason`, `ready_generation_id`, `coverage`, `close_pending`. There is **no separate `semantic_snapshot` method**; this immutable state is the semantic snapshot.
- `enable_semantic(key, settings: ProjectSemanticSettings, *, expected_epoch: int, expected_semantic_revision: int) -> ProjectSemanticState`: compares secret-free settings to the current catalog candidate, then CASes current keyword epoch and semantic revision. `disable_semantic(key, *, expected_epoch: int, expected_semantic_revision: int) -> ProjectSemanticState` revokes semantic consent without changing keyword policy. Use captured values from the current snapshots; stale calls fail rather than overwriting later choices.
- `refresh_semantic(key, *, expected_epoch: int, expected_semantic_revision: int) -> str`: returns a job ID after admission; requires Ready/Partial keyword state, enabled semantic state and an approved current destination. It starts an owned async build, not a synchronous UI call.
- `semantic_close_pending(key: ProjectIndexKey) -> bool` and `retry_semantic_close(key: ProjectIndexKey) -> bool`: model-free exact-binding pending projection and same-owner retry signal. `False` means no matching known pending owner was signalled; it does not certify native retirement.
- `search(authority: ProjectIndexSearchAuthority, query: str, *, limit: int = 10)` is the existing live-authorized search entrance. The service creates a finite model wrapper per query, one nonblocking semantic query slot per service, then fuses with keyword candidates before live Capture. Contention yields keyword-only search. Do not build query text queues or infer authority from a path.

## Candidate, approval and display

`semantic._settings_for_project_model(model_id)` resolves a **secret-free** current catalog/config/destination candidate and does not instantiate a model. A selected but unapproved candidate can be passed to `enable_semantic`; the store records `Paused` with `destination_approval_required`. Only an explicit destination approval should create `dataclasses.replace(candidate, approved_destination_fingerprint=candidate.destination_fingerprint)` and call `enable_semantic` with fresh CAS values. `enable_semantic` recomputes the candidate; a changed provider/config/destination is refused. Model/artifact loading happens later at build/query admission. This approval is separate from keyword consent and saved Library RAG policy.

A compatible retained Ready generation may leave `semantic_state().state == "Ready"` with a `previous_index_refresh_failed_...` reason after a failed rebuild. Show “previous index available; refresh failed,” not refresh success. The failed staging generation is Error and is never queried. A pointer by itself does not grant readiness: current scope/semantic revision/settings/destination/artifact/dimension/format compatibility and consent are checked with a finite SQLite Ready preflight before query wrapper/provider work; catalog, artifact, and live captured bytes are checked again after embedding before ranking; a newer keyword manifest alone does not disqualify a valid old Ready. With no compatible Ready, display Error. Zero-member Ready is distinct from unavailable.

## Pending and native retirement

Keep the actual `service` and `key` captured by the card/tool closure across a failed `await service.aclose()`. `aclose()` sets service admission closed and may raise `ProjectIndexRetirementUnproven("project_embedding_close_pending")` promptly while the original build/query worker still owns its wrapper/carrier. The old service remains the owner: use `service.semantic_close_pending(key)` to show Retry cleanup even after failed shutdown, call `service.retry_semantic_close(key)` on that same object, then await its retirement/`aclose()` again. Do not create a new service to “clean up” the old one or call a wrapper close on the UI/foreign thread. A fresh `semantic_state()` may be unavailable after `_closed`; retain the last state snapshot for display and use the in-memory pending projection for cleanup. Known model-close pending is distinct from generic uncertain registry/native retirement; the latter is retained and not made retryable by this signal.

An actual WorkspaceDB handle owned at admission is physically retired before model construction/encode/close/retry waits; a live borrowed caller handle is preserved and semantic work refuses. Each build uses one wrapper across pages; each query uses a fresh finite wrapper. Actual factory and `requests.Session.close`, wrapper, carrier, native worker and lease must positively retire before Ready publication or successful shutdown.
