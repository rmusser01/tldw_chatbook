covers the request, candidate and native-detail contracts. No additional decision.

The old six-edit body is replaced by a focused component workflow: exactly three
sequential requests with the same prepared reference, existing configured registry,
request validation and destination/count consent. Validation/consent refusal preserves
the old draft. A validated fresh batch installs a rest-only candidate before dispatch;
only current-batch successes can complete it. One-component retries feather only the
new raw edit, atomically replace its dependent group and retain unaffected encoded
roles exactly. Failed/uncertain retries retain the previous immutable snapshot. Source,
owner, settings revision, config and snapshot identity fence late native work. Existing
manual import/clear and explicit Apply contracts remain; composed Apply carries recipe
and region CAS, while manual edits drop lineage only on success. Speech ownership and
Console playback are unchanged.

The actual Review pairs modal uses immutable original PNGs, a labeled 2×3 matrix and
common original-pixel eye/mouth crops. Its raster is at most 1 megapixel, frames are
decoded/closed sequentially, and numeric/keyboard pan covers larger regions. It neither
transports, speaks, saves nor gates Apply. Late/closed/resized work is fenced. Explicit
retirement clears displayed artwork and defers its exact close beneath another modal;
the same correction applies to the region editor.

Reviewed all changed callers and the compositor/DB handoff, role readiness, metadata
normalization, region/config/source fences, paid-request count, manual transitions,
reopen/no-double-feather behavior and resource ownership. Actual visual review found
and resolved three issues before completion:

## Follow-up full-implementation review correction

The open viewer originally checked only in-memory owner identity. Five new mounted
cases reproduced missing retirement after a second DB handle changed saved source
or region revision, for pair and region dialogs and under a covering modal. The
existing context poll now schedules at most one owned off-thread source/revision
check while a dialog is open. A mismatch discards the stale draft and clears/retires
its exact dialogs; a failed read closes review while preserving draft bytes. Own Save,
changed epoch/revision and replaced dialog handles fence results. Screen close drains
the validation callback before retiring its database owner.

Lifecycle review found another queued-job race: reading epoch/draft inside the new
coroutine could adopt already-discarded state and overwrite the cancellation status.
Its regression was red before capturing arguments at scheduling and checking them
before native work. Held-read controls verify coalescing, replacement isolation,
close draining and read-error retention. Final affected region/generation/pair-viewer
gate: **68 passed in 198.94s**; isolated lifecycle controls: **4 passed in 10.35s**.
The displayed controls are captured before unmount, so cleared-content checks do not
mistake successful dismissal for missing behavior. Ruff/format/diff pass.

Self-review traced all context-poll/close callers, unknown-recipe reselection (the poll
reads only its revision), late/queued work, own Save and existing source/region CAS.
No provider, playback or storage schema change. Existing ADR-243 covers retirement;
no unresolved finding remains in this fix.
