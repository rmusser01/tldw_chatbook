# PR #2645: Console run hooks review

The review covered the complete implementation and integration with current
`dev`, including all 15 inline comments and the additional process-reaping
finding in Qodo's summary. It found permission bypasses, unbounded capture,
shutdown leaks, and durable/lifecycle gaps. ADR-148 remains the governing
decision; its review amendment documents the restriction-only runtime guard.

## Posted findings

| Finding | Disposition and evidence |
|---|---|
| Hook denials disappear when permission review raises | Refusals use unique call IDs and survive downstream exceptions. Runtime guards run separately before approval exemptions. Tests exercise mixed denied/surviving batches, reviewer exceptions, absent reviewers and Canvas preauthorization. |
| Prompt refusal loses staged attachments | Refusal preserves staged attachments, marks the echoed attempt blocked and abandons its preparation. Controller regressions retry the actual submission. |
| Missing appearance dependency | Rebase retains the complete appearance implementation from `dev`; restore the appearance model tests removed by the PR. Both appearance modules collect and pass. |
| `communicate()` retains unbounded output | Replace whole-output capture with continuous pipe draining and bounded retained prefixes. Overflow denies tool guards and contributes no prompt context. Tests use real subprocess output, UTF-8 and concurrent stdout/stderr. |
| Public config APIs lack documentation | Add field, argument, return and validation documentation to the config types, matcher and loader. |
| Queued submissions invoke the manual prompt hook | Gate strictly on MANUAL origin. Queued and authorized wake submissions are exempt. |
| Skill approval rounds omit hooks | Publish once after shared interrupt registration for tool, skill-install and skill-script rounds. Real production request-method tests verify run identity and script arguments. |
| Detached approval reports active | Activity requires both owning-session identity and an attached visible view. All three approval kinds cover active, parked and detached states. |
| Workers survive runtime disposal | Engine closure seals admission, cancels queued work and signals active subprocess owners; runtime shutdown fencing and disposal both close it. A positive pre-disposal execution and post-disposal refusal verify actual behavior. |
| Tool arguments exceed 4,000 characters | Preserve exact guard input under accepted ruling R28: truncation could conceal forbidden content. Notifications have whole-event 1 MiB, node and depth limits with preflight before JSON allocation; oversize events drop whole. Documentation now distinguishes argument fidelity from bounded summaries. |
| Hook output absent from searchable run logs | Accepted ruling R13 uses application Loguru records, not `search_run_log`. Correct contradictory claims in the ADR, spec and guide. Records carry command fingerprint, event and session/run identity; accepted injected context has a durable hook-origin transcript row. |
| Invalid working directory reaches subprocess | Validate through the central absolute-existing-directory helper before launch. Invalid paths retain purpose-specific failure behavior. |
| Textual enabled value silently enables commands | Require an actual boolean; malformed master switches disable execution with a content-free diagnostic. Tests cover malformed config values. |
| Concurrent lazy construction leaks engines | Synchronize configuration check, construction and publication with runtime shutdown. A concurrent first-access regression proves singleton identity. |
| Notification hooks serialize within a firing | Keep firing order while running matching hooks concurrently on a separate bounded four-worker pool. Capacity and concurrency tests use real subprocesses. |
| Bounded timeout abandons pipes/reaping | Kill the original process group even after the leader exits; explicitly close pipe transports and retain asynchronous process ownership through bounded cleanup. Test leader exit, inherited pipes, escaped descendants and shutdown. |

## Additional defects found by independent review

- A name-keyed guard verdict incorrectly affected another call to the same tool;
  call-ID verdicts preserve per-call decisions.
- A wrapper created while no hooks matched never observed a later configuration
  change; wrappers now consult live configuration on every call.
- Permission-review exemptions and missing permission reviewers skipped guards;
  the new optional restriction-only dependency sees every call and cannot grant
  an approval. Primary and child services bind the correct run identity.
- Durable continuation PostToolUse referenced undefined `full_content`; capture
  the result before normal runtime truncation.
- Prompt refusal and cancellation retained preparation state and could prevent
  another send; both release their preparation without consuming staged input.
- Durable acceptance discarded injected context; accepted payloads, idempotent
  hook transcript persistence and frozen-request recovery now retain it.
- Stop used coalesced toast eligibility and missed intermediate/cancelled queued
  turns; arm each accepted turn and consume one terminal notification. Durable
  ownership starts immediately after commit, before fallible audit publication,
  and postcommit retries cannot rearm it.
- SubagentStop and Stop observer exceptions could skip required settlement;
  isolate observers from the existing lifecycle work.
- Notification byte checks ran after JSON encoding had already allocated a large
  scalar; reject oversized aggregate/scalar input, cycles, excessive nodes and
  depth before encoding. A preallocated 16 MiB escaped scalar regression measures
  less than 2 MiB additional peak allocation.
- Approval summaries had the same allocation gap before calling the engine.
  Both summary sites now use bounded structural preflight and preserve small
  JSON exactly; oversized or unsupported arguments receive an explicit omission
  marker without conversion through arbitrary `__str__` methods.
- Skill installation omitted the captured run ID and script summaries used
  nonexistent payload fields; production approval tests now verify both.
- Two PR task IDs collided with older tasks on `dev`. Preserve the existing IDs
  and renumber the PR tasks to TASK-32508/32507 with provenance.
- GitHub's real UI-ready census caught an eager controller import of the hook
  engine: 974 resident modules exceeded ADR-097's 973 limit. Defer hook helpers
  to their lifecycle call sites and explicitly require the module to be absent
  in the existing real startup census. The budget and snapshot are unchanged.

## Verification scope

Targeted verification covers the engine, runtime guards and continuation,
fleet callbacks, controller and durable recovery, approval host, viewless runtime,
configuration reload, SQLite transcript persistence and both appearance modules.
No full repository sweep was run.

At the first expanded verification, 1,050 tests passed and one additional failure
was investigated. Together with 20 already isolated failures, all 21 reproduce on
the exact original `dev` base `a766133fc467c7b9abdf2fcd4e63d480971919f3`.
They concern eight old local-provider fixtures, ten Canvas/controller fixtures,
two old viewless delivery fixtures and one stale fleet-snapshot cleanup
expectation. The latter expects a read-only snapshot to mutate owner retention,
contrary to the current lifecycle contract. These are explicitly excluded from
the focused integration run, not reported as passing.

After rebase onto `71313cccd8bf13cbea0d25d341764463629375a4`, the expanded run
passed 1,061 tests with those 21 exclusions. The final approval-summary fix then
passed 131 focused engine, controller-regression and hook-composition tests.
Derived-artifact and final GitHub results are recorded in TASK-32507 and the PR.

## Remaining v1 limits

Hooks are trusted user-configured commands running with user privileges and
inherited environment. Guard arguments are exact; configured global workspace
cwd and nullable Stop run IDs remain accepted v1 limitations. Hook execution
records live in application logs. Four workers bound concurrency; more matching
commands execute in waves. A first deny returns promptly while already running
peers finish within their own deadlines. Process-group cleanup cannot contain a
descendant that deliberately escapes the group. These are explicit contracts,
not claims of sandboxing or guaranteed delivery under notification saturation.
