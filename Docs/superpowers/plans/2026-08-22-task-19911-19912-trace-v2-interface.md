# Trace v2 Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Trace responsive, keyboard-complete, state-explicit, and optimized for finding anomalies without hiding any event.

**Architecture:** Preserve `TrajectoryScreen` and its pure snapshot boundary; change only user-facing labels and presentation. Use Textual's native `VerticalScroll`, resize events, DataTable column rebuild, and existing selection/render guards. Add one focused filter-bar widget rather than embedding filter state across unrelated controls.

**Tech Stack:** Textual 8.x, Python, existing theme tokens, pytest Pilot/compositor geometry.

**Spec:** `Docs/superpowers/specs/2026-08-22-task-19907-trace-v2-exhaustive-collaboration-design.md`
**ADR required:** no
**ADR path:** N/A (ADR-080 already governs structure; this plan implements approved UI behavior without a new boundary).

### Task 1: TASK-19911 — Scrollable details, responsive ledger, and explicit states

**Files:**
- Modify: `tldw_chatbook/UI/Screens/trajectory_screen.py`
- Modify: `tldw_chatbook/UI/Screens/chat_screen.py` (labels only)
- Modify: `Docs/Features/Trajectory-View.md` or rename to `Docs/Features/Trace-View.md` with a compatibility redirect/link
- Test: `Tests/UI/test_trajectory_screen.py`
- Test: `Tests/UI/test_trajectory_live.py`
- Create: `Tests/UI/test_trace_responsive.py`

- [ ] **Step 1: Write failing reachability and geometry tests**

At 60×18, 80×24, 100×30, and 120×35 assert primary columns stay in bounds, no
primary horizontal scroll is required, inspector content can scroll to its last line,
and table context remains visible. Mutation-check by restoring the current fixed widths.

- [ ] **Step 2: Write failing state tests**

Assert exact visible states for live-following, live-paused after scroll, imported,
loading, incomplete, zero search results, zero search+time results, no timing data, and
worker/live failure with retry.

- [ ] **Step 3: Replace the inspector `Static` with native `VerticalScroll`**

Mount one non-markup Static inside it. Focus it when opened; preserve native scrolling;
add screen actions for detail focus/full-pane/copy/wrap only where Textual does not
already provide the behavior. Add a visible overflow cue based on scroll extent.

- [ ] **Step 4: Implement width tiers through `on_resize`**

Rebuild DataTable columns only when crossing 100 or 120 columns; use stable `event_id`
for DataTable row keys and shared selection while `seq` remains display-only. Preserve
cursor, selection, collapse, query, brush, and follow state. Compact/narrow tables show
identity/event/summary/state; metrics remain in the inspector.

- [ ] **Step 5: Add one-line state/filter summary and human labels**

Use Trace in title/footer/import labels. Move raw conversation ID into inspector metadata.
Humanize kinds through one mapping. Never show a blank ledger without an explanation and
clear/retry action.

- [ ] **Step 6: Verify and visually inspect once**

Run:

```bash
.venv/bin/pytest -q Tests/UI/test_trajectory_screen.py Tests/UI/test_trajectory_live.py Tests/UI/test_trace_responsive.py
```

Then export compositor evidence for all four sizes in one bounded pass, fix the observed
batch, and confirm once.

- [ ] **Step 7: Commit**

`git commit -m "feat(trace): add responsive ledger and reachable details"`

### Task 2: TASK-19912 — Semantic timeline, structured filters, and anomaly navigation

**Files:**
- Modify: `tldw_chatbook/UI/Widgets/trajectory_timeline.py`
- Modify: `tldw_chatbook/UI/Screens/trajectory_screen.py`
- Create: `tldw_chatbook/UI/Widgets/trace_filter_bar.py`
- Test: `Tests/UI/test_trajectory_timeline.py`
- Test: `Tests/UI/test_trajectory_timeline_integration.py`
- Create: `Tests/UI/test_trace_filters_navigation.py`

- [ ] **Step 1: Write failing semantic-lane and keyboard-parity tests**

Assert visible `Input`, `Model`, `Tools`, `Agents` labels, distinct glyphs in monochrome,
turn/agent boundaries, previous/next event, Enter selection, range start/end, Escape
clear, and focus-dependent hints for every mouse gesture.

- [ ] **Step 2: Write failing filter/navigation tests**

Cover kind/status/agent/provider/time filters, active chips, visible/total counts,
clear-all, next/previous match, next error/tool/feedback/child event, and preservation
through live refresh, including insertion before the selected display position without
changing the selected `event_id`.

- [ ] **Step 3: Replace greedy anonymous lanes with semantic lane assignment**

Keep `TimelineModel` pure. Change timeline bar/message identity from mutable display
`seq` to stable `event_id`. Map event families to named lanes; use distinct glyphs plus
theme styles. Collapse to one explanatory row when there is no timing. Preserve zoom,
pan, selection, and brush APIs.

- [ ] **Step 4: Add keyboard selection and range actions**

Use ADR-031-safe single-letter/punctuation bindings and contextual hints when the
timeline is focused. Mouse and keyboard paths call the same model methods.

- [ ] **Step 5: Add `TraceFilterBar`**

Own the filter dataclass and parsing in one widget. Wide mode exposes Select controls;
narrow mode exposes the same state through one Filters action/dialog. The screen
receives one changed message and composes it with search/brush through the existing
render generation guard.

- [ ] **Step 6: Verify**

Run: `.venv/bin/pytest -q Tests/UI/test_trajectory_timeline.py Tests/UI/test_trajectory_timeline_integration.py Tests/UI/test_trace_filters_navigation.py Tests/UI/test_trace_responsive.py`

- [ ] **Step 7: Commit**

`git commit -m "feat(trace): add semantic timeline and anomaly navigation"`
