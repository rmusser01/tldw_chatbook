# Console Row Collapse Controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a screen-local collapse control to the Console status-chip row and move both collapsed-row restore controls to the far left.

**Architecture:** Follow the existing composer pattern without adding persistence or a new abstraction. `ChatScreen` remains authoritative for the screen-local status collapse boolean. `ConsoleStatusChips` becomes a one-row `Horizontal` host with two always-mounted presentation containers: an expanded row containing a fixed left toggle plus an inner `HorizontalScroll` for the existing chips, and a collapsed row containing the restore control plus status copy. Toggling the presentation containers preserves every chip's independent semantic visibility while preventing background chip updates from leaking into the collapsed row. The composer change is a DOM-order-only adjustment inside its existing collapsed presentation.

**Tech Stack:** Python 3.11+, Textual 8.x, pytest/Pilot, TCSS

**Design:** `Docs/superpowers/specs/2026-08-12-console-row-collapse-controls-design.md`

**Backlog task:** `backlog/tasks/task-15704 - Console-add-collapsible-status-row-and-left-align-restore-controls.md`

**ADR required:** no

**ADR path:** N/A

**Reason:** This is a screen-local UI behavior change using an established ownership pattern; it changes no storage, runtime boundary, security policy, service contract, or long-lived application structure.

- [ ] **Step 3: Implement the minimal mounted-presentation toggle**

In `ConsoleStatusChips.__init__`, accept `collapsed: bool = False` and store it. Change the host from `HorizontalScroll` to a one-row `Horizontal`. In `compose()`, build `#console-status-expanded` with a fixed `Status ▾` button and `#console-status-chip-scroll` (`HorizontalScroll`) containing every existing chip unchanged; then build `#console-status-collapsed` with `Status ▴` and `Status hidden`. Add:

```python
@property
def collapsed(self) -> bool:
    return self._collapsed

def set_collapsed(self, collapsed: bool) -> None:
    self._collapsed = bool(collapsed)
    self.query_one("#console-status-expanded").display = not self._collapsed
    self.query_one("#console-status-collapsed").display = self._collapsed
```

Presentation-level display is load-bearing: never mutate individual chip `display` values during collapse. This lets `sync_run_chip()`, `sync_temporary_chip()`, `sync_scope_chip()`, `sync_cost_state()`, and tools sync continue updating their own semantic state while their expanded ancestor is hidden. Use existing Textual containers/widgets; add no dependency and no recompose.

- [ ] **Step 3: Implement the screen seam**

Initialize `self._console_status_chips_collapsed = False` beside the composer collapse state. Pass `collapsed=self._console_status_chips_collapsed` when constructing `ConsoleStatusChips`. Add narrowly decorated handlers and one synchronizer:

```python
@on(Button.Pressed, "#console-status-collapse")
def handle_console_status_collapse(self, event: Button.Pressed) -> None:
    event.stop()
    self._set_console_status_chips_collapsed(True)

@on(Button.Pressed, "#console-status-expand")
def handle_console_status_expand(self, event: Button.Pressed) -> None:
    event.stop()
    self._set_console_status_chips_collapsed(False)
```

`_set_console_status_chips_collapsed()` should no-op when setup blocks the workbench or the target state already matches, call `ConsoleStatusChips.set_collapsed()`, request layout refresh, and `call_after_refresh()` focus on the inverse control (`expand` after collapse, `collapse` after expand). Do not persist the boolean.
