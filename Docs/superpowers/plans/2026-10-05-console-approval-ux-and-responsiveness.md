# Console Approval Clarity and Responsiveness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Console permission requests understandable, quick to answer, and visibly responsive while retaining their existing enforcement and lifetimes.

**Architecture:** Prepare a captured presentation from the existing approval owners, keep the reusable card as the decision surface, and publish optional observations of receipt, settlement and grant application. Presentation and feedback never authorize execution. Measure the existing flow before selecting performance repairs and qualify the final native and browser behavior separately.

**Tech Stack:** Python >=3.12, Textual >=8.0.0,<9, existing permission store and runtime observers, pytest, governed TCSS. No new runtime dependency.

**Spec:** [Console approval clarity and responsiveness](../specs/2026-10-05-console-approval-ux-and-responsiveness-design.md).

ADR required: yes

ADR path: backlog/decisions/221-console-approval-interaction-and-feedback.md

Reason: The approved [ADR-221](../../../backlog/decisions/221-console-approval-interaction-and-feedback.md) defines lasting interaction and observational feedback changes while preserving existing security owners. ADR-032/067/090/093/150/161/195/210 continue to apply.

## Global Constraints

- Exact common action labels: **Allow once**, **Deny**, **More options**. Supported temporary grants use **Until Chatbook exits**, with provider-specific scope and revocation copy.
- Retain exact verdict strings, profile binding, file authority, exclusions, risk floors, hooks, kill switch, definition checks, default indefinite wait, positive timeout behavior and denial semantics. Do not migrate provider stamp keys or storage schemas.
- Raw shell grants cover future commands in this Console chat and clear on Disarm or exit. Its complete command and primary warnings remain visible. Default Deny is not a deliberate review gesture.
- Show captured profile names; explain Default inheritance for persistent writes. Exact-input matching uses canonical captured arguments, never normalized, redacted or clipped display data.
- Withhold independent remembered-input choices where a shared same-tool stamp cannot honor them. Do not replace them with broader grants or introduce new review floors for unfamiliar tools.
- A single grouped verdict describes all captured calls. Counts include calls outside the viewport. Bulk approval is one-time only; mixed choices resolve one complete round.
- Alt+A lands on a noncommitting target. Escape closes a disclosure without deciding. More options and Details do not introduce modal screens or alter deadline accounting.
- Keep gesture-generation and round-id fences. Late summaries, pages and feedback cannot reset decisions, steal focus, change another chat, or update a replacement round.
- Feedback may coalesce into a newer fact before first paint. Never delay worker release or FIFO promotion to display Applying.
- Grant success requires an owner observation. Preserve current execution behavior when remembering fails and show **Allowed this call; permission was not remembered** only when that current call is actually permitted.
- New Console collaborators live under UI/Console_Modules; a controller owns state and behavior, not DOM. Keep screen methods thin and obey its size ratchet.
- Follow backlog/docs/design-language.md and component-patterns.md. Fixed visual values use central tokens, Python uses classes, and CSS changes rebuild the generated bundle. Do not change shared token values for this feature.
- Qualification sizes: **80x24**, **120x40**, **170x48**, Inspect open and closed, dark and light themes.
- Targets: **100 ms** input-arrival-to-visible-feedback and **200 ms** completed-local-checks-to-actionable-paint, at p95 under recorded conditions. Use at least **40** warm samples per distribution and nearest-rank p95; report first-use behavior separately.
- Native and browser receipts stay separate. Cross-clock metrics require calibrated offset and bounded error. Pilot press plus pause, mounted widgets, and server frame emission alone cannot prove perceived paint latency.
- Timing diagnostics contain no arguments, paths, commands, rationale, conversation text, credentials or externally supplied identifiers. No external telemetry or extra model call.
- Run targeted tests only. A full suite requires the user's explicit opt-in. Do not weaken storage recovery or real-profile guards to obtain a passing run.

## Review Focus

1. An already selected raw-shell Deny must count only after a deliberate gesture; programmatic initialization must not satisfy review. Task 3 owns this test.
2. Remember inputs plus Once for repeated MCP tools must not silently lose the selected rule or widen another row. Task 2 owns capability tests; Task 6 owns the invocation journey.
3. Stop or a deadline winning between receipt and settlement must never produce an accepted or saved claim. Task 5 owns this arbitration test.
4. A late Details page or More options gesture after same-round payload replacement must not land on the new snapshot. Tasks 3 and 4 own the generation tests.
5. Fast execution and reordered observations must remain truthful without forcing an intermediate frame or delaying the next pending round. Task 5 owns this test; Task 6 measures the handoff.
