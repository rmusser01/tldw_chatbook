# Structured document editing

Library database Notes and File Notes keep source separate from language. Use the existing document tools to check or explicitly format YAML, JSON and JSONL.

## Checking, formatting and recovery

Choose Plain text, Markdown, YAML, JSON or JSONL independently of the body. Unknown future modes remain unchanged and have no structured parser. Check document runs on initial open, language change and after 400 ms of typing inactivity. Manual Check checks the whole current source. Editing or changing language retires previous diagnostics. **No syntax errors** means a complete check of that source found no grammar errors; it does not establish application-schema validity, correct values or intended structure. Markdown code blocks are not linted.

YAML indentation may be syntactically valid while expressing an unintended structure. For example, moving `name` under a different mapping can still pass Check; inspect the intended nesting yourself. JSON is strict: trailing commas, comments and non-finite numbers are refused. JSONL requires one JSON value per physical record, rejects blank records, allows a final newline, and treats an empty file as zero records; an empty JSON document is not valid JSON. Duplicate keys, including escaped JSON names, are reported and block formatting. YAML custom tags are never executed; ambiguous merge/key semantics or constructs the engine cannot prove it preserves may be unsupported for formatting even if grammar is valid.

**Format document** is an explicit action and checks its own captured source. Syntax errors, duplicates, unsupported constructs, excerpts, resource limits or unavailable editors/workers refuse formatting without changing the body. A changed result is one native undo transaction; an already formatted result adds no edit. Normal Undo restores the prior source. A pending result cannot apply after source, language, document or authority changes, conflict, loss of editability or supported composition begins. Formatting is deterministic and idempotent within each engine; whitespace need not match across the two apps.

Common limits are 1 MiB of UTF-8 source, nesting depth 100, 100 displayed diagnostics and a 2-second processing deadline per request. A limited, unsupported or failed check is not a successful syntax check. File Notes additionally keeps its existing 200,000-character interactive limit; an excerpt cannot become editable because the engine permits more bytes. Native mixed/lone-CR representation fences preserve canonical source for download/export and title/save while body editing is unavailable.

Syntax errors never add a save veto, and formatting never saves automatically. Existing optimistic versions, conflict/overwrite controls, authority and path checks still apply. Empty drafts remain local when a server's nonempty-body contract rejects saving; recovery keeps the empty source without inserting placeholder text. Restore the draft, add content if needed and retry the existing Save action. Diagnostics are separate from save and recovery status.

## Download source or export a note

In Library database Notes, **Download source** writes only the current canonical body as UTF-8. It adds no title, frontmatter or attribution and never parses or formats document values. Unsaved edits are included. BOM, line endings, boundary whitespace, invalid syntax and large numeric spellings stay exact, including source retained behind a native representation fence. Known canonical modes use `.txt`, `.md`, `.yaml`, `.json` or `.jsonl`; Default/null, absent and unknown future modes use `.txt` without guessing a language.

**Export note** writes a distinct `.note.json` file with the existing `tldw.note.v1` portable envelope: title, exact source string, canonical language and keywords. The envelope JSON escaping is a container representation, not a conversion of the source. Import as a note container to recover its metadata; importing it explicitly as source instead treats the whole envelope as source. Null and unknown future modes are preserved. An absent/unknown language field from an old server cannot become portable metadata automatically: download source remains available, while portable export refuses until canonical metadata is known. A temporary view selection does not change the source filename extension or fill portable metadata.

The existing Export Markdown and Export text actions add headings/metadata. They are separate conversions and are not exact-source or portable-note backups. Chatbook archives containing Notes use archive version 4.0 and retain Canvas records; Canvas-only archives continue to use 3.0. Unsupported portable-note/archive versions are refused before import writes. Use the existing archive export for combined Notes and Canvas; the single-note envelope does not contain Canvas.

The terminal file picker chooses the output path and retains its existing overwrite policy. A Library export captures the canonical note session when the action opens; edits after opening the picker do not alter that artifact. File Notes retains its existing Save/Save as actions, opened BOM/newline serializer, authority/hash and overwrite checks. These new database-note downloads do not export a normalized File Notes view or promote an excerpt into a complete source. See [Notes guide](library/notes.md) and the [User guide index](index.md).
