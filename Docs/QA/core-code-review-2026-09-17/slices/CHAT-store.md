## Verified-fine
- **Edit/delete/regenerate are atomic with the cursor write** — `_dispatch_branch_mutation` (:21971-21994) opens the outermost `BEGIN IMMEDIATE`; nested adapter calls (`chat_persistence_service.py:2863/2894/2906 self.db.transaction(immediate=True)`) enter `TransactionContextManager._enter_transaction` at depth>0 on the same thread-local connection and "defer completion to the outer transaction" (`ChaChaNotes_DB.py:23996-24004`); the `raise ValueError(...)` at :12325 / :13702 / :13713 propagates through the outer `with` → `_exit_transaction` rolls back (`:24067+`). So the "DB ahead of memory" divergence I first suspected at :12318-12325 cannot occur. Not a finding.
- **`_persist_active_leaf` returning False cannot strand a half-write** — same transaction reasoning; `InputError` from `set_conversation_active_cursor`'s stranded-owner query (`ChaChaNotes_DB.py:12655-12662`) is only reachable if a checkpoint was inserted between the `_dispatch_branch_mutation` pre-check and the cursor write, which `BEGIN IMMEDIATE` excludes.
