# Native ACL fixture baseline design review

Approved for the bounded test-only fixture correction, subject to the following implementation requirements. No code changes or native acceptance are claimed by this review.

Evidence: all three exact e683 Windows cases preserved owner, revision, 72 DACL bytes, and protection; the only change was control 0x9004 to 0x9404. Microsoft documents that SetSecurityInfo applies the current inheritance model and sets AUTO_INHERITED for converted objects: https://learn.microsoft.com/en-us/windows/win32/secauthz/automatic-propagation-of-inheritable-aces . A single setup application of the same retained DACL is justified; masking the final comparison would not supply the same evidence.

Smallest shape: retain the original descriptor and DACL pointer; call the existing SetSecurityInfo with identical protection/owner/SACL arguments before the body; read a temporary native descriptor and require exact owner, revision and DACL bytes, plus control in {original_control, original_control | 0x0400}. Save only its immutable tuple as the established baseline. Release the temporary descriptor. Run the body, then restore using the still-live original DACL pointer and compare the full restored tuple exactly to the established baseline. The original pointer remains valid until final cleanup completes; no temporary descriptor pointer may escape.

Setup failure must prevent the body. Keep all descriptor release paths and exception chaining; if setup has successfully mutated native state and subsequent read/validation fails, retain a bounded restoration attempt using the original DACL rather than leaving the cleanup lifetime outside that mutation. An unestablished baseline must never produce a successful fixture outcome, and a cleanup failure must retain the original setup/body error as context. No retry loop, public permission normalization, owner/SACL write, extra native API, or product change is necessary.

Meaningful tests: unchanged setup and already-normalized setup succeed; exact 0-to-1 AUTO_INHERITED setup succeeds and the body sees that baseline; 1-to-0 or any other control-bit change fails before body; owner/revision/DACL changes fail before body; a mismatch arising only at final restoration still fails (including 0x0400 if it was not in the established baseline); setup API/read failures never execute the body and release descriptors; body error with successful restoration preserves error identity; cleanup error preserves setup/body error context. Existing metadata privacy tests should target the final mismatch, not accidentally fail at setup, and retain byte-valued/null-DACL coverage.

Native Windows acceptance remains required. This design adopts documented OS bookkeeping during disposable fixture setup; it does not establish an application permission-policy change.
