# Workspace tray layout wake design review

Disposition: approve the bounded design, subject to the stored-signal cleanup and real lifecycle regressions below. This is a source/retained-evidence review; no reviewer app or test process ran.

The native stacked-screen receipt `/private/tmp/uat-tray-layout-stacked.log` establishes the actual failing condition: an initially measured 80×40 tray retains its positive region below two screens, while all five newly recomposed children have zero virtual regions. Its own screen is not current; fits increase from 4 to 3839 during the short wait. Returning to that screen produces real child geometry and eventually zero further fits. This proves a callback feedback loop under this lifecycle. It does not yet prove this was the sole cause of the Windows backup timeout or quantify a Windows improvement.

The existing `_fit_height_to_content` bottom==1 branch uses `call_after_refresh` recursively, but Textual routes these callbacks through the active screen. They do not promise a retained tray's owning screen was reflowed. `Screen.is_current` also includes background screens; a blanket non-topmost-screen check would be wrong for transparent/background rendering.

The proposed one-shot subscription to the owning screen's `screen_layout_refresh_signal` supplies the missing event. Installed Textual publishes it after reflow (`screen.py:1393`). `Signal.subscribe(..., immediate=True)` means synchronous delivery **on publication**, not immediate delivery upon subscribing. Unsubscribe and clear pending ownership first, then queue the existing fit: this bounds duplicate publications, avoids inline style mutation during reflow, and introduces neither polling nor a timer. Existing resize/relabel/scroll scheduling can remain unchanged.

Use the exact stored signal as the pending sentinel; set it only after successful subscription. Unmount must unsubscribe via that stored signal, not `self.screen`, which may no longer resolve during removal. The current initial draft's `on_unmount` lookup therefore needs the already-proposed stored-signal adjustment. `ConsoleSelectionMenu` already demonstrates this ownership/cleanup pattern. `unsubscribe(self)` removes all this node's callbacks from that signal; this tray currently has no other subscriber on it. Signal publication iterates a snapshot of subscriber items, so self-unsubscription is supported. No extra counter, timer, or screen-visibility state is needed.

Required acceptance: repeated real recomposes while covered keep at most one subscription and settle callback count; same-size return with larger content recomputes natural height and keeps lower content/scroll reachable; transparent/background rendering still fits; hidden-parent hide/show recovers; removal before publication releases the subscription and later layouts do not invoke the removed tray. Preserve the existing single scheduled fit/scroll restore contract and width-relabel tests. A fit triggered by another normal event while pending may resolve geometry; clearing that pending wake then is optional for correctness, but no persistent listener should remain after a successful delivered wake or unmount.

A legitimate bottom==1 state may wait harmlessly for a future owner layout rather than create work. Do not broaden the predicate or change content-height behavior on that speculation. Initial zero own-region handling remains governed by existing resize/mount behavior and must stay covered by lifecycle tests.
