## Strengthened evidence and remaining limits

The contender event is still emitted before original initializer entry, but it is now followed by a bounded observation of that actual contender thread. The predicate requires exact `threading.Condition.wait.__code__`, its `self` identical to `storage._changed`, and its immediate caller code identical to `original.__wrapped__.__code__`. Only a matching live stack permits continuation. The original condition and initializer results are not replaced. This directly witnesses the real initializer condition wait while the leader reservation remains held, rather than relying on the 20ms drain delay.

Both variants now require the heartbeat result to be `None`. Pause variants additionally require the exact native `bootstrap.RecoveryRequired` type with the exact `storage_locally_paused` argument, as well as no heartbeat publication. Thus unexpected exceptions from either callback cannot silently satisfy the pause evidence. After actual task termination, Scheduler drain must succeed, its native task set must be empty, and native pending/operation sets must be empty.

The renamed `actual_trace_callback` marker correctly describes an attempted real callback. In pause variants its transaction entry refuses; no transaction-body completion is claimed there. Complete variants explicitly prove admitted/logically complete trace work and heartbeat timestamp readback. Every variant then proves a fresh resumed trace batch completes and a fresh heartbeat is read back. The `workers_completed_after_release` marker denotes coroutine termination, including the expected pause refusal, rather than successful transactions in the pause phase.

The probe invokes `_offload` directly, not the full tick `_maintenance_operation`, dependency settlement graph, runtime monitor or capture's exclusive lease. Its Scheduler drain set holds the heartbeat; the trace task is a real competing native owner but is awaited separately by the driver. Cancellation, repeated ticks, existing populated trace batches, full startup/UI CPU contention and Windows native handle costs are not exercised. ## Interpretation for Windows

Windows10cc supplied actual heartbeat/default-config and trace-maintenance/Notes stacks together with a Scheduler30s false drain. This probe demonstrates that their deliberately serialized native initialization can finish, unwind on local pause and resume without a persistent ownership failure on the local host. It does not establish why Windows ran out of drain time, identify its exact initializer leader, reproduce its scheduling/CPU delays or rule out a different interleaving. A passing artificial-release test is not evidence for a heartbeat-path cache, admission bypass, task retirement shortcut or deadline increase.

No production correction follows from these four passes. Keep the Windows failure preserved. The probe is useful evidence against claiming that these two real callbacks inevitably deadlock merely because they share native initialization, subject to the exact coverage limits above.
