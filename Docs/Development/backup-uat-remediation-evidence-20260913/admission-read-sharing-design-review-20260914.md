## Race semantics and limits

This is not bit-for-bit equivalence under arbitrary interleavings. Today a new malformed record/registry intent between final permission and final scope can make the second read refuse. Shared observation can admit using the earlier valid pair. A newly added pending record can also disable scope's no-pending live-owner continuation today; reusing the earlier pending list changes that particular schedule. State changes after today's second read already have the analogous unavoidable window. The proposal must explicitly adopt one final observation boundary, not claim the second observation never matters.

The rationale is bounded: a ready native lease prevents overlapping namespace publication/remap completion while this acquisition retains it. Admission.register refuses introduction of busy aliases; Admission.remap can durably publish pending/proposed state before draining leases, but cannot finish overlapping mapping publication until owners retire. register_pending likewise can appear during a held lease. The next acquisition must freshly see that evidence, including acquisitions inside an already-active repository operation. The earlier native probe directly rules out any wider reuse.

_records and _registry are NOT an atomic snapshot: records use their existing bounded private pinned-directory reader; registry obtains and releases its own SH lock. Sharing must preserve that read order and ordinary validators. Do not extend registry SH across scope checks or introduce a new lock. The process-local storage lock does not freeze external record writers. No stronger atomicity or lifetime guarantee is justified.

## Exception behavior

Maintain the existing permission catch family exactly: OSError, ValueError, TypeError, KeyError, RuntimeError, AttributeError become recovery_scope_uncertain. Scope-only failures retain their existing classifications (including storage_scope_not_enrolled/startup_scope_changed and acquire_storage's storage_admission_unavailable translation). Do not wrap the entire combined function with permission's catch, because that would reclassify scope errors. Cancel/BaseException identity and token retirement follow the existing outer handler. Fresh scope _binding calls remain outside the permission classifier. A failure that existed only in the removed second physical read is necessarily no longer observable; do not describe exception preservation as covering that vanished operation.
