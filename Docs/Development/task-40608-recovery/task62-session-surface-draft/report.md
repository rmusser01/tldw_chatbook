## Bounded marker/queue integration map

Source-only follow-up; no code/schema changes or execution. The original order is `ChatScreen._sync_console_native_session_tabs` (18285–18325): retain rows/controller, read streaming ID, run `fleet.prepare_session_run_markers`, apply the existing parent ACK overlay, read queue counts, then await the actual surface. The adapter covers only that final surface/overlay portion.

- **Backend capture:** extend the existing `ConsoleBackendPresentation.capture_projection_view` boundary (33–75), reached inside `ConsoleLocalControls._read_projection`'s original preparation lock (478–494). Capture observations against those same actual rows, active session, request/source/incarnation and controller: `streaming_session_id()`, original per-row `run_marker_for(id)`, and `activity_for(id).queued_count`. Streaming prefers the active live assistant entry, then insertion order, otherwise None (`console_chat_controller.py:28457`). `activity_for` (5915) can hydrate queued dispatch recovery; preserve that original body and ownership rather than treating the count as an inert guessed field. Preserve the original order around the marker checkpoint and queue read.
- **Parent checkpoint before a viewed-clear command:** the actual `fleet.prepare_session_run_markers` decision at 254–270 uses the exact active row (`persisted_conversation_id or id`), revision-backed unseen IDs, the original wake pending check, and the actual displayed-screen check. Wiring's `_console_screen_is_displayed` (909) is `screen.app.screen is screen`; its exception-to-True branch serves unmounted fixtures and is not a remote attachment witness. Central's selected path must establish the actual App/screen/current visit and exact active row before issuing any command that could clear that viewed mark; retain source/visit/session association through the admitted operation and publication. Do not call the unchanged fleet owner through its existing local-controller lambdas or treat a read-only row as clear authority. This map does not invent a new command or payload.
- **Wake and unseen semantics:** `fleet_wake.has_pending` (505) includes both pending result IDs and pending progress, even while delivery is paused. A viewed clear requires the conversation to be marked, no such pending wake, and the screen actually displayed. Only a successful named `clear_fleet_unseen_completion` causes the fleet owner to reread unseen IDs; a failed clear preserves the observation. Preserve mount-time wake claiming before activation/first tab sync (`console_fleet_attention.py:27–32`).
- **Receipt-aware clear is essential:** `clear_fleet_unseen_completion` (104) prefers `activity_receipts.clear_fleet_mark_if_seen`; uncertainty returns False. `_activity_receipt_service` (57) currently discovers that owner through `app.console_runtime`. A selected parent with no local runtime must not accidentally select the direct marks-service fallback while the real backend receipt owner exists. Keep the original receipt reconciliation, durable clear and revision bump in their actual ownership/order; the presenter performs none of them.
- **Markers and None:** controller precedence is NEEDS_APPROVAL, RUNNING, unvisited terminal outcome, then NONE (`run_marker_for:6656`). `_console_run_marker_with_unseen` (`fleet.py:227`) substitutes SUBAGENT_UNSEEN only for NONE and uses the persisted-conversation-or-session identity. The clear opportunity occurs before the no-controller return: absent controller yields `run_markers=None`, `queue_counts=None`, `streaming_session_id=None`, but does not by itself skip the original viewed-mark check. Present controller requires a real marker/count for every row, including NONE/zero. Missing transport observations are not that original absence. ACK overlay remains parent-only, after marker policy, and keeps NEEDS_APPROVAL precedence.

Remaining gap: central must connect this real parent viewed checkpoint to backend-owned wake/run/receipt facts before capturing the final session-surface publication. Sending controller-only markers directly to the presenter would omit SUBAGENT_UNSEEN/viewed-clear behavior. Existing publication/visit checks and positive retirement remain required; no readiness claim follows from this mapping.
