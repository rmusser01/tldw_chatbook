# TASK-31827 diarizer bake-off

The measured go/no-go that decides whether the torch-free sherpa-onnx engine
becomes the default speaker diarizer (spec §7 of
`Docs/superpowers/specs/2026-09-07-meeting-onnx-diarizer-design.md`).

**Outcome: the bake-off FAILS.** No embedder clears all five gates; the
blocking gate is self-match separation for every candidate (best 0.640 vs
ECAPA's 0.734, allowance 0.05). ONNX wins DER by 3x and ties or beats every
other gate. See the Verdict section of [`report.md`](report.md).

- [`report.md`](report.md) — the Apple M-series run: every cell, the gate
  table, and a hand-written **Verdict** section at the end. Everything above
  that separator is generated by `run_bakeoff.py`; re-running it overwrites
  the tables, so the Verdict has to be re-appended.
- `results.json` — the same run as raw per-file rows.
- [`int8/report.md`](int8/report.md) + `int8/results.json` — the int8-vs-float
  segmentation study, run separately on a three-file subset.

The harness lives in [`Tests/Audio/bakeoff/`](../../../Tests/Audio/bakeoff/).
Only `test_der.py` is collected by pytest; `der.py`, `corpus.py` and
`run_bakeoff.py` are the harness itself.

## What is measured

| Metric | Definition |
| --- | --- |
| **Stop-pass DER** | `LocalDiarizer.diarize(wav, 0, duration)` over the whole file, scored against the corpus RTTM by `der.der` with a **0.25 s collar**: missed + false alarm + confusion over total reference speech, speakers mapped by the assignment maximising overlap. Overlapping reference speech counts once per speaker. |
| **Live purity / coverage** | 3 s windows lying entirely inside one reference speaker's turn (no other speaker active in the window), fed to `assign` in time order. Purity = fraction of windows whose cluster's majority reference speaker is the window's own. Coverage = fraction of reference speakers with at least one cluster whose majority is that speaker. `clusters vs speakers` is the mean absolute gap between the live cluster count and the reference speaker count — purity saturates at 1.0 long before the clusterer stops over-splitting, so that column is the honest one. |
| **RTF** | `diarize` wall time / audio duration, measured after `wait_ready`. |
| **Peak worker RSS** | `resource.getrusage(RUSAGE_CHILDREN).ru_maxrss` after `close()`, normalised to MB (macOS reports bytes, Linux kilobytes). Every cell runs in its own child process, so the high-water mark belongs to that cell's workers only. |
| **Per-window embed latency** | Median and p95 of the `assign` round trip over the live windows, first call dropped. |
| **Self-match separation** | `enroll_from_pcm` over up to 30 s of the busiest reference speaker's turns, then `cos(that speaker's Stop-pass cluster centroid, enrolled)` minus the best of the other clusters. The recommended `voice_match_threshold` is the midpoint of the two, expressed as a **distance**. |

The live threshold and the Stop-pass clustering threshold are swept
**independently**, not as a 5×5 grid: the Stop pass runs on a worker that has
never seen an `assign`, so it has no live centroids to reconcile against and
its DER depends only on the clustering threshold, and the live path never
runs a Stop pass.

## Corpus

Fixed and listed in `Tests/Audio/bakeoff/corpus.py` — changing it invalidates
every comparison in the report.

- **VoxConverse dev** (CC-BY-4.0), 20 files, five each at 2/3/4/5 speakers:
  `wmori ngyrk zajzs qvtia zrlyl jnivh ezsgk iwdjy mvjuk yrsve ycxxe uvnmy
  azisu qfdpp mgpok nnqfq kszpd vbjlx cmfyw zcdsd`.
  RTTMs from `joonson/voxconverse`; audio from the VGG dev WAV zip.
- **AMI dev** (CC-BY-4.0), headset mix, 4 meetings: `ES2011a IS1008a TS3004a
  IB4001`. RTTMs from `pyannote/AMI-diarization-setup` (`only_words`, dev).

Audio is downloaded on demand into `Tests/Audio/bakeoff/data/`, which is
git-ignored: ~370 MB, CC-BY-4.0 but not ours to redistribute. Everything must
be mono 16 kHz 16-bit PCM (what the meeting recorder writes); the harness
refuses anything else rather than silently resampling.

## Reproducing

```bash
# Models: fetched into --models-dir on first use (~46 MB per embedder).
python Tests/Audio/bakeoff/run_bakeoff.py \
  --engines onnx,speechbrain \
  --embedders titanet_small,wespeaker_resnet34,eres2net_en,campplus_en \
  --segmentation float,int8 \
  --live-thresholds 0.25,0.35,0.45,0.55,0.65 \
  --cluster-thresholds 0.4,0.5,0.6,0.7,0.8 \
  --files all \
  --out Docs/STT_Evaluation/task-31827/report.md
```

**How the committed run was actually produced.** The embedders do not share a
cosine scale — measured, the live optimum is 0.45 for `titanet_small` and
`eres2net_en` but 0.10 for `wespeaker_resnet34`, and the Stop optimum ranges
0.60 to 0.95 — so one grid over all four would spend most of its cells in a
region that is wrong for three of them. The committed numbers come from a
narrowing sweep on three files (`wmori,mvjuk,zcdsd`) followed by one narrow
full-corpus run per embedder, merged:

```bash
# 1. narrow: the full 5x5 grid, 3 files, all four embedders (~35 min)
#    then extend whichever end of each range was still improving.
# 2. final: one run per embedder at its own thresholds, plus the baseline.
python Tests/Audio/bakeoff/run_bakeoff.py --engines onnx --embedders titanet_small \
  --cluster-thresholds 0.9,0.95 --live-thresholds 0.45 --files all --out /tmp/titanet/report.md
# ... eres2net_en 0.9/0.45, wespeaker_resnet34 0.6/0.1, campplus_en 0.8/0.15 ...
python Tests/Audio/bakeoff/run_bakeoff.py --engines speechbrain --embedders "" \
  --cluster-thresholds "" --live-thresholds "" --files all \
  --speechbrain-python /path/to/torch-venv/bin/python --out /tmp/ecapa/report.md
# 3. merge into one report
python Tests/Audio/bakeoff/run_bakeoff.py \
  --merge /tmp/titanet/results.json,/tmp/eres2net/results.json,... \
  --out Docs/STT_Evaluation/task-31827/report.md
```

The int8 study is a separate merge into `int8/report.md`, one run per
embedder with `--segmentation float,int8 --inprocess-float-control`.

Useful flags:

- `--files wmori,mvjuk,zcdsd` narrows the sweep to a 3-file subset while you
  hunt for the promising threshold region (that is how the committed run
  chose its final thresholds).
- `--corpus-dir DIR` links from an already-prepared
  `{voxconverse,ami}/<id>.wav|.rttm` tree instead of downloading.
- `--speechbrain-python PATH` runs the ECAPA baseline from a **separate**
  virtualenv that has torch. Never install torch into the app's own venv: the
  whole point of this engine is that the base install does not need it. That
  venv also needs `torchcodec` (and, on macOS, `DYLD_LIBRARY_PATH` pointing at
  the Homebrew ffmpeg dylibs): torchaudio >= 2.9 routes `load` through it, and
  without it the SpeechBrain Stop pass returns no segments — see the report's
  incidental finding.
- `--merge a.json,b.json,...` renders several runs as one report, for the
  per-embedder split above.
- An engine whose packages are missing is skipped, with the missing names
  recorded in the report's "Not run" section — the harness never fails for it.

The **x86 proxy** run is `.github/workflows/diarizer-bakeoff.yml`
(`workflow_dispatch` only, never a required check); it uploads `report.md`
and `results.json` as an artifact.

Both threshold knobs are also settable per process without editing the
manifest, which is what the sweep uses:
`TLDW_DIARIZER_LIVE_THRESHOLD` and `TLDW_DIARIZER_CLUSTER_THRESHOLD`
(floats; an unparseable value is ignored).

## The gates (spec §7)

All must hold for the chosen embedder before `AUTO_ORDER` may put ONNX first:

1. Stop-pass DER within **0.02 absolute** of ECAPA.
2. Live purity within **0.03** of ECAPA.
3. RTF **≤ 0.15** on both machines.
4. Per-window embed latency **≤ 150 ms** (M-series) / **≤ 300 ms** (runner).
5. Self-match separation within **0.05** of ECAPA's, on VoxConverse speakers.

Pass: `AUTO_ORDER` goes ONNX-first and the manifest pins the embedder, its
thresholds and its licence. Fail: ONNX ships as the base-install fallback,
`AUTO_ORDER` stays SpeechBrain-first, and the report names the failed gate.
The report's own gate table is the authority; `report.md` states the verdict.

## The DER scorer

`Tests/Audio/bakeoff/der.py` is ~150 lines with its own unit test
(`test_der.py`, collected by CI) against hand-computed values — including
overlapping reference speech, the collar, and a case where best-first greedy
speaker mapping is measurably wrong. An unpinned scorer would let a wrong DER
decide the default engine.
