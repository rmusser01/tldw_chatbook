## What's Working

- **Import once is provably non-destructive and now genuinely Obsidian-aware.** D hashed all 71 vault files before and after Check, Import and an in-app edit of an imported note: byte-identical. `.obsidian/`, `.trash/` and `Templates/` each collapse to one skip row with a reason that names the remedy; frontmatter `title` becomes the title; `tags` + `aliases` become keywords; `[[wikilinks]]` and `[[link|alias]]` resolve in-batch; empty and whitespace-only files are "Empty file — nothing to import" rather than "Failed"; `Ideas 💡.md` and an em-dash filename survive intact. Every one of the prior run's Obsidian complaints is answered.
- **Session Git is the best-designed flow on the screen.** Trust modal → status list → Stage → pre-commit disclosure → commit, verified against real git twice (D's `3a19c0e`, mine `bd746be`), with "unrelated changes untouched" stated and proven.
- **The state vocabulary.** `Draft — not saved yet` / `Saved 16:24` / `Loading note…` / `Linked · Local folder: vault` / `READY TO STAGE · Git: unstaged` / `Stage at least one session note to commit`. Disabled controls mostly carry their reason as text.
- **Focus is legible by shape, not colour alone.** `█Blank note`, `┃ Import once ┃`, `┏━━┓` on the focused body against `▊▔▔▎` elsewhere — all survive a monochrome capture. Sam can find focus everywhere it exists.
- **Performance.** 35 KB note opens in ~0.7 s (doc budget 3 s), 59-file import under 2 s to review and ~12 s to execute, a 179-path vault tree in 0.39 s, filter instant.
- **The empty state, the ages and the list width all landed.** A zero-note profile now reads "No notes yet. Create your first note." with no unexplained `Agent_Lessons` folder.

## Priority Issues

- **[P0] A folder that trips any lasting-sync admission check fails with a message that blames the user, logs nothing, and can never be retried for the rest of the session.** *Why*: "Keep a folder synced" is one of the three worlds the canvas advertises and the one the guide gives the most space to. Both assessors hit it on their first real attempt (C caps 76–77 on two different folders; D cap 72–74, reproduced). Everything downstream — Activate, the conflict path, Manage sync folders — is unreachable, so the guide documents a chapter no one can enter. *Cause*: **PROVEN**, three parts, from the bisect run in parallel with this critique. (1) On any non-OWNER admission, `notes_sync_runtime.py:1598` `_ensure_lease` calls `_publish(..., persist=True)` → `notes_device_state_store.update_root_status` (:1005) raises `NotesDeviceStateError: The requested sync root does not exist` for a root setup never persisted, so the intended `RuntimeError("root_lease_unavailable")` at :1771 is never reached — the honest failure is destroyed by a secondary crash. (2) Each failed Check leaks a `_root_paths` entry (:1769-1774; the pop is skipped when `_ensure_lease` raises), so the next attempt on the same folder is rejected with `lasting_root_overlap` — the folder is permanently un-admissible for the session, invisibly, even after the user fixes the real cause. (3) `library_notes_sync_controller.py:806-814` wraps the call in a bare `except Exception:` and substitutes the fixed string; the module contains zero `logger` references. **Not a wave regression** — identical traceback at `c4a7b1911f`, and every failure site is original to the feature commits (`_ensure_lease`/`_publish` → `0dae7bb8b3`; `notes_sync_coordinator.private_path_overlap` → `eea5244886`; `notes_sync_filesystem` group check → `d2f5901467`). **Incidence caveat, stated plainly**: the trigger in this harness is environment-specific — the vault sits inside the profile's config directory (`private_path_overlap`) and everything under `/private/tmp` has group `wheel` ≠ egid, tripping `notes_sync_filesystem.py:191-192` `owner_group == os.getegid()` → `unsupported_metadata` for all 60 files → `root_discovery_incomplete`. A realistic vault in `$HOME` is admitted in 0.19 s. The 33.4 s both D and I would otherwise have reported is host contention: there is no timeout on this path and failure normally arrives in 0.1–1.3 s. No test pins the crash, the leak or the copy (`grep root_lease_unavailable\|root_discovery_incomplete Tests/` → 0; `grep "Check failed" Tests/` hits only Watchlists). *Fix*: make `_ensure_lease` fail with its own named error instead of crashing in `_publish`; pop `_root_paths` in a `finally`; catch the named admission states in the controller and render each with its own next action — the screen already owns that grammar four rows above the button; log the exception. ## Provocative questions

1. **Task-32131 is Done, its test is green, and `/` still types itself.** Three of this run's findings sit behind a passing test: the slash accelerator, the wizard hand-off (pinned only as a navigation message against a mocked receiver), and duplicate titles (pinned with two rows conveniently aged 2h and 5d). What is the rule for when a Notes fix needs a live check rather than a unit assertion — and would any of these three have survived it?
2. **If the runtime already knows why a folder is inadmissible, why does the screen throw the reason away and blame the user's settings?** The perfect precedent is four rows above the button: a disabled radio reading "Unavailable - server sync-folder capability not installed". Why is that grammar applied to the capability you don't have and not to the one that just failed?
3. **The compact layout gives the Markdown preview `height: 1fr` and the wide layout caps it at 20 rows.** Is there a reading in which a 235x52 terminal should show less of a document than a 100x30 one?
4. **Import once rewrites the user's sentences into `note://` UUIDs.** Is that a local-first product's decision to make? Keeping `[[wikilinks]]` verbatim and resolving them at render time gives the same navigation with none of the lock-in.
5. **The note Title selects on focus and the path fields do not.** One of those defaults destroys data on a single keystroke and the other makes a deep path untypeable. Was either chosen, or are both just what the widget did?
