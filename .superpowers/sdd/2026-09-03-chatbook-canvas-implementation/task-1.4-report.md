# Task 1.4 report — worker virtual DOM, trusted renderer, and zero-egress proof

## Status and release verdict

**Implementation status: complete; independent security review pending.**

Mandatory real-browser qualification passed in Chromium 145.0.7632.6 with
Playwright 1.58.0. Across the 30-case generated-code adversarial corpus there
were no post-execution HTTP(S) requests, WebSockets, frame/top navigations,
popups, downloads, or new workers, and the separately owned egress server
received no requests. Native shell, renderer, parent-DOM, and worker sentinels
were unchanged. A benign counter/form/timer/SVG document remained interactive
and successfully decoded static PNG, JPEG, GIF, and WebP assets.

**Strict-zero-egress verdict: PASS for the mandatory Chromium gate.** There is
no native-JavaScript fallback. Canvas product tools/UI remain disabled and
TASK-31226 remains In Progress until the controller's independent
security-focused review is clean. Firefox and WebKit were not installed and are
explicitly recorded as skips.

## Architecture and API surface

1. `compile_canvas_document()` produces the existing `canvas-v1` typed render
   plan. Raw HTML never reaches the browser as markup, and generated script text
   remains data.
2. The owned trusted shell embeds a real HTTP renderer response in
   `sandbox="allow-scripts"`. It transfers exactly one `MessagePort` after
   checking the renderer window and exchanges a per-load nonce. The shell marks
   the generated-execution boundary only after the worker has loaded QuickJS,
   created its runtime/context, installed the virtual DOM, and acknowledged
   preparation.
3. `canvas_renderer.js` independently revalidates the plan, creates native
   nodes with `createElement`, `createElementNS`, and `createTextNode`, inserts
   CSS through a detached/validated `CSSStyleSheet`, parses and bounds passive
   image metadata, requires a time-bounded native decode, and owns every
   passive-image object URL. It never assigns generated text to a markup or
   code sink.
4. Chromium denies a direct HTTP module worker from an opaque-origin iframe;
   blob wrapping also failed. The trusted renderer therefore creates a fixed
   `data:` module bootstrap whose only operation is importing the exact packaged
   `canvas_runtime_worker.js` URL and starting it. Generated bytes and URLs never
   enter this bootstrap.
5. The worker imports the manifest-covered single-file `quickjs-runtime.js`,
   constructs a fresh module/runtime/context, installs resource controls, calls
   `removeModuleLoader()`, installs the closed virtual facade, and only then
   evaluates generated classic scripts. It never evaluates generated code with
   native browser JavaScript.
6. The QuickJS facade exposes structural virtual nodes/document, simple ID/
   class/tag selectors, text/class/value/checked/disabled/selected properties,
   allowlisted attributes/styles, node insertion/removal, bounded timers,
   bubbling events, JSON, a bounded private console, structural SVG, and typed
   `canvas.submit(value)` / `canvas.download(value)` request emitters.
7. The facade explicitly removes/replaces native window/worker globals,
   navigation, fetch/XHR/WebSocket/EventSource/beacon access, storage/cookies/
   caches, filesystem pickers, workers/importScripts, SharedArrayBuffer/Atomics,
   WebAssembly, postMessage, dialogs/popups, and common server-runtime globals.
   Dynamic `import()` reached through QuickJS `eval()` has no configured module
   loader and produced no request.
8. QuickJS drains each operation to a JSON transaction. The renderer validates
   the exact message shape, operation ordering, every patch, every identifier,
   every tag/namespace/attribute/style/property, and every bridge value before
   touching native DOM or the shell port.
9. Native events are delegated by the renderer and processed one at a time
   through a bounded queue. Native anchor, reset, and form defaults are always
   suppressed. Because the iframe deliberately lacks `allow-forms`, submit
   controls synthesize a virtual form `submit` event after their virtual click.
10. Any invalid plan, worker protocol error, bad patch, timeout, or exhausted
    budget terminates/discards the worker, clears pending events and object URLs,
    reports a bounded failed status, and leaves scripts disabled. No alternate
    execution path exists.

The two bridges in this delivery only produce bounded typed request messages.
They do not insert a composer draft or start a download; confirmation and host
effects remain outside Task 1.4.

Budget poison survives a generated catch and is checked before a transaction is
accepted. The renderer's one-in-flight event protocol prevents later events or
timer traffic from cancelling the watchdog for a hung event. A 102-event native
storm deterministically exhausted the 100-entry waiting queue and discarded the
worker while the shell stayed responsive.

## Remaining limitations and review concerns

1. Only Chromium is qualified on this host. Firefox/WebKit remain a portability
   risk until their already-supported optional gate runs in an environment with
   those Playwright engines installed.
2. QuickJS and its Emscripten wrapper are part of the trusted computing base and
   are not claimed to be a formally audited security sandbox. The architecture
   relies on capability removal, strict typed rendering, CSP/sandbox defense in
   depth, resource termination, and version/integrity pinning.
3. `worker-src data:` is required solely because Chromium rejects direct and
   blob module-worker construction from the opaque iframe. It is safe only while
   the packaged renderer remains trusted and generated data cannot affect the
   fixed bootstrap. This deserves specific independent-review attention.
4. `wasm-unsafe-eval` is required for embedded-WASM compilation. Broad
   `unsafe-eval` must never be substituted.
5. V1 is intentionally not browser-DOM compatible: selectors are simple,
   implicit form reset is not emulated, active embeds/resources/custom elements/
   modules are excluded, and some valid web CSS/SVG is deliberately rejected.
6. The 10 MiB download JSON value is a hard ceiling, not a promise that every
   value near it can coexist with all other allocations under the 32 MiB heap.
7. Bridge messages are request-only in this delivery. Later gateway code must
   revalidate identity, nonce, schema, size/depth, conversation/revision/session,
   confirmation, and rate limits before any host effect.
8. The static renderer remains visible after worker termination, but passive
   object URLs are revoked and scripts cannot resume without a fresh load.
9. Chromium's native raster decoders remain part of the trusted computing base.
   Dimensions, pixels, frames, bytes, asset count, and preparation time are
   bounded before object-URL use, and a decode that completes after its timeout
   is immediately closed; JavaScript cannot synchronously cancel the underlying
   browser decode operation.
10. Product integration must remain disabled until the controller's independent
   security review explicitly accepts this release-blocking boundary.
